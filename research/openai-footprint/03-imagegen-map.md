### 1.2 Главный вопрос: есть ли контроль структуры (аналог ControlNet)?

**Нет.** У OpenAI нет ни depth-карт, ни edge-maps, ни pose-контроля, ни какого-либо
аналога ControlNet weight/conditioning-scale. Официальная документация прямо предупреждает
про единственный инструмент частичного контроля — маску, и оговаривает её ненадёжность:

> «Masking with GPT Image is entirely prompt-based. The model uses the mask as guidance,
> but may not follow its exact shape with complete precision.»
> — [Create image edit | OpenAI API Reference](https://developers.openai.com/api/reference/resources/images/methods/edit)

Второй потенциальный кандидат на «удержание структуры» — параметр `input_fidelity`.
Он существует только у `gpt-image-1` (`high`/`low`) и **отсутствует у `gpt-image-1.5`
и `gpt-image-2`** — там модель всегда обрабатывает вход «на высокой точности» без
возможности отключить. Но и там, где параметр есть, он не про геометрию:

> «Setting `input_fidelity="high"` is especially useful when editing images with faces,
> logos, or any other details that require high fidelity in the output.»
> — [OpenAI cookbook: high input fidelity](https://developers.openai.com/cookbook/examples/generate_images_with_high_input_fidelity)

Это точечное сохранение конкретных референсных деталей (лицо, логотип, текстура), а не
блокировка всей пространственной композиции. Документация нигде не заявляет про
«pixel-level structural preservation» окон/дверей/стен — наоборот, соседние с
референсной деталью области намеренно остаются «гибкими» под промпт.

Практическое подтверждение вне документации (сторонние обзоры продуктов класса RoomGPT,
построенных поверх GPT Image): при редизайне комнаты «AI может добавить окно или дверь,
которых не было в комнате», а мебель на рендере «зачастую физически не влезла бы в
реальное помещение» — то есть геометрическая точность не гарантирована даже в специально
заточенных под эту задачу продуктах-обёртках.
Источник: [Decoratly — ChatGPT Interior Design guide, 2026](https://www.decoratly.com/chatgpt-interior-design).

**Вывод по пункту 2:** доступны только (а) генерация по текстовому описанию,
(б) image-to-image через `edits` с опциональной маской, где маска — не более чем мягкая
подсказка модели, и (в) точечное сохранение отдельных референсных деталей через
`input_fidelity` (только на устаревающей `gpt-image-1`). Строгого, детерминированного
контроля геометрии — того, что ControlNet-depth даёт «из коробки» — у OpenAI нет.

### 1.3 Можно ли вытянуть маскированием, и какой ценой

Технически — да, частично, но с оговорками:

- **Кто рисует маску.** Автоматическая маска (сегментация «не трогать стены/окна/двери»)
  потребует отдельной модели сегментации (сама OpenAI такой не даёт — понадобится
  сторонняя, например SAM), либо маску рисует пользователь вручную на фронтенде — это
  доп. шаг UX, который продукт-конкурент (реальный Interior AI) не требует от пользователя.
- **Насколько надёжно.** Даже с маской модель, по признанию самой документации, может
  «не следовать точной форме» — то есть в замаскированной области возможны сдвиги
  контура, а в незамаскированной модель всё равно вправе перерисовать освещение/тени/
  пропорции, потому что вход — не conditioning-сигнал, а часть промпта.
- **Итеративный обход.** Практический паттерн «сгенерировать несколько вариантов и
  показать лучший» снижает вероятность брака, но не устраняет её и умножает счёт
  (см. 1.4) на количество попыток на одну комнату.

Итог: маскированием можно получить *приемлемый для части кейсов* результат ценой
дополнительного шага (сегментация/ручная маска), возросшей стоимости (генерация
в 2–5 попыток на комнату вместо одной) и без гарантии — то есть без SLA на «геометрия
сохранена», который требует продукт.

### 1.4 Цена, лимиты, время

Официальная страница цен даёт токенную модель, из которой выводится цена за изображение;
устоявшиеся публичные калькуляторы (на основе тех же тарифов) дают удобные ориентиры
для 1024×1024:

| Модель | Low | Medium | High |
|---|---|---|---|
| `gpt-image-1` (уходит 23.10.2026) | $0.011 | $0.042 | $0.167 |
| `gpt-image-1.5` | $0.009 | $0.034 | $0.133 |
| `gpt-image-2` | ~$0.006 | ~$0.053* | ~$0.21* |

\* данные по gpt-image-2 на medium/high менее устоявшиеся в открытых калькуляторах —
перепроверить перед прод-бюджетом через официальный калькулятор.

Токенные ставки (официальная страница цен): `gpt-image-2` — $8/$30 за 1М input/output
токенов, `gpt-image-1.5` — $8/$32, `gpt-image-1` — $10/$40, `gpt-image-1-mini` — $2.5/$8.
Источники: [developers.openai.com/api/docs/pricing](https://developers.openai.com/api/docs/pricing) ·
[pricepertoken.com — GPT Image pricing 2026](https://pricepertoken.com/gpt-image-pricing) ·

**Время генерации.** `gpt-image-1`: 20–60 с на изображение по отчётам разработчиков

(несколько попыток на комнату) реальное время до приемлемого кадра умножается.

### 1.5 Честное сравнение с self-hosted Stable Diffusion + ControlNet-depth

| Параметр | OpenAI (gpt-image-1.5/2 + маска) | Self-hosted SD + ControlNet-depth |
|---|---|---|
| Контроль геометрии | Мягкий, не гарантирован | Жёсткий: depth-карта прямо кондиционирует диффузию, окна/двери/стены детерминированно на месте |
| GPU нужен? | Нет — облачный API | Да, обязательно. CPU-инференс для приемлемого времени непригоден |
| Требования к GPU | — | От 8 ГБ VRAM (SD 1.5) практично; для SDXL — от 12–16 ГБ комфортно, 24 ГБ (RTX 4090) с запасом |
| Стоимость GPU-VPS | — | RTX 4090 on-demand: **$0.13–0.80/ч** в зависимости от провайдера (Vast.ai от $0.13–0.29/ч, RunPod от $0.34/ч) |
| Время генерации 1 изображения | 5–60 с (см. выше) | ~3–9 с на A100/V100 при depth-ControlNet, 100 шагов; на потребительской 4090 сравнимо или быстрее |
| Операционная нагрузка | Ноль — просто вызов API | Разворачивание и поддержка инференс-сервера (ComfyUI/Automatic1111 + ControlNet-веса), мониторинг GPU-инстанса, cold-start контейнера |
| Совместимость с ограничением курса (Docker Compose, VPS, без managed-BaaS) | Совместимо — обычный внешний API-вызов, как любой другой AI-провайдер | Совместимо и даже ближе к духу курса (свой контейнер), но требует GPU-VPS — более дорогого и специфичного узла инфраструктуры, чем обычный VPS проекта |

Источники по GPU-ценам: [Vast.ai RTX 4090 pricing](https://vast.ai/pricing/gpu/RTX-4090) ·
[RunPod RTX 4090](https://www.runpod.io/gpu-models/rtx-4090) ·
[getdeploying.com — Cloud GPU pricing comparison 2026](https://getdeploying.com/gpus/nvidia-rtx-4090).
Источники по времени ControlNet: [Replicate — controlnet-depth2img](https://replicate.com/jagilley/controlnet-depth2img) ·
[HuggingFace — ControlNet in Diffusers](https://huggingface.co/blog/controlnet).

При 8-недельном учебном курсе GPU-VPS — это разовая учебная статья расходов
(десятки центов в час на время демонстраций/защиты), а не постоянный прод-costs;
если проект не идёт дальше учебного показа, экономика self-host вполне приемлема.
Для реального прод-запуска с постоянной нагрузкой стоимость GPU-инстанса 24/7
($0.13–0.8/ч × 720 ч ≈ $95–580/мес) нужно сравнивать с объёмом заказов.

### 1.6 Прямой ответ по проекту 08

**Нет, OpenAI не закрывает требование «геометрия сохраняется» для проекта 08.**
У OpenAI нет ControlNet-подобного жёсткого структурного контроля; единственный
инструмент — маска (описана самой OpenAI как «prompt-based guidance», не точный контур)
и `input_fidelity` (точечное сохранение деталей, не геометрии, и недоступно на новых
моделях). Переход на OpenAI для проекта 08 означает переход с «геометрия гарантированно
сохранена» на «геометрия обычно похожа, но перестановка окна/двери — не исключение,
а наблюдаемое в проде поведение у сравнимых продуктов». Это прямая потеря главного
требования продукта, а не деградация качества по краю.

**Рекомендация:** для проекта 08 оставить self-hosted Stable Diffusion + ControlNet-depth
как основной путь генерации (или её более новый прямой наследник — SDXL/SD3 с
depth-ControlNet — принцип тот же). OpenAI здесь можно использовать вспомогательно
(например, для текстовых описаний стиля пользователю, не для самой генерации кадра),
но не как замену контуру.

## Часть 3 — вывод про footprint провайдеров

**Прямой ответ владельцу: нет, свести все восемь проектов к одному провайдеру
(только OpenAI) нельзя без потери функциональности — но проблема ровно в одном
проекте из восьми, а не в размытой части портфеля.**

- **7 из 8 проектов (01–07) сводятся к OpenAI без компромиссов** — речь идёт про STT
  (Whisper/`gpt-4o-transcribe`), vision (GPT-4o/5-класс), эмбеддинги
  (`text-embedding-3-*`) и генерацию текста (`gpt-5.6-*` семейство) — это ровно тот
  набор возможностей, который у OpenAI зрелый, документированный и ценово предсказуемый.
  Для 02 и 03 вопрос вообще снимается — там нет требования к модели как таковой.
- **Проект 08 — единственное реальное исключение.** Требование «геометрия сохраняется»
  для редизайна интерьера — это структурный/pose-контроль, которого у генеративных
  моделей изображений OpenAI нет в принципе (ни у `gpt-image-1`, ни у `gpt-1.5`, ни у
  `gpt-image-2`) — только мягкая маска и точечная фиделити по деталям. Здесь остаётся
  нужен второй компонент — self-hosted Stable Diffusion (или актуальный наследник) с
  ControlNet-depth на отдельном GPU-узле.
- **Овчинка выделки не стоит гнать до одного провайдера силой.** Экономия «один
  провайдер вместо двух» здесь не операционная (интеграция с OpenAI и с self-hosted SD —
  это два независимых REST-вызова, сложность интеграции сама по себе невелика), а скорее
  инфраструктурная: наличие GPU-VPS для проекта 08 — это отдельный класс инфраструктуры
  по сравнению с обычным VPS остальных семи проектов. Но замена self-host на OpenAI не
  устраняет эту сложность, а меняет её на другую — постобработку/повторные генерации/
  ручную разметку масок ради частичной компенсации отсутствующего структурного контроля,
  что для учебного продукта хуже, чем один явный GPU-контейнер.
- **Практическая рекомендация:** держать OpenAI как единственного AI-провайдера для
  проектов 01, 04, 05, 06, 07 (и опционально для лёгкой модерации в 02); для проекта 08
  держать self-hosted SD+ControlNet как второй, изолированный провайдер именно там, где
  это архитектурно оправдано ADR-уровня решением, а не как временный компромисс. Это
  сокращает число провайдеров с «до восьми потенциально разных» до **двух**
  (OpenAI + self-hosted SD), что уже даёт основную часть выигрыша от консолидации,
  которого хочет владелец, без потери ключевого требования продукта 08.
- Claude как инструмент разработки (Claude Code / feature-adr pipeline) остаётся вне
  этого расчёта — вопрос был только про модели внутри самих продуктов.
