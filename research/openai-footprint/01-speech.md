# Распознавание речи (STT) у OpenAI — для проектов 01 и 05

Дата фиксации данных: **2026-08-26**. Цены, лимиты и имена моделей у OpenAI меняются часто —
таблицы ниже верны на эту дату, перед реализацией сверить по ссылкам заново.

Источники — официальная документация OpenAI (`developers.openai.com/api/docs/...`, зеркало
`platform.openai.com/docs/...`), плюс `github.com/openai/whisper` и `github.com/SYSTRAN/faster-whisper`

перекрёстной проверки, не как первоисточник.

**Важное расхождение с памятью:** в текущей версии документации `timestamp_granularities`
(word/segment) явно и однозначно демонстрируется **только для `whisper-1`**. У
`gpt-4o-transcribe`/`gpt-4o-mini-transcribe` этот параметр в примерах и описании не встречается —
считать, что они timestamps НЕ отдают, пока не найдено прямое опровержение. Модель `whisper-1`
при этом жива и не в списке deprecated — вопреки ожиданию, что её снимут после выхода GPT-4o-серии.

## 2. Таймкоды — разбор для проекта 05

Два разных механизма, оба официально подтверждены:

1. **`whisper-1` + `response_format=verbose_json` + `timestamp_granularities=["word"]` и/или
   `["segment"]`.** Возвращает `words[]` (text, start, end в секундах на уровне слова) и/или
   `segments[]`. Цитата из гайда: *"There is no additional latency for segment timestamps, but
   generating word timestamps incurs additional latency."* Это единственный официально
   подтверждённый путь к **word-level** таймкодам.
2. **`gpt-4o-transcribe-diarize` + `response_format=diarized_json`.** Возвращает `segments[]` со
   `speaker`, `start`, `end` — то есть таймкоды на уровне сегмента речи + метка спикера, но
   НЕ на уровне слова.

Для проекта 05 (нарезка клипов из подкастов/интервью) это значит:
- Нарезка по границам реплик/спикеров → `gpt-4o-transcribe-diarize` + `diarized_json` (сразу
  даёт "кто говорит + где" — удобно для автовыбора клипабельных моментов).
- Нарезка по точной границе слова (например, чтобы клип не начинался с полуслова) →
  `whisper-1` + `timestamp_granularities: ["word"]`.
- Рабочая комбинация: гнать оба вызова (whisper-1 для word-таймкодов, diarize для спикеров) либо
  взять только diarize и на этапе нарезки клипов слегка "отступать" от границы сегмента — дешевле
  по вызовам API, чуть менее точно. Решение — на усмотрение архитектора фичи, здесь только факт
  наличия обоих путей.
- **Риск, не первоисточник OpenAI:** на GitHub есть открытые issue про
  `gpt-4o-transcribe-diarize` не возвращающую сегменты диаризации в некоторых окружениях (Azure
  SDK issue #43964, #38741) — не проверено на прямом OpenAI API, но как сигнал "модель новая,
  не заезженная" стоит держать в голове и тестировать на реальных подкастах перед committing to
  этой модели.

## 3. Расчёт стоимости для двух сценариев курса

Тариф — заявленная официальная цена «$/минута аудио» (раздел 1). Токенная цена (input/output за
1М токенов) даёт тот же порядок и здесь не пересчитывается отдельно — сама страница цен указывает
именно её как альтернативную запись тех же чисел, не независимую величину.

### (а) Проект 01 — 1000 видео-отзывов по 90 секунд
Суммарно: 1000 × 1.5 мин = **1500 минут аудио**. Таймкоды не нужны (FR-NFR-SEC-002 требует только
метку "машинная расшифровка" + неизменность текста отзыва) → любая file-модель подходит.

| Модель | Цена/мин | Итого на 1000 отзывов |
|---|---|---|
| `gpt-4o-mini-transcribe` | $0.003 | **$4.50** |
| `gpt-transcribe` | $0.0045 | **$6.75** |
| `gpt-4o-transcribe` / `whisper-1` | $0.006 | **$9.00** |

### (б) Проект 05 — 100 подкастов по 1 часу
Суммарно: 100 × 60 мин = **6000 минут аудио**. Нужны таймкоды → `whisper-1` и/или
`gpt-4o-transcribe-diarize`, обе по $0.006/мин.

| Модель | Цена/мин | Итого на 100 подкастов |
|---|---|---|
| `whisper-1` (word/segment timestamps) | $0.006 | **$36.00** |
| `gpt-4o-transcribe-diarize` (segment+speaker) | $0.006 | **$36.00** |
| Если гнать оба вызова на одно и то же аудио (whisper-1 + diarize) | — | **$72.00** |

**Вывод по деньгам:** для объёма учебного курса (8 продуктов, демо-масштаб) стоимость STT через
API — единицы-десятки долларов суммарно. Экономия на self-hosted STT здесь не является реальным
драйвером решения; определяющие факторы — приватность, задержка и архитектурная зависимость от
внешнего managed API (см. раздел 7).

## 4. Лимиты

- **Размер файла:** до **25 MB** на файл (гайд file-транскрипции). Дословно: *"Files can be up to
  25 MB."*
- **Рекомендация для файлов больше лимита:** сжать формат или разбить на чанки ≤25MB (PyDub),
  не резать посреди предложения (потеря контекста/точности). Готового API для авто-чанкинга
  длинных файлов (кроме `chunking_strategy=auto` в примере с диаризацией) не найдено.
- **Максимальная длительность:** не подтверждено — явного лимита по времени, только по размеру
  файла. Часовой подкаст в mp3 (~64–96 kbps) обычно укладывается в 25MB без чанкинга; записи 2+ часа
  или высокобитрейтные исходники потребуют разбивки.
- **Поддерживаемые форматы:** `mp3, mp4, mpeg, mpga, m4a, wav, webm`.
- **Rate limits:** организованы по tier (RPM/TPM), рост tier — по сумме потраченного:
  Tier 1 от $5, Tier 2 от $50, Tier 3 от $100, Tier 4 от $250, Tier 5 от $1000 (страница Rate
  Limits). Пример для `gpt-4o-transcribe` (Tier 1): 500 RPM / 10 000 TPM — далее растёт до
  10 000 RPM / 6 000 000 TPM на Tier 5. Отдельного лимита именно "аудио-минут в минуту" для
  file-транскрипции в явном виде не найдено (упоминается как метрика для некоторых
  realtime/потоковых моделей, но конкретные цифры не показаны).

Источники: [File transcription guide](https://developers.openai.com/api/docs/guides/speech-to-text),
[Rate limits guide](https://developers.openai.com/api/docs/guides/rate-limits).

## 5. Языки, качество на русском

- Whisper (`whisper-1` и открытая модель) — официально заявлено **98 языков** (репозиторий
  `openai/whisper`), точность варьируется по языку.
- `gpt-transcribe` принимает языковые коды трёх форматов (ISO 639-1, отдельные ISO 639-3, `zh-*`
  локали) — сам список поддерживаемых языков для GPT-4o-серии моделей отдельной таблицей в
  документации не найден.
- **Официальные цифры по WER для русского не найдены напрямую** — README `openai/whisper`
  ссылается на Appendix D.1/D.2/D.4 статьи (WER/CER на Common Voice 15 и Fleurs для large-v2/v3),
  но таблица подаётся как изображение, не как текст/HTML — не удалось вытащить построчно.
  Сторонний агрегированный источник (не первоисточник OpenAI) называет для `large-v3`: **WER ≈
  3.02% на Fleurs (русский)** и **≈5.10% на Common Voice 15 (русский)** — цифры **не подтверждены
  напрямую по первоисточнику**, приводятся только как ориентир. Помечаю в разделе 8.
- Практический вывод: русский — не low-resource язык для Whisper (в отличие от, например, редких
  языков), но точную цифру WER для курса считать неподтверждённой и проверять на собственных
  тестовых записях перед запуском в продакшн.

## 6. Self-hosted Whisper / faster-whisper как альтернатива

Официальные данные из `github.com/openai/whisper` (README) и `github.com/SYSTRAN/faster-whisper`
(README):

| Модель | Параметры | VRAM (GPU) | Относительная скорость |
|---|---|---|---|
| tiny | 39M | ~1GB | ~10x |
| base | 74M | ~1GB | ~7x |
| small | 244M | ~2GB | ~4x |
| medium | 769M | ~5GB | ~2x |
| large | 1550M | ~10GB | 1x (базовая) |
| turbo | 809M | ~6GB | ~8x |

**CPU-бенчмарк (faster-whisper README, официальный репозиторий), 13-минутный аудиофайл,
модель `small`, Intel i7-12700K, 8 потоков:**

| Реализация | Время | RAM |
|---|---|---|
| `faster-whisper`, int8, batch_size=8 | **51 сек** | 3.6 GB |
| `faster-whisper`, fp32, batch_size=8 | 1 мин 06 сек | 4.2 GB |
| `openai/whisper` (референсная реализация), fp32 | 6 мин 58 сек | 2.3 GB |

Итого: `faster-whisper` до **4x быстрее** референсной реализации на том же CPU при меньшей памяти
(измерено на модели `small`, не на `large`).

**Оценка для сценариев курса (экстраполяция из таблицы "относительная скорость", НЕ отдельное
измерение — явно помечаю как оценку):**
- Проект 01, файл 90 сек: на CPU (`faster-whisper`, модель small/medium, int8) — единицы секунд
  на файл, обработка в фоне легко укладывается в разумный SLA для одного отзыва.
  1000 отзывов × 1.5 мин = 25 часов аудио суммарно; при грубой скорости ~0.06–0.15x реального
  времени (экстраполяция из замера small/int8: 51 сек на 13 мин аудио) — суммарно **ориентировочно
  1.5–4 часа CPU-времени** на весь батч из 1000 отзывов. Оценка, не измерение.
- Проект 05, файл 60 мин, нужна модель `large`(-v3) ради качества на длинных интервью: по таблице
  относительной скорости `large` ~4x медленнее `small`. Экстраполируя от замера small/int8
  (51 сек на 13 мин аудио) → на 13-минутный файл ~3.4 мин, то есть примерно **~0.26x реального
  времени** для large на многоядерном CPU. Для 100 подкастов × 60 мин = 6000 минут аудио →
  **ориентировочно ~26 часов суммарного CPU-времени** на весь курсовой батч. Это ОЦЕНКА
  экстраполяцией таблицы относительной скорости на другой класс железа/файлов, не прямое
  измерение — подтверждать локальным тестом перед решением.
- Размер модели на диск: large-v3 ≈ 3GB весов — разовая загрузка в Docker-образ/volume.

Источники: [openai/whisper README](https://github.com/openai/whisper),
[SYSTRAN/faster-whisper README](https://github.com/SYSTRAN/faster-whisper).

## 7. API против self-hosted

| Критерий | OpenAI API | Self-hosted (faster-whisper, CPU, Docker Compose) |
|---|---|---|
| **Цена на объёме курса** | $4.50–$9 (проект 01) + $36–$72 (проект 05) — единицы-десятки $ суммарно | $0 маржинально, но требует CPU-время + место на диске (~3GB модель); окупаемости на демо-объёме курса нет |
| **Задержка** | Сетевой вызов + очередь модели; предсказуемая, не зависит от локального железа VPS | Зависит от CPU VPS; для `large` на 60-мин подкасте — минуты обработки в фоне (оценка раздела 6), не realtime |
| **Приватность** | Аудио уходит в OpenAI; по умолчанию **не используется для обучения моделей** и хранится **до 30 дней** для контроля злоупотреблений (Zero Data Retention доступен для соответствующих организаций/эндпоинтов) | Аудио не покидает VPS курса — единственный вариант, если это жёсткое требование (например, персональные данные интервьюируемых) |
| **Сложность эксплуатации** | Минимальная: один HTTP-вызов, нет управления моделью/GPU/очередями | Выше: контейнер с ffmpeg-препроцессингом, управление очередью задач, мониторинг CPU-нагрузки, обновление модели |
| **Соответствие Architecture Constraints курса** | Внешняя managed-зависимость (API), НЕ Managed BaaS в смысле правила PR-002 (то запрещает Supabase/Firebase/Neon как бэкенд, а не вызовы AI-моделей) — формально не противоречит, но это доп. внешний провайдер сверх заявленного "AI Integration: MCP servers" | Полностью укладывается в "Docker Compose на своём VPS" без внешних AI-провайдеров |

Источники по приватности: [OpenAI Business data privacy](https://openai.com/business-data/) (через
поиск, официальный домен openai.com).

## 8. Вывод по проекту 01 (Senja-клон)

**Рекомендация: OpenAI API, модель `gpt-4o-mini-transcribe` или `gpt-transcribe`.**
- Таймкоды не нужны → нет причины платить за `whisper-1`/diarize.
- Объём (1000×90 сек = 25 часов аудио) стоит $4.50–$6.75 суммарно — self-hosting не оправдан ни по
  деньгам, ни по инженерным трудозатратам на демо-масштабе курса.
- FR-NFR-SEC-002 (пометка "машинная расшифровка", неизменность текста отзыва) — это требование к
  **продуктовой логике** (как хранится и рендерится транскрипт), а не к выбору модели: любая из
  моделей просто возвращает текст, разработчик обязан хранить транскрипт в отдельном поле и
  помечать его как auto-generated, не подмешивая в поле самого отзыва. Ни одна модель не решает
  это автоматически.
- Единственный аргумент за self-hosted здесь — если в отзывах систематически звучат персональные
  данные и есть жёсткое требование не отправлять аудио пользователей во внешний API. Явно такого
  требования в постановке проекта 01 не приведено — считаю API оправданным выбором по умолчанию.

## 9. Вывод по проекту 05 (Opus Clip-клон)

**Рекомендация: OpenAI API, комбинация `whisper-1` (word-level timestamps) и/или
`gpt-4o-transcribe-diarize` (segment + speaker) — НЕ self-hosted на старте.**
- Без таймкодов проект не работает — это единственный по-настоящему жёсткий технический критерий.
  Только `whisper-1` даёт официально подтверждённые word-level таймкоды; только
  `gpt-4o-transcribe-diarize` даёт спикер + границы реплики "из коробки". Обе модели по $0.006/мин.
- Стоимость на объём курса (100×60 мин = 6000 мин) — $36 на одну модель, $72 если использовать обе
  на каждый файл. Незначимо для бюджета курса.
- Self-hosted `large-v3` на CPU технически работоспособен (см. раздел 6), но: (а) обработка часового
  подкаста на CPU — это минуты, а не секунды, то есть очередь задач и асинхронный UX обязательны в
  любом случае, что снижает выгоду self-host по задержке; (б) `gpt-4o-transcribe-diarize` через API
  даёт готовую диаризацию по спикерам без отдельного пайплайна (pyannote и т.п.), что для клипов
  из интервью — прямая экономия инженерного времени. Открытый Whisper диаризацию сам не делает.
- Если позже появится жёсткое требование приватности (подкасты с NDA-контентом) — тогда стоит
  вернуться к self-hosted `faster-whisper large-v3` + отдельный пайплайн диаризации (например,
  pyannote.audio, не проверялся в этом расследовании) на VPS; технически возможно, но не входит в
  зону этого исследования (диаризация вне API OpenAI не проверялась).
- Риск, который стоит протестировать до коммита в диаризацию: открытые issue про
  `gpt-4o-transcribe-diarize`, не возвращающую сегменты в некоторых окружениях (раздел 2) — до
  выбора модели прогнать реальный часовой подкаст курса через API и свериться, что диаризация
  стабильно возвращается.

## Не подтверждено

- Точные официальные цифры WER для русского языка (Common Voice 15 / Fleurs) — таблица в
  `openai/whisper` подаётся изображением, текстом не извлечена; цифры 3.02%/5.10% взяты из
  стороннего агрегатора, не из первоисточника.
- Поддерживает ли `gpt-transcribe` таймкоды (`timestamp_granularities` или аналог) — в
  документации модели не упомянуто ни в одну, ни в другую сторону.
- Официальный лимит максимальной **длительности** аудио в минутах/часах (независимо от размера
  файла в MB) — не найден; вероятно, лимита нет и работает только ограничение 25MB.
- Явные числа rate limit специально для file-based `/v1/audio/transcriptions` endpoint по каждому
