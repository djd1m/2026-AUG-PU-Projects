# PR-029: Защита пишется против первого экземпляра класса и молча не покрывает остальные

**Класс:** страж зелен на непроверенном коде · **Приоритет:** P0 · **Найдено:** три случая, два проекта, 2026-08-30 … 09-01

## Утверждение

Когда свойство безопасности относится к **классу** объектов — маршрутам, файлам провайдеров,
модулям с внешними вызовами, — страж пишется против того экземпляра, с которого начали.
Второй и последующие остаются **вне покрытия, и страж об этом не сообщает**: он зелёный,
потому что проверяет то, что ему перечислили.

Отказ невидим по построению. Отсутствие проверки заметно; **видимость проверки — нет**.

## Три случая

**1. Один роут защищён типом, соседний — прозой.** Проект 02, 2026-09-01. Инвариант «ответ
зависит только от слага» доказан для `GET /r/:slug` **сигнатурой**: у функции рендера нет
аргумента, куда подать контекст. Для соседнего `GET /go/:slug/:platform` тот же инвариант был
записан **утверждением в тексте**.

Формулировка автора, когда дыру предъявили:

> «Утверждение в прозе — это и есть слой 4. Разница между двумя роутами держалась не на
> конструкции, а на том, что до второго у меня не дошли руки. Ровно тот дефект, который вся
> конструкция закрывает, — и он оказался внутри неё самой.»

**2. Страж таймаутов со списком файлов литералом.** Проект 01. Проверка «число `fetch` равно
числу `signal`» перечисляла файлы явно: `['lib/sso.ts', 'lib/email.ts', 'lib/payment.ts']`.
Новый файл провайдера под неё не попадал — то есть первый же добавленный внешний вызов
оказывался без обязательного таймаута, при зелёном страже.

**3. Девять стражей, прибитых к пути первого провайдера.** Тот же проект. Девять проверок
читали файл по литеральному пути `app/api/auth/yandex/callback/route.ts`. Они стерегли
несущее: сеть вне транзакции, единственную точку выдачи сессии, отсутствие токена в журнале.

Самый быстрый способ добавить второго провайдера — скопировать каталог. И тогда **все девять
остаются зелёными и перестают покрывать новый маршрут**. Не падают. Не предупреждают.

## Почему обычные средства не ловят

| Средство | Почему молчит |
|---|---|
| Прогон тестов | Зелёный: страж проверяет перечисленное, и оно в порядке |
| Ревью правки | Видит новый файл, не видит, что старый страж его не охватил |
| Покрытие кода | Меряет строки, а не то, применён ли к ним инвариант |
| Мета-тест «страж падает» | Ловит поломку стража, а не сужение его области |

## Что предлагается

**1. Страж над классом обязан перечислять класс ИЗ РЕАЛЬНОСТИ, а не из литерала.** Не список
файлов, а `glob`; не путь роута, а таблица маршрутов; не имена провайдеров, а содержимое
каталога. Литеральный перечень внутри стража — сам по себе находка.

**2. Мета-тест на расширение класса.** Добавить фиктивный второй экземпляр (пустой файл
провайдера, новый роут-заглушку) — **страж обязан упасть**, пока экземпляр не покрыт. Если не
упал, он не про класс, а про один файл, и это надо знать до, а не после.

**3. Правило в навык ревью.** Утверждение об инварианте, записанное прозой рядом с
конструкцией, доказывающей тот же инвариант, — сигнал асимметрии. Спрашивать не «верно ли
утверждение», а «почему здесь текст, если рядом тип».

## Способ проверки

```
Взять проект со стражем над классом. Добавить второй экземпляр класса, не трогая страж.
Прогон зелёный — воспроизведение дефекта.
```
