# Паттерн: страж инварианта, читающий ИСХОДНИК

## Maturity: 🔴 Alpha · Извлечено: 2026-08-27 · Источник: `projects/01-testimonials-senja` · v1.0

## Когда применять

Когда требование сформулировано как свойство **кода целиком**, а не как результат одного
вызова. Признак — в формулировке есть слово «ни одного», «только», «нигде», «всегда»:

- «без подтверждения не отправляется **ни одного** запроса к внешней сети»
- «решение о тарифе принимает **только** сервер»
- «`project_id` **нигде** не принимается от клиента напрямую»

Обычный тест проверяет **тот путь, который сам прошёл**. Утверждение «ни одного» — про
все пути, включая те, которых сегодня нет. Завтра кто-то добавит `fetch` в другую ветку
компонента, поведенческий тест останется зелёным, и требование будет нарушено молча.

## Когда НЕ применять

- Свойство выражается типом → выражай типом, это дешевле и надёжнее (`badgeRequiredFor`
  принимает **ровно один** аргумент — второго параметра, куда передать `hide_badge`,
  физически не существует; проверяется как `expect(fn.length).toBe(1)`).
- Свойство про поведение в рантайме (значения, ветвления, ошибки) → обычный тест.
- Код часто и законно переписывается — страж по тексту начнёт мешать вместо того, чтобы
  защищать. Тогда поднимай проверку в линтер с правилом, а не в тест.

## Реализация

Два рабочих вида. Оба — **слой 1** по лестнице стоимости обнаружения: детерминированно,
без модели, ловят 100 %.

### Вид А: запрет вне границ функции

Разбирает тело функции по балансу фигурных скобок и проверяет, что опасных вызовов
за его пределами нет.

```ts
import { readFileSync } from 'node:fs';

/** Границы тела функции по балансу фигурных скобок. */
function functionBody(src: string, signature: string): { start: number; end: number } {
  const sigAt = src.indexOf(signature);
  if (sigAt === -1) throw new Error(`не найдена функция: ${signature}`);
  const start = src.indexOf('{', sigAt);
  let depth = 0;
  for (let i = start; i < src.length; i += 1) {
    if (src[i] === '{') depth += 1;
    else if (src[i] === '}') {
      depth -= 1;
      if (depth === 0) return { start, end: i };
    }
  }
  throw new Error('не найден конец тела функции');
}

// Комментарии выкидываем: в них запрещённые имена упоминаются ПО ДЕЛУ и вызовами не являются.
const code = readFileSync(SOURCE, 'utf8')
  .replace(/\/\*[\s\S]*?\*\//g, '')
  .replace(/^\s*\/\/.*$/gm, '');

const FORBIDDEN = ['fetch(', 'navigator.share', 'navigator.clipboard',
                   'XMLHttpRequest', 'sendBeacon', 'new WebSocket', 'new EventSource', 'import('];

it.each(FORBIDDEN)('вызов %s не встречается вне подтверждённого пути', (needle) => {
  const { start, end } = functionBody(code, GUARDED_FN);
  const outside: number[] = [];
  let at = code.indexOf(needle);
  while (at !== -1) {
    if (at < start || at > end) outside.push(at);
    at = code.indexOf(needle, at + 1);
  }
  expect(outside, `${needle} найден вне тела (смещения: ${outside.join(', ')})`).toEqual([]);
});
```

Дополняется двумя проверками, закрывающими обход:

```ts
// Ровно два упоминания: объявление + onClick. Любое третье — потенциально автоматический вызов.
expect(code.split('guardedFn').length - 1).toBe(2);
// Нет useEffect — то есть нет пути «сделать это при показе».
expect(code).not.toContain('useEffect');
```

### Вид Б: правило не продублировано

Обходит все исходники и требует, чтобы решение принималось в единственном месте.

```ts
it('сравнение с "paid" встречается только в lib/tariff.ts', () => {
  const offenders: string[] = [];
  for (const file of sourceFiles(SRC)) {
    if (file.endsWith(path.join('lib', 'tariff.ts'))) continue;
    const code = stripComments(readFileSync(file, 'utf8'));
    // Ищем именно СРАВНЕНИЕ, а не строку 'paid' в SQL или в типе.
    if (/[!=]==?\s*['"]paid['"]|['"]paid['"]\s*[!=]==?/.test(code)) {
      offenders.push(path.relative(SRC, file));
    }
  }
  expect(offenders, `правило продублировано в: ${offenders.join(', ')}`).toEqual([]);
});
```

Этот вид **дважды** поймал реальное дублирование в проекте-источнике — в обработчике
оплаты и в дашборде, оба раза автором, который знал о правиле.

## Подводные камни

| Камень | Что делать |
|---|---|
| Комментарии дают ложные срабатывания — в них запрещённые имена упоминаются по делу | Вырезать комментарии ДО поиска (`/\*…\*/` и `^\s*//.*$`) |
| Строковый поиск ловит подстроки (`'paid'` в SQL, в типе, в имени поля) | Искать **синтаксическую форму** (сравнение), а не слово |
| Тест ломается при безобидном переименовании | Держать сигнатуру/имя в константе наверху файла и в сообщении об ошибке — чинится за секунды |
| Соблазн проверить всё регэкспом вместо разбора | Для «внутри/снаружи функции» нужен баланс скобок; регэксп этого не выражает |
| Страж проверяет файл, который переименовали → тест зелёный на пустоте | Отдельным `it` утверждать, что файл и искомая сигнатура вообще существуют |

Последний пункт обязателен: без него удаление файла делает стража молча зелёным.
