# PR-012: Нет архитектурного запрета на публикацию БД наружу

**Класс:** отсутствует контроль безопасности · **Приоритет:** P0 ·
**Найдено:** реальной компрометацией на прогоне `/run mvp`, 2026-08-26

## Проблема

У p-replicator нет правила, запрещающего публиковать порт базы данных на хост. Ни в
Architecture Constraints, которые уходят в Phase 1, ни в шаблонах scaffold'ов, ни в одной
проверке. Результат этого пробела — не гипотетический.

**Что случилось.** На машине курса, где живут проекты, был поднят тестовый Postgres:

```bash
docker run -p 55432:5432 -e POSTGRES_PASSWORD=postgres postgres:16-alpine
```

Через час база была скомпрометирована из интернета:

1. перебор пароля роли `postgres` — десятки попыток в логе, затем успех;
2. `COPY (SELECT '') TO PROGRAM 'echo <base64>|base64 -d|bash'` — штатный вектор RCE для
   суперпользователя Postgres;
3. в `/tmp` контейнера легли два ELF-бинаря; расшифрованный payload — червь-майнер:
   тянет тело с внешнего IP и **убивает конкурирующие майнеры** (`kinsing`, `kdevtmpfsi`,
   `dnsmasq`, `/tmp/watchdog`) — то есть машина была не первой целью, а трофеем в чужой борьбе;
4. параллельный вектор `CREATE FUNCTION system(cstring) … libc.so.6` провалился только
   потому, что образ на Alpine/musl. На `postgres:16` (Debian) он бы сработал.

Радиус поражения ограничился контейнером. Спасла случайность выбора образа, а не архитектура.

## Ключевое наблюдение: сгенерированный compose был ПРАВИЛЬНЫМ

Это главное, ради чего написана заявка. В `docker-compose.yml`, который сгенерировал
пайплайн, всё верно:

```yaml
postgres:
  expose: ["5432"]     # наружу не публикуется
minio:
  expose: ["9000"]
```

Нарушением стал **ad-hoc `docker run` в обход compose** — тестовая БД, поднятая руками,
потому что тесты идут с хоста, а не внутри сети compose.

Отсюда вывод, определяющий форму исправления: **правило, живущее только в шаблоне
scaffold'а, не защищает.** Оно должно быть сформулировано как архитектурный инвариант
(«к БД нет прямых подключений снаружи — никогда, никаким способом»), а не как свойство
одного сгенерированного файла. Иначе первый же обходной путь его аннулирует, и именно
это и произошло.

## Исправление

### P0-1 — в Architecture Constraints (уходит в Phase 1)

`.claude/rules/replicate-pipeline.md`, блок, который подаётся в `sparc-prd-mini`:

```diff
  - Pattern: Distributed Monolith (Monorepo)
  - Containers: Docker + Docker Compose
  - Infrastructure: VPS (AdminVPS/HOSTKEY)
  - Deploy: Docker Compose direct deploy
  - AI Integration: MCP servers
+ - **Никаких прямых подключений к БД снаружи.** Postgres, Redis, MinIO и любые другие
+   хранилища объявляются ТОЛЬКО через `expose:`, никогда через `ports:`. Наружу смотрят
+   лишь reverse-proxy и приложение. Это инвариант архитектуры, а не свойство одного файла:
+   он распространяется и на разовые `docker run` в отладке.
```

Это заставляет требование появиться в `Architecture.md` проекта, где его увидит и
разработчик, и следующий агент — а не только генератор compose.

### P0-2 — детерминированная проверка (слой 1)

Скрипт, запускаемый после генерации и перед каждым запуском:

```bash
docker compose config | awk '<сервис с image ~ postgres|redis|minio|mysql|mongo|elastic
                              ИЛИ target ∈ {5432,6379,9000,3306,27017,9200}> И <есть published>'
# найдено → exit 1
```

Реализация: `scripts/check-port-conflicts.sh`, раздел «БД и хранилища не смотрят в интернет».
Проверена в обе стороны — падает на внедрённом `ports: ["55432:5432"]` у postgres
(код возврата 1), зелёная на корректном compose.

### P0-3 — правило про ad-hoc запуск

Ровно тот случай, который и выстрелил. Отдельным разделом, потому что compose его не покрывает:

```bash
# ❌ публикует на ВСЕ интерфейсы, включая публичный IP
docker run -p 55432:5432 -e POSTGRES_PASSWORD=postgres postgres:16-alpine

# ✅ только петля + случайный пароль
docker run -p 127.0.0.1:55432:5432 -e POSTGRES_PASSWORD="$(openssl rand -hex 24)" postgres:16-alpine
```

Два обязательных условия: явный `127.0.0.1` и случайный пароль. «Необычный» номер порта
защитой не является — 55432 нашли за час.

### P1 — запрет дефолтных учётных данных

`postgres/postgres`, `minioadmin/minioadmin`, `root/root`, Redis без пароля — не «временно
для тестов», а готовая точка входа. Проверяется грепом по `.env`/`compose`/командам запуска.

## Почему это P0 и почему слой 1

Обычные заявки этой кузницы описывают пропущенный артефакт: пайплайн зелёный, документ
отсутствует, цена — переделка. Здесь цена другая — чужой код на машине с исходниками
и учётными данными всех восьми проектов курса.

По лестнице стоимости обнаружения проверка обязана быть на слое 1: «разработчик не будет
публиковать порт БД» — это слой 5 (память агента), и он уже отказал один раз в условиях,
где все документы были написаны верно.
