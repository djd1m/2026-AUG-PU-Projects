# PR-019: `check-ports.cjs` удваивает относительный путь

**Класс:** баг, однострочный фикс · **Приоритет:** P2 · **Найдено:** обновление до 1.9.0, проект 01
· **Версия:** 1.9.0

## Сначала о хорошем

`check-ports.cjs` — прямое воплощение [PR-012](PR-012-db-never-published.md),
[PR-014](PR-014-env-vars-not-wired.md) и [PR-018](PR-018-guard-never-proven-to-fail.md).
Три кода возврата, где **2 = проверка не выполнена**, — ровно то, что просил PR-018, и
обоснование в шапке файла («страж, отвечающий „чисто“, когда не смог посмотреть, хуже
отсутствия стража») — формулировка из `guard-must-be-able-to-fail`.

Проверено на живом проекте:

```text
абсолютный путь, чистый compose          -> код 0, «ни одно хранилище не публикует порт наружу»
compose с ports: ["5432:5432"] у postgres -> код 1, названы и публикация БД, и обход прокси
compose без заданного пароля в env        -> код 2, назван недостающий TEST_PG_PASSWORD
```

Все три ветки ведут себя как задокументировано. Претензия ниже — единственная.

## Проблема

Относительный путь аргумента **приклеивается к корню проекта**, а не разрешается от
текущего каталога:

```console
$ cd /path/to/repo
$ node .claude/hooks/check-ports.cjs projects/01-testimonials-senja
⚠️  проверка НЕ выполнена: docker compose config вернул ошибку:
    open /path/to/repo/projects/01-testimonials-senja/projects/01-testimonials-senja/docker-compose.yml:
    no such file or directory
```

Путь удвоен. Тот же вызов с абсолютным путём отрабатывает верно.

## Почему это стоит починить, хотя код возврата верный

Отказ честный — 2, а не 0, и это правильно. Но диагноз **уводит**: в сообщении написано
«обычно это незаданная переменная», хотя переменные ни при чём. Пользователь пойдёт искать
`.env`, а проблема в форме аргумента.

Хуже: подсказка `docker compose -f projects/01-testimonials-senja/docker-compose.yml config`
напечатана с **неудвоенным** путём, то есть при ручном запуске сработает — и создаст
впечатление, что проверка врёт.

## Исправление

Разрешать аргумент от `process.cwd()`, а к корню проекта приклеивать только когда аргумент
не задан вовсе:

```js
const target = argv[2]
  ? path.resolve(process.cwd(), argv[2])   // было: path.join(projectRoot, argv[2])
  : projectRoot;
```

## Способ проверки

```bash
cd <репозиторий>
node .claude/hooks/check-ports.cjs projects/<проект>            # ожидается 0/1, не 2
node .claude/hooks/check-ports.cjs ./projects/<проект>           # то же
node .claude/hooks/check-ports.cjs /abs/path/to/<проект>         # не сломать: работает сейчас
node .claude/hooks/check-ports.cjs                               # без аргумента — корень проекта
```

## Смежное наблюдение (не дефект пакета)

Слияние `settings.json` при `update` **задвоило хуки**: локальные записи вида
`$CLAUDE_PROJECT_DIR/...` и добавленные пакетом `${CLAUDE_PROJECT_DIR}/...` — это одна и та
же команда, но сравнение шло по строке. В результате каждый хук был зарегистрирован дважды и
выполнялся бы дважды: два `autocommit-roadmap`, два `autocommit-insights`, два
`autocommit-plans`, два `session-insights`.

Нормализация `${VAR}` → `$VAR` перед сравнением команд снимает случай целиком.
