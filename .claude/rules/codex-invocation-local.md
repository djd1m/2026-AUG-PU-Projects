## Maturity: 🟡 Beta · Извлечено: 2026-09-21 · Источник: прогон N5 (проект 05) · v1.0

Действует, когда Claude Code делегирует работу Codex. Все отказы ниже НАБЛЮДАЛИСЬ, а не выведены;
у каждого назван код возврата или измеренное время.

## Правило №0 — заглушка читается как чистый результат

**`codex:codex-rescue` — обёртка Claude, которая ДИСПАТЧЕРИЗУЕТ и возвращается немедленно.** Её
возвращаемое значение — заглушка. Это законно там, где результат работы — ФАЙЛ, и факт записи
проверяется отдельно (код, план). Это ложь там, где результат — САМ ОТВЕТ: пустой отчёт ревью
неотличим от «замечаний нет».

Отсюда развилка, и она первая:

| Что нужно от Codex | Чем звать | Чем доказывается результат |
|---|---|---|
| написать/поправить файлы | `codex exec -s workspace-write` | барьер приземления: `git status` до и после, пока изменения не появятся |
| ответ, вердикт, разбор | `codex exec -s read-only -o <файл>` | непустой файл с разбираемым вердиктом; пустой ответ — НЕ «чисто» |
| фоновая длинная работа | `codex:codex-rescue` | только вместе с барьером приземления; иначе не звать |

## Четыре отказа, измеренные на прогоне

### 1. Зависание на stdin — 580 с и таймаут

```bash
codex exec -m gpt-6-astra -C "$DIR" -o out.md "прочитай brief.md и ответь"   # ← ЗАВИС
# stdout: "Reading additional input from stdin..."
```

Codex читает stdin, когда он не закрыт, ДАЖЕ если промпт передан позиционно: «If stdin is piped and
a prompt is also provided, stdin is appended as a `<stdin>` block». В неинтерактивной сессии Claude
Code stdin не закрыт и данных не даёт — процесс ждёт до таймаута.

**Лечение, обязательное всегда:** `</dev/null` в конце команды. Без него неинтерактивный вызов
ненадёжен независимо от промпта.

### 2. Недоверенный каталог — мгновенный выход 1

```
Not inside a trusted directory and --skip-git-repo-check was not specified.
```

Возникает, когда `-C` указывает вне git-репозитория (например на каталог `scratchpad`).
**Лечение:** `--skip-git-repo-check`, либо `-C` внутрь репозитория. Отказ мгновенный и громкий —
это лучший из четырёх.

### 3. Потолок длины промпта — молчаливое зависание

Апстрим измерил: тривиальный промпт ~6 с, однострочный вопрос по коду ~12 с, **55-строчная
полезная нагрузка — стоп после 280 с**. Порог, принятый апстримом, — 1200 символов.

**Лечение, проверенное дважды на этом прогоне (62 с и 86 с вместо зависания):** длинную постановку
класть В ФАЙЛ, а промптом давать одну строку «прочитай `<файл>` и ответь на вопросы из него».
Codex читает файл сам, и через промпт проходит ~120 символов вместо 6000.

### 4. Претензия на обрезанную страницу — ложноположительная находка

Наблюдение этого прогона, но НЕ про Codex: агент-валидатор (Claude) получил обрезанную выборку
страницы поставщика и объявил отсутствующей цитату, которая на странице есть. Класс общий для любого
делегирования: **вывод «этого там нет» требует второго независимого обращения**, прежде чем стать
находкой. Стоимость ошибки здесь была бы сменой модели во всём каноне.

## Рабочая форма вызова

```bash
# 1) постановка — в файл (обходит потолок длины)
cat > "$BRIEF" <<'EOF'
…длинная постановка…
EOF

# 2) вызов: stdin закрыт, каталог доверен, модель и усилие названы, ответ в файл
timeout 900 codex exec \
  --skip-git-repo-check \
  -m gpt-6-astra -c model_reasoning_effort="high" \
  -s read-only \
  -C "$DIR" \
  -o "$ANSWER" \
  "Прочитай $BRIEF в текущем каталоге и выполни, что там написано." </dev/null > "$LOG" 2>&1
echo "exit=$?"

# 3) доказательство: модель из журнала, непустой ответ
grep -m1 '^model:' "$LOG"        # фактическая модель, а не запрошенная
test -s "$ANSWER" || echo "ПУСТОЙ ОТВЕТ — это НЕ «замечаний нет»"
```

Для записи файлов: `-s workspace-write` вместо `read-only`, плюс барьер приземления ниже.
`--dangerously-bypass-approvals-and-sandbox` не применять: снимает песочницу целиком.

## Барьер приземления (обязателен при записи)

Codex пишет файлы СВОИМ рантаймом, асинхронно относительно вызывающего. Наивный конвейер запускает
ревью до того, как запись дошла до диска, и выставляет «работа не выполнена» по РЕАЛЬНО изменённому
коду — апстрим наблюдал это как оценку D на приземлившихся правках.

```bash
BEFORE=$(git -C "$REPO" status --porcelain | sort | sha256sum)
# …вызов codex exec -s workspace-write…
for i in $(seq 1 30); do
  AFTER=$(git -C "$REPO" status --porcelain | sort | sha256sum)
  [ "$AFTER" != "$BEFORE" ] && break
  sleep 1
done
[ "$AFTER" = "$BEFORE" ] && echo "изменений НЕТ — это отказ, а не пустая работа"
```

## Что доказывает модель, а что нет

- **Имя модели в allowlist доказывает, что оно ПИШЕТСЯ**, а не что она отвечает. Пробуй один раз за
  прогон и записывай фактическое имя из строки `model:` журнала.
- **`~/.codex/config.toml`** несёт `model` и `model_reasoning_effort` по умолчанию; `-c
  model_reasoning_effort="high"` перекрывает на вызов. Фактическое усилие изнутри ответа не
  наблюдаемо — записывать как ЗАПРОШЕННОЕ, не как подтверждённое.
- **Codex не лодка при исчерпании лимита Claude.** Обёртка `codex:codex-rescue` — сам агент Claude:
  при настоящем исчерпании умирает и она. Защита от лимита — предупреждающее переключение ДО него,
  а не аварийное после.

## Предполётная проверка

```bash
node "$(find / -name codex-companion.mjs -path '*scripts*' 2>/dev/null | head -1)" setup --json
# {"ready": true, "codex": {...}, "auth": {"loggedIn": true, ...}}
```

`ready: false` или отсутствие companion — работу делает Claude, и это записывается, а не
замалчивается: тихая подмена исполнителя обесценивает cross-family review
([`cross-family-review`](../../CLAUDE.md) — политика владельца от 2026-09-21).

## Анти-паттерны

| Анти-паттерн | Почему плохо |
|---|---|
| Вызов без `</dev/null` | 580 с ожидания и таймаут, наблюдалось |
| Длинная постановка прямо в промпте | стоп после 280 с на 55 строках, измерено апстримом |
| Пустой ответ прочитан как «замечаний нет» | заглушка обёртки выглядит как чистое ревью |
| Ревью сразу после записи, без барьера | «работа не выполнена» по приземлившемуся коду |
| `--dangerously-bypass-approvals-and-sandbox` ради удобства | снимает песочницу целиком |
| Codex как запасной путь при лимите Claude | обёртка — сам агент Claude и умирает вместе с ним |
| Одна находка «цитаты нет на странице» без второго обращения | ложноположительная; на этом прогоне чуть не сменила модель в каноне |
