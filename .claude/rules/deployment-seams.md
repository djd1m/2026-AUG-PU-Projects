# Дефект живёт в стыке, а не в модуле

## Maturity: 🔴 Alpha · Извлечено: 2026-08-27 · Источник: `projects/01-testimonials-senja` · v1.0

Правило для любого проекта, который собирается из нескольких контейнеров за
reverse-proxy. Оно не про качество кода — весь код ниже был корректен.

## Утверждение

**Модуль, корректный в изоляции, ничего не гарантирует о системе.** Три худших дефекта
проекта 01 имели одинаковую форму: каждая часть по отдельности правильная, дефект — в
допущении, которое одна часть делала о другой, и которое нигде не проверялось.

| Дефект | Код | Конфигурация | Что сломалось |
|---|---|---|---|
| Обходимый rate limit | `extractClientIP` берёт ПОСЛЕДНИЙ `X-Forwarded-For` — верно за прокси | `web` опубликован через `ports:` | Прокси обходится, «последний элемент» становится значением атакующего, лимит обнуляется сменой заголовка |
| Все ссылки на localhost | `urls.ts` читает `BASE_URL` — верно | `BASE_URL` не передан сервису в compose | Тихий дефолт; стенд поднимается, страницы открываются, но каждая выданная ссылка нерабочая |
| Виджет не грузится ни на одном сайте | Приложение ставит `Access-Control-Allow-Origin` — верно | Caddy ставит его же | Два одинаковых заголовка → браузер отвергает CORS. `curl` не видит: он не применяет CORS |

Общее: **юнит-тесты зелёные, сборка проходит, контейнеры здоровы, дефект в проде.**
Ни один из трёх не мог быть пойман тестом одного модуля, потому что ни один модуль не
был сломан.

## Почему обычные проверки промахиваются

- **Юнит-тест** проверяет функцию. Здесь сломана не функция, а то, что до неё не доехало
  значение — или доехало, но окружение отменяет её посылку.
- **`curl`** проверяет HTTP. CORS — политика браузера; `curl` её не применяет и потому
  подтвердит работоспособность сломанного.
- **Проверка страниц по отдельности** («открылась ли `/`, открылась ли `/dashboard`»)
  подтверждает рендер. Дефект `BASE_URL` жил не в странице, а в ссылке, которую страница
  выдаёт наружу.
- **Healthcheck контейнера** подтверждает, что процесс жив. Все три дефекта — при живом
  процессе.

## Три обязательных стража (слой 1 по лестнице стоимости обнаружения)

Каждый — детерминированный скрипт, не суждение агента. Запускать ДО того, как результат
отдан человеку, и после каждого изменения `docker-compose.yml`.

### 1. Полнота проброса переменных

```bash
bash scripts/check-env-wiring.sh          # 0 — всё проброшено, 1 — есть потери
```

Сверяет `process.env.X` в исходниках сервиса с `environment:` этого сервиса в
`docker compose config`. **Не опирается на `.env.example`** — на прогоне он сам был
неполон, и опора на неполный файл унаследовала бы его пробел.

Две ошибки, допущенные при написании самой проверки (обе — ложное «всё хорошо»):
- регэксп `[A-Z_]+` без цифр обрезает `S3_ENDPOINT` до `S`; правильный — `[A-Z][A-Z0-9_]*`;
- список исключений должен быть **явным**, иначе молчаливое исключение прячет настоящую потерю.

### 2. Граница доверия к прокси

```bash
bash scripts/check-port-conflicts.sh .    # включает раздел «за reverse-proxy»
```

Если в compose есть Caddy/nginx/traefik — он единственная дверь. Любой сервис,
опубликованный рядом, позволяет обойти прокси **вместе со всем, что прокси гарантирует**.
Код, доверяющий заголовку от прокси, обязан быть закрыт от прямого доступа, и это
обязано **проверяться**, а не подразумеваться. Подробности и запрет на публикацию БД —
[`docker-ports.md`](docker-ports.md).

### 3. Сквозной пользовательский сценарий на РАЗВЁРНУТОМ стенде

```bash
bash scripts/check-cjm.sh https://стенд.example
```

Не «открылась ли страница», а **пройти путь целиком**: зарегистрироваться → создать →
получить ссылку → **перейти по выданной ссылке** → отправить → увидеть результат.
Дефект `BASE_URL` виден только на шаге «перейти по выданной ссылке» — то есть только
тогда, когда проверка **пользуется** тем, что система выдала, вместо того чтобы
запрашивать известный ей самой адрес.

Проверять на том адресе, по которому системой будут пользоваться, а не на `localhost`:
внешний адрес — часть конфигурации, и именно он ломался.

## Анти-паттерны

| Анти-паттерн | Почему плохо |
|---|---|
| Проверять UI, передав переменные через `docker run -e` | Обходит compose — то есть ровно тот слой, где живёт дефект. Проверять надо запущенный стек |
| Считать `curl 200 OK` подтверждением работы виджета/CORS | `curl` не применяет политику браузера; сломанный CORS отвечает 200 |
| Ставить один заголовок и в приложении, и в прокси | Дублирование ломает CORS молча. Заголовок ставит РОВНО одно место |
| «Тесты зелёные — можно отдавать» | Все три дефекта прошли зелёные тесты. Зелёный юнит-тест — утверждение о модуле, не о системе |
| Добавить проверку в чек-лист ревьюера | Ревьюер поймает один случай и пропустит соседний. Стык проверяется скриптом |

## Когда правило НЕ применяется

Одиночный процесс без контейнеров, прокси и внешних адресов — стыка, о котором речь, там
просто нет. Как только появляется reverse-proxy или второй контейнер — применяется.
