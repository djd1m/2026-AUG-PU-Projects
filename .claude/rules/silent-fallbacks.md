# Тихий отказ живёт там, где есть запасной путь

## Maturity: 🔴 Alpha · Извлечено: 2026-08-27 · Источник: `projects/01-testimonials-senja` · v1.0

## Утверждение

**У каждого P0 этого прогона был graceful fallback, оставлявший систему «здоровой».**
Это не совпадение и не список частных ошибок — это место, где тихие отказы кучкуются.

| P0 | Запасной путь | Что он скрыл |
|---|---|---|
| Все выданные ссылки на localhost | Дефолт `BASE_URL = 'http://localhost:3000'` | Переменная не объявлена в compose. Приложение стартовало, 408 тестов зелёные, страницы открывались |
| Хуки не запускались | Хуки объявлены `non-blocking` | `MODULE_NOT_FOUND` из подкаталога проекта. Пайплайн шёл зелёным без единого хука |
| Тестовый стек вытеснил боевой | Имя compose-проекта по умолчанию | Контейнеры молча заменились. `ECONNREFUSED` читался как «БД не поднялась» |
| Ограничение частоты обходилось | Лимит продолжал отвечать `200` | Смена заголовка обнуляла счётчик, и ответ выглядел штатным |

Отсюда практический вывод, который стоит применять первым:

> **Аудит системы начинать с инвентаризации фолбэков.** Дефолт, `try/catch` без
> повторного броска, `|| значение`, `?? значение`, `non-blocking`, «если не смогли —
> пропустим» — это карта мест, где отказ будет невидим.

## Правило: переменная без права на дефолт

Значение, определяющее **то, что продукт отдаёт наружу**, дефолта иметь не должно.

Базовый URL, публичный домен, origin коллбэка, адрес вебхука, идентификатор магазина —
у всех них разумный дефолт превращает «неправильно настроено» в «молча неверно». Он
снимает единственный дешёвый сигнал — падение при старте — и переносит обнаружение на
человека, который откроет ссылку в проде.

Именно это и произошло: дефект нашёл владелец продукта, а не проверка.

### Реализация

```ts
function assertConfiguredInProduction(value: string | undefined): void {
  if (process.env.NODE_ENV !== 'production') return;
  // Сборка выполняется с NODE_ENV=production, но внешний адрес ей не нужен.
  if (process.env.NEXT_PHASE === 'phase-production-build') return;
  if (value) return;
  throw new Error('BASE_URL не задан. Он определяет КАЖДУЮ выдаваемую наружу ссылку …');
}
```

Три обязательных свойства:

1. **Только в проде.** В dev и test дефолт законен — иначе локальная разработка требует
   настройки, и правило начнут обходить.
2. **Сборка исключена явно.** Иначе первый же `docker build` упрётся в защиту, и её
   снимут целиком вместо того, чтобы уточнить условие.
3. **Сообщение объясняет цену, а не факт.** «BASE_URL не задан» без объяснения выглядит
   придиркой; «определяет каждую выдаваемую наружу ссылку, с дефолтом все они повели бы
   на localhost» — объясняет, почему дефолта нет намеренно.

### Проверка

```text
защита снята     ->  Tests  2 failed | 12 passed
защита на месте  ->  Tests  14 passed
```

Плюс отдельный тест, что **сборка не роняется** без переменной — иначе защита проживёт
до первого деплоя.

## Второе наблюдение: самый дорогой способ обнаружения применён четырежды

`BASE_URL`, обход rate limit, двойной CORS, запрещённый стек в постановке — каждый раз
вещь открыл руками владелец продукта или второе мнение, и каждый раз **после** этого
появлялся скрипт слоя 1.

Вывод для планирования: бюджет на сквозной прогон по развёрнутому стенду закладывать
**до**, а не после. Скрипт, написанный после инцидента, стоит инцидента.

## Анти-паттерны

| Анти-паттерн | Почему плохо |
|---|---|
| `process.env.X ?? 'разумное значение'` для внешнего адреса | Ровно механизм инцидента |
| `try { … } catch { /* не критично */ }` вокруг проверки | Проверка становится необязательной молча |
| Хук/шаг объявлен `non-blocking` «чтобы не мешал» | Не мешает и не работает — неотличимо снаружи |
| Фолбэк без записи в лог | Лишает даже дорогого способа обнаружения |
| Дефолт «чтобы тесты проходили» | Тесты и начнут проходить — на дефолте, а не на конфигурации |
