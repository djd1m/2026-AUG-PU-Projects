# promo-video — промо-ролик под наши проекты

## Назначение

Сделать для продукта из `projects/*` короткий ролик из **живых экранов стенда**, воспроизводимый одной командой
и честный: титр не обещает того, чего нет в кадре; в кадре нет цен, чужих брендов, служебных фикстур и выдуманных
данных без пометки. Инструмент выбран и не пересматривается навыком: **Remotion 4.0.529** на общем шаблоне
[`promo/remotion/shared/`](../../../promo/remotion/shared/README.md) (выбор — [`promo/RESULT.md`](../../../promo/RESULT.md),
[`docs/research/promo-videos/04_decision.md`](../../../docs/research/promo-videos/04_decision.md)).

## Входы

| Вход | Откуда | Обязателен |
|---|---|---|
| Проект `projects/<NN-slug>/` | README «простыми словами», CLAUDE.md (маршруты), `globals.css` (токены), шрифт | да |
| Выданный адрес стенда | квитанция развёртывания / README проекта | да (без него — только сцены-заголовки, ролик не делается) |
| Строка проекта в инвентаре | [`05_project_inputs.md`](../../../docs/research/promo-videos/05_project_inputs.md) — экраны без входа, «Нельзя» | да; нет строки — предварительный проход модуля 02 (первый шаг) её создаёт |
| Решения владельца | стиль, адрес в финале, музыка (по умолчанию нет), лимит платных вызовов | да, спросить до модуля 03 |
| Образ `promo-render:2026-09-29` | [`promo/render-image/`](../../../promo/render-image/README.md) | да для модулей 03–05 |

## Роли

| Роль | Кто | Что делает | Чего не делает |
|---|---|---|---|
| **Координатор** | Claude (основной сеанс) | модуль 01 (каркас), выдаёт постановку, держит журнал серии, решает спорное по правилам, собирает страницу владельцу, зовёт Codex | не пишет в worktree исполнителя; не правит продукт |
| **Исполнитель, часть A** | агент Claude в своём worktree | модуль 02 (до съёмки) → 01 (сценарий по каркасу координатора) → 03: инвентарь, сценарий, запись, квитанция записи | не монтирует; не правит шаблон и продукт |
| **Исполнитель, часть B** | тот же агент после сигнала «шаблон готов» | модули 04 → 05 → 07: конфиг, рендер, замеры, окончательные ворота | не переснимает записи без решения координатора |
| **Проверяющий** | Codex (другое семейство, read-only) | модуль 06 §6: титры ↔ кадр, запреты, единообразие, замеры, шаблон, вердикт | не рендерит; его «нет» не отменяется исполнителем |
| **Владелец** | человек | стиль, адрес, музыка, лицензия Remotion, учётки, публикация | — |

Один исполнитель на проект: у ролика одна пара «записи ↔ конфиг», делить её между агентами — два писателя в одном файле.

## Последовательность модулей

Порядок исполнения — НЕ порядок номеров: инвентарь нужен сценарию раньше, чем сценарий нужен записи, а проверка готовых
mp4 возможна только после рендера (вердикт Codex по навыку, §1).

| Шаг | Модуль | Кто | Ворота на выходе (команда → код) |
|---|---|---|---|
| 1 | [`02`](modules/02-inputs-and-forbidden.md) — инвентарь и «нельзя показывать», **предварительный проход до съёмки** | исполнитель A | `gate-forbidden.sh` → 0 (8 классов, у каждого способ; зоны, если кадрирование) |
| 2 | [`01`](modules/01-brief-and-scenario.md) — постановка, каркас 5 сцен, правила титров | координатор → исполнитель A | `SCENARIO.md`: 5 сцен, у каждого титра кадр-доказательство (0 пустых); длина титров — на шаге 4 |
| 3 | [`03`](modules/03-capture.md) — запись экранов | исполнитель A | `capture.sh` → 0 · размеры записей (ffprobe) · `gate-log.mjs` → 0 (с длительностью файла, демосеансы) · `gate-git.sh` → 0 · платные вызовы ≤ лимита |
| 4 | [`04`](modules/04-assemble-and-render.md) — зависимости, конфиг, предполётные ворота, рендер | исполнитель B | `gate-config.sh` → 0 · `gate-transitions.mjs check` → 0 (опасные стыки покадрово) · `stills.sh` → 0 · `gate-dirty.sh` → 0 · `render-run.sh` → 0 · `grep` переопределений → 1 |
| 5 | [`05`](modules/05-measure-and-receipt.md) — замеры и квитанции | исполнитель B | `gate-receipt.sh … since` → 0 (внутри `render-run.sh`); sha256 mp4 + конфиг + записи; категории попыток → 0 |
| 6 | [`07`](modules/07-final-check.md) — **окончательные ворота готового видео** | исполнитель B | `gate-media.sh` → 0 · `storyboard.sh` → 0 · `gate-verdict.sh` → 0 (листы с sha вердикта, титры ↔ кадр, демо-пометка) · публикация `cmp` |
| сквозной | [`06`](modules/06-swarm-protocol.md) — рой, блокировка, сторож, Codex | координатор | файловые квитанции всех исполнителей; `gate-watchdog.sh` после операций вне `render.sh`; вердикт Codex; узкий второй круг |

Модуль 06 читается **до** запуска любого исполнителя, если проектов больше одного: он задаёт worktree, имена
контейнеров, блокировку рендера и формат квитанции. Для одного ролика без роя из него нужны §3 (сторож хоста),
§4 (лимиты контейнера) и §6 (проверка Codex).

**Ворота по модулям.** У каждого модуля в разделе Quality Gate — порог, команда и действие по коду. Общий контракт
скриптов `scripts/*`: `0` — проверено, чисто · `1` — дефект доказан и назван · `2` — проверка НЕ выполнена (нет входа,
образа, журнала). Код `2` никогда не «готово». Каждый скрипт испытан на испорченном входе (код 1) и на отсутствующем
(код 2) — перечень испытаний в самих модулях.

## Где лежат выходы: `promo/` — отдельный проект серии (исключение из §9 протокола)

[`skill-interface-protocol`](../../rules/skill-interface-protocol.md) §9 требует выводить результаты навыка прямо в
проект, а AGENTS.md — хранить документы и телеметрию фичи в выбранном проекте `projects/<NN>/`. **Этот навык пишет в
`promo/` в корне репозитория, и это решение, а не пропуск** (вердикт Codex по навыку, §1):

- промо-ролик — не фича продукта: он не меняет код `projects/<NN>/`, его не собирает и не выкатывает стенд проекта;
- ролики серии делят один шаблон, один образ, один lockfile Remotion, одну блокировку рендера и одну таблицу замеров —
  разнести их по шести проектам значило бы шесть копий общего кода (`promo/remotion/shared/`, `promo/render-image/`);
- серия проверяется целиком одним вердиктом Codex и сравнима только в одном месте (`promo/RESULT-SERIES.md`).

Поэтому `promo/` считается **отдельным проектом серии**: `promo/<что>/<proj>/` — выходы по продукту, `promo/SERIES.md` —
журнал, телеметрия и вердикты серии — в `promo/`. В `projects/<NN>/` навык ничего не пишет; ссылка на ролик в README
продукта — отдельное решение владельца. Если владелец решит иначе (ролики внутри `projects/<NN>/promo/`), меняется
только эта таблица путей и `render.sh`.

## Критерий готовности (из [`promo/SERIES.md`](../../../promo/SERIES.md) + правки после вердиктов Codex)

Каждый пункт — с воротами; «готово» только при 0 во всех.

1. Три mp4 — `probe.sh` (в `render.sh`): 45,000000 с, 1350 **пакетов**, `yuv420p`, tv/bt709, 30/1, H.264 High; повтор 16:9
   побайтно совпал (`REPRO=1`) — `gate-receipt.sh` → 0. **Декодированные** 1350 кадров и 0 аудиопотоков — `gate-media.sh`
   → 0 (модуль 07 п. 1): `probe.sh` считает пакеты и аудио не смотрит.
2. `SCENARIO.md` — титры сцен для правки владельцем + «что титры НЕ обещают» (о чём титр молчит) + таблица «нельзя →
   как обойдено» с 8 классами — `gate-forbidden.sh` → 0.
3. `README.md` — одна команда повтора, адреса и тайминги записей (из `t_file_s` журнала), отклонения от сценария.
4. `MEASUREMENTS.md` — сборка и рендер отдельно, `memory.peak`, `host_load1`, sha256 трёх mp4, конфига и
   использованных записей; раздел «Окончательная проверка»: путь к листам, список проверенных интервалов, исходы.
5. `ITERATIONS.md` — каждая попытка ровно с одной категорией инструмент / среда / исполнитель (`awk` модуля 05 → 0);
   части A и B одним итогом; платные вызовы.
6. **Ни одного титра без кадра-доказательства** — `captions-proof.tsv` + `gate-verdict.sh` → 0 (модуль 07 п. 4–5).
7. **Пометка демо-данных видна и читаема во всех трёх форматах на всём интервале**, пока вымышленные данные в кадре:
   интервалы в `demo-intervals.tsv`, на каждом листе раскадровки этих интервалов (шаг 0,25 с и стыки ±5 кадров) —
   `видна`; проверяет `gate-verdict.sh` → 0. Пометка «внизу страницы», срезанная кадрированием, — отказ.
8. Бюджет исполнителя — 120 мин активной работы, ≤ 8 попыток с правками; превышение — остановиться и отчитаться.

  молчит (прокрутка без события), страж не найдёт — поэтому модуль 03 требует событие `scroll.top`.
- Ограничения шаблона (модуль 04, таблица): №5 `footnote` и №6 `titleColor` внесены; №1–№4, №7–№10 — нет, для них навык

- Музыка и озвучка — вне навыка (решение владельца); лицензия Remotion при команде от 4 человек — открытый вопрос владельцу.
