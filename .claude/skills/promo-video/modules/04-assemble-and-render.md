## Process

1. **Папка проекта** (шаблон, шаг 1): `project.config.ts`, `public/rec -> /assets` (симлинк), `public/fonts/` —
   TTF продукта с OFL либо симлинк на `/usr/local/share/fonts` (Onest 400/500/600/700 в образе). Свой `package.json` не
   заводить: он и lockfile — общие в `promo/remotion/`. В новом worktree `node_modules` нет — `render.sh` сам сделает
   `npm ci` в образе (N2: 12,3 с, сеть bridge, вне замера).
2. **Конфиг** — копия `n6/project.config.ts`, поля по таблице README шаблона: `id`, `name`/`tagline`/`url`, `tokens`
   (`#rrggbb`), `font` (400/600/700), `scenes` (Σ = 45 с, последняя — `outro`). Тексты титров живут ТОЛЬКО в конфиге;
   `SCENARIO.md` — копия для чтения владельцем, после правок конфига её обновить.
3. **Сегменты из журнала**: `{from, to, seconds, caption}` — `from/to` из `record-log-*.json` и кадра, не из памяти.
   Ускорение = (to−from)/seconds; ожидание сервера вырезать отдельным сегментом, а не ускорять ×10. Координаты `crop`
   снимать с кадра записи (`ffmpeg -ss <t> -frames:v 1`, команда в README шаблона, шаг 2).
4. **Раскладка фиксирована** шаблоном: 16:9 — запись сверху, титр снизу (18 %); 9:16 — титр сверху (15 %); 1:1 — титр
   сверху (30 %). **9:16 показывает запись целиком**: `crop` для `tall` падает, пока нет `allowTallCrop: true`; ставить
   его только осознанно и с причиной в README (N2 — ради цены в кабинете).
5. **Контрольные кадры до полного рендера** (≈ 1 мин вместо ≈ 5 на формат): команда `stills` из README шаблона, кадры
   60 250 600 820 1000 1250, лист `out/final/stills/promo-*-sheet.png` — смотреть все три формата. Искать: обрезанный
   интерфейс, третья строка титра, текст за полосой, значимый элемент у края (N4 степпер, N1 карточки).
6. **Рендер одной командой**:
   ```bash
   REPRO=1 bash promo/remotion/shared/render.sh <proj>   # три формата + повтор 16:9 со сверкой sha256
   bash promo/remotion/shared/render.sh <proj> 1x1       # черновик одного формата
   ```
   Скрипт — ЕДИНСТВЕННОЕ место среды и кодирования: `--cpus=2.5 --memory=4g --network none`; `--codec=h264 --crf=20
   --pixel-format=yuv420p --color-space=bt709 --offthreadvideo-cache-size-in-bytes=536870912 --concurrency=2`; Chromium
   образа (`--browser-executable`). В проекте эти флаги не повторять и не менять. Каждый флаг заслужен отказом пилота
   ([`promo/RESULT.md`](../../../../promo/RESULT.md), журнал N6 ревизии `8a9dc756`):

   | Флаг | Без него |
   |---|---|
   | `--offthreadvideo-cache-size-in-bytes=512MB` | кэш `<OffthreadVideo>` берёт долю памяти ХОСТА → `Compositor exited with signal SIGKILL` на кадре 550 в 4 ГБ |
   | `--concurrency=2` | Remotion округляет квоту cgroup ВНИЗ: при 2,9 CPU `concurrency 3` — отказ «Available CPU cores: 2» |
   | `--color-space=bt709` | `--pixel-format=yuv420p` в 4.x отдаёт `yuvj420p` (полный диапазон) |
   | `--cpus=2.5` | хостовый сторож перезапускает контейнер с мгновенным CPU > 300 % (модуль 06 §3) |
   | `Config.setCachingEnabled(false)` | время сборки зависит от кэша webpack прошлых запусков |

7. **Коды `render.sh`**: `0` — все форматы прошли `probe.sh`, сторож не трогал контейнеры; `1` — дефект доказан и назван
   (поле, файл, контейнер); `2` — проверка НЕ выполнена (нет образа, записей, журнала сторожа, имя контейнера занято).
   Сломанный конфиг бандл ещё собирает (webpack модуль не исполняет) — падает первый кадр с `project.config.ts (<proj>): …`
   в `logs/<формат>.txt`: читать журнал, а не код. Испытано: конфиг на 46 с → код 1.
8. **Раскадровка готовых mp4** (не только `stills`): модуль 02 п. 5 — листы с шагом 0,25 с по интервалам риска всех
   трёх форматов. Это и есть «просмотр глазами» критерия готовности: Codex вынес «нет» N1, потому что контрольные кадры
   не показали, что пометка «пример» есть только в последние 2 с.
9. **Публикация**: скопировать `out/final/{16x9,9x16,1x1}.mp4` в `promo/dist/<proj>/` (единственные mp4 в git),
   sha256 копии = sha256 из квитанции.

## Известные ограничения шаблона и что исправить (не внесено на 29.09; источник — Codex §5, DEC-S-04)

Править шаблон — задача владельца шаблона (`promo/remotion/shared/**`), не исполнителя проекта. До правки —
обходы из правой колонки.

| # | Ограничение | Что исправить в шаблоне | Обход до исправления |
|---|---|---|---|
| 1 | `validateProject` проверяет только непустоту текста: три блока титула N4 прошли | проверка вёрстки после загрузки шрифтов во всех форматах: число строк ≤ 2, текст внутри полосы, длинный `url` | ≤ 45 знаков на строку вручную (модуль 01) + лист `stills` каждого формата |
| 2 | `crop` — область, которую надо ВМЕСТИТЬ (`place()`), а не маска: вокруг видна остальная запись | явная маска прямоугольника или режим строгой обрезки; в README различить «вместить» и «скрыть» | считать видимое окно для каждого куска и писать его в комментарий конфига (N2); либо другая раскладка |
| 3 | `to > from` не гарантирует, что конец сегмента есть в файле; стыки не проверяются | preflight по `ffprobe` используемых файлов: длительность ≥ `to`, размер = `size` | `ffprobe` записей в README записи; `to` ≤ длительности, сверка с журналом (N2: «Отправлено» 22,5 с в конфиге против ~24 с в README) |
| 4 | одна дорожка = один файл → смена файла = новая сцена с затемнением 0,4 с (N1/N2/N5: 5 смысловых сцен стали 8/8/6) | `file` на уровне сегмента; монтажный стык отдельно от смысловой сцены | дробить сцены и описать это в README («5 смысловых = N технических») |
| 5 | одно семейство шрифта; нет постоянной сноски; успешная загрузка шрифта не доказывает кириллицу | роли шрифтов заголовок/текст; поле `footnote` на сцену (DEC-S-02); проверка глифов | N4: два TTF под одним `family` через насыщенности (700 — Unbounded, 400/600 — Onest), хрупко; пометка внутри записи; кадр с «ё» и «—» |
| 6 | цвет названия в финале = `accent` (N1 ≈ 1,9:1) | отдельный `titleColor` с проверкой контраста ≥ 4,5:1 | взять контрастный токен продукта в `accent` или фон из другого токена (N4) |
| 7 | `render.sh`: фиксированные пути `out/final`, `rm -rf bundle` до захвата блокировки, нет блокировки всего прогона → два запуска одного проекта перетирают друг друга | каталог запуска `out/<run-id>/`, `flock` проекта на весь прогон, в квитанцию хеши конфига, записей, шрифтов и бандла | один исполнитель на проект (модуль 06 §1); не запускать `render.sh <proj>` дважды параллельно |
| 8 | `probe.sh` считает видеопакеты, аудиопотоки не проверяет; `render.sh` сводит код 2 вложенной проверки к 1 | `-count_frames` (декодированные кадры) + требование «аудиопотоков 0»; пробрасывать 2 как 2 | отдельный `ffprobe -show_streams` на отсутствие `codec_type=audio` в `MEASUREMENTS.md` |
| 9 | README шаблона: «всё без сети, под flock» шире реализации — `npm ci` идёт с `--network bridge` без блокировки, пример `stills` без `flock` | уточнить README | писать в `MEASUREMENTS.md` как есть: установка с сетью, вне замера |

## Dependencies

- Образ `promo-render:2026-09-29` (REQUIRED) — без него `render.sh` отдаёт 2.
- Remotion 4.0.529 и общий lockfile `promo/remotion/package-lock.json` (REQUIRED).
- Журнал сторожа `/var/log/crypto-watchdog/watchdog.log` читаемый (REQUIRED для кода 0: иначе перезапуски не проверить → 2).
- `frontend-design` (OPTIONAL) — только если владелец меняет вид финала.

## Reusability

`render.sh` + `probe.sh` — переносимая пара «один скрипт среды и кодирования + страж формата с тремя кодами» для любого
headless-рендера в контейнере с лимитом cgroup; таблица флагов п. 6 — список тихих умолчаний, которые под cgroup надо
задавать явно.
