## Process

1. **Папка проекта** (шаблон, шаг 1): `project.config.ts`, `public/rec -> /assets` (симлинк), `public/fonts/` —
   TTF продукта с OFL либо симлинк на `/usr/local/share/fonts` (Onest 400/500/600/700 в образе). Свой `package.json` не
   заводить: он и lockfile — общие в `promo/remotion/`.
2. **Зависимости — ДО `stills`.** В новом worktree `node_modules` нет; `render.sh` ставит их сам, а команда `stills`
   README шаблона сразу зовёт `bundle` и на свежем worktree падает (Codex §2). С 1.2 установку при отсутствии
   `node_modules` делает `stills.sh` (п. 5) — тот же `in-container.sh install`, что в `render.sh` (сеть bridge, вне замера,
   контейнер `promo-<proj>-install`). Отдельной инлайн-команды больше нет: песочница агента её отвергала (замечание 8).
3. **Конфиг** — копия `n6/project.config.ts`, поля по таблице README шаблона: `id`, `name`/`tagline`/`url`, `tokens`
   (`#rrggbb`), `font` (400/600/700), `scenes` (Σ = 45 с, последняя — `outro`). Тексты титров живут ТОЛЬКО в конфиге;
   `SCENARIO.md` — копия для чтения владельцем, после правок конфига её обновить. **Сегменты из журнала**:
   `{from, to, seconds, caption}` — `from/to` = `t_file_s` событий из `record-log-*.json` (модуль 03 п. 5), уточнённые
   по кадру, не по памяти. Ускорение = (to−from)/seconds; ожидание сервера вырезать отдельным сегментом, а не
   ускорять ×10. Координаты `crop` и границы кусков — с листа кадров записи с метками секунд файла:
   `bash .claude/skills/promo-video/scripts/frames.sh <proj> <запись> <from> <to> <лист.png> [all|шаг]` (0 — лист;
   1 — интервал вне файла; 2 — нет записи/образа или > 120 кадров). Испытано на `a-tour-mobile.webm` N3: 24,6–25,1 с `all`
   → 0 (13 кадров, полоса видна на 24,60–24,72); `55–60` → 1; `5–5` → 1; `0–10 all` (250 кадров) → 2; нет файла → 2.
4. **Предполётные ворота конфига — ДО `stills` и рендера:**
   ```bash
   bash .claude/skills/promo-video/scripts/gate-config.sh <proj>; echo "rc=$?"   # вывод: $A/out/final/proof/config-inspect.tsv
   ```
   Импортирует конфиг в `promo-render` (Node 24, `--network none`, `--cpus=1 --memory=1g`) и проверяет: титры ≤ 2
   строк при переносе по 45 знаков; у КАЖДОГО сегмента файл есть в записях, ffprobe-размер = `size`, длительность
   файла ≥ `to`, `0 ≤ from < to`; видимое окно каждого куска не задевает `forbidden-zones.tsv` (модуль 02 п. 5); Σ = 45 с.
   Печатает `VISIBLE` (видимое окно каждого куска по формату) и `BOUNDARY` (стыки для раскадровки модуля 07).
   Коды: 0 · 1 — дефект назван · 2 — конфиг не импортируется / ffprobe не ответил / зоны нечитаемы. Проверено на N2:
   настоящий конфиг → 0; титр 110 знаков → 1; `to=99` при файле 59 с → 1; `size` 390×844 при файле 780×1688 → 1;
   несуществующий файл → 1; зона цены задета → 1; нет проекта → 2. **До правки шаблона №3 — этим скриптом вручную;
   после — preflight в `render.sh`.**

   **Видимая область `crop` — формула `place()`** (`promo/remotion/shared/src/Promo.tsx`). `crop` — не маска, а область,
   которую надо ВМЕСТИТЬ целиком; вокруг видна остальная запись. Область видео формата: ширина `W` = ширина кадра,
   высота `H` = высота кадра − полоса титра (`round(высота × доля)`, доля 16:9 — 0,18; 9:16 — 0,15; 1:1 — 0,30):
   16:9 → 1920×886, 9:16 → 1080×1632, 1:1 → 1080×756. Для записи `sw×sh` и `crop {x,y,w,h}`:
   ```text
   s = min(W / w, H / h)                                   масштаб
   по каждой оси (area = W или H, len = sw или sh, c = x + w/2 или y + h/2):
     rendered = len × s
     offset = rendered ≤ area ? (area − rendered)/2 : min(0, max(area − rendered, area/2 − c × s))
   видимое окно исходника: [ max(0, −offset/s) ; min(len, (area − offset)/s) ]
   ```
   Пример N2, сцена QR в 9:16: `owner-qr-desktop.webm` 1920×1080, `tall.crop = {x:590, y:0, w:740, h:1080}`, область
   1080×1632: `s = min(1080/740, 1632/1080) = min(1,4595; 1,5111) = 1,4595`; по x: rendered 2802 > 1080,
   offset = min(0, max(−1722; 540 − 960×1,4595 = −861)) = −861 → окно x **590–1330**; по y: rendered 1576 ≤ 1632 →
   поля по 28 px, окно y **0–1080**. `gate-config.sh` печатает ровно это: `VISIBLE tall 13.00-17.00 owner-qr-desktop.webm
   4-17.5 x 590–1330 y 0–1080`. Обратный пример той же сцены: `wide.crop = {x:590, y:240, w:740, h:470}` в области
   1920×886 даёт окно x **451–1469** — по x видно на 278 px больше, чем `crop`. Считать руками не нужно: окно берётся из
   `config-inspect.tsv`, а запрет задаётся зоной, которую проверяет скрипт.
4а. **Опасные стыки — покадрово, ДО рендера** (модуль 02 п. 5а; квитанция N3, замечание 1 + Codex):
   ```bash
   K=.claude/skills/promo-video/scripts; A=/home/dz-projects-2026/.promo-assets/<proj>
   node $K/gate-transitions.mjs make <proj> $A/out/final/proof/config-inspect.tsv $A $A/out/final/proof/transitions \
     promo/remotion/<proj>/forbidden-zones.tsv                 # листы КАЖДОГО кадра опасных кусков + verdict.tsv с «?»
   # просмотреть листы, в verdict.tsv: чисто | полоса | другое:<что>
   node $K/gate-transitions.mjs check <proj> $A $A/out/final/proof/transitions; echo "rc=$?"
   ```
   Окно перехода = [предыдущее событие файла; `*.open`/`scroll.top` + 0,5 с]; кусок, чей видимый прямоугольник
   пересекает хоть одну зону и чьи секунды задевают окно ±0,5 с, получает лист каждого кадра. `полоса` → расширить зону
   до этих кадров → `gate-config.sh` 1 → сдвинуть кусок → снова `make`/`check`. Коды check: 0 — все `чисто`; 1 —
   `полоса`/`другое` или лист с другой записи (sha256); 2 — `?`, нет файлов. Испытано на N3 (копии): настоящий конфиг
   (круг 3) → 4 опасных стыка, все листы просмотрены `чисто` → 0; кусок сцены 4 9:16 с 24,7 с (круг 2) → лист 24,70–25,46,
   кадр 24,72 с тёмной полосой «Лаборатория» → `полоса` → 1; повторный `make` перенёс 4 исхода → 0; запись подменена → 1;
   нет журналов → 2; нет листов → 2. Это та вспышка, которую 1.1 пропустил до готового mp4.
5. **Контрольные кадры до полного рендера** (≈ 1 мин вместо ≈ 5 на формат) — только после п. 4:
   ```bash
   bash .claude/skills/promo-video/scripts/stills.sh <proj>; echo "rc=$?"   # листы out/final/stills/promo-*-sheet.png
   ```
   Кадры 60 250 600 820 1000 1250, лист на формат — смотреть все три. Искать: обрезанный интерфейс, третья строка титра,
   текст за полосой, значимый элемент у края (N4 степпер, N1 карточки), кадр с «ё» и «—». Скрипт: установка при
   отсутствии `node_modules`, бандл **вне каталога записей** (`.promo-assets/.stills-<proj>/`, удаляется в конце — иначе
   ELOOP, ограничение шаблона №10), удаление своего остатка `out/final/bundle-dev`, `flock` общей блокировки рендера,
   сторож с ожиданием его обхода. Коды: 0 · 1 — бандл/кадр упал (журнал `logs/stills.txt`) или сторож трогал · 2 — нет
   проекта/записей/образа, имя занято. Команду `stills` из README шаблона не использовать.
   Испытано 29.09 на копиях N3 (конфиг и записи в scratchpad, с подложенным `out/final/bundle-dev/public/rec -> /assets`):
   настоящий конфиг → 0, три листа, `bundle-dev` и бандл вне каталога удалены (ждал блокировку за рендером N3);
   сцена на 1 с длиннее (46 с) → 1 «сцены дают 46 с»; нет проекта → 2; нет записей → 2.
6. **Рендер одной командой — с доказанным исходом**:
   ```bash
   bash .claude/skills/promo-video/scripts/gate-dirty.sh <proj>                   # 0: грязны только документы проекта
   REPRO=1 bash .claude/skills/promo-video/scripts/render-run.sh <proj>           # три формата + повтор 16:9
   bash .claude/skills/promo-video/scripts/render-run.sh <proj> 1x1               # черновик одного формата
   ```
   `render-run.sh` зовёт `promo/remotion/shared/render.sh` и **ждёт его до конца**, затем `gate-receipt.sh` с `since` —
   квитанция обязана быть ЭТОГО запуска (`started` ≥ момента запуска). Фоном — только так, чтобы ждущий ждал этот
   процесс: фоновая задача агента или `setsid -w bash …/render-run.sh <proj>`. **Не** `setsid bash render.sh …; echo $?`:
   `setsid` из лидера группы форкается и возвращает 0 до начала рендера (N3, 19:16: `rc=0` до рендера — замечание 2);
   и **не** «в `receipt.txt` есть `result=green`»: зелёная квитанция могла остаться от прошлого запуска (N3: после упавшего
   рендера 3 ворота прошли по файлам рендера 2 — уточнение Codex). Итог пишется и в `logs/run-<since>.rc`. Коды: 0 —
   render.sh 0 и квитанция этого запуска зелёная; 1 — красный рендер или квитанция; 2 — не выполнено. Испытано на
   подделках render.sh: форк с немедленным 0 при старой зелёной квитанции → 1 «квитанция не этого запуска»; свежая
   зелёная → 0; render.sh 2 → 2; нет каталога → 2.
   Скрипт — ЕДИНСТВЕННОЕ место среды и кодирования: `--cpus=2.5 --memory=4g --network none`; `--codec=h264 --crf=20
   --pixel-format=yuv420p --color-space=bt709 --offthreadvideo-cache-size-in-bytes=536870912 --concurrency=2`; Chromium
   образа (`--browser-executable`). В проекте эти флаги не повторять и не менять. Каждый флаг заслужен отказом пилота
   ([`promo/RESULT.md`](../../../../promo/RESULT.md), журнал N6 ревизии `8a9dc756`):

   | Флаг | Без него |
   |---|---|
   | `--offthreadvideo-cache-size-in-bytes=512MB` | кэш `<OffthreadVideo>` берёт долю памяти ХОСТА → `Compositor exited with signal SIGKILL` на кадре 550 в 4 ГБ |
   | `--concurrency=2` | Remotion округляет квоту cgroup ВНИЗ: при 2,9 CPU `concurrency 3` — отказ «Available CPU cores: 2» |
   | `--color-space=bt709` | `--pixel-format=yuv420p` в 4.x отдаёт `yuvj420p` (полный диапазон) |
   | `--cpus=2.5` | хостовый сторож перезапускает контейнер с мгновенным CPU > 300 % (модуль 06 §3) |
   | `Config.setCachingEnabled(false)` | время сборки зависит от кэша webpack прошлых запусков |

7. **Коды `render.sh` — как есть в коде, не как обещано в шапке.** `0` — все форматы прошли `probe.sh`, сторож не
   трогал контейнеры. `2` — только то, что проверяется ДО операций: нет проекта, неизвестный формат, нет образа, нет
   записей, журнал сторожа не читается, имя контейнера занято. **Всё, что случилось после старта операций, — `1`**:
   упавший `bundle` (`|| exit 1`), упавший рендер, `HIT` сторожа и — важно — **код 2 самого `probe.sh`** (нет mp4,
   ffprobe не прочитал): `render.sh` делает из любого ненулевого `probe.sh` `FAIL=1`. Значит, `1` из `render.sh` — не
   всегда «дефект доказан»: читать `logs/receipt.txt` и `logs/<формат>.txt`; строка `❌ …проверка НЕ выполнена` от
   `probe.sh` означает «не выполнено», а не «файл плохой». **До правки шаблона №8 — различать по журналу вручную;
   после — `render.sh` пробрасывает 2 как 2.** Сломанный конфиг бандл ещё собирает (webpack модуль не исполняет) —
   падает первый кадр с `project.config.ts (<proj>): …` в `logs/<формат>.txt`. Испытано: конфиг на 46 с → код 1.
8. **Дальше — [модуль 05](05-measure-and-receipt.md) (квитанции) и [модуль 07](07-final-check.md)** (раскадровка готовых

## Quality Gate

| Проверка | Команда | Порог | Код → действие |
|---|---|---|---|

```bash
command grep -rnE --include='*.ts' --include='*.tsx' --include='*.js' --include='*.mjs' --include='*.cjs' \
  --include='*.json' --include='*.sh' -e '--(crf|concurrency|pixel-format|color-space|codec|offthreadvideo-cache)' \
  -e '\b(setConcurrency|setCrf|setPixelFormat|setColorSpace|setCodec|setOffthreadVideoCacheSizeInBytes)\b' \
  promo/remotion/<proj>/; echo "rc=$?"     # 1 — чисто · 0 — найдено (строки выше) · 2 — ошибка/нет каталога
```
Рекурсивно, только исходники: `MEASUREMENTS.md` законно цитирует флаги (с `*.md` n1 и n2 давали ложное «найдено»);
`public/rec` — симлинк на записи, `grep -r` по нему не идёт. Проверено: n1, n2, n4, n5, n6 → 1; `Config.setConcurrency(6)`
в копии проекта → 0; `promo/remotion/nope/` → 2. Прежняя команда без `-r` по каталогу давала 2 «Is a directory» при
пустом stdout — ложный проход при проверке «вывод пуст» (Codex §5).

## Dependencies

- Образ `promo-render:2026-09-29` (REQUIRED) — без него `render.sh` отдаёт 2.
- Remotion 4.0.529 и общий lockfile `promo/remotion/package-lock.json` (REQUIRED).
- Журнал сторожа `/var/log/crypto-watchdog/watchdog.log` читаемый (REQUIRED для кода 0: иначе перезапуски не проверить → 2).
- `frontend-design` (OPTIONAL) — только если владелец меняет вид финала.

## Reusability

`render.sh` + `probe.sh` — переносимая пара «один скрипт среды и кодирования + страж формата с тремя кодами» для любого
headless-рендера в контейнере с лимитом cgroup; таблица флагов п. 6 — список тихих умолчаний, которые под cgroup надо
задавать явно.
