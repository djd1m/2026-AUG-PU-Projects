# Модуль 01: постановка и сценарий-каркас

Эталоны: [`promo/CAPTURE-BRIEF.md`](../../../../promo/CAPTURE-BRIEF.md) (постановка исполнителю),
[`promo/remotion/n2/SCENARIO.md`](../../../../promo/remotion/n2/SCENARIO.md) (сценарий с разделами «не обещают» и
«нельзя → обход»), дефекты титров — [`promo/VERIFY-SERIES-CODEX.md`](../../../../promo/VERIFY-SERIES-CODEX.md) §1.

## Input

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `proj` | строка `a-z0-9-` (`n1`…`n6`) | да | имя папки `promo/remotion/<proj>/`, префикс контейнеров |
| `project_dir` | путь `projects/<NN-slug>/` | да | README «простыми словами» — источник формулировок |
| `inventory_row` | строка `05_project_inputs.md` | да | сценарий продукта, экраны без входа, «Нельзя» |
| `owner_decisions` | стиль, адрес финала, музыка | да | см. §«Что решает владелец»; нет ответа — ставить значение по умолчанию и помечать «не подтверждено» |
| `stand_url` | URL | да | ВЫДАННЫЙ развёртыванием адрес, не `localhost` и не голый IP |

## Process

1. **Постановка исполнителю** — копия структуры `CAPTURE-BRIEF.md`: обязательные документы, часть A (сценарий, запись,
   фикстура, платные вызовы, README записи, коммиты), часть B (после сигнала координатора), критерий готовности,
   бюджет (120 мин, ≤ 8 попыток), WORK_UNIT_ID и TRACE_PATH (модуль 06 §5).
2. **Каркас — 5 смысловых сцен, ровно 45 с** (правило серии, [`promo/SERIES.md`](../../../../promo/SERIES.md)):

   | # | Смысл | Длительность в серии | Что в кадре |
   |---|---|---|---|
   | 1 | боль клиента | 5–7 с | сцена `title`: 1–2 строки на фоне токенов, вторая — акцентом |
   | 2 | шаг 1 продукта | 10–11 с | первое действие пользователя на стенде (ввод адреса, фото, создание точки) |
   | 3 | шаг 2 / результат | 13–15 с | то, ради чего продукт: ответ с источником, калории, клипы, три двери |
   | 4 | распространение | 8–9 с | виджет / ссылка / QR / карточка — как результат уходит к другим людям |
   | 5 | финал | 6–7 с | сцена `outro`: имя продукта, подзаголовок, адрес |

   Сцена 4 — именно распространение. У N2 QR и макеты попали в сцену 2, а сцена 4 стала «получением обращения» —
   Codex засчитал нарушение каркаса (§1). Если распространение не снимается (N6: экран установки за входом) —
   это решение владельца, а не замена титра.
3. **Для каждой сцены записать**: экран (маршрут), действие, какой файл записи и секунды внутри него будут
   доказательством титра. Нет доказательства — нет титра (п. 4).
4. **Титры — правила** (все — проверяемы чтением конфига):
   - 1–2 строки на кусок, **≤ 45 знаков на строку** (в 9:16 и 1:1 шаблон переносит после ~45; в 16:9 после ~70 —
     [`shared/README.md`](../../../../promo/remotion/shared/README.md) шаг 2). Третья строка — дефект.
   - **Не обещать титром того, чего нет в кадре.** Глагол титра описывает действие, которое ВИДНО.
   - Без канцелярита и обобщений, которые не доказаны («через неделю бросают»).
   - Без цен, названий тарифов, чужих брендов (модуль 02).
   - Цифры в титре — только из кадра или из измеренного файла.
5. **Реестр типовых дефектов** (из вердикта Codex, каждый встречался):

   | Проект | Было | Что не так | Стало (DEC-S-01 / Codex) |
   |---|---|---|---|
   | N6 | «Одна строка кода — и бот на вашем сайте» | в кадре окно чата предпросмотра, экран `<script>` не снят (за входом) | «Окно бота — на вашем сайте, без переделки страниц»; каркас восстанавливается только кадром установки |
   | N6 | «Вставьте адрес сайта. Через минуту бот отвечает по вашим материалам.» | 68 знаков — риск третьей строки в 9:16/1:1 | «Вставьте адрес сайта — создайте помощника» |
   | N5 | «Зритель переходит и делает свои клипы» | запись кончается страницей с кнопкой, перехода нет | «На каждом клипе — метка с короткой ссылкой на КлипМейкер» |
   | N2 | «Гость сканирует QR и видит три равные двери» | сканирования нет, гостевая открыта напрямую | «По QR — три способа оставить отзыв» |
   | N2 | «Довольные — на Карты, недовольные — вам» | внушает сортировку гостей по настроению; в кадре — свободный выбор | «Отзывы на Картах. Обратная связь — вам» |
   | N2 | «…не в публичный разнос» | оценочное | «Сообщение появится в вашем кабинете» |
   | N4 | три блока в первом титре | нарушено «1–2 строки»; «Через неделю бросают» не доказано | «Считать калории вручную — скучно.» / «Сфотографируйте тарелку.» |
   | N4 | «Ошиблась порция — поправьте» | ошибается распознавание или человек, не порция | «Порция не та? Измените вес.» |

6. **Расхождение титра и кадра, которое осталось,** — поле `note` сцены в конфиге и раздел «Что титры НЕ обещают»
   в `SCENARIO.md` (эталон — N2). Расхождение без записи — дефект, записанное — решение владельца.
7. **Финал** = `name` + `tagline` + `url`. Адрес — только подтверждённый владельцем (N5: `clipmkr.ru` на 29.09 не
   подтверждён — открытый вопрос, `RESULT-SERIES.md`). Цвет названия с контрастом к фону ≥ 4,5:1 (N1: акцент
   `#6701ef` на тёмном ≈ 1,9:1 — Codex «нет»).

## Output

- `promo/remotion/<proj>/SCENARIO.md`: таблица 5 сцен (время, экран и действие, титр, кадр-доказательство),
  «Что титры НЕ обещают», «Нельзя показывать → как обойдено» (из модуля 02), после части B — «Как смонтировано».
- Постановка исполнителю (файл координатора или текст задачи агента) с WORK_UNIT_ID и TRACE_PATH.

## Quality Gate

| Проверка | Как | Блокирует |
|---|---|---|
| Σ сцен = 45 с, 5 смысловых сцен, последняя — финал | чтение `SCENARIO.md`; позже `validateProject` шаблона падает на ≠ 45 с | да |
| Каждая строка титра ≤ 45 знаков, ≤ 2 строк | `awk` по строкам `caption:`/`text:` конфига (длина в символах, не байтах: `LC_ALL=C.UTF-8`) | да |
| У каждого титра назван кадр-доказательство | таблица `SCENARIO.md` | да |
| Сцена 4 — распространение | чтение | да, иначе решение владельца в `SCENARIO.md` |
| Адрес финала подтверждён владельцем | ссылка на ответ владельца | нет, но «не подтверждено» в итоге |

Слой: длина строк и Σ 45 с — слой 1 (скрипт/шаблон); «титр ↔ кадр» — слой 3–4 (просмотр + Codex, модуль 06 §6).

## Dependencies

- `frontend-design` (OPTIONAL) — только вкус финала; fallback — раскладка шаблона как есть.
- README проекта и строка инвентаря (REQUIRED).

## Что решает владелец (спросить один раз, до модуля 03)

| Вопрос | Умолчание серии |
|---|---|
| Стиль (светлая/тёмная, токены) | тема продукта по умолчанию, токены из `globals.css` |
| Адрес в финале | адрес стенда из README; помечать «не подтверждён», пока владелец не ответил |
| Музыка | нет (решение 29.09); только CC0/Public Domain с источником и лицензией |
| Съёмка за входом (фикстура) | разрешена одна фикстура на проект (модуль 03 §4) |
| Сцена, которую нельзя снять честно | не подменять титром: вынести владельцу «снять / убрать сцену / заменить смысл» |

## Reusability

Каркас и правила титров не зависят от Remotion: те же 5 сцен и реестр дефектов годятся для HyperFrames (запасной
инструмент пилота) и для статичных карточек. Реестр дефектов пополнять из каждого нового вердикта Codex.
