# Модуль 07: окончательные ворота проверки готового видео

Последний шаг перед публикацией: проверяются **готовые mp4**, а не конфиг и не контрольные кадры. Вынесен из модуля 02
(вердикт Codex по навыку, §1: ворота «раскадровка готовых mp4» в модуле инвентаря делали модуль 02 незавершаемым до
модулей 03–04). Скрипты — [`../scripts/`](../scripts/); каждый испытан на испорченном входе (журнал испытаний —
квитанция правки навыка, `WORK_UNIT_ID=promo-skill-fix-1`).

## Input

| Параметр | Тип | Обязателен | Описание |
|---|---|---|---|
| `proj` | `^[a-z0-9-]+$` | да | как в модуле 04 |

| `demo-intervals.tsv` | `promo/remotion/<proj>/` | да, если в кадре вымышленные данные | секунды ГОТОВОГО ролика, строки `6-17` |

## Process

Все команды — из корня репозитория; `A=/home/dz-projects-2026/.promo-assets/<proj>/out/final`,
`K=.claude/skills/promo-video/scripts`.

1. **Файлы — декодированные кадры и отсутствие аудио.** `probe.sh` шаблона считает пакеты (`-count_packets`) и аудио не
   смотрит (ограничение шаблона №8). До правки шаблона №8 — вручную; после — в `probe.sh`/`render.sh`:
   ```bash
   T0=$(date '+%Y-%m-%d %H:%M:%S'); bash $K/gate-media.sh "$A" <proj>; echo "rc=$?"
   bash $K/gate-watchdog.sh promo-<proj>-media "$T0"
   ```
   Внутри: `ffprobe -count_frames -select_streams v:0 -show_entries stream=nb_read_frames` = 1350 и
   `ffprobe -select_streams a -show_entries stream=index | wc -l` = 0 для каждого формата, размер по формату.
   Проверено: настоящие `promo/dist/n2` → 0; 1x1 с тихой дорожкой → 1 «аудиопотоков 1»; 1x1 на 44 с → 1
   «декодированных кадров 1320»; нет 1x1.mp4 → 2.
2. **Раскадровка — весь ролик и КАЖДЫЙ стык.**
   ```bash
   T0=$(date '+%Y-%m-%d %H:%M:%S'); bash $K/storyboard.sh <proj> "$A" "$A/proof/config-inspect.tsv"; echo "rc=$?"
   bash $K/gate-watchdog.sh promo-<proj>-storyboard "$T0"
   ```
   Делает: весь ролик с шагом 0,25 с (4 листа по 12 с на формат, 180 кадров) **плюс** каждый стык сцены и куска
   (`BOUNDARY` из `config-inspect.tsv`, у каждого формата свои) покадрово, ±5 кадров — лист 11×1. Шаг 0,25 с оставляет
   промежутки по 7 кадров при 30 fps (Codex §4); вспышки живут на стыках, поэтому стыки — покадрово. Листы — в
   `$A/proof/sheets/` (устойчивый путь, не scratchpad), `index.tsv` — лист, формат, вид, интервал, **sha256 mp4**;
   `verdict.tsv` — лист, исход, дефект, демо-пометка, **sha256 mp4, по которому вынесен исход**, что видно. N2: 46
   листов, 1 мин 20 с при `--cpus=2.5`.
   **Перерендер (1.2; квитанция N3, замечание 12):** `storyboard.sh` пересобирает листы и ПЕРЕНОСИТ исход листа, только
   если лист того же имени и интервала снят с mp4 с тем же sha256 (формат не изменился — у N3 16:9 и 1:1 побайтно
   совпали в трёх рендерах); остальные листы получают `?`. Досматривается ровно изменённое. В 1.1 старый `verdict.tsv`
   сохранялся целиком, а `gate-verdict.sh` сверял sha только в `index.tsv` (он пересобирается) — исходы листов
   изменённого 9:16 молча переживали перерендер. Испытано на N3 (копии): тот же mp4 → «перенесено 36, к просмотру 0»;
   9x16.mp4 подменён → «перенесено 24, к просмотру 12».
3. **Просмотр и вердикт по каждому листу — `verdict.tsv`** (глаз, слой 4; фиксируется строкой, проверяется п. 5):

   | Столбец | Закрытый список |
   |---|---|
   | исход | `принят` · `отклонён` |
   | дефект | `нет` · `цена` · `бренд` · `ip` · `ключ` · `титр-обрезан` · `элемент-обрезан` · `демо-пометка-пропала` · `другое:<что>` |
   | демо-пометка | `видна` · `не видна` · `нет-демо-данных` |

   **Критерий отказа — любое из:** цена, тариф или оплата; чужой бренд или продукт; голый IP или внутренний адрес;
   ключ, `.env`, личный чат; титр обрезан или третьей строкой; значимый элемент (кнопка, поле, число, ответ) обрезан
   краем; пометка демо-данных пропала хотя бы на одном кадре листа. «Почти не видно» — отказ.
4. **Титр ↔ кадр — `captions-proof.tsv`**, по строке на КАЖДЫЙ титр над записью (`CAPTION screen` в
   `config-inspect.tsv`), TAB:
   `титр · файл записи · интервал в файле (сек, «12,5-14») · что в кадре доказывает сказанное · исход`.
   Исход `принят` только если глагол титра ВИДЕН в названном интервале. Пример N6 сцены 4 (запись `widget-desktop.webm`
   0–12 с — окно чата на странице предпросмотра, экран установки `<script>` не снят):

   | Титр | Исход | Почему |
   |---|---|---|
   | «Одна строка кода — и бот на вашем сайте.» | отклонён | строки кода в кадре нет |
   | «Окно бота — на вашем сайте, без переделки страниц» (DEC-S-01) | отклонён | в кадре страница предпросмотра продукта, не сайт клиента |
   | «Окно бота — так его увидят посетители.» | принят | в кадре окно чата в том виде, в каком его ставит виджет |

   Если честного титра нет — вопрос владельцу «снять / убрать сцену / заменить смысл» (модуль 01), не запись `note`.
5. **Ворота вердикта — блокирующие:**
   ```bash
   bash $K/gate-verdict.sh "$A/proof" "$A" "$A/proof/config-inspect.tsv" promo/remotion/<proj>/captions-proof.tsv \
     /home/dz-projects-2026/.promo-assets/<proj> [promo/remotion/<proj>/demo-intervals.tsv]; echo "rc=$?"
   ```
   `1` — если хоть один лист `отклонён`, дефект ≠ `нет`, на демо-интервале пометка не `видна` (во всех трёх
   форматах: у каждого формата свои листы), титр без строки или `отклонён`, файл записи из строки не существует,
   sha256 mp4 в `index.tsv` ≠ текущему файлу (смотрели другой рендер), **sha256 в строке `verdict.tsv` ≠ sha листа**
   (исход вынесен по другому рендеру). `2` — остался `?`, значение не из списка, нет файла, строка `verdict.tsv` без
   sha256 (формат до 1.2 — пересобрать раскадровку, исходы неизменённых листов перенесутся). Испытано 29.09 на N3:
   настоящий `verdict.tsv` (формат 1.1) → 2 «нет sha256 — пересобрать»; после `storyboard.sh` того же mp4 → 0; 9x16
   подменён → 2 (12 листов `?`); sha чужого рендера в строке → 1; нет `verdict.tsv` → 2. Проверено на N2 (синтетическое заполнение — испытание стража, не просмотр N2): «?» → 2; всё `принят`
   → 0; лист `отклонён/цена` → 1; титр без строки → 1; титр `отклонён` → 1; листы от другого mp4 → 1; демо-интервал
   17–31 с пометкой `нет-демо-данных` → 1, с `видна` → 0.
6. **Квитанция рендера:** `render-run.sh` → 0 (модуль 04 п. 6) — квитанция ЭТОГО запуска; вручную —
   `bash $K/gate-receipt.sh <proj> "$A/logs/receipt.txt" "" <since>` → 0 (модуль 05 п. 9). Раскадровку и ворота пп. 1–5
   запускать только после 0 этого шага: иначе они проверят mp4 прошлого рендера (N3, рендер 3).
7. **git:** `bash $K/gate-git.sh <proj>` → 0 (модуль 03, Quality Gate).
8. **Публикация**: скопировать `$A/{16x9,9x16,1x1}.mp4` в `promo/dist/<proj>/` (единственные mp4 в git) и сверить:
   ```bash
   for f in 16x9 9x16 1x1; do cmp "$A/$f.mp4" promo/dist/<proj>/$f.mp4 || echo "❌ $f"; done
   ```
   После копии — повторить п. 5 со вторым аргументом `promo/dist/<proj>`: sha256 обязаны совпасть с `index.tsv`.
9. **В `MEASUREMENTS.md`** раздел «Окончательная проверка»: путь `$A/proof/`, число листов по формату, **список
   проверенных интервалов** (`cut -f2,4 $A/proof/index.tsv`), sha256 трёх mp4, исход каждого из пп. 1, 5–7 с кодом
   возврата, отклонённые листы и что с ними сделано.

## Output

- `$A/proof/{sheets/*.png,index.tsv,verdict.tsv,config-inspect.tsv}` — вне git, путь в `MEASUREMENTS.md`.
- `promo/remotion/<proj>/captions-proof.tsv` (+ `demo-intervals.tsv`) — в git.
- `promo/dist/<proj>/{16x9,9x16,1x1}.mp4` — в git, побайтно равны `out/final`.

## Quality Gate

| Проверка | Команда | Порог | Код → действие |
|---|---|---|---|
| декодированные кадры, аудио, размер | `gate-media.sh` | 1350 кадров, 0 аудио, размер формата | 1 → перерендер; 2 → выяснить, «готово» нельзя |
| весь ролик и стыки просмотрены, ни одного отказа | `gate-verdict.sh` (листы) | все листы `принят`/`нет` | 1 → править монтаж/раскладку, раскадровка заново; 2 → досмотреть |
| каждый титр доказан кадром | `gate-verdict.sh` (`captions-proof.tsv`) | все титры `принят` | 1 → честный титр или вопрос владельцу |
| пометка демо-данных видна на всём интервале во всех форматах | `gate-verdict.sh` + `demo-intervals.tsv` | `видна` на каждом листе интервала | 1 → пометка в записи/раскладке, перерендер |
| сторож не трогал ни одну операцию | `gate-watchdog.sh` после пп. 1–2 | 0 срабатываний | 1 → переснять операцию; 2 → повторить через 3 мин |
| опубликованное = проверенное | `cmp` + повтор п. 5 на `promo/dist` | побайтно | ≠ → не публиковать |

Все ворота блокирующие: вердикт «готово» выносится только при 0 во всех строках. Слой: пп. 1, 5–8 — слой 1
(детерминированно проверяют файлы и ДЕКЛАРАЦИЮ просмотра); что изображено на листе — слой 4 (глаз), OCR в образе нет.

## Dependencies

- Образ `promo-render:2026-09-29` (REQUIRED) — ffmpeg/ffprobe; нет образа → все скрипты отдают 2.

## Reusability

`storyboard.sh` + `gate-verdict.sh` — пара «детерминированная выборка кадров + закрытый вердикт по каждому листу с
привязкой к sha256», годится для любого видео, где запреты проверяются глазом: запись без просмотра не проходит, а
просмотр другого файла ловится хешем.
