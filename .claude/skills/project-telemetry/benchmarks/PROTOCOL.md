# Benchmark project-telemetry v1

Это локальная проверка извлечения и интерпретации, не оценка качества всех LLM
и не калибровка сроков разработки. Python 3.9+, стандартная библиотека.

## Фиксированные данные и разделение

- `development.json`: 15 случаев по известным пробелам аудита P1/P2/N3. Четыре
  сохраняют конкретные метрики исходных паспортов с provenance/hash; остальное
  синтетическое. Имена/даты идентичности заменены, исходные журналы не копируются.
- `holdout.json`: отдельно подготовленные случаи. Их ожидаемые ответы фиксируются
  до открытия разработчиком и до первого запуска кандидата. После открытия набор
  становится публичным регрессионным корпусом, а не вечным независимым holdout.
- `holdout-adjudicated.json`: отдельная исправленная версия эталона после первого
  запуска. Три ожидания признаны автором ошибочными: stage не равен run, а парные
  waits не доказывают полноту пауз. Исходный holdout и первые scores сохранены.
- `interpretation.json`: шесть вопросов для агента: singular/plural модель, граница
  приёмки, inclusive usage, цена/overhead, причина паузы, необоснованный прогноз.
  Они не исполняются parser-runner: это отдельный поведенческий тест навыка.

Ожидания нельзя менять ради зелёного кандидата. Исправление ошибки в эталоне требует
обоснования по исходным данным и сохранения первой оценки. Если кандидат дорабатывался
после открытия holdout, называй последующий результат регрессией, а не слепой оценкой.

## Запуск из каталога skill

```sh
python3 -B benchmarks/run.py --analyzer scripts/analyze.py \
  --suite benchmarks/development.json --suite benchmarks/holdout-adjudicated.json
python3 -B scripts/test_analyze.py
```

Для сравнения тот же runner и те же байты suite получают `--analyzer` с путём
предыдущего скрипта. Исходная версия этого эксперимента находится в commit `cb35d14`
по `.claude/skills/project-telemetry/scripts/analyze.py`; её можно извлечь через
`git show` в отдельный временный файл. Не копируй старый скрипт поверх действующего.

Exit 0 — все assertions и инвариант неизменности входов выполнены; 1 — есть неуспех.
Выход JSON содержит SHA скрипта и suite, результаты каждого assertion, исключения
и медиану времени извлечения по пяти повторам. Сохраняй baseline и candidate отдельно.
Это cached локальный microbenchmark с малым n, не latency всей агентной задачи.
Нельзя выводить из него экономию времени пользователя, токенов или денег.

## Критерии

Обязательны: все исходные regression-тесты, отсутствие подмены unknown нулём,
отсутствие двойного счёта/недоказанного actual, сохранение конфликтов и исходников,
новые ожидаемые значения и locators. Проверяй, что намеренное удаление защиты
делает тест красным; неизменённый mutant не считается проверкой.

Отчёт даёт отдельно development, первый holdout, последующие regression, corpus
coverage и semantic smoke. Укажи числитель и знаменатель, а не один общий процент.
Набор специально обогащён известными ошибками; его score не является оценкой
распространённости ошибок или точности на случайной будущей задаче.

## Поведенческая проверка

Дай исполнителю выбранный `SKILL.md`, reference и `interpretation.json`, без эталона,
предыдущих ответов и выводов ревью. Попроси JSON `answers` с id, result,
evidence_fields, explanation. Эталон для проверки результатов:

| id | result | Требование к объяснению |
|---|---|---|
| model-alias | `"model-sol"` | Singular-поле есть; это claim экспорта, raw host log не проверен |
| partial-acceptance | `false` | Native TEST с N3 disabled не закрывает agent→N3 |
| inclusive-usage | `100` | Child уже внутри parent, не прибавлять40 |
| cost-share | `null` | Нет тарифа/функционального разделения, cache входит в input |
| pause-cause | `false` | Approval и interruption не различены; корреляция не причина |
| forecast | `null` | Несопоставимые scope и нет калибровочной серии |

Проверь не только result, но и ссылки на поля и смысл объяснения. Запиши модель,
effort, число попыток и доступные usage/время; неизвестное — null. Для сравнения
инструкций нужны одинаковая модель/effort и независимые свежие сессии с раздельными
ответами. Если хост не позволяет, отмечай только candidate smoke без эффекта A/B.
Одна серия из шести вопросов не оценивает стабильность ответов и статистическую
значимость. Можно добавить скрытые переформулировки в следующем эксперименте.

## Прогнозы времени

Для реальной калибровки прогнозов нужны сохранённые ДО начала задачи оценки,
сопоставимые AC/scope, фактическое завершение/цензурирование и интервалы ожидания.
На последовательно отложенных задачах считать MAE, смещение, покрытие и ширину
диапазона, без будущих данных в аналогах. В этом benchmark проверяется способность
отказаться от неподдержанного P80, а не точность будущих сроков.
