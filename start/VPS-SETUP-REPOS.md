# VPS в облаке — путеводитель по публичным наработкам

Проект удобно начинать в **Claude Code Web** или **GitHub Codespaces**, но в какой-то момент
приходится переключаться на локальный Mac/ПК или на **VPS в облаке**. Этот файл — карта
**публичных** репозиториев, которые закрывают этот переход.

> **Только публичные репозитории.** Их можно свободно давать студентам курса.
> Часть инфраструктурных наработок лежит в приватных репозиториях и сюда сознательно не вошла —
> о ней смотрите в [`/research/vps-sources/`](../research/vps-sources/).

## 🔴 Шаг 7: проверка docker-compose до первого деплоя

Не абстрактная гигиена. На общем VPS с проектами предыдущего потока это уже приводило к
компрометации: контейнеры PostgreSQL, поднятые с публичным портом и дефолтным паролем, были
взломаны, внутрь залили криптомайнер, который съел почти весь CPU сервера.

**Чек-лист перед `docker compose up -d` на публичном VPS:**

- [ ] БД **не** биндится на `0.0.0.0`. Внутри compose сервисы видят друг друга по имени —
      публиковать порт Postgres наружу не нужно вообще. Если очень нужно — только `127.0.0.1:5432:5432`
- [ ] Пароли не дефолтные (`postgres`, `admin`, `root`) — даже «на неделю» и «это же учебный проект»
- [ ] При смене пароля в **существующем** volume нужен `ALTER USER` — переменная окружения
      применяется только при первичной инициализации тома, иначе останется старый пароль
- [ ] Порты наружу открыты только у reverse-proxy (80/443), у остальных сервисов — `expose`
- [ ] `.env` не в образе и не в git

Боты сканируют новые VPS непрерывно. Открытый порт БД находят за часы, не за недели.

## Защита и доступ

### [djd1m/vps-security](https://github.com/djd1m/vps-security)
Bash-скрипты + документация, последний коммит 2026-06-20. **Идемпотентный** хардининг Ubuntu VPS:
SSH hardening, fail2ban, iptables-persistent. Плюс утилиты tmux и Chromium-MCP.

Четыре сценария запуска: вручную / через промпт Claude Code / автоустановка Claude Code вместе
с хардинингом / полностью автономно. Секретов в репозитории нет.

**Чем ценен:** идемпотентность — повторный запуск безопасен. Для студента это правильный вход:
ошибиться и перезапустить не страшно.

**Пригодность для курса: высокая.**

> ⚠️ Любой хардининг закрывает SSH. Перед применением: держите **вторую SSH-сессию открытой**
> и проверьте, что ключ работает. Иначе есть шанс потерять доступ к серверу.

### [djd1m/dgx-remote-access](https://github.com/djd1m/dgx-remote-access)
Один интерактивный HTML-runbook, коммит 2026-06-12. Три уровня — минимальный / оптимальный /
максимальный:

- WireGuard-сервер на роутере
- SSH-хардининг: `PasswordAuthentication no`, смена порта, `AllowUsers`
- xrdp по VPN, включая фикс «чёрного экрана» на GNOME/Wayland
- **WireGuard-exit на облачном VPS** — реальные команды: `wg genkey`, `iptables MASQUERADE`,
  `sysctl net.ipv4.ip_forward=1`, systemd-юнит
- UFW с конкретными правилами

Готовый чек-лист «получил VPS → защитил его». Несмотря на название, к DGX привязана только часть.

**Пригодность для курса: высокая.**

### [djd1m/claude-code-vless-proxy](https://github.com/djd1m/claude-code-vless-proxy)
Только документация, коммит 2026-07-16. **Ключевой репозиторий, если студенты в РФ.**

Схема: `Claude Code → 127.0.0.1:10809 (локальный xray) → Cloudflare → ваш сервер → Anthropic`.
Через прокси идёт **только трафик Claude Code** (`HTTPS_PROXY`/`HTTP_PROXY`), остальной трафик
машины — напрямую.

Протокол — VLESS с транспортом **XHTTP** (сознательно вместо WebSocket: устойчивее на фильтрующих
сетях, обоснование есть в README), поверх TLS с fingerprint chrome, за Cloudflare — обходит DPI,
который режет голые IP, но не адреса Cloudflare.

Что внутри: установка xray одной командой, полный JSON-конфиг клиента с тремя плейсхолдерами,
автозапуск через systemd, верификация сравнением `curl` с прокси и без, проброс переменных
окружения именно в сессию Claude Code (разово и через `~/.bashrc`), отдельно — нюанс `claude login`.
Есть замечание: при запуске под другим пользователем, под `sudo` или в контейнере переменные
окружения нужно прописывать отдельно.

Секретов и реальных доменов нет — везде плейсхолдеры.

> ⚠️ **Главный пробел:** репозиторий закрывает **только клиентскую** сторону. Серверная настройка
> VLESS+XHTTP инбаунда за Cloudflare в нём не описана — сервер предполагается готовым заранее.

**Пригодность для курса: высокая** (для клиентской части).

## Провижининг и деплой

### [djd1m/cloudru-vm-cli](https://github.com/djd1m/cloudru-vm-cli)
Полноценный CLI на Go/Cobra, единственный коммит 2026-07-02. Провижининг VM в Cloud.ru **и**
деплой docker-compose одной командой:

```bash
cloudru-vm deploy
```

IAM-аутентификация, автоматический floating IP, авто-сайзинг VM, идемпотентные повторные деплои.
Собирается из исходников — готовых релизов пока нет.

**Пригодность для курса: средняя** — специфично под Cloud.ru и требует Go-тулчейна.

### [djd1m/dgx-setup](https://github.com/djd1m/dgx-setup)
Самодиагностирующиеся install-скрипты (Claude Code, LiteLLM, bootstrap прокси) +
`docker-compose.litellm.yml`. Несмотря на название — **платформенно-независимы**, применимы
к любому VPS, не только к DGX.

**Пригодность для курса: высокая** для шага «поставить Claude Code на сервер».

### [djd1m/2026-PU-APR-LESSON-01](https://github.com/djd1m/2026-PU-APR-LESSON-01)
Проект прошлого потока с рабочим `docker-compose.prod.yml` + Watchtower + Caddy — то есть ровно
тот паттерн, который задан Architecture Constraints нашего курса.

Плюс конкретные грабли, на которые уже наступали: Alpine + OpenSSL для Prisma, `.dockerignore`,
отсутствующий `DATABASE_URL`.

**Пригодность для курса: высокая** — готовый живой пример целевого паттерна.

## Чего в публичных репозиториях нет

Честные пробелы. Их придётся закрывать отдельно:

| Пробел | Комментарий |
|---|---|
| **Серверная часть VLESS+XHTTP за Cloudflare** | Клиент описан, сервер — нет. Самый заметный пробел |
| **Reverse-proxy с автоTLS: готовый рецепт** | Caddy виден в примере проекта, но отдельной инструкции нет |
| **Бэкапы и учения по восстановлению** | В публичных репозиториях нет; для учебного проекта — минимум `pg_dump` по cron |
| **Мониторинг и watchdog** | Нет готового решения в публичной части |
| Провижининг у AdminVPS / HOSTKEY | `cloudru-vm-cli` только под Cloud.ru, а Architecture Constraints называют AdminVPS/HOSTKEY |
| Единый сквозной сценарий «с нуля до задеплоенного проекта» | Есть куски у разных репозиториев, единого прохода нет |

Курсовые проекты предыдущих потоков (Odoo, Substack, WHOOP, Apollo, Instantly и др.) проверены
и не включены: они используют тот же типовой шаблон «Docker Compose + nginx на VPS», что уже
описан в правилах пайплайна, и нового знания о настройке сервера не добавляют. Исключение —
`2026-PU-APR-LESSON-01` выше, он попал в список из-за конкретных задокументированных граблей.
