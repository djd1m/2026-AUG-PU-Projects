## Сервер для восьми проектов курса

Рекомендация от **2026-09-09**: **16 vCPU, 32 ГБ RAM, 500 ГБ NVMe** для
одновременной работы восьми приложений и 1–2 параллельных процессов разработки
со сборками и браузерными E2E-тестами на том же VPS.

| Режим | CPU | RAM | NVMe |
|---|---|---|---|
| Учебные демо, разработка и тяжёлые сборки последовательно | 8 vCPU | 16 ГБ | 300 ГБ |
| Рекомендуемый: демо + активная разработка и тесты | 16 vCPU | 32 ГБ | 500 ГБ |
| 3–4 параллельных процесса разработки со сборками и браузерами | 16–24 vCPU | 64 ГБ | 500–1000 ГБ |

### Допущения и основание расчёта

Это прогноз для небольшой учебной посещаемости и восьми общих приложений,
а не отдельных окружений для каждого слушателя. LLM используются через внешние
API, поэтому GPU для этого режима не требуется. Локальные модели, интенсивная
обработка и массовое хранение видео требуют отдельного расчёта, особенно для
проекта 05. Стоимость внешних API не входит в ресурсы VPS.

Замер 2026-09-09 при небольшой нагрузке:

| Показатель | Значение |
|---|---|
| Текущий сервер | 8 vCPU, 16 ГБ RAM, диск 158 ГБ |
| Доступная RAM хоста | Около 8,5 ГБ |
| Свободное место после устранения переполнения диска | Около 9,4 ГБ |
| RAM работающих контейнеров проекта 01 | Около 447 МиБ |
| RAM работающих контейнеров проекта 02 | Около 116 МиБ |
| RAM работающих контейнеров проекта 03, включая варианты A–D | Около 180 МиБ |

Расход контейнеров получен через `docker stats --no-stream`; тестовые контейнеры
не включены в суммы проектов. Это моментальный замер, а не измерение пиков или
нагрузочный тест. На хосте есть другие сервисы, инструменты агентов, браузеры,
образы и кеши: умножать общее потребление сервера на `8/3` некорректно.
Конфигурация 16 vCPU / 32 ГБ — запас для комфортной разработки, а не доказанный
минимум. Прогноз нужно уточнить по пикам сборок, E2E и нагрузке всех восьми проектов.

### Эксплуатационные требования

- Ближайший приоритет — увеличить диск до 300–500 ГБ: его заполнение уже вызвало
  сбой PostgreSQL. При ограниченном бюджете можно пока оставить 8 vCPU / 16 ГБ
  RAM и выполнять тяжёлые сборки последовательно.
- Ограничивать накопление логов, временных файлов и кешей; настроить
  [автоматическую очистку кеша сборок Docker](https://docs.docker.com/build/cache/garbage-collection/)
  по возрасту и объёму. Данные БД и необходимые образы для отката не удалять
  вместе с кешами.
- Настроить уведомления о заполнении диска и нехватке памяти; резервные копии
  хранить вне этого VPS. Увеличение диска само по себе не заменяет эти меры.
- Сохранять архитектуру распределённого монолита в Docker-контейнерах.
  БД доступны только бэкенду по внутренней сети, без публикации портов наружу;
  использовать случайные пароли вместо дефолтных. Те же правила обязательны
  для тестовых стендов.

Этот раздел фиксирует требования и рекомендации; он не означает, что увеличение
VPS, мониторинг, очистка кешей или внешнее резервное копирование уже настроены.
