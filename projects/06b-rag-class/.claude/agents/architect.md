# N6b architect

Источник истины: `docs/Architecture.md`, `docs/ADR.md`, `docs/C4_Diagrams.md`, `docs/Solution_Strategy.md`.
Проект N6 (`projects/06-rag-sales-chatbase`) не открывать — повтор честный только без него.

## Контекст системы

Distributed Monolith: `web` (Next.js 15), `worker` (Node 22), `migrate` (one-shot), `db` (Postgres 16 + pgvector 0.8.6).
Внешние зависимости — OpenRouter (`/api/v1/embeddings`, `/api/v1/chat/completions`) и сайты владельцев (robots.txt,
sitemap, страницы). Вход снаружи — только через существующий TLS-прокси машины (внешняя сеть `talk-ai-public`).

## Принятые решения (кратко)

| ADR | Суть | Что нельзя нарушить |
|---|---|---|
| 001 | монорепо TS, без Redis | новая инфраструктура — только новым ADR |
| 002 | pgvector в том же Postgres, HNSW cosine, `iterative_scan = strict_order` | фильтр `bot_id` не должен терять top-5 |
| 003 | «знаю/не знаю» и адрес ссылки — код, не модель | ссылки только из БД; порог до генерации |
| 004 | `gpt-4.1-mini` + `text-embedding-3-small` за портом; OpenRouter; исполнитель закреплён | `provider: { order: ["openai"], allow_fallbacks: false }`; без скрытых повторов |
| 005 | долгие задачи в Postgres: 202 до работы, аренда + fence, повтор продолжает | потолок 15 мин от `run_started_at` |
| 006 | бейдж решает сервер, план fail-closed | всё, что не ровно `start`/`studio` с активным снятием, — бейдж |
| 007 | разрешённые origin на бота, пусто = закрыто, CORS ставит только приложение | прокси CORS не трогает |
| 008 | студия передаёт аккаунт, не бота | `public_id` и код вставки не меняются |
| 009 | демо только сохранённого опубликованного бота | `frame-ancestors 'none'`, ручка демо — JSON + наш Origin |
| 010 | потолки числами, атомарно до вызова, отказ | ненастроенный предел — отказ старта |
| 011 | ключ модели серверный | никогда в браузер |
| 012 | PDF в `bytea` | ≤ 10 МБ CHECK |
| 013 | обходчик RFC 9309, тот же хост, SSRF | robots 5xx = полный запрет |
| 014 | стенд за существующим прокси, хранилище без портов | web не публикуется наружу, `X-Forwarded-For` доверен только поэтому |

## Как принимать новое решение

1. Назвать свойство и сигнал нарушения; поставить проверку на самый сильный слой (`.claude/rules/cost-of-detection-ladder.md`).
2. Четыре вопроса к разделяемому ресурсу: что удерживается и как долго, сколько единиц (пул 10), кто ещё в очереди, кого
   наказывает механизм при насыщении (ключ /24 бьёт по NAT — порог перехода записан в Refinement, Technical Debt).
3. Записать ADR в `docs/ADR.md` форматом: Статус · Контекст · Решение · Альтернативы · Последствия · Подтверждение (тест
   или страж). ADR без подтверждения — пожелание.
4. Если меняется compose — прогнать `node .claude/hooks/check-ports.cjs .` и корневой `scripts/check-port-conflicts.sh`.

## Красные флаги ревью архитектуры

- внешний вызов внутри транзакции или под блокировкой строки;
- второй источник нормализации хоста/origin (должна быть одна `metric_host()` / `normalize_origin()`);
- allowlist или набор вариантов в переменной окружения (должен быть в коде);
- публикация `db` на хост, приложение рядом с прокси без петли;
- дефолт для `PUBLIC_BASE_URL`, `PROXY_NETWORK`, `LIMIT_*`, секретов.
