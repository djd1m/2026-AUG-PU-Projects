# Встраиваемый виджет: он живёт на ЧУЖОЙ странице

Действует, когда поставляемое — кусок, который клиент вставляет к себе: сборщик отзывов, чат-пузырь,
калькулятор. Там виджет есть ПРОДУКТ ЦЕЛИКОМ: не работает у клиента — не работает ничего.

## Своя страница — не проверка

**Проверка виджета ОБЯЗАНА выполняться на странице ЧУЖОГО origin** (origin = схема+хост+порт,
браузерное определение «другого сайта»). Другого порта достаточно: `http://localhost:8099` чужой
для `http://localhost:3000` и даёт настоящий предполётный запрос.

«Открыли свою демо-страницу, виджет отрисовался» — НЕ проверка. На своей странице origin совпадает
(предполётного запроса нет вовсе), чужого CSS нет, чужой политики безопасности нет: ни один из трёх
классов отказа там не может проявиться. Зелёный результат получен на единственной странице, чьё
поведение не имеет значения.

Механизм: **условия отказа принадлежат чужой странице, а тестируется своя.** Тот же дефект даёт
подтверждение развёртывания обращением к `localhost` — проверка обязана пользоваться адресом,
который система ВЫДАЛА, а не тем, который знает сама.

## Три класса отказа

Набор ЗАКРЫТЫЙ и ОБЯЗАТЕЛЬНЫЙ: виджет, переживший чужой CSS и умерший на чужом CSP, у клиента не
работает. Первый и третий отказывают при полностью зелёной проверке у вас.

| Класс | Признак у клиента | Лечение |
|---|---|---|
| `перекрёстный-запрос` | виджет виден, данные не идут; в консоли клиента `blocked by CORS policy`, а в вашем журнале запрос ЕСТЬ и отвечен 200 — ответ отбросил браузер | отвечать `Access-Control-Allow-Origin` с origin ХОЗЯИНА из явного списка; `OPTIONS` → 204 с `Allow-Methods`/`Allow-Headers`. С `credentials` джокер `*` НЕЛЕГАЛЕН, браузер отклонит |
| `протечка-стилей` | вёрстка едет только у клиента и у каждого по-своему: чужие reset, `* { box-sizing }`, `img { width: 100% }`, война `z-index`. Обратное направление — тоже отказ: ваши глобальные селекторы ломают хозяйскую страницу | изоляция ГРАНИЦЕЙ, а не специфичностью: Shadow DOM либо iframe; внутри `all: initial` на корне и свои единицы вместо унаследованных |
| `политика-безопасности` | виджет не появляется ВООБЩЕ; в консоли `Refused to load … violates the following Content Security Policy directive` | никаких инлайновых `<script>`/`<style>` (не требовать `unsafe-inline`); опубликовать точный список директив, который хозяин обязан разрешить (`script-src`, `connect-src`, `frame-src`, `img-src`); проверять ПОД ограничительным CSP |

**Оснастка, воспроизводящая все три:** страница по HTTP на ДРУГОМ порту, вставляющая виджет по
ПУБЛИЧНОМУ адресу, который выдало развёртывание, отдающая ограничительный `Content-Security-Policy`
и несущая враждебный CSS.

## Артефакт и ворота

`docs/embed-contract.md` — объявление плюс квитанция, по строке на каждый класс, и в каждой строке
ДОКАЗАТЕЛЬСТВО с адресом. Точная форма полей и закрытые списки значений — в шапке проверки:

```bash
node .claude/hooks/check-embed-contract.cjs .
```

`0` все три класса проверены и каждое доказательство называет ЧУЖОЙ origin · `1` дефект ДОКАЗАН и
назван (проверка на своём origin, страница `file://`, пропущенный класс, `НЕ ПРОВЕРЕН` под вывеской
выполненной проверки, доказательство без адреса, `credentials` вместе с `*`) · `2` **проверка НЕ
ВЫПОЛНЕНА** (нет контракта, нераспознанное значение, неразбираемый адрес, либо законные ответы «не
встраивается» и «НЕ ВЫПОЛНЕНА с причиной»). Код `2` никогда не значит «всё в порядке».

## Честная разметка слоя

Слои — по [`cost-of-detection-ladder`](./cost-of-detection-ladder.md).

**Слой 1 (детерминированно):** доказательство называет origin, и он не ваш; все три класса названы;
пара `credentials` + `*` отвергнута. Это проверка ДЕКЛАРАЦИИ.

**Слой 3–4 (остаётся суждением, и сузить нечем):** цел ли виджет на враждебной странице; те ли это
директивы CSP, которые нужны хозяину; не отражает ли список разрешённых origin произвольный origin
обратно. Детерминированной половины здесь быть НЕ МОЖЕТ по названной причине: у пакета ноль
зависимостей и нет браузера, а вердикт выносит только настоящий браузер на настоящей чужой странице.

**Нового семейства идентификаторов НЕТ, и это решение.** `FR-LOOK-nnn` отвечает «снятое с источника
доехало до спецификации?»; здесь снимать нечего — обязательство рождается из топологии доставки, а
не из внешности источника, и статусы `СНЯТ`/`НЕ ИЗМЕРЕНО` к нему неприменимы. Наблюдение о том, КАК
встраивается сам источник (iframe или Shadow DOM), — законная строка `FR-LOOK-nnn` оси `облик`; три
класса отказа — не она.

## Самопроверка

1. Назови origin страницы, где виджет проверяли. Совпал с origin виджета? Проверки не было.
2. Та страница отдавала CSP и враждебный CSS? Нет — проверены не те условия.
3. Адрес виджета там — тот, который ВЫДАЛО развёртывание, или тот, который ты знал заранее?
