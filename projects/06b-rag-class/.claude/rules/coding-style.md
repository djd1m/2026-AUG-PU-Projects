# Coding style — N6b

Стек: TypeScript (strict) на Node 22 во всём монорепо; Next.js 15 App Router; `pg` с пулом; esbuild для виджета.

## Структура и именование

- Пакеты: `apps/web`, `apps/widget`, `services/worker`, `packages/db`, `packages/rag`. Импорт между пакетами — по имени
  workspace (`@n6b/db`, `@n6b/rag`), не относительными путями через границу.
- Файлы — kebab-case (`metric-host.ts`), типы — PascalCase, функции и переменные — camelCase, константы окружения —
  UPPER_SNAKE. Имена сущностей и полей — как в `docs/Pseudocode.md` → Data Structures (`index_job`, `lease_fence`,
  `allowed_origins`), без синонимов.
- Закрытые множества (план `free|start|studio`, состояния задачи, исходы вопроса, превью-домены) объявляются ОДИН раз в коде
  (`packages/db/src/enums.ts`) и оттуда попадают в CHECK миграций. Окружение выбирает вариант, но не задаёт множество.
- Порядок импортов: node-встроенные → внешние → workspace → относительные.

## Паттерны

- Route Handler: разбор тела схемой → проверки порядка из `.claude/agents/planner.md` → ответ `{data}` или
  `{error: {code, message}}` с кодом из Pseudocode → API Contracts.
- Внешний вызов (OpenRouter, сайт владельца) — только через порт/адаптер с дедлайном и без скрытых повторов; никогда внутри
  транзакции или под блокировкой строки.
- Одна функция на нормализацию: `normalizeOrigin()`, `metricHost()`, `planOf()`. Вторая копия — дефект.
- Недоступность источника истины — исключение, откатывающее транзакцию, а не возвращаемое значение.
- Комментарий пишется только для ограничения, которое код не показывает сам (измеренная причина, внешний контракт).

## Known Gotchas

### TypeScript / JavaScript
- `\w` в регэкспе не совпадает с кириллицей — для текста страниц `\p{L}` с флагом `/u`.
- Приведение `req as CustomType` падает с TS2352 — через `unknown` или типизированный обработчик.
- `jest.fn(async () => v)` не удовлетворяет `jest.Mocked<T>` в strict — `mockResolvedValue`.
- `fetch` в Node 22 не бросает на 4xx/5xx — проверять `res.ok` явно (иначе 503 OpenRouter читается как ответ).
- `Number('')` === 0 — пустая строка предела не должна стать нулём; различать `undefined` и `''`.

### Postgres / pgvector
- `SET LOCAL` действует только в текущей транзакции текущего соединения; значения — через параметризованный `set_config()`.
- Фильтр `WHERE bot_id=…` применяется ПОСЛЕ скана HNSW: без `SET LOCAL hnsw.iterative_scan = strict_order` top-5 теряется.
- `FOR UPDATE` строки аккаунта клинит с внешним ключом — `FOR NO KEY UPDATE`.
- Счётчик квоты: `INSERT … ON CONFLICT DO UPDATE SET used = used + n WHERE used + n <= limit RETURNING` — одна инструкция;
  «прочитать, потом записать» проходит однопоточный тест и падает на параллельном.

### Инфраструктура
- Лимитеры и порты провайдера — синглтоны; экземпляр на запрос обходит защиту.
- Браузер не шлёт `Origin` на same-origin GET — атрибуцию хоста брать из конфиг-запроса виджета с явным `page`.
- Лимит прокси на адрес не должен считать `w.js` и статику (429 у офисов за NAT).
- Скриншот Playwright сам нарушает CSP страницы — не принимать его за дефект виджета.
- Сборка Docker монорепо — из корня (`package-lock.json` только там), `npm ci` видит манифесты ВСЕХ workspace.
