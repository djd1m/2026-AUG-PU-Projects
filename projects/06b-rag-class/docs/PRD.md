## 1. Executive Summary

### 1.1 Purpose
Владелец малого сайта за 10 минут получает чат-бота, который отвечает посетителям по его страницам и PDF и в каждом ответе
показывает, откуда ответ; если ответа в документах нет — честно говорит «не знаю» и даёт контакт.

### 1.2 Scope

**In Scope:** обход сайта по URL и загрузка PDF; индексация в pgvector (`text-embedding-3-small`, 1536); чат с RAG-ответом и
ссылкой на источник; «не знаю» со ссылкой на контакт; виджет одним `<script>` с бейджем на Free; публичная демо-страница
сохранённого бота; подаккаунты студий и передача бота клиенту; метрика недели; потолки расходов на модель.

**Out of Scope:** передача оператору, мультиязычность, аналитика диалогов, CRM, обучение на диалогах (постановка); оплата,
партнёрские выплаты, удаление аккаунта (объём сборки); сброс пароля по почте; OCR сканов; анонимное демо по чужому URL
(вариант B отвергнут владельцем); вознаграждение студий (часть C отвергнута владельцем).

### 1.3 Definitions & Acronyms

| Term | Definition |
|------|------------|
| RAG | ответ модели, собранный только из найденных фрагментов документов владельца |
| Фрагмент | кусок текста ≈500 токенов со ссылкой на страницу сайта или страницу PDF и вектором 1536 |
| Бейдж | строка «Работает на N6b» в виджете Free, ведёт на лендинг с `ref` бота |
| Внешний виджет | пара (бот, внешний хост): загрузка конфига и ≥1 вопрос с этого origin, хост не наш, не localhost, не IP, не частная сеть, не превью-домен хостинга; аккаунт не тестовый; страница перепроверена — полное определение Specification FR-n6b-15 |
| Студия | аккаунт веб-студии с подаккаунтами клиентов |

## 2. Product Vision

### 2.1 Vision Statement
> Бот, которому владелец сайта может доверить отвечать от своего имени, потому что каждый ответ можно проверить кликом.

### 2.2 Problem Statement

**Problem:** посетители малых сайтов задают одни и те же вопросы ночью и уходят без ответа; существующие боты либо требуют
сценариев, либо выдумывают, включая несуществующие ссылки (PD-INSIGHT-002).

**Impact:** потерянные обращения у С1 — «владельца малого сайта» (PD-SEGMENT-001).

**Current Solutions:** форма и почта, live-chat с оператором (Jivo), конструкторы со сценариями (Salebot), Chatbase и SiteGPT.

### 2.3 Strategic Alignment
Повтор проекта N6 на занятии: цель — показать работу пайплайна, поэтому код N6 не используется, а модули N1–N5
переиспользуются по инвентарю (PD-REUSE-001). Рост — значковая петля и демо-страница (выбор владельца, PD-CJM-001).

### 2.4 Метрики успеха

Одна таблица на проект — [`Final_Summary.md`](Final_Summary.md) → Success Metrics (цель, срок и источник значения), чтобы
источник одной метрики не расходился между документами. Главная: 15 внешних виджетов (бот × внешний хост, определение — Specification FR-n6b-15) с ≥1 вопросом за неделю (PD-METRIC-001);
текущее значение — 0 (стенда нет).

## 3. Target Users

### 3.1 Primary Persona: «Ольга, владелица пекарни с сайтом на Tilda» (С1)

| Attribute | Description |
|-----------|-------------|
| **Role** | ИП, сама ведёт сайт и прайс в PDF |
| **Demographics** | малый бизнес РФ, 1–10 сотрудников `[H]` |
| **Goals** | отвечать посетителям ночью по своему прайсу и условиям доставки |
| **Pain Points** | повторяющиеся вопросы; страх, что бот наврёт от её имени |
| **Technical Proficiency** | Low — умеет вставить код в конструктор сайта |
| **Usage Frequency** | настройка один раз, затем Weekly (дозагрузка документов) |

### 3.2 Secondary Persona: «Студия “Пиксель”, делает сайты клиентам» (С2)

| Attribute | Description |
|-----------|-------------|
| **Role** | веб-студия, 3–15 человек `[H]` |
| **Goals** | добавить клиенту ИИ-фичу и передать её клиенту |
| **Pain Points** | нет подаккаунтов и передачи бота у массовых сервисов |
| **Technical Proficiency** | High |
| **Usage Frequency** | Weekly |

### 3.3 Anti-Personas
- Контакт-центры, которым нужна передача оператору и аналитика диалогов (С3 — вне недели).
- Тот, кто хочет бота по чужому сайту без согласия владельца сайта.

### 4.2 Non-Functional Requirements

#### 4.2.1 Performance

| Metric | Requirement | Rationale |
|--------|-------------|-----------|
| Ответ посетителю p95 | ≤ 6 с | генерация 2–5 с — внешний вызов |
| «Не знаю» ниже порога p95 | ≤ 1,5 с | без вызова генерации |
| Поиск top-5 p95 | ≤ 100 мс при 200 000 фрагментов | HNSW |
| Бандл виджета | ≤ 30 KB gzip | чужие страницы, мобильные сети |

#### 4.2.2 Availability & Reliability

| Metric | Requirement |
|--------|-------------|
| Uptime на неделе | стенд без SLA; `restart: unless-stopped`, healthcheck |
| RTO | 1 час (перезапуск/откат тегов образов) |
| RPO | 24 часа (ежедневный `pg_dump`) |
| Недоступность модели | отказ с текстом «сервис ответа недоступен», не вечная загрузка |

#### 4.2.3 Security

| Requirement | Implementation |
|-------------|----------------|
| Authentication | e-mail + пароль (bcrypt), cookie httpOnly |
| Authorization | RLS по `account_id`, доступ студии к подаккаунтам |
| Data Encryption (at rest) | диск VPS; IP посетителя не хранится, только HMAC префикса |
| Data Encryption (in transit) | TLS на существующем прокси |
| Compliance | 152-ФЗ и 38-ФЗ — открытые вопросы владельцу (PD-RISK-001, PD-RISK-002) |

#### 4.2.4 Scalability

| Dimension | MVP | Предел архитектуры MVP |
|-----------|-----|------------------------|
| Аккаунты | десятки | тысячи |
| Фрагменты | тысячи | ≈ 200 000 на одном VPS |
| Вопросы/сутки | ≤ 3 000 (глобальный предел) | ограничено потолками |

## 5. User Journeys

### 5.1 Journey: «Бот на сайте за 10 минут» (вариант A)

**Persona:** Ольга · **Goal:** бот отвечает по прайсу на её сайте · **Trigger:** увидела бейдж на сайте знакомой

1. Клик бейджа → лендинг с `ref` → регистрация.
2. «Новый бот»: URL сайта + PDF → `202` и прогресс «страниц 12 из 40».
3. Песочница: «сколько стоит доставка?» → ответ со ссылкой «Прайс.pdf, стр. 3» → CTA «Вставить на сайт» / «Поделиться демо».
4. Контакт для «не знаю», домен сайта (подставлен) → `<script>` → вставка в Tilda.
5. Посетитель спрашивает в виджете → ответ со ссылкой; бейдж виден → петля.

**Error Paths:**

| Step | Error Condition | System Response | User Recovery |
|------|-----------------|-----------------|---------------|
| 2 | robots.txt недоступен (5xx) | задача «отказ» с причиной | «Повторить» позже или загрузить PDF |
| 2 | PDF — скан | «в PDF нет текста» | загрузить текстовый PDF |
| 3 | нет ответа в документах | «не знаю» + контакт | дозагрузить документ |
| 5 | домен не добавлен | виджет молчит, кабинет «добавьте домен» | добавить домен |

## 6. UI/UX Requirements

### 6.1 Design Principles
- Ссылка на источник видна под каждым ответом, всегда.
- Три различимых состояния задачи: «выполняется N из M», «готово», «отказ + причина + Повторить».
- Палитра — отраслевой фолбэк (облик источника не снят), подписан как фолбэк.

### 6.2 Key Screens/Views

| Screen | Purpose | Key Elements |
|--------|---------|--------------|
| Лендинг | вход из бейджа | «Сделайте такого бота для своего сайта», регистрация |
| Бот: источники | индексация | URL, PDF, прогресс, «Повторить» |
| Песочница | Aha | вопрос, ответ, ссылки, CTA |
| Публикация | установка | контакт, домены, `<script>`, демо вкл/выкл, «убрать бейдж» |
| Студия | клиенты | список подаккаунтов, «новый клиент», «передать» |
| Демо `/b/{slug}` | поделиться | чат, бейдж |
| `/admin/metrics` | оператор | внешние виджеты (с перепроверкой страниц), бейдж, conv% |

### 6.3 Accessibility Requirements
- WCAG 2.1 Level: AA; клавиатура, `aria-live` для ответов, контраст ≥ 4.5:1.

| Q-004 | Считать ли превью-домены хостингов внешними в метрике недели? | владелец | до подсчёта метрики | **решён** OWN-06B-005 (допущение координатора, помечено): не засчитываются, закрытый список в коде → FR-n6b-15 |
