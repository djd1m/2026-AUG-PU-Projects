# Architecture Decision Records — N6b «RAG-бот для сайта»

**Фаза:** 1 · **Дата:** 2026-09-30 · Формат: контекст → решение → альтернативы → последствия → подтверждение (чем проверяется).
Номер `ADR-nnn` не переиспользуется, в том числе после замены решения.

## ADR-001 — Distributed monolith в монорепо на TypeScript, без Redis

**Статус:** принято. **Контекст:** ограничения пайплайна (монорепо, Docker Compose, VPS); готовые модули N1–N5 на TS
(PD-REUSE-001); неделя на MVP. **Решение:** `apps/web` (Next.js 15: кабинет, API, публичные страницы, `w.js`),
`apps/widget` (esbuild-бандл), `services/worker`, `packages/db`, `packages/rag`; одна БД Postgres. Очередь, квоты и лимиты —
в Postgres, Redis не вводится. **Альтернативы:** BullMQ на Redis (N5 #18) — лишний контейнер и второе хранилище состояния
задачи; отдельный сервис API — лишняя граница контейнера. **Последствия:** меньше сервисов, но Postgres — единая точка
нагрузки. **Подтверждение:** `docker compose config` содержит ровно db, migrate, web, worker.

## ADR-002 — pgvector в том же Postgres: `vector(1536)`, HNSW по косинусу, итеративный скан

**Статус:** принято. **Контекст:** постановка: «pgvector — расширение нашего Postgres, не отдельная БД», модель
`text-embedding-3-small` (1536). **Решение:** образ `pgvector/pgvector:0.8.6-pg16`, колонка `vector(1536)`, индекс HNSW
`vector_cosine_ops` (m=16, ef_construction=64), в запросе `SET LOCAL hnsw.iterative_scan = strict_order` и фильтр
`bot_id`. **Альтернативы:** IVFFlat — требует обучения на данных, хуже скорость/полнота (Research T5); отдельная векторная
БД — запрещено постановкой. **Последствия:** HNSW в памяти, предел MVP ≈ 200 000 фрагментов на VPS. **Подтверждение:**
интеграционный тест «top-5 бота B не содержит фрагментов бота A при 10 000 чужих фрагментов».

## ADR-003 — Граница «знаю / не знаю» и адрес ссылки принадлежат коду, а не модели

**Статус:** принято. **Контекст:** главная жалоба на категорию — выдумки и несуществующие URL (PD-INSIGHT-001,
PD-INSIGHT-002). **Решение:** (1) порог сходства `MIN_SIMILARITY` проверяется ДО генерации, ниже — «не знаю» без вызова модели;
(2) модель возвращает JSON `{answer, cited_ids, unknown}`; (3) `cited_ids` обязаны быть непустым подмножеством выдачи;
(4) ссылки строятся из записей `document` (URL или «файл, стр. N»), URL из текста модели вырезаются; (5) текст выводится как
текст. **Альтернативы:** «просить модель ставить ссылки» — это и есть механизм выдумок. **Последствия:** выше доля «не
знаю» на бедных сайтах — лечится дозагрузкой источников. **Подтверждение:** тесты SC-US-005-2, SC-US-006-1, SC-US-006-2.

## ADR-004 — Модели: `text-embedding-3-small` и `gpt-4.1-mini` за портом провайдера

**Статус:** принято. **Контекст:** постановка называет только модель эмбеддингов; цена ответа нужна числом для потолков
(PD-INSIGHT-003). **Решение:** генерация — `gpt-4.1-mini` через Chat Completions со структурированным выводом, ≤ 400 токенов
ответа, дедлайн 20 с, без скрытых повторов; порт провайдера по образцу N4 #16 с адаптерами `fake` (тесты) и `live`. Имя модели
— из закрытого списка в коде; окружение выбирает вариант, неизвестное имя — отказ старта. **Альтернативы:** `gpt-5-mini` —
модель с рассуждением: токены рассуждения оплачиваются как выход, задержка непредсказуема (Research T7). **Последствия:**
≈ $0.0015 за ответ `[H]` по объёму. **Подтверждение:** контрактный тест адаптера на `fake`; замер токенов на стенде.

## ADR-005 — Долгие задачи индексации в Postgres: ручка до работы, аренда с fence, повтор продолжает

**Статус:** принято. **Контекст:** обход сайта и PDF — минуты; правило `long-running-job.md`. **Решение:** `POST` отвечает
`202 {job_id}` до работы; `index_job` с частичным уникальным индексом по живой задаче источника (идемпотентный ключ);
аренда `leased_until` + `lease_fence`, ≤ 3 захвата, уборщик; повтор возвращает тот же `job_id` и не пересчитывает документы
и чанки с тем же хэшем; потолок задачи 15 мин. **Альтернативы:** синхронный ответ — длиннее окна прокси (60 с); BullMQ —
см. ADR-001. **Подтверждение:** `docs/long-job-contract.md` + `node .claude/hooks/check-job-contract.cjs .`.

## ADR-006 — Бейдж решает сервер, план толкуется в коде fail-closed; снятие — намерение

**Статус:** принято. **Контекст:** FR-GROWTH-003; оплата вне сборки. **Решение:** `badge_required = NOT (plan_of(plan) ∈
{start, studio} AND badge_removal = active)`; `plan_of` возвращает `free` для любого неточного значения; клиент только
рисует и восстанавливает бейдж; ссылку бейджа строит сервер; кнопка «убрать бейдж» пишет намерение; включение снятия —
только оператором через CLI с аудитом. **Альтернативы:** флаг в конфиге виджета, который задаёт клиент, — снимается одной
строкой на чужом сайте. **Подтверждение:** тест мусорного входа плана (11 видов) → бейдж обязателен.

## ADR-007 — Список разрешённых origin на бота; пустой список закрыт; CORS ставит только приложение

**Статус:** принято. **Контекст:** публичная ручка ответа тратит деньги владельца и наши; чужой сайт может встроить
бесплатный бот. **Решение:** `bot.allowed_origins`; запрос с неразрешённого origin — `403` без вызова модели и без
CORS-заголовка; пустой список = закрыто; хост источника предлагается первым доменом. CORS выставляет только web, прокси —
нет (двойной заголовок ломает CORS). **Подтверждение:** `docs/embed-contract.md`, проверка на ЧУЖОМ origin.

## ADR-008 — Студии: передаётся аккаунт, а не бот

**Статус:** принято. **Контекст:** FR-GROWTH-004; перенос строк бота через границу арендатора ломает RLS (инвентарь #11).
**Решение:** бот клиента с первого дня живёт в подаккаунте студии (`parent_account_id`, один уровень, ≤ 5); передача —
одноразовая ссылка (хэш, 7 дней), по которой клиент задаёт e-mail и пароль и становится владельцем подаккаунта; строки ботов
и фрагментов не двигаются, `public_id` и код вставки прежние. **Альтернативы:** `UPDATE bot SET account_id` с каскадом по 5
таблицам — окно несогласованности и обход RLS. **Подтверждение:** тест SC-US-014-2 (`public_id` до и после равен).

## ADR-009 — Демо-страница только для сохранённого опубликованного бота; анонимное демо по URL не строится

**Статус:** принято (выбор владельца «A + демо из B»). **Решение:** `/b/{slug}` при `published AND demo_enabled`,
`noindex`, `no-store`, те же пределы на посетителя, что у виджета; вопросы с демо не считаются в метрику внешних доменов.
Анонимный ввод чужого URL (вариант B целиком) — не строится: платный обход по запросу постороннего. **Подтверждение:**
SC-US-012-1..3.

## ADR-010 — Потолки расходов: числа, атомарно до вызова, отказ; посетитель = HMAC префикса IP + бот

**Статус:** принято. **Контекст:** правило `model-call-cost.md`; ответы виджета запускает посторонний. **Решение:** пределы
`docs/model-cost-contract.md`; счётчик `quota_counter` увеличивается атомарно ДО вызова, все ключи попытки в одной
транзакции; попытка считается и при ошибке провайдера; при достижении — `429`; ненастроенный или неположительный предел —
отказ старта; единица посетителя — HMAC(`VISITOR_SECRET`, префикс /24 или /64 + `bot_id`), 30 ответов/сутки, чтобы офис за
NAT не упирался в предел одного человека. **Подтверждение:** `node .claude/hooks/check-model-cost.cjs .`; конкурентный тест
«50 параллельных запросов при остатке 3 → ровно 3 вызова модели».

## ADR-011 — Ключ модели серверный; шаблон «ключи пользователя в браузере» не применяется

**Статус:** принято. **Контекст:** шаблон `/replicate` предлагает хранить ключи пользователя в IndexedDB (AES-GCM) и не
держать их на сервере. **Решение:** не применять: ключ — оператора, один на продукт, виджет обязан отвечать посетителям
чужого сайта без браузера владельца. Ключ живёт в окружении web и worker, не логируется, не отдаётся клиенту. **Последствия:**
расход — наш, поэтому ADR-010 обязателен.

## ADR-012 — PDF хранится в Postgres (`bytea`), без объектного хранилища

**Статус:** принято. **Контекст:** ≤ 3 PDF × 10 МБ на бота; S3/MinIO — ещё одно хранилище с портом и паролем.
**Решение:** `source_file.bytes bytea`, CHECK размера, загрузка через web, чтение воркером. **Альтернативы:** presigned-загрузка
в S3 (N5 #23) — оправдана при больших файлах, не в MVP. **Последствия:** рост базы ≈ 30 МБ на бота; бэкап — один дамп.

## ADR-013 — Обходчик: RFC 9309, тот же хост, SSRF-фильтр, вежливость

**Статус:** принято. **Решение:** robots.txt: 4xx — можно, 5xx/сеть — задача `failed` (Research T8–T9); тот же хост;
sitemap первым; пауза 1 с; ≤ 100 страниц на Free; SSRF-фильтр по разрешённым IP на каждом соединении и редиректе; текст по
блочным элементам с разделителем. **Подтверждение:** тесты SC-US-002-2, SC-US-002-3.

## ADR-014 — Стенд за существующим TLS-прокси машины; хранилище без портов

**Статус:** принято. **Контекст:** 80/443 держит чужой прокси (`port-conflicts-local.md`), тестовый домен как у N3/N4.
**Решение:** web подключается во внешнюю сеть прокси (`${PROXY_NETWORK:?}` — без дефолта), своих 80/443 нет; db без `ports:`;
отладочная публикация web — только `127.0.0.1:${N6B_WEB_PORT:-3106}`. **Подтверждение:** `check-ports.cjs` и
`check-port-conflicts.sh` до `up`; подъём стенда — остановка у владельца.
