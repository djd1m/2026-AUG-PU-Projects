# Solution Strategy — N6b «RAG-бот для сайта»

**Фаза:** 1 `/replicate` · `sparc-prd-mini` AUTO, внутренняя фаза 2 (Solve, навык `problem-solver-enhanced`, 9 модулей)
**Дата:** 2026-09-30 · **Входы:** [`00-task.md`](00-task.md), [`product-discovery-brief.md`](product-discovery-brief.md),
[`CJM_Variants.md`](CJM_Variants.md) (выбор владельца «A + демо из B + минимум C» — PD-CJM-001), [`Research_Findings.md`](Research_Findings.md)

## SCQA

- **Situation.** У малого сайта (С1, PD-SEGMENT-001) есть страницы и PDF с ответами, но посетитель ночью уходит без
  ответа. Категория «бот по своим документам» доказана источником (Chatbase, $8M+ ARR).
- **Complication.** Главная жалоба на категорию — бот выдумывает, включая несуществующие ссылки (PD-INSIGHT-002); каждый
  ответ публичного виджета оплачивается нами и запускается посторонним (PD-INSIGHT-003); 152-ФЗ и 38-ФЗ задают вопросы к
  логам вопросов и к бейджу (PD-RISK-001, PD-RISK-002). На всё — неделя, оплата вне сборки.
- **Question.** Как за неделю выпустить бота, которому владелец сайта доверит отвечать от своего имени, и получить 15
  виджетов на внешних доменах с ≥1 вопросом, не открыв неограниченный счёт?
- **Answer.** «Ответ, которому можно не верить на слово»: каждый ответ собирается только из найденных фрагментов и несёт
  ссылку, построенную из НАШЕЙ записи источника; если фрагмента нет — «не знаю» и контакт владельца без вызова модели.
  Рост — бейдж на Free (основная петля) плюс демо-страница сохранённого бота и минимум для студий (выбор владельца).
  Каждый платный вызов закрыт потолком числом, ненастроенный потолок роняет старт.

## First Principles

1. Доверие к ответу = проверяемость. Посетитель проверяет ответ только кликом на источник → ссылка обязательна.
2. Модель не знает, где правда; знает наша БД (URL страницы, имя PDF и номер страницы). Значит адрес ссылки — поле БД, а не
   текст модели.
3. Ответ стоит денег, отказ «не знаю» до вызова модели — ноль. Значит порог релевантности проверяется ДО генерации.
4. Виджет — продукт целиком, он живёт на чужой странице (правило `embeddable-widget.md`): CORS, CSS и CSP хозяина.
5. Индексация — минуты, а не секунды (правило `long-running-job.md`): ручка задачи выдаётся до работы.
6. Нет оплаты → нет денег за бейдж → бейдж на неделе работает как дистрибуция, а не как выручка; «снять бейдж» — кнопка
   намерения, которую мы считаем.

## Root Cause Analysis (5 Whys) — «почему боты-конкуренты выдумывают»

1. Почему выдумывают? Модель генерирует ответ даже при слабом контексте.
2. Почему генерирует при слабом контексте? Порог релевантности не является воротами: контекст всегда передаётся, «найдено
   хоть что-то».
3. Почему ссылки выдуманы? Ссылка — часть сгенерированного текста.
4. Почему это не ловится? Нет проверки, что процитированный фрагмент действительно был в выдаче.
5. **Корневая причина:** граница «знаю / не знаю» и адрес источника отданы модели, а не детерминированному коду.

Следствие: две детерминированные ворота — порог сходства до вызова и проверка «цитаты ⊂ выдачи» после; ссылки рендерятся из БД.

## Game Theory

| Игрок | Интерес | Действие, которое нас ранит | Ответ стратегии |
|---|---|---|---|
| Владелец сайта (С1) | бот не врёт от его имени | не ставит виджет из страха | «не знаю + контакт», ссылка в каждом ответе, песочница до публикации |
| Посетитель чужого сайта | получить ответ | крутит вопросы (намеренно или ботом) | предел на посетителя (HMAC префикса IP) и на бота в сутки, отказ при достижении |
| Веб-студия (С2) | продать клиенту ИИ-фичу | не ставит бейдж клиентам | подаккаунт клиента и передача бота без смены кода вставки (FR-GROWTH-004) |
| Злоумышленник | бесплатная модель / XSS на чужих сайтах / SSRF | встраивает чужой бот к себе; внедряет HTML в страницы для обхода | список разрешённых доменов бота (пустой = закрыто); ответ рендерится как текст; обходчик блокирует частные адреса |
| Мы (оператор) | метрика недели, без счёта | — | потолки числом, отказ при ненастроенном потолке, журнал попыток до вызова |

Равновесие по Нэшу при списке доменов: встраивать чужой бот невыгодно (он не отвечает на чужом origin), значит квоту владельца
тратят только его посетители. Без списка доминирующая стратегия злоумышленника — встроить чужой бесплатный бот.

## Second-Order Effects

- Отказ «не знаю» без вызова модели снижает счёт, но повышает долю «не знаю» на бедных сайтах → владелец видит счётчик «не
  знаю» и дозагружает PDF (Hook из CJM A). Аналитика диалогов вне объёма — только счётчик.
- Пустой список доменов = виджет нигде не работает → лишний шаг онбординга (ввести домен). Компенсация: домен подставляется
  из URL источника при создании бота, владелец подтверждает.
- Предел по префиксу IP (/24, /64) бьёт по офису за NAT (урок корня 2026-09-27 про 429 у офисов). Компенсация: предел на
  «адрес» 30 ответов/сутки на бота, а не 5; статика и бандл виджета лимитом не считаются.
- Демо-страница на нашем origin раздаёт контент владельца публично → только по включению владельцем, `noindex`.
- Передача бота клиенту переносом строк через границу арендатора ломает RLS (reuse-inventory #11) → передаём АККАУНТ, а не
  бота (см. TRIZ).

## TRIZ

**IFR:** бот отвечает только правду из документов владельца, сам говорит «не знаю», когда правды нет, не тратит денег на
пустые ответы и сам приводит новых владельцев — без ручной модерации.

| Contradiction | TRIZ Principle | Resolution |
|---|---|---|
| Ответ должен быть полным (модель пишет свободно) и не должен выдумывать (модель не пишет ничего своего) | Разделение по условию + №2 «Вынесение» | текст пишет модель, но ФАКТ ссылки и граница «знаю» вынесены в код: порог до вызова, `cited_ids ⊂ retrieved_ids` после, URL из БД |
| Виджет должен работать на любом сайте клиента и не должен работать на сайте злоумышленника | Разделение по условию (origin) | список разрешённых origin на бота; CORS отвечает только им; неразрешённый origin — 403 без вызова модели |
| Передать бота клиенту и не перемещать строки между арендаторами (RLS) | №13 «Наоборот» | не бот уходит к клиенту, а клиент получает аккаунт, в котором бот живёт с первого дня (подаккаунт студии) |
| Бейдж должен быть заметен (петля) и не мешать ответу | Разделение в пространстве | бейдж — строка под лентой сообщений внутри Shadow DOM, ссылка строится сервером |
| Демо-страница нужна для «поделиться» и не должна давать анонимный платный обход | Разделение во времени | демо открывается только ПОСЛЕ сохранения бота владельцем; анонимного ввода URL нет (вариант B отклонён владельцем) |
| Потолок расходов строгий и не должен наказывать офис за NAT | №3 «Местное качество» | два предела: на посетителя (адрес) и на бота в сутки; статика вне лимита |

## Recommended Approach

1. Монорепо TypeScript: `apps/web` (Next.js: кабинет, API, лендинг, демо), `apps/widget` (бандл одним `<script>`, Shadow
   DOM), `services/worker` (обход, PDF, нарезка, эмбеддинги; аренда задач в Postgres), `packages/db` (миграции, RLS).
2. Postgres 16 + pgvector (`pgvector/pgvector:0.8.6-pg16`), `vector(1536)`, HNSW `vector_cosine_ops`. Без Redis: лимиты и
   очередь — в Postgres (reuse-inventory #5, #13, #14 — PD-REUSE-001).
3. RAG: эмбеддинг вопроса → top-5 по косинусу в пределах бота → порог сходства → генерация `gpt-4.1-mini` с JSON
   `{answer, cited_ids, unknown}` → проверка цитат → ссылки из БД.
4. Рост: бейдж решает сервер (fail-closed: неопознанный план = бейдж), клик → `/r/b/{public_id}` → лендинг с `ref`.
5. Переиспользование N1–N5 — по [`discovery/reuse-inventory.md`](discovery/reuse-inventory.md) (PD-REUSE-001): виджет и бейдж
   N1, аренда задач N4, квоты N4/N5, подаккаунты N2, auth N5, публичные страницы N5.

## Risks

| Risk | Probability | Impact | Mitigation |
|---|---|---|---|
| 15 внешних виджетов за неделю не набираются петлёй (K 0.1–0.2) | High | High | ручной посев 15 знакомым владельцам/студиям (канал 1 brief); метрика считает честно, без подмены |
| Порог сходства откалиброван неверно → много «не знаю» или выдумки | Medium | High | калибровочный набор вопросов в Refinement; порог в конфиге, отсутствует → отказ старта |
| Счёт от посторонних вопросов | Medium | High | потолки на адрес и бот, глобальный суточный, журнал попытки ДО вызова |
| 152-ФЗ: вопросы посетителей уходят во внешнюю модель | Medium | High | открытый вопрос владельцу; в MVP: предупреждение в виджете, IP только HMAC, хранение 30 дней |
| Промпт-инъекция в обходимых страницах | Medium | Medium | инструкция модели отделена от данных; ответ рендерится текстом; ссылки только из БД |
| SSRF через URL источника | Medium | High | только http/https, порты 80/443, запрет частных/служебных адресов после DNS, повтор проверки на редиректах |
| Правовой статус бейджа (38-ФЗ) | Low | Medium | открытый вопрос до публичного запуска (PD-RISK-002) |
