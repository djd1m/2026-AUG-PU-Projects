# Specification — N6b «RAG-бот для сайта»

**Фаза:** 1 `/replicate` · `sparc-prd-mini` AUTO, внутренняя фаза 3 · **Дата:** 2026-09-30 · **Ревизия:** v1.0
**Входы:** [`00-task.md`](00-task.md) (объём: только MVP; оплата, партнёрские выплаты, удаление аккаунта — вне сборки),
[`product-discovery-brief.md`](product-discovery-brief.md), [`CJM_Variants.md`](CJM_Variants.md) (PD-CJM-001),
[`Solution_Strategy.md`](Solution_Strategy.md), [`ADR.md`](ADR.md). Сценарии BDD полностью — [`test-scenarios.md`](test-scenarios.md).

## Executive Summary

Владелец сайта регистрируется, даёт URL сайта и PDF, через минуты задаёт вопрос в песочнице и получает ответ со ссылкой на
свою страницу или страницу PDF (Aha, FR-GROWTH-001). Вставляет один `<script>` на свой домен — посетители получают те же
ответы в виджете с бейджем «Работает на …» (Free). Нет фрагмента — «не знаю» и контакт владельца. Вторично: публичная
демо-страница сохранённого бота и подаккаунты студий с передачей бота клиенту. Метрика недели — 15 внешних доменов с ≥1
вопросом (PD-METRIC-001).

## Соглашения

- `US-nnn` — пользовательская история, номер не переиспользуется; `SC-US-nnn-k` — её сценарий приёмки.
- `FR-n6b-k` / `NFR-n6b-k` — машинные ключи требований (заголовки уровня 3); `Pseudocode.md` ссылается на них строками
  `REQUIREMENT:`.
- `FR-GROWTH-nnn` — требования роста из семени Фазы 0; каждое принятое имеет три сценария в `test-scenarios.md`
  (`@happy-path`, `@edge-case`, `@security`).
- Роли: **владелец** (зарегистрированный аккаунт), **студия** (аккаунт типа studio), **клиент студии** (владелец подаккаунта),
  **посетитель** (аноним на чужом сайте или демо-странице), **оператор** (мы).

## Требования роста (промоушен семени Фазы 0)

| Семя | Решение | Где реализовано |
|---|---|---|
| FR-GROWTH-001 | принято: момент ценности = первый верный ответ со ссылкой на СВОЙ документ; CTA «вставить на сайт» и «поделиться демо» показываются в этот момент, а не на онбординге | US-005 (SC-US-005-3), FR-n6b-5 |
| FR-GROWTH-003 | принято: бейдж обязателен на Free, решает сервер, неопознанный план = бейдж; снятие — платная опция (на неделе — кнопка намерения, оплата вне сборки); бейдж ведёт на лендинг с `ref` | US-009, US-010, US-011; FR-n6b-9..11 |
| FR-GROWTH-004 | принято в минимуме владельца: подаккаунты клиентов студии и передача бота клиенту без смены кода вставки; без вознаграждения студии | US-013, US-014; FR-n6b-13, FR-n6b-14 |
| FR-GROWTH-005 | принято: публичная демо-страница только для сохранённого бота, включается владельцем, тот же бейдж и те же пределы | US-012; FR-n6b-12 |
| FR-GROWTH-006 | принято: метрика недели считается с первого релиза — внешний origin + ≥1 вопрос; показы бейджа (i) и конверсия клика в регистрацию (conv%) раздельно | US-015; FR-n6b-15 |

FR-GROWTH-002 — отклонено для этой сборки: партнёрская атрибуция до платной конверсии требует оплаты, а оплата и выплаты вне объёма (00-task, «Объём сборки»); вернуть вместе с оплатой.

## Требования облика (Фаза 0.5)

Облик источника **НЕ ИЗМЕРЕН** (`no-browser-mcp`), путь **НЕ ИЗМЕРЕН** (`no-browser`) — см. [`source-product-profile.md`](source-product-profile.md).
Строк семени облика нет, промотировать нечего. Интерфейс строится по отраслевой палитре-фолбэку (Productivity: slate/orange),
подписанной как фолбэк; сходство с источником не заявляется.

## User Stories и сценарии приёмки

### US-001: Регистрация и вход владельца
As a владелец сайта, I want to зарегистрироваться по e-mail и паролю и войти, So that мои боты и источники были только моими.

- [SC-US-001-1] Given новый e-mail, When владелец регистрируется с паролем ≥ 10 символов, Then создаётся аккаунт плана `free` и сессия (httpOnly cookie, 7 дней).
- [SC-US-001-2] Given аккаунт существует, When вход с неверным паролем, Then ответ одинаковый для «нет такого e-mail» и «неверный пароль», время ответа выровнено фиктивным хэшем.
- [SC-US-001-3] Given при регистрации выбран тип «студия», Then аккаунт получает `kind=studio` (в MVP бесплатно, оплата вне сборки).

### FR-n6b-1
Регистрация, вход, выход владельца; пароль bcrypt; сессия хранится хэшем; `SESSION_SECRET` отсутствует → отказ старта. Сброс
пароля вне MVP (нет почтового провайдера).

### US-002: Источник — сайт
As a владелец, I want to указать URL своего сайта, So that бот знал содержимое страниц.

- [SC-US-002-1] Given URL `https://example.ru`, When владелец создаёт бота, Then ответ `202` сразу содержит `job_id`, задача обходит только тот же хост, сначала `sitemap.xml`, затем ссылки, не более 100 страниц (Free).
- [SC-US-002-2] Given robots.txt отвечает 5xx или недоступен по сети, Then обход не начинается, задача `failed` с причиной «robots.txt недоступен — по RFC 9309 это полный запрет».
- [SC-US-002-3] Given URL указывает на `127.0.0.1`, `10.0.0.0/8`, `169.254.169.254` или имя, разрешающееся в частный адрес, Then создание отклоняется `422` до любого сетевого запроса к этому адресу; редирект на частный адрес обрывает загрузку страницы.

### FR-n6b-2
Обход сайта: схема http/https, порты 80/443, тот же хост (с `www.` и без), robots.txt по RFC 9309 (4xx → можно, 5xx/сеть →
нельзя), пауза 1 с между страницами, таймаут 15 с на страницу, HTML ≤ 2 МБ, только `text/html`, предел страниц по плану. Текст
извлекается по блочным элементам с разделителем (абзацы не склеиваются).

### US-003: Источник — PDF
As a владелец, I want to загрузить PDF с прайсом или условиями, So that бот отвечал и по ним.

- [SC-US-003-1] Given PDF 4 МБ, When загрузка, Then ответ `202` с `job_id`, текст извлекается постранично, каждый фрагмент помнит номер страницы.
- [SC-US-003-2] Given файл > 10 МБ, или 4-й PDF на Free, или сигнатура не `%PDF-`, Then `413`/`409`/`415` соответственно, задача не создаётся.
- [SC-US-003-3] Given PDF без текстового слоя (скан), Then задача `failed` с причиной «в PDF нет текста (скан) — распознавание вне MVP».

### FR-n6b-3
PDF ≤ 10 МБ, ≤ 300 страниц, ≤ 3 файла на бота (Free), проверка сигнатуры, файл хранится в Postgres (`source_file.bytes`),
извлечение текста локальной библиотекой без внешних вызовов.

### US-004: Прогресс индексации
As a владелец, I want to видеть, что происходит с индексацией, So that не жать кнопку повторно и понимать отказ.

- [SC-US-004-1] Given задача идёт, When владелец открывает бота, Then видит «Индексация: страниц 12 из 40» по `GET /api/jobs/{job_id}`; кнопка «добавить источник того же типа» неактивна.
- [SC-US-004-2] Given задача завершилась, Then видит «Готово: 40 страниц, 312 фрагментов» и кнопку «Спросить в песочнице».
- [SC-US-004-3] Given задача упала, Then видит причину и кнопку «Повторить»; повтор ПРОДОЛЖАЕТ ту же задачу (уже обработанные страницы и фрагменты с тем же хэшем не пересчитываются).
- [SC-US-004-4] Given тот же источник запрошен повторно, пока задача жива, Then возвращается тот же `job_id` (идемпотентный ключ `source_id`).

### FR-n6b-4
Задача индексации: `job_id` выдаётся до работы (`202`), три различимых состояния `running|succeeded|failed`, аренда исполнителя
с fence, ≤ 3 захвата, уборщик зависших, потолок задачи 15 мин, эмбеддинги кэшируются по хэшу текста фрагмента.

### US-005: Ответ со ссылкой на источник (песочница)
As a владелец, I want to задать вопрос своему боту до публикации, So that убедиться, что он отвечает по моим документам.

- [SC-US-005-1] Given проиндексирован PDF «Прайс», When вопрос «сколько стоит доставка?», Then ответ содержит текст и ≥1 ссылку вида «Прайс.pdf, стр. 3» или URL страницы; каждая ссылка взята из записи источника в БД.
- [SC-US-005-2] Given модель вернула идентификатор фрагмента, которого не было в выдаче, Then ответ заменяется на «не знаю» (US-006).
- [SC-US-005-3] Given это первый ответ бота со ссылкой на источник, Then под ответом показываются CTA «Вставить на сайт» и «Поделиться демо-страницей» (FR-GROWTH-001), событие `first_cited_answer` пишется один раз на бота.

### FR-n6b-5
RAG-ответ: вопрос ≤ 500 символов; эмбеддинг вопроса; top-5 фрагментов бота по косинусу; порог сходства `MIN_SIMILARITY`
(конфиг, отсутствует → отказ старта); генерация `gpt-4.1-mini`, ≤ 400 токенов, ответ JSON `{answer, cited_ids, unknown}`;
проверка `cited_ids ⊂ retrieved_ids` и `cited_ids ≠ ∅`; ссылки рендерятся из БД; текст модели выводится как текст, не HTML.

### US-006: «Не знаю» со ссылкой на контакт
As a посетитель, I want to получить честное «не знаю» и контакт, So that не уйти с выдуманным ответом.

- [SC-US-006-1] Given ни один фрагмент не прошёл порог, When вопрос, Then ответ «В материалах сайта нет ответа на этот вопрос. Свяжитесь: <контакт>» без вызова модели генерации.
- [SC-US-006-2] Given модель вернула `unknown=true` или пустые `cited_ids`, Then тот же ответ «не знаю + контакт».
- [SC-US-006-3] Given у бота не задан контакт, Then бот нельзя опубликовать (код вставки и демо не выдаются), песочница работает.

### FR-n6b-6
«Не знаю» — детерминированный ответ кода, не модели; контакт владельца (e-mail, телефон или URL, валидируется) обязателен для
публикации; каждое «не знаю» пишется в журнал вопросов с причиной `below_threshold|model_unknown|invalid_citation`.

### US-007: Код вставки и разрешённые домены
As a владелец, I want to получить `<script>` и указать домены, So that виджет работал только на моих сайтах.

- [SC-US-007-1] Given бот опубликован, Then выдаётся `<script src="https://n6b.194.85.249.105.sslip.io/w.js" data-bot="<public_id>" async></script>`, адрес строится из `PUBLIC_BASE_URL`.
- [SC-US-007-2] Given создание бота по URL сайта, Then хост источника предлагается первым разрешённым доменом; владелец подтверждает.
- [SC-US-007-3] Given список доменов пуст, Then виджет не отвечает ни на одном origin (fail-closed), кабинет показывает «добавьте домен».

### FR-n6b-7
Список разрешённых origin на бота (схема+хост, порт по умолчанию), пустой список = закрыто; `PUBLIC_BASE_URL` без дефолта в
проде.

### US-008: Виджет на чужом сайте
As a посетитель чужого сайта, I want to открыть чат и получить ответ, So that не писать на почту.

- [SC-US-008-1] Given страница разрешённого origin с ограничительным CSP, разрешающим наш `script-src` и `connect-src`, When посетитель задаёт вопрос, Then ответ приходит; в консоли нет ошибок CORS и CSP.
- [SC-US-008-2] Given враждебный CSS хозяина (`* {box-sizing}`, `img {width:100%}`, `z-index` войны), Then вёрстка виджета не меняется (Shadow DOM, `all: initial` на корне) и виджет не меняет стили хозяина.
- [SC-US-008-3] Given origin не в списке бота, Then `POST /api/widget/ask` → `403` без вызова модели; CORS-заголовок не выдаётся.

### FR-n6b-8
Виджет: один бандл ≤ 30 KB gzip, без инлайновых `<script>/<style>`, Shadow DOM, `fetch` без `credentials`; CORS ставит только
приложение (прокси — нет), `Access-Control-Allow-Origin` = origin из списка, `OPTIONS` → `204`.

### US-009: Бейдж на Free
As a оператор, I want to чтобы каждый Free-виджет показывал бейдж, So that посетители узнавали о продукте (петля A).

- [SC-US-009-1] Given бот аккаунта плана `free`, Then конфиг виджета содержит `badge_required=true` и `badge_url`, виджет показывает «Работает на N6b».
- [SC-US-009-2] Given план в БД не распознан (`'PAID'`, `null`, `' start'`), Then `badge_required=true`.
- [SC-US-009-3] Given хозяин скрыл бейдж стилем внутри видимой ему части, Then виджет восстанавливает его (наблюдатель + повтор через 2 с) и пишет событие `badge_tamper`.

### FR-n6b-9
Решение о бейдже — только сервер: `badge_required = NOT (plan ∈ {start, studio} AND badge_removal = active)`; клик по бейджу
идёт на `/r/b/{public_id}`, сервер пишет клик (дедупликация: посетитель+бот+сутки) и отвечает `302` на лендинг с `ref`.

### US-010: Намерение снять бейдж
As a владелец, I want to нажать «убрать бейдж», So that узнать цену (оплата пока не принимается).

- [SC-US-010-1] Given Free, When «убрать бейдж», Then показано «Скоро: ~990 ₽/мес, оставьте заявку», пишется событие `badge_removal_intent` (один раз на аккаунт в сутки), бейдж остаётся.

### FR-n6b-10
Кнопка-намерение; включение `badge_removal=active` в MVP — только оператором через CLI, с записью в журнал аудита.

### US-011: Лендинг и атрибуция клика бейджа
As a посетитель, кликнувший бейдж, I want to попасть на страницу «сделай такой для своего сайта», So that создать своего бота.

- [SC-US-011-1] Given переход `/r/b/{public_id}`, Then лендинг ставит cookie `n6b_ref` (первое касание, 30 дней), регистрация записывает `referred_by_bot_id`.
- [SC-US-011-2] Given регистрирующийся — владелец бота-источника (тот же аккаунт или его подаккаунт), Then регистрация не засчитывается в conv% (самореферал).

### FR-n6b-11
Лендинг, cookie первого касания, атрибуция регистрации к боту, исключение самореферала.

### US-012: Публичная демо-страница бота
As a владелец, I want to включить демо-страницу, So that поделиться ссылкой, где мой бот отвечает по моему сайту.

- [SC-US-012-1] Given бот опубликован и владелец включил демо, Then `https://…/b/{slug}` открывается без входа, чат работает, бейдж по плану, заголовок `X-Robots-Tag: noindex`.
- [SC-US-012-2] Given демо выключено или бот не опубликован, Then `/b/{slug}` → `404` (не `403`: существование не раскрывается).
- [SC-US-012-3] Given посетитель демо исчерпал 30 ответов в сутки, Then отказ с текстом «лимит вопросов на сегодня исчерпан» и контактом владельца.

### FR-n6b-12
Демо-страница на нашем origin, только для опубликованного бота с включённым флагом; те же пределы, что у виджета; вопросы с
демо не засчитываются в метрику внешних доменов.

### US-013: Подаккаунт клиента студии
As a студия, I want to создать подаккаунт клиента и собрать в нём бота, So that вести клиентов из одного кабинета.

- [SC-US-013-1] Given аккаунт `kind=studio`, When «новый клиент», Then создаётся аккаунт `parent_account_id=<студия>`, студия переключается в него и собирает бота.
- [SC-US-013-2] Given 6-й подаккаунт, Then `409` «предел 5 клиентов в MVP».
- [SC-US-013-3] Given аккаунт не студия или подаккаунт пытается создать свой подаккаунт, Then `403` (один уровень).

### FR-n6b-13
Подаккаунты: один уровень, ≤ 5 на студию, RLS по `account_id` с доступом студии к дочерним аккаунтам.

### US-014: Передача бота клиенту
As a студия, I want to передать клиенту его бота, So that клиент владел им сам, а код на его сайте не менялся.

- [SC-US-014-1] Given подаккаунт с ботом, When студия создаёт ссылку передачи, Then выдаётся одноразовая ссылка на 7 дней (показывается студии, почта вне MVP).
- [SC-US-014-2] Given клиент открыл ссылку и задал e-mail и пароль, Then подаккаунт становится самостоятельным аккаунтом клиента, `public_id` бота и код вставки не меняются, источники и фрагменты на месте; доступ студии сохраняется, только если клиент отметил «оставить доступ студии».
- [SC-US-014-3] Given ссылка использована, просрочена или подделана, Then `410`/`404`, аккаунт не меняется.

### FR-n6b-14
Передача аккаунта, а не перенос бота: строки ботов и фрагментов не пересекают границу арендатора; токен передачи хранится
хэшем, одноразовый, срок 7 дней, в одной транзакции с изменением владельца.

### US-015: Метрика недели и инструментирование
As a оператор, I want to видеть число внешних доменов с ≥1 вопросом, показы бейджа и конверсию, So that понять, работает ли петля.

- [SC-US-015-1] Given первый вопрос с origin `https://shop.example` к боту B, Then создаётся запись `widget_install(bot_id, origin_host='shop.example')` с `first_question_at`; повтор ничего не меняет.
- [SC-US-015-2] Given origin — наш хост, `localhost`, IP-литерал, `*.local` или частный адрес, Then запись не создаётся.
- [SC-US-015-3] Given оператор открывает `/admin/metrics`, Then видит: внешние домены с ≥1 вопросом (цель 15), показы бейджа, клики, регистрации с `ref`, conv% — и «n < 30, K не считается», пока регистраций меньше 30.

### FR-n6b-15
Инструментирование с первого релиза: `widget_install` (уникальность `bot_id, origin_host`, вставка атомарно), `badge_event`
(показ, клик), `signup.referred_by_bot_id`; доступ к `/admin/*` — только аккаунтам из списка операторов в коде/БД.

### US-016: Потолки расходов на модель
As a оператор, I want to чтобы каждый платный вызов имел предел числом, So that посторонний не выставил нам счёт.

- [SC-US-016-1] Given посетитель (HMAC префикса IP /24 или /64 + бот) задал 30 вопросов за сутки, Then 31-й → `429` «лимит на сегодня», модель не вызывается.
- [SC-US-016-2] Given любая из переменных пределов не задана или не положительное целое, Then сервис не стартует и называет переменную и последствие.
- [SC-US-016-3] Given вызов модели завершился таймаутом, Then попытка засчитана в пределы (счёт по попыткам).

### FR-n6b-16
Пределы (числа — в `docs/model-cost-contract.md`): ответ посетителю 30/адрес/бот/сутки, 300/бот/сутки, 3000/сутки всего;
песочница 100/аккаунт/сутки; эмбеддинги индексации 2 000 000 токенов/аккаунт/сутки, 20 000 000/сутки всего. Сутки по Москве.
Счётчик увеличивается атомарно ДО вызова; при достижении — отказ.

### US-017: Управление источниками
As a владелец, I want to видеть источники бота, удалять и переобходить их, So that бот отвечал по актуальным данным.

- [SC-US-017-1] Given источник удалён, Then его фрагменты удаляются в той же транзакции и больше не участвуют в ответах.
- [SC-US-017-2] Given «переобойти», Then создаётся новая задача; фрагменты с неизменным хэшем не эмбеддятся повторно.

### FR-n6b-17
Список источников с состоянием последней задачи, удаление, повторный обход.

## Non-Functional Requirements

### NFR-n6b-1
Производительность: ответ посетителю p95 ≤ 6 с (из них генерация ≤ 5 с), «не знаю» ниже порога p95 ≤ 1,5 с; поиск top-5 по
HNSW p95 ≤ 100 мс при ≤ 200 000 фрагментов; бандл виджета ≤ 30 KB gzip.

### NFR-n6b-2
Онбординг: от регистрации до первого ответа со ссылкой ≤ 10 минут для сайта ≤ 100 страниц и PDF ≤ 10 МБ (медиана по журналу).

### NFR-n6b-3
Безопасность: RLS по `account_id` для ботов, источников, фрагментов, журнала; SSRF-фильтр обходчика; ответ и имена источников
рендерятся текстом (нет XSS на чужих сайтах); пароли bcrypt; сессии хэшем; секреты только в окружении; БД без публикации порта.

### NFR-n6b-4
Персональные данные: IP не хранится, только HMAC префикса с секретом; журнал вопросов хранится 30 дней и удаляется воркером;
виджет показывает строку «Не сообщайте персональные данные»; данные на VPS. Трансграничная передача вопроса во внешнюю модель
— открытый вопрос владельцу (PD-RISK-001).

### NFR-n6b-5
Надёжность: `restart: unless-stopped` у каждого сервиса, healthcheck у БД и web, зависимости через `service_healthy`;
недоступность модели → отказ с понятным текстом, не «вечная загрузка».

### NFR-n6b-6
Доступность UI: WCAG 2.1 AA для кабинета и виджета (клавиатура, фокус, контраст, `aria-live` для новых ответов).
