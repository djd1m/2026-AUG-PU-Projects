## Наблюдения, приемлемые по документам (не находки)

- **Н-1. Смешение версий при частичном прогоне.** Шаг 7 удаляет устаревшие части только после всех батчей: если изменённый
  документ упёрся в суточный предел, в поиске до «Повторить» живут и старые, и новые части страницы. Порядок совпадает с
  Pseudocode (шаг 7 после 6) и обратный порядок оставил бы бота без фрагментов — приемлемо.
- **Н-2. Оплата при потере аренды.** Вызов, во время которого аренду перехватили, оплачен, части не пишутся, повтор платит
  снова. Окно — один батч ≤ 100 частей (≤ 50 000 токенов ≈ $0,001 по `model-cost-contract`), попытка честно засчитана в
  `embed:*` (счёт по попыткам). Приемлемо; раскрыто в 05_completion п. 7.
- **Н-3. `hnsw.max_scan_tuples`.** Неполный, но не чужой top-K — раскрыт только в 05_completion п. 3, в Refinement/ADR-002
  не записан. Моя проба: 25 000 чужих фрагментов ближе любого своего (шум 0,001) плюс точная копия вопроса у чужого бота,
  путь HNSW принудительно (`Index Scan using chunk_embedding_hnsw`, `max_scan_tuples=20000`) — вернулось **5 из 5 своих**.
  Отказ неполной выдачи честный («не знаю»), утечки нет; при MVP-пределе 200 000 фрагментов приемлемо. Рекомендация: строка в
  Refinement «Риски» вместо одного 05_completion.
- **Н-4. Каскад перенарезки.** Вставка предложения в абзац 3 из 60 меняет хэш у **1 из 12** частей — кэш по `text_sha256`
  переживает правку страницы, а не только её неизменность.
