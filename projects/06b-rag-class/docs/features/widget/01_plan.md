## AC и проверка

- WID-01: один автономный /w.js ≤30 KB gzip, script data-bot async из F08 запускает чат. Shadow DOM, adoptedStyleSheets, без inline script/style, fetch credentials:omit. Чужой host CSS не меняет содержимое виджета, виджет не меняет host. Предусмотреть открытие/закрытие, доступные названия элементов, 390/1440 без overflow.
- WID-02: GET config и POST ask используют единый published/public_id + точный нормализованный Origin gate. Пустой список, отсутствующий/null/неверный/чужой Origin →403 без CORS и без gateway/квоты; unpublished/nonexistent404. Только приложение ставит ACAO=разрешённый origin, Vary:Origin, без credentials/wildcard; OPTIONS204 с POST/Content-Type после такого же gate. Поскольку preflight не содержит тела, public_id передаётся в query bot; POST body bot по контракту должен совпадать, если задан. Клиент не выбирает account/channel/visitor_key.
- WID-03: bounded JSON и вопрос1..500 до платного резерва; существующий AnswerQuestion/PaidGateway с channel widget и ключом HMAC от последнего XFF, /24 или /64 + внутренний bot.id. Нет IP → закрытый отказ до платного вызова. Сохраняются квоты/logging/цитаты/не знаю/contact/429/503, текст и ссылки безопасно выводятся через DOM, не innerHTML. Нового fake selector в production нет.
- WID-04: server privacy_notice ровно из Pseudocode показывается над вводом до первого вопроса; поле недоступно до успешного конфига. Ошибка конфигурации честно видна, без молчаливого enabled. Pending и 429/503/error/recovery проверяются.
- WID-05: plan_of допускает только точные free/start/studio; всё неизвестное (null, массив, пробелы, регистр) →free. badge_required = NOT((start|studio) AND removal==='active'); badge_url строится сервером из PUBLIC_BASE_URL/r/b/public_id. Free показывает «Работает на N6b». MutationObserver плюс проверка каждые2с восстанавливают удалённый/скрытый badge внутри shadow root, отправляют tamper; impression≤одного на загрузку страницы. Для telemetry допустим fetch keepalive credentials:omit вместо sendBeacon, чтобы не нарушить отсутствие credentials. Публичный bounded event endpoint с тем же gate принимает лишь impression/tamper, HMAC и дату задаёт сервер. Click/referral и removal-intent — F10.
- WID-06: один metric_host helper lower-case/remove-www для config page/origin/ask. Существующая widget_install записывается ON CONFLICT DO NOTHING только для совпадающего page host и допустимого внешнего host, не test/operator. Excluded: собственный host, localhost, IP literals, .local, фиксированные preview suffixes из Pseudocode. Успешный семантический исход ask отмечает first_question_at только в уже существующей строке с config_seen_at; 422/429/503 и ask без config не создают метрику. Concurrent config не дублирует строку, concurrent first question не переписывает первое время. Операторская панель/проверка страницы/weekly report — F11.
- WID-07: unit + real PG проверки gates, plan decision, publication/account scoping, no calls for denied requests, trusted visitor derivation, shared config/install concurrency and accepted/failed outcomes. Fixed tests должны содержательно покраснеть при отключении Origin guard и неверном badge decision; exact restore и тот же green, с hash/exit evidence. Не повторять мутации неизменённых quota/citation guards.
- WID-08: Node22 полный typecheck/all unit/all real PG/build по frozen source, immutable image/source hashes, fresh independent Astra review после Sol. Реальный Docker UI на ЧУЖОМ origin с CSP script-src/connect-src нашего сервиса, style-src только host (без inline и widget style origin), hostile CSS, 390/1440, реальный OPTIONS/CORS, config/loading/answer/citations/unknown/badge restoration/events.
