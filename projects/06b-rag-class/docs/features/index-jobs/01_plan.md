# Фича 3 · index-jobs — план

**Тир:** L (дорожная карта; новый публичный путь кабинета, разделяемый ресурс — пул и очередь). **Требования:** US-004,
FR-n6b-4, SC-US-004-1…4, ADR-005, Pseudocode «Create source and enqueue index job», «Worker lease loop», State Transitions.
Документы Phase 1 свежие, алгоритмы расписаны — отдельный цикл PLAN/VALIDATE не гонялся (оговорка complexity-router о
свежих документах), ревью — отдельный агент.

## 1. Граница фичи

| Входит | Не входит (кто наполнит) |
|---|---|
| `POST /api/bots/{id}/sources` `{url}` → `202 {job_id}` до работы | multipart PDF, 413/409/415 — `pdf-source` |
| проверка URL: http/https, порт 80/443, без учётных данных, ≤ 2048 | SSRF по разрешённым адресам (шаг 2 алгоритма) — `crawl-site`: сети здесь нет вовсе |
| `GET /api/jobs/{id}`, `POST /api/jobs/{id}/retry` | обход, извлечение, нарезка, эмбеддинги — фичи 4–6 |
| аренда `SKIP LOCKED` + `leased_until` + `lease_fence`, ≤ 3 захвата, уборщик, потолок 15 мин от `run_started_at` | платные вызовы — их в фиче нет |
| интерфейс исполнителя `JobRunner` и честная заглушка | удаление источника, recrawl — `source-management` |
| экран кабинета: три состояния, «Повторить», кнопки гаснут | создание бота из кабинета — не в этой фиче (боты создаются следующими фичами) |

## 2. Решения

1. **Идемпотентный ключ — два уровня.** «Тот же источник» = тот же бот + нормализованный URL (без `#фрагмента`): миграция
   `004_source_site_key.sql` — частичный уникальный индекс `source (bot_id, url) WHERE kind='site'`. Задача — частичный
   уникальный `index_job (source_id) WHERE state IN ('queued','running')` (есть с foundation). Обе вставки — `ON CONFLICT DO
   NOTHING` + чтение победителя, одна транзакция кабинета под RLS. N одновременных POST → один источник, одна задача.
2. **Пользователю три состояния, в хранилище четыре.** `queued` и `running` отдаются одним `running` (Architecture, сверка).
3. **Аренда — одной инструкцией** `UPDATE … WHERE id = (SELECT … FOR UPDATE SKIP LOCKED LIMIT 1)`, транзакция закрывается
   ДО работы (N4 #13: после закрытия воркеров разделяет срок аренды, а запись результата — номер захвата). Кандидат —
   `queued`, или `running` с истёкшей арендой, и `attempts < 3` (CHECK колонки 0…3: четвёртого захвата не бывает).
   `run_started_at` ставится только при захвате из `queued`; перезахват его не сбрасывает; «Повторить» обнуляет.
4. **Fence в каждой записи исполнителя** — продление, прогресс, исход: `WHERE id AND lease_fence = $f AND state='running'`.
   Ноль строк — работа отдана (перезахват или уборщик), результат не пишется.
5. **Потолок считает БД:** `now() − run_started_at > 15 мин` в том же `UPDATE`, что продлевает аренду (контрольная точка).
   Часы одного источника, `created_at` в расчёте не участвует.
6. **Уборщик** раз в минуту: (А) `running`, аренда истекла, `attempts ≥ 3` → `failed` «исполнитель не отвечает»;
   (Б) `running`, аренда истекла, потолок пройден → `failed` «превышено время задачи». Уборщик fence не повышает и трогает
   только строки с истёкшей арендой; воркер, чью строку закрыл уборщик, упирается в `state='running'`.
7. **Исполнитель — порт `JobRunner`**: `run(ctx)` → `{succeeded, note}` | `{failed, error}`; `ctx.progress(done,total)`,
   `ctx.checkpoint()`, `ctx.signal`. Пульс продлевает аренду каждые 30 с (аренда 120 с); потеря аренды — `abort`.
   Заглушка отвечает `failed` с причиной «обработка источников ещё не подключена» — честный исход, а не «готово».
8. **Разделяемый ресурс.** Работа идёт без удержания соединения пула: каждая запись — короткая транзакция. Пул воркера — 10.

## 3. Тесты (идентификатор SC в имени)

Unit: вид состояний (`jobView` — три разных текста и действия), проверка URL, стражи по исходнику (S-13 аренда, S-14 fence,
S-15 потолок от `run_started_at`, S-16 ручка до работы) с плохим входом рядом.
Int (Postgres): SC-US-004-4 (20 одновременных POST → 1 источник, 1 задача, один `job_id`); 202 до работы; чужой бот/задача
→ 404; два воркера × 10 задач — каждая захвачена один раз; fence — воркер с просроченной арендой не пишет ни прогресс, ни
исход; ≤ 3 захвата + уборщик; `run_started_at` не сбрасывается перезахватом; потолок 15 мин и «вчерашняя» задача после
«Повторить»; повтор 409 для живой и готовой; пул не удерживается во время работы; три состояния через GET — квитанция с
`job_id` для `docs/long-job-contract.md`. Мутации — `tests/artifacts/index-jobs/mutations.txt`.
