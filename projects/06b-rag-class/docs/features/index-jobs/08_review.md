**Собственные пробы** (`n6b-f03v-probe.int.test.ts`, смонтирован в раннер; в репозиторий не входит): 6/6 зелёные.
- **P1 fence после уборщика и «Повторить».** Уборщик закрыл задачу, владелец нажал «Повторить» (строка `queued`, fence
  прежний: при повторе он не растёт). Старый исполнитель: прогресс `false`, продление `lost`, исход `lost`. После перезахвата
  (fence+1) снова `false`/`lost`; в строке `progress_done` = 0. Защищает условие `state='running'` в каждой записи.
- **P2** истёкшая, но не перехваченная аренда → исполнитель продлевает и пишет (по спецификации; см. F-5).
- **P3** три параллельных захвата за раунд, 5 раундов с истечением: не более одного захвата за раунд, всего ровно 3.
- **P4 RLS.** Под ролью кабинета аккаунта B: вставка задачи на источник A (account=A) → `42501`, (account=B) → `23505`
  (F-7). Источник на бот A (account=B) → `23503`, (account=A) → `42501`. `UPDATE` чужой задачи → 0 строк, `SELECT` → 0.
  HTTP: GET и retry чужой задачи и несуществующего uuid дают байт-в-байт одинаковый 404; POST на чужой и на
  несуществующий бот → 404/404.
- **P5 Origin и тело.** Без Origin, `Origin: null`, чужой Origin → 403 (POST источника и retry); без сессии → 401;
  `text/plain` → 422; `javascript:`, `ftp:`, `u:p@`, порт 8443, `''`, пробелы, число, `null` → 422; частные адреса → 202
  (F-4).
- **P6** после отказа повторный POST того же URL создаёт вторую задачу (новый `job_id`). SC-US-004-4 требует того же
  `job_id` только пока задача жива, так что это соответствует спецификации. Кабинет показывает последнюю задачу источника.
- **Стражи R-1/R-2** (`n6b-f03v-guards-probe.test.ts`): см. F-2, пойман 1 из 5 обходов.
