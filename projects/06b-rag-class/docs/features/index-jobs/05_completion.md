## Границы и открытое

- **Квитанции контракта — с тестового стека, не со стенда.** Три состояния доказаны вызовом тех же ручек и тех же функций
  воркера на настоящем Postgres в раннере, с настоящими `job_id`. Разрыв соединения прокси и повтор клиента через
  настоящий посредник не проверялись: стенд не поднимался (запрет задания). Это слой 3–4 правила `long-running-job`.
- **SSRF-проверка адреса (шаг 2 алгоритма) — в `crawl-site`.** Здесь проверяются схема, порт и учётные данные; сетевых
  запросов в фиче нет, поэтому `https://127.0.0.1/` сейчас создаёт задачу, которая честно падает «не подключена».
  `crawl-site` обязана отказывать до первого запроса и, по SC-US-002-3, возвращать 422 при создании — ручка для этого
  готова (`normalizeSiteUrl` → место для проверки адресов).
- **PDF (multipart, 413/409/415) — `pdf-source`.** `POST …/sources` принимает только JSON `{url}`.
- **Создания бота из кабинета нет** — ни одна фича 1–3 его не вводит; кабинет показывает ботов и источники, если они есть.
- **Кнопка «Спросить в песочнице»** на экране «Готово» погашена с подсказкой — песочница в `rag-answer-sandbox`.
- **Воркер и `createLiveGateway`:** конфигурация воркера не содержит пределов ответа, а `limitsFrom` требует все семь.
  Фича `chunk-embed` должна либо дать воркеру полную связку, либо ввести дверь только для индексации (и добавить
  `services/worker/src/paid.ts` — он уже в списке S-12).
- Ответ `GET /api/jobs/{id}` шире контракта API (добавлены `job_id`, `source_id`, `fragments`) — ради экрана «312 фрагментов».
- Телеметрия прогона по `docs/development/model-routing-telemetry.md` — у координатора; исполнитель её не вёл.
