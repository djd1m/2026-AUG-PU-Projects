## AC

- MET-01: GET /admin/metrics и POST /admin/metrics/verify доступны только существующей аутентифицированной сессии с account_id в operator; пустая таблица закрывает доступ всем. Аноним/обычный владелец/подделанный body account →404. POST оператора дополнительно требует точный same-origin; foreignOrigin403 и ноль запросов наружу. Страница/JSON не кэшируются публично. Ни новых grant, ни allowlist из env/body, ни публичного selector роли.
- MET-02: показать verified widgets (цель15), raw config+question count рядом, показы/клики badge_event, регистрации account.referred_by_bot_id, conv%=signups/clicks; при0clicks «нет данных», при signups<30 точное «n < 30, K не считается». Canonical не определяет формулу K при n≥30: не изобретать K, тогда просто убрать предупреждение. «Неделя» — отчёт кампании по накопленным строкам canonical алгоритма, не вводить неподтверждённый скользящий7дней фильтр. Единица bot×normalizedhost: двабота наодномхосте=2; verified требует config+firstquestion+page_verified и eligible non-test/nonoperator. Использовать единственную существующую metricHost/excludedMetricHost, в том числе текущий PUBLIC_BASE_URL и закрытые preview suffixes. Badge/signup агрегаты по canonical отдельны от eligibility install; не смешивать эти определения.
- MET-03: перепроверка берёт только eligible pending install с config+first_question, page_verified null; сохранённый page_url повторно совпадает с origin_host через metricHost и не excluded. Существующий createSafeHttp единственный production outbound GET: полный DNS/IP guard и pinned socket, ≤15с настранице и≤2МБ, без автоматических редиректов; не выполнять JS/robots/crawl. Принимается только успешный HTML с настоящим script элементом, src после URL-разрешения ТОЧНО равен PUBLIC_BASE_URL/w.js и data-bot ТОЧНО public_id. Комментарии, текст, wrongbot, wrongorigin/path/query/hash, redirect, invalidHTMLtype, body/timeout/network failure не ставят verified. Никаких отключений DNS/TLS/SSRF ради UI.
- MET-04: POST возвращает202 как принятие bounded проверки после ответа через существующий Next after, а не как обещание её завершения. ≤5страниц заbatch, ≤60с total, последовательные fetch. Общий PostgreSQL advisory transaction lock даёт не более одного batch across instances; освобождение commit/rollback автоматически. Серверный keyset cursor позволяет следующему запуску пройти дальше неуспешных первых страниц и начать новый круг после конца; не допускать starvation за первыми5. Lease и выбранный batch должны быть приняты до202; busy ответ не продвигает cursor. pending rows остаются discoverable после crash/restart, новый круг повторяет оставшиеся; не обещать durable background queue. В callback повторно проверить operator перед outbound. Установка page_verified_at условная: та же page_url/public_id/host, config/question всёещёесть, аккаунт всёещёeligible и actor всёещёoperator; не переписывать существующее время. Concurrent invocations не делают дубликаты fetch; race eligibility/page change не засчитывает устаревший результат. UI честно сообщает «проверка запущена», обновление метрик отдельным действием; никаких незавершённых bare promises.
- MET-05: сохранить F09 нормализацию www/host, exclusion/test/operator/no-config/422/429/503 и idempotent firstquestion semantics. Частные/IP адреса блокируются существующей нормализацией/SSRF-гранью, DNS-resolved private не могут стать verified. Не ослаблять исходные gates, не менять AnswerQuestion/PaidGateway. Панель не раскрывает чужие private данные неоператору, React escaping для host/botname, нет raw IP/секретов в логах.
- MET-06: unit auth/gates/exactscript/zeroandnthreshold and limits; real PG агрегаты, двабота/одинhost, eligibility, concurrentbatch/conditionalwrite and operator revoked. Meaningful mutation нового operator guard или exactscript predicate: fixed test red→exactrestore→samegreen. Существующий safe-http SSRF suite входит в полную регрессию, не повторять неизменённую старую мутацию ради формальности. Node22 полный type/allunit/allrealPG/build, exactsource/image hashes, отдельный свежий Astra review. ActualDockerUI1440/390 realoperatorpage/ordinary404/POST202/refreshedcounts; DBfixtures disposable. Live external verification acceptance не подменять тестовым localhost bypass: маршрут/verifier проверяются realPG+DI fetch тестами, production safeHTTP отдельно имеющимся suite. Реальный UI может проверять pending→202→metrics для недоступных/private fixtureurls без ожидания ложного verified, а positive verified count показывать из честно seededfixtures; раскрыть binding.
