# F08 — публикация бота

База: принятый F07 `13898d855b9dcc9368042488f8f0c979ca75fa2f`; собственная ветка `feature/06b-publish-bot`. Требования: Specification FR-n6b-6/7, SC-US-006-3,007-1/2/3; Pseudocode Publish bot и API PATCH publish; Architecture bot/RLS; ADR-007; Refinement нормализация origin и стражи. N6 donor не читать.

ROUTE перед PLAN: механический S (4 заранее названных файла), повышен до M: контракт публикации и разрешённые origin. Нового публичного неаутентифицированного маршрута, внешнего вызова, схемы/роли или второго production-процесса нет. Обязательные M: meaningful mutation, конкурентная запись общего bot, перекрёстное чтение requirement/architecture, полный type/unit/int/build. Свежая утверждённая SPARC проекта остаётся источником решений. Повторить ROUTE перед IMPLEMENT.

## Приёмка

- PUB-01: PATCH `/api/bots/{id}/publish` только после same-origin/session/UUID/bounded JSON; чужой/несуществующий bot404, unauth401, badOrigin403, malformed/invalid422, слишком большое тело413. Клиент не выбирает account/public_id. RLS owner-pool; ни модели, ни сети для контакта/origin.
- PUB-02: контакт обязателен и ограничен длиной; e-mail, E.164 или https URL. Пустой/неверный контакт422, published/contact/origins не меняются и код не выдаётся. HTTPS с credentials запрещён; произвольные схемы не принимаются. Песочница безконтакта остаётся рабочей.
- PUB-03: массив HTTP(S) origin нормализуется единым helper через URL; схема/host/порт участвуют в идентичности; default80/443 канонизируются, нестандартный порт сохраняется отдельно. Нормализуются регистр/IDNA, дубликаты убираются. Credentials, opaque/null, wildcard и пустой host отклоняются. Полный URL допускается как ввод и приводится к origin. Пустой массив допустим и сохраняется пустым: UI говорит «добавьте домен», последующий widget gate останется закрыт. Ограничить массив/строки и тело, никакого wildcard по умолчанию.
- PUB-04: первый site-source предлагает свой origin в форме неопубликованного бота, без автоматического сохранения; владелец явно подтверждает submit. PDF-only не выдумывает origin. Сохранённый пустой список опубликованного бота не заполняется заново предложением.
- PUB-05: один атомарный owner-scoped UPDATE contact+allowed_origins+published=true (demo_enabled при передаче boolean по имеющемуся API контракту; demo URL/runtime — будущий этап). Конкурентные разные payload не смешиваются: конечное состояние равно одному целому payload. Реальные PostgreSQL/RLS тесты owner/foreign/invalid-before-write/persistence/concurrency.
- PUB-06: успешный ответ/кабинет выдаёт точный script embed-code с URL w.js из PUBLIC_BASE_URL, immutable public_id, async; отображение как текст, без исполнения HTML. До публикации и при пустомконтакте код не показывается; reload сохраняет published/contact/origins/code. Честный текст о пустом origin. Не создавать несуществующий demo URL.
- PUB-07: labelled cabinet form, pending/error/recovery, мобильная390 и desktop1440 без overflow/JSerrors; существующий CTA «Вставить на сайт» ведёт к форме публикации. Demo CTA остаётся недоступен до своей реализации. Реальный DockerUI с настоящей регистрацией/PATCH/PG, без fake provider (платный вызов не нужен).
- PUB-08: Node22 typecheck + все unit + все realPG integration + build, immutable final source hash binding; meaningful contact-publication guard mutation fixed assertion red/restoredgreen; независимый Astra после Sol, только конкретные коррекции; telemetry/sourcebound receipts/cleanup. Публикация стенда посетителям и live calibration — отдельные release gates, не этот этап.
