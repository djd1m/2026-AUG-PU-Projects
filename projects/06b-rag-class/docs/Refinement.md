## Testing Strategy

- **Unit (цель: 80% строк `packages/rag`, 100% ветвей `plan_of`, `excluded`, `normalize_origin`, SSRF-фильтра):** нарезка,
  порог, проверка цитат, вырезание URL, толкование плана, нормализация origin, HMAC посетителя, разбор robots.txt.
- **Integration (Postgres в тестовом compose `name: n6b-test`, пароли `${VAR:?}`):** RLS (чужие строки не видны),
  квоты конкурентно, аренда задач, частичный уникальный индекс, HNSW-изоляция ботов (ADR-002), передача аккаунта.
- **Contract:** порт провайдера на адаптере `fake` (детерминированные эмбеддинги и JSON-ответы), включая «чужой cited_id».
- **E2E (Playwright, на РАЗВЁРНУТОМ стенде по выданному адресу):** регистрация → URL → прогресс → песочница с ссылкой →
  публикация → виджет на странице ЧУЖОГО origin с ограничительным CSP и враждебным CSS → вопрос → бейдж → клик → лендинг.
- **Performance:** 200 000 фрагментов синтетики, поиск p95 ≤ 100 мс; ответ p95 ≤ 6 с на стенде (20 вопросов подряд).
- **Калибровка порога:** 30 вопросов по тестовому сайту (20 с ответом в документах, 10 без) → выбрать `MIN_SIMILARITY`, при
  котором 10 «без ответа» дают «не знаю», а из 20 ≥ 17 отвечены со ссылкой; начальное значение 0.40 `[H]`.
- **Мутационная проверка стражей:** для каждого стража (квота, origin, бейдж, цитаты, SSRF) — прогон с внесённым дефектом,
  тест обязан покраснеть (правило «страж должен уметь падать»).

## Performance Optimizations

- Индексы: HNSW `vector_cosine_ops` + btree `bot_id`; `SET LOCAL hnsw.iterative_scan = strict_order`, `hnsw.ef_search = 64`.
- Кэш: эмбеддинги по `text_sha256` (повторный обход не платит за неизменённые страницы); документ по `content_sha256`.
- «Не знаю» ниже порога без генерации — дешевле и быстрее (≤ 1,5 с).
- Lazy loading: `w.js` грузится `async`; конфиг запрашивается сразу (бейдж нужен при показе пузыря), а панель чата
  создаётся только по клику.
- Статика и `w.js` с `Cache-Control: public, max-age=300` и хэшем версии; не считаются лимитом прокси (урок 429 за NAT).

## Security Hardening

- Input validation: схема тела на каждой ручке; длины; нормализация origin; сигнатура PDF.
- Rate limiting: квоты посетителя/бота/глобальные на ответы (ADR-010); регистрация и вход — 10 попыток/час на адрес.
- Audit logs: смена плана и `badge_removal` оператором; передача аккаунта; публикация бота.
- Заголовки кабинета: CSP без `unsafe-inline`, `X-Frame-Options: DENY`; публичные страницы `no-store`.
- Секреты: `OPENAI_API_KEY`, `SESSION_SECRET`, `VISITOR_SECRET` — только окружение; ключ никогда не уходит в браузер (ADR-011).

## Accessibility

WCAG 2.1 AA: виджет — кнопка с `aria-label`, панель `role="dialog"`, лента `aria-live="polite"`, фокус в поле ввода при
открытии, `Esc` закрывает, контраст ≥ 4.5:1 в фолбэк-палитре; кабинет — навигация с клавиатуры, подписи полей, ошибки
текстом рядом с полем.

## Technical Debt

- Сброс пароля отсутствует (нет почтового провайдера) — владелец, забывший пароль, восстанавливается оператором вручную.
- Предел по адресу /24 грубый: за одним NAT 30 ответов/сутки на всех; при жалобах — сессионная единица в cookie первого лица.
- `widget_install` засчитывает вопрос самого владельца со своего сайта — отличить от посетителя без входа нельзя; честная
  граница метрики, записана.
- Превью-домены хостингов (`*.vercel.app`, `*.tilda.ws`) считаются внешними — открытый вопрос из инвентаря (#4).
- OCR сканов, мультиязычность, аналитика диалогов — вне объёма постановки.
