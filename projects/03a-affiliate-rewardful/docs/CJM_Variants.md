# N3a — варианты CJM

Статус: **владелец одобрил вариант A без уточнений 2026-09-09**. CHOSEN_CJM: A. PRD — следующий этап.
Дата: 2026-09-09. [Кликабельное сравнение](prototypes/cjm/index.html).

## Общее ядро

Первый подключённый бизнес — N1 Proofwall. Партнёр получает ссылку и промокод; вознаграждение возникает после подтверждённой оплаты N1 через ЮKassa. Повторная оплата может дать следующую комиссию. N1 сейчас продлевает доступ вручную на 30 дней; автоматические списания и достоверный партнёрский MRR не обещаются.

Каждого 5-го числа владелец вручную перечисляет доходы за прошлый календарный месяц по таблице начислений. CSV не означает банковскую отправку, ручная отметка не доказывает зачисление получателю. Возвраты отражаются корректировками. В HTML всё демонстрационное: 990 ₽, ставка 20%, комиссия 198 ₽, возврат 330 ₽ → корректировка 66 ₽.

Варианты — альтернативные основы PRD, а не обязательство реализовать три отдельных приложения или все каналы роста одновременно.

## A — Через вознаграждение

[Открыть HTML A](prototypes/cjm/variant-a.html).

| Поле | Содержание |
|---|---|
| Entry Hook / сегмент | Владелец Proofwall хочет платить за продажи; консультант с аудиторией хочет видеть вознаграждение за свои рекомендации |
| Onboarding | Владелец видит N1, ставку, срок выплаты; партнёр получает ссылку и промокод с понятными условиями |
| Core Loop | Настройка → приглашение → оплата N1 → комиссия партнёра → месячная выплата → рекомендация платформы |
| Aha Moment | Первая подтверждённая оплата N1 видна как конкретная комиссия партнёра |
| Growth loop | Incentivized referral; собственная партнёрская программа платформы как способ продвижения |
| Paywall | После первой комиссии предложить владельцу снятие брендинга; цена не определена |
| Риск | Без подходящих активных партнёров программа не приводит продажи |
| Проверяемая гипотеза | Прозрачная комиссия и календарь мотивируют партнёра рекомендовать повторно |

Сигналы для гипотезы: процентные/repeated-payment rewards и персональные coupons документированы [в настройках кампаний Rewardful](https://help.rewardful.com/en/articles/14148863-campaign-settings-overview); независимый код рекомендации — в [promotion-code tracking](https://help.rewardful.com/en/articles/9336630-how-to-use-promotion-codes-for-referral-tracking). Это документированные механики, не измерение их популярности или роста рынка.

## B — Через видимый бренд

[Открыть HTML B](prototypes/cjm/variant-b.html).

| Поле | Содержание |
|---|---|
| Entry Hook / сегмент | Будущий партнёр приходит на публичную страницу программы Proofwall и сразу видит условия |
| Onboarding | Условия до регистрации → явное согласие → персональная ссылка и промокод |
| Core Loop | Страница программы → вступление → оплата N1 → комиссия → месячная выплата → переход посетителя по badge N3a |
| Aha Moment | Участник открытой программы видит первую подтверждённую комиссию |
| Growth loop | Badge loop на публичной странице программы; видимость платформы растёт с посещениями программы |
| Paywall | Снять N3a badge с публичной страницы — платная опция владельца; цена не определена |
| Риск | Без трафика страницы нет охвата; показы не равны виральности и продажам |
| Проверяемая гипотеза | Открытые условия снижают барьер вступления, а бренд знакомит посетителей с платформой |

Сигналы для гипотезы: merchant/affiliate dashboards и контроль брендинга описываются [Rewardful](https://www.rewardful.com/pricing); links/coupons и portal controls — [настройками кампаний](https://help.rewardful.com/en/articles/14148863-campaign-settings-overview). Эффективность badge именно N3a — гипотеза. Изменение виджетов/Wall of Love N1 этим вариантом не предлагается.

## C — Через сопровождение

[Открыть HTML C](prototypes/cjm/variant-c.html).

| Поле | Содержание |
|---|---|
| Entry Hook / сегмент | Владелец Proofwall хочет сначала убедиться в корректности финансового учёта |
| Onboarding | Совместный разбор → проверка маршрута оплаты → приглашение партнёра |
| Core Loop | Разбор → проверка N1 → приглашение → сверка продажи и комиссии → реестр → показ кейса коллеге |
| Aha Moment | Первая оплата N1, комиссия N3a и сумма в будущем реестре сошлись |
| Growth loop | Sales loop: ручное сопровождение и работа с владельцем; нового клиента привлекает человек |
| Paywall | После результата можно предложить платное сопровождение; снятие брендинга остаётся платной опцией. Цены не выбраны |
| Риск | Рост требует времени человека, а один удачный запуск не доказывает масштабируемость |
| Проверяемая гипотеза | Совместная настройка и сверка снижают недоверие к расчётам |

Сигналы для гипотезы: [ручная выплата комиссий Rewardful](https://help.rewardful.com/en/articles/2773351-how-do-i-pay-commissions) разделяет расчёт и внешний перевод; [уведомления ЮKassa](https://yookassa.ru/developers/using-api/webhooks) требуют учитывать подтверждённые состояния платежей/возвратов. Это основания для удобной сверки, не доказательство спроса на сопровождение. CRM кандидатов, авторассылка и бронирование встреч не входят в вариант.

## Growth-требования, общие для любого выбранного варианта

| ID | Как проявляется в вариантах |
|---|---|
| FR-GROWTH-001 | Добровольно подготовить рекомендацию/кейс после первой подтверждённой комиссии; не отправлять автоматически |
| FR-GROWTH-002 | Ссылка с cookie и промокод связывают клиента с партнёром до подтверждённой оплаты; регистрация сама по себе не оплачивается |
| FR-GROWTH-003 | Badge N3a на публичной странице программы в free; снятие — платная опция владельца |
| FR-GROWTH-004 | Персональный код партнёра с аудиторией (в примере ANNA), раздельная атрибуция результатов |

Эти ID не переименовываются под альтернативные growth loops. После выбора в PRD/Specification каждый получит happy/edge/security сценарии; сейчас это вход к выбору, не готовая спецификация.

## Решение владельца

Владелец выбрал **A — Через вознаграждение** без уточнений 2026-09-09. Основа PRD: настройка → приглашение → оплата N1 → комиссия партнёра → месячная выплата → рекомендация платформы.

Обязательные условия повторно подтверждены: первая интеграция N1, ЮKassa, ручные выплаты 5-го числа за предыдущий календарный месяц. Демонстрационная ставка 20% не становится утверждённым коммерческим условием: ставка задаётся владельцем программы.

B и C сохранены как рассмотренные альтернативы и не выбраны, поскольку владелец выбрал A. Других причин отказа владелец не указал. Общие FR-GROWTH-001..004 сохраняются; самостоятельные onboarding-пути B/C не входят в реализацию A.

HTML и ZIP — сохранённый снимок демонстрации на момент выбора. Их кнопки подготавливают сообщение, а статус одобрения определяется этим разделом и решением в чате.
