## Required adversarial/concurrency cases

1. Bootstrap two clients with same request, conflicting requests and same pilot slot; crash after commit before token write. Repeat with the original existing output path returns IDs only without opening/truncating that file. Explicit offline reissue revokes the unconsumed predecessor and creates one linked replacement on the same ownerless program, with replay/conflicting/consumed-predecessor denial tests. Race reissue versus HTTP acceptance in both serial orders; a second distinct reissue request against an already replaced predecessor denies without a second usable grant. Missing evidence and app role cannot provision. No one is declared verified merely by producing a hash.
2. New-user signup under two valid grants for the same normalized identity: unique identity prevents duplicate/replacement. A grant bound to another user fails. Missing/disabled/changed credential snapshot and grant revoke/expiry after KDF preflight all deny the final write. No DB lease is held while KDF paused.
3. Session revocation concurrent with grant acceptance: mutation function recheck and lock ordering produce a valid serial outcome. If revoke commits first, acceptance denies; if acceptance commits first, subsequent request denies. Use two real clients: hold session FOR SHARE during authorized mutation and observe logout waiting; commit logout before a blocked acceptance resumes and require denial on fresh locked recheck. Lock waits crossing expiry must deny by fresh clock_timestamp. Tests must not require impossible rollback of an already committed authorized action.
4. Owner grant acceptance versus policy/invite request: null owner cannot configure before its membership commits. Delegation tests every prohibited scope and malformed/duplicate scope; client role/tenant/partner fields are rejected, not silently authoritative. Owner recovery/transfer is excluded rather than an untested superuser route.
5. Hold a program/session lock across a scheduled effective boundary and require stale displayed consent to conflict using post-lock decision_at; grant expiry across the wait also denies. A synthetic latest fact later than decision_at makes a new transition unavailable without backdating. Policy effective_at exact boundary, no policy, only-future policy, timestamp collision, latest future version preventing a retroactive now insertion. Full terms with Cyrillic/multibyte text remain exact hash; HTML/script rendered as text. Future timezone snapshot does not change the current effective calendar; switching at effective time selects terms and timezone together. IANA timezone before/after lock; paused state cannot unlock calendar.
6. Consent concurrency/failure after membership, each asset, each fact and consume writes. Injection harness is test-only, e.g. transaction rollback trigger/fixture; no HTTP failpoint or runtime control. Replay after invite expiration can read original result only for current valid authority; revocation/suspension denies and leaves state unchanged.
7. Suspension/reactivation/asset revoke histories at same timestamp use version order. An active old customer eligibility fixture stays historically active when current partner is suspended; no N1 ledger test is claimed. Repeating same transition adds no new fact; individually revoked promo never revives with partner.
8. Hold16 handler slots with blocked runtime/DB/body operations; seventeenth request fails503 without reading body or enqueueing a DB waiter. Cancellation never over-releases a slot; settled work releases exactly once. Counter concurrency at exact window limit, adjacent windows and restart; varied source/identity keys never add rows. Hash collisions share limit safely. Honest distinct identities behind a NAT succeed below source budget; saturation yields explicit finite429, no claim of unlimited availability. Source headers never create trusted source identity. Global/source transaction committed before parsing; rejection creates no enrollment effect.
9. CSRF tests anonymous→authenticated rotation, reused preauth proof, missing/mismatched cookie/header, expired proof, foreign/null/no Origin, content type and body slow/oversize; no business write before guards. Cookie remains Secure and HttpOnly in actual browser, not just string unit assertion.
10. No function relies exclusively on service validation; app schema privileges remain foundation-denied. Catch raw errors with sensitive sentinels and ensure none reach logs/HTTP/URLs.
