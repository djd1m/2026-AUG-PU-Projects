# N3a — партнёрская программа для N1 Proofwall

N3a — отдельный проект партнёрского учёта для первого пилота N1: персональная
атрибуция, комиссии по подтверждённым оплатам ЮKassa, refund-корректировки,
месячный реестр и ручная фиксация внешнего перевода.

## Текущее состояние

- Выбран CJM A; HTML в `docs/prototypes/cjm/` остаётся демонстрацией.
- PRD, Specification, Pseudocode, Architecture, ADR, C4, Refinement и Completion
  прошли документальную проверку с оговорками; результат в `docs/validation-report.md`.
- Создан проектный toolkit: роли, правила, контекстные skills и dependency-ordered roadmap.
- Общие lifecycle-команды, hooks и базовые skills используются из корневой `.claude/` и
  не копируются в проект.
- Реализуется foundation: каркас Next.js, приватная PostgreSQL, миграции и внутренние сессии. Публичное подключение партнёров и финансовые функции ещё впереди. Итоговая приёмка foundation отслеживается в `docs/features/foundation/05_completion.md`.
- D7 (собственная партнёрка N3a) остаётся заблокированным решением владельца.

В работе `foundation`: самостоятельный каркас, миграции, Argon2id из N1 и внутренние сессии. Аудит доноров завершён; семь критериев первого блока находятся в `docs/features/foundation/`. Публичные маршруты регистрации и входа появятся вместе с полным контуром доверенного подключения и согласия партнёра.

Будущие `/feature`, `/next`, `/go` и `/run` принадлежат корневому toolkit. Их наличие в
репозитории не означает, что N3a уже готова к запуску: публичные и финансовые функции проходят следующие стадии roadmap.

## Проверка разработки

Требуются Node22.22.0 и Docker Compose. Из каталога проекта:

```sh
npm ci --ignore-scripts
npm run verify
npm run test:isolated -- --mutations --image
```

Последняя команда сама создаёт новые тестовые секреты и отдельный namespace, проверяет порты, собирает приложение, запускает PostgreSQL без host port, проверяет реальные SQL-права и мутации, собирает и запускает Docker-образ web. После проверки останавливает только свой стек; тестовый volume сохраняется для диагностики. Команды выполнять последовательно: smoke использует законченный build.

`npm start` требует явно заданных `DATABASE_URL` и `SESSION_SECRET`; автоматически тестового пользователя не создаёт. `/api/health` означает только живой процесс. Регистрация, вход, подключение N1 и выплаты пока не доступны.
