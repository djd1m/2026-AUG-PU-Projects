## Порядок фич

Двенадцать фич MVP в линейном порядке зависимостей, [`.claude/feature-roadmap.json`](.claude/feature-roadmap.json):

```
foundation → upload-and-quota → queue-and-probe → transcription → selection-and-score
  → render-and-watermark → progress-and-clips-screen → short-link ─┐
                                                                    ├→ partner-codes-and-dashboard
  progress-and-clips-screen → guest-pack ───────────────────────────┘
  progress-and-clips-screen → limits-ui-and-pro-interest
  guest-pack + limits-ui-and-pro-interest → retention-and-erasure
```

Порядок не произволен: конвейер «загрузка → probe → транскрипция → выделение → рендер» доводится до
конца прежде, чем появляются экраны, потому что до первого отрендеренного клипа проверять на
экранах нечего. `short-link` идёт после рендера, но **строка `clip_link` создаётся раньше** — на
стадии выделения: метка обязана нести код ЭТОГО клипа, а метка вшивается в пиксели.

`upload-and-quota` и `render-and-watermark` — **XL** по
[`complexity-router.md`](../../.claude/rules/complexity-router.md): первая трогает деньги, вторая —
несущий инвариант метки и метрику недели. Обе требуют остановки на плане у владельца.

## Цикл одной фичи

```bash
# 0. тир — до всего остального
bash ../../scripts/complexity-router.sh          # 0 → напрямую · 1 → L/XL, полный /feature · 2 → разобраться

# 1. выбрать фичу
/next                                            # читает .claude/feature-roadmap.json

# 2. выполнить
/go <feature-id>                                 # маршрутизирует в /plan | /feature
#    при коде 1 роутера вендорная оценка /go НЕ применяется: идти по нашему тиру

# 3. закрыть
/next <feature-id>                               # отметить done, каскадно разблокировать
```

Фазы `/feature` — PLAN → VALIDATE → IMPLEMENT → REVIEW, и **Phase 2 не пропускается**
(`../../.claude/rules/feature-lifecycle.md`). Коммит после каждой фазы, push — отдельное решение
владельца.

Каждая фича закрывается квитанцией `docs/features/<slug>/05_completion.md`, и в ней обязаны быть
три вещи: обе строки испытания каждого нового стража (красная при внедрённом дефекте и зелёная
после восстановления); что фича **НЕ** доказывает; хвост — что осталось непроверенным и почему.

## Режим cross-family (OWN-002)

Планирование и проверка — семейство **Anthropic**. Кодирование — семейство **OpenAI** (Codex).
Ревью кода возвращается на **Anthropic**. Правило простое: модель, написавшая код, не проверяет его
сама.

Телеметрия p-replicator ведётся с первой стадии, а не задним числом:
`docs/telemetry/p-replicator/<RUN_ID>/` — `run.json`, `events.jsonl`, квитанции единиц. Запись
начинается ДО первой стадии и обновляется на границах стадий; учитываются координатор, все агенты,
повторы и fallback. Недоступный счётчик помечается `null` с причиной, а не опускается. Выбор модели
в тексте не означает, что она была переключена — фактическую модель подтверждают метаданные
исполнения.

## Стражи: что и когда запускать

### Перед каждым `docker compose up`

```bash
node ../../.claude/hooks/check-ports.cjs .               # Правило №0: db, redis, minio наружу не смотрят
bash ../../scripts/check-port-conflicts.sh .            # занятость портов этой машины и обход прокси
```

Две проверки, не одна: вендорная отвечает «что смотрит наружу», наша — «свободно ли то, что мы
просим». Ни одна не заменяет другую. `docker compose` вызывать **с `--project-directory .`**.

### Перед передачей результата фичи

```bash
npm test                                   # ВСЕ наборы, не только свой
npm run lint && npm run build              # по каждому workspace
bash scripts/check-env-wiring.sh           # страж №1 deployment-seams; пишется фичей foundation
bash ../../scripts/check-port-conflicts.sh .
bash scripts/check-cjm.sh https://<стенд>  # путь целиком по ВЫДАННОМУ адресу, не localhost
```

Прогон **всех** наборов, а не своего, — не педантизм: урок предшественника, где миграция была
зелёной в своём наборе и уронила три чужих.

### Ворота документов (когда документы менялись)

```bash
node ../../.claude/hooks/check-canon.cjs .          # канон назван и привязан
node ../../.claude/hooks/check-model-cost.cjs .     # у каждого платного вызова назван предел числом
node ../../.claude/hooks/check-job-contract.cjs .   # три состояния долгой задачи различимы
node ../../.claude/hooks/check-external-deps.cjs .  # у каждой внешней способности есть вердикт
node ../../.claude/hooks/check-look-trace.cjs .     # снятое с источника доехало до спецификации
```

Код `2` означает «проверка НЕ выполнена» и **никогда** не читается как «всё в порядке». На момент
Phase 2 `2` отвечают: `check-growth-trace` и `check-handoff-manifest` (Phase 0 не выполнялась, вход
`--from-docs`), `check-job-contract` (`not-deployed`), `check-webhook-contract` и
`check-embed-contract` (законные ответы «вебхуков нет» и «виджета нет»), `check-review-contract`
(Phase 4 не выполнялась), `check-source-version` (нет `docs/source-versions.md`).

### Испытание стража внедрённым дефектом

Страж, ни разу не показавший красное, стражем не является. Для каждого из 12 стражей ADR (таблица в
[`.claude/rules/testing.md`](.claude/rules/testing.md)):

```text

2. восстановить код            →  прогон обязан дать зелёное
3. обе строки — в квитанцию фичи
```

## Проверка на развёрнутом стенде

Юнит-тесты — утверждение о модуле, а не о системе. Три дефекта проекта-предшественника имели
одинаковую форму: каждая часть корректна, дефект в допущении, которое одна часть делала о другой.

1. Закрыть Pre-Deployment из [`docs/Completion.md`](docs/Completion.md) целиком. В нём, среди
   прочего: **шесть** отдельных прогонов старта на отсутствующие `N5_LIMIT_*` (не пять), седьмой на
   `N5_PUBLIC_ORIGIN`, бакет Cloud.ru с CORS и lifecycle на префиксе `clips/free/`, замер скачивания
   2 ГБ на канале VPS, свободный диск ≥ 20 ГБ.
2. Поднять профиль `edge`; единственный публикуемый порт — `127.0.0.1:${N5_EDGE_PORT:-4181}`.
3. Пройти CJM D **целиком по внешнему адресу, который выдало развёртывание**, а не по `localhost`:
   вход → загрузка → прогресс → клипы → скачать → короткая ссылка → отправить гостю → гостевая
   страница → код партнёра → кабинет.
4. Ручная приёмка совместимости Cloud.ru: `CompleteMultipartUpload`, `AbortMultipartUpload`,
   `Range GET` клипа, presigned `PUT` из браузера. Тесты на MinIO этого не доказывают.
5. Читаемость метки на телефоне: два человека смотрят 5 клипов с руки, экран ≈6 дюймов. Результат —
   строка в `Completion.md`, а не предположение.

Четвёртый и пятый пункты не автоматизируются, и это записано прямо, чтобы зелёный отчёт не
выдавался за то, чем не является.

## Параллельная работа

Каждый пишущий агент получает изолированный worktree и непересекающийся набор файлов. У единицы
есть `WORK_UNIT_ID`, абсолютный `TRACE_PATH` и квитанция, последняя строка которой — ровно
`Status: completed` либо `Status: failed`. Координатор интегрирует только по таким квитанциям:
мёртвый агент молчит ровно так же, как работающий, и различает их только файл
(`../../.claude/rules/swarm-file-evidence.md`).

Общие манифесты — `package.json`, lockfile, `docker-compose.yml`, миграции — правит **только**
integration owner. Читающее исследование может идти параллельно без ограничения.
