## Edge Cases Matrix

| Scenario | Input | Expected | Handling |
|---|---|---|---|
| Empty input | `POST /api/upload/complete` с суммой частей 0 байт или без частей | `video.status = failed(not_media)` «файл не является видео или аудио»; минуты не списаны; слот `user_uploads` ВОЗВРАЩАЕТСЯ той же транзакцией, что и `failed` — `not_media` входит в список возврата по СВОЙСТВАМ файла (DEC-A-014, V3-R04), а не в список отказов по потолку | Magic-bytes проверка на `upload/complete` до `ffprobe` (FR-INGEST-002) |
| Max size | `video.create` с заявленным размером > 2 000 000 000 байт | Отказ ДО выдачи подписанных ссылок; ссылки не создаются; слот `user_uploads` ЕЩЁ НЕ СПИСАН на этом шаге — списание происходит позже, ПОСЛЕ выдачи ссылок (FR-INGEST-001), так что возвращать здесь нечего | Числовая проверка на входе процедуры (FR-INGEST-001, канон §7) |
| Фактическая сумма частей превышает потолок | Заявлено 1,9 ГБ, реально догружено 2,3 ГБ частями | `422` на `upload/complete`, объект удалён, минуты НЕ списаны (вызова поставщика не было); слот `user_uploads` ВОЗВРАЩАЕТСЯ той же транзакцией — `too_large` тоже входит в список возврата по свойствам файла (DEC-A-014, V3-R04: соседняя строка молчала о слоте) | Сервер суммирует части на завершении, не доверяет заявленному клиентом размеру (ADR-002 Confirmation б) |
| Concurrent access | Две загрузки одного аккаунта приходят одновременно на границе суточного потолка минут | Суммарно списано не больше потолка, ровно одна отклонена (SC-US-011-3) | Один атомарный оператор `WHERE used + :minutes <= :limit`, не «прочитать-потом-записать» (FR-LIMIT-001) |
| Network failure | OpenAI Audio API или Anthropic Messages API не отвечает или обрывает вызов | `job_attempt.status = failed`, попытка ЗАСЧИТАНА в журнал расхода (счёт по попыткам), видео получает «отказ» с причиной и кнопкой «повторить» | Исключение из вызова провайдера не проглатывается: недоступность источника истины — исключение, а не возвращаемое значение (`security-operation-order.md`) |
| Файл без звуковой дорожки | Видео-контейнер валиден по magic bytes и по размеру, но `ffprobe` в `worker-stt` (шаг `probe`, ПОСЛЕ скачивания оригинала) не находит аудиопоток | `failed(no_audio)` «в файле нет звуковой дорожки»; минуты не списаны (вызова Whisper не было); слот `user_uploads` ВОЗВРАЩАЕТСЯ той же транзакцией, что и `failed` (DEC-A-014) | Проверка звуковой дорожки — часть шага `probe` на `worker-stt`, ДО списания минут и ДО Whisper; у `web` нет `ffprobe` (DEC-A-011, V2-R11) |
| Полиглот | Файл валиден одновременно и как видео, и как HTML/архив | Отвергается на этапе определения типа по первым байтам на `upload/complete`, не доходит до скачивания воркером | Magic-bytes проверка не принимает множественную интерпретацию (Security Architecture) |
| Длительность 1:59 | Запись на 1 с короче нижней границы; измеряется `ffprobe` в `worker-stt` ПОСЛЕ скачивания оригинала | `failed(too_short)` «запись короче 2 минут» на экране прогресса (не в ответе на завершение загрузки); минуты не списаны; слот `user_uploads` ВОЗВРАЩАЕТСЯ (DEC-A-014) | Граница строгая: `< 120` с, а не `<= 120` (FR-INGEST-002, канон §7, DEC-A-011) |
| Длительность 90:01 | Запись на 1 с длиннее верхней границы; измеряется `ffprobe` в `worker-stt` ПОСЛЕ скачивания оригинала | `failed(too_long)` «запись длиннее 90 минут»; минуты не списаны; слот `user_uploads` ВОЗВРАЩАЕТСЯ (DEC-A-014) | Граница строгая: `> 5400` с (FR-INGEST-002, DEC-A-011) |
| Два слишком длинных файла подряд | У аккаунта 2 загрузки в сутки, обе не использованы; обе записи длиннее 90 минут, обе отвергнуты `probe` по длительности | Обе `failed(too_long)`, ОБА слота `user_uploads` возвращены (списан ровно 1 из 2 возможных возвратов `user_upload_refunds`); третья загрузка в те же сутки принимается; `user_minutes` не изменился ни разу (DEC-A-014) | Без возврата два таких файла сожгли бы оба суточных слота без единого клипа — тот же класс, что `fail-closed-defaults.md`, но в обратную сторону: отказ по СВОЙСТВАМ файла не должен стоить как отказ по ПОТОЛКУ |
| Третий негодный файл за сутки — потолок возвратов исчерпан | У аккаунта уже 2 возврата слота за сегодня (`user_upload_refunds`); третий файл того же дня отвергнут `probe` по СВОЙСТВАМ (`too_long`, `too_short`, `no_audio`, `not_media`, `too_large`, `probe_timeout`) | `failed` с причиной по свойству файла КАК ОБЫЧНО, но слот `user_uploads` НА ЭТОТ РАЗ НЕ возвращается: `CheckAndConsumeQuota(reason=upload_refund)` отказывает по достигнутому потолку 2/сутки; текст объясняет, что третий отказ — за счёт пользователя (DEC-A-015) | `RefundUploadSlot` сама списывает атомарный ключ `user_upload_refunds` ДО возврата; пустой результат оператора — возврата не происходит, слот потерян, а не молча продлевается на бесконечность |
| Загрузка оборвана на 60 % | Соединение оборвалось после части 6 из 10 | `video.status = uploading` остаётся; пользователь находит задачу по `video_id` и либо догружает, либо создаёт новую с новым `Idempotency-Key`; незавершённые части удаляются lifecycle через 1 день | `AbortIncompleteMultipartUpload(DaysAfterInitiation=1)` на бакете (ADR-002 п.4); задача не попадает в очередь `stt`, потому что `upload/complete` не вызван |
| `ffprobe` таймаут | Файл вызывает зависание `ffprobe` в `worker-stt` (повреждённый контейнер) | `failed(probe_timeout)` «не удалось прочитать файл»; минуты не списаны; слот `user_uploads` ВОЗВРАЩАЕТСЯ (DEC-A-014); временный файл удалён | `ffprobe` — дочерний процесс с ограничением по времени на `worker-stt`, принудительное завершение (INS-010: `ffprobe` обязан быть в образе ВОРКЕРА, не `web` — V2-R11, DEC-A-011) |
| Whisper вернул результат без таймкодов слов | Ответ `verbose_json` без `words[].start/end` (несоответствие контракта поставщика) | Результат отвергается ДО постановки `select`; `job_attempt(stage=stt)` → `failed(no_timestamps)` | Контракт `Transcriber` проверяется в адаптере, не у вызывающего кода (ADR-003 Confirmation) |
| Чанк на границе фразы | Разбиение по паузам всё же приходится на середину фразы одного слова | Слово не теряется и не дублируется: сшивка по смещению чанка с проверкой перекрытия по времени слова | `TRANSCRIBE-002`: разбиение по паузам, не по фиксированному времени; перекрытие чанков сверяется по `start/end`, дубликат на стыке отбрасывается |
| Потеря одной части при чанкинге | Один аудиочанк из пяти не ответил после повтора | Отказ ВСЕЙ транскрипции, а не тихая склейка с дырой; `failed` с причиной «не удалось расшифровать» | FR-TRANSCRIBE-002: транскрипт с пропущенной серединой хуже честного отказа |

## Testing Strategy

Раннер — **vitest**. Слой выбирается по природе признака, а не по удобству
([`cost-of-detection-ladder`](../../../.claude/rules/cost-of-detection-ladder.md)):

| Природа признака | Слой | Примеры из проекта |
|---|---|---|
| арифметика, закрытые перечисления, границы | unit | оценка = сумма трёх компонентов 0–33; границы 2–90 мин, 20,0–75,0 с; fail-closed по `account.plan` и статусам; честное число фрагментов < 3 |
| согласованность двух и более компонентов, транзакции, ответы маршрутов | integration | три исхода `code.apply` (ADR-007); фенс попыток (ADR-001); `guest.create` без согласия (ADR-008); маршрут вебхука отсутствует (ADR-005) |
| путь человека на РАЗВЁРНУТОМ стенде | E2E | загрузка → клипы (Сергей); гостевая страница (Анна); код партнёра (Кирилл); удаление аккаунта за 72 ч |
| разделяемый ресурс | **конкурентный** | квота (6 ключей: `user_minutes`, `user_uploads`, `user_upload_refunds`, `user_llm`, `global_minutes`, `global_llm` — DEC-A-010, DEC-A-015); идемпотентность `video.create`; `link_view`/`guest_opened` — уникальность переходов и открытий; два воркера на одном фенсе |

Интеграционные тесты — на НАСТОЯЩЕМ PostgreSQL 16 и Redis 7 в тестовом профиле compose (без
публикации портов), с MinIO вместо Cloud.ru (ADR-002: тесты в MinIO НЕ доказывают совместимость
Cloud.ru — только ручная приёмка на развёрнутом стенде это делает). Фейки поставщиков STT/LLM/S3 —
детерминированные, отвечают по контракту, включая пограничные случаи (без таймкодов, > 8 кандидатов,
оценка вне диапазона, 5xx, таймаут). **Тесты не ходят в интернет.** Живой режим включается ключами
и помечается в отчёте отдельно — прогон без ключей не выдаётся за смоук с реальными поставщиками.

### Обязательные конкурентные прогоны

Последовательный тест на разделяемом ресурсе зеленеет при ОБЕИХ реализациях — атомарной и
«прочитать-потом-записать» ([`shared-resource-verification.md`](../../../.claude/rules/shared-resource-verification.md)):

1. **Квота, шесть ключей (DEC-A-010, DEC-A-015).** N параллельных `video.create`/повторов `select`
   одного аккаунта на границе `user_minutes` (90) и `user_uploads` (2) — суммарно списано не больше
   потолка, ровно лишние отклонены. Отдельно — `user_llm` (2) на границе, когда одна и та же сессия
   параллельно шлёт два «повторить» на стадии выделения: РОВНО один проходит. Отдельно —
   `user_upload_refunds` (2) на границе: два параллельных отказа по СВОЙСТВАМ файла у одного
   аккаунта при остатке 1 — РОВНО один возврат слота проходит, второй отказ слот не возвращает.
   Отдельно — `global_minutes` (600) и `global_llm` (20) на границе при параллельных запросах
   РАЗНЫХ аккаунтов: добросовестный параллельный пользователь на своём лимите не блокируется чужой
   квотой. **Это ДОПОЛНЯЕТ, а не заменяет, отдельный тест на границу суток** (см. таблицу находок
   Phase 2, V2-R01 ниже) — конкурентный прогон проверяет гонку НА УЖЕ СУЩЕСТВУЮЩЕЙ строке счётчика и
   не ловит дефект ветки `INSERT`, который виден уже на первом запросе суток и без конкурентности.
2. **Идемпотентность `video.create`.** Два одновременных запроса с одним `Idempotency-Key` дают одну
   строку `video` и одно списание `user_uploads`.
3. **Два воркера на одном фенсе.** Задание `render(fence=N)` доставлено дважды — либо эксклюзивность
   очереди не допускает второго исполнителя, либо (если оба всё же выполнились) только ОДИН `UPDATE
   … WHERE fence` затрагивает строки; второй — 0 строк, аудит `stale_attempt_result`.
4. **Уникальность `link_view`.** 20 параллельных переходов по одному `/c/{code}` с одного `ip_prefix`
   за одни сутки засчитываются как РОВНО 1 (частичный `UNIQUE (type, clip_link_id, ip_prefix, day)
   WHERE type = 'link_view'`, V2-R12).
5. **Уникальность `guest_opened`.** 10 параллельных открытий одной гостевой страницы с одного
   `ip_prefix` за одни сутки засчитываются как РОВНО 1 — частичный `UNIQUE (type, guest_pack_id,
   ip_prefix, day) WHERE type = 'guest_opened'` (V2-R12): у `link_view` уникальность была, у
   соседнего события её не было, хотя кабинет партнёра и вторая половина метрики недели («≥ 50 %
   открыто») считают оба события одинаково уникальными.

## Performance Optimizations

Частичный индекс `video (status) WHERE status IN ('queued','transcribing','selecting','rendering')`
для сторожа (Architecture, Data Architecture). Чанкинг STT по паузам вместо фиксированного времени
снижает число повторов на границе фразы. Один рендер на клип в неделе — снятие метки означало бы
повторный рендер, вне недели (FR-TARIFF-001). Кроп 9:16 без распознавания лиц — дешевле и
детерминированнее auto-framing. `worker-video` с `concurrency: 1` — узкое место названо явно
(Architecture, Scalability), а не скрыто за автоматическим масштабированием, которого нет.
Даунскейл оригинала до 1080p на входе рендера при узком канале VPS (Architecture, Scalability:
«при узком канале даунскейл до рендера»). Кэша субтитров/оценок нет осознанно: один вызов на запись,
повторное вычисление дешевле инфраструктуры кэша при 10 записях в сутки.

## Security Hardening

Порядок операций — защита, не деталь (`security-operation-order.md`, Specification §1, пять
последовательностей): лимит частоты Caddy до тела запроса; валидация до заявки `Idempotency-Key`;
квота после валидации и до постановки в очередь; резерв диска до скачивания оригинала; согласие
гостя до создания `guest_pack`. Magic-bytes проверка типа на `upload/complete`, не расширение и не
`Content-Type` от клиента (FR-INGEST-002). Presigned-ссылки ≤ 15 мин, ключи хранилища только у
`web`, `worker-stt`, `worker-video` (NFR-SEC-001, канон §6). Чужой и несуществующий `video_id`/
`clip_id` дают одинаковый `404` — владение проверяется по `account_id` сессии, не по телу запроса
(аналог `security.md` проекта N4, не переизобретается здесь заново). CSP без инлайновых скриптов;
`connect-src` — свой origin плюс endpoint S3 для загрузки браузером. Anti-fraud: порог 50/10 мин на
`ip_prefix`, самореферал и самопереходы не считаются (FR-PARTNER-003). Секреты только `${VAR:?…}`,
без дефолтов (`docker-ports.md`, `honest-configuration.md`).

## Accessibility

Экран клипов управляем с клавиатуры: фокус на карточке, `Enter` = скачать, `Space` = отметить
чекбокс гостя. Субтитры вшиты как текст (ASS), а не только пиксели плеера — экранный ридер клипа
их не видит, но исходный транскрипт остаётся текстом в интерфейсе результата (доступность
редактирования, не только просмотра). Контраст подложки метки ≥ 4,5:1 (FR-RENDER-002) — то же число,
что и общий контраст текста интерфейса WCAG 2.1 AA. Гостевая страница и `/c/{code}` открываются в
WebView площадок БЕЗ клиентского JS: SSR — не только производительность, а условие доступности для
устройств с блокировкой скриптов (embed-contract.md).

Осознанно отложено в неделю: FR-INGEST-003 (ссылка VK Видео/Rutube), FR-RESULT-003 (отправить в
Telegram), FR-AUTH-002 (вход через Telegram) — все три `Should`, решение фиксируется в

anti-fraud (50/10 мин) — отправная точка без калибровки по реальному трафику этой недели.
`FR-INGEST-003` в Architecture отмечен `UNCONFIRMED` (нет документации поставщика, разрешающей
скачивание) — требование остаётся Should и не реализуется, пока не найдено подтверждение.
Восстановление пароля отложено осознанно (DEC-A-007): почтового провайдера нет в инвентаре внешних
зависимостей, а вход через Telegram (`Should`, FR-AUTH-002) не покрывает того, кто регистрировался
по почте. На неделю измерения единственный путь — ручная смена `password_hash` оператором по
обращению пользователя; полноценное самостоятельное восстановление входит в v1 вместе с почтовым
провайдером в `Architecture.md` → `## External Dependencies`.

Грабли январского клона, учтённые заранее (полный список — `scratchpad/opus-clone/myinsights/`):
