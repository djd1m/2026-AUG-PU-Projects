# Как поднять «КлипМейкер» заново в другом окружении

Документ описывает продукт **таким, каким он собран и проверен на 24.09.2026**, а не таким, каким
он был задуман. Там, где SPARC-документы Phase 0–2 (`PRD.md`, `Specification.md`, `Architecture.md`,
`Final_Summary.md` и другие) расходятся с этим файлом, **прав этот файл** — расхождения перечислены в
разделе «Что изменилось относительно замысла».

Порядок разделов — порядок действий. Каждый шаг заканчивается проверкой: не переходите к следующему,
пока проверка не прошла.

---

## 0. Что получится в конце

Веб-приложение, в которое загружают запись подкаста или вебинара (до 2 ГБ, 2–90 минут), и через
~13 минут на 88-минутную запись получают 3–8 вертикальных клипов 1080×1920 с субтитрами, кадром,
следующим за лицом говорящего, и меткой с короткой ссылкой.

Измерено на живой записи 88,4 мин (`docs/measurements/2026-09-23-first-long-recording.md`):
расшифровка 7 мин 48 с, выбор фрагментов 1 мин 46 с, резка 7 клипов 3 мин 05 с.

## 1. Что нужно заранее

### Машина

| Ресурс | Минимум | Почему |
|---|---|---|
| CPU | 4 ядра | ffmpeg режет клипы по одному, но занимает все ядра |
| Память | 8 ГБ | само приложение ~600 МБ; ffmpeg и OpenCV растут на длинных файлах |
| Диск | **от 100 ГБ SSD** | перед скачиванием записи резервируется её **тройной** объём; предельная загрузка 2 ГБ требует 6 ГБ свободных. Образы с OpenCV весят ~1,5 ГБ, и каждая пересборка оставляет слои — чистить `scripts/cleanup-our-docker.sh` |
| ОС | Linux с Docker 24+ и Compose v2 | всё крутится в контейнерах |

Node на хосте нужен только для локального запуска тестов без Docker: **Node 22** (`engines` в
`package.json`: `>=22 <23`).

### Внешние учётные записи

| Что | Зачем | Где взять |
|---|---|---|
| **OpenRouter**, ключ API | ОДИН ключ на обе модели: расшифровка и выбор фрагментов | openrouter.ai → Keys. Точную цену записи не измеряли; фактический расход по каждой попытке пишется в журнал `model-spend.jsonl` (том `model-spend`) и виден в кабинете OpenRouter |
| **S3-совместимое хранилище** | исходники и клипы | для стенда достаточно встроенного MinIO (профиль `test`); в бою — Cloud.ru Object Storage |
| **Домен** | адрес вшивается в пиксели метки каждого клипа | любой регистратор; **короткий** — см. шаг 6 |
| TLS | сертификат для домена | Caddy выпустит сам, если домен смотрит на машину |

## 3. Конфигурация

```bash
cp .env.example .env
chmod 600 .env
```

Файл `.env` в git не попадает. Ниже — **каждая** переменная, её смысл и чем заполнить.

### Секреты — сгенерировать

```bash
openssl rand -hex 24   # по одному вызову на каждое значение ниже
```

| Переменная | Что это |
|---|---|
| `N5_DB_APP_PASSWORD` | пароль приложения к PostgreSQL |
| `REDIS_PASSWORD` | пароль очереди |
| `SESSION_SECRET` | подпись сессий, **не короче 32 байт** — иначе `web` не стартует |
| `MINIO_ROOT_USER`, `MINIO_ROOT_PASSWORD` | учётка встроенного MinIO (только профиль `test`) |
| `S3_ACCESS_KEY`, `S3_SECRET_KEY` | доступ к бакету. Для встроенного MinIO — те же, что `MINIO_ROOT_*` |

**Никогда не ставить** `postgres/postgres`, `minioadmin/minioadmin` и подобные: на этой машине в
августе 2026 года тестовый Postgres с паролем `postgres` взломали из интернета за час.

### Внешний ключ

| Переменная | Значение |
|---|---|
| `OPENROUTER_API_KEY` | ключ из кабинета OpenRouter |

`OPENAI_API_KEY` и `ANTHROPIC_API_KEY` **не используются** — они остались от замысла, где каждая
модель ходила к своему поставщику напрямую. Весь вывод моделей идёт через один шлюз OpenRouter.

### Адреса и поведение

| Переменная | Значение и как выбрать |
|---|---|
| `N5_PUBLIC_ORIGIN` | `https://ваш.домен` без слеша на конце. **Обязан уместиться в метку** — см. шаг 6 |
| `N5_SHORT_CODE_LENGTH` | `6`. Допустимы только 6 и 10 |
| `N5_TRUSTED_PROXY_HOPS` | сколько прокси стоит ПЕРЕД приложением. Свой Caddy проекта + TLS-прокси машины = **2**; только свой Caddy с TLS = **1**. Неверное число ломает ограничитель частоты: он берёт адрес клиента не из того места цепочки `X-Forwarded-For` |
| `N5_EDGE_PORT` | порт на хосте для своего Caddy, по умолчанию `4181`. Публикуется **только на 127.0.0.1** |
| `N5_LLM_MODEL` | `anthropic/claude-sonnet-5`. Допустима ещё только `google/gemini-3.8-flash`; любое другое значение валит старт |
| `N5_GLOSSARY` | необязательно. Пусто — встроенный словарь терминов для субтитров. Пополнение: `услышано=правильно;…` |
| `N5_COMPOSE_PROJECT` | имя стека, по умолчанию `n5-clipmaker` |

### Потолки расхода — все шесть обязательны

Отсутствие **любой** валит старт и называет именно её. Значения стенда:

```
N5_LIMIT_USER_MINUTES=900        # минут распознавания на аккаунт в сутки
N5_LIMIT_USER_UPLOADS=6          # загрузок на аккаунт в сутки
N5_LIMIT_USER_UPLOAD_REFUNDS=2   # возвратов слота при негодном файле
N5_LIMIT_USER_LLM=6              # вызовов модели выделения на аккаунт в сутки
N5_LIMIT_GLOBAL_MINUTES=2000     # минут на всех в сутки
N5_LIMIT_GLOBAL_LLM=20           # вызовов модели на всех в сутки
```

В каноне заложены 90 / 2 / 2 / 2 / 600 / 20. На стенде подняты, потому что квота списывается
**авансом за всю запись**: одна неудачная попытка на 88-минутной записи съедает 89 минут квоты,
хотя поставщику уходит три. При отладке потолок выгорает быстрее денег.

### Хранилище

| Переменная | Встроенный MinIO | Cloud.ru |
|---|---|---|
| `S3_ENDPOINT` | `http://minio:9000` | `https://s3.cloud.ru` |
| `S3_PUBLIC_ENDPOINT` | **внешний** адрес MinIO, по которому до него дотянется браузер (см. шаг 7) | `https://s3.cloud.ru` |
| `S3_REGION` | `us-east-1` | `ru-central-1` |
| `S3_BUCKET` | любое имя, например `n5-demo` | имя бакета |
| `S3_FORCE_PATH_STYLE` | `true` | `false` |

**`S3_PUBLIC_ENDPOINT` не равен `S3_ENDPOINT`**, и это не опечатка. Контейнеры ходят в хранилище по
внутреннему имени `minio:9000`, а браузер пользователя этого имени не знает. Если подписать ссылку
на загрузку внутренним адресом, браузер получит `http://minio:9000/…` и откажется: страница по HTTPS
не имеет права грузить по HTTP (Mixed Content). Грабля PE-001, 22.09.2026.

## 4. Сборка и тесты — до всякого запуска

```bash
docker compose --project-directory . --env-file .env --profile test run --rm --build test
```

**`--build` обязателен.** Без него `run` берёт ранее собранный образ и молча проверяет старый код:
22.09.2026 результат совпал с прошлым побайтово, включая длительность упавшего теста.

Ожидаемый итог на 24.09.2026: **72 файла, 604 теста, все зелёные** — на настоящих PostgreSQL 16,
Redis 7 и MinIO. Тесты в интернет не ходят: поставщики моделей заменены детерминированными фейками.

Пропущенный тест — не зелёный: в тестовом профиле включён приёмочный режим, и любой пропуск валит
прогон с названием причины.

## 5. Первый запуск стенда

```bash
# 1. хранилища
docker compose --project-directory . --env-file .env --profile test up -d db redis minio

# 2. миграции (14 штук, идемпотентны)
docker compose --project-directory . --env-file .env run --rm --entrypoint sh web \
  -c "node packages/db/dist/migrate.js"

# 3. бакет
docker compose --project-directory . --env-file .env --profile test exec minio \
  sh -c 'mc alias set local http://localhost:9000 "$MINIO_ROOT_USER" "$MINIO_ROOT_PASSWORD" && mc mb -p local/<S3_BUCKET>'

# 4. приложение и обработчики
docker compose --project-directory . --env-file .env --profile test --profile edge \
  up -d --build web worker-stt worker-llm worker-video proxy
```

**Миграции применять до запуска приложения.** 22.09.2026 на стенде обнаружилось, что восемь из
двенадцати миграций так и не были применены: приложение поднялось, а падало на первом же запросе к
новым таблицам.

**CORS на бакете.** MinIO по умолчанию принимает запросы с любого источника, поэтому на стенде
загрузка «работала сама». **В Cloud.ru это не так**: на бакете нужно задать правило CORS, разрешающее
`PUT` и `GET` с вашего домена и отдающее заголовок `ETag` — без `ETag` многочастная загрузка не
соберётся.

### Проверка шага

```bash
docker compose --project-directory . --env-file .env ps          # все сервисы Up, db/redis healthy
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:4181/health   # 200
```

`/health` отвечает 200, только если конфигурация прочитана **и** база доступна.

Если `web` или обработчики перезапускаются по кругу — читать журнал:
`docker compose --project-directory . logs --tail 20 web`. Сообщение называет переменную и причину.
Самая частая — шаг 6.

## 6. Домен: он должен уместиться в метку

Метка на бесплатном клипе — одна строка: `КлипМейкер · <домен>/c/<код>`. Она рисуется кеглем
3,8 % высоты кадра и обязана поместиться в безопасную область 972 px из 1080.

**Длинный домен физически не помещается**, и приложение это знает: `web` и все три обработчика
**отказываются стартовать** с непригодным адресом, называя измеренную ширину и предел. Это сделано
намеренно: иначе продукт принимал бы файлы, списывал минуты, оплачивал распознавание и выбор
фрагментов — и только на рендере выяснялось бы, что метку нарисовать нельзя.

Измерено:

| Адрес | Худшая ширина (код 6 знаков) | Старт |
|---|---|---|
| `clipmkr.ru` | 875 px | проходит |
| `clipmaker.aicoding.space` | 1190 px | **отказ** |

Проверить свой домен до выкатки:

```bash
docker compose --project-directory . --env-file .env run --rm --entrypoint node web \
  apps/web/.next/preflight/preflight.js ; echo "код: $?"
```

Код 0 — годится. Код 1 — сообщение назовёт ширину; нужен домен короче.

**Порядок при смене адреса.** Сначала DNS, потом всё остальное. Запись `A` на IP машины, проверка
`dig +short A ваш.домен` — и только когда она вернула ваш адрес, выпускать сертификат. Если объявить
имя в прокси раньше, Caddy будет бесконечно пытаться выпустить сертификат на чужой адрес.

**Состояние домена `.RU`.** Новый домен регистратор помечает `UNVERIFIED`, пока владелец не
подтвердит данные. Без подтверждения делегирование снимают примерно через 30 дней — а адрес к этому
времени уже вшит в пиксели опубликованных клипов. Подтвердить в первый же день:
`whois ваш.домен | grep state`.

## 7. Выход наружу

Свой Caddy проекта (сервис `proxy`, профиль `edge`) слушает **обычный HTTP** на
`127.0.0.1:${N5_EDGE_PORT}`. TLS он не делает. Варианта два.

**A. На машине уже есть общий TLS-прокси** (так устроен исходный стенд). Добавить в его конфиг:

```
ваш.домен {
	encode gzip zstd
	header X-Robots-Tag "noindex, nofollow"
	reverse_proxy n5-clipmaker-proxy-1:80
}
```

Контейнер `n5-clipmaker-proxy-1` подключить к сети общего прокси:
`docker network connect <сеть_прокси> n5-clipmaker-proxy-1`. `N5_TRUSTED_PROXY_HOPS=2`.

**Для MinIO нужен отдельный публичный адрес** — его и указать в `S3_PUBLIC_ENDPOINT`:

```
s3.ваш.домен {
	reverse_proxy n5-clipmaker-minio-1:9000
}
```

Для Cloud.ru этого не нужно: у него свой публичный адрес.

**B. Общего прокси нет.** Заменить в `proxy/Caddyfile` строку `:80 {` на `ваш.домен {` и
опубликовать 80 и 443 вместо `127.0.0.1:4181`. `N5_TRUSTED_PROXY_HOPS=1`.

**Грабля, стоившая часа.** Если конфиг общего прокси смонтирован в контейнер **отдельным файлом**,
его нельзя править редактором, пишущим через временный файл и переименование: монтирование привязано
к inode, контейнер продолжит видеть старое содержимое, а `caddy reload` бодро ответит «config is
unchanged» с кодом 0. Править только дозаписью в тот же файл (`cat >> файл`) и сверять контрольную
сумму на хосте и внутри контейнера. Готовый сценарий со всеми проверками —
`scripts/switch-to-clipmkr.sh`; он отказывается работать, пока DNS не указывает на машину.

**Базы наружу не публиковать никогда.** `db`, `redis`, `minio` — без `ports:`. Проверка:
`node ../../.claude/hooks/check-ports.cjs .` обязан вернуть 0.

### Проверка шага

```bash
curl -s -o /dev/null -w '%{http_code}\n' https://ваш.домен/health      # 200
curl -s -o /dev/null -w '%{http_code}\n' https://ваш.домен/c/ZZZZZZ    # 404: маршрут отвечает сам
```

## 8. Приёмка — настоящим файлом, не тестами

**Это обязательный шаг, а не формальность.** 23.09.2026 набор из 580 зелёных тестов пропустил девять
дефектов, которые первая же настоящая 88-минутная запись вскрыла за вечер. Все девять жили в
допущениях о данных: какими таймкоды *должны* быть, где *должны* сидеть люди.

1. **Короткий файл** (3–5 минут): регистрация → загрузка → через 2–4 минуты клипы на экране.
2. **Длинный файл** (60–90 минут, с двумя участниками): ориентир 13–20 минут.
3. Посмотреть журналы решений кадрирования — по одной строке на клип:

   ```bash
   docker logs n5-clipmaker-worker-video-1 2>&1 | grep framing_plan
   ```

   Ожидается `mode: single` с числом планов 3–10 на клип. `mode: center` на всех клипах значит, что
   детектор лиц не отработал — проверить, что в образе обработчика есть OpenCV:
   `docker exec n5-clipmaker-worker-video-1 python3 -c 'import cv2; print(cv2.__version__)'`.

4. Глазами, на **телефоне**, пять клипов с руки:
   - кадр переключается на того, кого показывает камера, и не смотрит в стену;
   - субтитры не мигают и не висят после окончания речи;
   - метка читается и несёт ваш домен;
   - английские названия в субтитрах написаны латиницей.

   Этого прибор не проверит: читаемость на экране в руке не автоматизируется.

5. **Музыка:** загрузить файл с отмеченной галочкой «Добавить фоновую музыку». В журнале по одной
   строке на клип:

   ```bash
   docker logs n5-clipmaker-worker-video-1 2>&1 | grep -E 'music_(mix|skipped)'
   ```

   Ожидается `music_mix` на каждом клипе с `gain_db` в пределах −30…+12. `music_skipped` —
   прочитать `reason`. Послушать: музыка слышна в паузах и не заглушает речь. Проверить на громкой
   и тихой записи: уровень относительно речи обязан быть одинаковым (OWN-009).

## 10. Что изменилось относительно замысла

SPARC-документы писались до кода и не переписывались задним числом: они фиксируют замысел.
Реализация от него отошла в следующем — и каждое отступление обосновано измерением.

| В замысле | В реализации | Почему |
|---|---|---|
| OpenAI `whisper-1`, ключ `OPENAI_API_KEY` | `openai/whisper-large-v3` через OpenRouter у Together | DEC-A-022; один шлюз, закреплённый исполнитель |
| Claude Sonnet 5 через Messages API, `ANTHROPIC_API_KEY` | `anthropic/claude-sonnet-5` через OpenRouter | тот же ключ; исполнитель закреплён, `require_parameters` |
| ffmpeg 7 | ffmpeg 8.1.2 (из Alpine) | версия пакета в образе |
| Центральная обрезка 9:16 | кадр следует за лицом (ADR-009) | центр показывал стену между двумя участниками |
| Метка в две строки, код 10 знаков | одна строка, код 6 знаков, домен `clipmkr.ru` | OWN-007, SL-001…008 |
| Строгая проверка таймкодов | поджатие с журналом, отказ только при их отсутствии (ADR-010) | строгость отвергала настоящие записи |
| Модели — весь транскрипт со словами | только сегменты | 1128 КБ против 115 КБ; границы к словам двигает наш код |
| Субтитры 68 px, перенос 32 знака | 86 px, перенос 24, обводка 5, тень 1 | просьба владельца; перенос измерен отрисовкой |
| — | словарь терминов для субтитров | распознаватель пишет английские названия кириллицей |
| — | фоновая CC0-музыка по галочке (ADR-011), колонка `video.music` | просьба владельца; уровень вычисляется из речи клипа |
| Таймаут выделения 120 с | 240 с | запись 88 мин не укладывалась |

## 11. Чего стенд не доказывает

- **Музыку слушал один человек на двух записях.** 18 LU подтверждено на громкой (≈ −19 LUFS) и тихой
  (≈ −33 LUFS) речи; жанры кроме разговорного не проверялись.

- **Cloud.ru не проверен.** Всё шло на MinIO. Подпись SigV4, многочастная загрузка и CORS на Cloud.ru
  требуют ручной приёмки (`docs/Completion.md`).
- **p95 времени обработки не измерен.** Одна длинная запись — одна точка.
- **Следование за лицом тестами не покрыто на настоящем видео**: в тестовом образе нет OpenCV,
  и детектор там не запускается. Проверено только живым прогоном.
- **Кадр следует за самым крупным лицом, а не за говорящим.** Пока камера режет на говорящего, это
  совпадает. На общем плане обоих — нет. Точное следование требует раздельных дорожек звука по
  участникам (в исходной записи звук сведён: каналы совпадают с точностью 0,0 дБ).
- **База персональных данных вне РФ** на исходном стенде (OWN-006). Перенос в российскую юрисдикцию
  обязателен до первого реального пользователя.

## 12. Грабли, собранные на исходном стенде

| Симптом | Причина | Лечение |
|---|---|---|
| Тесты зелёные, а правка «не работает» | `run` без `--build` взял старый образ | всегда `--build` |
| Страж по исходнику падает с `ENOENT` в контейнере | читаемый им файл отсечён `.dockerignore` | точечное исключение `!путь` в `.dockerignore` |
| Прокси говорит «config is unchanged», а правка не видна | bind-mount привязан к inode | править дозаписью, сверять md5 внутри контейнера |
| Браузер: Mixed Content, `http://minio:9000` | ссылки подписаны внутренним адресом | задать `S3_PUBLIC_ENDPOINT` |
| `web` в цикле перезапуска после смены домена | метка не помещается | короче домен, проверить preflight |
| Кнопка «Повторить» серая до полуночи | экран гасил её по прогнозу квоты | исправлено: решает сервер |
| Файл из MinIO на диске не читается | MinIO хранит объект каталогом частей, данные не читаются напрямую | доставать через S3 API, а не с диска |
| `pkill -f "что-то"` убил собственную оболочку | шаблон совпал со строкой самой команды | искать по PID, а не по строке |
| Диск тает на глазах | каждая пересборка оставляет слои | `bash scripts/cleanup-our-docker.sh`; **никогда** `docker system prune` на общей машине |
| Прокси: `md5` файла на хосте ≠ внутри контейнера, хотя правили дозаписью | файл уже раньше кто-то переписал переименованием, контейнер держит старый inode | `caddy validate` нового файла внутри контейнера (`docker cp` в `/tmp`), затем `docker restart` прокси, затем обойти все сайты за ним |
| Тест проходит на хосте и падает только в Docker | нормализация путей `replaceAll('/app', …)` задела `/apps/…` | заменять префикс `cwd + '/'`, не голую строку |
| «Поставщик выделения не завершил запрос» на длинной записи | таймаут 120 с при ответе модели ≈ 1:45–2:00 | 240 с (FR-SELECT-005); повтор со стадии выделения минут не тратит |
| Тестовый стек под тем же именем проекта, что и стенд | в тестовом env нет `N5_COMPOSE_PROJECT` | безопасно, только пока пароли в тестовом и боевом env совпадают — иначе `run` пересоздаст БД стенда; сверять хешами до запуска |
| Домен через месяц перестал разрешаться | `.RU` в состоянии `UNVERIFIED` | подтвердить данные у регистратора |
