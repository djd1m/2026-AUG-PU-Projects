### Deployment Sequence

1. **Сборка образов.** Integration owner фиксирует commit/SHA; собирает `web` и образ воркера
   (общий для `worker-stt`/`worker-llm`/`worker-video`, три контейнера из одного образа — канон §6)
   с явными тегами. Контекст сборки — корень монорепо npm workspaces (`compose-hygiene.md`,
   правило 5); секреты создаются заново для окружения, вне git.
2. **Миграции.** Применяются миграции `db` (15 сущностей канона §4); все сервисы объявляют
   `healthcheck`, зависимые ждут `condition: service_healthy`, не `service_started`
   (`compose-hygiene.md`, правило 3); каждый сервис — `restart: unless-stopped` (правило 4).
3. **Подъём за Caddy.** Профиль `edge`: единственный публикуемый порт —
   `127.0.0.1:${N5_EDGE_PORT:-4181}` у `proxy`; `db`, `redis` (и `minio` в тестовом профиле) без
   `ports:`. После старта — сквозной сценарий CJM D на развёрнутом стенде по внешнему адресу, который
   выдало развёртывание, не `localhost` (`deployment-seams.md`): вход → загрузка → прогресс → клипы →
   скачать → короткая ссылка → отправка гостю → гостевая страница → код партнёра → кабинет.

### Rollback Procedure

Остановить приём новых `video.create` (лимит `user_uploads` в 0 или флаг обслуживания на `proxy`),
не трогая очередь: активные `job_attempt` — строки БД с фенсом, не теряются при откате образа
(ADR-001). Вернуть предыдущие теги образов `web`/воркера. Миграции с данными не удалять; объекты S3
не трогать — откат кода не должен стирать уже отрендеренные клипы или гостевые страницы с их сроком
хранения. Presigned-ссылки, выданные до отката, истекают сами через 15 минут — отдельной
инвалидации не требуется (NFR-SEC-001).

## CI/CD

Стадии `test → build → deploy`.

- **test:** `npm test` — unit + integration из `Refinement.md`, включая 4 обязательных конкурентных
  прогона и 12 стражей ADR, каждый испытанный на внедрённом дефекте.
- **build:** `npm run lint`, затем `npm run build` для каждого workspace монорепо (`web`, воркер);
  `COPY` в образ — из пути workspace, не из `/app` (`compose-hygiene.md`, правило 5).
- **deploy:** `deploy.sh` выполняет Deployment Sequence выше; шаг блокируется, если Pre-Deployment
  checklist не закрыт целиком.

Команды — план CI: `package.json` монорепо заводится на шаге `/start`, имена скриптов
подтверждаются исходником, а не постановкой.

## Logging

Уровни `info`/`warn`/`error`/`fatal` с `video_id` как correlation id. `model-spend.jsonl` —
строка НА КАЖДУЮ попытку: `video_id`, стадия (`stt`/`select`/`render`), единица счёта (минуты или
вызов), исход (NFR-OPS-001, счёт по попыткам, не по успехам). **Не логировать:** подписи presigned-
ссылок, ключи хранилища и моделей, тела/байты видео и аудио, полный (не усечённый) `ip_prefix`,
содержимое транскрипта целиком (живёт в БД, не в логе). Retention операционных логов — 30 суток,
совпадает со сроком хранения клипов free (3 дня) плюс запас на разбор инцидента; журнал расхода —
90 суток, для сверки с отчётом поставщика за квартал.

## Что живо на конец недели и что нет

Метрика недели двумя числами (Specification §8): **≥ 40 клипов с меткой, вышедших наружу** (хотя
бы 1 внешний переход по `/c/{code}`), от **≥ 10 аккаунтов**; вторая половина — **≥ 30 % записей с
отправленной гостевой ссылкой**, из них **≥ 50 % открыты**. Обе половины измеряются нашей БД
(`growth_event`, `link_view`/`guest_sent`/`guest_opened`), без ручной сверки. Читаемость метки на
телефоне (FR-GROWTH-005) — измеряется РУКАМИ, два человека на пяти клипах, и результат — строка в
этом разделе после проверки, а не предположение.

Что НЕ живёт на конец недели, по канону §1 «НЕ входит» и Feature Matrix Specification §7: приём
денег (код ЮKassa из клона спящий, ADR-005), автопостинг, brand kit, командная работа, распознавание
лиц и авто-фрейминг, диаризация, бонусные минуты за гостя, выплаты партнёрам, экспорт в NLE, AI
B-roll, дубляж, шоуноты как публичная страница. Из трёх `Should` (FR-INGEST-003 ссылка VK/Rutube,
FR-RESULT-003 отправить в Telegram, FR-AUTH-002 вход через Telegram) — включение в неделю решается
по факту оставшегося времени и фиксируется в этом разделе постфактум, а не молчаливым пропуском;
`FR-INGEST-003` отмечен `UNCONFIRMED` в Architecture (нет документации поставщика, разрешающей
скачивание чужого видео) и не реализуется, пока подтверждение не найдено. `FR-RESULT-003` отмечен
`UNCONFIRMED` тем же образом (страница Telegram Bot API открыта, но описание метода доставки файла
и предельный размер не подтверждены цитатой — V2-R08) и в неделю измерения НЕ входит: «скачать» и
«скопировать ссылку» покрывают путь получения ценности без него.
