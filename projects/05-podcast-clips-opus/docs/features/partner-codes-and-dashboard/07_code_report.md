# Фича 10 — код реализован, обязательная приёмка не завершена

Реализованы `code.apply`, `partner.dashboard`, кабинет в существующем `/dashboard`, ввод кода при регистрации/входе и перенос источника из короткой/гостевой ссылки. Новых публичных обработчиков, некaнонических процедур или типов событий нет. Изменения фич 1–9 ограничены необходимым подключением атрибуции, личного кода ведущего и кабинета. Применённые миграции, канон и `.claude/` не изменены; `011_partner.sql` добавляет только индексы.

**Фича не объявлена принятой:** настоящие PostgreSQL 16 / Redis 7 / MinIO недоступны; обязательное Anthropic-ревью OWN-002 не получено. Заглушки SQL не доказывают атомарность и ограничения базы.

## Реализация

Применение сериализуется блокировками аккаунта и кода `FOR NO KEY UPDATE`. Каждая попытка действительного активного кода, включая конфликт и самореферал, записывается существующим `code_applied`. **Пятидесятая попытка** в окне `(now − 10 минут, now]` блокирует код и отклоняется до записи атрибуции. Состояние кода и аудит коммитятся до ответа 422; неожиданный сбой откатывает транзакцию. Следующие обращения с любых префиксов получают 422 без повторной блокировки. Прежние атрибуции остаются в базе; кабинет показывает блокировку и необходимость проверки. Аккаунт владельца не блокируется.

Самореферал создаёт `rejected/self_referral`, не увеличивает регистрации. Существующий `explicit` сохраняет обязательный 409 даже для попытки самореферала: это приоритет прямого требования брифа «explicit → любой» над неоднозначным порядком шагов псевдокода. `rejected` не восстанавливается новым кодом. Успешный несобственный `guest_link` транзакционно пишет канонический `guest_registered`. Прежняя активация `pending → activated` по первому завершённому выпуску в рендере переиспользуется.

Личный код ведущего создаётся атомарно при первой отправке гостевого пакета и сохраняется в `host_partner_code_id`; существующий заблокированный код не заменяется новым активным. Короткая ссылка использует первый существующий личный код владельца. Для аккаунта без партнёрского кода пассивная короткая ссылка пока не создаёт атрибуцию. Административная выдача кодов блогерам не добавлена в закрытый список процедур.

Форма сначала завершает существующий вход/регистрацию, затем вызывает `code.apply`. Неверный явный код показывает ошибку; cookie не применяется. Повтор исправляет код без второй регистрации. Пользователь может явно продолжить без применения кода. Регистрация и применение кода — два запроса, не единая транзакция: прерывание браузера между ними может оставить аккаунт без атрибуции; надёжность этого стыка E2E не доказана.

Кабинет показывает свои коды, их состояния, агрегаты статусов по источникам и **пять отдельных счётчиков за всё время**: переходы → регистрации → загруженные записи → клипы с внешним переходом → приглашённые гости. Отклонённые атрибуции исключены из воронки. Чужие email/идентификаторы приведённых аккаунтов не выдаются. Выплаты и балансы не добавлены.

## Почему 403 именно здесь

`partner.dashboard` сначала получает коды текущего партнёра по серверной сессии. Запрошенный UUID вне этого списка даёт 403, в том числе неизвестный UUID: чужой кабинет не раскрывается. Партнёрские коды — известный пользователю предмет запроса. Для приватных видео, клипов, файлов и гостевых пакетов сохраняется одинаковый 404 на чужой и отсутствующий ресурс, чтобы не подтверждать их существование. Ранее существовавший протокольный 403 для запрещённого Origin — отдельная CSRF-проверка, не раскрытие ресурса; она не менялась.

## Непроверенное и передача

1. Обязательные SQL, конкурентные проверки и семь интеграционных мутаций: Docker socket возвращает permission denied; `DATABASE_URL` отсутствует. Локальные PostgreSQL-бинарники есть, но root запускать их нельзя, а `runuser` запрещён окружением. Ограничения не обходились.
2. Полная регрессия на PostgreSQL 16 / Redis 7 / MinIO: нужны существующий профиль test с `--build` и затем mutation-скрипт в том же окружении. Число «391 зелёный» из брифа в этой сессии не перепроверено.
3. OWN-002: запрос `opus` через Claude CLI исправлен после ошибки разбора аргументов; следующая попытка закончилась timeout 40 секунд, exit 124, без результата. Дополнительный независимый OpenAI-агент нашёл два P2: конфликт порядка FK-блокировок и отсутствие `guest_registered`. Исправления проверены отдельным чтением; это **не замена** обязательного Anthropic-ревью.
4. Живые E2E регистрации с deeplink, мобильного браузера и чтения кабинета, Cloud.ru и deployment не выполнялись. Изолированный HTML-тест подтверждает состав экрана, но не внешний CJM.
