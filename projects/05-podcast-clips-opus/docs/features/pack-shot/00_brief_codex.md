# Постановка для Codex — фича 17 `pack-shot`: финальный акцент клипа

Готовы фичи 1–16 (16 — `music-bed`, коммит `5f38ac2`), **637 тестов зелёные**. Стенд `https://clipmkr.ru`.

Пэк-шот — короткий звуко-визуальный акцент на последних долях секунды клипа. Разбор и измерения:
`docs/proposals/music-and-stinger/00_proposal.md` §6 (обязательно). Главный вывод оттуда:
**пэк-шот — НАЛОЖЕНИЕ, а не вставка.** Кадров не прибавляется, длительность не меняется (опыт О-3),
шкала времени звука, картинки и субтитров одна. Вставка кадров запрещена (О-1, О-2, Л-1…Л-4).

Решения владельца (24.09.2026):
- картинка — **вспышка без текста** (без бренда: годится и для `paid` без метки, и для гостевых
  клипов — предмет согласия гостя не меняется);
- звук — **CC0-сэмпл**;
- включение — **той же галочкой**, что и музыка: пэк-шот ставится ТОГДА И ТОЛЬКО ТОГДА, когда в
  клип фактически смешана подложка (`renderClip` вернул `music !== null`). Схема БД не меняется.

Тир L по `scripts/complexity-router.sh` (web + worker).

## Сэмпл

Лежит: `apps/worker/assets/sfx/kenney-low-frequency-explosion-001.ogg` — Kenney, набор «Sci-Fi
Sounds 1.0», файл `lowFrequency_explosion_001.ogg`. **CC0 1.0** — подтверждено дважды: страница
`https://kenney.nl/assets/sci-fi-sounds` («Creative Commons CC0») и `License.txt` внутри архива
(лежит рядом: `LICENSE-kenney-sci-fi-sounds.txt`). Vorbis 44,1 кГц стерео, 1,00 с, 9 408 байт,
sha256 `cdda50600a4928f2f1b8371224d53c171ac799c1cf2c30b11999508985250b3b`, истинный пик −0,8 dBFS.

Закрытый каталог в коде рядом с `MUSIC_TRACKS` (`STINGERS`, один элемент: id, путь через
`resolve('apps/worker/assets/sfx/…')`, sha256). Никакой переменной окружения.

## Что построить

### 1. Звук

- Длительность акцента `STINGER_SECONDS = 0.8`: сэмпл обрезается `atrim=0:0.8` с затуханием
  `afade=t=out:st=0.6:d=0.2` (без щелчка на обрезе).
- Начало `t0 = duration − STINGER_SECONDS`; задержка `adelay=<t0 в мс>:all=1`.
- **Уровень — вычисляется, как у подложки, а не задаётся константой** (§4.1): громкость сэмпла
  измеряется тем же `measureLoudness` в той же полосе 300–3400 Гц (результат можно кэшировать в
  памяти процесса — сэмпл один и не меняется); `gain = S_speech − STINGER_MARGIN_LU − S_stinger`,
  `STINGER_MARGIN_LU = 6` с комментарием «оценка, не измерение; заморозить после прослушивания
  владельцем». Потолок усиления тот же `MUSIC_MAX_GAIN_DB`.
- Смешение — **третьим входом того же `amix`**: `amix=inputs=3:duration=first:normalize=0`, `aformat`
  на ветви сэмпла, как на двух других. Второго `amix` и второго прохода кодирования нет.
- Сэмпл — ТРЕТИЙ `-i`, после трека, без `-ss`/`-t`.
- Если замер сэмпла не удался или усиление вне потолка — пэк-шот пропускается
  (`{"event":"packshot_skipped","reason":…}`), **подложка остаётся**. Отказ пэк-шота не валит рендер
  и не снимает музыку.

### 2. Картинка — вспышка

- Вспышка короткая: подъём яркости с пиком в `t_peak = t0 + 0.05` и спадом за ~0,5 с, например
  `eq=brightness='<A>*max(0,1-abs(t-<t_peak>)/<W>)':eval=frame` или равноценный детерминированный
  фильтр; константы `FLASH_PEAK = 0.35`, `FLASH_HALF_WIDTH_SECONDS = 0.25` — оценки, названы.
- **Порядок фильтров: кадрирование → субтитры → ВСПЫШКА → метка.** Метка верхним слоем и НЕ
  засвечивается: FR-GROWTH-003 требует читаемую метку на каждом кадре.
- `t` в графе — время клипа (как у кадрирования `if(lt(t,…))`). Проверить тестом, что пик вспышки
  приходится на последние 0,8 с, а не на начало.
- Работает в обеих ветках источника: `[0:idx]` и `color=` (аудио без видео).

### 3. Результат и контракт

- `renderClip` возвращает `{ music: {...} | null, packshot: { stinger: string, gain_db: number } | null }`.
- В хеш контракта `packshot` добавляется ТОЛЬКО при фактическом наложении. При `music = false` —
  аргументы ffmpeg и JSON контракта побайтово прежние (эталон `tests/fixtures/music-bed/baseline.json`
  остаётся зелёным без правки). При музыке без пэк-шота — контракт равен сегодняшнему контракту с
  музыкой.
- Журнал: `{"event":"packshot_mix","t0":…,"gain_db":…}`.

### 4. Интерфейс

`Uploader.tsx`: подпись галочки «Добавить музыку и финальный акцент»; строка источников под ней:
«Komiku — Everything is groovy · Kenney — Sci-Fi Sounds, CC0». Поведение галочки не меняется.

## ОБЯЗАТЕЛЬНЫЕ правки после VALIDATE (перекрывают текст выше при расхождении)

Независимая проверка (Anthropic, 24.09.2026): NOT READY → правки 1–4 обязательны, 5–11 тоже вносятся.
Замеры валидатора: ffmpeg 4.4.2 (хост) и 8.1.2 (образ).

0. **ПЕРВЫМ делом, до любых правок кода:** на текущем `HEAD` снять эталон случая «музыка включена»
   — аргументы ffmpeg (временные пути нормализовать, как в `music.test.ts`) и хеш контракта при
   `music:true` с фиксированными моками замера (−20 / −15) — в `tests/fixtures/pack-shot/music-only.json`.
1. **[blocker] Уровень акцента — в ПОЛНОЙ полосе, не в 300–3400 Гц.** Сэмпл — низкочастотный взрыв:
   в полосе −29,3 LUFS, в полной −12,8 LUFS, истинный пик −0,8 dBTP. По полосе формула даёт +7 дБ и
   клиппинг (+6,8 dBFS во float, −0,45 dBTP после AAC). Поэтому:
   - `S_stinger` — интегральная громкость `ebur128` (K-взвешенная, без полосовых фильтров) обрезанного
     и затухающего сэмпла (0,8 с); `S_speech_full` — громкость речи клипа ТОЖЕ в полной полосе,
     отдельным замером того же прохода 1 (допускается ещё один аудиовызов в `loudness.ts`; в
     `render/ffmpeg.ts` по-прежнему ровно один `execFFmpeg`);
   - `gain = min(S_speech_full − STINGER_MARGIN_LU − S_stinger, −3 − P_stinger)`, где `P_stinger` —
     истинный пик сэмпла (dBTP, измеряется тем же `ebur128=peak=true`), плюс прежний потолок
     `MUSIC_MAX_GAIN_DB`; `STINGER_MARGIN_LU = 6` остаётся оценкой (ожидаемо gain ≈ −9 дБ);
   - страж «уровень» — в полной полосе; мутация `gain = 0` обязана его покрасить на громком сэмпле;
   - страж «пик» мерить ДВАЖДЫ: до кодера (float WAV из того же графа) и в готовом MP4; оба ≤ −1,0 dBTP.
2. **[high] Страж «длительность» против вставки.** Выходной `-t` прячет вставку (О-1), поэтому
   длительность и число кадров её не ловят. Добавить: источник с меняющимся содержимым (`testsrc` со
   счётчиком); кадр в `t0 − 0,5` совпадает с рендером «только музыка» в пределах допуска кодека; и
   страж по исходнику: в графе пэк-шота нет `tpad|concat|loop|setpts`.
3. **[high] Страж «метка цела» — только непрозрачная часть.** Плашка метки полупрозрачная
   (`black@0.6`) и законно светлеет под вспышкой (9 → 44). Сравнивать только непрозрачный
   прямоугольник кода (белая плашка и чёрный текст, для `WWWWWW` — `x=633..905, y=1589..1673`, брать
   из `watermarkGeometry`, не числами): при «вспышке после метки» чёрный текст светлеет → красный.
4. **[high] «Музыка без пэк-шота = прежний контракт» — против эталона из п. 0**, побайтово: и
   аргументы (два `-i`, `amix inputs=2`), и хеш.
5. **[medium] «Место звука».** Полоса сэмпла — `lowpass=f=300`. Второе окно — `[0, 0.8]`, а не
   `[0, t0]` (на длинном окне дефект `adelay=0` размывается до 0,05 LU).
6. **[medium] Кэш замера сэмпла.** Кэшировать только конечное число, не промис; отмена, таймаут и
   `FFmpegError` в кэш не попадают; после ошибки — `signal?.throwIfAborted()`, как в `prepareMusic`.
   Экспортировать сброс кэша для тестов.
7. **[medium] `S_speech` не мерить повторно** — полосовое значение брать из `prepareMusic`
   (внутреннее поле результата, НЕ в контракт); полнополосное — см. п. 1. **Разрешённые правки
   существующих тестов — только эти:** `toEqual({music:null})` → `{music:null, packshot:null}` в
   `music.test.ts`; число `-i` 2 → 3 там, где пэк-шот есть; мок `render` в `render-worker.test.ts`.
   Прочие стражи (RD-001, SL-008, baseline) не трогать.
8. **[medium] В контракт при наложении — все оценки:** `packshot: { stinger:<id>:<sha256>, gain_db,
   margin: STINGER_MARGIN_LU, flash: 'v1:<FLASH_PEAK>:<FLASH_HALF_WIDTH_SECONDS>' }`, иначе смена
   константы после прослушивания не доедет (Л-5).
9. **[medium] `t0` округлять один раз до целых миллисекунд**; из него же — `adelay`, `t_peak`,
   журнал. Тест на дробную длительность клипа (например 22,47 с).
10. **[medium] Интерфейс:** тест на новую подпись галочки и строку источников.
11. **[medium] Форма вспышки — асимметричная и не раньше звука:** 0 до `t0`, быстрый подъём к пику в
    `t0 + 0,05`, линейный спад до нуля к `t0 + 0,55`. Страж: кадр в `t0 − 1` совпадает с рендером
    «только музыка». В отчёте назвать, что вспышка высветляет и субтитры (порядок «субтитры →
    вспышка → метка» — решение).
12. Для сведения: клипы, уже отрендеренные с музыкой, при повторном рендере получат новый хеш —
    `storage.put` откажет. Это ожидаемо (контракт изменился); координатор перед перерендером удаляет
    объекты, как делалось 24.09.

## Тесты, без которых фича не принимается

Медиа-тесты — на настоящем ffmpeg (как `tests/music-media.test.ts`).

| Страж | Что проверяет | Внедряемый дефект → ожидание |
|---|---|---|
| длительность | клип с пэк-шотом той же длительности и того же числа кадров, что без него (±1 кадр) | вставка вместо наложения (`concat`/`tpad`) → красный |
| место звука | энергия в полосе сэмпла на `[t0, duration]` заметно выше, чем в том же окне рендера только с музыкой; до `t0` — без разницы (≤ 0,5 LU) | `adelay=0` → красный |
| уровень | сэмпл через тот же граф один на окне `[t0, duration]` не громче `S − 6 + 0,5` в полосе | `gain=0` при громком сэмпле → красный |
| пик | истинный пик клипа с пэк-шотом ≤ −1,0 dBTP на заглушке И-5 (≈−4 dBTP при −17 LUFS) | +20 дБ → красный |
| вспышка там | средняя яркость кадра в `t_peak` выше, чем в `t0 − 1` | пик вспышки в `t=0.05` → красный |
| метка цела | пиксели области метки в `t_peak` совпадают с теми же пикселями рендера без пэк-шота (допуск кодека) | вспышка ПОСЛЕ метки → красный |
| выключено | `music=false` → эталон `baseline.json` побайтово | безусловный третий вход → красный |
| музыка без пэк-шота | отказ замера сэмпла → `music` смешана, `packshot=null`, рендер успешен | бросок из пэк-шота → красный |
| хеш | контракт с пэк-шотом ≠ контракт только с музыкой; контракт при `packshot=null` = прежний с музыкой | поле безусловно → красный |
| каталог | сэмпл существует, sha256 совпадает, длительность ≥ 0,8 с | подменить хеш → красный |
| RD-001 | ровно один `execFFmpeg` на кодирование в `render/ffmpeg.ts` | — не ослаблять |

Мутации — обеими строками в отчёте, скрипт по образцу `tests/run-music-mutations.mjs`.
