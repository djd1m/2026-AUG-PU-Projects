## FP-001 · blocker · событие скачивания не заполняет `day`

`tests/progress-screen.integration.test.ts` — `download event только для своего готового клипа,
удалённое видео скрыто`:

```
null value in column "day" of relation "growth_event" violates not-null constraint
```

Вставка `growth_event` типа `download` не задаёт колонку `day`. Она обязательна и не случайно:
**на ней держатся частичные уникальные индексы**, которые обеспечивают уникальность `link_view` и
`guest_opened` за сутки на `ip_prefix` — это делает БАЗА, а не код (V2-R12).

`day` — **календарные московские сутки**, как у счётчиков квоты; функция для этого уже есть
(`moscowDay`, используется в `quota_counter` и в фиче 5). Второй реализации быть не должно.

**Что сделать.** Заполнять `day` из той же функции при КАЖДОЙ вставке `growth_event`, а не только
для `download`. Проверь остальные места вставки — если где-то ещё колонка не задаётся, это тот же
дефект, просто ещё не дошедший до теста.

**Страж по исходнику:** ни одна вставка в `growth_event` не обходится без `day`. Мутация: убрать
`day` из одной вставки → тест красный. Обе строки в отчёт.
