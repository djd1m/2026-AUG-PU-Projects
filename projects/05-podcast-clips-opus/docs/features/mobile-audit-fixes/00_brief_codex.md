# Постановка для Codex — фича 24 `mobile-audit-fixes`: исправления базовой линии мобильной вёрстки

Шаг 2 плана `docs/plans/2026-09-25-mobile-ui.md` (OWN-016). Методика — `.claude/skills/responsive-ui/SKILL.md`
(прочитай целиком, правила 1–14 обязательны). Базовая линия — `docs/measurements/2026-09-25-responsive-baseline.md`.
Прибор — `scripts/check-responsive.sh` (фича 23). Цель шага: **прибор даёт код 0 в WebKit и Chromium на
320–1440** на стенде, без ослабления правил прибора.

Тёмная тема, новая карточка клипа, лендинг с демо и лента стадий — СЛЕДУЮЩИЕ шаги, здесь их НЕ делать.
Но токены и `rem` вводятся уже сейчас так, чтобы тёмная тема легла заменой значений токенов.

## Что исправить (каждый пункт — наблюдение базовой линии или аудита)

### A. Масштаб текста (R8, все публичные страницы)
1. `globals.css`: все размеры шрифта — в `rem` (`body` 1rem, заголовки `clamp(<rem>, <vw + rem>, <rem>)`),
   отступы там, где они связаны с текстом, — в `rem`/`em`. `html` без явного размера в px.
2. Инлайн-CSS SSR-страниц `apps/web/src/server/short-link-handler.ts` (`/c/`) и
   `apps/web/src/server/guest-page.ts` (`/g/`) — то же самое (сейчас `font:18px`, `clamp(28px,…)`).
3. Предупреждения R7 (px в `clamp`, голый `100vh`) — устранить: `min-height: 100svh` (с фолбэком
   `100vh` строкой выше), `clamp` в `rem`.

### B. Цели касания ≥ 44×44 (R2)
1. Логотип и ссылки в шапке (`.navigation a`, «Мои записи»), ссылка «← назад» в шапке экрана записи,
   логотип/ссылки на `/c/` и `/g/` (включая `footer a` на `/g/`) — `min-height: 44px` (в `rem`:
   `2.75rem`), `display:inline-flex; align-items:center`.
2. `select` музыки в карточке клипа (`ClipMusicChoice.tsx`) и `summary` «Послушать треки» — ≥ 44 px
   высотой, `select` на всю ширину карточки.
3. Кнопки ▶/■ прослушивания в раскрытом списке — ≥ 44×44.
4. Чекбоксы (форма «Клипы для гостя», галочки загрузки, подтверждение удаления): сейчас
   `input { width:100% }` растягивает их на всю ширину. Правило ширины применять ТОЛЬКО к текстовым полям
   (`input:not([type=checkbox]):not([type=radio]):not([type=file])`), а `label` с чекбоксом —
   строка `display:flex; gap; align-items:center; min-height:2.75rem`, чекбокс ≈ 1.25rem.

### C. Шрифт полей ≥ 16 px (R5)
Поля формы входа (сейчас 14 px — унаследовано от `.auth-card label { font-size:14px }`) и `select`
музыки (13,3 px — браузерный дефолт) — `font-size: max(1rem, 16px)` для `input, select, textarea`.
Размер подписи `label` отделить от размера поля.

### D. Контраст (R4 serious)
Блок лимитов кабинета: `p.muted`/`small` на белом не проходят AA. Цвет `--muted` поднять до контраста
≥ 4.5:1 на `--paper` и на белом; проверить все места, где `.muted` на цветном фоне
(`#eaf0df` в `upload-panel`).

### E. Первый экран (новое правило прибора R9 — см. раздел «Прибор»)
1. `/` на 390×844, 375×667 (iPhone SE) и 360×740: кнопка «Войти →» формы видна без прокрутки.
   Решение на выбор: на узком экране форма ИДЁТ ПЕРВОЙ (порядок в сетке), либо текст лендинга
   сокращается/уменьшается. Заголовок не прятать целиком: имя продукта и одна строка ценности
   остаются над формой или в шапке.
2. `/c/{code}` на тех же размерах: кнопка действия (`.cta`) видна без прокрутки (превью кадра
   уменьшается на узком экране, либо действие поднимается выше превью).

### F. Порядок и ритм
1. Экран записи (`dashboard/videos/[videoId]/page.tsx`): блок «Осталось на сегодня» сейчас ПЕРВЫЙ,
   до заголовка записи и клипов. Перенести ПОСЛЕ содержимого экрана записи.
2. Кабинет (`dashboard/page.tsx`): первым — загрузка; остатки — компактной строкой рядом/сразу под
   загрузкой; удаление аккаунта — последним (уже так).
3. Вертикальный ритм: между разделами `main` отступ (например `main > * + * { margin-top: 2.5rem }` —
   примитив stack из навыка). Сейчас разделы «слипаются».
4. Кнопка «Удалить аккаунт навсегда» — стиль опасного действия (`.danger`: красный текст/рамка на
   светлом фоне, контраст AA), а не основной зелёной кнопки; отделена от остального отступом.

### G. Текст
`/g/`: «ваши 2 моментов» — склонение. Функция `pluralRu(n, ['момент','момента','моментов'])` в
`packages/shared` (или `apps/web/src/lib`) с юнит-тестом на 0, 1, 2, 4, 5, 11, 12, 14, 21, 22, 25, 101, 111.
Заголовок при 1 клипе: «ваш 1 момент» (согласовать и притяжательное). Проверь другие места, где
число стоит перед существительным в интерфейсе (`grep -rn '\${.*}\s*[а-я]'` по `apps/web/src`), и
примени ту же функцию, если склонение там неверно.

### H. Прочее из навыка
- `viewport`: добавить `viewportFit: 'cover'`, отступы шапки/нижних панелей с `env(safe-area-inset-*)`.
- `@media (prefers-reduced-motion: reduce)` — уменьшить переходы (их почти нет; правило должно быть).
- `@media (pointer: coarse)` — не нужен отдельный размер, если B выполнен; не добавлять лишнего.

## Прибор — одно новое правило, остальные НЕ ослаблять

**R9 (отказ): основное действие на первом экране.** В `scripts/responsive/rules.mjs` — правило,
получающее список `{route-шаблон → селектор действия}` из конфигурации прибора: `/` → кнопка отправки
формы входа (`form.auth-card button:not([type=button])`), `/c/{code}` → `.cta`. На размерах 390×844,
375×667, 360×740 при загрузке (без прокрутки) `rect.bottom <= innerHeight && rect.top >= 0` и элемент
видим. Нет элемента по селектору → нарушение R9 «действие не найдено» (не молчаливый пропуск).
Тест `tests/browser/…` с фикстурой: действие ниже сгиба → R9; действие в первом экране → 0;
селектор не найден → R9.

Пороги, списки правил и ширины прибора НЕ трогать. Если какое-то нарушение кажется ложным —
не глушить, а описать в отчёте с доказательством (скриншот, размеры), решит координатор.
