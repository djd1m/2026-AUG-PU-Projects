# Постановка для Codex — фича 24, второй круг: правки по ревью и по стенду

Прочитай `docs/features/mobile-audit-fixes/08_review.md` (ревью Anthropic, APPROVE WITH FIXES).
Первый круг выкачен на стенд: прибор дал **код 0** (97 страниц, оба движка). Но скриншот 1440×900
лендинга (`.responsive-artifacts/step2a/chromium-width-1440-35.png`) подтвердил M1 и M2: заголовок
36 px, слово «зрите-лей» разорвано дефисом, между заголовком и вводным текстом ~180 px пустоты.
Прибор это не ловит — поэтому правим по ревью. Прибор после правок обязан остаться с кодом 0.

## Обязательно
1. **M1** — `clamp` с достижимым максимумом: `clamp(2rem, 4.2vw, 3.875rem)` для h1 лендинга и
   аналогично для прочих заголовков в `globals.css` и SSR (`short-link-handler.ts`, `guest-page.ts`).
   Проверь условие R8 из `01_validate.md` для каждой формулы при 390 px (на 390 обязан срабатывать
   rem-минимум), запиши расчёт в отчёт.
2. **M2** — сетка лендинга на ≥600: форма не растягивает строки заголовка; левая колонка — один
   блок (заголовок, вводный текст, строка шагов идут подряд), вертикально по центру относительно формы.
3. **Текст лендинга вернуть как был** (изменение текста — решение владельца, а не вёрстки):
   надстрочник «ВАШИ МЫСЛИ. НОВАЯ АУДИТОРИЯ.» и заголовок «Хороший разговор / заслуживает /
   **больше зрителей.**» с переносами строк, как в исходнике до этой фичи (`git show HEAD:apps/web/src/app/page.tsx`).
   На узком экране (<600) ради первого экрана разрешено ТОЛЬКО средствами CSS: скрыть надстрочник,
   убрать принудительные `<br>` (`display:none` у br внутри h1 при узком экране), уменьшить отступы.
   Кнопка «Войти →» обязана остаться в первом экране 375×667 и 360×740 (R9).
4. **Переносы с дефисом** (`hyphens:auto`) — убрать у заголовков, кнопок, ссылок и полей; для
   длинных слов оставить `overflow-wrap:anywhere` / `break-word`. Если без `hyphens` R8 даёт скролл
   при 200 % — сообщи с числами, не глуши.
5. **L2** — отключённый `select` выглядит отключённым (opacity/cursor), рамка полей и `select`
   с контрастом ≥ 3:1 к фону (WCAG 1.4.11 для границ элементов управления).
6. **L3/L4** — края шапки и контента совпадают на десктопе; `min-height` лендинга считается от
   фактической высоты шапки (переменная `--nav-h`, одна на оба места), без лишней прокрутки.
7. **L6** — токены в одном блоке `:root` (подготовка к тёмной теме шагом 3).
8. **L7** — ограничение высоты превью клипа — только на узком экране, как было до фичи.
