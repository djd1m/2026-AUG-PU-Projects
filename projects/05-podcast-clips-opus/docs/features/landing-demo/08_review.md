## 1. Маршрут витрины (`showcase-file.ts`, `screen-runtime.ts`, `route.ts`)

- **Членство до базы точным сравнением** — `findShowcase` делает `SHOWCASE_CLIPS.find(clip => clip.code === code)`,
  вызывается ДО `deps.pool.query`; тест `tests/landing-demo.test.ts:55` подтверждает 0 обращений к БД на
  код вне набора (включая форматно похожие: `ctduug`, `23456789AB`, `CTDUUG%00`). Мутация `set-membership`/
  `set-membership-db` killed.
- **404 одинаковый во всех отказах** — код вне набора, не `done`, нет объекта, стёртый аккаунт, удалённая
  запись (`v.deleted_at`), отозванная `clip_link`, чужой код того же формата, код в базе на другом клипе —
  везде один `missing()` с одним и тем же телом и заголовками. Проверено юнитами и `tests/landing-demo.integration.test.ts`
  на настоящем PostgreSQL (строки 46–74), включая специально сконструированный разъезд «набор и база
  разошлись» (клип витрины со ссылкой на другой код, код витрины — на соседе) → 404.
- **Все четыре условия в одном SQL** — `showcase-file.ts:27-31`: `c.status='done'`, `a.status='active'`,
  `v.deleted_at IS NULL`, `EXISTS(... l.code=$2 AND l.revoked_at IS NULL)`. `l.clip_id` в схеме — `UNIQUE`
  (`001_init.sql:70`), поэтому «код витрины указывает на другой живой clip_link того же клипа» структурно
  невозможно — разъезд может быть только «код у соседа», что тест и проверяет.
- **302 ≤ 900 с** — `sign: key => generateDownloadUrl(ctx, key)`, тот же подписыватель, что у владельца;
  `tests/landing-demo.test.ts:100` гоняет настоящий `generateDownloadUrl` и проверяет
  `0 < X-Amz-Expires ≤ 900`. Байты через `web` не идут — страж по исходнику (`:110`) требует отсутствия
  `stream`/`guestSecret` в `showcaseRoute`.
- **Cache-Control** — `private, no-store` на редиректе (как путь владельца); `no-store` уже исключает любое
  кеширование дольше жизни подписи — согласуется с `01_validate.md` §1 («не блокер»).
- **Лимит частоты** — `allowRead` (120/мин, тот же лимитер чтения) вызывается ПЕРВЫМ, до `findShowcase` и
  до любого запроса к БД; тест `:88` подтверждает 429 и ноль вызовов `query`. Общий счётчик с `/c/{code}`
  и гостевыми чтениями — известный, документированный (ADR-018 «Последствия», `01_validate.md`) риск
  ложных 429 при трафике с одной подсети; не блокер, как и решено при валидации.
- **Нет утечки ключа объекта/других клипов** — ответ отдаёт только `Location` (подписанный URL одного
  запрошенного `kind`), тело 404/429/503 — фиксированный текст без данных из БД; маршрут не принимает и не
  возвращает список клипов записи.

## 2. Ретенция

- **Исключение только клипов набора** — `retention.ts:90`: `AND NOT (c.id = ANY($3::uuid[]))`,
  `$3 = SHOWCASE_CLIP_IDS`. Тест `retention.integration.test.ts` (новый) на PostgreSQL: клип витрины
  переживает `retentionTick`, сосед той же записи/возраста/тарифа — стирается тем же прогоном (не
  «зелено потому что взяли другой видео»). Мутация `retention-exclusion`/`-db` killed.
- **Удаление аккаунта их стирает** — `eraseAccount` (строки 7–41) не знает о `SHOWCASE_CLIP_IDS` и
  безусловно чистит клипы аккаунта (`DELETE FROM clip WHERE video_id IN (...)`); отдельный тест
  `retention.integration.test.ts` «account erasure still erases a showcase clip» подтверждает на
  PostgreSQL.
- **SQL корректен** — `c.id` (PK, `NOT NULL`) сравнивается с `$3::uuid[]`; пустой массив даёт `NOT(false)`
  = не исключает ничего (fail-closed: пустой набор не открывает дыру в защите ретенции, наоборот —
  ретенция продолжает работать как раньше). NULL-опасных мест в этом фрагменте нет — `c.id` не бывает NULL,
  `$3` всегда определённый (частично) frozen-массив, никогда не `NULL`.

## 3. Правка `/c/` (`short-link.ts` `previewState`)

`expires = link.expires_at ?? (plan!=='paid' && finished_at && !isShowcaseClip(link.clip_id) ? … : null)` —
исключение работает ТОЛЬКО когда `isShowcaseClip(clip_id)` истинно, то есть только для id из закрытого
`SHOWCASE_CLIP_IDS`. Для любого другого клипа (`clip_id` не в наборе, `undefined`, `null`) ветка не меняет
поведение — подтверждено тестом `previewState({ ...link, clip_id: undefined }, later) → 'expired'` и
интеграционным тестом, где сосед `ABCDEF` остаётся `expired`, пока витрина — `ready`. Явный `expires_at`
по-прежнему в приоритете (`??`) — не обходится витриной. Регрессии для не-витринных клипов нет.
