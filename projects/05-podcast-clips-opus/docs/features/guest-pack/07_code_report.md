## Что изменено

- Согласие проверяется в серверной Zod-схеме **до соединения/транзакции и любой вставки**: строго `true`, известная версия и точный SHA-256 текста. Отсутствие/`false` → HTTP `422`. Факт, версия, хэш, время записываются одной вставкой пакета, затем membership в той же транзакции; код возвращается после commit. `randomBytes(24)` даёт 192 бита.
- Созданный пакет закрыт: `sent_at` и `expires_at` пусты. `guest.send` под блокировкой строки ставит обе даты одним UPDATE и пишет `guest_sent` в той же транзакции. Срок — 336 часов от отправки; повтор → `409`, без продления.
- Гостевая страница без входа: `noindex` в HTTP и HTML, `no-store`, `no-referrer`, CSP; адаптивная сетка, плееры, скачивание каждого клипа и всех последовательно. Показываются только отмеченные клипы; файлы сохраняют исходную метку.
- Неотправленный, отозванный, истёкший, отсутствующий пакет → одинаковые статус/тело/заголовки `404`. Самооткрытие ведущим не пишет событие. Префиксы /24 и /64, сутки — существующая реализация.
- На экране записи — выбор клипов, имя, обязательное согласие, создание/отправка, ссылка, срок и отзыв. Список пакетов восстанавливается сервером при перезагрузке, новой публичной процедуры списка нет.
- Отзыв идемпотентный, только владельцем; повторная отправка отозванного пакета запрещена. Владение видео, активный аккаунт, удаление видео, состояние и срок клипа проверяются сервером.

### Как отзыв закрывает уже выданную ссылку

Прямой bearer URL S3 нельзя отозвать обновлением `guest_pack`. Поэтому гостевой `302` ведёт на **тот же канонический маршрут файла** с HMAC-подписью, кодом пакета и сроком ≤900 секунд. На каждом обращении, включая Range и ранее выданный URL, обработчик вновь проверяет БД. Затем сервер читает S3 и отдаёт поток байтов: адрес S3 гостю не раскрывается. Подпись связана с клипом, видом объекта, кодом, режимом скачивания и сроком; без действующего `guest_code` она не создаёт третьего пути доступа. Прямой redirect владельца сохранён.

Это закрывает новые обращения после отзыва; уже полученные/сохранённые байты или начатую передачу отозвать нельзя. Гостевые копии объектов не создаются, поэтому при отзыве не удаляется файл ведущего.
