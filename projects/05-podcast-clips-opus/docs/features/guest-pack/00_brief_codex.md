# Постановка для Codex — фича 9 `guest-pack`

Готовы фичи 1–8. **360 тестов зелёные** на настоящих PostgreSQL 16, Redis 7 и MinIO.

**Это правовая граница, а не форма интерфейса.** Ведущий отправляет гостю подкаста клипы с его
участием; гость публикует их своей аудитории. Значит наружу уходит изображение и голос человека,
который нашей кнопки не нажимал. Именно поэтому ADR-008 требует зафиксированного согласия ДО
создания страницы — и требует его не ради юридической аккуратности, а потому что отозвать
опубликованный клип из чужой ленты невозможно.

Тир XL: несущий инвариант.

## Переиспользование

В клоне гостевой страницы НЕТ — механика наша. Таблица короткая, и это законный ответ:

| Источник | Вердикт |
|---|---|
| форма публичного route handler, коды ответов, чтение сессии | **перенести подход** из `/c/{code}` (фича 8) — она уже наша и уже проверена |
| `growth_event`, частичные уникальные индексы, `moscowDay` | **уже есть** — второй реализации не писать |
| доступ к файлу клипа по подписанной ссылке | **уже есть** (фича 7) — расширить вторым путём доступа, не дублировать |

Ответь по каждой строке в отчёте.

## Что построить

### 1. `guest.create` — согласие ДО создания, и это проверяется

**Без подтверждённого согласия — `422`, и `guest_pack` НЕ создан.** Не «создан со статусом
ожидания», не «создан и помечен», а не создан. Поле обязательное: `consent_confirmed` со значением
`false` или отсутствующее даёт тот же `422`.

Порядок операций (перестановка — дефект): согласие → создание `guest_pack` → отбор клипов
(`guest_pack_clip`) → выдача кода. Код ≥ 128 бит, генерируется криптографически стойким источником.

Срок жизни — **14 дней от отправки**, не от создания.

### 2. `GET /g/{guest_code}` — гостевая страница

Проверь по канону §5, есть ли этот путь в закрытом списке из 10. **Если его там нет — НЕ изобретай:
назови это расхождением в отчёте и останови реализацию этой части.** Список закрыт, и его правка —
решение владельца канона, а не исполнителя.

- отдаётся **без входа** — у гостя нет аккаунта;
- `noindex` обязателен: страница приватна по коду, и попадание в поисковую выдачу сводит приватность
  к нулю;
- отозванный, истёкший и несуществующий код дают **один и тот же `404`**;
- мобильная вёрстка обязательна.

### 3. Отзыв ведущим

Ведущий может отозвать пакет в любой момент. После отзыва страница отвечает `404`, **и файлы по
ранее выданным подписанным ссылкам перестают отдаваться** — иначе отзыв только выглядит отзывом.

### 4. Доступ к файлу клипа — ровно два пути

Сессия владельца видео **либо** `guest_code` неотозванного и неистёкшего пакета, в котором клип
отмечен строкой `guest_pack_clip`. Третьего пути нет. Чужой клип по гостевому коду — `404`.

### 5. События `guest_sent` и `guest_opened`

Уникальность `guest_opened` за сутки на `ip_prefix` обеспечивает **БАЗА частичным индексом**.

**Проверять отдельным конкурентным тестом, а не «заодно» с `link_view`** (V2-R12): у `link_view`
уникальность была изначально, у соседнего события её не было — хотя обе половины метрики недели
считают события одинаково уникальными. Это измеренная находка, а не предосторожность.

## Тесты, без которых фича не принимается

**Конкурентный, обязательный (пятый из пяти в `testing.md`):** 10 параллельных открытий одной
гостевой страницы с одного `ip_prefix` за сутки — **РОВНО 1** событие.

| Страж | Внедряемый дефект |
|---|---|
| ADR-008: согласие ДО создания | сделать поле необязательным → `guest.create` без согласия создаёт пакет → красный |
| отзыв закрывает и файлы | оставить файлы доступными после отзыва → красный |
| истёкший, отозванный, несуществующий — один `404` | вернуть разные коды → красный |
| ровно два пути к файлу | добавить третий → красный |
| `guest_opened` уникален за сутки | убрать частичный индекс → конкурентный красный |
| `noindex` на гостевой странице | убрать → красный |

Мутации обеими строками.
