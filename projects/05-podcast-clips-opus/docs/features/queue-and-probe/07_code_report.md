## Что реализовано

- `packages/queue`: ровно `stt`, `select`, `render`; ID `stage:video_id:fence`,
  `attempts: 1`, числовое хранение 1000/5000; Redis из конфигурации с обязательным паролем,
  `maxRetriesPerRequest: null` у потребителя. Восстановление отсутствующих и сохранённых
  terminal-заданий; при восстановлении сохраняется требуемая задержка.
- `packages/db/src/attempts.ts`, `probe.ts`, миграция `005_queue_probe.sql`:
  блокировка video сериализует выдачу общего монотонного фенса; счётчик попыток отдельный
  на `(stage, clip_id, series_no)`, максимум две попытки; единственная уникальность
  попыток остаётся `(video_id, fence)`. Результат рендера принимается единожды по
  `render_fence` и статусу, устаревший результат пишет структурированный аудит.
- `apps/worker/src/media/`, `workers/stt.ts`, `retry.ts`, `runtime.ts`:
  резерв 3× ДО S3 GET, ограниченный поток загрузки, очистка в finally, отдельный ffprobe
  с SIGKILL/таймаутом 30 секунд; четыре причины отказа probe. Возврат слота и failed
  выполняются одной транзакцией через существующий `refundUploadSlot`; списание минут
  через существующий `checkAndConsumeQuota` после проверки свойств и до продолжения.
  `no_disk` обновляет метку активности и откладывает тот же job на пять минут через
  `moveToDelayed`/`DelayedError`. Автоматическая ошибка создаёт новый фенс в той же серии.
- `apps/web/src/server/watchdog.ts`, `queue-runtime.ts`, instrumentation:
  один таймер на процесс, раз в минуту, без перекрытия проходов; ограниченные пачки,
  курсор обхода исключает голодание заданий после первой сотни. Потерянная доставка
  восстанавливается из БД; молчание 30 минут завершает video, открытые попытки и
  незавершённые клипы отказом. Готовые клипы не затираются.
- `video-retry.ts` + tRPC `video.retry`: проверка владельца, одинаковый 404 для чужого
  и отсутствующего; 409 без исходного объекта/размера и для негодного файла; новая серия,
  продолжение из состояния transcript/clip; отказ LLM-квоты сохраняет правильную причину.
- Стык с фичей 2: `upload-runtime.ts` создаёт/переиспользует попытку ПОСЛЕ commit
  загрузки; сторож закрывает окно commit→publish. Запрещённый `video.ts` не изменён.
- Новые 18 unit/source-проверок и 24 интеграционных сценария, включая обязательную
  конкурентную доставку render, восемь первых попыток разных клипов, повторное списание,
  возвраты, deferred/watchdog, новую серию, LLM-квоту и восстановление Redis.

## Границы, расхождения и передача

- Whisper, выделение, рендер, экраны и retention не реализованы. select/render consumers
  запущены локально paused и не поглощают задания как успешные.
- После probe job остаётся ожидающим `step=transcribe`, video — `transcribing`.
  Живой consumer обновляет метку ожидающей передачи, остановленный по-прежнему обнаруживается
  сторожем. Feature 4 должна подключить `continueTranscription` внутри withSource: обычный путь
  использует тот же файл, восстановление после очистки/перезапуска повторно скачивает источник,
  но не списывает уже сохранённые минуты ещё раз. Сейчас реальной расшифровки нет.
- Повтор select уже списывает оба LLM-ключа и сохраняет `unit_count=1`; feature 5 должна
  учитывать эту предоплату попытки, чтобы не списать второй раз при фактическом вызове.
- `probe_timeout` обозначает также нечитабельный ответ ffprobe; ошибки запуска бинарника
  отделены как ошибки воркера и не возвращают слот как отказ по свойствам файла.
- Противоречивое `fence < mine` в части Pseudocode разрешено в пользу ADR-001/брифа:
  актуальность проверяется равенством захваченного фенса плюс одноразовым статусом результата.
- Сторож дополнительно восстанавливает потерянные select/render доставки и циклически
  обходит пачки. Восстановление только queued оставляло бы retry после commit без транспорта.
- Аудит stale_attempt_result — структурированный stdout, без новой таблицы аудита.
- packages/s3 не изменён. Для будущего устранения локального GetObject-адаптера можно добавить
  в packages/s3 потоковое чтение с abort/deadline; это отдельная правка integration owner.
- BullMQ 5.81.5 принимает трёхчастный ID с двоеточиями через compatibility-ветку; имеются
  source-страж и Redis-сценарий. При смене основной версии библиотеки этот контракт нужно проверить.
- Проверки compose выполнены на искусственной конфигурации, не доказывают боевое окружение.
  Нет доказательства Cloud.ru, ffmpeg 7 в образе, throughput или развёрнутого CJM.
- Независимый читающий агент нашёл и помог закрыть: состояние при отказе LLM-квоты,
  потерю delay, передачу в транскрипцию, голодание пачек и классификацию ошибок ffprobe.
  Обязательное **Anthropic cross-family review не выполнено**: такой модели в хосте нет.
  Его и реальные PostgreSQL/Redis-прогоны должен завершить integration owner до приёмки.
