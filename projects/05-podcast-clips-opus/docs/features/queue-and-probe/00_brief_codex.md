## Что построить

### 1. `packages/queue` — три очереди

`jobId = {stage}:{video_id}:{fence}` — повторная постановка того же фенса идемпотентна, и сторож
может ставить, не опасаясь дубля. Подключение — из конфигурации, пароль обязателен, дефолта нет.

### 2. `LeaseAttempt` — аренда попытки с фенсом

Фенс МОНОТОНЕН на видео и общий для трёх стадий и всех серий; уникальна ровно пара
`(video_id, fence)`. `attempt_no` — порядковый внутри `(stage, clip_id, series_no)`, без `UNIQUE`.
Потолок ≤ 2 автоматических попыток считается ВНУТРИ серии; `RetryVideo` открывает новую серию.

Результат стадии принимается оператором с условием актуальности фенса; ноль затронутых строк —
это `stale_attempt_result` в аудит, а не тихая перезапись.

### 3. `ProbeSource` — первый шаг стадии `stt` в `worker-stt`

Порядок операций (перестановка = дефект, не стиль):

1. резерв диска ≥ 3× размера файла ДО скачивания; не хватает → `deferred(no_disk)`,
   `job_attempt.wait_reason = 'no_disk'`, задание возвращается в очередь с задержкой 5 мин,
   **`video.updated_at` двигается** — иначе сторож убьёт исправную задачу как молчащую;
   обращений к S3 на этом пути должно быть НОЛЬ;
2. скачивание оригинала один раз;
3. `ffprobe` ОТДЕЛЬНЫМ процессом с таймаутом → длительность и наличие звуковой дорожки;
   зависший разбор — `probe_timeout`, а не ожидание;
4. границы 2–90 мин → `too_short` / `too_long`; нет дорожки → `no_audio`;
   каждый из этих четырёх — отказ по СВОЙСТВАМ файла, слот `user_uploads` ВОЗВРАЩАЕТСЯ
   (`RefundUploadSlot` из фичи 2, с потолком возвратов) в ТОЙ ЖЕ транзакции, что пишет `failed`;
5. `CheckAndConsumeQuota` на `user_minutes` (90) и `global_minutes` (600) — ДО первого вызова
   Whisper; отказ → `refused_user_minutes` / `refused_global_minutes`, слот НЕ возвращается;
6. `video.status = transcribing`, дальше стадия транскрипции (фича 4) — здесь только постановка.

### 4. `WatchdogTick` — сторож в `web`, раз в минуту

`queued` без активного задания → поставить заново (идемпотентно по `jobId`);
`updated_at` старше 30 мин при активном статусе → `failed(stalled)`, незавершённые клипы `failed`;
клипы free старше 3 дней и гостевые страницы старше 14 дней — в этой фиче НЕ трогаем (фича 12).

Сторож — синглтон процесса, не экземпляр на запрос.

### 5. `RetryVideo`

Запрещён для видео без `object_key` (отказ случился ДО загрузки: `refused_user_uploads`,
`too_large`, `not_media`) — иначе воркер получит задание на несуществующий объект. Для
`refused_user_minutes` и `refused_global_minutes` повтор со стадии `probe` (файл есть), новая серия.
Стадия продолжения определяется СОСТОЯНИЕМ: нет транскрипта → `stt`, есть → `select`, и так далее.

## Тесты, без которых фича не принимается

**Конкурентный, обязательный (третий из пяти в `testing.md`):** задание `render(fence=N)`
доставлено дважды — либо эксклюзивность очереди не допускает второго, либо только ОДИН
`UPDATE … WHERE fence` затрагивает строки; второй даёт ноль строк и `stale_attempt_result`.

**Стражи ADR с внедряемым дефектом, обе строки в отчёт:**

| Страж | Внедряемый дефект |
|---|---|
| ADR-001 (а) фенс | убрать `WHERE fence = :mine` → тест красный |
| ADR-006 (а) резерв диска | убрать проверку свободного места → счётчик вызовов S3 GET на пути `deferred` перестаёт быть нулём |
| `deferred` двигает `updated_at` | не двигать → сторож убивает исправную задачу |
| `RetryVideo` без `object_key` | разрешить повтор → задание на несуществующий объект |

**Интеграционные** — в профиле `test` compose на настоящих PostgreSQL и Redis: они у нас работают.
