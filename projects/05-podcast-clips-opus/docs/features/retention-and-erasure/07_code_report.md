## Реализация и переиспользование

| Существующий механизм | Использование |
|---|---|
| `watchdogTick` / `startWatchdog`, фича 3 | Добавлен вызов `retentionTick` из того же таймера. Часовой интервал после успешного прохода; незавершённые пачки и ошибки повторяются на следующем минутном тике. Второго сторожа нет. Межпроцессная блокировка PostgreSQL исключает одновременную уборку. |
| `account.status`, `deletion_requested_at`, `erase_deadline` | `account.delete` с обязательным `confirm: true`: `erasing` → отзыв сессий и гостевых пакетов → закрытие коротких ссылок/результатов воркеров. Повтор не сдвигает срок 72 ч. |
| `video.deleted_at`, `fence`, проверки активности аккаунта | Закрывают принятие поздних результатов. Создание новой загрузки теперь проверяет активность под блокировкой аккаунта. |
| S3-клиент, `deleteObject`, `abortMultipartUpload` | Очистка серверных префиксов оригиналов, free/paid-клипов и превью, включая объекты без ссылок в БД и незавершённые multipart. Версионированный/приостановленный бакет отклоняется, чтобы delete marker не выдавался за стирание. |
| Короткие ссылки и гостевые сроки, фичи 8–9 | Существующие проверки доступа сохранены. Отзыв по уже вычисленному `guest_pack.expires_at`, без второго вычислителя 14-дневного срока. Короткая ссылка после обычного истечения файла сохраняется; при удалении аккаунта отзывается. |
| Срок клипа в выдаче файлов/экране | Физическая очистка через 3 дня от `video.finished_at`, включая готовые клипы частично завершённых, затем отказавших выпусков. Paid и ещё не истёкшие клипы исключены. Только после успеха S3 очищаются ключи и ставится маркер срока. |
| RU-005, отчёт фичи 2 | Отказы `failed/refused_user_uploads` старше 24 ч удаляются пачками, с продолжением очереди уборки. Новая миграция `012_retention.sql` добавляет частичный индекс по `created_at`; старые SQL не изменены. |
| `growth_event` / FK `ON DELETE SET NULL` | События сохраняются; ссылки на удаляемые сущности и `ip_prefix` очищаются. CASCADE не добавлен. |
| Существующие `/api/trpc` и `/dashboard` | Подтверждение и предупреждение до удаления. После отзыва сессии подписанная HttpOnly/Secure квитанция даёт только просмотр статуса на dashboard, не доступ к API. Состояния: удаляем / удалено / задержка или ошибка. |

После запроса выдерживается час для истечения выданных ссылок частей и завершения
ограниченных по времени операций S3. Затем сторож удаляет объекты, очищает связанные
строки и только после этого ставит `deleted`. Сбой S3 сохраняет строки и `erasing` для
повтора. Во время работы S3 нет открытой SQL-транзакции. Жёсткий SLA 72 ч при недоступных
БД/S3 не доказан; интерфейс после дедлайна честно сообщает о задержке.

**Что именно НЕ удаляется:** скачанные копии и публикации в чужих лентах — они вне
нашего хранилища; обезличенные `growth_event` и глобальные квоты — агрегатные метрики;
техническая строка аккаунта со статусом `deleted`, UUID и сроками — квитанция завершения,
с почтой заменённой на непригодный для входа `deleted:UUID`, пустым хэшем пароля и без
Telegram ID. Прямые идентификаторы заданий могут сохраняться в транспортной очереди и
операционных журналах прежних фич; их полная очистка и резервные копии этим прогоном не
проверены. UI заранее говорит о невозможности удалить внешние копии.

## Ограничения и передача

- Не доказаны реальные FK/транзакции/конкурентность PostgreSQL и физическое отсутствие
  файлов в MinIO; интеграционные тесты написаны, запуск заблокирован правами среды.
- Нет браузерного E2E состояния удаления, Cloud.ru-проверки и доказанного SLA 72 ч.
  Подписанные GET, выданные до отзыва, действуют до своего прежнего срока; страницы
  закрываются сразу, сами объекты удаляются фоново.
- S3-роль должна разрешать чтение статуса версионирования, листинг объектов и multipart,
  abort и delete. Совместимость и права Cloud.ru пока не проверены.
- Сохраняется OWN-006: демонстрационный проект, PostgreSQL на VPS вне РФ; этот код
  не подтверждает готовность принимать реальные персональные данные.
- Следующий шаг на разрешённом тестовом хосте: port preflight, затем
  `docker compose --project-directory . --profile test run --rm --build test` с тестовым
  окружением, мутации на живой интеграции и ревью Anthropic. До этого приёмку не объявлять.
