# Постановка на исправление — сторож молчит о причине отказа

**Найдено ЖИВЫМ ПРОГОНОМ на развёрнутом стенде 23.09.2026.** Ни один из 460 тестов этого не видел:
тесты проверяют, что проход сторожа делает правильные вещи, но не то, что он вообще проходит.

## WD-001 · high · причина отказа сторожа уничтожается обработчиком

`apps/web/src/server/watchdog.ts:48,53`:

```ts
export function startWatchdog(tick, onError = () => console.error('Сторож: проход не завершён')) {
  …
  try { await tick(); } catch { onError(); } finally { running = false; }
```

`catch` **без привязки** — объект ошибки не просто не печатается, он не принимается в обработчик
вовсе. По умолчанию `onError` тоже не имеет параметра.

**Наблюдение на стенде:** в журнале `n5-clipmaker-web-1` строка «Сторож: проход не завершён»
повторяется **каждый проход, бесконечно**, и по ней невозможно узнать ни причину, ни какой из
шагов прохода упал. Сторож при этом честно не притворяется успешным — он отказывает. Но отказ без
причины не даёт ничего, кроме факта отказа.

Это прямо противоречит `.claude/rules/honest-configuration.md` и практике проекта: сообщение обязано
называть ЦЕНУ и ПРИЧИНУ, а не факт. Образец — наши же сообщения об отсутствующих переменных:
«`S3_PUBLIC_ENDPOINT` не задана: браузер не сможет загрузить части».

**Что сделать.**

1. `catch (error) { onError(error); }`, и обработчик по умолчанию печатает ошибку:
   `(error) => console.error('Сторож: проход не завершён', error)`.
2. Проход состоит из нескольких шагов (постановка заданий, retention). **Отказ одного шага не должен
   рушить весь проход молча** — назови в сообщении, какой шаг упал. Смотри строку 40: там уже есть
   образец правильного поведения (`catch { console.error('Сторож: транспорт заданий недоступен'); }`)
   — но и он теряет саму ошибку, поправь и его.
3. Проверь остальные `catch` без привязки в `apps/web/src` и `apps/worker/src`: если ошибка
   уничтожается там, где она единственный источник диагноза, это тот же дефект. Перечисли найденное
   в отчёте; правь только там, где ошибка действительно теряется безвозвратно.

**Тест обязателен:** проход, у которого шаг бросает названную ошибку, печатает эту ошибку, а не
только общую фразу. Мутация: вернуть `catch` без привязки → тест красный. Обе строки в отчёт.

## Границы

Правь только обработку ошибок и сообщения. **Логику прохода не менять** — она проверена 460
тестами. Если по дороге увидишь настоящую причину падения прохода на стенде, НАЗОВИ её в отчёте,
но не чини вслепую: причину установит следующий прогон с уже видимым сообщением.
