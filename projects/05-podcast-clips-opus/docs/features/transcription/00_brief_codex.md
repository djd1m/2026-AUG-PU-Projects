# Постановка для Codex — фича 4 `transcription`

Рабочий каталог — корень проекта. Готовы фичи 1–3: монорепо, 15 сущностей, конфигурация с отказом,
вход, приём загрузки с шестью ключами квоты, три очереди BullMQ, аренда попытки с фенсом, шаг
`probe` с резервом диска, сторож. **195 тестов зелёные** в контейнере на настоящих PostgreSQL 16,
Redis 7 и MinIO. Ты продолжаешь эту базу, а не начинаешь заново.

Эта фича впервые тратит **настоящие деньги за вызов поставщика**. Каждое числовое решение берётся
из канона, а порядок операций — из `security.md`; перестановка здесь не стиль, а дефект.

## Пункт 0 — смена поставщика распознавания, читать первым

**Решение DEC-A-022** (`docs/decisions-autonomous.md`), основано на измерении, а не на документации:
`docs/proposals/openrouter-probe-results.md`.

Было в канонe: `OpenAI whisper-1`, ключ `OPENAI_API_KEY`.
Стало: **`openai/whisper-large-v3` через OpenRouter**, ключ `OPENROUTER_API_KEY`, базовый адрес
`https://openrouter.ai/api/v1`.

Форма запроса **установлена ответом сервера**, не документацией — документация в обоих местах врёт:

```js
POST /audio/transcriptions
{
  model: 'openai/whisper-large-v3',
  input_audio: { data: <base64>, format: 'mp3' },   // ОБЪЕКТ, не строка `audio` — строка даёт 400
  response_format: 'verbose_json',
  timestamp_granularities: ['word', 'segment'],
  language: 'ru',
  provider: { only: ['Together'], allow_fallbacks: false }   // ← без этого блока решение недействительно
}
```

**Закрепление поставщика обязательно и проверяется стражем.** Слова отдают только
OpenAI-совместимые хостеры; без `provider.only` OpenRouter выбирает эндпоинт сам, и часть из них
отвечает `400`. Отсутствие закрепления — blocker, а не стилистика.

Проверено на прогоне: 12 слов из 12 с `start` и `end`, русский распознан верно, Together и Groq
дали побайтово одинаковые тайминги. НЕ проверено: часовой файл, живая дикция, фоновая музыка,
чанкинг — это делаешь ты.

## Что построить

### 1. `packages/shared` — типы транскрипта

`TranscriptWord { word, start, end }`, `TranscriptSegment`, закрытые перечисления как в канонe §4.
Объявляются ОДИН раз и оттуда же попадают в `CHECK` миграции `006_*.sql` (005 занята фичей 3 —
проверь и возьми следующий свободный номер).

### 2. `apps/worker/src/stt/extract.ts` — извлечение звука

Из исходника в моно, частота дискретизации под распознавание, потоково. Промежуточного видео на
диске не создавать: резерв диска уже посчитан фичей 3 под исходник, а не под копии.

### 3. `apps/worker/src/stt/chunker.ts` — резка

Потолок **25 МБ на чанк** — жёсткий, он у поставщика. Резать **по паузам**, а не по секундам:
разрез посреди слова даёт два обрубка, и склейка их не чинит. Паузы ищутся по тишине; если пауза не
находится в разумном окне — режем по времени и ЗАПИСЫВАЕМ это в отчёт как ухудшение, а не молча.

### 4. `apps/worker/src/stt/client.ts` — адаптер поставщика

Один путь, форма из пункта 0. Конфигурация из `packages/shared/src/config.ts`, своего чтения
`process.env` нет. Таймаут на вызов; отказ поставщика — исключение, не возвращаемое значение.

**Граница, ради которой это отдельный файл:** решение о поставщике меняется настройкой, а не
переписыванием воркера. Интерфейс описывает РЕЗУЛЬТАТ (`words[]` с границами), а не поставщика.

### 5. `apps/worker/src/workers/stt.ts` — стадия целиком

Порядок операций (перестановка = дефект, не стиль):

1. длительность и звуковая дорожка уже измерены фичей 3 (`probe`) — не измерять заново;
2. `CheckAndConsumeQuota` на `user_minutes` (90) и `global_minutes` (600) — **ДО первого вызова
   поставщика**. Между «файл годен» и «за него заплачено» не должно быть ни одного обращения
   наружу. Отказ → `refused_user_minutes` / `refused_global_minutes`, слот `user_uploads` НЕ
   возвращается;
3. извлечение звука → резка на чанки;
4. вызов поставщика по каждому чанку; **каждая ПОПЫТКА пишет строку в `model-spend.jsonl`** —
   `video_id`, стадия, единица (минуты), количество, результат. Таймаут и отказ поставщика — такие
   же строки, как успех: поставщик берёт деньги за попытку;
5. **повтор чанка списывает минуты ЗАНОВО** (тест «сначала красное» `г` из `testing.md`);
6. склейка: слова каждого чанка сдвигаются на его смещение от начала записи. Проверяется тестом на
   монотонность: `start` каждого следующего слова не меньше предыдущего;
7. **страж ADR-003:** результат без `words[].start/end` отвергается ДО постановки стадии `select`.
   Не «логируем и идём дальше» — отказ;
8. запись транскрипта в БД одной транзакцией, затем `video.status = selecting` и постановка
   задания — **фиксация строки ДО постановки**, иначе воркер возьмёт задание и не увидит записи.

## Тесты, без которых фича не принимается

**Стражи с внедряемым дефектом, обе строки в отчёт** (красная при дефекте, зелёная после):

| Страж | Внедряемый дефект |
|---|---|
| ADR-003: результат без слов отвергается | принять результат без `words` → тест красный |
| закрепление поставщика в запросе | убрать `provider.only` → страж по исходнику красный |
| минуты списаны ДО первого вызова | переставить списание после вызова → красный |
| повтор чанка списывает заново | считать по успехам → красный |
| склейка со смещением | не сдвигать слова второго чанка → немонотонный `start`, красный |

**Фейк поставщика детерминированный** и отвечает по контракту, включая пограничные случаи: без
таймкодов, пустой ответ, 5xx, таймаут. **Тесты не ходят в интернет.**

**Живой прогон отдельно и помечается в отчёте.** Ключ лежит в `/root/.config/n5/openrouter.env`
(вне репозитория). Если запускаешь живьём — возьми короткий файл, не часовой: лимит ключа $10/нед,
и он общий на все наши проверки. Прогон без ключа НЕ выдавать за смоук с настоящим поставщиком.
