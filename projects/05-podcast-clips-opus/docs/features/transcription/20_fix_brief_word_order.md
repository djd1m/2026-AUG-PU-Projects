# Постановка TR-010 — строгая монотонность отвергает настоящие записи

**Находка на живых данных, не в тесте.** Владелец загрузил запись 5305,9 с (88,4 мин). Списано
89 минут квоты, отработал ОДИН кусок из тридцати за 3 секунды, и вся расшифровка отвергнута.

Точная причина из журнала `worker-stt`:

```
TranscriptError: Нет пригодных таймкодов слов
timingIssue: { reason: 'order', kind: 'word', index: 98,
               start_seconds: 50.96, previous_start_seconds: 51.22 }
```

Слово №98 начинается на **0,26 с раньше** предыдущего. `packages/shared/src/transcript.ts:41`:
`if (time.start < previous) throw` — допуск НУЛЕВОЙ.

## Почему нынешнее поведение неверно

Таймкоды слов у распознавания речи **приблизительны** по природе: на границах сегментов и при
наложении голосов соседние слова изредка расходятся на доли секунды. Требование строгой
монотонности строже, чем бывает в действительности, и отвергает годную запись целиком из-за одной
пары слов из тысяч.

**От чего страж защищает на самом деле.** Он писался против дефекта СКЛЕЙКИ кусков (TR-003): куски
идут по 180 с с перекрытием 2 с, и при неверной склейке начала слов уезжают назад на масштаб куска —
десятки и сотни секунд. Именно это и надо ловить. Дрожание поставщика в четверть секунды — не то.

## Что сделать

**Ввести НАЗВАННЫЙ допуск и различать два случая.**

1. Откат назад **меньше допуска** — дрожание поставщика. Начало слова поджимается к предыдущему
   (`start = max(start, previous)`, `end` не меньше `start`), случай СЧИТАЕТСЯ и попадает в журнал.
   Молчаливой починки быть не должно: `silent-fallbacks.md` запрещает фолбэк без записи.
2. Откат **не меньше допуска** — настоящий беспорядок, отказ как сейчас, с прежней диагностикой.

**Значение допуска предлагаю 0,5 с, и вот обоснование числом.** Перекрытие кусков —
`STT_OVERLAP_SECONDS = 2`; дефект склейки проявляется откатом НЕ МЕНЬШЕ перекрытия, то есть от 2 с и
выше. Допуск 0,5 с — четверть этого расстояния, значит он пропускает дрожание и по-прежнему ловит
любой дефект склейки. Если считаешь, что число должно быть другим, назови своё И покажи, почему оно
сохраняет обнаружение дефекта склейки.

3. **Массовое дрожание — тоже отказ.** Если поджатых слов больше, скажем, 1 % от общего числа, это
   уже не дрожание, а испорченный результат. Порог назови числом и обоснуй.

## Второе: диагноз лжёт

`TranscriptError` при ЛЮБОЙ причине говорит «Нет пригодных таймкодов слов». В этом случае таймкоды
ЕСТЬ, и я сам сначала пошёл искать не там. Сообщение обязано различать: таймкодов нет ·
таймкоды вне границ · таймкоды не по порядку. Поле `timingIssue.reason` уже несёт различие —
доведи его до текста ошибки.

Пользовательский текст для `no_timestamps` в `failureMessages` тоже проверь: он не должен утверждать
отсутствие того, что есть. Закрытый набор `failure_reason` НЕ расширяй — это отдельное решение.

## Стражи

| Страж | Внедряемый дефект |
|---|---|
| откат 0,26 с принимается, слово поджато, случай посчитан | вернуть нулевой допуск → красный |
| откат 2 с и больше отвергается | поднять допуск выше перекрытия → красный |
| доля поджатых выше порога → отказ | убрать проверку доли → красный |
| текст ошибки называет ПРИЧИНУ, а не «нет таймкодов» всегда | вернуть общий текст → красный |
| поджатие попадает в журнал, а не молчит | убрать запись → красный |

Мутации обеими строками. Отдельно: тест на настоящей форме ответа с реальным откатом 0,26 с — не
синтетический массив из двух слов, а последовательность, где нарушение стоит в середине.
