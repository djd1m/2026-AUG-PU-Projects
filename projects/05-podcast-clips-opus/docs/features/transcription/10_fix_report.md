# TR-001 / TR-002 — исправление границы транскрипта

Код исправлен; локальные проверки пройдены. Полная приёмка **не закрыта**: независимое
ревью Anthropic завершилось таймаутом без ответа модели, 134 интеграционных теста не запущены.

## Решение

Выбран третий вариант: подрезка окончания с обязательным журналированием. Допуск не константа:
`max(0, измеренная длительность MP3 − длительность видео)`. MP3 измеряется существующим
`probeFile` после `extractAudio`, до платных вызовов; таймаут ограничен оставшимся временем задачи.
В текущем исходнике `extractAudio` возвращает только путь и паузы, поэтому измерение добавлено
в воркер, а извлечение и чанкинг не менялись.

Сначала каждый чанк проверяется по своей длительности, затем склейка — строго по измеренному MP3.
Только прошедшим проверку словам/сегментам с началом внутри видео подрезается `end` до конца
видео. Затем повторяется строгая проверка по видео; существующая проверка в `acceptTranscript`
сохранена. Слово целиком за видео, неверные таймкоды и превышение измеренной границы отвергаются.
Это закрывает также повторную проверку БД, которую одной заменой аргумента склейки не исправить.

Число из брифа: `237,528 − 237,433 = 0,095 с` — измерение владельца, не новый наш замер.
В регрессионной фикстуре MP3 длится 237,55 с: допуск 0,117 с, окончание на +0,1 с принимается
и подрезается; +5 с отвергается. Реальный AAC→MP3 тест отдельно измеряет обе длительности
через ffprobe и доказывает появление хвоста без заданного вручную допуска.

## Диагностика

- Отказ поставщика без пригодных слов сохраняет `no_timestamps`.
- Отказ сборки — `TranscriptMergeError`, в БД существующая причина `stt_failed`, в журнале
  `stt_merge_failed`. Enum и миграции не расширяются за границы задания.
- Журнал содержит video_id, fence, вид элемента, индекс слова в склейке и chunk_index,
  начало, конец, проверяемую границу и `excess_seconds`. Слово идентифицируется индексами,
  текст пользовательской речи в служебный журнал не копируется.
- Подрезка пишет `stt_timestamp_clamped` с исходным окончанием, величиной подрезки и измеренной
  длительностью MP3. Успешные ответы провайдера остаются `success` в журнале расхода:
  ошибка сборки является отдельным событием и не переписывает историю платного вызова.
- Ошибка измерения производного MP3 не выходит как `ProbeError` к возврату слота исходного файла.
