# Постановка — фича 25 `dark-theme`: тёмная тема (FR-LOOK-008, OWN-016)

Шаг 3 плана `docs/plans/2026-09-25-mobile-ui.md`. Исполнитель — агент Anthropic (Opus 5.5); модели
OpenAI в проекте временно не используются (решение владельца 25.09.2026). Методика —
`.claude/skills/responsive-ui/SKILL.md` (прочитай целиком, особенно «Токены и тема» и «Код 0 — необходимое,
не достаточное»). Прошлый шаг — `docs/features/mobile-audit-fixes/05_completion.md`: его соглашения
(rem, цели 44 px, поля 16 px, R9, первый экран) обязаны сохраниться.

## Решения (автономные, A-2509-03 — владелец может поменять)
1. **Тёмная тема — по умолчанию для всех**, независимо от `prefers-color-scheme` (FR-LOOK-008: «тёмная как
   основная»). Светлая — только по ЯВНОМУ выбору пользователя.
2. Выбор хранится в cookie `n5_theme` со значением ровно `light` или `dark` (`Path=/; Max-Age=31536000;
   SameSite=Lax; Secure`; не `HttpOnly` — его пишет клиент). Любое другое значение, пустое, отсутствующее →
   тёмная (закрытый набор в коде, fail-closed — см. `honest-configuration`).
3. Тема применяется НА СЕРВЕРЕ атрибутом `<html data-theme="light|dark">`, чтобы не было вспышки не той
   темы: Next — корневой `layout.tsx` читает cookie (`cookies()` из `next/headers`); SSR-страницы `/c/` и
   `/g/` — из заголовка `cookie` запроса в `short-link-handler.ts` / `guest-page.ts`. Разбор cookie — одна
   функция `themeFromCookie(header: string | undefined): 'light' | 'dark'` в `apps/web/src/lib/theme.ts`
   с юнит-тестом (включая `n5_theme=LIGHT`, `n5_theme= light`, два значения, мусор, отсутствие → `dark`).
4. Переключатель — в шапке лендинга `/` и кабинета: кнопка ≥ 44×44 с `aria-label` «Светлая тема» /
   «Тёмная тема» и `aria-pressed`, клиентский компонент: пишет cookie и меняет `data-theme` на `<html>` без
   перезагрузки. На `/c/` и `/g/` переключателя нет (страницы без JS, CSP `script-src` отсутствует —
   НЕ ослаблять), но выбранная тема соблюдается.
5. `<meta name="color-scheme">` / CSS `color-scheme` — по теме (тёмные скроллбары и поля в тёмной).
   `theme-color` для адресной строки мобильного браузера — цвет фона темы.

## Палитра (свои значения, не из источника — граница легальности `replicate-pipeline`)
Закономерности FR-LOOK-008/010, значения выбрать самим:
- фон почти чёрный, текст почти белый; второстепенный текст — отдельный токен, контраст ≥ 4,5:1;
- ТРИ ступени поверхностей (`--paper` фон страницы, `--surface` карточки, `--surface-2` вложенные блоки/
  поля/загрузка) — различимы глазом, рамки `--line` ≥ 3:1 к соседней поверхности для рамок контролов
  (WCAG 1.4.11), декоративные разделители — можно тише;
- основная кнопка в тёмной теме — светлая заливка с тёмным текстом (FR-LOOK-010), вторичная — прозрачная
  с рамкой; акцентный зелёный (`em`, оценка клипа, eyebrow) — осветлённый вариант, контраст ≥ 4,5:1 на фоне;
- статусы (`.running`, `.success`, `.failure`, `.silent`), `.notice`, `.danger`, фокус-обводка, тени,
  `.brand span`, превью клипа, `video-row:hover` — все через токены, в обеих темах контраст AA.
- Светлая тема — текущая палитра (не менять её значения без необходимости).

## Что править
- `apps/web/src/app/globals.css`: ВСЕ цвета — только через токены на `:root` (тёмная) и
  `:root[data-theme=light]` (светлая). После правки `grep -nE '#[0-9a-fA-F]{3,8}|\bwhite\b|\bblack\b|rgba?\('`
  вне блоков токенов — пусто (кроме явно обоснованных в отчёте).
- Инлайн-стиль с цветом в `apps/web/src/app/clips/GuestPacks.tsx` (`border: '1px solid #ced6cb'`) и любые
  другие цвета в `.tsx` (`grep -rn "#[0-9a-fA-F]\{3,6\}" apps/web/src/app`) — в классы/токены.
- SSR-CSS `/c/` и `/g/`: те же два набора токенов (можно продублировать значения — у страниц нет общего
  CSS-файла; значения обязаны совпадать с `globals.css`, добавь unit-тест, сравнивающий значения токенов
  в трёх местах, или вынеси токены в общий модуль строкой, импортируемый в оба SSR-файла и проверяемый тестом
  против `globals.css`). CSP не менять.
- Существующие тесты: не ломать ожидания по разметке (`grep -rn` в `tests/` по классам и строкам
  `short-link-handler`, `guest-page`, `layout`). Если тест проверяет точный HTML — обновить тест осмысленно.

## Прибор — проверка в обеих темах
`scripts/check-responsive.mjs`: измерение `theme` (`dark`, `light`) для ВСЕХ сценариев, включая
`first-screen-*`: тёмная — без cookie (проверяет умолчание), светлая — cookie `n5_theme=light` на домен
`--base` в контексте (для `/dashboard` — вместе со `storageState` входа). В отчёте каждое нахождение и
страница несут `theme`, скриншоты — с темой в имени. Отдельная проверка-предусловие: на странице `/` без
cookie `document.documentElement.dataset.theme === 'dark'`, с cookie — `light`; иначе код 2
(«тема не применена — проверка не выполнена»), а не зелёный.
Тест в `tests/browser/`: фикстура с тёмной палитрой и серым текстом на чёрном (контраст < 4,5) → R4;
та же с исправленным цветом → 0. Мутация: сломать умолчание (`themeFromCookie` возвращает `light` на
мусоре) → юнит-тест красный; вернуть → зелёный. Обе строки в отчёт.
