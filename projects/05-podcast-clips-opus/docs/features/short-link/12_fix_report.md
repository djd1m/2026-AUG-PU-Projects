# SL-003–SL-005 · проверка метки до запуска

Постановка: `11_fix_brief_codex.md`. Реализация локального объёма завершена. Интеграционная
приёмка и независимое ревью Anthropic остаются integration owner согласно брифу.

## SL-003: конфигурация проверяется до работы

`loadWebConfig` и `loadWorkerConfig('worker-video')` вызывают общую проверку вместимости.
Она использует тот же расчёт геометрии и те же метрики шрифта, что рендер: самый широкий символ
выбирается из **алфавита генератора**, длина — из `N5_SHORT_CODE_LENGTH` (6 по умолчанию, 10 явно).
Проверяется кадр 1080×1920, соответствующий portrait-рендеру воркера. Длина 10 проверяется
по худшему коду `WWWWWWWWWW`, а не по случайному примеру, который может оказаться уже.

Геометрия и JSON метрик перенесены в `packages/shared/src/watermark.ts` и
`watermark-metrics.json`; генератор шрифта пишет туда же. Web получает их через существующий
COPY packages без зависимости от шрифта, ffmpeg или каталога assets воркера. Проверка SHA шрифта
на старте воркера сохранена. Алфавит и разбор длины общие с генератором ссылок.
Входные точки обоих сервисов передают длину; worker-video теперь выводит диагностическое
сообщение через существующий очиститель секретов вместо безличного отказа.

Реальные собранные входные точки — `apps/web/.next/preflight/preflight.js` и
`apps/worker/dist/workers/render.js` — проверены отдельными процессами. На длинном адресе
обе завершаются **exit 1**, до открытия сервера/очереди и платных стадий:

| Origin | Длина | Худшая ширина | Предел кода | Результат |
|---|---:|---:|---:|---|
| `https://clipmaker.aicoding.space` | 6 | 1190 px | 972 px | отказ старта web и worker-video |
| `https://clipmaker.aicoding.space` | 10 | 1350 px | 972 px | отказ старта web и worker-video |
| `https://clipmkr.ru` | 6 | 875 px | 972 px | конфигурация проходит |
| `https://clipmkr.ru` | 10 | 1035 px | 972 px | конфигурация отклонена |
| `http://localhost:4182` (test) | 6 | 965 px | 972 px | конфигурация проходит |

Сообщение для длины 6:

```text
N5_PUBLIC_ORIGIN непригодно при N5_SHORT_CODE_LENGTH=6: Адрес метки не помещается в безопасную область: ширина 1190 px, предел 972 px. Запуск остановлен до приёма загрузок: иначе минуты будут списаны, Whisper и выделение оплачены, а рендер откажет.
```

Положительный контроль web preflight: `https://i.io`, длина 10 → exit 0.
Полный успешный запуск воркера с инфраструктурой здесь не заявляется.

Страж испытан мутацией удаления `assertWatermarkFits(origin, env.N5_SHORT_CODE_LENGTH)`:

```text
проверка снята:       exit 1 тестов; 2 failed / 1 passed
проверка восстановлена: exit 0 тестов; 3 passed / 0 failed
```

При мутации два отдельных процесса загрузки конфигурации, web и worker-video, дают exit 0
вместо ожидаемого 1. Третий тест остаётся зелёным: та же геометрия по-прежнему бросает отказ
на рендере. Так воспроизводится именно позднее обнаружение, без сетевого запуска очереди.
Артефакты: `tests/artifacts/short-link-startup-fix/mutations/startup-watermark-{red,green}.json`.

## SL-004: две разные границы

**972 px** = `1080 − 2 × ceil(1080 × 0.05)` — каноническая безопасная область,
обеспеченная кодом на старте и при рендере. **880 px** — добровольная строгая зона сторис,
обеспеченная тестом эталонного `clipmkr.ru` с худшим шестизначным кодом.
Произвольный настроенный адрес шириной 930 px код пропустит.

Фраза прошлого отчёта «страж ловит именно 893 > 880» относится **только к тесту**
`one-line worst code fits strict 880 zone`: при кегле 75 ширина 893 px, runtime-предел
972 px ещё не нарушен. Комментарий непосредственно у проверки теперь различает эти границы.
Сами пределы и производственный кегль 73 px не изменены.

## SL-005: 5 px — риск, а не надёжный запас

Для `clipmkr.ru`, худшего кода `WWWWWW` и кадра 1080×1920. Ширина — сумма округлённых вверх
advance закреплённого шрифта плюс 80 px горизонтальных отступов. Проценты запаса считаются
от **880**, высоты кегля — от **1920**. Канонические 3,5 % соответствуют **67,2 px**.

| Кегль, px | Плита, px | До 880, px | До 880, % | Кегль / высота кадра | Над минимумом 67,2 px |
|---:|---:|---:|---:|---:|---:|
| 73 | 875 | 5 | 0.57 % | 3.802 % | +5.8 px |
| 72 | 868 | 12 | 1.36 % | 3.750 % | +4.8 px |
| 71 | 854 | 26 | 2.95 % | 3.698 % | +3.8 px |
| 70 | 845 | 35 | 3.98 % | 3.646 % | +2.8 px |
| 69 | 842 | 38 | 4.32 % | 3.594 % | +1.8 px |
| 68 | 815 | 65 | 7.39 % | 3.542 % | +0.8 px |
| 67 | 813 | 67 | 7.61 % | 3.490 % | -0.2 px |

Наибольший целый кегль, обеспечивающий не менее 5 % (44 px), — **68 px**:
запас **65 px / 7,39 %**, высота кегля **3,542 %**, то есть **+0,8 px / +0,042 процентного
пункта** над каноническими 3,5 %. Высота плиты при этом 111 px, но она не подменяет высоту
кегля. Для шестизначного кода оба требования численно совместимы.
Для худшего десятизначного кода при том же домене нужен кегль не выше **57 px**:
плита 830 px, запас 50 px (5,68 %), высота 2,969 % — ниже 3,5 % на 10,2 px;
оба требования для него несовместимы при неизменных шрифте и отступах.

Текущие **5 px / 0,57 % при 73 px — риск**: расчёт основан на метриках одного закреплённого
начертания; он не доказывает пиксельную точность или устойчивость к другой растеризации.
Метка рисуется `drawtext`/FreeType, libass используется для субтитров. Таблица — расчёт advance,
а не новое измерение фактической высоты глифов или мобильной читаемости каждого кегля.
Решение о смене кегля оставлено владельцу. Данные: `tests/artifacts/short-link-startup-fix/font-sizes.json`.
