# SL-006 · проверка всех форматов на старте

Единственный источник размеров — `packages/shared/src/formats.ts`:
`FORMAT_DIMENSIONS`, из ключей которой выводится `ClipFormat`.
`apps/worker/src/render/format.ts` импортирует и реэкспортирует эту карту;
`getScaleFilter` и `assertWatermarkFits` используют её напрямую.
Производственная карта по-прежнему содержит только `portrait: 1080×1920`.
Геометрия метки, настройки окружения, DNS и развёртывание не изменены.

`assertWatermarkFits` перебирает все записи. Для высоты каждой записи вычисляет
кегль и самый широкий символ из алфавита генератора, затем проверяет худший код
настроенной длины. Ошибка содержит имя формата.

## Страж и мутация

В `tests/watermark-startup.test.ts` отдельный процесс добавляет в собранную общую
карту `unfit_test: 540×960` после `portrait`. Постоянного тестового формата в
исходной карте нет. Проверяются оба загрузчика конфигурации и реальные собранные
точки старта: web preflight и worker-video.

```text
unfit_test добавлен: web и worker-video → exit 1, ошибка называет «формат unfit_test».
unfit_test отсутствует: конфигурация web и worker-video → exit 0.
```

Положительный контроль означает прохождение конфигурации; подключение воркера к
очереди и работоспособность развёрнутого сервиса он не доказывает.

Отдельная мутация заменяет вызов геометрии внутри обхода карты на зашитые
`watermarkGeometry(1080, 1920, …)`, сохраняя негодный формат в тесте:

```text
зашитые размеры: exit 1 тестов; 2 failed / 2 passed — оба загрузчика ошибочно дают exit 0.
обход с размерами карты восстановлен: exit 0 тестов; 4 passed / 0 failed.
```

В этом целевом прогоне 10 тестов SL-003 исключены фильтром `-t SL-006`.
Артефакты: `tests/artifacts/short-link-formats-fix/mutation-{red,green}.txt`,
`mutation-results.json`; воспроизведение — `run-mutation.py` в том же каталоге.
Скрипт восстанавливает исходник в `finally`, затем запускает зелёный контроль.
