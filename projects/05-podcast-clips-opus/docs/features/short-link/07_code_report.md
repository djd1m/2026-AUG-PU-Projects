# short-link — отчёт реализации

Код реализован, **приёмка не завершена**: обязательные проверки на настоящих PostgreSQL 16,
Redis 7 и MinIO, две мутации БД, E2E и независимое ревью Anthropic недоступны в этой сессии.
Изменения не развёрнуты, миграция на стенде не применялась.

## Реализация

- `GET /c/{code}` — HTML без обязательного JavaScript или входа: превью-изображение, название
  КлипМейкер, приглашение сделать свои клипы, адаптация под телефон, `no-store`.
  Видеофайл публичному зрителю не выдаётся; существующие проверки доступа к файлам сохранены.
- Ссылка читается из существующего `clip_link`; новый код при открытии/копировании не создаётся.
  Заголовок клипа и URL превью экранируются. Для превью используется существующая подпись S3
  после HEAD; отсутствие объекта не превращает страницу в битую ссылку.
- При истечении `expires_at` либо 72 часов после готовности бесплатной записи — `200` с текстом
  об истёкшем хранении и CTA. Удалённый файл/превью не требуется для учёта перехода.
- Неизвестная, отозванная ссылка, удалённая запись и неактивный владелец скрыты одинаковым `404`.
  В исходной схеме признака отзыва короткой ссылки не было: добавлена **новая** миграция
  `009_short_link.sql` с nullable `clip_link.revoked_at`; применённые миграции не изменены.
  Новая процедура отзыва не добавлена: отзыв задаётся данными, как требует постановка.
- `link_view` вставляется через `ON CONFLICT DO NOTHING RETURNING id` под **существующим**
  частичным UNIQUE; только успешная вставка увеличивает `unique_view_count` и обновляет
  `last_view_at`. Оба действия выполняются одним соединением внутри `BEGIN/COMMIT`.
  Самопереход владельца не открывает транзакцию. Адрес берётся через существующую проверку
  доверенных прокси и усечение IPv4 /24, IPv6 /64. День вычисляет существующий `moscowDay`.
- `link.create` подключена к существующему tRPC endpoint и авторизации мутирующих запросов.
  Владение проверяется по сессии; чтение существующего кода и `link_copy` — одним SQL statement.
  Чужой/неизвестный/отозванный ресурс — `404`; московский `day` указан явно.
- Карточка получила кнопку копирования. Она доступна и после истечения срока файла;
  при недоступном Clipboard API показывает адрес для ручного копирования.
  `link_copy` фиксирует запрос владельца на получение ссылки; ОС не подтверждает фактическую
  публикацию или завершение последующего ручного копирования.

Гостевая страница, партнёрские коды, установка атрибуционного cookie и их применение остаются
вне границ этой фичи. Новых типов `growth_event` нет; публичный путь `/c/{code}` и процедура
`link.create` уже присутствовали в закрытом списке канона.

## Мутации — обе строки каждой пары

Запуски выполняются в отдельной временной копии; исходники рабочей копии не мутируются.
SQL-мутации допускаются только с `DATABASE_URL`, указывающим на отдельную `*_test` БД.

| Страж | Внедрённый дефект: красная строка | Восстановленный код: зелёная строка |
|---|---|---|
| Уникальность даёт БД | `database-uniqueness-red.txt`: **NOT RUN**, exit=null. Мутация заменяет атомарный conflict-result на предварительный SELECT и обычный INSERT с задержкой для гонки. | `database-uniqueness-green.txt`: **NOT RUN**, exit=null. ## Что осталось непроверенным

- Девять новых интеграционных тестов: 20 параллельных HTTP-handler вызовов с разными IP одной
  /24; прямой дубль SQL; rollback при сбое счётчика; истечение файла; реальный отзыв; владелец
  и другой авторизованный зритель; московская полночь и IPv6; `link_copy`; удаление/неактивность.
  Все написаны, но **не исполнены**. Наличие теста не доказывает поведение PostgreSQL.
- Полная регрессия с PostgreSQL 16, Redis 7 и MinIO, две SQL-мутации и применение новой миграции.
- Независимое ревью Anthropic по OWN-002: CLI завершился таймаутом, заключения нет.
- Реальный HTTP/E2E, Clipboard API в браузере, мобильная визуальная приёмка и Cloud.ru HEAD/GET.
- Установка атрибуционного cookie требует реализации партнёрских кодов, исключённой постановкой.

После доступности окружения: применить миграции в тестовой БД, выполнить compose test **с
`--build`**, затем mutation script с этой БД; провести независимое ревью и E2E кандидата.
Не считать восстановленные пары успешными, пока их журналы не заменены результатами реальных
новых запусков с привязкой к ревизии.
