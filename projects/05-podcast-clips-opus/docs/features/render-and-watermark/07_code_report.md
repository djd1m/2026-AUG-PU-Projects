# render-and-watermark — отчёт Codex

Реализован перенос рендера и подключён настоящий обработчик `worker-video`. **Приёмка не завершена:**
обязательные PostgreSQL/S3 интеграции недоступны в sandbox, Anthropic review завершился таймаутом.
Ни пропущенные тесты, ни дополнительное ревью OpenAI не объявляются прохождением этих ворот.

## Существенные решения и необходимые изменения фич 1–5

- `render_fence`, CHECK неотрицательности и четыре статуса уже существуют в **001_init.sql**.
  Применённые миграции не изменены. Новая **008_render.sql** добавляет триггер, запрещающий
  `job_attempt(stage=render)` без существующей ссылки именно этого клипа/видео.
- `selection.ts`: существующий 22-символьный base64url-код не помещался. `CreateClipLink` канона
  (`Pseudocode.md`) требует **10 символов, ≈50 бит**, уникальность и максимум три попытки.
  Это вынесено в `db/src/clip-link.ts`; ссылка по-прежнему фиксируется до lease и enqueue.
  Старые строки ссылок автоматически не переписываются.
- Две строки сами по себе не решают ширину длинного домена. В образ поставлен **ClipMaker Narrow**:
  воспроизводимая производная Liberation Sans Narrow Bold, горизонтальные метрики 70%, вертикальные
  без изменений, кегль 68. Оригинальный TTF, производный TTF, лицензия, GPL-2 и скрипт генерации
  включены. SHA файла сверяется с метриками на старте. Для `clipmaker.aicoding.space/c/WWWWWWWWWW`
  верхняя расчётная граница текста **895 px**, с подложкой **911 ≤ 972 px**. Непомещающийся адрес
  отвергается, не обрезается и не уменьшается. Контраст белого/чёрного — **21:1**.
- `runtime.ts`, `workers/render.ts`, `db/src/index.ts` и Dockerfile изменены для подключения обработчика,
  S3/рабочего каталога и шрифтов. Фикстуры двух прежних SQL-наборов теперь создают ссылку до попытки;
  прежний guard concurrency перенаправлен с заглушки на реально регистрируемый воркер.
- `withSource` фичи 3 переиспользован без изменений: резерв ≥3× до GET, очистка каталога и освобождение
  резерва в finally. Deferred сохраняет принятый фичей 3 статус клипа `rendering`, причина `no_disk`
  живёт у попытки, heartbeat двигается. BullMQ переносит задание на 5 минут.
- Канонические S3-ключи не содержат fence. По находке независимого аудита **RENDER-001 (HIGH)**
  публикация усилена `If-None-Match: *`: одной блокировки PostgreSQL недостаточно при обрыве соединения.
  Существующий объект можно принять только по совпадающему хешу контракта (источник, границы, слова,
  тарифная метка, origin/code, шрифт, версия рендера); bytes берутся из S3.
  **Автоматического DELETE канонического объекта при ошибке БД нет:** его уже могла принять новая попытка.
  Объекты после потери подтверждения можно принять повтором; чужой контракт требует отдельного разбора.
  Дополнительный аудитор повторно проверил исправление, исходная HIGH закрыта.
- Результат принимается условным UPDATE по clip/render_fence/status в транзакции; обновляются
  `clips_done`, терминальный статус видео и pending-атрибуция. При дубле — stale_attempt_result.
  У sibling-клипов разные fence, актуальность не сравнивается с последним fence всего видео.

## Настоящий файл и пределы доказательств

**Да, настоящий MP4 отрендерен установленным ffmpeg 4.4.2:** 20 с, 1080×1920, AAC-аудио,
кириллические ASS-субтитры с подсветкой и две строки метки. Вход синтетический (цвет + синус),
**записи настоящего подкаста не было**. Файлы `clip.mp4`, `frame.png`, `thumb.jpg` сохранены
в каталоге квитанций. Размер, длительность, наличие аудио и JPEG проверены инструментально;
кадр просмотрен. Пиксельный тест проверяет наличие букв/подложки в обеих полосах, **не OCR адреса**.

Не доказано / остаётся до приёмки:

1. Конкурентный PostgreSQL-прогон двух доставок fence=N, trigger/migration, retry/deferral,
   partial success и настоящая потеря соединения при публикации. SQL-тесты написаны, но недоступная
   БД не превращает чтение исходника в измерение.
2. Реальные MinIO/Cloud.ru PUT с If-None-Match и HEAD metadata, особенно поведение гонок/обрывов;
   storage-fake проверяет наш алгоритм, не реализацию сервера. При неподдерживаемой условной записи
   серверная ошибка не маскируется успешной публикацией.
3. Образ worker с ffmpeg 7, контейнерный E2E и CJM: Docker недоступен, `check-cjm.sh` отсутствует,
   экраны/выдача следующей фичи ещё не реализованы. E2E pass не заявлен.
4. Обязательное cross-family ревью Anthropic. Дополнительный OpenAI-аудит — только дополнение.
5. Читаемость на телефоне двумя людьми, пять клипов; NFR p95 и нагрузка на VPS не измерены.
6. Уже существующие длинные коды и произвольные длинные домены могут отказать по ширине; миграция
   данных/перевыпуск опубликованных ссылок не производились. Согласование старых конфликтующих
   канонических объектов не автоматизировано. Аудиофайл без видеодорожки отдельно не проверен.
