# Постановка на исправление — рендер не умеет аудио без видеодорожки

**Найдено ПЕРВЫМ СКВОЗНЫМ ПРОГОНОМ на развёрнутом стенде 23.09.2026.** Ни один из 469 тестов этого
не видел: тесты проверяют сборку цепочки фильтров, но ни один не подаёт на вход настоящий файл без
видеодорожки.

## RD-001 · blocker · аудиофайл проходит весь конвейер и падает на рендере

**Измерено на стенде.** Загружен MP3 длительностью 189 с (одна дорожка, `codec_type=audio`).
Путь: `queued` → `transcribing` → `selecting` → `rendering` → `failed(render_failed)`.
Все **шесть** выделенных клипов получили `failure_reason = ffmpeg_failed`.

**Канон §7 и `.claude/rules/security.md` прямо разрешают загружать `M4A` и `MP3`** — тип проверяется
по магическим байтам, и оба в списке допустимых. То есть подкаст без картинки — законный вход, а не
краевой случай.

**Цена дефекта — деньги пользователя.** К моменту отказа уже израсходованы: минуты распознавания
(`user_minutes`, `global_minutes`) и вызов модели выделения (`user_llm`, `global_llm`). Пользователь
платит квотой за путь, который не может завершиться никогда. Слот `user_uploads` при этом НЕ
возвращается, потому что `render_failed` — не отказ по свойствам файла.

**Что сделать.** Рендер обязан строить кадр для входа без видеодорожки. Варианты (выбери и обоснуй):
однотонный фон через `lavfi` источник внутри того же графа фильтров, либо обложка из метаданных
файла, если она есть. **Второй проход ffmpeg не заводить** — это удвоило бы время рендера
(измерено в `WU-02-render.md`: наивная пересборка даёт ×2 и ломает NFR-PERF-001).

Субтитры, метка и порядок фильтров остаются прежними: меняется только источник изображения.

**Альтернатива, которую надо рассмотреть и отвергнуть явно:** запретить аудио на приёме. Отвергни её
с обоснованием — канон допускает эти типы, и запрет означал бы правку замороженного документа плюс
потерю законного сценария «подкаст без видео».

## RD-002 · high · ошибка ffmpeg не сохраняется нигде

Журнал `n5-clipmaker-worker-video-1` **пуст**: шесть отказов подряд, и ни одной строки о причине.
`failure_reason = ffmpeg_failed` не говорит, что именно не понравилось ffmpeg.

Это тот же класс, что WD-001, исправленный сегодня в стороже: отказ честный, но диагностировать по
нему нечего. **Код возврата и последние строки `stderr` ffmpeg обязаны попадать в журнал** (без
подписанных ссылок и секретов — их в журнал не писать, это правило уже есть).

Проверь заодно остальные `catch` в `apps/worker/src`, как это было сделано для `apps/web/src`.

## Тесты

| Страж | Внедряемый дефект |
|---|---|
| вход без видеодорожки рендерится | вернуть прежнее поведение → красный |
| `stderr` ffmpeg попадает в журнал при отказе | заглушить → красный |
| подписанные ссылки в журнал НЕ попадают | записать URL → красный |
| второго прохода ffmpeg нет | добавить → страж по исходнику красный |

**Интеграционный обязателен:** сгенерироватькороткий MP3 без видеодорожки прямо в тесте
(`ffmpeg -f lavfi -i sine`), прогнать рендер, проверить, что на выходе видеофайл 9:16 с субтитрами.

Мутации обеими строками.
