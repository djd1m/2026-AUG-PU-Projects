## RD-001: источник изображения

Выбран однотонный тёмный фон `color` из libavfilter, внутри того же `-filter_complex`.
Перед рендером локальный `ffprobe` определяет индекс первой настоящей видеодорожки
(`V:0`, без attached picture). Если её нет, источник — `color` 1080×1920, 25 fps,
ограниченный длительностью клипа; если есть — существующая видеодорожка.
Ошибка probe не считается отсутствием видеодорожки: задача получает обычный отказ/повтор.
Probe ограничен 30 секундами, 64 КиБ вывода, протоколом `file` и сигналом отмены.

Обе ветки используют существующую цепочку **scale → crop → ASS → watermark**.
Звук явно выбирается из оригинала. Длительность выхода ограничена 20–75 секундами,
таймауты рендера и очистка каталога сохранены. Производственный `renderClip` вызывает
`execFFmpeg` ровно один раз. Отдельное существующее создание JPEG-превью сохраняется;
оно не является вторым кодированием клипа.

Обложка не выбрана: она может отсутствовать, быть неподходящего размера или содержать
произвольное изображение. Однотонный фон даёт одинаковый результат для MP3/M4A с обложкой
и без неё, без промежуточного видео и дополнительного прохода кодирования.

**Запретить аудио на приёме — отвергнуто.** MP3/M4A разрешены каноном §7,
`Specification.md:74` и правилами безопасности. Запрет менял бы замороженную спецификацию
и убирал законный сценарий «подкаст без видео». Приём, STT и выделение не изменены.

## RD-002: диагностика

При отказе ffmpeg журнал получает структурированную запись: причина, `exit_code`,
сигнал завершения, код ошибки запуска (если процесс не удалось запустить) и последние
20 строк `stderr`, не более 4096 символов. Буфер процесса ограничен 65536 символами.
После переполнения первая неполная строка отбрасывается: она может содержать хвост
длинной подписанной ссылки. При таймауте запись делается после `close`.

URL целиком удаляются, строки с заголовками авторизации/cookie, параметрами подписей
и именованными секретами редактируются. Аргументы запуска, объект `Error`, его `cause`
и окружение не сериализуются. Это защита известных форм credentials, не обещание
распознавать произвольный секрет без контекста в любом тексте.
Воркер до попытки повторной постановки пишет `video_id`, `clip_id`, `fence` и очищенное
сообщение; ошибка самого enqueue также очищается.
