## 3. Риски и то, что план сознательно НЕ решает

1. **ADR-005 утверждает несуществующее.** «Спящего кода ЮKassa» в N5 нет (§0 п.1). Это расхождение документа с кодом,
   его надо исправить в ADR при реализации, иначе следующий исполнитель будет искать файлы, которых нет.
2. **Понижение после оплаты стирает клипы.** Без U6 (срок от конца оплаты) первый же проход ретенции после истечения
   удалил бы все клипы оплаченного периода старше 3 суток — тихая потеря данных клиента. Решение исполнителя в плане;
   владелец может выбрать иное (например, «после истечения клипы живут по правилам free от даты готовности»).
3. **Экран интереса и оплата сосуществуют.** Страж «на экране нет слов оплат/checkout» должен стать условным по режиму;
   иначе он либо ложно падает в режиме live, либо его снимут целиком.
4. **Двойной прокси на стенде.** `clientIp` при `N5_TRUSTED_PROXY_HOPS=2` проверен для ограничителя частоты, но не для
   сверки с сетями ЮKassa: если общий прокси перезапишет цепочку иначе, чем Caddy проекта, все уведомления получат 400
   (отказ громкий, не тихий — деньги не потеряются: ЮKassa повторяет до 24 ч, платёж виден в кабинете).
5. **Лендинг без раздела тарифов.** FR-LOOK-014 требует страницу тарифов с «экспорт без метки»; в коде лендинга раздела
   тарифов нет. В план не включено — вне объёма «оплата»; отмечено как хвост для владельца.
6. **Файлов меньше 500 строк:** крупнейший донор `yookassa.ts` — 288 строк, `billing-handler.ts` — 209; при адаптации
   правило держится.
