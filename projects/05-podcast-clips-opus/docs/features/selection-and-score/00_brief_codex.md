## Поставщик и форма вызова — измерено, не взято из документации

Опорная модель — `anthropic/claude-sonnet-5` через OpenRouter, **поставщик закрепляется**:

```js
POST https://openrouter.ai/api/v1/chat/completions
{
  model: 'anthropic/claude-sonnet-5',
  messages: [...],
  response_format: { type: 'json_schema', json_schema: { name: 'fragments', strict: true, schema: SCHEMA } },
  provider: { only: ['Anthropic', 'Claude Platform on AWS'], allow_fallbacks: false, require_parameters: true }
}
```

**Закрепление обязательно и проверяется стражем.** У Sonnet 5 на OpenRouter строгий режим схемы
объявляют только **2 эндпоинта из 10**; без закрепления запрос уходит туда, где схема становится
пожеланием, и это не видно по ответу. Отсутствие `provider.only` — blocker.

**Модель выбирается настройкой, а не правкой кода.** Вторая модель объявлена претендентом:
`google/gemini-3.8-flash` (схему держит, вдвое быстрее, впятеро дешевле — измерено). Адаптер обязан
позволять прогнать ОБЕ на одном транскрипте, не меняя ничего, кроме значения конфигурации: сравнение
на настоящих выпусках — отдельная работа владельца, и она не должна упираться в код.

## Что построить

### 1. Схема ответа — закрытая и строгая

3–8 фрагментов; у каждого `start_seconds`, `end_seconds`, заголовок, три компонента `0–33` целыми и
три непустых объяснения по-русски. Объявляется ОДИН раз в `packages/shared` и оттуда попадает и в
запрос, и в `CHECK` миграции.

### 2. `SelectFragments` — один вызов на запись

**Один вызов модели на ЗАПИСЬ, а не на клип.** Потолок `global_llm` = 20 в сутки посчитан из этого
допущения; вызов на клип пробил бы бюджет на второй же записи.

Порядок операций:

1. `CheckAndConsumeQuota` на `user_llm` (2) и `global_llm` (20) — **ДО вызова**;
2. вызов с закреплённым поставщиком; **каждая ПОПЫТКА пишет строку в `model-spend.jsonl`**, включая
   таймаут и отказ;
3. **проверка диапазонов НАШИМ кодом.** Структурированный вывод гарантирует форму, но не смысл:
   длина вне 20,0–75,0 с, компонент вне 0–33, пустое объяснение, сумма компонентов, не равная
   `score` — всё это отвергается нами, а не считается принятым;
4. **границы прижимаются к СЛОВАМ транскрипта** (ADR-003): модель назвала секунды — мы находим
   ближайшую границу слова и берём её. Резать посреди слова запрещено;
5. честное число фрагментов: нашлось меньше трёх — так и записываем, **не добираем слабыми**;
6. запись клипов одной транзакцией, затем `video.status = rendering` и постановка заданий —
   фиксация ДО постановки.

### 3. Повтор

Команда «повторить выделение» — новая серия (`series_no`), списывает `user_llm` заново. Две
параллельные команды на одном видео: проходит РОВНО одна (конкурентный прогон из `testing.md`).

## Тесты, без которых фича не принимается

**Стражи с внедряемым дефектом, обе строки в отчёт:**

| Страж | Внедряемый дефект |
|---|---|
| закрепление поставщика | убрать `provider.only` → страж по исходнику красный |
| диапазоны проверяет НАШ код | довериться схеме, убрать проверку → тест с ответом вне диапазона красный |
| границы по словам | брать секунды модели как есть → тест на разрез посреди слова красный |
| `user_llm` списан ДО вызова | переставить → красный |
| счёт по попыткам | считать по успехам → красный |
| меньше трёх фрагментов не добирается | добрать слабыми → красный |

**Конкурентный (из пяти обязательных):** две параллельные команды «повторить» при `user_llm` = 2 —
проходит ровно одна, списание ровно одно.

**Фейк модели детерминированный:** отвечает по контракту и пограничными случаями — больше 8
кандидатов, оценка вне диапазона, пустое объяснение, длина вне границ, 5xx, таймаут.
**Тесты не ходят в интернет.**
