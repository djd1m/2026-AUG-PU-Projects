# Фича 5 · selection-and-score · отчёт Codex

Реализован обработчик выделения и оценки; **приёмка не завершена**: обязательный прогон на
PostgreSQL/Redis/MinIO и ревью Anthropic недоступны в этой среде. Рендер, метка и экраны не реализованы.
Живых вызовов модели не было. Все ответы поставщика в тестах — детерминированные фейки.

## Что создано

- `packages/shared/src/fragments-schema.json`, `fragments.ts`: одна закрытая схема ответа,
  проверка формы, целых компонентов 0–33, суммы, объяснений с русскими буквами, длительности,
  положения внутри записи и пересечений. Прижимание начала к началу слова, конца к концу слова;
  повторная проверка после прижимания, включая пересекающиеся слова. Не больше восьми лучших;
  один-два сохраняются без добора, ноль даёт `failed(no_fragments)`.
- `apps/worker/src/llm/provider.ts`, `prompts/selection.ts`: один запрос OpenRouter на запись,
  весь транскрипт, оценки и заголовки в том же ответе. `response_format=json_schema`, `strict=true`,
  `provider.only`, `allow_fallbacks=false`, `require_parameters=true`. Таймаут 120 с охватывает тело
  ответа. Автоматических повторов и переключения модели после отказа нет.
- Модель задаётся `N5_LLM_MODEL`: `anthropic/claude-sonnet-5` с поставщиками `Anthropic` /
  `Claude Platform on AWS` либо `google/gemini-3.8-flash` с `Google`. Для переключения нужен только
  конфиг. Неизвестная модель/пустой ключ отказывают при старте; fake разрешён только в тестовой среде.
- `packages/db/src/selection.ts`: блокировка видео, проверка актуального фенса/активного аккаунта,
  списание обоих ключей квоты до вызова. `llm_dispatched` предотвращает второй вызов при дублированной
  доставке; `unit_count=1` использует уже оплаченный резерв существующего `video.retry` без двойного
  списания. Поздний результат не создаёт клипы.
- `apps/worker/src/workers/select.ts`: запись попытки в `model-spend.jsonl` с fsync ДО отправки;
  отдельная строка результата для успеха, 5xx, таймаута и невалидного ответа. Для подсчёта вызовов
  учитывается только `phase=attempt`, не строки `outcome`. Недоступный журнал запрещает отправку.
- Клипы, `clip_link`, попытки рендера и `video.status=rendering` фиксируются одной транзакцией
  ДО enqueue. Ссылки готовы до рендера. Потерянную публикацию восстанавливает существующий watchdog.
  Метка определяется серверным `plan !== 'paid'`; сам рендер остаётся на фичу 6.
- `007_selection.sql` и `scripts/generate-selection-migration.mjs`: CHECK сгенерирован из shared-схемы,
  его равенство проверяется тестом. Точность `start_seconds/end_seconds` заменена на `numeric` без
  округления: прежний `numeric(10,1)` мог сдвинуть таймкод внутрь слова. Применённые миграции не менялись.
  Генератор не перезаписывает существующий файл; проверка: `node scripts/generate-selection-migration.mjs --check`.
- `llm/fake.ts`, три набора `tests/selection*.test.ts`, скрипт шести мутаций. Интеграционный набор
  включает параллельный повтор, двойную доставку, старый фенс, персональный/глобальный потолки,
  фиксацию перед публикацией, восстановление watchdog и сохранение точности в PostgreSQL.

Команда повтора использует существующий `video.retry` для failed-видео с транскриптом и без клипов:
новая `series_no`, одно списание, конкурентный проигравший получает conflict. Новая команда повторного
выделения уже успешно обработанной записи в этой фиче не добавлялась.

## Ревью и ограничения доказательств

Дополнительный независимый read-only проход запрошен у `gpt-5.6-sol`, effort high. Он не обнаружил
других blocker/high в квоте, предоплате повтора, pinning, границах, фенсе и фиксации перед очередью,
но отметил конфликт строгого `minItems=3` с прямым честным ответом модели из одного-двух фрагментов.

Сохранено **прямое требование брифа** о строгой схеме 3–8. Путь «три кандидата, два пригодных после
нашей проверки» подтверждён тестом адаптера: длительность и пересечения не гарантируются JSON-схемой.
Это не доказывает, что модель при нехватке сильных мыслей не доберёт слабые. Прямое представление
такой нехватки в строгом ответе остаётся противоречием требований и требует уточнения владельца;
схема молча не ослаблялась. Подробности: `supplemental-review.md`.

Не проверены: реальная конкуренция на PostgreSQL, применение новой миграции к существующей базе,
доставка Redis, контейнерная сборка, качество обеих моделей на настоящем выпуске, поведение настоящего
поставщика при нехватке фрагментов, скорость длинной записи, Cloud.ru и пользовательский E2E.
Фейк и транспорт с подставленным fetch не выдаются за живой вызов. Обязательный Anthropic cross-family
review не выполнен; supplemental review его не заменяет. Следующий шаг — доступная среда для
указанной compose-команды и Anthropic-ревью снимка исходников.
