# N5: подключение аналитики при запуске в Cloud.ru РФ

Статус: **план реализации на целевом сервере**, не выполненная активация.
Владелец уточнил: текущий VPS используется для кода, запуск будет в Cloud.ru РФ.
На текущем production VPS аналитика не включается; настоящий counter пока не создан.

Общий порядок остальных работ: [план запуска N5](../../cloudru-launch-plan.md).
Активация Метрики следует после кредитов и подключения FM/Object Storage.

## 1. Перед переносом

Получить код проверенной feature/n5-acquisition-analytics-20261026 и результаты
[приёмки](05_completion.md). Сохранить и перенести БД/секреты штатным порядком,
не через git. Проверить адреса S3, права, TLS, origin и тестовые/боевые режимы
по существующей docs/REPRODUCE.md. Эта фича не мигрирует тарифы или провайдера.

Целевые тарифы: Старт990 ₽/300кредитов (5часов), Про3990 ₽/1800кредитов
(30часов), доппакет1490 ₽/600кредитов (10часов),30кредитов только после
регистрации; обычный режим1кредит/мин. Фактическую реализацию подтвердить отдельно.

## 2. Счётчик и конфигурация

В аккаунте владельца создать собственный счётчик Яндекс Метрики для целевого
домена. Не использовать чужой или вымышленный ID. Публичный номер записать в
закрытый env-файл, реально используемый штатным запуском Compose, как N5_METRIKA_COUNTER_ID.
В REPRODUCE.md это `--env-file .env`; если файл назван `runtime.env`,
при каждом целевом запуске явно указать `docker compose --env-file runtime.env ...`.
Само имя файла не загружает его в интерполяцию Compose.
Пароли, OAuth-токены и весь объект окружения в браузер/репозиторий не передавать.

Compose передаёт эту переменную только web; пустое значение оставляет аналитику
выключенной. ID читается runtime сервером, а не build-time NEXT_PUBLIC значением.
Настройка требует перезапуска web по штатному процессу, не изменения глобальных
настроек сервера или моделей. Не копировать production.env в сессию/логи.

Создать цели типа JavaScript-событие с точными идентификаторами:

- n5_visit
- n5_signup_success
- n5_first_clip_ready
- n5_payment_confirmed

Выключить Вебвизор, автоматические цели и лишний автоматический сбор данных в
настройках счётчика. Проверить настройки SDK и согласия; имен/контента/URL с
токенами в запросах быть не должно. Не считать это юридическим заключением:
политику обработки и необходимые согласия на целевом контуре проверить отдельно.

## 3. Синтетическая проверка до рекламного трафика

1. Без согласия и при отказе нет SDK/goals. После разрешения виден n5_visit.
2. Новый тестовый аккаунт после успешной защищённой операции даёт signup goal.
   Login и повтор email с формальным200 не должны его создавать.
3. Разрешённая синтетическая фикстура с доступным done-клипом даёт ready goal.
   Не отправлять пользовательскую запись в модель ради проверки аналитики.
4. Payment goal проверяется по достоверному статусу в тестовом платёжном
   контуре; redirect/pending/operator-paid не подходят. Реальный платёж только
   в отдельно разрешённом платёжном прогоне, не автоматически по этой инструкции.
5. Отозвать согласие, перейти на исключённый путь: ранее загруженный SDK тоже
   прекращает последующие отправки. Проверить storage/network/adblock ошибки.

## 4. Доказательство поступления

Проверить обычные запросы к Метрике **без interception/fulfill** с правильным
owner ID. Сохранить очищенные host/counter/event/time/HTTP сведения. Затем
через кабинет/отладчик проверить сами цели: HTTP200 или SDK callback по отдельности
не доказывают ingestion в отчёт. При отсутствии доступа отметить unknown/planned.

Сверить подтверждённые оплаты и возвраты с БД: браузерная аналитика считает
только наблюдённые подтверждения и не является финансовым ledger. Воронка
согласившихся пользователей не равна всем посетителям. Не тестировать настоящую
доставку вымышленным счётчиком или чужим аккаунтом.

Итоговую квитанцию записать в05_completion.md с ревизией, сервером, временем,
очищенными доказательствами и непройденными воротами. Пока этого нет,
«события приходят в аналитику» остаётся planned, а не pass.

Официальные инструкции: [цели reachGoal](https://yandex.ru/support/metrica/ru/objects/reachgoal),
[проверка счётчика](https://yandex.ru/support/metrica/ru/general/check-counter),
[автоматические цели](https://yandex.ru/support/metrica/ru/general/auto-goals).
