# Постановка на исправление — публичный адрес хранилища для подписанных ссылок

**Найдено ЖИВЫМ ПРОГОНОМ владельца 22.09.2026**, не тестами. Ни один из 313 зелёных тестов этого не
видел: тесты ходят в MinIO изнутри сети, где внутренний адрес работает.

## PE-001 · blocker · браузер получает неработающий адрес хранилища

Журнал браузера владельца на `https://clipmaker.aicoding.space/dashboard`:

```
Mixed Content: The page at 'https://clipmaker.aicoding.space/dashboard' was loaded over HTTPS,
but requested an insecure resource 'http://minio:9000/n5-demo/videos/…?X-Amz-Signature=…&partNumber=1
&uploadId=…'. This request has been blocked
```

**Причина — одна переменная на два разных назначения.** `S3_ENDPOINT` используется И для серверных
вызовов, И для подписи ссылок, отдаваемых БРАУЗЕРУ. Это разные потребители с разными требованиями:

| Потребитель | Нужен адрес | Сейчас получает |
|---|---|---|
| `web`, `worker-stt`, `worker-video` — изнутри сети compose | `http://minio:9000` | верно |
| **браузер пользователя** | публичный HTTPS | `http://minio:9000` — **недостижим и заблокирован** |

У Cloud.ru эти адреса СОВПАДАЮТ, поэтому пробел не проявлялся. Он виден только там, где хранилище
внутреннее — то есть на нашем стенде и у любого, кто развернёт продукт с MinIO.

Это класс `deployment-seams`: код верен, конфигурация верна для одного потребителя, сломан стык.

## Что сделать

**Ввести `S3_PUBLIC_ENDPOINT`** — отдельная обязательная переменная, используемая ИСКЛЮЧИТЕЛЬНО при
подписи ссылок, отдаваемых браузеру (`presign`, ссылки частей multipart, ссылка скачивания клипа).
Серверные операции (`HEAD`, `GET` диапазона, `CompleteMultipartUpload`, `Delete`, `Abort`)
продолжают ходить по `S3_ENDPOINT`.

**Подписывать сразу публичным хостом.** Подменить хост в ГОТОВОЙ ссылке нельзя: подпись SigV4
считается от хоста, и замена даёт `SignatureDoesNotMatch` — это записанная грабля клона
(`myinsights/INS-007-s3-signature-mismatch.md`, прочитать до кода). Значит нужен отдельный
экземпляр клиента для подписи, настроенный на публичный адрес.

**Fail-closed, как у `N5_PUBLIC_ORIGIN`:** переменная обязательна, без неё старт `web` валится с
сообщением, называющим переменную И последствие. Цена умолчания здесь та же: подставленный
внутренний адрес уедет в браузер и загрузка не заработает НИ У КОГО, при этом сервер будет здоров,
а тесты зелёными.

Значение должно быть **HTTPS** в боевом профиле: отдача незащищённого адреса на HTTPS-странице
блокируется браузером — именно это и наблюдалось.

## Тесты, обязательные

| Страж | Внедряемый дефект |
|---|---|
| подписанная ссылка содержит ПУБЛИЧНЫЙ хост, не внутренний | подписать `S3_ENDPOINT` → красный |
| серверные операции идут по внутреннему адресу | подписать всё публичным → красный (или назови, почему это допустимо) |
| старт валится без `S3_PUBLIC_ENDPOINT` | сделать необязательной → красный |
| в боевом профиле схема `https` | принять `http` → красный |

Мутации обеими строками.
