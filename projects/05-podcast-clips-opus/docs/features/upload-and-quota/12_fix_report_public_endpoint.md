# PE-001 — публичный endpoint подписанных ссылок

Исправление в разрешённых файлах реализовано; приёмка **заблокирована** необходимым пробросом
в `apps/web/src/server/environment.ts`, который не входит в явный список «Границы» постановки.
Разрешение на одну строку запрошено у владельца, ответа пока нет. Без неё web не запускается:
явный `readEnvironment()` не передаёт новый обязательный параметр в `loadWebConfig()`.
Подготовленный патч: `tests/artifacts/public-endpoint/environment.patch`.

## Что изменено

- `packages/shared/src/config.ts`: `loadWebConfig` требует `S3_PUBLIC_ENDPOINT`; ошибка называет
  переменную и последствия для браузерной загрузки/скачивания. Допускается только HTTPS, кроме
  явно заданных `NODE_ENV=development/test`. Пустые, непригодные адреса, пути, credentials,
  query/hash и управляющие символы отвергаются. `loadS3Config` остаётся серверным конфигом.
- `packages/s3`: клиент внутреннего транспорта владеет отдельным клиентом подписи. `signParts`
  и `generateDownloadUrl` подписывают сразу публичный endpoint; замены готового URL нет.
  Создание/list/complete/abort multipart, HEAD, GET и Delete используют внутренний транспорт.
  Закрытие владельца освобождает оба клиента. Серверные контексты с обычным `S3Client` совместимы;
  попытка подписи без публичного клиента явно отказывает.
- `.env.example`: обязательная новая переменная, совпадение адресов Cloud.ru, требование внешнего
  HTTPS origin для MinIO и сохранения подписанного Host прокси.
- Обновлены тестовые конфиги/потребители подписи, добавлены поведенческие стражи и проверка
  собранного startup-preflight без новой переменной.

## Проброс по сервисам

`docker compose config` с фиктивными значениями подтвердил:

| Сервис | S3_PUBLIC_ENDPOINT | Причина |
|---|---|---|
| web | обязательная `${S3_PUBLIC_ENDPOINT:?…}` | выдаёт браузеру PUT частей и GET клипов/превью |
| test | `http://minio:9000`, `NODE_ENV=test` | тестовый потребитель находится внутри compose-сети |
| worker-stt, worker-video | отсутствует | скачивают/выгружают сами через `S3_ENDPOINT` |
| worker-llm, db, redis, minio | отсутствует | не подписывают браузерные ссылки |

Публичность реального MinIO этим тестовым значением не доказывается. Порты не менялись.
Проверка `checkWiring` на развёрнутом Compose нашла ровно ожидаемую недостающую строку
`web environment.ts: S3_PUBLIC_ENDPOINT`; секреты окружения в артефакты не выводились.

## Что не проверено и что осталось

1. Разрешить и добавить `S3_PUBLIC_ENDPOINT: process.env.S3_PUBLIC_ENDPOINT` в web environment reader,
   затем повторить затронутые проверки и полный прогон. До этого результат не готов к запуску.
2. Полный Docker-прогон с `--build` не выполнен: доступ к `/var/run/docker.sock` запрещён.
   89 пропусков локального набора не объявляются зелёными интеграционными тестами.
3. Живой браузер, внешний DNS/TLS, сохранение Host на прокси, CORS и Cloud.ru/MinIO через публичный
   адрес не проверялись; инфраструктура и deployment не менялись.
4. Anthropic CLI доступен, но попытка валидации плана завершилась таймаутом 40 с без ответа.
   Требуемое OWN-002 cross-family ревью остаётся незавершённым.
