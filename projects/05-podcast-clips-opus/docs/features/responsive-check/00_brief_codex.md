# Постановка для Codex — фича 23 `responsive-check`: автоматическая проверка мобильной вёрстки

Шаг 1 плана `docs/plans/2026-09-25-mobile-ui.md` (OWN-016: проверка — эмуляцией Playwright, не руками).
Методика — `.claude/skills/responsive-ui/SKILL.md` (прочитай целиком: правила 1–14). Исследование —
`docs/research/2026-09-25-ui-ux-mobile-skillset.md` (раздел 4 и поправки Codex в разделе 7 — ОБЯЗАТЕЛЬНЫ).
Этот шаг НЕ чинит вёрстку — он строит прибор и снимает базовую линию. Код продукта `apps/web` не трогать.

## Что построить

### 1. Зависимости — воспроизводимо
- Playwright и `@axe-core/playwright` — `devDependencies` КОРНЕВОГО `package.json` (версии закрепить),
  lockfile обновить. Браузеры: `npx playwright install chromium webkit` (в `REPRODUCE.md` это
  допишет координатор). НЕ брать Playwright соседнего проекта.
- Образы продукта не должны прибавить в весе заметно: проверь, что `Dockerfile` рантайма их не
  тащит (devDependencies только в build/test).

### 2. `scripts/check-responsive.mjs`
- Вход: `--base <origin>`, `--fixture <ui-fixture.json>` (формат — `scripts/seed-ui-fixture.mjs`),
  `--out <каталог>` (отчёт JSON + скриншоты-улики), `--engines chromium,webkit`, `--widths …`.
  Для `/c/{code}` код брать из фикстуры: доработай `seed-ui-fixture.mjs`, чтобы он создавал короткую
  ссылку одного клипа процедурой `link.create` и писал `short_code` (без повторной загрузки при
  продолжении — `prior.video_id` уже поддержан).
- Движки и устройства: WebKit — `devices['iPhone 13']` и `devices['iPhone SE']`; Chromium —
  `devices['Pixel 7']`; плюс ширины 320/360/390/414/768/1024/1440 (`isMobile`/`hasTouch` для ≤ 430).
- Маршруты: `/`, `/c/{code}`, `/g/{code}` без входа; `/dashboard` и экран записи — ПОСЛЕ входа формой
  (кнопка формы без `type`, селектор `form.auth-card button:not([type=button])`), проверить, что после
  входа НЕ произошло перенаправления на `/` (иначе «проверка не выполнена», код 2, а не зелёный).
- Правила (поправки Codex из раздела 7 исследования — обязательны):
  - **R1 (отказ):** `documentElement.scrollWidth > innerWidth` → нарушение; виновник — элементы за
    правым краем, КРОМЕ внутри контейнеров с `overflow-x: auto|scroll` (карусели).
  - **R2 (отказ):** основные цели (`button`, `a` вне абзаца, `[role=button]`, `summary`, `select`,
    `input` кроме hidden, И чекбокс/радио вместе с его `label`) < 44×44 → нарушение; прочие < 24×24 без
    зазора → нарушение. Кликабельная `label` засчитывается в область цели.
  - **R3 (предупреждение):** перекрытие целей — перед `elementFromPoint` прокручивать элемент в видимую
    область; элементы вне экрана не считать нарушением.
  - **R4 (отказ):** axe `wcag2a,wcag2aa,wcag21a,wcag21aa,wcag22aa` + ЯВНО включённое правило
    `target-size`; serious/critical → нарушение; moderate и `incomplete` — в отчёт, не отказ.
  - **R5 (отказ):** computed `font-size` < 16 px у текстовых `input` (text/email/password/url/search/
    tel/number) и `select`, `textarea`; viewport с `user-scalable=no` или `maximum-scale` < 2; `<video>`
    без `playsinline`. Чекбоксы/радио/hidden — не проверять.
  - **R6 (предупреждение):** превью видео не помещается в видимую область с учётом позиции
    (`rect.top >= 0 && rect.bottom <= innerHeight` после прокрутки к элементу) на 390×844 и 1440×900.
  - **R7 (предупреждение):** статический линт CSS (`globals.css` и inline-CSS SSR-страниц
    `guest-page.ts`, `short-link-handler.ts`): голый `100vh`; `clamp(` в px.
  - **R8 (отказ):** увеличение текста до 200 % (`document.documentElement.style.fontSize='200%'`) на
    390 px не создаёт горизонтального скролла на `/`, `/c/`, `/g/`.
- Выход: `0` чисто · `1` есть нарушения (маршрут, движок, ширина, правило, селектор, размер) ·
  `2` проверка НЕ выполнена (нет браузера, стенд не отвечает, фикстура отсутствует/непригодна,
  вход не удался). Отчёт `report.json` + `summary.md` в `--out`; скриншоты — улики, НЕ ассерт.

### 3. Страж обязан уметь падать
Тесты vitest `tests/responsive-check.test.ts` гоняют ФУНКЦИИ правил на локальных HTML-фикстурах
(`tests/fixtures/responsive/*.html`, отдача с `file://` или маленьким http-сервером на петле) — БЕЗ
стенда: чистая страница → 0 нарушений; для КАЖДОГО правила R1, R2, R4, R5, R8 — страница с внедрённым
дефектом → ровно это нарушение (широкий блок, кнопка 30×30, контраст 2:1, `input` 14 px, фиксированная
ширина 600px при 200 %). Плюс: нет браузера → код 2; фикстура без пароля → код 2. Тесты медиа
Playwright — если браузер не установлен, тест ГРОМКО «НЕ ВЫПОЛНЕН» (как у teaser-media), не молча.

### 4. Базовая линия
Запусти скрипт против `https://clipmkr.ru` с фикстурой, которую даст координатор (путь передаётся
аргументом; сам фикстуру не создавай — нужен ключ OpenRouter стенда). ЕСЛИ сети/стенда нет в
песочнице — запиши в отчёт «базовая линия НЕ снята, причина» (координатор снимет сам).

## ОБЯЗАТЕЛЬНЫЕ правки после VALIDATE (перекрывают текст выше)

Проверка плана (Anthropic): READY WITH FIXES, 2 блокера. Координатор проверил на машине: WebKit на
хосте НЕ запускается (нет libgtk-4 и др.), а в официальном образе `mcr.microsoft.com/playwright:v1.60.0-noble`
WebKit (iPhone 13) и Chromium (Pixel 7) открывают `https://clipmkr.ru` — ответ 200.

0. **Где запускается прибор — контейнер Playwright, не хост.** Версия `playwright` **ровно `1.60.0`**
   (без `^`), `@axe-core/playwright` тоже точной версией; обе — `devDependencies` корня. Команда
   `npm run test:responsive` / запуск `check-responsive.mjs` — внутри
   `docker run --rm -v "$PWD:/w" -w /w mcr.microsoft.com/playwright:v1.60.0-noble …` (браузеры и
   системные библиотеки уже в образе; `npm ci` внутри контейнера или смонтированные `node_modules`).
   Оформи это обёрткой `scripts/check-responsive.sh` (коды возврата прокидываются как есть). Хост и
   `apt` не трогать. Предполётная проверка: запустить оба движка и закрыть; неудача → код 2 с именем движка.
1. **[blocker] Браузерные тесты — ВНЕ основного набора.** Тестовый образ — `node:22-alpine` (musl),
   Playwright там не работает никогда, а `N5_ACCEPTANCE=1` превращает любой пропуск в отказ. Поэтому:
   каталог `tests/browser/**`, в `vitest.config.ts` `exclude: ['tests/browser/**', …существующее]`,
   отдельный `vitest.browser.config.ts` и `npm run test:responsive` (запуск в контейнере Playwright).
   В основном наборе — только то, что без браузера: линт R7, разбор аргументов и фикстуры (без пароля →
   код 2), «нет браузера → код 2» через подставной путь. Основной набор в образе обязан остаться
   зелёным и без пропусков.
2. **[blocker] R8 сначала доказывает рост текста.** Замер computed `font-size` выборки узлов (`body`,
   `h1`, `label`, `p`) до и после `html{font-size:200%}`; рост < 1,8× → нарушение «текст не
   масштабируется» (ОТКАЗ). Фикстуры: в `rem`, помещается при 100 % и переполняет при 200 %
   (`white-space:nowrap; width:22rem`); и в `px` — R8 обязан упасть по признаку «не растёт».
   (Ожидаемо базовая линия стенда даст R8-отказ: весь CSS в px — это и есть находка.)
3. **[high] Лимит частоты стенда.** Вход формой — ОДИН раз на движок, `waitForURL('**/dashboard')` с
   таймаутом, `storageState` переиспользуется во всех контекстах движка. Остались на `/` с `role=alert`
   или 429 → код 2 с причиной; повтор после 60 с не больше одного раза.
4. **[high] `link.create` — один раз.** В `seed-ui-fixture.mjs`: если в фикстуре есть `short_code` —
   не вызывать; иначе вызвать для первого клипа (вход `{clip_id}`, выход `result.data.data = {code,url}`)
   и сразу записать `short_code`; 404 → код 1 с причиной. Удалить ложное поле `screens.short_links`
   (оно всегда пустое). В отчёт: открытие `/c/` проверкой пишет `link_view` (не чаще раза в сутки на префикс).
5. **[high] Воспроизводимость:** см. п. 0 (контейнер вместо `--with-deps` на хосте).
6. **[medium] Вес образов:** `devDependencies` УЖЕ попадают в рантайм-образы (`npm ci` без
   `--omit=dev`); прибавку измерь (`docker image ls` до/после, если доступно; иначе оценка по
   `du` пакетов) и запиши. `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` — чтобы сборка образа не качала браузеры
   (Dockerfile тебе трогать нельзя — если нужно, назови это в отчёте, координатор внесёт).
7. **[medium] R2 геометрия:** ссылка — исключение «inline» WCAG 2.5.8, если её ближайший блочный предок
   `p`/`li` содержит текст вне ссылки; чекбокс/радио — объединение прямоугольников `input` и связанной
   `label` (обёртка или `for`/`id`); `label` вокруг текстового поля целью не считать; «без зазора» —
   окружность Ø 24 px с центром в цели пересекает соседнюю цель; невидимые и `disabled` — не проверять.
8. **[medium] axe:** `new AxeBuilder({ page }).withTags([...]).options({ rules: { 'target-size': { enabled: true } } })`
   (НЕ `.withRules` — он отключит теги). Тест-мутация: контраст 2:1 + кнопка 20×20 → ОБА нарушения.
   В `summary.md` дедуплицировать совпадения R2 и `target-size` по селектору.
9. **[medium] Предусловия маршрутов:** экран записи — ≥ 1 карточка клипа и `<video>`; `/g/` — ≥ 1 клип;
   иначе код 2 «фикстура непригодна». `input[type=file]` в R5 не проверяется — записать явно.
10. **[low]** Фикстуры правил отдавать http-сервером на `127.0.0.1`, не `file://`; `--out` по
    умолчанию в каталог вне git (добавь в `.gitignore`); пароль НИКОГДА не попадает в `report.json`/логи.
