Ревьюер: Sonnet 5 (OWN-017), независимо от исполнителя (Opus 5.5). Против `git diff -- .` +
новые файлы каталога `projects/05-podcast-clips-opus` (без `docs/telemetry`, без `projects/06`).
Прочитаны `00_brief.md` (раздел 27a), `01_validate.md` целиком, `07_code_report.md`.

## Вердикт: **APPROVE**

Все 12 правок `01_validate.md`, применимые к 27a (1, 7-исключён явно по постановке, 8, 9, 11, 12; №2-6,10
корректно отнесены к 27b), выполнены и подтверждены тестом или мутацией. Локально перепроверено: `npm run
typecheck --workspace=packages/shared` и `--workspace=apps/web` — чисто; `vitest run tests/clip-cta.test.ts
tests/enums.test.ts` — 58/58; `node tests/run-clip-cta-mutations.mjs` (9 не-интеграционных id) — все 9
`killed`, красное/зелёное совпадает построчно с квитанцией отчёта. Интеграционные (PostgreSQL) и
браузерные (R9/axe) мутации не перезапускались (нет стенда с БД/браузером в среде ревью) — доверие к ним
основано на согласованности кода с описанием, а не на повторном прогоне; отмечено ниже как единственный
непроверенный лично пункт.

## 1. Безопасность `/c/`

- **XSS.** `escapeHtml` применён и к `href`, и к тексту кнопки, и к видимому домену
  (`short-link-handler.ts` `actions()`). Тест `XSS: кавычки, угловые скобки и апостроф…` в
  `tests/clip-cta.test.ts` подтверждает: `"><script>` и `'onmouseover=` в query/hash не выходят из
  атрибута, `<script>` не появляется в HTML. Второй рубеж не нужен — сам `new URL().href` уже
  percent-encode'ит `"<>` во фрагменте, `escapeHtml` — defense-in-depth, как требует правило проекта.
- **Протокол — закрытый список.** `parseCtaUrl` пускает только `protocol === 'https:'`; `http:`,
  `javascript:`, `data:`, `ftp:` отвергаются (юнит-тест `it.each` в `clip-cta.test.ts`, мутация
  `protocol` killed). Пробелы/control-символы (`\s\x00-\x1f\x7f`) отклоняются ДО `new URL()`, что
  закрывает трюк «控制-символ внутри схемы, распарсенный в https после нормализации URL».
- **Хост / IDN.** `ctaDisplayHost` берёт `new URL(url).hostname` — punycode-форма для нелатинских
  доменов (`пример.рф` → `xn--e1afmkfd.xn--p1ai`, тест подтверждает), зритель не видит визуального
  двойника под красивым именем.
- **Открытый редирект.** `href` — прямой `cta.url`, никакого `/redirect?to=` на нашем домене; тест
  проверяет `html).not.toMatch(/redirect|[?&]to=/)`.
- **CSP.** Не менялась — тест сверяет строку заголовка дословно.
- **`rel`/`target`.** `rel="noopener noreferrer nofollow"` `target="_blank"` присутствуют у кнопки
  призыва.
- **Логин/пароль в адресе.** `url.username || url.password` отклоняется (мутация `credentials` killed).

## 2. Разбор адреса и порядок операций

- Набор `CTA_KIND` закрыт (`none|watch_full|subscribe|open_link`), неизвестный вид — отказ и в Zod
  (`video.setCta`, строгий `z.enum`), и в `parseCtaTarget` (`video.create`, где вид необязателен).
  Пустое/undefined для `none` — ок; для остальных видов — явный `422` с причиной, не молчаливый `none`.
- **Порядок в `video.create` соблюдён**: `parseCtaTarget` вызывается ДО `transaction(...)` (то есть до
  заявки `Idempotency-Key` и до `checkAndConsumeQuota`) — см. `apps/web/src/server/video.ts`, комментарий
  «Призыв разбирается ДО заявки ключа и квоты». Тест «непригодный адрес — 422 … ни одного обращения к
  БД» подтверждает это по факту (`connect` не вызван), а не только по расположению строк.
- Мутация `parse-before-claim` (пропуск разбора) killed.

## 3. `video.setCta`

- Владение проверяется по `v.account_id=$2` в одном `UPDATE`; чужая и несуществующая запись дают
  одинаковый `404` (нет утечки существования через разные коды). Мутация `owner` (интеграционная) в
  отчёте — killed; не перезапускалась мной локально (нет БД), но код читается однозначно: снятие
  `account_id=$2` — единственное условие владения в WHERE, а тест проверяет ИМЕННО за это.
- Нет пересборки, нет `checkAndConsumeQuota`, нет `job_attempt`/`render_version` — юнит-тест явно
  проверяет regex `not.toMatch(/updated_at|quota|job_attempt|render_version/)` по тексту SQL, а не
  только по побочному эффекту — сильная проверка.
- `updated_at` не обновляется — обоснованно и протестировано (юнит + интеграционный: `after.updated_at
  === before.updated_at`).

## 4. Миграция 020

- `cta_kind text NOT NULL DEFAULT 'none' CHECK (... IN (...))` — существующие строки получают `none`
  автоматически, обратная совместимость есть.
- `cta_url` CHECK разрешает `NULL` или `https://` + длина 9–2048 — второй рубеж на случай прямой записи
  в обход кода.
- Отдельный `CHECK ((cta_kind = 'none') = (cta_url IS NULL))` — пара согласована.
- `source_url` НЕ тронут — подтверждено и тестом (`sql.replace(/--.../).not.toContain('source_url')`).
- Все три CHECK проверены интеграционным тестом на настоящем PostgreSQL (в отчёте; не перезапускался
  локально).

## 5. Страж `tests/enums.test.ts` и список исключений

- Проверил список исключений (`attribution.reject_reason`, `clip.music_skip_reason`, `job_attempt.unit`,
  `job_attempt.wait_reason`, `partner_code.blocked_reason`) вручную по `grep CHECK.*IN` во всех
  миграциях — список ТОЧНО совпадает с перечислениями вне `SQL_ENUMS`, ни одного пропуска не нашёл.
  Страж не прячет реальные пробелы — он бы упал, если бы в списке исключений было что-то новое или
  что-то из него было убрано без причины (мутация `sql-enums-entry` подтверждает: убрать запись
  `video.cta_kind` → страж падает).
- Регэксп стража берёт последнее (`.at(-1)`) определение CHECK на таблицу/колонку — корректно для
  колонок, чей CHECK потом заменяется `ALTER ... DROP/ADD CONSTRAINT` (attribution.status,
  quota_counter.scope), поведение не новое в этой фиче, но подтверждено, что новая запись не сломала
  существующую логику (лично прогнал `enums.test.ts` — зелёный).

## 6. Форма `CtaFields`

- `<label htmlFor>` для select и input — доступные подписи. Ошибки — `role="alert"`, статус —
  `role="status"`.
- Touch-таргеты 44px и шрифт 16px не заданы локально в `CtaFields`/`.cta-fields`, а наследуются от
  глобальных правил `globals.css` (`input,select,textarea{font-size:max(1rem,16px)}`,
  `select{min-height:2.75rem}`, `input:not([type=checkbox])...{min-height:2.875rem}`) — то есть авторы
  сознательно не дублируют геометрию, а полагаются на уже существующий контракт мобильной вёрстки. Новые
  токены (`.cta-panel`, `.secondary-link`) используют только переменные (`--surface`,`--line`,`--space-*`)
  — согласовано для обеих тем; браузерный тест на контраст (R1/R2/R5 + axe) добавлен для обеих тем и
  фикстур.
