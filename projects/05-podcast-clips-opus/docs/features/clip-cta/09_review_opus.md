## Заявления квитанции, не подтверждённые кодом

- «Конкурентные на PostgreSQL: setCta ↔ setMusic ровно одно действие ×5, два setCta — один 409 ×3, остаток 4 → 429
  целиком» (`07b_code_report.md:198`) — тесты в дереве есть, прогон на БД в ревью не выполнялся. По коду обе
  процедуры берут `video … FOR UPDATE OF v` первой (`video-cta.ts:31-33`, `clip-music.ts:17-19`), попытки вставляются
  сразу `running` (`packages/db/src/attempts.ts:31-33`), поэтому второй `setCta` видит их в проверке занятости —
  рассуждение совпадает с заявлением.
- «Медиатест пикселей: надпись не задевает субтитры» — медиатест не рисует субтитры одновременно с надписью
  (исполнитель это сам записал), высота субтитров взята из стиля ASS, не измерена.
- «Мутации 27a check-pair/check-url/owner» не перезапускались после 27b (записано исполнителем).
- Подтверждено чтением: адрес в пиксели и в воркер не идёт (`render.ts` SELECT без `cta_url`), `/c/` — прямая
  внешняя ссылка без редиректа через наш домен, `escapeHtml` на адресе и домене, CHECK миграции + `readStoredCta`
  fail-closed при чтении, разбор адреса ДО заявки `Idempotency-Key`, `409` до квоты, квота одним вызовом на N,
  отказ квоты откатывает и призыв.

## Что сделано хорошо

- Текст призыва — только из закрытого словаря, свободного текста автора нет ни на странице, ни в пикселях.
- Три рубежа для адреса: разбор при вводе, CHECK в базе, fail-closed при показе.
- Смена только адреса не трогает пиксели и квоту; смена вида — одна транзакция, `409`/`429` целиком.
- Сервер по адресу никуда не ходит — SSRF-поверхности нет.

GRADE: B
