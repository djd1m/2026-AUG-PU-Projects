# Постановка для Codex — фича 22 `clip-music-choice`: выбор и смена музыки у готового клипа

Готовы фичи 1–21, **743 теста** в образе. Решения владельца — OWN-015 в `docs/decisions-owner.md`.
Каталог — 9 треков (`apps/worker/src/render/music.ts`, OWN-013/014). Тир L: миграция, новая
процедура, новый ключ квоты, web + worker.

## Что построить

### 1. Общий каталог
- `packages/shared/src/music-catalog.ts`: закрытый список `{ id, title, author }` для 9 треков в
  порядке `MUSIC_TRACKS`. `MUSIC_TRACKS` в worker строится по нему (sha256 и путь остаются в worker);
  тест: множества id совпадают, порядок совпадает.
- Выбор пользователя: `'auto' | 'none' | <id из каталога>`. Неопознанное → 422.

### 2. Миграция `018_clip_music.sql`
- `clip.music_track_id text` — `NULL` = авто (по номеру клипа, как сейчас), `'none'` = без музыки,
  иначе id трека; `CHECK (music_track_id IS NULL OR char_length(music_track_id) BETWEEN 1 AND 64)`.
- `clip.render_version integer NOT NULL DEFAULT 1 CHECK (render_version >= 1)`.
- `quota_counter.scope` — **7** значений: добавить `user_rerenders` (CHECK пересоздать по образцу
  016: DROP/ADD с тем же именем `quota_counter_scope_check`, без `IF EXISTS`).

### 3. Квота
- `QUOTA_SCOPE` — 7; `QuotaReason` += `'rerender'` → `['user_rerenders']` (глобального нет).
- `N5_LIMIT_USER_RERENDERS` — обязательная (fail-closed на старте `web`, сообщение называет
  переменную и последствие «смена музыки останется без потолка перерендеров»); `docker-compose.yml`
  (`${N5_LIMIT_USER_RERENDERS:?…}` — только сервису `web`), `.env.example` (`=20`),
  `scripts/check-env-complete.sh`, страж проброса переменных.

### 4. Процедура `clip.setMusic` (16-я)
Вход `{ clip_id: uuid, track: 'auto' | 'none' | <id> }`, `.strict()`. Одна транзакция:
1. клип владельца сессии (чужой/несуществующий → **404**, как везде), запись не удалена, аккаунт активен;
   `FOR UPDATE` строки клипа;
2. клип обязан быть `done`, и у клипа нет активной попытки рендера (`job_attempt` `running|deferred`)
   → иначе **409** «Клип ещё собирается»;
3. выбор равен текущему (`auto` ≡ `NULL`) → **409** «Уже выбран этот трек», квота НЕ списывается;
4. `checkAndConsumeQuota(tx, …, 'rerender', 1)` → отказ → **429** тем же путём, что прочие отказы по
   потолкам (`quotaError`);
5. `UPDATE clip SET music_track_id=$, render_version=render_version+1`; новая серия попыток
   `leaseAttemptTx(tx, video, 'render', series, clip)`; **`clip.status` остаётся `done` и старый
   `object_key` остаётся действующим** до публикации нового файла; `video.status` не меняется.
После коммита — постановка задания в очередь (как `video.retry`; сбой публикации восстанавливает
сторож). Проверь, что сторож и экран прогресса не переводят запись в «обработку» из-за этой
попытки при `video.status='done'`.

### 5. Рендер
- `getRenderInput` отдаёт `c.music_track_id`, `c.render_version`.
- Трек: `'none'` → без музыки и без пэк-шота; id → этот трек, **даже если `video.music=false`**
  (выбор пользователя включает музыку и пэк-шот для этого клипа); `NULL` → прежнее поведение
  (`video.music` + `selectTrack(index−1)`).
- Ключи объектов: при `render_version = 1` — ПРЕЖНИЕ (`…/{clip}.mp4`, эталоны не меняются); при
  `> 1` — `…/{clip}-v{render_version}.mp4` и `thumbs/…/{clip}-v{N}.jpg` (контракт другой → старый
  ключ дал бы S3 `412`). `publishRenderResult` пишет новый `object_key`/`thumbnail_key`; ПОСЛЕ
  успешной публикации — удаление объектов предыдущей версии (best-effort, ошибка → журнал
  `rerender_cleanup_failed`, не отказ).
- Уплотнение (`cut_plan`) и заголовок — прежние; `cut_plan` не пересчитывается.

### 6. Интерфейс
- `ClipCard.tsx`: выпадающий список «Музыка: Авто · <9 треков> · Без музыки», текущее значение из
  `clip.music_track_id`; у каждого трека кнопка ▶ — `<audio>` с `/music-previews/<id>.mp3`.
  Пока у клипа активная попытка рендера — «Пересобираем…», список заблокирован; после — новый файл
  (screen/clip.list отдают признак активной пересборки).
- Отказы — текстом из сервера (409/429), без `dangerouslySetInnerHTML`.
- Превью: `scripts/build-music-previews.mjs` делает из `apps/worker/assets/music/*.mp3` фрагменты
  20 с с 30-й секунды (`loudnorm=I=-18:TP=-2`, `afade` 0,5/1 с, mp3 128k) в
  `apps/web/public/music-previews/<id>.mp3`; файлы закоммитить. Тест: у каждого id каталога есть
  превью. Проверь CSP (`media-src`/`default-src`) — превью с того же origin должно проигрываться.

## ОБЯЗАТЕЛЬНЫЕ правки после VALIDATE (перекрывают текст выше)

Проверка плана (Anthropic): **NOT READY** — весь механизм рендера привязан к `status='rendering'`
клипа и записи, а пересборка обязана оставить клип `done`. Пункты 1–4 — блокеры.

1. **[blocker] Режим пересборки у `leaseAttemptTx`** (`packages/db/src/attempts.ts:24-26`): отдельный
   вариант (параметр/функция), который принимает клип ТОЛЬКО в `done`, выставляет `render_fence` и НЕ
   трогает `clip.status`/`failure_reason`. Серия — `max(series_no)+1` по всей записи (как
   `video-retry.ts:37`). Признак пересборки — поле попытки (например `job_attempt.rerender boolean`
   в миграции 018) — по нему, а не по статусу записи, ветвятся шаги ниже.
2. **[blocker] Блокировка и публикация** (`packages/db/src/render.ts` `lockRender`,
   `publishRenderResult`, `getRenderInput`, `setRenderDeferred`, `saveCutPlan`, `saveLoudnessMedian`,
   `retryRender`): для попытки пересборки предикат — клип `done`, `c.render_fence = fence`, попытка
   `running|deferred`, запись неудалена и аккаунт активен (статус записи НЕ важен). Публикация —
   `done → done` при совпадении fence, пишет новые ключи и `rendered_music_track_id` (п. 3).
3. **[blocker] Отказ пересборки не портит клип.** Миграция 018 добавляет
   `clip.rendered_music_track_id text` (что ОТРИСОВАНО; при публикации обычного рендера — то, что
   фактически смешано: id трека или `'none'`). После исчерпания двух попыток пересборки клип остаётся
   `done` со СТАРЫМИ ключами, `music_track_id` откатывается к `rendered_music_track_id`-эквиваленту
   (или хранится отдельно — главное: сравнение «тот же трек» ведётся с ОТРИСОВАННЫМ). Квота при отказе
   НЕ возвращается (решение координатора, записано). `updateRenderProgress` для пересборки не
   вызывается. Тест: обе попытки упали → клип `done`, отдаётся старый файл, запись `done`, повтор того
   же выбора разрешён.
4. **[blocker] Сторож** (`apps/web/src/server/watchdog.ts`): отдельная ветка для попыток пересборки у
   клипов `done` с совпадающим `render_fence` — повторная постановка потерянного задания и закрытие
   зависшей по `STALLED_AFTER_MS` (клип остаётся `done`, запись не трогается). Тесты на оба случая.
5. **[high] Переменная `N5_LIMIT_USER_RERENDERS` — вариант (а):** добавить в `x-quota-env` (web,
   worker-stt, worker-llm, test), `apps/worker/src/quota-environment.ts`,
   `apps/web/src/server/environment.ts`, `.env.example`, `check-env-complete.sh`. Тест: без неё не
   стартует ни один из процессов, читающих `LIMIT_NAMES`, и сообщение называет её.
6. **[high] Срок хранения не продлевается:** публикация пересборки не трогает `video.finished_at`,
   `clips_done`, `status`. Тест: `finished_at` неизменен.
7. **[high] Истёкший клип:** `setMusic` требует `object_key IS NOT NULL` и не истёкший срок (то же
   условие, что `screen.ts:66-67`) → иначе 409 без списания квоты. Тест.
8. **[high] Сироты версий:** старые ключи для удаления читаются ИЗ БАЗЫ в той же транзакции публикации
   (не вычисляются как `v{N-1}`: тариф мог смениться), удаляются после коммита. `retention.ts`
   удаляет объекты клипа по ПРЕФИКСУ `clips/{free,paid}/{video}/{clip}` и `thumbs/{video}/{clip}`.
   `RenderStorage` получает `delete`.
9. **[medium] `setMusic` требует `video.status='done'`** (иначе 409): пересборка не пересекается с
   `video.retry` и пересчётом прогресса.
10. **[medium] Канон** (§4 «ровно 6» ключей квоты, §5 «ровно 15» процедур, §7 каталог треков) правит
    КООРДИНАТОР отдельно — тебе `docs/` не трогать.
11. **[medium] Эквивалентность и опрос:** (а) сравнивать РЕЗУЛЬТАТ, а не поле: при `video.music=false`
    «Авто» ≡ «Без музыки» → 409 без списания; (б) экран отдаёт признак активной пересборки клипа, и
    страница опрашивает сервер, пока он есть (как `poll_after_seconds`), чтобы «Пересобираем…»
    сменилось новым файлом без перезагрузки.
12. **[low]** Неизвестный воркеру `music_track_id` → самое строгое: без музыки, событие
    `music_track_unknown`, без исключения. Удаление старого объекта ломает уже выданные подписанные
    ссылки владельца до их истечения (≤ 900 с) — принято, записать в отчёт.

Дополнительные тесты: п. 2 (`lockRender` принимает пересборку и отвергает чужой fence), 3, 4, 5, 6, 7.
