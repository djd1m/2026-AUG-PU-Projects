### Что исправлено

1. Retention вызывает отдельный `eraseClipPrefix`: только `clips/free|clips/paid|thumbs/{uuid}/{uuid}`, без завершающего `/`. Каталожный `erasePrefix` сохранён для стирания аккаунта. Тест проходит через retention и настоящий S3-валидатор, подменяя только транспорт; проверяет все версии и соседний UUID в той же записи.
2. `setRenderDeferred` обновляет `job_attempt.started_at` как отметку жизни; воркер вызывает его до скачивания, после скачивания и при отложенном запуске. Сторож использует эту обновляемую отметку. Добавлен SQL-сценарий «25 минут ожидания → старт → 10 минут работы», включая deferred.
3. При отклонении публикации удаляются версионные объекты отклонённого результата. Под блокировками video → clip отбираются только ключи, которые не приняты и не могут быть приняты активным повтором той же версии; S3-удаление выполняется после транзакции. Дубликат уже принятого результата, активный retry той же версии и v1 защищены. Ошибки удаления журналируются.
4. Новая миграция `019_music_skip_reason.sql` сохраняет причину пропуска музыки; миграции 001–018 не менялись в этом проходе. Причина проходит prepareMusic → renderClip → worker → fenced UPDATE. UI показывает отрисованный трек и предупреждение, `setMusic` отклоняет известный пропущенный выбор/его auto-эквивалент до квоты. Ошибка измерения имеет отдельный пользовательский текст.
5. `clip.list` отдаёт `rerender_failure` актуального fence. После окончательного отказа карточка сообщает об ошибке и сохранённом предыдущем файле; активный retry не показывает прежний отказ.
6. `published_render_version` выводится из опубликованного object_key; video key/src/poster используют её. Изменение заказанной версии или rerendering не перезапускает старый проигрыватель, успешная публикация обновляет его.
7. Проверка env переведена на POSIX `sh`, регулярное выражение пробелов тоже переносимо; тест запускает `sh`. Успешная проверка полного env и отказ с именем отсутствующего `N5_LIMIT_USER_RERENDERS` сохранены.
