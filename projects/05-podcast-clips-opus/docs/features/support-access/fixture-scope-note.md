# AC11: коррекция штатного fake-provider для сквозной UI-фикстуры

Контекст28.10.2026: настоящий локальный upload/SQL/Redis/S3 pipeline завершил
200-секундную синтетическую запись с `no_fragments`. Production-валидатор сработал
правильно: существующий fake STT вернул одно слово на первой секунде, а fake selector
предложил25-секундные фрагменты. После привязки границ к словам материал слишком короток.

Узкое уточнение реализации AC11: только явно выбранный fake STT должен создавать
детерминированные синтетические слова/сегменты в пределах измеренной длительности,
совместимые с существующим valid fake selector. Нужны проверка совместимости через
настоящий валидатор фрагментов, короткая запись и отмена запроса.

Реальные OpenRouter/Yandex ветки, их таймкоды, ограничения, учёт, parser и word-snapping
сохраняются. Production запрет fake и явная provider-attribution сохраняются.
Это тестовые данные, не распознанная речь и не доказательство качества STT.
Новый backend, движок, внешний провайдер или публичная настройка не добавляются.

Файлы до правки назначены backend-кодеру: `apps/worker/src/stt/client.ts` (fake-ветка)
и `tests/support-fake-pipeline.test.ts`. Основная спецификация и HTTP/SSR канон неизменны.
