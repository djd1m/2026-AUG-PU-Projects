# Постановка FR-1 — двойной кадр вместо центральной обрезки

**Находка владельца на живых клипах 23.09.2026:** «у нас в нарезке аудиоряд вовлекающий, а видеоряд
„ни о чём“, в некоторых случаях просто „стена“: сидят 2 человека, а показан не кто-то один из них и
не оба издалека, а пространство посередине».

## Причина, и она в одной строке

`apps/worker/src/render/format.ts` — `getScaleFilter`:

```
scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920,setsar=1
```

`crop` без координат — **центральный** вырез. Для записи 1920×1080 кадр растягивается до высоты
1920 (ширина становится 3413), и берётся 1080 посередине. В координатах исходника это полоса
примерно **с 607-го по 1313-й пиксель из 1920** — видна центральная **треть**, две трети
выброшены. Двое по краям кадра не попадают в неё ОБА, и зритель видит стену между ними.

Это не сбой реализации: способ кадрирования ничего не знает о содержимом и знать не может.

## Решение владельца

Выбран **двойной кадр**: оба участника, один над другим. Сознательно выбран не за красоту, а за
надёжность — «стены» он не даёт никогда и распознавания не требует.

Следующий шаг (НЕ сейчас, но заложи возможность): владелец подтвердил, что **у участников отдельные
микрофоны, разведённые по каналам**. Значит следование выреза за говорящим потом обойдётся почти
даром — громкость канала прямо называет говорящего, без разметки голосов и без видеокарты. Не
реализуй это, но не мешай этому: геометрия панелей должна вычисляться функцией, которой можно будет
передать другое положение окна.

## Что построить

### Геометрия

Панелей две, каждая **1080×960** (итог 1080×1920). Отношение сторон панели 1,125.

**Размеры окна вычисляются из ФАКТИЧЕСКИХ размеров исходника, а не зашиваются.** Записи бывают
разные, и зашитые числа — ровно тот класс, который сегодня стоил нам пяти отказов подряд:

```
windowW = floor(srcW / 2)
windowH = round(windowW / 1.125)
если windowH > srcH:  windowH = srcH;  windowW = round(srcH * 1.125)
```

Для 1920×1080 это даёт окно **960×853** на каждого — то есть половина ширины кадра вместо нынешней
трети, и почти вся высота.

Левое окно берётся из левой половины, правое из правой. По вертикали — **со смещением вверх**:
лица обычно в верхней части кадра, и центрирование срезает макушки. Величину смещения назови числом
и обоснуй; если считаешь, что центрирование лучше — скажи почему.

Ширина и высота обязаны быть **чётными**: `yuv420p` нечётных не принимает.

### Когда двойной кадр НЕ применяется

Набор закрытый, и каждое условие обоснуй строкой в отчёте:

- исходник уже вертикальный либо квадратный — обрезать нечего, двойной кадр бессмыслен;
- ширины не хватает: `floor(srcW/2)` даёт окно уже 480 px — панели выйдут мыльными.

В этих случаях остаётся нынешнее поведение. **Сделай выбор ЯВНЫМ и проверяемым**: функция, которая
по размерам исходника возвращает способ кадрирования, и тест на каждую ветку.

### Порядок фильтров

Нынешняя цепочка — строка, склеенная запятыми. Двойной кадр требует графа с метками:

```
[0:v]split=2[l][r];
[l]crop=W:H:0:Y,scale=1080:960[top];
[r]crop=W:H:X:Y,scale=1080:960[bot];
[top][bot]vstack=inputs=2[v]
```

Субтитры и метка накладываются **после** сборки, на готовый кадр 1080×1920, и метка остаётся
ПОСЛЕДНЕЙ — это условие канона и оно не ослабляется.

Проверь, что ASS-субтитры с `PlayResX/Y` 1080×1920 ложатся правильно на собранный кадр.

## Тесты

| Страж | Внедряемый дефект |
|---|---|
| для 1920×1080 выбирается двойной кадр, окна 960×853 | вернуть центральную обрезку → красный |
| вертикальный исходник двойного кадра НЕ получает | применить его → красный |
| узкий исходник (окно < 480) двойного кадра не получает | применить → красный |
| метка рисуется ПОСЛЕ сборки и последней | переставить → красный |
| размеры окон чётные при любом нечётном исходнике | вернуть нечётные → ffmpeg падает, тест красный |

**Настоящим ffmpeg:** собрать двухпанельный клип из синтетического исходника, где левая половина
залита одним цветом, правая другим, и проверить ПИКСЕЛЯМИ, что верхняя панель несёт первый цвет, а
нижняя второй. Это единственное доказательство, что панели не перепутаны и не взяты обе из одной
половины.

Мутации обеими строками.

## Границы

реализовывать — это следующий шаг и отдельное решение. `docs/` — свой отчёт и `docs/canon.md` §7,
если способ кадрирования требует записи в канон (скорее всего требует: там сказано «центральный
вырез»).
