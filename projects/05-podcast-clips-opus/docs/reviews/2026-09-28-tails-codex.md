**1. Безопасность `npm prune`.** В текущих манифестах причины поломки рантайма не обнаружены. Workspace-пакеты объявлены production-зависимостями; их манифесты присутствуют при очистке, а `packages` вместе с собранными файлами копируются позднее. Отсутствие исходников и `dist` на стадии очистки само по себе не делает эти зависимости лишними.

`bcrypt` — production-зависимость; стадии используют одинаковую базу Node/Alpine. SWC объявлен optional-зависимостью Next, React и React DOM — прямыми production-зависимостями приложения. `--omit=dev` не означает исключение всех optional/peer-зависимостей. [Документация npm](https://docs.npmjs.com/cli-commands/prune.html/).

`next.config.ts` **не копируется в текущую цель `web`**, поэтому конкретно его загрузка не требует там TypeScript. Это существующая особенность Dockerfile, а не результат очистки. `@types/*` рантайму не нужны. Миграция из `REPRODUCE.md` запускает готовый `packages/db/dist/migrate.js`; dev-зависимостей в этом пути не нашёл. Однако `npm run db:migrate` из корневого манифеста сначала вызывает `tsc` и в очищенном образе работать не будет — документированный способ запуска другой.

**2. Полнота стражей.** Недостаточна для общей гарантии отсутствия devDependencies, хотя исходную регрессию «копировать `node_modules` из `build`» они покрывают. Замена очистки на один `npm ci` обнаруживается; добавление `npm ci` **после** очистки — нет. Разбор физических строк недостаточен для инструкций с `\`.

Пропуск `devOptional` сам по себе ошибкой не считаю: пакет может одновременно требоваться production optional-ветке. В текущем lockfile таких записей нет. [Описание флагов lockfile](https://docs.npmjs.com/cli/v11/configuring-npm/package-lock-json/).

Положительный контроль проверяет лишь непустоту: виртуальный образ с одним `next` из 74 ожидаемых prod-пакетов получает код 0. Это не проверка работоспособности образа; для неё нужны отдельные smoke-проверки.

**3. Витрина.** Ограничение 120/мин действительно применяется к маршруту выдачи подписи, не к скачиваниям S3. Код задаёт срок 900 секунд; повторное использование соответствует семантике подписанных URL. [Документация S3](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html).

Фраза «нет `Cache-Control`» требует уточнения: у ответа **302 есть** `private, no-store`; отсутствие заголовка у самого объекта — утверждение о стенде, из кода оно не следует.

Вывод «без нового объекта безопасной правки нет» слишком категоричен, если задача — уменьшить **повторный** трафик. Возможен вариант только в коде: кратковременно переиспользовать подпись по текущему ключу объекта после каждой проверки доступа и добавить ограниченный `ResponseCacheControl`, согласованный с оставшимся сроком подписи. S3 поддерживает такое переопределение без изменения объекта. [GetObject](https://docs.aws.amazon.com/AmazonS3/latest/API/API_GetObject.html). Совместимость хранилища и браузерную экономию нужно проверить. Этот вариант не уменьшает первые 23 МБ и не защищает от массового скачивания. Для уменьшения размера первого просмотра облегчённый ассет остаётся обоснованным решением.
