## ADR-001 · Очередь заданий — BullMQ на Redis из клона, с фенсом попыток

**Контекст.** Конвейер «STT → выделение → рендер» состоит из заданий длительностью минуты. В
январском клоне очередь BullMQ на Redis 7 с четырьмя воркерами уже написана и отлажена (27
записанных граблей). Соседний проект N4 держал очередь в PostgreSQL (`FOR UPDATE SKIP LOCKED` +
аренда с fence), но там задания длились секунды и кода не было. Второе мнение (gpt-6-astra,
квитанция `receipts/codex-astra-second-opinion.md`): длительность заданий сама по себе Postgres не
дисквалифицирует; честный аргумент — наличие кода; но пароля и закрытых портов недостаточно.

**Решение (OWN-003).** BullMQ на Redis 7 в compose. Условия, без которых решение не действует:
1. Redis: AOF на томе, `maxmemory-policy noeviction`, пароль из `${REDIS_PASSWORD:?…}`, без `ports:`.
   Документация BullMQ: «it is very important to configure the maxmemory-policy setting to
   noeviction»; «We recommend enabling AOF».
2. Воркеры на ioredis с `maxRetriesPerRequest: null` (требование BullMQ для Worker).
3. `removeOnComplete` / `removeOnFail` с числовым потолком хранимых заданий.
4. Источник истины о задаче — PostgreSQL (`video.status`, `job_attempt`), Redis — только транспорт.
   Постановка в очередь выполняется ПОСЛЕ фиксации строки `video`; сторожевой цикл раз в минуту
   находит `queued`-строки без активного задания и ставит их заново.
5. Фенс попыток: каждая попытка стадии — строка `job_attempt` с монотонным `fence`; воркер пишет
   результат `UPDATE … WHERE fence = :mine`; ноль затронутых строк = попытка устарела, результат
   отброшен, в аудит — `stale_attempt_result`. Причина: BullMQ возвращает «зависшее» задание в
   очередь («that job is moved back to the waiting list»), и без фенса старая попытка дописала бы
   результат поверх новой.
6. ffmpeg запускается дочерним процессом с таймаутом 15 мин и `SIGKILL`; рендер не блокирует event
   loop воркера (иначе задание объявляется stalled через 30 с по умолчанию BullMQ).
7. Не больше 2 АВТОМАТИЧЕСКИХ попыток на стадию внутри одной серии (`job_attempt.series_no`); после
   второй — стадия `failed` с причиной. Что становится с ВИДЕО, зависит от стадии, и разница
   существенна (V2-R23, вторая половина): отказ на `stt` или `select` — `video.status = failed`
   (клипов нет вовсе); отказ рендера ОТДЕЛЬНОГО клипа — `clip.status = failed`, а видео остаётся
   `done`, если готов хотя бы один клип (FR-RENDER-003, `RenderClip` шаг 11, диаграмма состояний
   `rendering --> done : хотя бы один клип готов`). Видео становится `failed` по рендеру только
   когда провалились ВСЕ клипы. Повтор по кнопке «повторить» открывает новую
   серию с тем же потолком и ограничен суточными потолками минут и вызовов (FR-RENDER-003,
   `RetryVideo`; V2-R23). Уникальность попыток — `UNIQUE (video_id, fence)`, не по `attempt_no` (V2-R02).

**Последствия.** Один лишний контейнер и один секрет; протокол долгой задачи
(`long-job-contract.md`) исполняется поверх BullMQ: `video_id` выдаётся до постановки в очередь.
Повторное исполнение зависшего задания не может испортить результат: оно либо продолжает с
актуальным фенсом, либо отбрасывается.

**Альтернативы.** Очередь в PostgreSQL как в N4 — отвергнута на неделю: переписывание рабочей
очереди ради одного контейнера меньше; остаётся кандидатом, если Redis на VPS окажется лишним ртом
по памяти (замер в первой фиче).

**Confirmation.** (а) Интеграционный тест: две попытки одного `render` с фенсами 1 и 2; попытка 1
пишет результат ПОСЛЕ попытки 2 — её `UPDATE` затрагивает 0 строк, результат попытки 2 не тронут,
в аудите `stale_attempt_result`. Внедряемый дефект: убрать `WHERE fence = :mine` → тест красный.
(б) Страж по compose: `docker compose config` содержит у `redis` `command` с `--appendonly yes` и
`--maxmemory-policy noeviction`, `requirepass` из переменной с `:?`, и НЕ содержит `ports:`.
Внедряемый дефект: опубликовать `6379:6379` → `check-ports.cjs` код 1.

## ADR-002 · Файлы — Cloud.ru Object Storage в боевом профиле, MinIO только в тестах

**Контекст.** Постановка §05 говорила «файлы — том Docker, не внешнее хранилище». Клон несёт
S3-код в 21 файле (пакет `@clipmaker/s3`: клиент, presign, multipart, операции; загрузчик в
браузере; воркеры; отдача клипов) и был настроен на `https://s3.cloud.ru`, регион `ru-central-1`.
На VPS свободно 18 ГБ из 158. Второе мнение (gpt-6-astra, раунд 2): согласен с Cloud.ru на неделю,
но условий координатора недостаточно; предложенный «том + холодный архив» сам отверг.

**Решение (OWN-004).** Боевой профиль — Cloud.ru Object Storage (S3, SigV4, регион `ru-central-1`);
тестовый профиль compose — MinIO без публикации портов, тот же код через `S3_ENDPOINT`. Условия:
1. Бакет приватный; ключи `S3_ACCESS_KEY/S3_SECRET_KEY` только у `web` (подпись ссылок для
   браузера), `worker-stt`, `worker-video`; у `proxy`, `db`, `worker-llm` — нет.
2. Числовые лимиты ДО выдачи подписанной ссылки: `user_uploads` 2/сутки, размер ≤ 2 000 000 000
   байт; multipart завершает СЕРВЕР (`POST /api/upload/complete`) с проверкой суммарного размера
   частей и типа по байтам; длительность измеряет `worker-stt` (`ffprobe` после скачивания) ДО
   списания минут и ДО Whisper (DEC-A-011). Подпись сама размера не ограничивает.
3. Срок подписанной ссылки ≤ 15 мин (Cloud.ru допускает до 604800 с; берём минимум достаточный).
   Подписи не попадают в логи; ключи объектов только серверные с проверкой владельца.
4. Lifecycle на бакете: `AbortIncompleteMultipartUpload` (`DaysAfterInitiation: 1`) — Cloud.ru
   тарифицирует хранение незавершённых частей; `Expiration` для клипов free — 3 дня после `done`
   исполняет приложение; объекты free и paid лежат под РАЗНЫМИ префиксами `clips/free/` и
   `clips/paid/`, и страховочное правило lifecycle на 7 дней навешивается только на `clips/free/`
   (V2-R24). `Transition`
   не используется: у Cloud.ru «не поддерживается в текущей версии».
5. CORS на бакете под публичный origin приложения (`PUT`, `POST`, `GET`, `HEAD`; заголовки
   `content-type`, `x-amz-*`; `ETag` в `ExposeHeaders`).
6. Воркер скачивает оригинал во временный каталог тома ОДИН раз (`s3-download.ts`), рабочая область
   резервируется до скачивания (≥ 3× размера оригинала) и очищается после успеха И после отказа.
7. Совместимость Cloud.ru (SigV4 с ключом `<tenant_id>:<key_id>`, multipart complete/abort, Range
   GET, CORS preflight) подтверждается ручной приёмкой на РАЗВЁРНУТОМ стенде по выданному адресу;
   тесты в MinIO совместимость Cloud.ru не доказывают.

**Последствия.** Диск VPS не накапливает оригиналы и клипы; трафик наружу в пределах льготы
(Cloud.ru: «не тарифицируются первые 10 ТБ исходящего трафика» в месяц); появляется счёт, который
крутят посетители — он связан лимитами п. 2 и `FR-LIMIT-*`. Строка постановки пересмотрена
владельцем (запись в `start/REPLICATE-PROMPTS-PROJECTS.md`).

**Альтернативы.** MinIO в проде — те же грабли подписей и CORS плюс двойной диск на VPS; том без S3 —
переделка 21 файла (оценка: два дня из семи). Обе записаны в квитанциях второго мнения.

**Confirmation.** (а) Страж по compose: сервис `minio` присутствует ТОЛЬКО под `profiles: [test]`,
у него нет `ports:`; боевой `web` получает `S3_ENDPOINT` из `${S3_ENDPOINT:?…}` без дефолта на
MinIO. Внедряемый дефект: дефолт `http://minio:9000` → страж красный. (б) Тест: `video.create` при
`user_uploads = 2` за сутки возвращает `refused(user_uploads)` и НЕ выдаёт ссылок; `upload/complete`
с суммой частей > 2 000 000 000 байт → `422`, объект удаляется, минуты не списаны.

## ADR-003 · STT — `whisper-1` с таймкодами слов; интерфейс поставщика не закрывает диаризацию

**Контекст.** Без таймкодов нарезка невозможна в принципе (постановка). Документация OpenAI: «Use
whisper-1 when you need word or segment timestamps»; «The timestamp_granularities[] parameter is
only supported for whisper-1». `gpt-4o-transcribe-diarize` отдаёт сегменты со спикером, но не
слова; в CJM D диаризации нет, в полном B она нужна.

**Решение.** `whisper-1`, `response_format=verbose_json`, `timestamp_granularities=[word,segment]`.
Поставщик STT скрыт за интерфейсом `Transcriber` с двумя реализациями: живой клиент и
детерминированный фейк для тестов; контракт результата — слова с `start/end`, сегменты, язык;
поле `speaker` — необязательное, чтобы diarize-модель подключалась без смены контракта.
Файлы длиннее лимита («Files can be up to 25 MB») режутся на аудиочанки по тишине, не посреди
фразы («Avoid splitting in the middle of a sentence»), таймкоды чанков сдвигаются на смещение.

**Последствия.** Цена 0,006 $/мин (страница тарифов OpenAI, 2026-09-21) → 600 мин/сутки ≈ 3,6 $.
Субтитры и границы клипов режутся по словам, а не по сегментам. Переход на diarize — смена
реализации, не контракта.

**Альтернативы.** `gpt-4o-transcribe` — нет таймкодов, отвергнута; `diarize` — нет таймкодов слов,
отложена до полного B.

**Confirmation.** Юнит-тест контракта: результат `Transcriber` без `words[].start/end` отвергается
до постановки в очередь выделения (`failed(no_timestamps)`); внедряемый дефект: принять результат
без таймкодов → тест красный. Страж по исходнику: строка `timestamp_granularities` присутствует
в живом клиенте ровно один раз.

## ADR-004 · Метка — часть тарифной архитектуры, несёт короткую ссылку с кодом клипа

**Контекст.** Метка на free — основная петля роста (FR-GROWTH-003) и решение, подтверждённое у
источника (тарифная страница: «Has watermark» / «Remove Watermark»). Метка без адреса — показ без
измерения: метрика недели считается по переходам.

**Решение.** Метка вшивается ffmpeg на этапе рендера (клон: цепочка `scale → ASS → CTA →
watermark`), текст «КлипМейкер · <домен>/c/<code>», где `code` — `clip_link.code`, созданный ДО
рендера. Позиция — нижний левый угол внутри safe zone сторис, высота ≥ 3,5 % кадра, подложка с
контрастом ≥ 4,5:1. Решение «метка или нет» принимается сервером по `account.plan` fail-closed:
всё, что не ровно `paid`, получает метку. Гостевые клипы — всегда с меткой (гость не `paid`).
Снятие метки — отдельный рендер без фильтра, доступный только `paid`; в неделе ведёт на экран
интереса.

**Последствия.** Один рендер на клип в неделе (free); `clip_link` существует у каждого клипа;
`/c/{code}` — публичная страница с атрибуцией и счётчиком уникальных переходов по `ip_prefix`.
Читаемость на телефоне проверяется на устройстве (FR-GROWTH-005), не в браузере.

**Альтернативы.** Метка без ссылки (как у источника) — не измерима; метка оверлеем плеера — не
уходит с файлом на площадку.

**Confirmation.** (а) Тест fail-closed: для `plan ∈ {null, '', 'PAID', ' paid', 'premium', 0, true}`
функция `watermarkRequired` возвращает `true`; внедряемый дефект: `!== 'free'` вместо `=== 'paid'`
→ красный. (б) Интеграционный: рендер клипа free содержит фильтр `drawtext` с текстом, содержащим
`/c/<code>`, и `clip_link` создан до `job_attempt(stage=render)`; внедряемый дефект: создать ссылку
после рендера → красный.

## ADR-005 · Оплата в неделе — экран интереса; ЮKassa из клона остаётся спящим кодом

**Контекст.** У клона есть `yookassa.ts`, вебхук и тарифы; постановка оплату в неделю не включала,
владелец подтвердил план (OWN-005).

**Решение.** Тариф `paid` существует в модели и в fail-closed-правилах, но в неделе недостижим:
«снять метку» и «больше минут» ведут на `interest.create` (`pro_interest`). Код ЮKassa и вебхук не
удаляются и не подключаются к маршрутам; `webhook-contract.md` отвечает «вебхуков нет».

**Последствия.** Атрибуция партнёра до платной конверсии остаётся `pending`/`activated` без
`paid`-события; комиссии не начисляются. Вторая волна включает ЮKassa вместе с контрактом вебхуков
(три класса отказа).

**Альтернативы.** Включить ЮKassa в тестовом режиме сразу — тянет контракт вебхуков и деньги в
неделю; отвергнуто владельцем.

**Confirmation.** Страж по маршрутам: в боевом профиле нет зарегистрированного обработчика
`/api/webhooks/yookassa` (тест роутера возвращает 404); внедряемый дефект: подключить маршрут →
красный.

## ADR-006 · Одна тяжёлая задача одновременно; резерв и очистка рабочей области

**Контекст.** Один VPS, 18 ГБ свободно, ffmpeg-рендер и скачивание 2 ГБ конкурируют за диск, CPU и
канал. Второе мнение: «рабочая область 20 ГБ при свободных 18 невозможна», Docker-том размер не
ограничивает.

**Решение.** `worker-video` с `concurrency: 1`; перед скачиванием оригинала — проверка свободного
места ≥ 3× размера файла (`statvfs`), иначе задание откладывается с причиной `no_disk`, а не
падает; временный каталог на именованном томе с очисткой в `finally`; отдельный лимит
длительности 90 мин и разрешения (не выше 1080p на входе, иначе даунскейл до рендера).
`worker-stt` и `worker-llm` — `concurrency: 2`, они не пишут на диск больших файлов (аудио
извлекается потоково в чанки ≤ 25 МБ и удаляется после отправки).

**Последствия.** Пропускная способность недели ≈ 10 записей в сутки (NFR-SCALE-001) — достаточно
для метрики; масштабирование — второй `worker-video` на другой машине, не на этой.

**Альтернативы.** Параллельный рендер — упирается в диск и CPU раньше, чем в очередь.

**Confirmation.** Тест: при свободном месте < 3× размера задание получает `deferred(no_disk)` и
не скачивает объект (счётчик вызовов S3 GET равен 0); внедряемый дефект: убрать проверку → красный.
Страж по коду: `concurrency` у `worker-video` — литерал `1`, не переменная окружения.

## ADR-007 · Явный код партнёра сильнее cookie; гостевая ссылка — третий источник атрибуции

**Контекст.** N4 ADR-008 и N1 `referral.ts`: код сильнее cookie, недействительный код не
откатывается к cookie. В D появляется третий источник — гость, пришедший по `/g/{guest_code}`,
атрибутируется ведущему.

**Решение.** `attribution.source ∈ {explicit, guest_link, cookie}`, ровно одна строка на аккаунт
(`UNIQUE (account_id)`), но строка изменяема по правилу: `explicit` побеждает всё; `guest_link`
побеждает `cookie`; равные и более слабые источники дают `409`; замена пишет `replaced_source`.
Недействительный явный код — `422`, без отката. Самопереходы владельца по своим `/c/` и `/g/`
ссылкам не создают ни атрибуции, ни `growth_event`.

**Последствия.** Метрики гостя и блогера не смешиваются; кабинет партнёра считает только свой
источник.

**Confirmation.** Интеграционный тест трёх исходов `code.apply`: `cookie → explicit` = `200` +
`replaced_source = cookie`; `explicit → любой` = `409`; `guest_link → cookie` = `409`; недействительный
код = `422` и строка не тронута. Внедряемый дефект: разрешить откат к cookie при `422` → красный.

---

**Объявленная граница (RT-008, 24.09.2026, A-2409-06; подтверждено владельцем).** Исключение самоперехода
работает только для ОПОЗНАННОЙ сессии: владелец без входа неотличим от постороннего, второй аккаунт
того же человека — от другого человека. Связывание людей по отпечатку браузера или адресу не
добавляется. Защита от нескольких аккаунтов одного человека — вопрос OWN-008 (подтверждение почты).

## ADR-008 · Согласие гостя фиксируется ведущим до создания гостевой страницы

**Контекст.** Гостевая страница передаёт клипы с изображением гостя третьему лицу и делает их
скачиваемыми. Изображение гражданина охраняется (ст. 152.1 ГК РФ); запись принадлежит ведущему,
согласие гостя на публикацию обычно есть в договорённости о выпуске, но у нас его нет в системе.

**Решение.** `guest.create` принимает `consent_confirmed: true` обязательным полем; без него —
`422`, страница не создаётся. Текст чекбокса версионирован (хэш в `guest_pack.consent_version`).
Страница приватная по коду (≥ 128 бит энтропии), `noindex`, 14 дней, отзыв ведущим удаляет
страницу и объекты гостевых копий немедленно. На странице — контакт для жалобы; снятие по
требованию — не позже 72 ч.

**Последствия.** Ответственность за наличие согласия — на ведущем, и это записано в момент
действия; мы храним факт и версию текста.

**Confirmation.** Тест: `guest.create` без `consent_confirmed` или с `false` → `422`, строк
`guest_pack` не появилось; внедряемый дефект: сделать поле необязательным → красный.

## ADR-009 · Кадр следует за лицом, а не режется по центру

**Статус:** принято 23.09.2026 по находке владельца на живых клипах. Заменяет центральную обрезку
FR-RENDER-001 и промежуточный вариант FR-1 «две панели по половинам кадра».

**Контекст.** Центральный вырез 9:16 из кадра 16:9 показывает среднюю треть (для 1280×720 — полосу
шириной ~405 px из 1280). В подкасте с двумя участниками по краям в неё не попадает ни один: зритель
видит стену. Владелец: «аудиоряд вовлекающий, а видеоряд ни о чём». Промежуточный вариант — два
этажа по половинам — опроверг замер: нижняя панель пустовала в 10 замерах из 12. Следование за
говорящим по каналам звука опроверг второй замер: в загруженной записи каналы совпадают
(корреляция громкостей 0,9995, ни одного окна из 10 611 с разницей выше 3 дБ).

**Решение.** Детектор лиц YuNet (OpenCV 4.12, модель 228 КБ вендорена в образ) берёт кадр раз в
0,5 с. Кадр следует за самым крупным лицом, прошедшим порог размера; порог — 0,4 медианы ширины
лиц этого клипа, не ниже 0,03. Камера в подкасте уже режет на говорящего, поэтому следование за
видимым лицом совпадает со следованием за говорящим там, где камера делает выбор за нас. Два этажа —
только если обе группы лиц присутствуют в ≥ 0,9 замеров. Нет плана или лиц — центральный кроп.
Подвижный вырез строится выражением от времени внутри `crop`, второго прохода нет.

**Отвергнуто.** Постоянный порог размера лица (0,06): в клипе, снятом общими планами, медианное
лицо 0,048 — порог отсекал большинство настоящих участников, кадр переставал переключаться.
Детектор губ (активный говорящий): десятки минут расчёта на запись без видеокарты.

**Последствия.** В образе воркера — python3 и OpenCV (+~1,5 ГБ к образу). Отказ детектора рендер
не валит. На общем плане обоих кадр идёт за более крупным лицом, а не за говорящим; точное
следование требует раздельных дорожек звука.

**Confirmation.** (а) Юнит: без плана `getFramingFilter` не строит `split`/`vstack`; с явной
раскладкой строит. (б) Настоящий ffmpeg: граф двух этажей на исходнике «красное | синее» даёт
красное сверху и синее снизу. (в) Живой прогон 23.09.2026 по готовым клипам: 384 секунды, семь
клипов, кадров без лица — ноль; переключений 38 против 14 при постоянном пороге. Внедряемый дефект
(а): вернуть откат к слепым этажам при отсутствии плана — тест FR-1 краснеет.

## ADR-010 · Погрешность таймкодов исправляется, а не отвергает запись

**Статус:** принято 23.09.2026 решением владельца: «не нужна супер точность на данном этапе, нам
нужно, чтобы раскадровка не ломалась в процессе». Уточняет ADR-003.

**Контекст.** ADR-003 требовал отвергать расшифровку без пригодных таймкодов. Проверка была написана
строже реальности: настоящая запись на 88 минут отвергалась трижды подряд — откат начала слова на
0,26 с; пять поджатий на 409 слов при пороге доли 1 %; сегмент длиннее куска на 0,0000205 с. Каждый
порог выбирался без данных.

**Решение.** Порядок слов не повод для отказа: откат поджимается к предыдущему слову (событие
`stt_word_order_clamped`). Выход за границы поджимается в `[0, duration]` (событие
`stt_timing_clamped`). Отказ остаётся только там, где данные непригодны по существу: таймкодов нет,
не числа, начало целиком за пределами записи. Требование ADR-003 «границы по словам» сохраняется.

**Отвергнуто.** Допуск 0,5 с и доля 10 %: обе величины отвергли настоящую запись.

**Последствия.** Дефект склейки кусков (TR-003), прежде ловившийся здесь, теперь даст клип со
сдвинутой границей вместо отказа. Цена принята владельцем; сигнал — рост событий поджатия в
журнале. Измерено на живой записи: 43 поджатия на 12 916 слов (0,33 %).

**Confirmation.** Тесты с измеренными величинами: откат 0,26 с, 5 поджатий на 409 слов, превышение
0,0000205 с — принимаются; отсутствие таймкодов — отказ. Внедряемый дефект: вернуть отказ при
откате — красный.

## ADR-011 · Фоновая музыка: CC0-трек, уровень вычисляется из речи клипа, статический микс

**Статус:** принято 24.09.2026 решениями владельца (трек CC0, галочка при загрузке, двухпроходная
схема — В-1, В-6 из `docs/proposals/music-and-stinger/00_proposal.md`); запас 18 LU заморожен OWN-009.

**Контекст.** Владелец попросил «вирусную музыку». Две преграды названы в предложении: право
СУБЛИЦЕНЗИРОВАТЬ трек пользователям (подписки Artlist/Epidemic это запрещают) и громкость — речь
между записями различается на 15,4 LU (И-1), продукт звук не нормализует.

**Решение.**
- Трек из закрытого каталога в коде (`MUSIC_TRACKS`): Komiku «Everything is groovy», CC0 1.0,
  проверено по двум независимым источникам (Internet Archive, Free Music Archive), sha256 в коде.
- Галочка при загрузке, выключена по умолчанию; `video.music boolean NOT NULL DEFAULT false`
  (миграция 014). Повтор `video.create` с тем же ключом и другим флагом — `409`.
- Проход 1 (только звук): громкость речи клипа и трека в полосе 300–3400 Гц (`ebur128`, разбор блока
  после `Summary:`); `gain = S_речь − 18 − S_трек`, потолок +12 дБ. Проход 2 — прежний рендер,
  трек вторым входом, `amix normalize=0` (без него речь тише на 6,0 дБ).
- Любой отказ замера — клип без музыки (`music_skipped`), не отказ рендера; отмена пробрасывается.
- Хеш контракта строится из ФАКТА смешения; при `music=false` аргументы ffmpeg и контракт побайтово
  прежние.

**Отвергнуто.** Ducking (`sidechaincompress`): разброс 10,4 дБ между тремя правдоподобными наборами
параметров и ни одного детерминированного критерия правильности. Постоянное усиление: на тихой
записи (−33 LUFS) подложка оказалась бы в 4 LU от речи. Трек из подписки: запрет сублицензии.

**Расширение 24.09.2026 (фича 18, A-2409-01; ПЕРЕСМОТРЕНО OWN-013/014).** Сначала каталог был из 11 треков того же альбома Komiku (CC0 по
тем же двум источникам); трек выбирается детерминированно: `MUSIC_TRACKS[(clip.index − 1) mod 11]`,
нецелый индекс → первый трек и событие `music_track_fallback`. Первый клип записи звучит как раньше;
клипы одной записи — по-разному; повтор рендера — тот же трек. Отбор треков: ≥ 75 с, первые 20 с в
полосе 300–3400 Гц не тише −21 LUFS, ни одного провала тишины > 1 с на −40 дБ. **Владелец отверг этот
подбор на слух** («невозможно слушать»): измеримые свойства вкус не проверяют. Итоговый каталог — 9
треков, каждый прослушан владельцем (Komiku «Everything is groovy» + 8 HoliznaCC0; CC0 подтверждён на
страницах треков FMA, независимого источника вне FMA нет — принято владельцем, OWN-014).

**Последствия.** Файл клипа один — музыка уходит и на гостевую страницу; у CC0-трека нет
лицензиара, предмет согласия гостя не меняется. Тариф `paid` музыку не отключает.

**Confirmation.** Стражи Г-1 (речь не тише, 0,1 LU; мутация `normalize=1` → 6,0 LU), Г-2 (трек в
полосе ≤ S−18+0,5; мутация `gain=0`), Г-3 (пик ≤ −1 dBTP; мутация +20 дБ), сквозной тест против
вечного пропуска, эталон аргументов с `main`. Живой прогон: 7 клипов громкой записи (речь ≈ −19,
усиление −13,4…−19,7 дБ) и 6 тихой (≈ −33, усиление −23,9…−28,1 дБ), ни одного пропуска.

## ADR-012 · Пэк-шот — наложение в конце клипа, а не вставка кадров

**Статус:** принято 24.09.2026 решениями владельца: вспышка без текста, CC0-сэмпл, включается той
же галочкой, что музыка. Уровень удара подобран на слух в три итерации (см. «Последствия»).

**Контекст.** Владелец просил «пэк-шот или перебивку». Вставка кадров меняет шкалу времени: звук
идёт мимо графа фильтров, и вставка молча съедает хвост содержания (О-1) или разводит звук и
картинку (О-2); ломаются субтитры и обе проверки длины (Л-1…Л-4, proposal music-and-stinger §6).

**Решение.**
- Наложение на последние 0,8 с: удар — третий вход того же `amix normalize=0`, `adelay` до
  `t0 = длительность − 0,8` (округлено до мс); вспышка — `eq=brightness` 0 до `t0`, подъём за 0,05 с,
  спад до `t0 + 0,55`, пик 0,35. Порядок фильтров: кадр → субтитры → вспышка → метка (метка
  читается и под вспышкой, FR-GROWTH-003). Длительность и число кадров неизменны.
- Ставится тогда и только тогда, когда в клип фактически смешана музыка; схема БД не меняется.
- Сэмпл — закрытый каталог `STINGERS`: Kenney «Sci-Fi Sounds» `explosionCrunch_002`, CC0 (страница
  kenney.nl и `License.txt` архива). Уровень в ПОЛНОЙ полосе:
  `gain = min(S_речь − STINGER_MARGIN_LU − S_сэмпл, −3 − P_сэмпл)`, потолок +12 дБ.
- Отказ замера удара — клип с музыкой, но без пэк-шота; контракт из факта, при `packshot=null`
  равен контракту «только музыка».

**Отвергнуто.** Вставка кадров (О-1, О-2). Текст/бренд в пэк-шоте (paid-клипы обещаны без бренда,
гостевые — меняется предмет согласия). Замер удара в полосе речи: низкочастотный сэмпл получил бы
+7 дБ и клиппинг. Низкочастотный сэмпл `lowFrequency_explosion_001`: 16,5 дБ энергии ниже 300 Гц,
динамик телефона их не воспроизводит — владелец «не понял даже где он».

**Последствия.** Прослушивания владельца: 6 LU + низкочастотный сэмпл — не слышно; 0 LU +
`explosionCrunch_002` — «слишком громкий»; 3 LU — см. OWN-010. Вспышка 0,35 — «заметил, норм».

**Confirmation.** 19 мутаций обеими строками (`tests/run-pack-shot-mutations.mjs`): вставка,
`adelay=0`, `gain=0`, +20 дБ, вспышка в начале и симметричная, вспышка после метки, безусловный вход,
контракт, кэш, пиковый потолок, подпись в UI. Полный набор в образе 653/653.

## ADR-013 · Окно приманки — заголовок клипа крупно в первые 2,5 с

**Статус:** принято 24.09.2026 в автономном режиме (A-2409-04, A-2409-05); **подтверждено владельцем
в тот же день** после просмотра клипов.

**Контекст.** Первые секунды решают досмотр. proposal hook-music-cta §1.1 предлагал дословную строку
транскрипта, выбранную моделью, — это новое поле ответа модели, миграция и платный повтор выделения
для уже загруженных записей.

**Решение.** Текст — `clip.title` (модель уже пишет его для каждого фрагмента), подаётся как
ЗАГОЛОВОК без кавычек. Своя галочка, по умолчанию включена (`video.teaser`, миграция 015, прежние
записи — `false`). Рендер: `drawtext` с `textfile=` во временном каталоге (`expansion=none`, путь
экранирован — заголовок недоверенный ввод), `text_align=C`, разметка по `measureText` (≤ 3 строк,
кегль 84 → 60, обрезка с «…»), `y = 0,17·h`, показ `lt(t, 2,5)` с исчезновением последние 0,3 с;
порядок кадр → субтитры → приманка → вспышка → метка. Ошибка разметки (глиф вне метрик) — клип без
приманки, не отказ.

**Отвергнуто.** Дословная цитата — отложена (новое поле модели + платный повтор); вставка
кадров-заставки — ломает шкалу времени (ADR-012); подавление субтитров в окне — текст другой.

**Последствия.** Центрирование строк требует ffmpeg ≥ 6.1 (`text_align`); в образе 8.1, на хосте 4.4
медиа-тест громко «НЕ ВЫПОЛНЕН». Уже загруженная запись получает приманку после
`UPDATE video SET teaser=true` и перерендера.

**Confirmation.** Разметка, инъекция через заголовок, порядок фильтров по строке, окно по пикселям в
образе, контракт; эталоны `baseline.json` и `music-only.json` побайтово при `teaser=false`.

## ADR-014 · Справедливость партнёрской программы: различные аккаунты, разблокировка, обезличивание

**Статус:** принято 24.09.2026 решением владельца («RT-002 и RT-009 — делай, как рекомендуешь»).
Уточняет ADR-007 и канон §4, §7.

**Контекст.** RT-002: блокировка считала ПРИМЕНЕНИЯ, а не людей, и разблокировать было нечем —
добросовестный партнёр с аудиторией за одной сетью терял код навсегда. RT-009: удаление партнёра
удаляло атрибуции приглашённых живых аккаунтов, и тот же человек мог быть «приведён» повторно.

**Решение.**
- Порог 50 и окно 10 мин прежние, считаются `DISTINCT account_id` событий `code_applied`; нижняя
  граница окна `GREATEST(now − 10 мин, unblocked_at)`, `unblocked_at` читается под той же
  блокировкой строки кода.
- Разблокировка — `packages/db/scripts/partner-code-unblock.mjs <код> "<причина>"` в контейнере
  `web` (новой процедуры и публичного пути нет — канон §5 закрыт); причина 1–500 знаков после
  `trim`, видна партнёру в кабинете. Снимает и ручную блокировку.
- Миграция 016: `attribution.partner_code_id` обнуляемый, FK `ON DELETE SET NULL`; статус
  `partner_deleted` (терминальный); `CHECK (partner_code_id IS NOT NULL OR status='partner_deleted')`.
  Удаление партнёра переводит чужие атрибуции в `partner_deleted` с `partner_code_id = NULL`,
  `reject_reason = NULL`; `code.apply` для них — `409`.

**Отвергнуто.** Журнал разблокировок отдельной таблицей (след блокировки после разблокировки живёт
только в журнале оператора — принято); ключ по подсети без различения людей.

**Последствия.** Удаление кода мимо `retention` падает на CHECK — fail-closed, так задумано.
Стёртые аккаунты выпадают из подсчёта окна (их `account_id` обнуляется) — не обход, пока период
ожидания стирания длиннее 10 минут.

**Confirmation.** 17 аккаунтов × 3 смены источника (51 событие, 17 различных) → код активен, при
`count(*)` — блок; 50 → `blocked`, 49 → активен; после разблокировки 50 старых + 1 новое → активен,
50 новых различных → снова `blocked`; конкурентный 60 запросов / 55 аккаунтов → ровно 50 успехов.
Удаление партнёра с 3 приглашёнными → 3 строки `partner_deleted`. Мутации в образе: 21 партнёрская,
7 удаления — красные.

## ADR-015 · Уплотнение пауз: вырез по огибающей звука, план резов хранится, одна плановая длина

**Статус:** принято 24.09.2026 решением владельца (OWN-012: K = 0,05 с выбран по образцам, галочка
по умолчанию включена).

**Контекст.** Владелец просил «сжатие клипа — вырезку пауз и мусора». Измерено (proposal density):
паразитов в тексте нет (распознаватель их выкинул), паузы по транскрипту втрое завышены против
звука; честный выигрыш — 1–3 с на клипе 40–60 с.

**Решение.** Порог — медиана огибающей ВСЕЙ записи − 18 дБ (считается лениво, записывается и
перечитывается из БД); режутся паузы 0,30–2,0 с не ближе 0,5 с к краям; на стыке остаётся K тишины;
кадровая сетка 25 к/с, перекрестие `xfade`/`acrossfade` 0,08 с; одна плановая длина D' для `-t`,
`color=`, музыки, пэк-шота и обложки; `mapTime` переносит слова субтитров и планы следования за лицом;
план пишется под фенсом (`WHERE cut_plan IS NULL`) и при любом пропуске — из одного куска.
Уплотнение только при экономии ≥ 3 % и итоге ≥ 20 с + 1 кадр.

**Отвергнуто.** Вырезание слов-паразитов по тексту (их там нет), повторов (смысловая правка),
звук поверх непрерывной картинки (рассинхрон губ), ускорение речи; перекрестие 0,06 с (1,5 кадра —
звук уезжает от картинки до 20 мс на стык).

**Последствия.** Составляющая оценки «Длина» описывает исходный фрагмент. Уже отрендеренный клип
уплотняется только перерендером с удалением старых объектов (иначе S3 `412`).

**Confirmation.** 10 мутаций в образе (MAX_PAUSE, мин. длина, 3 %, K без XF, пересчёт при повторе,
часы субтитров и пэк-шота, безусловное уплотнение, схема, галочка). Живой прогон: запись 88 мин,
6 из 7 клипов уплотнены на 4,7–8,9 %, один пропущен (< 3 %).

## ADR-016 · Смена музыки у готового клипа: пересборка без выхода из `done`

**Статус:** принято 25.09.2026 решениями владельца (OWN-015: превью ▶, 20 смен в сутки, 16-я процедура).

**Контекст.** Трек выбирается по номеру клипа, а не по настроению; владелец попросил выбирать и
менять музыку у клипа. Весь механизм рендера был привязан к `status='rendering'` клипа и записи —
пересборка готового клипа по нему либо не запускалась, либо лишала пользователя файла.

**Решение.** `clip.setMusic` (`auto | none | <id>`); отдельный режим попытки (`job_attempt.rerender`):
клип остаётся `done`, старый `object_key` отдаётся до публикации; предикат блокировки не зависит от
статуса записи, публикация `done → done` по fence; отказ пересборки оставляет старый файл; сравнение
«тот же трек» — с ОТРИСОВАННЫМ (`rendered_music_track_id`); ключи версий `-vN`, старые читаются из БД
и удаляются после коммита; срок хранения и `finished_at` не меняются; сторож видит пересборку по
отметке жизни; квота `user_rerenders`, `N5_LIMIT_USER_RERENDERS` (fail-closed); очистка по сроку —
по префиксу клипа `eraseClipPrefix` с закрытым регэкспом.

**Отвергнуто.** Перевод клипа в `rendering` на время пересборки (пропадает файл, гостевая страница и
короткая ссылка); вычисление старого ключа как `v{N-1}` (тариф мог смениться); возврат квоты при
отказе пересборки (решение координатора).

**Последствия.** Удаление старого объекта ломает уже выданные подписанные ссылки владельца до их
истечения (≤ 900 с). Выбор трека при записи без музыки включает музыку и финальный акцент у этого
клипа.

**Confirmation.** Проверка плана NOT READY (4 блокера) → исправлено; ревью REJECT (очистка по сроку
отвергалась настоящей проверкой префикса, в тестах стояла заглушка) → исправлено тестом на настоящей
проверке. Полный набор в образе 786/786; мутации выбора музыки и удаления — red/green.

## ADR-017 · Призыв к действию в конце клипа: закрытый набор, адрес не в пикселях, без редиректа

**Статус:** часть **27a** принята и выкачена 25.09.2026 (OWN-018); часть **27b** (надпись в пикселях и пересборка
клипов записи, постановка `docs/features/clip-cta/00b_brief.md`) — реализована исполнителем 25.09.2026, ждёт ревью
(OWN-017) и выкатки. Координатор сверяет.

**Контекст.** Клип продвигает весь выпуск (`clipmkr.ru/c/CTDUUG` → выпуск на YouTube), но ни в клипе, ни
на странице `/c/` пути к выпуску не было. Владелец: «перед монтажом задать, какой action ждём от зрителя
по окончании».

**Решение (27a).**
1. **Вид — закрытый набор** `CTA_KIND = none | watch_full | subscribe | open_link` (`packages/shared/src/enums.ts`,
   `SQL_ENUMS['video.cta_kind']`, CHECK миграции `020_clip_cta.sql`). Надписи — словарь в коде
   (`packages/shared/src/cta.ts`), свободного текста нет: он на нашем домене — поверхность фишинга, а в 27b
   уедет в пиксели навсегда.
2. **Адрес** `video.cta_url`: только `https:`, разбор `new URL`, без логина/пароля, без пробелов и
   управляющих символов, ≤ 2048 символов в исходном и нормализованном виде; `search` и `hash` разрешены
   (ссылка на выпуск YouTube несёт `?v=`), безопасность вывода обеспечивает экранирование, а не запрет.
   Непригодное — `422` с причиной, не молчаливое `none`. Пара в базе: `(cta_kind='none') = (cta_url IS NULL)`,
   `cta_url LIKE 'https://%'`, длина 9–2048 — второй рубеж на случай записи в обход кода.
3. **Где задаётся:** в форме загрузки (`video.create`, поля необязательны — старый клиент получает `none`;
   разбор ДО заявки `Idempotency-Key` и квоты; повтор ключа с другим призывом — `409`) и на экране записи
   (`video.setCta`, 17-я процедура канона §5). В 27a `video.setCta` **только сохраняет** вид и адрес:
   пересборки нет, квота не списывается, `updated_at` не трогается (по нему экран отличает «выполняется»
   от «нет ответа»). Чужая и несуществующая запись — одинаковый `404`.
4. **Где видит зритель (27a):** страница `/c/{code}` — главная кнопка «Смотреть полный выпуск →» и т. п.:
   обычный `<a href>` на адрес автора с `rel="noopener noreferrer nofollow"` `target="_blank"`, **не редирект
   через наш домен** (открытого редиректа нет); под кнопкой «Ссылка автора клипа · youtube.com» (домен
   после `new URL`, IDN — в punycode). Адрес и домен проходят `escapeHtml`. CSP `/c/` не ослаблена
   (внешняя ссылка не требует `connect-src`/`frame-src`).
5. **Класс `.cta` = основное действие `/c/`** (R9, `FIRST_SCREEN_ACTIONS`): при заданном призыве его несёт
   кнопка автора, «Сделать свои клипы» становится `.secondary-link`; без призыва `.cta` остаётся у
   «Сделать свои клипы». Ровно один `.cta` в обоих вариантах — проверяется тестом и прибором.
6. **Чтение fail-closed:** неизвестный вид или непригодный адрес из базы читаются как «призыва нет»
   (`readStoredCta`), а не как ссылка.
7. **Сервер по `cta_url` не ходит** ни на одном шаге (`video.create`, `video.setCta`, `/c/`): только разбор
   строки в памяти — SSRF-поверхности нет. Это строка контракта, а не подразумеваемое свойство.
8. `video.source_url` не переиспользуется: он принадлежит FR-INGEST-003.

**Решение (27b).** Правки 2–7 и 10 из `docs/features/clip-cta/01_validate.md`.
9. **Надпись в кадре** — только при `cta_kind ≠ none`, текст из закрытого словаря `CTA_FRAME_LABELS`
   (`packages/shared/src/cta.ts`); адрес в кадр НЕ вшивается и воркеру не передаётся вовсе (SELECT рендера берёт
   `v.cta_kind`, но не `cta_url` — отступление от буквы правки 10 ради меньших данных; страж по исходнику).
   Модуль `apps/worker/src/render/cta-overlay.ts`: `drawbox` (плашка `black@0.60`) + `drawtext` (`text=` с
   экранированием, `expansion=none`, шрифт метки). Порядок фильтров: кадр → субтитры → заголовок → вспышка →
   **призыв** → метка (вспышка не засвечивает надпись, метка всегда сверху).
10. **Геометрия числом, fail-closed.** Полоса между низом субтитров `h − MarginV(500) + обводка 5 + тень 1` и верхом
    плашки метки (`watermarkPlateTop`, та же формула, что у `watermarkGeometry`), зазоры по 12 px: на 1080×1920 —
    **y 1438–1561** (123 px). Кегль **72 → 48** шагом 4, плашка `24 + ceil(1,15·кегль)` по высоте, текст + 2·24 по
    ширине в поле `w − 2·⌈0,05w⌉`; плашка прижата к низу полосы, по центру. На 1080×1920 все три надписи
    помещаются кеглем 72 (плашка 107 px). Не помещается даже 48 — клип собирается **без надписи**, событие
    `cta_skipped` (`no_room`, `glyph_missing`, `window_empty`), а не наложение и не отказ рендера. Позиция одна
    для free и paid (у paid метки нет, место то же). Субтитры и метка по построению не перекрываются.
11. **Окно — числом:** последние **2,5 с** клипа (`CTA_SECONDS`), но не раньше конца заголовка (2,5 с) и не раньше
    начала; это НЕ 0,8 с пэк-шота. Без исчезновения: `drawbox` не умеет прозрачность по времени, а
    полупрозрачная плашка под непрозрачным текстом читалась бы хуже, чем появление целиком.
12. **Пересборка при смене вида.** `video.setCta` сравнивает вид в базе с новым (`ctaPixelsChange`): меняется вид
    (включая `none ↔` не-`none`) — пиксели меняются; меняется только адрес — нет, сохраняется без пересборки и
    без квоты. При смене вида одна транзакция под блокировкой `video`: (а) ОДИН запрос на всю запись — есть ли
    `job_attempt(render)` в `running|deferred` или клип в `rendering`; есть — `409` целиком ДО квоты (гонка с
    `clip.setMusic` и с параллельным `video.setCta`; обе процедуры блокируют `video` первым); (б) клипы `done` с
    файлом и неистёкшим сроком; (в) сохранение призыва; (г) `checkAndConsumeQuota(…, 'rerender', N)` ОДНИМ
    вызовом — нехватка остатка бросает исключение, откатывается всё, включая призыв (`429` целиком); (д) по
    каждому клипу `render_version+1`, фиксация отрисованного трека, `leaseAttemptTx(…, rerender=true)` одной
    серией; постановка в очередь — после коммита, потерю доставки восстанавливает сторож. Механизм публикации —
    ADR-016 без изменений (клип остаётся `done`, старый файл до публикации, ключи `-vN`).
13. **Частичный отказ ПОСЛЕ постановки принят как известное ограничение** (аналог ADR-016): если пересборка клипа
    не удалась дважды, у него остаётся прежний файл со СТАРОЙ надписью (или без неё), а `video.cta_kind`, `/c/` и
    остальные клипы — уже новые; успевшие клипы не откатываются, квота не возвращается. Повторить: сменить вид
    туда и обратно (тот же вид повторно пересборку не запускает — он совпадает с сохранённым).

**Отвергнуто.** Списание квоты по одной единице на клип в цикле (частичная пересборка при нехватке или ручной
откат); пересборка при смене одного адреса (пиксели не меняются — трата лимита впустую); надпись поверх
субтитров при нехватке места (перекрывает речь) и падение рендера при нехватке (ломает клип без вины
пользователя); передача `cta_url` воркеру; отдельная колонка причины пропуска надписи (при нынешних числах
пропуск невозможен на 1080×1920, достаточно журнала — вернуться, если появится второй формат);
Свободный текст призыва (фишинг, пиксели навсегда); редирект `/go?to=` через наш домен
(открытый редирект, чужая репутация на нашем домене); запрет `search`/`hash` (ломает ссылки на выпуск);
переиспользование `source_url`; перевод `updated_at` при смене призыва (маскирует зависшую обработку).

**Последствия.** Наш домен показывает ссылку на произвольный `https`-адрес автора — остаточный риск фишинга
закрыт видимым доменом, пометкой автора и `nofollow`, но не устранён: модерации адресов нет. `/c/` меняется
сразу для всех клипов записи, пиксели — после пересборки. Уже отрендеренные клипы получают надпись только
пересборкой (смена вида на экране записи; по одной единице `user_rerenders` на клип). Смена вида у записи из 8
клипов тратит 8 из 20 суточных пересборок. Пока хоть один клип записи собирается, вид сменить нельзя (`409`).

**Confirmation.** `tests/clip-cta.test.ts`, `tests/clip-cta.integration.test.ts`, `tests/enums.test.ts`
(каждый `CHECK … IN` объявлен в `SQL_ENUMS`), браузерные R9 на настоящей странице `/c/`; мутации
`tests/run-clip-cta-mutations.mjs` — квитанция `docs/features/clip-cta/07_code_report.md`. 27b:
`tests/clip-cta-render.test.ts` (геометрия, окно, закрытый набор, порядок фильтров), `tests/cta-media.test.ts`
(пиксели в образе ffmpeg 8.1), `tests/clip-cta-worker.test.ts`, `tests/clip-cta-rerender.integration.test.ts`

`tests/run-clip-cta-27b-mutations.mjs` — квитанция `docs/features/clip-cta/07b_code_report.md`.

## ADR-018 · Витрина лендинга — третий путь к файлу клипа: закрытый набор в коде, только чтение

**Статус:** черновик исполнителя 26.09.2026 (фича 28 `landing-demo`, постановка `docs/features/landing-demo/00_brief.md`,
проверка плана READY WITH FIXES — `01_validate.md`). Ждёт ревью (OWN-017) и выкатки. Выбор клипа — владелец 25.09.2026
(«вот этот клип можно поставить на витрину https://clipmkr.ru/c/CTDUUG»).

**Контекст.** Посетитель лендинга видел только текст и форму входа — момент ценности (FR-GROWTH-001 для гостя сайта,
FR-LOOK-011) не показан. Демо должно проигрываться анонимно, а `.claude/rules/security.md` разрешал к файлу клипа
РОВНО ДВА пути: сессию владельца и код неотозванной гостевой страницы. Третье: клип витрины принадлежит бесплатному
аккаунту, а ретенция (`retention.ts`) выбирает клипы по `plan <> 'paid'` и `finished_at <= now − 3 сут`; `expires_at`
в отборе не участвует. Запись витрины закончена 24.09.2026 10:24 UTC — без исключения объект `/c/CTDUUG` был бы
стёрт около 27.09, а `/c/CTDUUG` показывал бы «срок хранения истёк».

**Решение.**
1. **Набор — код, не окружение и не флаг в БД** (`honest-configuration` CFG-I8): `SHOWCASE_CLIPS` в
   `packages/shared/src/showcase.ts`, сейчас одна запись `{code:'CTDUUG', clipId:'46f99d89-…4152', 88 мин, 7 клипов}`
   (числа — из базы стенда 26.09: `video.duration_seconds` 5305,9, 7 клипов `done`). Изменение набора — правка кода с
   ревью и выкаткой.
2. **Третий путь** `GET /api/showcase/{code}/file|thumbnail` (`apps/web/src/server/showcase-file.ts`): лимит чтений
   120/мин на префикс IP (тот же `allowRead`) → **членство кода в наборе точным сравнением ДО любого запроса к базе**
   (код того же формата вне набора — `404`, ни одного обращения к БД) → строка клипа по `clipId` из набора при
   `c.status='done'`, `v.deleted_at IS NULL`, `a.status='active'` и неотозванной `clip_link` с ЭТИМ кодом → ключ
   объекта → **302 на подписанную ссылку ≤ 900 с** (`generateDownloadUrl`, как путь владельца в `clip-file.ts`).
   Байты через `web` не идут; двухшаговый гостевой проброс (`guestFileTicket` + `stream`) не используется.
   `Cache-Control: private, no-store`, `Referrer-Policy: no-referrer`. Отказ базы — `503`.
3. **Граница:** только чтение (GET), без сессии и без сведений о владельце; ни списков, ни мутаций, ни других клипов
   записи. Отзыв короткой ссылки, удаление записи или стирание аккаунта закрывают витрину тем же `404`.
4. **Ретенция бесплатного тарифа не стирает клипы набора:** в отбор шага «очистка клипов» добавлено
   `AND NOT (c.id = ANY($3::uuid[]))` с параметром `SHOWCASE_CLIP_IDS`. **Стирание аккаунта** (право на удаление)
   клипы витрины НЕ щадит — это сильнее витрины.
5. **`/c/{code}` клипа витрины не объявляется истёкшим** (`previewState` в `short-link.ts`): срок бесплатного
   тарифа к клипу набора не применяется; явный `expires_at` соблюдается всегда. Иначе ссылка «Открыть клип» под
   демо вела бы на «срок истёк» при живом объекте.
6. **Первый экран лендинга** (FR-LOOK-011): телефон — заголовок → демо (видео 9:16 шириной `clamp(7rem,38vw,9.5rem)`,
   постер ЦЕЛИКОМ, подпись «88 мин разговора → 7 клипов», «Открыть клип» → `/c/CTDUUG`) → кнопка «Попробовать
   бесплатно» (якорь `#auth`, фокус в поле почты клиентским обработчиком) → форма; `≥ 600` — демо в левой колонке
   под текстом, форма справа, кнопки нет. `<video controls playsinline preload="none">`, без автозвука.
   R9 проверяет ОБА: `.landing-cta` и `.landing-demo video` (`FIRST_SCREEN_ACTIONS.selector: string | string[]`).

**Отвергнуто.** Список витрины в переменной окружения или флаг `clip.showcase` в БД (пустое или ошибочное значение
открывает файл любого клипа; разрешение без ревью); проверка формата кода вместо членства (перебор кодов);
раздача байтов через `web` (полоса и CPU на каждого посетителя); `preload="auto"` или автовоспроизведение (≈ 23 МБ на
каждый заход, звук без спроса); отдельная облегчённая версия клипа (постер и `preload=none` достаточны);
исключение по `expires_at IS NULL` (колонка не участвует в отборе ретенции — защиты не дало бы); защита через
перевод аккаунта витрины в `paid` (снимает метку и зависит от тарифа, а не от решения о витрине); видимая форма
вместо кнопки на телефоне (демо и форма вместе в первый экран 375×667 не помещаются).

**Последствия.** Файл клипа витрины доступен любому посетителю — это и есть цель; клип публичен и так (`/c/CTDUUG`
отдаёт превью всем). Лимит чтений общий с `/c/` и гостевыми чтениями того же префикса: при заметном трафике с одной
подсети возможны ложные `429` на постер — наблюдать после выкатки. Воронка: на телефоне форма уходит ниже сгиба,
до поля почты +1 касание («Попробовать бесплатно») — контролируемое изменение, ставка на показанную ценность.
Если клип витрины удалят или отзовут, плеер лендинга покажет пустую рамку (маршрут `404`), страница не падает;
лендинг наличие клипа не проверяет — в базу он по-прежнему не ходит. Экран владельца (`presentClip`, `clip-file.ts`,
смена музыки и призыва) по-прежнему считает срок 3 суток: владелец видит клип витрины «истёкшим» — строгая сторона,
не расширялось в этой фиче.

**Confirmation.** `tests/landing-demo.test.ts` (набор, маршрут: вне набора → 404 без базы, 429 до базы, 302, ≤ 900 с
настоящим подписывателем; SQL ретенции с параметром; `previewState`; разметка), `tests/landing-demo.integration.test.ts`
(PostgreSQL: чужой настоящий клип с кодом того же формата → 404, не `done` → 404, отозванная ссылка/удалённая запись/
стирание → 404, код в базе на другом клипе → 404, `/c/` витрины `ready` при соседе `expired`),
