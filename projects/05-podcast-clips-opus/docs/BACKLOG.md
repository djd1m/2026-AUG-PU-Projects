## 1. Перенос на другой сервер — чего НЕТ в репозитории

Репозиторий переносит код и документы. Эти вещи живут только на текущей машине, их нужно перенести или
пересоздать отдельно:

## 2. Требования спецификации, отложенные (`Should`, «при нехватке недели»)

   (публикуют с телефона, делают на компьютере). Рекомендуемый следующий шаг.
2. **FR-INGEST-003 — загрузка по ссылке VK Видео / Rutube.** Зависимость `UNCONFIRMED`: скачивание с площадок не

3. **FR-AUTH-002 — вход через Telegram** (второй способ входа).
4. **Восстановление пароля по почте** — нужен почтовый сервис.

## 3. Ждут решения или данных владельца

0. **СРОЧНО — домен `clipmkr.ru` в состоянии `UNVERIFIED`** (whois 23.09.2026: `REGISTERED, DELEGATED, UNVERIFIED`,
   регистратор REG.RU; подробно — `docs/decisions-pending.md`, «Срочное»). По правилам .RU неподтверждённые данные владельца
   примерно через 30 дней (≈ 23.10.2026) ведут к **снятию делегирования** — а адрес вшит в пиксели каждого бесплатного клипа
   и правится только повторным рендером, которого в продукте нет. Что сделать: подтвердить данные по письму reg.ru
   (тема про подтверждение данных администратора домена), при необходимости загрузить документ в кабинете. Перепроверить
   `whois clipmkr.ru` после подтверждения — с этой машины whois недоступен (порт 43 закрыт), проверка 28.09 не выполнена.

5. **RT-005** — контакт оператора на гостевой странице `/g/`: нужен реальный адрес и ответственный.
6. ~~**Приём денег**~~ — **решено фичей 30 `payments` (28.09.2026, OWN-019, ADR-019):** тариф Pro 990 ₽ за 30 дней, тракт
   ЮKassa перенесён из N6, контракт вебхуков — три класса (`docs/webhook-contract.md`). **Ждёт владельца — магазин:**
   стенд работает с незаданным `N5_PAYMENTS_MODE` (экран интереса, как раньше). Перед выкладкой кода фичи 30 в
   `.env.n5-demo` добавить `N5_LIMIT_PAID_USER_MINUTES=270` (без неё compose стенд не поднимет — `${…:?}`); включить
   оплату — `bash scripts/stand-set-yookassa.sh`, в кабинете ЮKassa адрес уведомлений
   `https://clipmkr.ru/api/webhooks/yookassa`, события `payment.succeeded`, `refund.succeeded`; затем тестовая оплата и
   повторная доставка из кабинета (`docs/features/payments/05_completion.md`, «Что НЕ доказано»).
7. **Перенос базы в российскую юрисдикцию** (OWN-006) — ОБЯЗАТЕЛЕН до первого реального пользователя: сейчас
   персональные данные в PostgreSQL на VPS в Нидерландах.
8. **Подтверждение почты при регистрации** — до реальных пользователей (сейчас несколько бесплатных аккаунтов на
   одного человека возможны — принятый риск OWN-008).
9. **Cloud.ru Object Storage** — боевое хранилище по замыслу (OWN-004); тесты и стенд на MinIO. Ручная приёмка
   (SigV4, multipart, Range, CORS) — чек-лист в `Completion.md` (DEC-A-005).

## 5. Технические хвосты

15. Витрина лендинга раздаёт клип ≈ 23 МБ публично; ограничение — только 120 запросов/мин на адрес, облегчённой
    версии клипа нет (`docs/features/landing-demo/05_completion.md`).
16. Модерации адресов призыва нет: вредный https-сайт автора покажется на `/c/` с доменом (фича 27).
17. Рантайм-образы несут devDependencies (Playwright ≈ 32 МБ): `npm prune --omit=dev` в Dockerfile.
18. Прибор вёрстки: R9 на стенде проверяет экран записи только в готовом состоянии (фикстура `done`); мобильный
    WebKit изредка даёт «нестабильный замер» контраста — прибор помечает его предупреждением.
19. Осиротевший аккаунт UI-фикстуры `ui-fixture-1790328187143` на стенде (мусор от первого прогона сида).
20. ~~Модели OpenAI в разработке не используются с 25.09.2026 (OWN-017): фичи 25–29 проверены одним семейством
    (Opus пишет, Sonnet ревьюит). Когда квота вернётся — кросс-семейное ревью фич 25–29 желательно.~~ — **закрыто 28.09.2026:**
    ревью Codex `gpt-6-astra` (усилие medium), три круга B/B/B, blocker и high нет; находки исправлены коммитами `e2352ebc`,
    `2d07e7d7` — `docs/reviews/2026-09-28-review-25-29-codex.md`.
21. **Отвергнутая публикация пересборки при отказе хранилища остаётся сиротой** (Codex, круг 3, medium, принятый риск):
    поздний PUT отменённой пересборки после очистки клипа отвергается, а удаление объекта при отказе S3 только журналируется
    (`rerender_cleanup_failed`). Объект в приватном бакете без ссылки, живёт до удаления аккаунта. Лечение — долговечная
    очередь очистки отвергнутых объектов (`packages/db/src/render.ts`, `publishRenderResult`).
