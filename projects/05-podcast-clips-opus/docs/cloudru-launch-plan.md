## Поддержка и доступ: отдельная приёмка перед трафиком

Кандидат `support-access` добавляет `/support`, подтверждение почты,
`/forgot` и `/reset`, а также только читающий `/admin/support/accounts`.
Исходные сценарии/границы — [спецификация](features/support-access/01_specification.md),
проверки и их статус — [квитанция](features/support-access/05_completion.md).
N1/N3 дали основу почтовых токенов, N6b/N4 — операторский доступ и компактную карточку;
тикеты обслуживает официальный Libredesk, собственный движок тикетов не добавляется.

1. Применить аддитивную миграцию023 при штатном обновлении целевого сервера.
   Сохранить текущие аккаунты, пароли, сессии, кредитные остатки и аудит.
2. По умолчанию `N5_MAIL_MODE=disabled` и `N5_SUPPORT_MODE=disabled`.
   Это честно недоступные интеграции; приложение не выбирает отправителя само.
   Режим `test` разрешён лишь в изолированном тестовом runtime с БД `*_test`;
   на целевом сервере его не включать.
3. Настроить собственный SMTP по `.env.example`:465/TLS либо587/STARTTLS,
   обязательная проверка сертификата, авторизация и отправитель. Проверить
   SPF/DKIM/DMARC и получение письма адресатом; SMTP acceptance не доказывает доставку.
   После отправки нет обещания долговечной очереди доставки/автоматического повтора.
4. Для Libredesk указать явный HTTPS URL и UUID inbox. Идентификация отдельно
   выключена (`N5_SUPPORT_IDENTIFIED=false`); для её включения нужен отдельный JWT-secret.
   Проверить реальный пилот: два аккаунта, чужая/старая история, ответ оператора,
   переключение аккаунта и независимая сессия поставщика. Локальная SDK-фикстура этого не доказывает.
5. Назначить реального ответственного и `N5_SUPPORT_CONTACT_EMAIL`, часы ответа,
   сроки хранения/удаления, вложения/индексы/резервные копии и восстановление.
   До этих решений vendor-пилот использует только синтетические данные.
6. Зарегистрировать и подтвердить почту оператора, затем из доверенного процесса
   выполнить `npm run ops:support-operator -- <UUID> grant --by <actor> --reason <reason>`.
   Отзыв — та же команда с `revoke`; публичного назначения роли и email-allowlist нет.
   Проверить404 для обычного пользователя и после отзыва роли; карточка не меняет деньги.
7. До трафика пройти на целевой ВМ подтверждение, восстановление/повторный вход,
   прекращение старых N5-сессий, безопасный контекст, обращение и ответ оператора.
   Выход N5/JWT expiry не доказывают глобальный отзыв vendor-сессии или удаление истории.

Это будущая целевая выкладка. Текущий VPS этим прогоном не обновляется;
реальная почта, helpdesk и перенос в РФ не подменяются локальными проверками.

## 1. Кредитные условия и совместимость

| Пакет | Цена | Объём обычной записи | Срок |
|---|---:|---|---|
| Бонус регистрации | 0 ₽ | 30 кредитов = 30 минут = 0,5 часа | Один раз, без срока |
| Старт | 990 ₽ | 300 кредитов = 5 часов | 30 дней |
| Про | 3990 ₽ | 1800 кредитов = 30 часов | 30 дней |
| Дополнительный | 1490 ₽ | 600 кредитов = 10 часов | 30 дней с покупки, платные функции на весь срок |

1 кредит = 60 секунд исходника. Сначала сохраняется измеренная длительность с
точностью до секунды, затем резервируется весь объём; округления до целой
минуты нет. Один исходник списывается один раз; технические попытки поставщика
продолжают учитываться отдельно. Успешный первый клип закрепляет списание,
нулевой технический результат освобождает резерв. Частный 24-часовой recovery
для исходной записи не продлевает весь пакет.

Переключатель `N5_BILLING_MODE=legacy|credits_v1`, отсутствие означает legacy.
Режим credits_v1 включает новые регистрации и продажи; существующим аккаунтам
ничего автоматически не начисляется. Старые оплаченные условия, операторские
права, незавершённые счета 990 ₽ и начатые задания сохраняют прежнюю политику.
`optInCredits` — отдельный аудируемый DB API для подходящего free-аккаунта;
готовой операторской CLI для этой операции в релизе нет. Массовый перевод
через SQL не является штатной командой.

Повторная покупка базового пакета ставит следующий период после уже оплаченных.
Доппакет действует сразу. До оплаты показаны ожидаемые даты; окончательные
даты подтверждаются после оплаты. Мгновенный апгрейд с зачётом денег выключен,
автоматического списания с карты нет. Это выбранные ограниченные правила
кода под автономную работу, а не дополнительные ответы владельца:
[решения и полномочия](features/credit-packages/owner-decisions.md).

Восемь прежних операционных потолков расходов остаются отдельными настройками.
Кредитный пакет не отменяет их; перед трафиком их нужно сопоставить с нагрузкой.

## 2. Подготовить целевую конфигурацию

Использовать [штатную инструкцию развёртывания](REPRODUCE.md), затем изменения
этого файла. Она описывает базовый стек на сентябрь; новые кредитные/Cloud.ru
контуры выше имеют отдельные квитанции. Не запускать команды целевого деплоя
на текущем VPS. Для старых данных нужны защищённый дамп и файлы/ключи вне Git.

В каталоге проекта создать приватный env-файл по `.env.example`, права 0600;
значения секретов не включать в отчёты, shell history или коммиты.
Сначала проверить обязательные переменные и конфликты портов штатными scripts,
собрать совместимые образы. Применять миграции собранным
`node packages/db/dist/migrate.js` по REPRODUCE §5: runtime-образ не содержит tsc.
Добавочная миграция 022 создаёт кредитный ledger, не переименовывает старые счета и не
выполняет массовый cutover. Не запускать старых writers поверх новых кредитных
записей. После продаж rollback требует совместимой сборки либо forward-fix;
удалять ledger или откатывать схему нельзя.

| Настройка | Значение или правило |
|---|---|
| `N5_BILLING_MODE` | legacy до принятой миграции/готовности; credits_v1 для целевого запуска новых кредитных аккаунтов |
| `N5_LLM_PROVIDER` | cloudru для нового явно выбранного LLM |
| `N5_LLM_MODEL` | deepseek-ai/DeepSeek-V4-Pro |
| `CLOUDRU_FM_API_KEY` | приватный FM-ключ; передаётся только worker-llm |
| `N5_STT_PROVIDER` | yandex после приёмки нового адаптера; cloudru сохраняет отказ при старте, отсутствие селектора сохраняет OpenRouter |
| `YANDEX_SPEECHKIT_API_KEY` | отдельный приватный SpeechKit-ключ только worker-stt; его наличие само по себе не выбирает провайдера |
| `S3_ENDPOINT`, `S3_PUBLIC_ENDPOINT` | https://s3.cloud.ru |
| `S3_REGION` | ru-central-1 |
| `S3_ACCESS_KEY` | tenant_id:key_id, приватное составное значение |
| `S3_SECRET_KEY` | Key Secret Object Storage, отдельный от FM |
| `S3_BUCKET` | свой приватный бакет |
| `S3_FORCE_PATH_STYLE` | false |
| `N5_METRIKA_COUNTER_ID` | оставить пустым до этапа3 |

FM-ключ проверен авторизованным каталогом, SpeechKit — коротким реальным STT.
Это не приёмка целевого Cloud.ru Object Storage. Для бакета нужны CORS под точный origin приложения,
многочастная загрузка и lifecycle незавершённых multipart по REPRODUCE §5.
Хранение остаётся приватным, выдача — подписанными ссылками; не открывать бакет
ради прохождения браузерного теста.

### Что осталось в выбранном российском pipeline

Cloud.ru Whisper в проверенных конфигурациях вернул фразы, но не слова;
это ограниченный результат проверок, не доказательство отсутствия любой
недокументированной возможности. Текущие подсветка слов и word-snapping
требуют таймкодов слов. Нарезка и субтитры целыми фразами возможны другим
контуром, но такой переход владельцем не выбран и здесь не реализуется.

Владелец выбрал другой STT в РФ и предоставил SpeechKit-ключ. Явный Yandex
API v3 RecognizeStreaming/FULL_DATA подтверждён короткой синтетической записью
и200с через собранный N5-адаптер. [Квитанция кода v4](features/cloudru-provider-foundation/05_completion.md)
включает независимое ревью, полные проверки, offline220с склейку/субтитры/FFmpeg.
До целевой приёмки нужны естественная русская речь и проверки полного
пользовательского пути на будущем сервере, а не ещё один неизменный synthetic probe.
DeepSeek и Object Storage остаются в Cloud.ru. Скрытого fallback нет.

## 3. Целевая приёмка, затем Метрика

На одной стартовой ВМ Cloud.ru и её сервисах выполнить защищённую запись:
загрузка → реальная транскрибация → выделение → рендер → скачивание.
Проверить восстановление базы/ключей, права, expiry, повторы, очередь, запас SSD.
Измерить SpeechKit attempts/15-секундные единицы, FM usage, хранение/операции/egress
и ресурсы обработки часа; сверить [плановые 57 ₽/час и стресс 62 ₽/час](research/unit-economics-20261026/unit-economics-summary.md)
со счетами и фактическим распределением загрузок. Это не полная цена с ВМ,
комиссией, налогами и привлечением. Рост 100→1000 пользователей
привязать к очереди и замерам, без обязательной второй ВМ ради моделей.
Экономный кандидат пилота — одна ВМ 2 vCPU / 4 ГБ / 60 ГБ; достаточность ещё нужно
измерить. Старые размеры из сентябрьского REPRODUCE не означают обязательную
покупку: [актуальные расчёты ресурсов](research/unit-economics-20261026/README.md).

Затем создать свой счётчик и 4 цели, передать его публичный ID в web runtime,
проверить согласие и обычный transport, после этого наличие целей в кабинете:
[инструкция](features/acquisition-analytics/cloudru-launch.md).
HTTP200 и вызовы wrapper не доказывают приём; оплаты сверять с ledger.

## 4. Пилот после технической приёмки

Один Telegram-канал/сообщество → Старт 990 ₽ / 300 кредитов (5 часов) → нарезка с
русскими субтитрами → автор еженедельного видеоподкаста.
Размещение и бюджет согласовать отдельно. Считать расходы канала, всех проб,
обработок, комиссии и постоянной инфраструктуры. При прежних предположениях
канала и полном разовом 30-минутном trial новый CAC — 690 ₽; сценарий с
10% оплат убыточен, порог около 12,68%: [пересчёт](research/acquisition-20261026/economics.md). LTV
неизвестен; выбор SEO/referral либо B2B делать по результатам пилота.
