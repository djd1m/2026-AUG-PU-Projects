## Decision (alternative-provider shortlist; see later GigaASR addendum)

**Recommend Yandex SpeechKit v3 as the first RF alternative to qualify, prioritizing its word-capable gRPC `RecognizeStreaming` with `FULL_DATA`, not v1 synchronous or an assumed async-only design.** It has an explicit word/phrase timing schema, Russian general model, MP3 support and no required extra bucket for this path. It adds a gRPC/protobuf client boundary and a tighter provider input limit. Runtime fit under N5's 120-second request budget still needs a separately authorized real probe; documentation is not a latency or N5-quality pass.

If absolutely no gRPC dependency is acceptable, Yandex v3 REST asynchronous inline upload is documented, but requires a deliberate operation/poll/recovery design. Its possible 24-hour completion conflicts with the current 30-minute job contract. Do not silently hide this behind a 120-second transcribe wrapper or blindly resubmit timed-out jobs.

T-Bank VoiceKit is a useful second candidate because whole-file synchronous recognition with word timing is documented. Its exact REST STT wire contract, RF data-plane location and current account onboarding conditions need confirmation before selecting it over Yandex. SaluteSpeech has genuine word alignment docs but **new-client access is closed**; it is not a practical new-account choice.

**No candidate is READY or runtime-accepted.** No free or paid inference is authorized by this research.

## Yandex: verified fast path versus incompatible shortcuts

[Y1] [Official v3 streaming reference](https://aistudio.yandex.ru/ru/docs/speechkit/stt-v3/api-ref/grpc/Recognizer/recognizeStreaming) documents `audio_processing_type=FULL_DATA`: “Process audio after all data was received.” It accepts MP3 containers. Its word times are described as estimates in milliseconds; phrase alternatives have their own text/start/end. Normalized refinements are separate events associated with a final index. No extra alignment model or invented word boundaries is required by this schema.

[Y2] [Official quotas/limits](https://aistudio.yandex.ru/ru/docs/speechkit/concepts/limits): streaming max 5 minutes, 10 MB, one channel; synchronous max 30 seconds, 1 MB, one channel; async max 4 hours, 1 GB via bucket or 60 MB when supplying the file in a v3 body. Results retention is 3 days. Async status API v3 is limited to 5 requests/second; submit limit is 500 requests/hour. These are provider limits, not permissions to enlarge N5's limits.

The [streaming guide](https://aistudio.yandex.ru/ru/docs/speechkit/stt/streaming) recommends sending audio at approximately its real-time rate and says a >5-second sending gap can close the session. In contrast, the [official file-stream example](https://aistudio.yandex.ru/ru/docs/speechkit/stt/api/streaming-examples-v3) reads/yields successive chunks without an explicit sleep, although that example selects REAL_TIME. This is **not evidence of a FULL_DATA latency guarantee** or a general pacing exemption. Qualify FULL_DATA with a known 180-second fixture under the existing 120-second cancellation budget; if unsuitable, root must choose an explicit smaller provider chunk policy or async architecture. No automatic mode/provider fallback.

[Y3] [Official async result schema](https://aistudio.yandex.ru/ru/docs/speechkit/stt-v3/api-ref/AsyncRecognizer/getRecognition) explicitly gives JSON word text/startTimeMs/endTimeMs, plus phrase text/start/end and language estimates. These numeric strings must be checked then divided by 1000 for N5 seconds. A stream of provider results must be parsed as documented; do not guess one arbitrary JSON envelope or concatenate duplicate partial/refinement events.

The [v1 synchronous API](https://aistudio.yandex.ru/ru/docs/speechkit/stt/api/request-api) explicitly returns only `{"result": <recognized text>}` and accepts LPCM or OggOpus, not MP3. Its 30-second/1-MB limit is separate from v3 streaming. **Smaller v1 chunks cannot solve N5's real-word requirement**; the documented response has no word timing. Do not derive words/times from plain text.

[Y4] [Supported models/languages](https://aistudio.yandex.ru/ru/docs/speechkit/stt/models) document the stable `general` model and `ru-RU` (default); rc/deprecated are separate tags. This confirms Russian support, not measured podcast WER, proper-name quality, diarization or subtitle readability. N5-specific quality and timing-origin accuracy remain unmeasured. Request ru-RU and use actual returned language evidence or explicit request-derived metadata under a future reviewed adapter contract.

[Y5] [SpeechKit quickstart](https://aistudio.yandex.ru/ru/docs/speechkit/quickstart/) requires an ACTIVE/TRIAL_ACTIVE billing account. [SpeechKit auth](https://aistudio.yandex.ru/ru/docs/speechkit/concepts/auth) supports a service-account API key in `Authorization: Api-Key ...` or IAM token. Grant `ai.speechkit-stt.user` on its folder; a service account uses its own folder rather than an arbitrary caller folder ID. [API-key creation](https://yandex.cloud/ru/docs/iam/operations/authentication/manage-api-keys) is the official creation guide. Account/key creation and grant use are owner actions, not executed here. No permanent STT free allowance or grant eligibility/amount for this owner was verified; unknown is null.

[Y6] [v3 REST submit schema](https://aistudio.yandex.ru/ru/docs/speechkit/stt-v3/api-ref/AsyncRecognizer/recognizeFile) documents POST `https://stt.api.cloud.yandex.net/stt/v3/recognizeFileAsync`, inline bytes `content` or `uri`, `recognitionModel.audioFormat.containerAudio.containerAudioType=MP3`, model general. Thus v3 inline can keep existing Cloud.ru storage. Do not choose v2 URI upload assuming an arbitrary Cloud.ru presigned URL works: [v2 docs](https://aistudio.yandex.ru/ru/docs/speechkit/stt/api/transcribation-api) specifically restrict URI files to Yandex Object Storage. A new Yandex bucket is unnecessary for the preferred paths and is not authorized.

[Y8] [Async concept documentation](https://aistudio.yandex.ru/ru/docs/speechkit/stt/transcribation) says both standard `general` and `deferred-general` may take several minutes to 24 hours. Deferred mode has a lower queue priority. Polling/fetching an existing operation is not another ASR dispatch; resubmitting is a new potential charge. A timeout/abort after submit must not lead to a hidden duplicate or another customer credit debit. Existing worker retries/claims cannot simply treat an asynchronous submit as a completed Transcriber call.

## Processing/storage location: documentation versus inference

[Y7] [Yandex region documentation](https://yandex.cloud/ru/docs/overview/concepts/region) says the console/account determines region and user data remains inside its region. For RF use, choose the Russian console/account, not the Kazakhstan region. The official [data privacy page](https://yandex.cloud/ru/security/data-privacy) describes storage/processing in its Russian protected cloud and RF data centers. **Documented:** regional storage isolation and an RF processing offering. **Not independently established by this run:** a SpeechKit v3-specific contractual routing/subprocessor guarantee for a particular new account. Root/operator must bind the chosen account/endpoint to RF terms before real customer content; neither a Russian domain nor Russian-language model alone proves location.

[Y9] [AI Studio storage policy](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/security/data-storage) explicitly lists SpeechKit async recognition results retained for 3 days. Disabling improvement logging does not remove data needed to operate APIs. The linked [disable-logging guide](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/disable-logging) describes `x-data-logging-enabled: false`; its exact SpeechKit endpoint applicability should be confirmed during the bounded adapter contract/probe rather than promised from an LLM example. No zero-retention claim.

T-Bank: no primary document found in this bounded search specifying RF location of VoiceKit inference and uploaded/result storage. A Russian bank/service name and local legal incorporation do not establish data-plane geography. [Deferred-recognition docs](https://developer.tbank.ru/voicekit/api/speech-recognition/grpc/longRunningRecognize) document results retained 5 days and completion up to 24 hours; [upload docs](https://developer.tbank.ru/voicekit/api/speech-recognition/grpc/longrunnings3api) document uploaded files retained <=5 days. Synchronous input retention remains unknown.

SaluteSpeech: [corporate agreement](https://developers.sber.ru/docs/ru/policies/salutespeech-agreement) contains RF database localization obligations for personal data; that alone does not prove every uploaded ASR audio/result stays in RF. Precise inference/storage region and retention are unconfirmed here; new-client closure already excludes this route.

## T-Bank: precise evidence and remaining gaps

[T1] [Recognize reference](https://developer.tbank.ru/voicekit/api/speech-recognition/grpc/recognize) describes one whole-file protobuf request and response after processing, with no intermediate hypotheses. Word start_time/end_time are `google.protobuf.Duration`; convert validated seconds+nanos to N5 seconds. Phrase result start_time/end_time and first alternative transcript can supply usable segments without synthesizing timings. Explicit encoding, sample rate and channel count are required; max message 32 MB includes protocol payload, not a permission to exceed N5's 25 MB raw limit.

[T2] [Technical STT overview](https://developer.tbank.ru/voicekit/api/speech-recognition) lists MP3 and one/two channels, and says models were trained on Russian call-center conversations. Domain/quality fit for long podcasts is unmeasured; no marketing WER is adopted as N5 acceptance. [Official tutorial](https://developer.tbank.ru/voicekit/api/speech-recognition/stttutorial) gives gRPC endpoint `api.tinkoff.ai:443`. Exact current REST STT mapping/codec/size contract was not established; do not adapt the TTS REST example or auth page's illustrative GET into a verified STT POST.

[T3] [Onboarding](https://developer.tbank.ru/voicekit/intro) allows recognition for individuals/legal entities but instructs registration plus a request for required documents before generating API_KEY/SECRET_KEY. [Authorization](https://developer.tbank.ru/voicekit/intro/authorization) specifies locally signed HS256 JWT with API_KEY as kid, SECRET_KEY signing and STT audience `tinkoff.cloud.stt`. This needs a reviewed worker-only auth helper/client, not a new token service. No key or signup exists here; no current free allowance verified.

[Limits](https://developer.tbank.ru/voicekit/intro/limits) document 50 concurrent STT streams by default. [Release notes](https://developer.tbank.ru/voicekit/api/release-notes/releasenotesstt) dated 2023-12-22 describe continuity for connections shorter than 3 min 25 s and max request execution 1 hour. This is not a 120-second processing guarantee or a documented 180-second input-duration ceiling. Exact synchronous audio-duration cap is unknown.

Evidence availability caveat: official T-Bank search results exposed the above page text, including complete relevant request/response tables; repeated direct web opens timed out/502 and a local verified-TLS GET failed certificate-chain verification. No TLS verification was disabled, no source hash is invented, and indexed text is not a live API receipt. Prefer provider proto/schema confirmation before coding if choosing T-Bank.
