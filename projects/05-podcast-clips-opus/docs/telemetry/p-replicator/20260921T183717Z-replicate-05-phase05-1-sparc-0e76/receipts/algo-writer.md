## Расхождения — ВХОД ДЛЯ СВЕРКИ КООРДИНАТОРА

Ничего из перечисленного я не правил: `Specification.md` заморожена, `canon.md` и
`Architecture.md` принадлежат другим единицам. Те же семь пунктов продублированы в самом
`Pseudocode.md` разделом «Открытые расхождения» — чтобы читатель документа их видел, не открывая
квитанцию.

### А. Противоречие между документами (требует решения, а не редактуры)

- **Р-1 · Механизм входа.** `FR-AUTH-001` описывает вход ОДНОРАЗОВОЙ ССЫЛКОЙ («пользователь
  получает одноразовую ссылку, срок её жизни ограничен, повторный запрос не продлевает
  предыдущую»). `Architecture.md`, раздел «Security Architecture», называет «почта + пароль
  (bcrypt)». Это два РАЗНЫХ механизма, а не два описания одного: у одноразовой ссылки нет поля
  пароля, у пароля нет срока жизни ссылки. Задание координатора называло bcrypt. Я реализовал
  механизм СПЕЦИФИКАЦИИ (она заморожена и владеет наблюдаемым поведением), поле назвал
  `account.auth_secret_hash` — оно пригодно для любого из двух исходов. **Решение нужно принять
  явно**, иначе Phase 3 получит два разных экрана входа из двух документов.
- **Р-5 · Момент списания `user_uploads`.** `model-cost-contract.md`: «Три ключа списываются в
  одной транзакции: `user_minutes`, `global_minutes`, `user_uploads`». `FR-INGEST-001`: `video.create`
  «создаёт `video` со статусом `uploading`, СПИСЫВАЕТ `user_uploads` и возвращает `video_id`» —
  то есть раньше, на создании. Списать дважды было бы дефектом. Я развёл: `user_uploads` — на
  создании (как в требовании), минутные ключи — на завершении загрузки, в одной транзакции и
  каждый одним атомарным оператором.
- **Р-6 · Потолок попыток против кнопки «повторить».** `FR-RENDER-003` ограничивает рендер двумя
  попытками; `FR-RESULT-001` даёт кнопку «повторить» без потолка. Я отнёс потолок 2 к
  АВТОМАТИЧЕСКИМ попыткам очереди, а повтор по кнопке ограничил квотами минут и вызовов — то есть
  деньгами, а не счётчиком. Это ИНТЕРПРЕТАЦИЯ, а не вывод из текста.
- **Р-7 · Событие активации атрибуции.** `FR-GROWTH-002` объявляет переход `pending → activated`,
  но НЕ называет событие, которым он происходит. Я назначил активацией первый `video.status = done`
  у привязанного аккаунта. Требует подтверждения владельцем: от этого определения зависит второй
  счётчик кабинета партнёра.

### В. Отклонения от формулировок задания координатора

- Задание называло коды ошибок «`refused(scope)`, `conflict`, `invalid`, `not_found`,
  `consent_required`» — воспроизведены дословно как закрытый список. Добавлен `401` для маршрута
  выхода и `503` для `/health`: это коды ТРАНСПОРТА, а не тела `{ error: { code } }`, и списка они
  не расширяют.
- Задание требовало «атомарное списание трёх ключей квоты одним оператором» в `CompleteUpload`.
  Написано: три ключа в ОДНОЙ транзакции, каждый — ОДНИМ оператором (один оператор на три разные
  строки `quota_counter` с разными пределами невыразим), причём `user_uploads` списан раньше —
  см. Р-5.
- Алгоритмов 33 вместо названных 18+: добавлены `IngestFromUrl`, `RecordModelSpend`,
  `CreateClipLink`, `IssueSignedObjectUrl`, `ReadVideoProgress`, `ListClipsForScreen`,
  `SendClipToTelegram`, `ComputeWatermarkGeometry`, `PurgeExpiredClips`, `RevokeOrExpireGuestPack` —
  иначе 8 ключей (`FR-INGEST-003`, `FR-RESULT-003`, `NFR-OPS-001`, `NFR-SEC-001`, `NFR-PERF-002`,
  `FR-TARIFF-003`, `FR-GUEST-003`, `FR-GROWTH-005`) не имели бы заявителя.
- Из клона взяты структура и грабли: потоковое извлечение звука, чанкинг со смещениями, ASS с
  переносом по словам, цепочка фильтров, дочерний процесс ffmpeg с таймаутом. НЕ взяты автопостинг,
  пользовательские ключи моделей, модели Cloud.ru. Метка клона (правый нижний угол,
  полупрозрачная, БЕЗ адреса) заменена на левый нижний с подложкой и короткой ссылкой — ADR-004.

## Что НЕ проверено и проверено быть не могло

- **Ни один шаг не измерен на живом стенде.** Ни 20 минут на часовой записи, ни 15-минутный
  таймаут ffmpeg, ни резерв «3× размера», ни поведение подписей Cloud.ru. Это проектный план.
- **Покрытие сценариев доказывает ВЗАИМНОЕ НАЗЫВАНИЕ, а не корректность.** 32 из 32 означает
  «про каждый сценарий что-то написано», а не «написанное его реализует». Алгоритм, упомянувший
  идентификатор и реализующий его неверно, этой проверкой не ловится — это слой 3–4.
- **Совпадение множеств ключей `REQUIREMENT`** доказывает связность двух документов, а не то, что
  алгоритм выполняет требование по смыслу.
- **Цены поставщиков** взяты с их тарифных страниц на 2026-09-21 и верны на эту дату; расчёт
  «порядка 600 ₽/сутки при полном потолке» — арифметика по этим ценам, а не наблюдение счёта.
- **Скачивание по ссылке с VK Видео / Rutube** остаётся `UNCONFIRMED` (`Architecture.md`):
  алгоритм `IngestFromUrl` описан, но в Phase 3 не входит, пока вердикт не изменится.
- **Число 32 символа на строку субтитров** взято из задания координатора; в клоне было 35, в
  каноне числа нет. Проверяется только глазом на телефоне.
- Вторичные числа рынка (рост видеоподкастов, ≈ 40 % брака у инструментов класса) в требования
  НЕ перенесены и целевыми показателями не стали.
