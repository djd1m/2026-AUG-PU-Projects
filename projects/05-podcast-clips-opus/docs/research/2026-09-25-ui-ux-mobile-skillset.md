# Какой набор навыков брать для mobile-friendly, very responsive UI/UX — исследование роя

**25.09.2026.** Запрос владельца: «провести в отдельном рое агентов ресерч, какой скилл-сет оптимальнее
всего использовать для данного проекта, чтобы сделать UI и UX mobile friendly very responsive»;
рекомендация посмотреть https://github.com/mickadesign/fluid-functionalism; «вдохновляйся примерами UI из
предварительного ресерча». Рой — пять исследователей Anthropic (Opus), каждый сдал файл-квитанцию
(5/5, `Status: completed`); сводку перепроверил Codex (OpenAI) — раздел 7.

| Единица | Что делала |
|---|---|
| U1 | разбор fluid-functionalism |
| U2 | аудит текущего UI: код + 29 скриншотов стенда на 390×844, 360×740, 768×1024, 1280 |
| U3 | инвентаризация навыков на машине и внешних кандидатов |
| U4 | методика и детерминированные проверки |
| U5 | закономерности из предварительного ресёрча (OpusClip, CJM D) |

## 1. Главный вывод

**Tailwind/shadcn/fluid-functionalism не брать; взять методику + собственную проверку.** Проект уже
живёт на своём CSS с токенами (`globals.css`, 90 строк, `:root`-переменные, `min-height:46px` у
контролов), горизонтального скролла не найдено в обследованной выборке (3 страницы × 360/390/768/1280; 320 px, экран записи и `/g/` не измерялись — поправка Codex). Проблемы — в деталях вёрстки и в
невоплощённых решениях собственного ресёрча, а не в отсутствии фреймворка.

## 2. fluid-functionalism — брать только принципы (U1)

Это реестр компонентов shadcn/ui на Tailwind v4 + Radix/Base UI + framer-motion, MIT, v0.1.0, 918★,
последний коммит 2026-09-15. «Fluid» здесь — прежде всего анимация и отклик на наведение; мобильные решения есть (выдвижная панель, определение сенсорного ввода — поправка Codex), но
нет `clamp()`, safe-area, тач-целей ≥ 44 px (контролы 36/28 px). Без Tailwind несовместим — пришлось
бы перестраивать UI. Переносимые принципы: уменьшать анимацию при `prefers-reduced-motion`, а не
выключать; тач определять через `(pointer: coarse)`; `svh`/`dvh` вместо `vh`; боковая панель на
телефоне — выдвижная.

## 3. Оптимальный набор (U3) — 4 элемента, 0 новых рантайм-зависимостей

| # | Элемент | Роль | Цена |
|---|---|---|---|
| 1 | Проектный навык **`responsive-ui`** (написать самим): mobile-first; fluid-токены шрифта и отступов (Utopia) в `:root`; 4–5 примитивов Every Layout (Stack, Cluster, Switcher, Center) по CUBE CSS; container queries для карточек клипов; правила: тач-цель ≥ 44 px, инпуты ≥ 16 px, `dvh/svh`, `clamp()` в `rem`, `prefers-reduced-motion`; контрольные ширины 320/390/768/1024/1440 | методика для агента-генератора (слой 2) | ~1 ч + ~1 ч перевод `globals.css` (оценка) |
| 2 | **`frontend-design`** — плагинная версия; убрать конфликт с устаревшей локальной копией (запрещает системные шрифты, ничего о mobile) | визуальный план, тексты | 0 |
| 3 | **`scripts/check-responsive.mjs`** на Playwright, уже стоящем на машине: числовые инварианты, не картинки; коды 0/1/2 | проверка, слой 1 | ~2–3 ч (оценка) |
| 4 | **axe-core** в том же скрипте (`target-size` включить ЯВНО — по умолчанию выключено) | доступность, слой 1 частично | ~30 мин, пакет только в тестовом скрипте |

Не брать: Tailwind + shadcn + fluid-functionalism (смена парадигмы без выигрыша в адаптивности),
Open Props (дублирует Utopia), BackstopJS (пиксельный дифф нестабилен); Lighthouse — вручную перед
релизом.

## 4. Проверки R1–R7 и критерии готовности G1–G10 (U4)

Детерминированные (слой 1), каждая испытывается внедрённым дефектом:
R1 нет горизонтального скролла (7 ширин × 5 маршрутов) · R2 тач-цели основных действий ≥ 44×44, прочих
≥ 24×24 или зазор (WCAG 2.5.8) · R3 нет перекрытий целей · R4 axe wcag2a…wcag22aa, 0 serious/critical ·
R5 `font-size` полей ≥ 16 px, viewport без запрета зума, `playsinline` у видео · R6 превью 9:16 целиком в
экране на 390×844 и 1440×900 · R7 статический линт CSS (`100vh` без `svh/dvh`; `clamp` в px или max < 2×min).

Критерии готовности: G1–G8 — слой 1 (R1–R7 + Lighthouse mobile: LCP ≤ 2,5 с, CLS ≤ 0,1, TBT ≤ 200 мс
на `/c/` и `/g/`; `reduced-motion`); **G9 «одна рука»** и **G10 встроенные браузеры Telegram iOS/Android
и VK Android** — только ручной прогон на телефонах (эмуляции WebView нет).

## 5. Что нашёл аудит (U2) — объём работы M

**high:** чекбоксы растянуты на всю ширину правилом `input` (`globals.css:11`); у полей 14 px
(`globals.css:5,28`) и у `select` шрифт браузера → автозум iOS (выведено из CSS, WebKit не запускался).
**medium:** порядок кабинета ставит главное действие не первым (`dashboard/page.tsx:19`); слова рвутся
в счётчиках партнёра (`globals.css:88-89`); «Удалить аккаунт навсегда» выглядит как обычная кнопка
(`AccountDeletion.tsx:41`); нет отступов между секциями; на iPhone 13 кнопка «Войти» ниже первого экрана;
на `/c/` при 360×740 призыв ниже первого экрана; кнопки карточки клипа без промежутка; превью 9:16 на
телефоне обрезано ограничением высоты; `.landing` на `100vh`.
Не проверены: экран записи и `/g/` вживую (у аудит-аккаунта нет записей) — только по коду.

## 6. Что из собственного ресёрча не воплощено (U5)

Доли телефонов и «одной руки» в ресёрче нет. Есть: «обрабатывают с компьютера, публикуют с телефона»
(`Specification.md:210-214`); `/c/` и `/g/` обязаны работать во встроенных браузерах VK/Telegram без
JS; **ни одна фича не проверялась в мобильном браузере** (отчёты фич 7, 9, 10, 11, 8).
Не воплощены принятые решения — и отклонение нигде не записано:
- лендинг с демо-клипом вместо формы входа (FR-LOOK-007/011, CJM D);
- тёмная тема как основная (FR-LOOK-008), шаг отступов 4;
- «Отправить гостю» на каждой карточке — FR-RESULT-002 выполнено ЧАСТИЧНО (плеер, оценка, скачать, ссылка есть; «гостю» нет — поправка Codex);
- оценка плашкой на кадре; прогресс лентой стадий; первая карточка как момент ценности.

Идеи в порядке U5: оценка плашкой + объяснения раскрытием → первая карточка → липкая нижняя панель
«Скачать · Ссылка · Гостю» + галочка «гость» на карточке → карусель 9:16 со scroll-snap → лента стадий →
лендинг с демо-клипом → тёмная тема (начать с экрана клипов) → музыка нижней шторкой → убрать `video_id`
с экранов; после каждой — проверка на телефоне из VK и Telegram.

## 7. Перепроверка Codex (OpenAI) — «согласен с поправками»

Полный ответ: `docs/research/2026-09-25-ui-ux-mobile-skillset-codex-review.md`. Поправки, принятые в план:
- **Главный риск — зелёный скрипт на неполных данных.** Первым шагом — воспроизводимые данные (запись,
  клипы, гостевой пакет у тестового аккаунта) и базовый проход на телефоне, затем правки и автоматизация.
- Playwright, браузер и axe **закрепить в тестовых зависимостях проекта**: брать установку соседнего
  проекта невоспроизводимо (противоречит `REPRODUCE.md`).
- Перевод всего CSS на Utopia/CUBE — только по конкретной проблеме, не заранее; `frontend-design` —
  по желанию.
- R6 (превью 9:16) и R7 (линт `clamp`/`100vh`) — **предупреждения, не отказ**: не доказывают видимость
  кадра и масштабируемость; принимать масштабирование — увеличением текста до 200 %.
- R2/R3: учитывать кликабельный `label` и прокрутку (иначе `elementFromPoint` даёт ложные нарушения);
  R5 — только текстовые поля и `select`; R4: ноль serious/critical ≠ соответствие WCAG — плюс клавиатура и фокус.
- G10: `/c/` сейчас — картинка и призыв, без воспроизведения; требовать там плеер — расширение
  функциональности, а не проверка.

## 8. Предлагаемый план (решает владелец)

0. **Данные и базовый проход (S):** тестовый аккаунт с записью, клипами и гостевым пакетом; ручной проход
   на телефоне (iPhone + Android, из Telegram и VK) — список того, что реально мешает.
1. **Фундамент (S):** короткий навык `responsive-ui`, `check-responsive.mjs` + axe с Playwright в тестовых
   зависимостях проекта; разрешение конфликта `frontend-design`; скрипт — базовая линия.
2. **Исправления аудита (M):** три high + medium из раздела 5; скрипт зелёный на 320–1440.
3. **UX из CJM D (L, по одному):** карточка клипа (плашка оценки, нижняя панель с «Гостю»), лента стадий,
   лендинг с демо-клипом, тёмная тема — каждый шаг с ручной проверкой на телефоне в VK/Telegram.

Решения, которые нужны от владельца: брать ли тёмную тему (FR-LOOK-008) или записать отклонение; нужен
ли лендинг с демо-клипом до входа; порог N тапов для «одной руки» (G9).
