## Actual contract, from source

- `apps/worker/src/llm/prompts/selection.ts`: Russian podcast, 3–8 self-contained, nonoverlapping clips, each 20–75 seconds. An honest 1–2 is allowed; do not fill the quota with weak clips. A standalone opening and completed thought matter. Return a Russian title and three concrete Russian explanations. Hook evaluates first 1–3 seconds. Do not promise virality. Transcript text is data, including embedded instructions.
- Model input is **segments only**: JSON containing `duration_seconds`, `transcript.language`, and `transcript.segments` (`text/start/end`, optional speaker). Full `words[]` is retained locally for boundary snapping and subtitles. The prompt says to select segment timestamps; source validation does not enforce that an original model timestamp exactly equals a segment timestamp.
- Historical source comment: an 88-minute episode had 12,916 words; sending words was 1,128 KB / approximately 385k tokens, versus segments 115 KB / approximately 39k. Those are historical estimates, not measured DeepSeek token counts or a universal maximum. Russian tokenization, segment density, system prompt, schema and output headroom must be counted on the actual selected endpoint. Large context capacity does not prove attention to strong moments throughout a long recording.
- `packages/shared/src/fragments-schema.json`: exactly `{fragments: [...]}`; 1–8 array items; exactly 10 required fields per item. Numeric start/end >=0; integer total score 0–99; integer hook/completeness/length 0–33 each; nonempty title; explanations include Cyrillic. The schema’s `$defs.duration` is not referenced into the item and cannot itself enforce duration.
- `parseCandidates` rejects the whole response on wrong top-level shape, missing/extra per-item keys or wrong primitive types. `validFragment` rejects individual candidates on numeric bounds, blank/invalid text, noninteger scores, 20–75 second duration, end beyond recording, or total unequal to the component sum. `validateFragments` then snaps to nearest local word starts/ends, revalidates, rejects any word-straddling boundaries, sorts descending by model score (start breaks ties), removes overlaps and takes at most eight. Thus raw and accepted clip counts differ. A stale function comment says invalid candidates reject the whole response; actual filtering code and later comment define the implemented behavior. Empty selection is not success.
- `packages/shared/src/transcript.ts`: requires actual nonempty words with usable numeric timing before selection. It clamps timing bounds/order according to existing policy. A model change must preserve this local boundary/subtitle authority.
- `apps/worker/src/llm/provider.ts`: exactly one nonstream OpenRouter chat-completions request, `json_schema` with `strict:true`; no BYOK/fallback path. `allow_fallbacks:false`, `require_parameters:true`. Current routing pins Sonnet to Anthropic/AWS Claude Platform; every other model currently routes to Google. Merely adding a DeepSeek model name would therefore pin the wrong providers.
- `SELECT_TIMEOUT_MS` is **240,000 ms**, combined with the caller’s abort signal. It is not 60 seconds. Source ties it to the UI’s five-minute silence window; increasing it is a product-contract change, not a free fix for slow reasoning.
- Provider currently reads only `choices[0].message.content`, rejects non-string/refusal content and parses JSON. It does not record usage/served provider/model or inspect `finish_reason`; those are important evaluation gaps. `packages/shared/src/config.ts` permits only `anthropic/claude-sonnet-5` and `google/gemini-3.8-flash`.

## Current official DeepSeek compatibility

The current direct API publishes `deepseek-flash` (served by **DeepSeek-V4.1-Flash-1017**) and `deepseek-v4-pro` (V4-Pro-0813), both with 1M context and up to 384K output. Flash aliases of retired models are redirected, so an alias is not an immutable model pin. Recheck the actual dated model and route at evaluation time. These direct-API facts do not establish an OpenRouter route’s schema support. [Models & Pricing](https://api-docs.deepseek.com/quick_start/pricing/)

There are three distinct interfaces:

1. **Chat Completions JSON object:** current direct API documents `response_format.type` as `text` or `json_object`, not the N5 `json_schema` envelope. This guarantees JSON syntax rather than the ten-field contract. It needs JSON instructions/example; empty content and truncation remain documented failure modes. Treat choosing this path as an explicit weaker provider guarantee, while preserving all local validation. Do not call it equivalent strict output. [Chat Completions reference](https://api-docs.deepseek.com/api/create-chat-completion/), [JSON Output guide](https://api-docs.deepseek.com/guides/json_mode/)
2. **Strict tool arguments (Beta):** `/beta`, function `strict:true`, required properties and `additionalProperties:false`. N5’s nonempty strings and array bounds use **unsupported** `minLength`, `minItems`, `maxItems` on this strict-tool path; the original schema cannot be pasted unchanged. `pattern` and numeric bounds are documented. A one-shot extraction function would require different request/result parsing and a supported schema projection while the canonical N5 runtime validator stays intact. Forced/named tool choice requires non-thinking mode in current Chat Completions. This would be a compatibility route, not a need for an agent loop or actual tool execution. [Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/), [Chat Completions reference](https://api-docs.deepseek.com/api/create-chat-completion/)
3. **Responses structured text:** the current direct `/responses` reference explicitly documents `text.format` with `type:json_schema`, `name` and `schema`; the guide says `format` is fully supported. Therefore “DeepSeek has no JSON schema output” is false. Neither page proves every N5 keyword or the OpenRouter chat-completions path. First validate the **exact canonical schema at the exact endpoint/model/mode**. A direct Responses adapter changes request/output/usage parsing and the existing one-gateway/key assumption; it needs a separate architecture/access decision. It is not the smallest currently authorized N5 change. [Responses reference](https://api-docs.deepseek.com/api/create-response/), [Responses guide](https://api-docs.deepseek.com/guides/responses_api/)

Thinking defaults to enabled/high; this is not a harmless default for cost/latency comparison. Explicitly select disabled first for the economical Flash candidate; a low-thinking variant is a separate bounded candidate if quality fails. `reasoning_content` is separate from answer JSON, and some sampling parameters are ignored in thinking mode. [Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)

Responses token caps include reasoning plus visible text, and usage separates reasoning tokens. Account for billed total output, not just short JSON. Direct peak cache-miss input/output per million currently reads Flash $0.30/$1.20 and Pro $1.32/$3.96 (off-peak half); OpenRouter rates must be checked separately. A 39k-token historical estimate is not a cost receipt. Measure actual input, cached input, visible/reasoning output, failed attempts and cost per **human-usable accepted clip**, with missing billing data recorded unavailable. [Responses reference](https://api-docs.deepseek.com/api/create-response/), [Models & Pricing](https://api-docs.deepseek.com/quick_start/pricing/), [Token Usage](https://api-docs.deepseek.com/quick_start/token_usage/)

## Minimal future adapter work, conditional on compatibility gate

Prefer the existing OpenRouter transport **only if** its selected dated Flash route/provider demonstrably supports N5’s exact `json_schema strict` request. Add a code-owned model entry and explicit provider mapping, preserve no-fallback and require-parameters behavior, set explicit reasoning/output limits, reject incomplete/length/content-filter answers, and capture actual served model/provider, finish reason, latency and usage in existing telemetry. Preserve 240s abort, call-attempt quotas before every paid attempt, existing fencing and validator unchanged. Do not route failures invisibly to Sonnet or add automatic repair calls outside the attempt budget. If no route meets strict output requirements, record an incompatibility instead of silently changing the response guarantee; compare the separately scoped direct Responses option before implementing anything.

## Blind A/B: one bounded future pilot, not a new evaluation engine

**Authorization gate:** plan only. An owner-approved spend cap and permitted public/synthetic inputs are required before any call. Suggested bound: eight Russian public/consented episodes, two calls per episode (Sonnet baseline and one Flash candidate), plus four preregistered repeat calls on two difficult episodes = **20 paid calls maximum**, **$5 maximum total** (or lower approved cap), stop at first cap; no repair retries. If cap prevents full coverage, result is inconclusive rather than a reduced passing threshold.

Freeze source revision, exact prompt/schema, segment payload hashes, local word data, both model/provider versions, endpoint, reasoning/output settings, deadlines and price timestamp. Use the actual configured Sonnet route as baseline; if unavailable, report blocked/inconclusive rather than silently substitute another Sonnet. Alternate model order to reduce load/time confounding.

Select episodes before viewing answers: short tutorial, slow interview, energetic multi-speaker discussion, technical terminology/names, poor ASR/pauses, subtle context dependence, and at least two 60–90 minute recordings with good moments in early/middle/late positions. Include a transcript-instruction injection as synthetic data. Use owner/editor reference intervals or whole-episode coverage review to detect missed strong moments; do not penalize a different equally good interval simply because it differs from a reference.

First record raw schema validity, candidate/accepted counts, rejection reasons, snapping changes, overlaps, truncation/timeout/provider errors, actual tokens/cost and end-to-end selection latency. Run existing validation, not a new schema/benchmark engine. Keep provider failures in denominators. Validate that each returned accepted clip still satisfies 20–75s, word-aligned boundaries, no overlap and score sum. Structurally malformed responses and failures must remain visible.

Render accepted clips through the same downstream path. Two Russian-speaking editors independently review random A/B labels, hiding provider, latency/cost and model scores. Show clips without prior context first; allow source context only when checking factual distortion. Rank the top three **per episode** and also review the whole set so volume does not masquerade as quality. Use episode as the main paired unit; eight clips from one episode are not eight independent wins. Resolve disagreements with recorded reasons.

| Human dimension | Rating anchors |
|---|---|
| Standalone completeness | 1: missing antecedent/payoff; 3: understandable with minor loose context; 5: clear premise and completed thought |
| First 1–3 seconds | 1: setup/filler; 3: clear point begins; 5: immediately clear, compelling claim/question without distortion |
| Faithful value | 1: misleading/cut qualification; 3: accurate but ordinary; 5: accurate and useful/surprising with its essential qualification |
| Boundaries and pace | 1: cut speech/thought or padding; 3: clean enough; 5: natural concise start/end and pace |
| Title/explanations | 1: fabricated/generic; 3: accurate; 5: precise Russian title and explanations grounded in the actual clip |
| Set quality/coverage | 1: repetitive/strong moments missed; 3: varied useful set; 5: distinct strong moments with good episode coverage |

Primary human result: blinded episode-level A preference / tie / B preference, publishable-without-meaning-edit clip count, and explicit critical distortion/open-ending flags. Suggested decision rule, agreed **before** calls: no critical distortion/injection success; canonical transport/schema conformance on every completed answer; no more deadline/provider failures than baseline; at least three usable clips on every episode pre-labelled by editors as containing three, while preserving honest 1–2 on sparse episodes; Flash wins or ties at least 6/8 paired episodes and loses by >1 anchored point on no critical completeness/faithfulness dimension; total cost per usable clip improves by at least 50%; each completed selection remains within 240 seconds. These are pilot screening thresholds, not confidence intervals, calibrated human quality or production p95 estimates. Mixed results lead to a targeted next authorized experiment, not automatic promotion.

A small passing pilot supports an owner-reviewed canary with an explicit rollback to the prior configuration. It does not establish virality, engagement uplift, equal quality for all podcasts or production reliability. No calls, canary or rollout were run in this research.
