# Контракт входящих вебхуков — N5 «КлипМейкер»

Дата: 2026-09-21. Правило: [`incoming-webhooks.md`](../../../.claude/rules/incoming-webhooks.md).
Проверка: `node ../../.claude/hooks/check-webhook-contract.cjs .`

**Входящие вебхуки:** нет

В продукт никто не звонит снаружи в неделю MVP: приёма денег нет (OWN-005 — «снять метку» ведёт на
экран интереса), Telegram-бот, если появится для «отправить себе в Telegram» (FR-RESULT-003,
Should), отправляет сообщения, а не принимает; Cloud.ru Object Storage уведомлений о событиях в
контракте не требует — завершение загрузки подтверждает наш собственный `POST /api/upload/complete`
по запросу самого пользователя.

## Что произойдёт, когда ответ изменится

Первый же платёжный провайдер (ЮKassa из клона, вторая волна) превращает этот файл в
обязательный: с ним придут все три класса отказа сразу — `подделка` (адрес публичен), `повтор`
(доставка «не менее одного раза» по построению), `перестановка` (события платежа приходят не по
порядку). В клоне вебхук ЮKassa уже есть (`apps/web/app/api/webhooks/yookassa`); при его пробуждении
здесь появятся строки на каждый класс с именем поля ключа повторности (`event.id` провайдера),
местом (`UNIQUE` по нему в таблице событий) и атомарным механизмом.
