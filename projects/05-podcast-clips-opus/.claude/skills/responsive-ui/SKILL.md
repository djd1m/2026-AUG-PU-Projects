# responsive-ui — как делать интерфейс КлипМейкера под телефон

Источник: исследование роя `docs/research/2026-09-25-ui-ux-mobile-skillset.md` (5 отчётов Anthropic +
перепроверка Codex), решения владельца OWN-016. Правило одно: **генерацию направляет эта методика,
приёмку делает скрипт** `scripts/check-responsive.mjs` — зелёный скрипт обязателен, «на глаз
выглядит нормально» не считается.

## Почему это важно именно здесь

Клипы публикуют с телефона; зритель приходит по короткой ссылке `/c/{code}` и гостевой `/g/{code}`
из Telegram и VK — во встроенном браузере, часто без JS. Кабинет открывают и с компьютера, и с
телефона. Значит: **первый экран на телефоне — главный экран продукта**.

## Жёсткие правила (нарушение — дефект)

| # | Правило | Почему |
|---|---|---|
| 1 | Mobile-first: базовые стили — для 320–430 px; расширение `@media (min-width: …)` | базовый случай — телефон |
| 2 | Нет горизонтального скролла на 320–1440 px | WCAG 1.4.10 |
| 3 | Основные действия (кнопки, ссылки-действия, чекбокс с подписью целиком) — ≥ 44×44 CSS px; прочие цели ≥ 24×24 или с зазором | WCAG 2.5.8 AA, Apple HIG 44 pt |
| 4 | `font-size` текстовых полей и `select` ≥ 16 px (`1rem`) | иначе iOS увеличивает страницу при фокусе |
| 5 | Высота экрана — `svh`/`dvh`, не голый `vh` | адресная строка мобильного браузера |
| 6 | Размеры шрифта — в `rem`/`clamp(rem, …, rem)`, не px; текст выдерживает увеличение до 200 % | WCAG 1.4.4 |
| 7 | Viewport без `user-scalable=no` и `maximum-scale` | запрет зума — нарушение доступности |
| 8 | У `<video>` — `playsinline`; превью 9:16 целиком в экране: `height: min(70svh, …)` + `aspect-ratio: 9/16` + `object-fit: contain` | иначе iOS открывает полноэкранный плеер, а кадр режется |
| 9 | Отступы от выреза iPhone: `padding: max(16px, env(safe-area-inset-left))` у краевых контейнеров и нижних панелей | чёлка и «домашняя» полоса |
| 10 | `prefers-reduced-motion`: анимацию **уменьшать** (короче, без смещения), а не выключать целиком | принцип fluid-functionalism |
| 11 | Тач определять `@media (pointer: coarse)`, а не по ширине | планшет с мышью и телефон в альбомной ориентации |
| 12 | `/c/` и `/g/` работают **без клиентского JS** (SSR) | встроенные браузеры VK/Telegram, `embed-contract` |
| 13 | Галочки и радио — **не** под общим правилом `input { width: 100% }`; кликабельна вся подпись | находка аудита 25.09 |
| 14 | Опасное действие («Удалить аккаунт») выглядит опасным и отделено отступом | находка аудита 25.09 |

## Токены и тема

Все цвета, отступы и размеры — переменные на `:root` в `apps/web/src/app/globals.css`. Тёмная тема
(OWN-016, FR-LOOK-008) задаётся переопределением тех же токенов: по умолчанию тёмная, светлая — по
`prefers-color-scheme: light` и явному выбору. Контраст текста ≥ 4,5:1 в ОБЕИХ темах (axe).

Шкала отступов — шаг 4 px (FR-LOOK-009): `--space-1: .25rem` … `--space-8: 2rem`. Плавные размеры —
`clamp()` в `rem`, пример: `--step-0: clamp(1rem, .95rem + .25vw, 1.125rem)`. Правило
«max ≥ 2 × min» из MDN — ориентир, не закон (проверка выдаёт предупреждение, не отказ).

## Примитивы раскладки (Every Layout, чистый CSS)

Не изобретать сетку в каждом компоненте — брать примитив:

```css
.stack > * + * { margin-block-start: var(--stack-space, var(--space-4)); }       /* вертикальный ритм */
.cluster { display: flex; flex-wrap: wrap; gap: var(--space-3); align-items: center; } /* кнопки в ряд, переносятся */
.switcher { display: flex; flex-wrap: wrap; gap: var(--space-4); }
.switcher > * { flex-grow: 1; flex-basis: calc((40rem - 100%) * 999); }           /* колонки → строки без медиазапроса */
.center { box-sizing: content-box; max-inline-size: 70rem; margin-inline: auto; padding-inline: max(var(--space-4), env(safe-area-inset-left)); }
```

Карточка клипа адаптируется к СВОЕЙ ширине, а не к экрану: `container-type: inline-size` на обёртке
и `@container (min-width: 28rem) { … }` внутри.

## Порядок экрана на телефоне

Главное действие — в первом экране без прокрутки (390×844). Кабинет: загрузка первой, лимиты
компактно под ней. Экран записи: сама запись и клипы первыми. Действия у карточки клипа — у нижнего
края, в зоне большого пальца.

## Навык `frontend-design`

В репозитории лежит вендорская копия `.claude/skills/frontend-design` (пакет skills-feature-adr) —
**не править**. Для этого проекта предпочтительна версия плагина `frontend-design:frontend-design`;
при конфликте **правила этого навыка важнее эстетики**: рабочий инструмент — прежде всего читаемость и
скорость на телефоне. Веб-шрифт — не больше одного, самохостинг через `next/font`.

## Чего не делать

Tailwind, shadcn, fluid-functionalism — не вводить без отдельного ADR: это смена парадигмы стилей без
выигрыша в адаптивности (исследование роя, раздел 3). Пиксельные сравнения скриншотов — не ассерт
(нестабильны между машинами); скриншоты — улики для человека.

## Приёмка

```bash
node scripts/check-responsive.mjs --base https://clipmkr.ru --fixture <ui-fixture.json>
# 0 — чисто; 1 — нарушения (маршрут, ширина, движок, селектор); 2 — проверка НЕ выполнена
```

Движки: WebKit (iPhone, движок Safari) и Chromium (Android); ширины 320/360/390/414/768/1024/1440;
маршруты `/`, `/c/{code}`, `/g/{code}`, `/dashboard`, экран записи. Тестовые данные —
`scripts/seed-ui-fixture.mjs` (`REPRODUCE.md`, шаг 8а). Остаток, который эмуляция не покрывает —
встроенные браузеры Telegram/VK (скачивание изнутри), — короткая проверка в конце, не блокер (OWN-016).
