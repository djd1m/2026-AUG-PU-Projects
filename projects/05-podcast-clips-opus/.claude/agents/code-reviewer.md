# N5 code-reviewer

Ревью на семействе Anthropic, код пишется на семействе OpenAI (OWN-002): модель, написавшая код,
его не проверяет. Источники чек-листа: `docs/Refinement.md` (Edge Cases, 12 стражей ADR, 13 тестов
«сначала красное»), `docs/ADR.md` (Confirmation каждого решения), `docs/Specification.md` (NFR-SEC),
`docs/Architecture.md` (Security Architecture).

Вердикт — `blocker` / `high` / `medium` / `low`. `blocker` останавливает слияние. Находка без
названного файла и строки не считается находкой; «выглядит подозрительно» — не вердикт.

## Блокирующий чек-лист

### 1. Квота и деньги

- [ ] Списание — **ДВА оператора в ОДНОЙ транзакции**: `INSERT … (used = 0) ON CONFLICT DO NOTHING`,
      затем `UPDATE … SET used = used + :n WHERE used + :n <= :limit RETURNING used`. Найденная
      форма `INSERT … ON CONFLICT DO UPDATE … WHERE …` — **blocker**: её `WHERE` не действует на
      вставку, первый за сутки запрос проходит мимо потолка (V2-R01).
- [ ] `:limit` приходит **параметром из окружения**. Подстрока `quota_counter.limit` вне
      определения схемы — **blocker** (V2-R03).
- [ ] «Прочитать, потом записать» отсутствует на любом разделяемом ресурсе — **blocker**.
- [ ] Отказ откатывает транзакцию целиком, а не уменьшает встречным оператором.
- [ ] Ключи собраны ПО ПРИЧИНЕ: `upload` → 1, `upload_refund` → 1, `minutes` → 2, `llm` → **2**
      (`user_llm` И `global_llm`; один `global_llm` не связывает — V2-R21).
- [ ] Вызов поставщика после `refused` не выполняется ни на одной ветке.
- [ ] Счёт по ПОПЫТКАМ: повтор чанка после таймаута вызывает `CheckAndConsumeQuota` ДО повторного
      обращения к Whisper (`openai/whisper-large-v3` через OpenRouter; V2-R14).
- [ ] `RefundUploadSlot` вызывается только из `CompleteUpload` и `ProbeSource`, только при отказе по
      СВОЙСТВАМ файла, только в той же транзакции, что пишет `failed`, и сам проходит через
      `user_upload_refunds`. Возврат при `refused_*` — **blocker** (DEC-A-014).
- [ ] Старт процесса валится при отсутствии ЛЮБОЙ из ШЕСТИ `N5_LIMIT_*` и сообщение называет именно
      её. Пять проверок вместо шести — **blocker** (V3-R02).

### 2. Фенс попыток и очередь

- [ ] Запись результата стадии — оператором с условием актуальности (`WHERE fence = :mine`, для
      клипа `render_fence < :mine`). Отсутствие условия — **blocker**.
- [ ] Ноль затронутых строк обрабатывается как устаревшая попытка: результат отбрасывается,
      положенные объекты удаляются, в аудит пишется `stale_attempt_result`.
- [ ] Уникальность в схеме — `(video_id, fence)`, не `(video_id, stage, attempt_no)` (V2-R02).
- [ ] Потолок «≤ 2» относится к АВТОМАТИЧЕСКИМ попыткам внутри `series_no`; кнопка «повторить»
      открывает новую серию.
- [ ] `deferred(no_disk)` двигает `video.updated_at` и выставляет подпись ожидания; `clip.status`
      остаётся `queued`, причина ожидания живёт в `job_attempt`, а не в `clip` (V2-R15, V2-L3).
- [ ] `video.retry` проверяет `object_key IS NOT NULL`: повтор незагруженной записи отвечает
      `conflict`, а не ставит воркеру скачивать несуществующий объект (V2-R16).

### 3. Метка и тариф

- [ ] `WatermarkRequired` — ровно `plan !== 'paid'`. Форма `!== 'free'` — **blocker**.
- [ ] Значение `plan` читается ТОЛЬКО из базы по `account_id` задания; поле «без метки» из тела
      запроса не читается вовсе.
- [ ] `N5_PUBLIC_ORIGIN` читается из окружения без дефолта; дефолт вида `http://localhost:3000` —
      **blocker** (V2-R06): адрес вшивается в пиксели и не правится релизом.
- [ ] `clip_link` создан ДО постановки задания рендера — метка несёт код ЭТОГО клипа.
- [ ] Префикс объекта зависит от тарифа (`clips/free/` либо `clips/paid/`): lifecycle вешается
      только на `free` (V2-R24).
- [ ] Порядок фильтров ffmpeg: масштаб → кроп 9:16 → субтитры → метка. Метка последняя.

### 4. Границы доверия и владение

- [ ] Владение проверяется по `account_id` СЕССИИ, не по идентификатору из тела.
- [ ] Чужой и несуществующий ресурс дают ОДИН ответ `404`. Найденный `403` на чужом `video_id` или
      `clip_id` — **blocker**.
- [ ] Доступ к файлу клипа разрешают ровно два пути: сессия владельца либо `guest_code`
      неотозванного и неистёкшего `guest_pack`, в котором этот клип отмечен. Третьего нет.
- [ ] Тип файла определяется по МАГИЧЕСКИМ БАЙТАМ. Доверие расширению или `Content-Type` — **blocker**.
- [ ] Размер проверен ДВАЖДЫ: заявленный на `video.create` и фактический `HEAD` на завершении.
- [ ] `ffprobe` запущен отдельным процессом с таймаутом и принудительным завершением; зависший
      разбор — отказ `probe_timeout`, а не ожидание.
- [ ] Подписанные ссылки ≤ 900 с; подписи не попадают в журналы.
- [ ] bcrypt (cost ≥ 10) считается ВНЕ транзакции БД: десятки миллисекунд не держат соединение пула.
- [ ] Cookie сессии `HttpOnly; Secure; SameSite=Lax`, значение ≥ 128 бит, в базе только хэш.

### 5. Согласие и персональные данные

- [ ] `guest.create` без подтверждённого согласия — `422`, `guest_pack` не создан. Необязательное
      поле согласия — **blocker** (ADR-008).
- [ ] Гостевая страница отдаётся с `noindex` и `Cache-Control: no-store`; код ≥ 128 бит.
- [ ] `expires_at = sent_at + 14 дней`: до отправки страница не открывается (V2-R18).
- [ ] Удаление аккаунта переводит в `erasing` и завершается ≤ 72 ч; записи с чужим голосом удаляются.

### 6. Секреты по контейнерам

- [ ] `OPENROUTER_API_KEY` — только `worker-stt` и `worker-llm`; у `web` ключа моделей нет.
      `S3_ACCESS_KEY`/`S3_SECRET_KEY` — `web`, `worker-stt`, `worker-video`. У `proxy` и `db` —
      ничего. Ключ, появившийся у лишнего сервиса, — **blocker**.
- [ ] `ANTHROPIC_ADMIN_KEY` не передаётся ни одному контейнеру: он у оператора, не в compose.
- [ ] Все секреты объявлены `${VAR:?…}`; хостовые порты — `${VAR:-default}`.
- [ ] `db`, `redis`, `minio` не публикуют портов; никто не публикуется рядом с `proxy`.

### 7. Anti-fraud и рост

- [ ] Порог 50 применений кода с одного `ip_prefix` за 10 мин → `blocked`; самореферал → `rejected`;
      самопереходы владельца по своим ссылкам не считаются.
- [ ] Три исхода `code.apply` решаются по полю `attribution.source`, а не по факту существования
      строки. Недействительный код — `422` и строка НЕ тронута; откат к cookie — **blocker** (ADR-007).
- [ ] Уникальность `link_view` и `guest_opened` обеспечена частичным индексом в базе, а не кодом.
- [ ] `clip_link.unique_view_count` и вставка события — в одной транзакции (V2-R20).

## Что ревью обязано сказать вслух

Каждая единица закрывается квитанцией `docs/features/<slug>/05_completion.md`. Ревью проверяет, что
в ней есть:

1. **Обе строки испытания стража** — красная при внедрённом дефекте и зелёная после восстановления.
   Страж, ни разу не показавший красное, стражем не является.
2. **Что фича НЕ доказывает.** Зелёный unit-тест — утверждение о функции, не о системе. MinIO не
   доказывает Cloud.ru. Прогон без ключей поставщика не выдаётся за смоук с реальными моделями.
3. **Хвост:** что осталось непроверенным и почему.

Отсутствие любой из трёх — `high`, а отсутствие первой при наличии стража — `blocker`.
