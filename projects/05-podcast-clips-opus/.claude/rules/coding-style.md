## Монорепо

npm workspaces, один репозиторий, один образ `web` и ОДИН образ воркера, запускаемый тремя
контейнерами с разными командами. Предполагаемая раскладка (фиксируется исходником фичи
`foundation`, до неё не считать существующей):

```
apps/web/            Next.js 15 App Router, tRPC-роутеры, route handlers, SSR-страницы
apps/worker/         общий образ; workers/stt.ts, workers/select.ts, workers/render.ts
packages/db/         Prisma schema + миграции SQL
packages/shared/     закрытые перечисления, Zod-схемы, единицы, время
packages/s3/         адаптер объектного хранилища (SigV4, multipart, presign)
```

Пять граблей монорепо в Docker, каждая из которых в проекте-предшественнике ломала ВСЕ образы
([`compose-hygiene.md`](../../../../.claude/rules/compose-hygiene.md), правило 5):

1. Контекст сборки — **корень монорепо**: `package-lock.json` только там.
2. `npm ci` нужны манифесты **ВСЕХ** workspace, иначе `Exit handler never called!`.
3. `COPY` из пути workspace, не из `/app`.
4. `CMD` только на скрипт, существующий в ЭТОМ `package.json`.
5. `.dockerignore` обязателен при `COPY . .`.

`docker compose` вызывать **с `--project-directory .`** из каталога проекта: из корня монорепо
конфигурация не находится.

## TypeScript

- `strict: true`. `any` не добавляется; для внешних тел — `unknown` и разбор Zod на границе.
- **Закрытые перечисления — union-типы, а не `string`.** Каждое перечисление канона §4 объявляется
  один раз в `packages/shared` и оттуда же попадает в `CHECK`-ограничение миграции. Одно значение в
  двух местах — два источника истины, расходящихся молча.

  ```ts
  export const VIDEO_STATUS = ['uploading','queued','transcribing','selecting','rendering','done','failed'] as const;
  export type VideoStatus = typeof VIDEO_STATUS[number];        // ровно 7

  export const QUOTA_SCOPE = ['user_minutes','user_uploads','user_upload_refunds','user_llm','global_minutes','global_llm','user_rerenders'] as const;
  export type QuotaScope = typeof QUOTA_SCOPE[number];          // ровно 7 (седьмой — user_rerenders, OWN-015)
  ```

- **Неопознанное значение → самый строгий вариант.** Сравнение на равенство с единственным
  разрешающим значением, а не отрицание запрещающего:

  ```ts
  export function watermarkRequired(plan: unknown): boolean {
    return plan !== 'paid';   // null, '', 'PAID', ' paid', 'premium', 0, true → метка
  }
  ```

- `\w` в регулярных выражениях НЕ совпадает с кириллицей. Для русских заголовков клипов —
  `\p{L}` с флагом `/u` либо явные классы символов.
- Прямое приведение `req as CustomType` падает с TS2352; двойное через `unknown` работает, но лучше
  типизированный обработчик.

## PostgreSQL и Prisma

**Схема — контракт, миграции — проверяемый SQL.** Prisma используется как источник типов и клиент;
всё, что обеспечивает целостность, пишется явным SQL в миграции и проверяется тестом:

- `UNIQUE (account_id, idempotency_key)` на `video`;
- `UNIQUE (video_id, fence)` на `job_attempt` — **единственная** уникальность попыток;
- `UNIQUE (scope, scope_key, day)` на `quota_counter`, **колонки `limit` нет**;
- частичные `UNIQUE … WHERE type = 'link_view'` и `… WHERE type = 'guest_opened'`;
- `CHECK (failure_reason IN (…))`, `CHECK (score IS NULL OR объяснения непусты)`;
- частичный индекс по активным статусам для сторожа.

**ORM-магия не подменяет атомарность.** Списание квоты, заявка идемпотентного ключа, принятие
результата по фенсу пишутся сырым SQL через `$executeRaw`/`$queryRaw` с параметрами — не через
`findFirst` + `update`. Правило одно: **«прочитать, потом записать» на разделяемом ресурсе
запрещено.** Последовательный тест зеленеет при обеих реализациях, различает их только конкурентный
прогон.

Шаблон списания, единственная законная форма:

```sql
INSERT INTO quota_counter (scope, scope_key, day, used) VALUES ($1, $2, $3, 0)
  ON CONFLICT (scope, scope_key, day) DO NOTHING;
UPDATE quota_counter SET used = used + $4
  WHERE scope = $1 AND scope_key = $2 AND day = $3 AND used + $4 <= $5
  RETURNING used;
```

`$5` — предел из окружения. Пустой результат второго оператора И ЕСТЬ отказ. Форма
`INSERT … ON CONFLICT DO UPDATE … WHERE …` недействительна и в код попасть не должна.

`SET LOCAL` действует только на текущую транзакцию текущего соединения; параметризованный
`set_config()` вместо интерполяции строк.

## Единицы и время

| Величина | Единица в коде | Замечание |
|---|---|---|
| Размер файла | **байты**, `bigint` | 2 000 000 000, не «2 ГБ» |
| Длительность записи | **секунды**, `int` | границы 120 и 5400; в минуты переводится только для списания: `ceil(sec / 60)` |
| Длина клипа | **секунды с десятыми** | 20,0–75,0 |
| Оценка | `int` 0–99 | сумма трёх компонентов 0–33, каждая с непустым объяснением |
| Сроки хранения | **дни** | клип free — 3 дня после `done`; гостевая страница — 14 дней от отправки |
| Подписанная ссылка | **секунды** | ≤ 900 |
| Таймауты | **миллисекунды** в коде | ffmpeg 15 мин, задача целиком 30 мин, окно посредника 60 с |

**Время — `Europe/Moscow`** (`TZ` в compose). Сутки счётчика квоты — календарные московские;
граница суток — отдельный тест, не «заодно» с конкурентным. Хранение — `timestamptz`, а не
локальное время.

## Деньги и расход

Каждая попытка платного вызова пишет строку в `model-spend.jsonl`: `video_id`, стадия, единица
(минуты или токены), количество, результат. Счёт по ПОПЫТКАМ: таймаут и повтор — такие же строки,
как успех. Журнал пишется и при отказе поставщика, иначе расход виден только в счёте.

## Ошибки и отказы

`failure_reason` — закрытый набор, объявленный один раз и продублированный `CHECK`-ограничением.
Шесть причин по свойствам файла (`too_large`, `not_media`, `no_audio`, `too_short`, `too_long`,
`probe_timeout`) отличаются от отказов по потолкам (`refused_user_minutes`, `refused_global_minutes`,
`refused_user_uploads`, `refused_user_llm`, `refused_global_llm`) — на этом различии держится
возврат слота. Ключей квоты СЕМЬ (с 25.09.2026 — `user_rerenders`), пользовательских текстов меньше: у `user_upload_refunds` своего
текста нет намеренно.

`try/catch` вокруг проверки запрещён: проверка не становится необязательной молча. Недоступность
внешнего источника истины — исключение, а не возвращаемое значение: штатный возврат из колбэка
транзакции её КОММИТИТ вместе со всем, что успело записаться
([`security-operation-order.md`](../../../../.claude/rules/security-operation-order.md)).

## Очередь

`jobId = {stage}:{video_id}:{fence}` — повторная постановка того же фенса идемпотентна, и сторож
может ставить, не опасаясь дубля. `worker-video` объявляет `concurrency` **литералом `1`**, не
переменной окружения: это условие ADR-006 и оно проверяется стражем по исходнику. Рендер запускается
ДОЧЕРНИМ процессом — тяжёлая работа не занимает цикл событий, иначе BullMQ объявит задание
зависшим через 30 с непрерывной занятости и та же работа начнётся во второй раз.

Временный каталог чистится в блоке `finally` — и после успеха, И после отказа: каталог, который
чистится только на счастливом пути, наполняет диск ровно тогда, когда на нём уже мало места.

## Грабли, заслуженные не этим проектом

База `/myinsights` этого проекта **пуста** — ни одной записи на 21.09.2026, поэтому ниже только то,
что подтверждено документами репозитория, а не пересказ по памяти. Пополнять через `/myinsights`,
а не дописывать сюда непроверенное.

- Сервисы с ограничителями (лимитер, автомат защиты) обязаны быть синглтонами: экземпляр на запрос
  обходит защиту, счётчик не накапливается.
- `image: minio/minio` без тега — это `:latest`; через месяц приедет другой образ.
- `depends_on: condition: service_started` без healthcheck означает «процесс запущен», а не «готов
  принимать».
- Дополнительный compose-файл обязан объявлять `name:`, иначе берёт имя каталога и вытесняет
  боевой стек молча.
