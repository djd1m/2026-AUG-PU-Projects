## Слой выбирается по природе признака, а не по удобству

| Природа признака | Слой | Примеры из проекта |
|---|---|---|
| арифметика, закрытые перечисления, границы | unit | оценка = сумма трёх компонентов 0–33; границы 120–5400 с и 20,0–75,0 с; `ceil(sec/60)`; fail-closed по `plan`; честное число фрагментов < 3 |
| согласованность двух и более компонентов, транзакции, ответы маршрутов | integration | три исхода `code.apply` (ADR-007); фенс попыток (ADR-001); `guest.create` без согласия (ADR-008); маршрут вебхука отсутствует (ADR-005) |
| путь человека на РАЗВЁРНУТОМ стенде | E2E | загрузка → клипы (Сергей); гостевая страница (Анна); код партнёра (Кирилл); удаление аккаунта за 72 ч |
| **разделяемый ресурс** | **конкурентный прогон** | шесть ключей квоты; идемпотентность `video.create`; `link_view`/`guest_opened`; два воркера на одном фенсе |
| свойство исходника или compose | страж по коду | текст SQL списания; `concurrency` литералом; шесть имён `N5_LIMIT_*` в коде и compose дословно совпадают |

Интеграционные — на НАСТОЯЩЕМ PostgreSQL 16 и Redis 7 в профиле `test` compose (без публикации
портов), с MinIO вместо Cloud.ru. Фейки поставщиков STT/LLM/S3 детерминированные и отвечают по
контракту, включая пограничные случаи: без таймкодов, больше 8 кандидатов, оценка вне диапазона,
5xx, таймаут. **Тесты не ходят в интернет.** Живой режим включается ключами и помечается в отчёте
отдельно: прогон без ключей не выдаётся за смоук с реальными поставщиками.

## Пять обязательных конкурентных прогонов — не опция

Последовательный тест на разделяемом ресурсе зеленеет при ОБЕИХ реализациях: и при атомарном
операторе, и при «прочитать, потом записать». Различает их только параллельный прогон.

1. **Квота, шесть ключей.** N параллельных `video.create` одного аккаунта на границе `user_minutes`
   (90) и `user_uploads` (2): суммарно списано не больше потолка, ровно лишние отклонены. Отдельно
   `user_llm` (2): две параллельные команды «повторить» на стадии выделения — проходит РОВНО одна.
   Отдельно `user_upload_refunds` (2) при остатке 1: два параллельных отказа по свойствам файла —
   слот возвращает РОВНО один. Отдельно `global_minutes` (600) и `global_llm` (20) при параллельных
   запросах РАЗНЫХ аккаунтов: добросовестный пользователь на своём лимите не блокируется чужой
   квотой.
   **Это ДОПОЛНЯЕТ, а не заменяет тест на границу суток:** дефект ветки `INSERT` (V2-R01) виден уже
   на первом запросе суток и без конкурентности.
2. **Идемпотентность `video.create`.** Два одновременных запроса с одним `Idempotency-Key` дают одну
   строку `video` и одно списание `user_uploads`.
3. **Два воркера на одном фенсе.** Задание `render(fence=N)` доставлено дважды: либо
   эксклюзивность очереди не допускает второго, либо только ОДИН `UPDATE … WHERE fence` затрагивает
   строки; второй — ноль строк и `stale_attempt_result` в аудит.
4. **Уникальность `link_view`.** 20 параллельных переходов по одному `/c/{code}` с одного
   `ip_prefix` за сутки засчитываются как РОВНО 1.
5. **Уникальность `guest_opened`.** 10 параллельных открытий одной гостевой страницы с одного
   `ip_prefix` за сутки — РОВНО 1. Проверять отдельно, а не «заодно» с четвёртым: у `link_view`
   уникальность была изначально, у соседнего события её не было, хотя обе половины метрики недели
   считают события одинаково уникальными (V2-R12).

## Двенадцать стражей ADR, испытанных внедрённым дефектом

Страж, ни разу не показавший красное, стражем не является. Каждая строка — тест или проверка по
исходнику, ОБЯЗАННАЯ упасть при внедрении названного дефекта. В квитанцию фичи пишутся **обе**
строки: красная при внедрённом дефекте и зелёная после восстановления.

| Страж | Что проверяет | Внедряемый дефект |
|---|---|---|
| ADR-001 (а) | `UPDATE … WHERE fence = :mine` попытки 1 после попытки 2 затрагивает 0 строк | убрать `WHERE fence = :mine` |
| ADR-001 (б) | `redis` несёт `--appendonly yes`, `--maxmemory-policy noeviction`, `requirepass` из `${…:?}`, без `ports:` | опубликовать `6379:6379` → `check-ports.cjs` даёт 1 |
| ADR-002 (а) | `minio` только под `profiles: [test]`, без `ports:`; `S3_ENDPOINT` без дефолта | дефолт `http://minio:9000` |
| ADR-002 (б) | `video.create` при `user_uploads = 2` → `refused` без ссылок; `upload/complete` при сумме > 2 000 000 000 → `422`, минуты не списаны | убрать проверку суммы частей на завершении |
| ADR-003 | результат `Transcriber` без `words[].start/end` отвергается до постановки `select` | принять результат без таймкодов |
| ADR-004 (а) | `watermarkRequired` возвращает `true` для `null`, `''`, `PAID`, ` paid`, `premium`, `0`, `true` | `!== 'free'` вместо `=== 'paid'` |
| ADR-004 (б) | рендер free содержит `drawtext` с `/c/<code>`; `clip_link` создан ДО `job_attempt(stage=render)` | создать ссылку после рендера |
| ADR-005 | нет зарегистрированного обработчика `/api/webhooks/yookassa` в боевом профиле | подключить маршрут |
| ADR-006 (а) | при месте < 3× — `deferred(no_disk)`, счётчик вызовов S3 GET равен 0 | убрать проверку `statvfs` |
| ADR-006 (б) | `concurrency` у `worker-video` — литерал `1`, не переменная окружения | заменить на `process.env.RENDER_CONCURRENCY` |
| ADR-007 | `cookie→explicit` = 200 + `replaced_source`; `explicit→любой` = 409; `guest_link→cookie` = 409; недействительный = 422 без изменения строки | разрешить откат к cookie при 422 |
| ADR-008 | `guest.create` без `consent_confirmed` или с `false` → 422, `guest_pack` не создан | сделать поле необязательным |

## Тринадцать тестов «сначала красное» на находки Phase 2

Правки раунда исправлений (DEC-A-010…016) закрыли шесть блокеров и восемь high. Каждая закрывается
тестом, который был бы КРАСНЫМ до правки, — не «тест существует», а «тест доказал бы исходный
дефект». Полная таблица с внедряемым дефектом по каждой строке — `docs/Refinement.md`, раздел
«Тесты „сначала красное“». Коротко, что обязано быть покрыто:

`а` ветка `INSERT` квоты · `б` восемь первых попыток рендера при `UNIQUE (video_id, fence)` ·
`в` `:limit` параметром, не колонкой · `г` повтор чанка списывает минуты заново · `д` `deferred`
двигает `updated_at` и сторож его не убивает · `е` `video.retry` на `refused_user_uploads` отвечает
`conflict` · `ж` старт без `N5_PUBLIC_ORIGIN` валится · `з` возврат слота при `too_long` и
НЕвозврат при `refused_user_minutes` · `и` уникальность `guest_opened` и одна транзакция для
счётчика с событием · `к` третий вызов LLM за сутки на аккаунте отказан `refused_user_llm` ·
`л` **ШЕСТЬ отдельных прогонов старта**, по одному на каждую отсутствующую `N5_LIMIT_*` ·
`м` шесть имён переменных дословно совпадают в коде и compose.

Строка `л` — отдельное правило, а не деталь: чек-лист из пяти прогонов зеленеет на конфигурации,
которая не запустится из-за шестой (V3-R02). Один прогон с пятью переменными — не проверка.

## Три стража стыка, обязательные ДО передачи результата

Зелёный юнит-тест — утверждение о модуле, а не о системе
([`deployment-seams.md`](../../../../.claude/rules/deployment-seams.md)).

```bash
bash scripts/check-env-wiring.sh                        # полнота проброса переменных каждому сервису
bash ../../scripts/check-port-conflicts.sh .            # публикация рядом с прокси, занятость портов
bash scripts/check-cjm.sh https://<стенд>               # путь целиком по ВЫДАННОМУ адресу, не localhost
```

Третий — не «открылась ли страница», а пройти путь целиком: вход → загрузка → прогресс → клипы →
скачать → короткая ссылка → отправка гостю → гостевая страница → код партнёра → кабинет. По адресу,
который выдало развёртывание, а не по тому, который знает сам скрипт.

## Что считается зелёным

Единица закрыта, когда выполнено ВСЁ:

1. `npm test` зелёный целиком — **все наборы, не только свой**. Урок предшественника: миграция была
   зелёной в своём наборе и уронила три чужих.
2. Конкурентные прогоны, задетые единицей, зелёные (см. пять выше).
3. Каждый добавленный страж испытан внедрённым дефектом, обе строки в квитанции.
4. `npm run lint` и `npm run build` по каждому workspace зелёные.
5. Три стража стыка отработали; код `2` («проверка НЕ выполнена») **не** читается как «в порядке».
6. В квитанции названо, что единица НЕ доказывает.

## Чего проверки этой недели доказать НЕ могут

Названо прямо, чтобы зелёный отчёт не выдавался за то, чем не является:

- **MinIO не доказывает Cloud.ru.** SigV4 с ключом `tenant_id:key_id`, multipart complete/abort,
  Range GET и CORS preflight проверяются ручной приёмкой на развёрнутом стенде (ADR-002 п.7,
  DEC-A-005).
- **Фейки поставщиков не доказывают поставщиков.** Найдёт ли модель три самодостаточных фрагмента в
  настоящем выпуске — вопрос живого прогона.
- **Ни один тест не измеряет NFR-PERF-001.** Уложится ли часовая запись в 20 минут p95, покажет
  стенд.
- **Читаемость метки на телефоне не автоматизируется.** Два человека смотрят 5 клипов с руки на
  экране ≈6 дюймов; результат — строка в `Completion.md` (FR-GROWTH-005).
- **Утверждения о поведении SQL выведены чтением документов, не прогоном** (§7.3 отчёта валидации).
  Они становятся фактом в тот момент, когда тест СНАЧАЛА показал красное.
