# N3 — состояние проекта и выбранная реализация

Подготовлены четыре PRD, общий PRD, HTML CJM A–D, исследование, независимый challenge и уточнённый контракт F1. Каждому варианту соответствует собственная подпапка; shared код служит единственным источником финансовых и authorization правил. Выбор варианта ещё не сделан.

Целевой runtime — распределённый монолит Docker Compose: UI A/B/C/D, общий API и PostgreSQL. БД доступна только backend во внутренней сети, без host ports; случайный пароль через secret. Эти требования распространяются и на тестовые стенды. Перед показом работающего UI владельцу обязательны browser E2E.

Владелец разрешил автономный `/go` после документов и минимального harness. Порядок shared→A→B→C→D. Текущий документ фиксирует план, а не завершение реализации; результаты появятся в per-feature completion/review и telemetry. F1 synthetic; ручная выплата до5-го, CSV отдельно от sent. Реальные платежи, provider credentials и protocol interoperability не выдаются за выполненные заранее.

Метрики: корректность — наша БД и наш журнал; UI latency и время принятия — ручное измерение: одинаковые fixture задания и таймер; модельные usage — наш журнал только при доступных host counters. Неизвестное остаётся null, экономия ещё не доказана.
