# Входящие уведомления ЮKassa — F2

**Входящие вебхуки:** да
**Отправитель:** ЮKassa
**Проверка повторной доставкой:** НЕ ВЫПОЛНЕНА
**Причина:** no-provider
**Ключ повторности:** object.id, квалифицированный provider/shop/kind
**Источник ключа:** событие-отправителя
**Хранилище ключа:** immutable_facts, колонки tenant_id/kind/business_key
**Механизм исключения:** уникальный-индекс
**Порядок событий:** перестановочен

Статус «НЕ ВЫПОЛНЕНА» относится к повторной доставке **настоящим магазином ЮKassa**: выделенные credentials N3 отсутствуют. Контрактный HTTP-provider fixture и реальная SQL-транзакция проверены параллельными/повторными/переставленными доставками в tests/payment-integration.test.mjs, без реальной оплаты.

ЮKassa не подписывает native-уведомления HMAC. Поля «что подписано», «когда проверяется подпись», «сравнение подписи» неприменимы: не выдаём несуществующую подпись за реализованную. Используется документированный authenticated read-back к фиксированному api.yookassa.ru/v3, до обработки/дедупликации события. Проверяются shop, test/live, ID, amount/RUB/status и сохранённый order binding. Root check-webhook-contract.cjs имеет контракт только для signed-body webhook, поэтому его exit2 здесь честно обозначает отсутствие live provider verification, не зелёный результат.

## Классы отказа

| Класс | Статус | Признак | Лечение | Доказательство |
|---|---|---|---|---|
| подделка | ЗАКРЫТ | Подставленные статус/сумма/магазин | Authenticated provider read-back и сравнение с неизменяемой заявкой до journal | tests/yookassa-adapter.test.mjs |
| повтор | ЗАКРЫТ | Два начисления за один provider object | Tenant lock + immutable_facts unique PK, одинаковый business key после рестарта | tests/payment-integration.test.mjs |
| перестановка | ЗАКРЫТ | Возврат пришёл раньше payment notification | Проверить исходную payment через API и применить payment/refund атомарно, не затирая историю | tests/payment-integration.test.mjs |

ЗАКРЫТ в таблице означает контрактные/SQL тесты реализации; live sandbox acceptance остаётся непроверенным. Без ответа провайдера нет подтверждённого начисления и ACK200; повтор может безопасно выполнить ту же операцию. Переставленные реальные refund/payment после подтверждения у провайдера дают один неизменяемый экономический итог.

[Официальный механизм проверки подлинности](https://yookassa.ru/developers/using-api/webhooks).
