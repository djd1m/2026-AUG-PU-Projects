# Потолок расхода · Тесты и мутации

| T | Сценарий | Ловит |
|---|---|---|
| S-1 | Суточный потолок достигнут → отправка получает явный отказ, вызовов модели **ноль** (fetch подменён и считает обращения) | потолок объявлен и не применяется |
| S-2 | Провайдер отвечает 500 → попытка **израсходована** | счёт по успехам вместо попыток |
| S-3 | Счётчик увеличивается **до** вызова: обрыв соединения после отправки запроса — попытка учтена | «увеличим после ответа» теряет оплаченные попытки |
| S-4 | Пользовательский потолок исчерпан, суточный нет → отказ только этому ключу, соседний проект работает | потолки перепутаны местами |
| S-5 | `USER > DAILY` в конфиге → **процесс не стартует** | предел, который не сработает никогда |
| S-6 | Потолок не задан → процесс **не стартует**, текст называет последствие | молчаливый дефолт |
| S-7 | Ноль и отрицательное значение → отказ старта, а не «без ограничений» | `0` прочитан как «выключено» |
| S-8 | Отказ по потолку **не повторяется**: `transcript_status='failed'`, попытки не тратятся | повтор жжёт попытки об закрытую дверь |
| S-9 | Расход виден в кабинете и совпадает с числом строк `model_call` за сутки | цифра из другого места |
| S-10 | Обе строки (суточная и пользовательская) пишутся **одной транзакцией** | расхождение счётчиков при отказе между ними |
| S-11 | Роль `web` **не может** писать в scope `model_call` — прямой запрос от роли | счётчик, накручиваемый без вызова |

## Мутации

| M | Внедрить | Красным обязан стать |
|---|---|---|
| MS-1 | Счётчик увеличивается после ответа модели | S-2, S-3 |
| MS-2 | Отказ по потолку → повтор вместо `failed` | S-8 |
| MS-3 | Незаданный потолок → дефолт 1000 вместо отказа старта | S-6 |
| MS-4 | Снята проверка `USER <= DAILY` | S-5 |
| MS-5 | Записывается только суточная строка | S-4, S-10 |
| MS-6 | Выдан грант `web` на запись `model_call` | S-11 |

Мутации внедряются копией файла и с проверкой, что легли (PR-035).

## Чего тесты не проверяют

Реальную цену у провайдера (она меняется и берётся из его прайса, а не из нашего кода). Что
владелец **увидел** цифру расхода. И главное — что счётчик не обойдён дефектом в нашем же
процессе: от этого защищает только потолок в кабинете провайдера, и он вне нашего кода.
