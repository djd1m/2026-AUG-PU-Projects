# Потолок расхода · Валидация плана

Вердикт: **🟢 READY** — с двумя находками, обе вошли в план.

## Проверено на коде, а не по документам

| Проверка | Результат |
|---|---|
| Длительность режется на сервере | ✅ `ffmpeg -t 120` — стоимость запроса ограничена конструкцией, а не доверием к клиенту |
| Видео идёт через тот же лимит 5/час | ✅ проверено живьём: шестая отправка → 429 |
| Умножитель повторов | ✅ 3 попытки, не 5 — худший случай одной отправки ≈$0.018 |
| Существующий механизм лимитов расширяем через `scope` | ✅ правило проекта прямо это предписывает; новая таблица не нужна |
| Суточный/общий потолок | ❌ **не существует** — это и есть предмет фичи |
| Место, где виден расход | ❌ **не существует** |

## Находка 1: счётчик нельзя ставить на приёме

Очевидное место — обработчик приёма видео. Неверно: между приёмом и вызовом модели стоит очередь,
и одна принятая запись порождает **до трёх** вызовов при повторах. Счётчик на приёме считал бы
заявки, а платим мы за вызовы — расхождение до трёх раз в худшую сторону. Перенесён в воркер,
непосредственно перед вызовом.

## Находка 2: отказ по потолку не должен молчать так же, как выключатель

Уже выкаченный `VIDEO_INTAKE_ENABLED` — fail-closed и молчит: незаданная переменная просто
закрывает путь. Для выключателя это верно.

Для потолка **неверно**: если ненастроенный потолок тоже молча закроет путь, «потолок не
настроен» станет неотличимо от «видео выключено владельцем», и владелец пойдёт чинить не то.
Поэтому здесь противоположное поведение — **отказ запуска с текстом**, называющим последствие.
Два похожих механизма с намеренно разной реакцией на отсутствие значения; разница объяснена в
плане, чтобы следующий читатель не «унифицировал» их.

## Честная граница плана

Ключ анонима обходится сменой адреса, и в рамках фичи это не чинится. Несущим пределом объявлен
**суточный общий**, а не пользовательский. И отдельной строкой записано, что **границу ставит
потолок в кабинете провайдера**, а наш счётчик лишь уменьшает вероятность: любой счётчик внутри
нашего процесса отменяется дефектом в нашем же процессе.

Блокеров нет. Три решения владельца блокируют выкатку, не реализацию.
