## Конкурентная проверка (R17)

Погашение токена обязано быть атомарным. Последовательный тест этого не различает:

```
два одновременных reset с ОДНИМ токеном  ->  ровно один 200, ровно один 400
                                             пароль сменён РОВНО один раз
```

При проверке-перед-обновлением оба увидят «токен годен» и оба сменят пароль — второй затрёт
первый. Наблюдаемо это только под конкуренцией, и это тот же класс, что
`shared-resource-verification.md` требует проверять третьим пунктом.

## Как проверяется отправка письма, когда почты нет

Отправитель принимается **параметром** (`sendEmail`), а не импортируется внутри. В тестах
подставляется счётчик вызовов: сколько раз позвали, с каким адресом, с какой ссылкой. Это же
даёт AC-015.10 («писем ноль») и AC-015.16 («отказ не меняет ответ») без всякой сети.

Отдельный страж по исходнику проверяет, что вызов стоит **вне** `withService` — свойство порядка
относится ко всем путям кода, включая те, которых сегодня нет.
