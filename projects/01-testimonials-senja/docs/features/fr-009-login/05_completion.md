# FR-009 · Готовность

## Определение готовности

- [ ] Все критерии приёмки из `01_specification.md` закрыты тестами
- [ ] `npm test` зелёный целиком, не только новые файлы
- [ ] `npm run typecheck` — код 0
- [ ] Стражи испытаны на способность падать, результат записан
- [ ] Роадмап: `FR-009` → `done`, `files` — фактически затронутые

## Метрика

Доля владельцев, вернувшихся в кабинет после истечения сессии, — измерима только
после месяца работы стенда. До тех пор проверяемый признак один: **сессия, выданная
входом, открывает кабинет** — то есть путь возврата существует.

## Риски, принимаемые осознанно

**1. Восстановления пароля нет** (FR-010). Владелец, забывший пароль, по-прежнему теряет
доступ. FR-009 закрывает случай «сессия истекла, пароль помню» — это большинство, но не все.
Отсюда же выбор свободного лимита по IP (30/час): при отсутствии восстановления цена
ложного срабатывания — потерянный кабинет до конца окна.

**2. [v2] Анти-перечисление учёток не становится системным свойством.**
`/api/auth/register` на существующий email отвечает `409` с явным текстом
(`lib/register.ts:74`). Вход закрывает одну дверь из двух. Утверждать, что учётки не
перечисляются, после этой фичи **нельзя** — только что их не перечисляет вход.

**3. [v2] Тайминг-тест вероятностен.** Порог «не более чем в 2 раза» подобран так,
чтобы не мигать на нагруженной машине, и потому может смолчать при небольшом
расхождении. Несущую роль играет страж по исходнику, а не он.
