# FR-009 · Готовность

## Определение готовности

- [ ] Все критерии приёмки из `01_specification.md` закрыты тестами
- [ ] `npm test` зелёный целиком, не только новые файлы
- [ ] `npm run typecheck` — код 0
- [ ] Стражи испытаны на способность падать, результат записан
- [ ] Роадмап: `FR-009` → `done`, `files` — фактически затронутые

## Метрика

Доля владельцев, вернувшихся в кабинет после истечения сессии, — измерима только
после месяца работы стенда. До тех пор проверяемый признак один: **сессия, выданная
входом, открывает кабинет** — то есть путь возврата существует.

## Риски, принимаемые осознанно

**1. Восстановления пароля нет** (FR-010). Владелец, забывший пароль, по-прежнему теряет
доступ. FR-009 закрывает случай «сессия истекла, пароль помню» — это большинство, но не все.
Отсюда же выбор свободного лимита по IP (30/час): при отсутствии восстановления цена
ложного срабатывания — потерянный кабинет до конца окна.

**2. [v2] Анти-перечисление учёток не становится системным свойством.**
`/api/auth/register` на существующий email отвечает `409` с явным текстом
(`lib/register.ts:74`). Вход закрывает одну дверь из двух. Утверждать, что учётки не
перечисляются, после этой фичи **нельзя** — только что их не перечисляет вход.

**3. [v3] Распределённый перебор одной учётки ограничен только счётчиком по IP.**
Тугой счётчик ключуется парой `email+IP`, поэтому атакующий с ботнета получает по 5 попыток
на учётку с каждого адреса. Это сознательный размен: счётчик по одному email закрывал бы
этот сценарий, но давал бы примитив «выключить чужую учётку» ценой пяти запросов — а при
отсутствии восстановления пароля у запертого владельца нет обходного пути вообще.
Выбран сценарий, который не оставляет добросовестного владельца без доступа.

**4. [v5] Граница пула перенесена, а не снята (D-010).** argon2 остаётся в транзакции,
пул расширен с 10 до 30. Поток, способный занять 30 соединений, положит приложение так же,
как занимал 10. Признак, по которому следует вернуться к варианту B (вынести argon2):
приложение встаёт под нагрузкой, а в `pg_stat_activity` видны параллельные транзакции входа.

**5. [v6] Грубый счётчик по IP держит 30/час последовательно и ~60 при параллельной пачке.**

Измерено на тестовой БД (пул 30, таймаут 5000):

| Пачка | Дошло до argon2 | Получили `429` | Задержка постороннего запроса к тому же пулу |
|---|---|---|---|
| 60 параллельных, один IP, разные email | 59 | 1 | 614 мс |
| 300 параллельных, один IP, разные email | 59 | 241 | 1193 мс (в покое — единицы) |

Причина: сериализуется только ТУГОЙ счётчик по паре `email+IP` — он и есть контроль
перебора пароля. Грубый по IP намеренно оставлен без лока (NFR-009.8): лок по IP общий
для всех за одним адресом и при насыщении наказывает офис за NAT, а не атакующего.

Размен принят: фактический потолок ~60 argon2 в час с адреса вместо 30, переполнение
ограничено размером пула. Это грубая мера против машины, а не точная против учётки, и
как грубая она работу делает. **Неприемлемо было молчание:** число 30 стояло в документе
как факт, а измеренное вдвое больше нигде не значилось.

Признак вернуться к решению: задержка посторонних запросов к пулу перестанет быть
приемлемой — тогда лимит по IP выносить ДО транзакции, в отдельное хранилище.

**6. [v4] Ветка `429` не записывает попытку — намеренно.** Значит запертый атакующий может
стучаться в один ключ сколько угодно: сервер отвечает быстро (два запроса, без argon2), но
бесплатно. Запись на этой ветке продлевала бы окно и возвращала бы примитив «выключить чужую
учётку», закрытый в ревизии 3. Внешний пояс — ограничение частоты на уровне прокси, вне
объёма этой фичи.

**7. [v5] Тайминг-тест вероятностен.** Порог — **не более чем в 4 раза**, семь замеров,
сравниваются медианы. Прежние «2 раза» при трёх замерах мигали на полном прогоне
(зафиксировано: 2.3x при пороге 2, машина под нагрузкой соседних процессов). Тест ловит
ПОРЯДКОВУЮ разницу — ранний возврат делает ответ в десятки раз быстрее — и не претендует
на большее. Несущую роль играет страж по исходнику, а не он.

Значение порога живёт в `apps/web/tests/login.test.ts`. Изменение одного без другого —
ровно то расхождение документ↔код, ради которого этот пункт переписан.
