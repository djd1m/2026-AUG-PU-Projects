# FR-014 · Спецификация: импорт отзывов из CSV

## Проблема

Пустая стена — главное возражение против продукта в первый день. Референс (Senja) импортирует
с 30+ площадок, и это его основной аргумент. У нас единственный способ наполнить стену —
попросить клиентов написать заново, то есть заплатить полной ценой за то, что уже есть.

## Решение владельца, которого нет

Роадмап помечает `DEC-003` — «приоритет CSV-импорта относительно других фич следующей недели»
— как решение владельца. Оно **не принято**. Эта фича спроектирована и реализована, но её место
в очереди остаётся за владельцем; документ не делает вид, что решение есть.

## Несущее ограничение: импорт НЕ ДОЛЖЕН стать второй дверью

Текст отзыва рендерится **на чужих сайтах** через виджет. Всё, что защищает этот путь, живёт
в одной функции — `validateTextSubmission` (`testimonial.ts:53`), и она сегодня единственная
дверь. Импорт добавляет вторую.

Класс известен проекту дословно: ревью нашло `L-2` — «у входа предел тела был, у регистрации
нет, закрытой оставалась одна дверь из двух». Здесь цена ошибки выше: там утекала нагрузка,
здесь на чужие сайты уедет чужой контент.

Поэтому: **импортированная строка проходит РОВНО ту же валидацию, что строка из формы, той же
функцией.** Не «аналогичную», не «свою для импорта» — ту же.

## Функциональные требования

| # | Требование |
|---|---|
| FR-014.1 | Загрузка CSV с сопоставлением колонок: владелец указывает, какая колонка — имя, какая — текст, какая — роль |
| FR-014.2 | **Предпросмотр до записи**: показывается, что будет импортировано и что отклонено, с причинами. Запись — отдельным действием |
| FR-014.3 | Импортированные отзывы получают статус `pending` и помечены источником `import` |
| FR-014.4 | Повторный импорт тех же строк не создаёт дублей |
| FR-014.5 | Отклонённые строки перечисляются с номером строки и причиной — владелец должен понимать, что потерялось |

## Нефункциональные требования `@security`

| # | Требование | Почему несущее |
|---|---|---|
| NFR-014.1 | Каждая импортируемая строка проходит `validateTextSubmission` — **ту же функцию**, что строка из формы | См. выше. Своя валидация для импорта — это вторая дверь, и она разойдётся с первой молча |
| NFR-014.2 | Число строк в одном импорте ограничено числом; тело запроса — общим пределом | Иначе один запрос пишет неограниченно много строк в одной транзакции, удерживая соединение общего пула. Тот же разделяемый ресурс, что у входа, дашборда, витрины и виджета |
| NFR-014.3 | Идемпотентность обеспечена **ограничением БД**, а не проверкой «нет ли уже такой строки» перед вставкой | Проверка-перед-вставкой оставляет окно между проверкой и записью. В проекте это уже решено так дважды: `on conflict (code) do nothing` у партнёрских кодов и `unique(payment_event_id)` у начислений (ADR-006) |
| NFR-014.4 | Импорт доступен **только владельцу проекта**, и проект берётся из проверенной сессии, никогда из тела | Класс, закрытый в FR-010 (NFR-010.7) и FR-011: проверки изоляции молчат, когда «своим» объявлен чужой |
| NFR-014.5 | Предпросмотр **ничего не пишет** — ни отзывов, ни счётчиков, ни файлов | Иначе «предпросмотр» становится записью с другим названием, и владелец теряет возможность передумать |
| NFR-014.6 | Разбор CSV — вне транзакции | Длительностью разбора управляет клиент (размер файла). Внутри транзакции он удерживал бы соединение пула ровно так, как разбор тела у входа, который проект уже вынес наружу |

## Критерии приёмки

| # | Критерий | Падает при |
|---|---|---|
| AC-014.1 | Валидный CSV из N строк: предпросмотр показывает N принимаемых, в БД **ноль** новых строк | писать в предпросмотре |
| AC-014.2 | Запись после предпросмотра создаёт ровно N отзывов, все со статусом `pending` и источником `import` | ставить `approved` |
| AC-014.3 | **Повторная запись того же содержимого не создаёт ни одной новой строки** и не падает | заменить ограничение БД на проверку-перед-вставкой |
| AC-014.4 | Строка, не проходящая `validateTextSubmission` (имя короче 2, текст длиннее предела), отклоняется с номером строки и причиной | завести свою валидацию для импорта |
| AC-014.5 | **Страж по исходнику:** `lib/csv-import.ts` не содержит собственных проверок длины имени и текста — он вызывает `validateTextSubmission` | скопировать проверки |
| AC-014.6 | Импорт в **чужой** проект невозможен: `project_id` в теле игнорируется, берётся из сессии | взять `body.project_id` |
| AC-014.7 | CSV с числом строк выше предела отклоняется целиком, с понятной причиной | убрать предел |
| AC-014.8 | Тело больше общего предела → `413`; маршрут в списке стража предела тела | своя копия предела |
| AC-014.9 | Строки, отличающиеся только пробелами по краям имени или текста, считаются **одной** | не нормализовать перед отпечатком |
| AC-014.10 | Отзывы, созданные через форму, импорт не трогает и не считает дублями | брать отпечаток и с формы тоже |
| AC-014.11 | CSV с разделителем `;` и с `,` разбирается одинаково; кавычки и переводы строк внутри поля не ломают разбор | наивный `split(',')` |
| AC-014.12 | Пустой файл и файл только с заголовком дают понятный отказ, а не «импортировано 0» | считать пустоту успехом |
| AC-014.13 | Байты, не являющиеся UTF-8, дают отказ, а не порчу текста в БД | не проверять кодировку |
| AC-014.14 | **Страж по исходкику:** разбор CSV вызывается вне `withAccount` | занести разбор в транзакцию |

## Вне объёма

Импорт с внешних площадок по API (Google, Trustpilot и прочие 30+ у референса) — это отдельная
интеграция на каждую площадку. Импорт видео и фото: CSV несёт текст, а файлы требуют второго
канала. Автоматическая модерация импортированного — статус `pending` означает, что владелец
просматривает их тем же способом, что и остальные.
