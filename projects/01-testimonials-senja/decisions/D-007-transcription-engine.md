# D-007: Чем транскрибировать видео — Claude API не принимает аудио

**Дата:** 2026-08-26 · **Статус:** ⚠️ ТРЕБУЕТ РЕШЕНИЯ ВЛАДЕЛЬЦА · **Приоритет:** блокер

## Что выяснилось

Архитектура (ADR-005, §5) и постановка задачи предполагали транскрипцию видео-отзывов
**через Claude API**: `services/mcp-claude` с единственным tool `transcribe_video`
получает аудио и возвращает текст.

**Claude API не принимает аудио.** Проверено по документации Anthropic SDK:

- поддерживаемые типы content-блоков: `text`, `image`, `document` (PDF / текст);
- аудио прямо назван неподдерживаемым: SDK выбрасывает `UnsupportedMCPValueError`
  для «unsupported content types **like audio**».

Агент, генерировавший сервис, самостоятельно заподозрил это и пометил `[GAP]`
(«no documented audio content type exists in the current Anthropic API surface»),
поставив base64-заглушку в блок `document`. Заглушка не заработала бы.

## Почему это не поймали раньше

Ни одна фаза пайплайна не проверяет **реализуемость внешней зависимости**.
Валидация Phase 2 проверяла согласованность документов между собой, INVEST/SMART,
покрытие сценариями — но не задавала вопрос «а существует ли такой API вообще».

Требование было внутренне непротиворечивым и полностью прослеживаемым — и при этом
невыполнимым. Поймал это не пайплайн, а агент, который сел писать код.

## Варианты

| Вариант | За | Против |
|---|---|---|
| **A. Whisper в контейнере** | Self-hosted, согласуется с Architecture Constraints (всё в Docker, ничего managed). Тот же Whisper заявлен в стеке проекта 05 — общий опыт для курса | Вес модели, время обработки на CPU |
| B. Внешний STT-API (Deepgram, AssemblyAI и т.п.) | Быстро, качественно | Managed-зависимость — тот же конфликт, что был с Supabase. Ещё один платный внешний сервис |
| C. Убрать видео из MVP, оставить текстовые отзывы | Радикально упрощает неделю | Видео — половина ценности продукта («видео убеждает сильнее текста») |
| D. Браузерный Web Speech API на стороне клиента | Ноль инфраструктуры | Ненадёжно, зависит от браузера, качество низкое |

## Рекомендация

**Вариант A — Whisper в контейнере.** Обоснование: единственный, который не нарушает
Architecture Constraints. Внешний STT-API повторил бы ошибку с Supabase — увод компонента
во внешнее облако из самодостаточного деплоя на VPS.

## Что меняется при варианте A

- `services/mcp-claude` **исчезает из MVP**. Единственная его задача была транскрипция;
  других применений Claude в MVP-скоупе нет (AI-редактирование отзывов запрещено FTC,
  теги и поиск — вне scope недели)
- Транскрипция переезжает в `services/worker`: ffmpeg + whisper локально
- **ADR-005 переписывается**: FTC-граница остаётся в силе, но реализуется иначе —
  не «у сервиса один tool», а «в продукте нет ни одного пути, где модель порождает
  текст отзыва». Whisper делает speech-to-text, а не генерацию
- `ANTHROPIC_API_KEY` уходит из docker-compose — в MVP он не нужен
- Стек в постановке для будущих проектов: «Claude API» стоит называть только там,
  где он реально применим

## Что это упрощает

Один сервис вместо двух, минус один внешний API, минус один секрет, минус сетевая
зависимость в критическом пути обработки видео.

## Как переиграть

Если владелец выберет B — вернуть сервис-обёртку, но над STT-провайдером, а не над Claude,
и зафиксировать managed-зависимость как осознанное исключение из Architecture Constraints.
