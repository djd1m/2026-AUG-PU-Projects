# D-003: Хранилище видео-отзывов

**Дата:** 2026-08-26 · **Проект:** 01-testimonials-senja · **Статус:** принято агентом-архитектором

## Контекст

После отказа от Supabase Storage (конфликт с Architecture Constraints) нужно было решить,
где хранить видео-файлы отзывов.

## Варианты

| Вариант | За | Против |
|---|---|---|
| **MinIO как сервис compose** ← выбрано | S3-совместимое API даёт presigned URL для загрузки и отдачи | Ещё один контейнер и том |
| Том Docker напрямую | Проще, без лишнего сервиса | Нет presigned URL — файлы придётся отдавать через приложение |
| Внешний S3 | Надёжно, снимает заботу о бэкапе | Уводит компонент во внешнее облако — тот же конфликт, что был с Supabase |

## Решение

**MinIO.** Обоснование: presigned upload/download требует S3-протокол, голый том его не даёт.
Без presigned загрузка видео пошла бы через приложение, что делает его узким местом.

Путь миграции на том описан в `Architecture.md` — если MinIO окажется избыточным.

## Как переиграть

Правка `Architecture.md` §5 и §7 (docker-compose), плюс алгоритм загрузки в `Pseudocode.md` §1.1.
Затрагивает `video_object_key` — канон имён останется тем же.
