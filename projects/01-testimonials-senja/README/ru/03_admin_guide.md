# Руководство администратора

## Состав стека

| Сервис | Наружу | Роль |
|---|---|---|
| `caddy` | `${HTTP_PORT:-80}`, `${HTTPS_PORT:-443}` | Единственная дверь. TLS через Let's Encrypt |
| `web` | `expose` | Next.js: страницы и API |
| `worker` | — | Очередь транскрипции видео |
| `transcribe` | — | Обращение к OpenAI STT. **Единственный сервис с `OPENAI_API_KEY`** |
| `postgres` | `expose` | Данные |
| `minio` | `expose` | Видео и фото |

Все сервисы объявлены с `restart: unless-stopped`.

## Правило портов

**Порт базы данных не публикуется никогда.** Postgres, MinIO и любое другое хранилище
объявляются через `expose:`, а не `ports:`. Наружу смотрит только Caddy.

Это не гигиена, а несущее условие безопасности:

1. **Прямое подключение к БД снаружи не нужно ни одному сценарию.** Приложение ходит в
   базу по внутренней сети, миграции запускаются из контейнера, отладка — через
   `docker compose exec postgres psql`.
2. **Опубликованная БД взламывается.** 2026-08-26 на этой машине тестовый Postgres,
   поднятый как `-p 55432:5432` с паролем `postgres`, был взломан из интернета примерно
   за час: `COPY … TO PROGRAM` дал выполнение команд, в контейнер лёг червь-майнер.
   «Необычный» номер порта защитой не является.
3. **`web` тоже не публикуется.** Определение IP клиента доверяет последнему элементу
   `X-Forwarded-For`, потому что его дописывает Caddy. Опубликованный `web` позволяет
   обойти Caddy и прислать свой единственный `X-Forwarded-For` — ограничение частоты
   обнуляется сменой заголовка. Воспроизведено: 7 запросов подряд при пороге 5.

Перед любым запуском:

```bash
bash ../../scripts/check-port-conflicts.sh .    # 0 — чисто, 1 — конфликт
```

## Развёртывание

```bash
cp .env.example .env && ${EDITOR:-nano} .env
bash ../../scripts/check-port-conflicts.sh .
docker compose up -d --build
docker compose exec web npm run migrate --workspace packages/db
bash scripts/check-cjm.sh "$BASE_URL"
```

Последний шаг обязателен. Он проходит путь клиента целиком и, главное, **идёт по тем
ссылкам, которые выдало само приложение**, а не по сконструированным. Именно так
обнаруживается несогласованность конфигурации: приложение работает, но выдаёт нерабочее.

### За существующим reverse-proxy

Если на машине уже есть свой Caddy/nginx, не публикуйте `80`/`443` из проекта. Подключите
`web` в сеть существующего прокси и проксируйте на него. `BASE_URL` при этом должен
указывать на **внешний** адрес — от него строятся все выдаваемые ссылки.

Заголовок `Access-Control-Allow-Origin` должен ставить **ровно одно** место. Если его
поставят и прокси, и приложение, браузер отвергнет CORS и виджет перестанет грузиться
на всех сторонних сайтах. `curl` этого не покажет — он не применяет политику браузера.

## Секреты

| Секрет | Кто получает |
|---|---|
| `POSTGRES_PASSWORD`, `DATABASE_URL` | `web`, `worker` |
| `SESSION_SECRET` | `web` |
| `S3_ACCESS_KEY` / `S3_SECRET_KEY` | `web`, `worker` |
| `YOOKASSA_SHOP_ID` / `YOOKASSA_SECRET_KEY` | `web` |
| `OPENAI_API_KEY` | **только `transcribe`** |

Изоляция ключа OpenAI — сознательное архитектурное решение: ключ живёт в одном сервисе,
у которого нет ни доступа к сессиям, ни доступа наружу.

`.env` в git не коммитится. Пароли генерировать: `openssl rand -hex 24`.

## Роли в базе данных

| Роль | Права |
|---|---|
| владелец схемы | миграции |
| `app_authenticated` | под RLS; видит только строки своего аккаунта |
| `app_service` | `BYPASSRLS`; для анонимных путей и системных операций |

`app_service` обходит RLS **на всех таблицах**. Изоляция на анонимных путях —
обязанность кода: обработчик резолвит слаг в идентификатор проекта сам. Ни один
анонимный маршрут не принимает идентификатор проекта от клиента.

## Резервное копирование

```bash
# База
docker compose exec -T postgres pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB" | gzip > backup-$(date +%F).sql.gz

# Объектное хранилище
docker compose exec minio mc mirror --overwrite local/testimonial-videos /backup/videos
docker compose exec minio mc mirror --overwrite local/testimonial-photos /backup/photos
```

Видео и фото лежат в **разных** бакетах: видео отдаётся только по подписанной ссылке
с ограниченным временем жизни, фото — публично через собственный маршрут приложения.
Общая политика на оба однажды сделала бы публичным и видео.

Восстановление:

```bash
gunzip -c backup-2026-08-27.sql.gz | docker compose exec -T postgres psql -U "$POSTGRES_USER" "$POSTGRES_DB"
```

## Наблюдение

```bash
docker compose ps                 # состояние и healthcheck
docker compose logs -f web        # логи приложения
docker compose logs -f worker     # очередь транскрипции
```

Воркер работает бесконечным циклом и берёт по одной задаче через
`FOR UPDATE SKIP LOCKED` — несколько экземпляров не возьмут одну и ту же строку.

Признак, что воркер не работает: отзывы с видео остаются со статусом расшифровки
`pending`. Первым делом проверить, что контейнер жив (`docker compose ps`) и что
миграции применены — воркер, стартовавший до миграций, падает.
