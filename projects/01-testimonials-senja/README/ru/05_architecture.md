# Архитектура

## Форма системы

Распределённый монолит в монорепозитории npm workspaces. Один стек Compose, шесть
сервисов, общая база.

```
                    интернет
                       │
                   ┌───▼────┐
                   │ caddy  │  единственная дверь, TLS
                   └───┬────┘
                       │ expose
                   ┌───▼────┐        ┌──────────┐
                   │  web   │───────▶│ postgres │
                   │ Next15 │        └────▲─────┘
                   └───┬────┘             │
                       │              ┌───┴────┐      ┌─────────────┐
                   ┌───▼────┐         │ worker │─────▶│ transcribe  │──▶ OpenAI STT
                   │ minio  │◀────────┤ очередь│      │ единств. ключ│
                   └────────┘         └────────┘      └─────────────┘
```

Наружу опубликован **только** Caddy. Всё остальное — `expose:`, то есть видно лишь
соседям по внутренней сети.

## Стек

| Слой | Выбор |
|---|---|
| Приложение | Next.js 15 (App Router), React 19, TypeScript |
| База | PostgreSQL, **сырой SQL без ORM**, изоляция арендаторов на RLS |
| Хранилище | MinIO (S3-совместимое), раздельные бакеты для видео и фото |
| Пароли | argon2id |
| Тесты | Vitest против живой Postgres, откат транзакции после каждого теста |
| Развёртывание | Docker Compose на VPS, Caddy + Let's Encrypt |

## Изоляция арендаторов — два независимых места

**1. Роль базы данных.** Дашборд-пути работают в транзакции под ролью
`app_authenticated` с установленным контекстом аккаунта. Политики RLS фильтруют строки
сами — обработчику не нужно дублировать условие в каждом запросе, и он не может забыть
его дописать.

**2. Код обработчика.** Анонимные пути (форма, виджет, витрина, вебхуки, воркер)
работают под ролью `app_service`, у которой `BYPASSRLS`. Там RLS не защищает **ничего**,
и фильтрация — целиком обязанность кода: обработчик резолвит слаг в идентификатор
проекта сам, и ни один анонимный маршрут не принимает идентификатор проекта от клиента.

Разделение сознательное: один механизм закрывает случай «забыл условие», второй —
случай «нет сессии, по которой фильтровать». Ни один из них не покрывает оба.

## Границы данных

| Данные | Где | Как отдаётся |
|---|---|---|
| Видео | бакет `testimonial-videos` | Только по подписанной ссылке с ограниченным временем жизни |
| Фото | бакет `testimonial-photos` | Через маршрут приложения, с типом, определённым по содержимому, и `nosniff` |
| Расшифровка | отдельное поле, помечено как машинная | Никогда не пишется в текст отзыва |
| Ключ OpenAI | только сервис `transcribe` | `web` и `worker` его не получают |

Разные бакеты — потому что режимы доступа разные. Общая политика на оба однажды сделала
бы публичным и видео.

## Очередь транскрипции

Воркер берёт по одной задаче:

```sql
SELECT id, video_object_key
  FROM testimonials
 WHERE transcript_status = 'pending'
   AND video_object_key IS NOT NULL
 ORDER BY created_at
 FOR UPDATE SKIP LOCKED
 LIMIT 1
```

`FOR UPDATE SKIP LOCKED` позволяет запускать несколько воркеров: они не возьмут одну
строку. Условие `video_object_key IS NOT NULL` обязательно — без него в очередь попадают
текстовые отзывы, у которых видео нет.

Неудача расшифровки переводит статус в `failed`, а не роняет отзыв: отзыв остаётся
валидным и модерируемым и без расшифровки.

## Доверие к заголовкам

Определение IP клиента берёт **последний** элемент `X-Forwarded-For`, потому что его
дописывает Caddy. Взять первый — принять значение от атакующего.

Это рассуждение верно **ровно до тех пор, пока `web` недоступен снаружи напрямую**.
Поэтому `web` объявлен через `expose:`, и это не косметика, а несущее условие: с
опубликованным `web` ограничение частоты обнуляется сменой заголовка.

Общий вывод, вынесенный в правила репозитория: гарантия, которую даёт прокси, действует
ровно до тех пор, пока прокси нельзя обойти.

## Ключевые решения

| Решение | Почему |
|---|---|
| Сырой SQL вместо ORM | RLS и `SET LOCAL` требуют контроля над транзакцией и соединением; ORM его прячет |
| Отзыв принимается без вычищения разметки | Обезвреживание — при рендере. Очистка на входе теряет исходник и не защищает другие контексты вывода |
| Виджет в Shadow DOM | Стили сайта-хозяина и виджета не пересекаются ни в одну сторону |
| `badge_required` считает сервер | Единственный источник правила; параметра для влияния со стороны клиента не существует |
| Идемпотентность на уникальном ограничении | Проверка «есть ли уже» перед вставкой не спасает от одновременных доставок |
| ЮKassa вместо зарубежного провайдера | Российская аудитория; провайдер не подписывает уведомления, поэтому подлинность — по сети источника и перезапросу статуса |

Полные формулировки — в `docs/ADR.md` и `decisions/`.

## Проверки как часть архитектуры

Часть свойств системы нельзя выразить типом или обычным тестом, поэтому они закреплены
скриптами и тестами, читающими исходный код:

| Проверка | Что стережёт |
|---|---|
| `check-port-conflicts.sh` | БД не опубликована; прокси не обходится; порты свободны |
| `check-env-wiring.sh` | Переменная, читаемая кодом, доезжает до сервиса |
| `check-cjm.sh` | Путь клиента проходит целиком на развёрнутом стенде |
| `share-cta-guard.test.ts` | Ни одного обращения в сеть до подтверждения — свойство **кода**, а не одного прогона |
| `tariff.test.ts` | Правило тарифа не продублировано ни в одном файле |
