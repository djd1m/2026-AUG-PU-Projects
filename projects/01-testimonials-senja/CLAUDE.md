## Что за продукт

Proofwall — клон [Senja.io](https://senja.io/): сбор отзывов (текст + видео) и публикация
«Wall of Love», встраиваемой на любой сайт одним `<script>`-тегом. MVP-неделя целится в
инди-хакера с одним SaaS, который хочет собрать отзывы и вставить стену на лендинг за вечер
перед запуском на Product Hunt (PRD §2.2, §3.1).

**Момент ценности переопределён относительно оригинала (PRD §2.3).** Senja продаёт магию
«мы нашли 47 ваших отзывов по всему интернету» — это требует импорта с 30+ платформ, явно вне
scope недели. Здесь момент ценности — **«твоя стена живёт на твоём домене»**: скорость от нуля
до публичного proof, ноль интеграций. Цена решения зафиксирована честно: активация слабее
оригинала без импорта — компенсируется метрикой `time-to-first-widget`.

## Метрика недели и критерий успеха

**Единственная метрика: число установленных виджетов на внешних доменах — цель 10 за неделю**
(PRD §2.4, допущение владельца продукта, не расчёт). Меньше 5 — loop не запустился; больше 20 —
проверить, не накрутка ли.

**Считаем сайты, а не людей** (PRD §2.4.1, решение по находке C-1 валидации): `widget_installed`
уникален на пару (`project_id`, `domain`), не на владельца — один владелец с пятью сайтами даёт
впятеро больше показов badge, чем пятеро с одним.

MVP считается done (Completion.md §1), когда одновременно:
1. FR-001…FR-007 реализованы и проходят acceptance criteria;
2. метрика недели **вычисляется** из события `widget_installed`, не подсчитывается вручную.

## Стек и Architecture Constraints (не обсуждаются, только выражаются)

| Аспект | Решение |
|---|---|
| Архитектура | Distributed Monolith в монорепо |
| Контейнеризация | Docker + Docker Compose |
| Инфраструктура | VPS (AdminVPS/HOSTKEY), TLS через Caddy (ADR-007) |
| Деплой | CI → образы → миграции → `docker compose -f docker-compose.prod.yml up -d` по SSH |
| БД | **PostgreSQL в контейнере compose** — managed BaaS (Supabase/Firebase/Neon) запрещён; см. Architecture §9 «Миграция со стека Supabase» — Postgres/RLS остались, изменился только слой инфраструктуры |
| Хранилище видео | **MinIO** (S3-совместимое, контейнер compose), presigned URL с TTL, никогда постоянная публичная ссылка |
| AI-интеграция | Claude API **только через MCP-сервер** `services/mcp-claude`, единственный tool `transcribe_video` (ADR-005) |
| Монорепо | `apps/web`, `apps/widget`, `services/mcp-claude`, `services/worker`, `packages/{shared-types,db,ui}` |

## Основной growth loop: BADGE LOOP — это цель проекта, не украшение

Единственный growth-канал недели (PRD §4.2): виджет живёт на сайте клиента → каждый посетитель
видит бренд Proofwall → часть кликает по badge → регистрируется. Работает **без нашего
трафика вообще** — ни один другой компонент недели не растит базу.

Loop ломается, если тариф проверяется на клиенте (ADR-002) — поэтому `badge_required`
вычисляется и отдаётся **только сервером** (`GET /api/widget/config`); виджет физически не
может решить иначе, потому что решение принимается не в нём. Валидный TLS на своём домене
(ADR-007) — предпосылка этого loop, а не инфраструктурная деталь: без него браузер хоста молча
блокирует запрос как mixed content, и badge не отрендерится ни на одном внешнем сайте.

Вторичная тактика — one-click share в момент ценности (FR-GROWTH-001): show-CTA на **каждую**
новую установку домена, не только на первую в жизни проекта.

**Правило приоритета при реализации:** если выбор стоит между «удобнее для клиента» и «тариф
проверяется на сервере» — выбирай сервер. Это не стиль кода, это единственный канал роста продукта.

## Non-negotiable ограничения

1. **FTC-граница применения Claude (ADR-005, PRD §4.4).** Claude API — **только** для
   транскрипции речи видео-отзыва, через единственный MCP-tool `transcribe_video`. Инструмента
   «переписать/улучшить/сгенерировать текст отзыва» не должно существовать в кодовой базе —
   граница на уровне набора tool'ов MCP-сервера, а не промпта. Штраф FTC Rule 16 CFR Part 465 —
   до $53,088 за нарушение. Подробности — `.claude/rules/security.md`.
2. **XSS: экранирование на рендере, не на приёме.** FR-002/003 сохраняют ввод побайтово как есть
   (это условие побайтового совпадения из FR-NFR-SEC-002, не забытая санитизация). FR-005/006
   обязаны экранировать при рендере — SSR-страница `/w/<slug>` и виджет на произвольном чужом
   домене. Один необработанный payload исполняется на каждом сайте клиента, где стоит виджет.
3. **Изоляция арендаторов на анонимных путях держится на коде, а не на RLS.** Форма, виджет,
   Wall of Love идут под ролью `app_service` (`BYPASSRLS`) — RLS осознанно обходится, защита —
   исключительно явный фильтр `WHERE project_id = ...` в обработчике, резолвится только по
   `slug`, никогда по `project_id` от клиента (Architecture §3.1). RLS + `SET LOCAL` защищает
   только аутентифицированный дашборд-путь — второе не подстраховывает первое, оба обязательны.
