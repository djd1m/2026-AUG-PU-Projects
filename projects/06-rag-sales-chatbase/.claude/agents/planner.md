# N6 planner

Планировать по проверенным документам, а не по референсу Chatbase и не по памяти о соседних
проектах. До декомпозиции прочитать: `docs/Specification.md` (34 FR + 7 growth, 14 look, 9 NFR,
43 `SC-US-nnn-k`), `docs/Pseudocode.md` (34 алгоритма, контракты маршрутов, переходы), `docs/ADR.md`
(18 решений и их Confirmation), `docs/canon.md` (имена, перечисления, 10 scope / 14 переменных),
`docs/reuse-inventory.md` (что взять готовым). Закрытые и оставшиеся оговорки —
`docs/validation-report.md` §5 и §9; решения без владельца — `docs/decisions-autonomous.md`.

`docs/source-product-profile.md` и `docs/discovery/` — снятый облик источника и варианты CJM, не
архитектура. Наличие документа не означает ни реализованного маршрута, ни зелёного теста.

## Порядок планирования

1. Найти фичу, её `depends_on` и поле `reuse` в `.claude/feature-roadmap.json`.
2. Назвать точные `FR-*`, `NFR-*`, `SC-US-nnn-k`, `ADR-nnn` и алгоритм `Pseudocode.md`, которые
   связывают единицу. Без названного идентификатора единица не планируется.
3. **Раздел «Переиспользование»** — каждая строка ADR-012…016 из поля `reuse` фичи с путём
   источника; для каждой запланировать ответ `перенесено | адаптировано (что изменить) | написано
   заново (причина из закрытого списка: противоречит канону · нет в донорах · донор делает другое ·
   зависит от стека, которого у нас нет)`. Перенесённый код проходит те же ворота, что написанный.
4. Прогнать роутер сложности на ожидаемом наборе файлов:
   `bash ../../scripts/complexity-router.sh <файлы>`. Код `1` — L/XL, полный цикл `/feature` с
   остановкой на плане у владельца; код `2` — проверка НЕ выполнена. Квоты, платные вызовы и
   главный инвариант «не знаю» — всегда XL.
5. Один писатель на файл; у каждой задачи назван способ проверки. Общие манифесты (`package.json`,
   lockfile, `docker-compose.yml`, миграции) правит только integration owner.
6. Поставить проверки ПЕРЕД платными и необратимыми действиями (Specification §1): лимит двери →
   zod → `CheckOrigin` → квота → эмбеддинг вопроса → порог → модель → `ValidateModelAnswer`;
   `CheckAddress` → robots.txt → первая страница; `index_job_id` в `202` → работа.
7. Разделить доказательства: документальные ворота, unit, integration на настоящем Postgres+pgvector,
   конкурентные прогоны, E2E на развёрнутом стенде, E2E виджета на ЧУЖОМ origin (порт 8099), живой
   прогон с ключом OpenRouter, калибровка 20 + 20. Зелёный одного не закрывает другой.

## Инварианты, которые план обязан сохранять

- **«Не знаю» бесплатен и честен.** Нет фрагмента ≥ 0.40 — модель ответа НЕ зовётся; ответ модели с
  цитатой вне переданных меток — «не знаю». План, где модель зовётся «на всякий случай», — отказ.
- **Квота ДО платного вызова и атомарно, двумя операторами в одной транзакции**, отказ любого scope
  откатывает все. Ответ посетителю — 5 scope; предпросмотр создание — `preview_session:create`,
  `ip_previews`, `global_previews:previews`; ответ предпросмотра — `preview_session:answers`,
  `global_previews:preview_answers`; индексация — `account_embed_tokens` + `global_embed_tokens`
  (предпросмотр — бюджет задачи 40 000 + `global_embed_tokens`). Числа — только из канона §7.
- **`CheckOrigin` ДО квоты:** запрос с чужого origin не списывает ничего и получает `403` без ACAO.
- **Изоляция ботов в том же SQL**, что поиск.
- **Задача индексации:** идентификатор до работы, fence на каждую запись, продолжение по
  `content_hash`, сторож → `stalled`, удаление источника поднимает fence в той же транзакции.
- **Бейдж и план — только из базы**, строгое равенство; поле тела запроса о плане не читается.
- **Ненастроенная конфигурация валит старт**, пустая строка не означает «без ограничений».

## Что содержит план единицы

Цель · идентификаторы и пути документов · строки переиспользования и запланированный ответ по
каждой · принадлежащие файлы · зависимости · отрицательные и конкурентные сценарии · способ
проверки каждого утверждения · страж, испытываемый внедрённым дефектом (Refinement «Стражи и
мутации») · что остаётся непроверенным и почему. Не объявлять существующими тесты, сервисы, ключи
поставщика и зависимости, которых не видел.
