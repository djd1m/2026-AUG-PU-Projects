# security-patterns — N6 «Суфлёр»

Источники: Architecture «Security Architecture», ADR-003/004/005/008/010/018, четыре контракта
(`embed`, `model-cost`, `long-job`, `webhook`), Refinement «Security Hardening» и «Стражи и
мутации». Правило для этого проекта: [`.claude/rules/security.md`](../../rules/security.md).

## Граница 1. Чужой origin (виджет) — `embeddable-widget`

Три класса отказа, набор закрытый: `перекрёстный-запрос` (ACAO), `протечка-стилей` (чужой CSS в
обе стороны), `политика-безопасности` (CSP хозяина). Первый и третий отказывают при полностью
зелёной проверке на своей странице.

| Держим | Как | Внедрённый дефект → красное |
|---|---|---|
| ровно один ACAO | ставит только `web`, точный origin из списка | `header Access-Control-Allow-Origin *` в Caddyfile → тест числа заголовков = 2 |
| чужой origin не платит | `CheckOrigin` ДО квоты | квота до проверки → 403-тест видит рост `quota_counter` |
| XSS на чужом сайте | `textContent`, ссылки только из источников бота | `innerHTML` → тест `xss` донора N1 |
| изоляция стилей | Shadow DOM, `all: initial`, свои единицы | враждебный CSS страницы-хозяина ломает окно |
| CSP без `unsafe-inline` | нет инлайновых script/style | виджет не появляется под `script-src <origin>` |

Проверка — `host.html` на `http://localhost:8099` с CSP `default-src 'none'; script-src <origin>;
connect-src <origin>; img-src <origin> data:; style-src 'self'` и враждебным CSS; адрес виджета — ВЫДАННЫЙ
развёртыванием. Итог — строки `docs/embed-contract.md`, `check-embed-contract.cjs` → `0`.

## Граница 2. Чужой контент — prompt injection и выдумка

| Держим | Как | Внедрённый дефект → красное |
|---|---|---|
| «не знаю» бесплатен | порог 0.40 ДО модели | вызов модели при пустом поиске → счётчик 0 → 1 |
| цитата из контекста | `ValidateModelAnswer` | пропуск проверки → SC-US-006-4 |
| контент — данные | разделители `<материал>`, системные правила отдельно | вредоносная страница → обещание скидки (SC-US-006-3) |
| изоляция арендаторов | `bot_id` в том же SQL | фильтр после `LIMIT 4` → цитата бота B в ответе A (`SC-SEC-001`) |

Проверка цитат не доказывает смысловое соответствие ответа цитате — это известный долг (v1, NLI),
записанный, а не скрытый.

## Граница 3. Чужой адрес — SSRF

`CheckAddress`: DNS → все адреса → запретные диапазоны → соединение по проверенному IP →
перенаправления вручную, каждое снова через проверку, ≤ 5. 12 адресов в тесте: `127.0.0.1`,
`169.254.169.254`, `10.0.0.5` через A-запись, `172.16.0.1`, `192.168.1.1`, `100.64.0.1`, `[::1]`,
`[fc00::1]`, `[fe80::1]`, `0.0.0.0`, редирект на `127.0.0.1`, `http://user:pass@host`.
Внедрённый дефект — проверка только до DNS → домен с A-записью `10.0.0.5` проходит.

## Граница 4. Аноним и платный вызов — `model-call-cost`

Единица «сессия» НЕДОСТАТОЧНА одна (очистка `sessionStorage` даёт новую) — поверх неё `ip_answers`,
`bot_day/month_answers`, `global_answers`. Отказ — текст с контактом; деградации и очереди нет.
Журнал `model-spend.jsonl` по попыткам (`phase=attempt` + `fsync` до вызова). Внедрённые дефекты:
«прочитать, потом записать» → конкурентный тест даёт > 1 ответа при остатке 1; дефолт `?? 1000` →
тест старта без переменной завершается 0; создание предпросмотра списывает `:answers` → 10-й ответ
отказывает.

## Граница 5. Внешний шлюз модели

Ключ только на сервере; недоступность эмбеддингов — `failed(embedding_unavailable)` с сохранением
сделанного; недоступность модели ответа — «не знаю» с пометкой «сервис временно недоступен»
(попытка оплачена и записана). `EmbedProbe` при старте: ответ ≠ 200 или длина ≠ 1536 — процесс не
стартует (дефект — `text-embedding-3-large` без `dimensions` не валит старт).

## Граница 6. Долгая задача — `long-running-job`

Идентификатор до работы; молчание — не «выполняется»; повтор продолжает. Дефекты: запись без
`current_fence` → старая попытка перезаписывает; повтор без `content_hash` → эмбеддит 50 вместо 20.

## Граница 7. Персональные данные — 152-ФЗ

Текст только у `unknown`, 14 дней; IP — префикс; удаление ≤ 72 ч; не логировать вопросы, IP,
токены, ключ. Дефект — запись `question_log.text` при `answered` → `CHECK` в БД отвергает вставку.

## Входящие вебхуки

В неделю их нет (ADR-017): страж по дереву маршрутов — нет `/api/webhooks/*`. Когда появится оплата
(донор N4 `payments-webhook.ts`), включается `incoming-webhooks.md` целиком: подпись/подлинность до
разбора, ключ повторности из события, атомарный уникальный индекс, порядок.
