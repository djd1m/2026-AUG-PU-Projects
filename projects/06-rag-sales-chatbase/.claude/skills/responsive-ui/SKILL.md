# responsive-ui — интерфейс «Суфлёра» под телефон

Адаптация навыка N5 (`projects/05-podcast-clips-opus/.claude/skills/responsive-ui/SKILL.md`,
решения OWN-016) под N6 по ADR-012 (строки «токены, тёмная тема» и «прибор адаптивности») и
FR-LOOK-008…014. Правило одно: **генерацию направляет эта методика, приёмку делает скрипт** —
зелёный прибор обязателен, «на глаз нормально» не считается.

## Почему это важно именно здесь

Две разные поверхности: **наш сайт** (лендинг с полем URL, тарифы, предпросмотр, кабинет, демо-страница
`/b/{slug}`, которую делятся в Telegram) и **окно виджета на ЧУЖОЙ странице** — где нет нашего CSS,
есть враждебный CSS хозяина и его CSP. Посетитель сайта клиента чаще всего на телефоне: окно виджета
на 360 px — главный экран продукта для конечного пользователя.

## Жёсткие правила (нарушение — дефект)

| # | Правило | Почему |
|---|---|---|
| 1 | Mobile-first: базовые стили — 320–430 px; расширение `@media (min-width: …)`; брейкпоинты ≈ 400 / 736 / 1112 + проверенная точка 360 (FR-LOOK-014) | базовый случай — телефон |
| 2 | Нет горизонтального скролла на 320–1440 px | WCAG 1.4.10 |
| 3 | Основные действия ≥ 44×44 CSS px, прочие цели ≥ 24×24; кнопки высотой 48, на ≤ 400 px — во всю ширину стопкой (FR-LOOK-010) | WCAG 2.5.8, HIG |
| 4 | `font-size` полей ≥ 16 px (`1rem`) — особенно поле URL на лендинге и поле вопроса в виджете | иначе iOS увеличивает страницу |
| 5 | Высота — `svh`/`dvh`, не голый `vh`; полноэкранное окно виджета на мобильном — `100dvh` | адресная строка браузера |
| 6 | Шрифт — в `rem`/`clamp()`; текст выдерживает 200 % | WCAG 1.4.4 |
| 7 | Viewport без `user-scalable=no` и `maximum-scale` | доступность |
| 8 | Отступы от выреза: `max(16px, env(safe-area-inset-*))`; пузырь 56 px, 16 px от края (FR-LOOK-011) | чёлка, домашняя полоса |
| 9 | Пузырь виджета не перекрывает основной призыв страницы хозяина на мобильном | FR-LOOK-011 |
| 10 | `prefers-reduced-motion` — уменьшать анимацию пузыря, не выключать всё | fluid-functionalism |
| 11 | Тач — `@media (pointer: coarse)`, не ширина | планшет с мышью |
| 12 | `/b/{slug}` отдаётся SSR и читается без клиентского JS до открытия чата | встроенные браузеры Telegram/VK |
| 13 | Главное действие в первом экране: `/` → поле URL + «Создать бота» (FR-LOOK-001), `/b/{slug}` → окно чата | 390×844 без прокрутки |
| 14 | Опасное действие («Удалить аккаунт», «Удалить источник») выглядит опасным и отделено | урок аудита N5 |

## Токены и тема (FR-LOOK-008/009)

Все цвета, отступы, размеры — переменные в `apps/web/src/app/globals.css` (донор N5, палитра
заменена): **нейтральная** — один основной тон, серый вторичный текст, чёрно-белые основные кнопки,
один акцент только для «готово/включено» и денег. **Кабинет — тёмный по умолчанию, светлая —
переключаемая** (cookie `n6_theme`, всё, кроме ровно `light`, — тёмная; тема ставится на сервере
атрибутом `<html data-theme>`, вспышки нет). Лендинг и тарифы — по тем же токенам. Вне двух блоков
токенов цветовых литералов нет (страж по образцу N5 `tests/theme.test.ts`). Контраст текста ≥ 4,5:1,
контролов и фокуса ≥ 3:1 в ОБЕИХ темах.

Шрифт — одна гротескная семья с кириллицей, **Onest**, самохостинг через `next/font`; 8–9 ступеней
12–64, H1 ≈ 4× body на десктопе и ≈ 3× на мобильном, вес заголовков 500, отрицательный трекинг
крупных. Шкала отступов — шаг 4 px. Радиусы 8 / 14–16 / 20 + пилюля.

**Виджету тема хозяина, не наша cookie:** светлая/тёмная по `prefers-color-scheme` и атрибуту
`data-theme` в теге `<script>`; токены виджета — внутри shadow root, `all: initial` на корне.

## Примитивы раскладки (Every Layout, чистый CSS)

```css
.stack > * + * { margin-block-start: var(--stack-space, var(--space-4)); }
.cluster { display: flex; flex-wrap: wrap; gap: var(--space-3); align-items: center; }
.switcher { display: flex; flex-wrap: wrap; gap: var(--space-4); }
.switcher > * { flex-grow: 1; flex-basis: calc((40rem - 100%) * 999); }
.center { box-sizing: content-box; max-inline-size: 70rem; margin-inline: auto;
          padding-inline: max(var(--space-4), env(safe-area-inset-left)); }
```

Карточка ответа с плашкой источника адаптируется к СВОЕЙ ширине: `container-type: inline-size` +
`@container`. Окно виджета ≤ 400 px шириной на десктопе, на всю ширину и высоту на мобильном.

## Порядок экрана на телефоне (FR-LOOK-012)

Лендинг: герой с полем URL → как это работает в 4 шага → пример ответа с источником → «для кого» →
доверие (152-ФЗ, данные в РФ, «не знаю» вместо выдумки) → тарифы → FAQ. Предпросмотр: прогресс
чтения (`role="progressbar"`) → макет страницы → живое окно бота. Кабинет: статус бота и установки
первыми, код установки — в одно касание «Скопировать».

## Доступность окна виджета (Refinement «Accessibility»)

Пузырь — `<button aria-label="Открыть чат с ИИ-помощником">`; окно — `role="dialog"`, фокус в поле
вопроса, Esc закрывает и возвращает фокус; ловушка фокуса в полноэкранном виде; лента —
`aria-live="polite"`; «печатает…» — `aria-busy`; плашка источника — ссылка с текстом, не иконка.

## Чего не делать

Tailwind, shadcn — без отдельного ADR. Пиксельные сравнения скриншотов — не ассерт. Инлайновые
стили в виджете — нельзя (CSP хозяина). Веб-шрифт в виджете — нельзя (бюджет 45 КБ и чужой CSP):
системный стек шрифтов.

## Приёмка

Прибор переносится из N5 (ADR-012): `projects/05-podcast-clips-opus/scripts/check-responsive.sh` +
`.mjs`, `scripts/responsive/rules.mjs`, `tests/browser/responsive-check.test.ts` → `scripts/` N6.
Файл теста в N5 правится параллельно — брать после их коммита (reuse-inventory §5).

```bash
bash scripts/check-responsive.sh --base <ВЫДАННЫЙ адрес стенда> --fixture <ui-fixture.json>
# 0 — чисто; 1 — нарушения (маршрут, ширина, движок, селектор); 2 — проверка НЕ выполнена
```

Движки WebKit и Chromium; ширины 320/360/390/414/768/1024/1440; маршруты `/`, `/pricing`,
предпросмотр, кабинет, `/b/{slug}` **и страница-хозяин на `http://localhost:8099` с виджетом**
(360 px, окно открыто — полноэкранное, без горизонтального скролла, пузырь не перекрывает `.cta`
хозяина). Правила прибора N5 R1–R9 и обе темы. `FIRST_SCREEN_ACTIONS`: `/` → поле URL и кнопка,
`/b/` → окно чата.

**Код 0 — необходимое, не достаточное условие:** композицию десктопа прибор не видит — после правки
открыть скриншоты `width-1440` и `first-screen-375x667`. Текст интерфейса ради вёрстки не менять.
