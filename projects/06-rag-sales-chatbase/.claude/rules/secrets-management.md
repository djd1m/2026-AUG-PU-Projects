# Секреты и конфигурация N6 «Суфлёр»

Источник: канон §6, Architecture «Security Architecture», Completion «Deployment Sequence» и
«Handoff», `.env.example`, `docker-compose.yml`, корневые `honest-configuration.md`,
`silent-fallbacks.md`, `model-call-cost.md`.

## Принцип

Ключ продукта (`OPENROUTER_API_KEY`) принадлежит НАМ, а не пользователю: он живёт только на сервере,
в `.env` машины, и никогда не уходит в браузер, бандл виджета, журнал или ответ API. Паттерн
пайплайна «ключ пользователя шифруется в IndexedDB» к N6 не применяется — у пользователя ключа нет.

## Какой секрет какому сервису

| Переменная | `web` | `worker-index` | `migrate` | `db` | `redis` | Без значения по умолчанию |
|---|---|---|---|---|---|---|
| `N6_DB_PASSWORD` (→ `DATABASE_URL`) | ✓ | ✓ | ✓ | ✓ | | да |
| `REDIS_PASSWORD` (→ `REDIS_URL`) | ✓ | ✓ | | | ✓ | да |
| `OPENROUTER_API_KEY` | ✓ | ✓ | | | | да |
| `SESSION_SECRET` (HMAC токенов, cookie реферала) | ✓ | | | | | да |
| `N6_PUBLIC_ORIGIN` | ✓ | ✓ (User-Agent краулера) | | | | да |
| `ANSWER_MODEL`, `EMBED_MODEL` | ✓ | ✓ | | | | да |
| 14 × `QUOTA_*` (канон §7) | ✓ | ✓ | | | | да |

`DATABASE_URL` и `REDIS_URL` собираются в compose из паролей — одно значение не может разойтись с
паролем самой БД. Сервис получает только то, что читает: лишний секрет в `environment:` — лишняя
поверхность, недостающий — тихий дефолт (`bash ../../scripts/check-env-wiring.sh` после появления
кода).

## Отказ вместо дефолта

- В compose — `${VAR:?причина}` для всех строк таблицы выше; `docker compose config` без `.env`
  обязан упасть, называя переменную.
- В коде — `LoadCeilings` при старте `web` и `worker-index`: отсутствие, пустая строка, нечисловой
  или ≤ 0 потолок → выход с кодом 1 и сообщением, называющим переменную и незащищённый вызов.
- `N6_PUBLIC_ORIGIN` валидируется `new URL`, протокол `https:` в production; `localhost`, `/`,
  пустая строка — отказ. Он определяет каждую выдаваемую наружу ссылку (бейдж, демо-страница,
  приглашение, User-Agent краулера) и границу «установка ≠ свой origin».
- Исключение для сборки — только названная фаза (`NEXT_PHASE=phase-production-build`), не общий
  «non-production».

## Где хранятся

- Машина: `.env` рядом с `docker-compose.yml`, права `600`, вне git (`.gitignore`). Секреты не в
  образах, не в аргументах `command:` (Redis получает пароль переменной, а не флагом — иначе виден в
  `ps`).
- Шаблон: `.env.example` — имена всех переменных, неопасные значения потолков, пустые секреты.
- Генерация: `openssl rand -hex 32` для `SESSION_SECRET`, `openssl rand -hex 24` для паролей БД и
  Redis. Дефолтные учётные данные (`postgres/postgres`) — запрещены даже «для тестов» (компрометация
  2026-08-26).
- Не в чате: владелец передаёт ключ OpenRouter на машину сам; агент ключ не печатает и не логирует.

## Ротация

| Секрет | Когда | Как | Последствие |
|---|---|---|---|
| `OPENROUTER_API_KEY` | утечка, смена владельца, переход с ключа стенда N5 на свой (A-N6-019) | новый ключ в `.env` → `docker compose up -d web worker-index` → `EmbedProbe` зелёный | ответы и индексация на время рестарта деградируют в «не знаю» / `embedding_unavailable` |
| `SESSION_SECRET` | утечка | новый секрет → рестарт `web` | все сессии и cookie рефералов недействительны; перелогин |
| `N6_DB_PASSWORD` | утечка | `ALTER ROLE` в `db`, затем `.env`, затем рестарт приложений | окно недоступности |
| `REDIS_PASSWORD` | утечка | `.env` → рестарт `redis`, `web`, `worker-index` | задачи в полёте повторяются по fence |

## Потолки — не секреты, но с тем же режимом

14 переменных `QUOTA_*` — числа, а не секреты, но без значений по умолчанию: пустая переменная не
означает «без ограничений» (model-call-cost, Правило №0). Изменение потолка — решение владельца
(Completion «Handoff»), не оператора; значение правится в `.env` и в каноне §7 одновременно.
