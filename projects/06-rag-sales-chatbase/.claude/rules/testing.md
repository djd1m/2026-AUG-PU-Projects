## Конкурентные прогоны (обязательны; последовательный зеленеет при сломанной реализации)

1. **Квота посетителя:** 20 одновременных вопросов при остатке 1 → ровно 1 ответ, 1 вызов модели,
   19 × `429` с контактом (SC-US-007-3).
2. **Идемпотентность источника:** два `POST /sources` с одним `Idempotency-Key` одновременно → одна
   задача, два одинаковых `202`.
3. **Fence:** старая попытка «ожила» после новой → её запись отброшена (0 строк, откат).
4. **Предпросмотр:** 5 одновременных создания с одного браузера при `QUOTA_PREVIEW_SESSION_CREATE=1` → 1.
5. **Эмбеддинги индексации:** две задачи одного аккаунта у потолка `account_embed_tokens` → сумма
   списанного ≤ предела.
6. **Добросовестный NAT:** 20 разных `visitor_session` за одним префиксом → первые 60 ответов
   проходят без ложных отказов (`ip_answers`, shared-resource-verification п.4).

Мерить число одновременно занятых соединений пула: ожидающие не должны его растить.

## Старт без конфигурации — 14 прогонов, не 10

`LoadCeilings` испытывается **отдельным прогоном на каждую из 14 переменных `QUOTA_*`** канона §7
(перенос M2 Phase 2: `BOT_DAY/MONTH × FREE/PAID`, `PREVIEW_SESSION_CREATE/ANSWERS`,
`GLOBAL_PREVIEWS/GLOBAL_PREVIEW_ANSWERS`) плюс `ANSWER_MODEL`, `EMBED_MODEL`, `OPENROUTER_API_KEY`,
`N6_PUBLIC_ORIGIN`. Список имён в тесте ЧИТАЕТСЯ из одного источника и сверяется с каноном, а не
перепечатывается: тест на 10 имён зеленеет при забытых остальных. Каждый прогон: пустое, `abc`, `0`,
отсутствует → код 1 и имя СВОЕЙ переменной в сообщении. Плюс пары «персональный ≤ суточного».

## Стражи с внедряемым дефектом (Refinement «Стражи и мутации», 16 строк)

Каждый страж принимается с двумя строками в квитанции фичи:
`дефект возвращён → N failed | M passed` и `код восстановлен → K passed`. Скрипты — по образцу N5
`scripts/test-*-mutations.mjs`. Главные: пропуск `ValidateModelAnswer` → SC-US-006-4 красный; вызов
модели при пустом поиске → счётчик 0 → 1; `toLowerCase` в `BadgeRequired`; «прочитать, потом
записать» в квоте; дефолт `?? 1000` потолка; `CreatePreview` списывает `:answers`; квота до
`CheckOrigin`; `header Access-Control-Allow-Origin *` в Caddy; `CheckAddress` только до DNS; запись
без `current_fence`; повтор без `content_hash`; фильтр `bot_id` после `LIMIT`; `text-embedding-3-large`
без `dimensions`; PDF удаляется только после успеха; потолок бандла 450 КБ; `playwright` в воркере.

## Обязательные наборы данных

Два бота с одинаковым прайсом (изоляция, `SC-SEC-001`); вредоносная страница «игнорируй
инструкции» (SC-US-006-3); скан PDF; PDF 11 МБ и 101 страница; SPA без SSR; `Disallow: /`;
12 SSRF-адресов (включая домен с A-записью `10.0.0.5` и редирект на `127.0.0.1`); 11 форм плана
(`'NOBADGE'`, `' nobadge'`, `null`, `''`, `['nobadge']`, …); 8 форм мусорного ответа модели.

## Калибровка порога «не знаю» (до выпуска)

20 вопросов «в базе» (URL страницы-ответа записан ДО прогона) + 20 «вне базы» на двух реальных ботах;
разметка двумя людьми; критерий — **0 выдумок из 20 и ≥ 16 из 20 верно**, шаг порога 0.05, приоритет
у нуля выдумок. Результат — `docs/measurements/threshold-calibration.md`. Это ручное измерение и так и
называется; автотест его не заменяет.

## Что считается зелёным

Все наборы (не только свой) после каждой миграции; `--build` у `docker compose run`; мутационные
прогоны тронутых стражей; для фич виджета — `node ../../.claude/hooks/check-embed-contract.cjs .` →
`0` на стенде; для задачи индексации — `check-job-contract.cjs` → `0` с названным `index_job_id`;
для потолков — прогон, упёршийся в `visitor_answers`, и сверка журнала с activity OpenRouter.

## Чего проверки доказать не могут

Проверка цитат доказывает, что цитата была в контексте, а не что ответ ей соответствует по смыслу
(Technical Debt, v1 — NLI). Зелёный CI не доказывает работу у клиента — только чужой origin на
стенде. Код 0 прибора адаптивности — необходимое, не достаточное условие.
