# Контракт входящих вебхуков — N6 «Суфлёр»

Дата: 2026-09-26 (переписан фичей `tariffs-and-interest`; прежняя редакция 2026-09-25 — «входящих вебхуков нет»).
Правило: [`incoming-webhooks.md`](../../../.claude/rules/incoming-webhooks.md). Проверка:
`node ../../.claude/hooks/check-webhook-contract.cjs .` · Решения: ADR-017 (дополнен), A-N6-040 — живая оплата ЮKassa по
решению владельца 26.09 («оплату через юкасса можешь взять из предыдущих проектов»).

**Входящие вебхуки:** да
**Отправитель:** ЮKassa
**Проверка повторной доставкой:** НЕ ВЫПОЛНЕНА
**Причина:** no-provider
**Ключ повторности:** event + object.id уведомления ЮKassa (`payment_succeeded:<id платежа>`, `refund_succeeded:<id возврата>`)
**Источник ключа:** событие-отправителя
**Хранилище ключа:** таблица payment_event, колонки provider/provider_event_id
**Механизм исключения:** уникальный-индекс
**Порядок событий:** перестановочен

Маршрут — `POST <N6_PUBLIC_ORIGIN>/api/webhooks/yookassa` (стенд: `https://sufler.aicoding.space/api/webhooks/yookassa`),
события `payment.succeeded` и `refund.succeeded`; при `N6_PAYMENTS_MODE=off` маршрут отвечает 404.

Статус «НЕ ВЫПОЛНЕНА» относится к повторной доставке **настоящим магазином ЮKassa**: своего тестового магазина у N6 нет (у
магазина один адрес уведомлений, магазины N1–N4 заняты). Повтор, одновременная двойная доставка, перестановка, подделка и
недоступность проверены НАСТОЯЩИМ адаптером ЮKassa (донор N4 `payments/yookassa.ts`) против подменного HTTP-сервера ЮKassa
и настоящего Postgres — `tests/billing.integration.test.ts`, без реальной оплаты.

**Подписи у ЮKassa нет.** Уведомления ЮKassa не подписаны, поэтому поля «что подписано», «когда проверяется подпись»,
«сравнение подписи» и «окно свежести» неприменимы — несуществующая подпись за реализованную не выдаётся. Подлинность —
сочетание трёх проверок, и ни одна не заменяет другие (донор N4, ADR-011 N4): адрес источника, записанный дверью N6
(`X-Forwarded-For` из одного адреса; цепочка — отказ), ∈ сетям ЮKassa из списка в коде; ПЕРЕЗАПРОС платежа или возврата
по API ЮKassa с ключом магазина; сверка заявленного уведомлением объекта с перезапрошенным (id, статус, сумма строкой в
копейках, магазин `recipient.account_id`, режим `test`, `metadata.order_id`, время провайдера). Всё это — ВНЕ транзакции и
ДО записи ключа повторности (security-operation-order: подделка с угаданным id не занимает ключ настоящего события).
Вендорная проверка `check-webhook-contract.cjs` описывает только подписанные вебхуки, поэтому её код 2 здесь честно
означает «живой магазин не проверен», а не зелёный результат.

**Недоступность ЮKassa** — исключение `PaymentProviderUnavailable` до транзакции: ответ 503, ни одной записи; ЮKassa повторит
уведомление, и повтор пройдёт полным путём (урок N1: потерянная оплата при возврате значением).

## Классы отказа

| Класс | Статус | Признак | Лечение | Доказательство |
|---|---|---|---|---|
| подделка | ЗАКРЫТ | «Оплачено» с чужого адреса, по неоплаченному платежу или с другой суммой/магазином | Сеть ЮKassa из кода + перезапрос + сверка объекта до ключа повторности; 400 без записи | tests/billing.integration.test.ts |
| повтор | ЗАКРЫТ | Два продления за одно уведомление | Ключ `<событие>:<object.id>` из уведомления, уникальный индекс payment_event (provider, provider_event_id); 20 одновременных доставок → одно применение | tests/billing.integration.test.ts |
| перестановка | ЗАКРЫТ | Студия откатилась на «Без бейджа», срок укоротился | Перестановочно: план — старший из действующего и оплаченного, срок — GREATEST(срок, now()) + 30 дней; возврат не снимает план автоматически (решение владельца: вручную оператором) | tests/billing.integration.test.ts |

ЗАКРЫТ означает контрактные и SQL-тесты реализации и мутации (`scripts/test-tariffs-mutations.mjs`); приёмка на живом
тестовом магазине ЮKassa остаётся непроверенной. Что нужно от владельца: shopId и секретный ключ тестового магазина N6,
`N6_PAYMENTS_MODE=live`, `YOOKASSA_TEST_MODE=true` и адрес уведомлений выше в кабинете магазина.

[Официальный механизм проверки подлинности](https://yookassa.ru/developers/using-api/webhooks).
