## Общее ядро (одинаково во всех вариантах)

Владелец даёт адрес сайта и/или PDF → система читает, режет на фрагменты, кладёт вектора в НАШ
Postgres (pgvector) → бот отвечает **только по этим материалам**, и **под каждым ответом — плашка
источника** (страница или PDF + цитата фрагмента). Нет фрагмента выше порога → «Не нашёл этого в
материалах компании. Напишите: <контакт>» (@security, PD-CORE-001). Виджет — один `<script>`-тег;
бот представляется ботом. НЕ входит в неделю: оператор, мультиязычность, аналитика диалогов, CRM,
обучение на диалогах.

Варианты РАЗЛИЧАЮТСЯ growth-петлёй, а не интерфейсом.

## A — Бот из URL за 5 минут (badge)

| Поле | Содержание |
|---|---|
| **Aha Moment** | На скриншоте СВОЕГО сайта всплыл виджет; владелец спросил «сколько стоит доставка в Казань?» — бот ответил и показал «Источник: /dostavka · «По России — от 350 ₽…»». Время от ввода URL ≤ 5 мин |
| Entry Hook / сегмент | S1; пришёл по бейджу с сайта другого клиента (лендинг помнит домен-источник: «бот как на site-x.ru — для вашего сайта») |
| Onboarding | Одно поле «адрес сайта» + «добавить PDF (необязательно)»; прогресс чтения по шагам (страницы → фрагменты → готово); без регистрации до предпросмотра |
| Core Loop | вопрос → ответ с источником → «не знаю» подсвечивает, чего не хватает → владелец добавляет PDF → бот знает больше; раз в неделю сводка «ответил на N, не знал M» |
| Paywall | «Убрать бейдж» (план «Без бейджа») и потолок ответов в месяц на Free; достижение потолка — отказ посетителю с контактом, владельцу — уведомление |
| Growth loop | **Badge**: бейдж в виджете → клик с доменом-источником → лендинг → свой URL → свой бот → свой бейдж |
| FR-GROWTH-001 | CTA «Поставить на сайт» + «Поделиться ссылкой на бота» — ровно под первым верным ответом в предпросмотре |
| FR-GROWTH-002 | поле «код студии/партнёра» при входе + cookie `ref`; атрибуция живёт до оплаты |
| FR-GROWTH-003 | бейдж на Free решает сервер; платное снятие |
| FR-GROWTH-004 | код партнёра в ссылке; дашборд когорты — минимальный (из B) |
| Главный риск | малый трафик малого бизнеса → мало показов бейджа; петля медленнее недели. Лечение — сидинг на сайты с трафиком (N1–N5, студии) |
| Проверяемая гипотеза | ≥ 15 внешних доменов с ≥ 1 вопросом за неделю; i ≥ 3 клика на 1000 показов [H, бенчмарка нет] |

## B — Студия ставит всем (incentivized referral через партнёров)

| Поле | Содержание |
|---|---|
| **Aha Moment** | Студия создала бота для клиента по его URL, поставила свой логотип и нажала «передать клиенту» — через 2 минуты видит бот живым на домене клиента в своём кабинете |
| Entry Hook / сегмент | S2; клиент студии просит «ИИ-чат как у всех», студия не хочет интегрировать Jivo за 12 990 ₽/мес клиенту |
| Onboarding | вход студии → «новый клиент» → URL клиента → бот → брендинг → приглашение клиенту |
| Core Loop | новый клиент студии → бот → перенос → оплата клиентом «Без бейджа» → комиссия студии |
| Paywall | тариф «Студия» (знак студии вместо нашего, до 10 ботов); клиент платит «Без бейджа» |
| Growth loop | **Incentivized referral**: студия получает % с оплат своих клиентов (до платной конверсии, не до регистрации) |
| FR-GROWTH-001 | «передать клиенту» в момент готовности бота |
| FR-GROWTH-002 | клиент атрибутирован к студии через приглашение (сильнее cookie) |
| FR-GROWTH-003 | на Free у клиентов студии — наш бейдж; знак студии только на «Студии» |
| FR-GROWTH-004 | ядро: код студии, sub-аккаунты, когортный дашборд установки → ответы → оплаты |
| Главный риск | продажа студии дольше недели; самый большой объём нового кода (иерархия студия → клиент, white-label отсутствует во всех N1–N5); выплаты физлицам |
| Отвергнут как основной, потому что | постановка задаёт основной loop badge и метрику «виджеты на внешних доменах»; B её обслуживает косвенно. Сохранён целиком — к нему возвращаемся, если бейдж не даст сигнала |

## C — Публичная страница бота (content-driven)

| Поле | Содержание |
|---|---|
| **Aha Moment** | Владелец опубликовал `/b/<slug>` в своём Telegram-канале; через час видит «12 человек спросили, 2 ответа — «не знаю»» |
| Entry Hook / сегмент | S4 (эксперт/автор курса) и S1 без доступа к коду сайта (Tilda без платного тарифа, маркетплейс-продавец) |
| Onboarding | URL/PDF → бот → «опубликовать страницу» |
| Core Loop | ссылка → вопросы незнакомцев → счётчик → добавить материалы |
| Paywall | свой домен для страницы, без бейджа |
| Growth loop | **Content-driven**: страница бота — контент, которым делятся; на странице «сделать такого же» |
| FR-GROWTH-001 | «поделиться страницей» ровно после первого ответа |
| FR-GROWTH-003 | бейдж на публичной странице Free |
| Главный риск | без аудитории владельца страница мертва; не растит главную метрику постановки (виджеты на внешних доменах); индексация шаблонных страниц — scaled content abuse |
| Отвергнут как основной, потому что | постановка делает демо-страницу ВТОРИЧНОЙ тактикой; как вторичная она взята в гибрид |

## H — Гибрид: РЕКОМЕНДАЦИЯ (ожидает владельца)

**Состав:** весь путь A (badge) + из C — публичная страница `/b/<slug>` как вторичная тактика без
нового бэкенда + из B — минимум FR-GROWTH-004: код студии, несколько ботов в одном кабинете, перенос
бота клиенту приглашением. **Не входит в неделю из B:** замена нашего знака на знак студии
(white-label) — закладывается в тарифную архитектуру Specification как план «Студия», реализуется
после сигнала от студий.

**Письменное обоснование (почему рекомендую именно это):**
1. Постановка задаёт основной loop badge и метрику «виджеты на внешних доменах» — A единственный,
   кто растит её напрямую.
2. Постановка сама называет демо-страницу вторичной тактикой — C уже вписан в рамку и почти не
   стоит кода (тот же чат на нашей странице).
3. FR-GROWTH-004 постановки прямо требует sub-аккаунтов для студий; минимум (много ботов + перенос)
   переиспользует N1/N4 и даёт каналу старт, а полный white-label — самый дорогой кусок, у которого
   нет донора ни в одном из N1–N5.
4. Главный риск A (мало трафика у малого бизнеса) лечится как раз студиями из B и сидингом.

**Что сделает владелец:** ответит «вариант A/B/C», «гибрид H» или соберёт свой; до ответа строка
`CHOSEN_CJM` не пишется.
