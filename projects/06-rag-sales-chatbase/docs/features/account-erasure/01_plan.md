- Сторож воркера (`apps/worker/src/watchdog.ts`) — место для шага стирания; `sweepVisitorText` (14 дней / 30 мин) уже есть.

```
Кабинет → «Удалить аккаунт» (экран с последствиями: боты, виджеты, остаток плана, начисления партнёра)
  → повторный ввод пароля + слово-подтверждение → DELETE /api/account { confirm: true, password }

    ОДНА транзакция (блокировка account FOR NO KEY UPDATE первой — тот же порядок, что оплата и приём приглашения, A-N6-048):
      status = erasing, erase_requested_at = now(), erase_deadline = now() + 72 ч
      все session удалены (отзыв), все bot аккаунта → deleted (виджеты 403 с этого коммита),
      незавершённые studio_invite аккаунта → аннулированы, partner_code аккаунта → frozen,
      payment_intent в полёте → failed(account_erasing)
    → 202 { erase_deadline } + подписанная cookie-квитанция (N5 erasure-receipt) → экран «Аккаунт удаляется, до <срок>»
  повтор при erasing → 409 erasure_already_running (N4); вход под erasing/deleted → отказ как неверный пароль
Сторож worker-index (раз в час, advisory lock, по одному аккаунту на единицу работы — N4/N5):
  наблюдение: erasing c erase_deadline < now() → СИГНАЛ ОПЕРАТОРУ (N5 «наблюдение срока» — до повторов)
  для каждого erasing старше «тихого периода» (задачи в полёте дописали — N5 ERASURE_QUIET_MS):
    1. задачи индексации аккаунта: отменить (фенс +1), дождаться отсутствия running
    2. источники: deleteSource по одному (страницы, фрагменты, задачи); тома uploads/<index_job_id> — rm (ADR-018)
    3. боты: question_log, visitor_session, widget_install, allowed_origin, preview, quota_counter по bot_id — DELETE; bot — DELETE
    4. growth_event — обезличить (account_id, bot_id, visitor_session_id, from_domain → NULL; агрегаты остаются, N5)
    5. деньги и партнёрка — по ответам владельца (вопросы 1–3), по умолчанию: payment и commission_entry остаются
       (account_id → NULL у payment; commission_entry.partner_account_id — ссылка на обезличенную строку account)
    6. account → deleted, email → 'deleted:<id>', password_hash → '', plan → free, partner_code_id → NULL
  каждый шаг идемпотентен (повторный прогон находит пустоту); сбой одного аккаунта не блокирует других
Владелец бота (без удаления аккаунта): POST /api/bots/{id}/question-log/erase → question_log бота стёрт, сводка «нет данных»
```

## Порядок операций

`DELETE /api/account`: лимит двери → Origin → сессия → тело ≤ 1 КиБ, закрытый набор `{confirm, password}` → bcrypt ВНЕ
транзакции → транзакция: `account FOR NO KEY UPDATE` ПЕРВОЙ → проверка статуса → сессии → боты → приглашения → коды →
намерения оплаты. Сторож: advisory lock → наблюдение просрочки → по аккаунту: задачи (фенс) → источники (`deleteSource`,
порядок «задачи → бот» фичи 16) → тома → строки ботов → обезличивание → деньги → `deleted` последним. Внешние объекты (тома PDF)
удаляются ДО `deleted`; `deleted` ставится только когда внешнего не осталось (N4 RV-02).

## Решения исполнителя (будут записаны как A-N6-054…, если владелец не решит иначе)

- Повторный ввод пароля при удалении (у N4 его нет — Telegram; у N6 почта + пароль, удаление необратимо).
- Отменить удаление нельзя: после `erasing` сессий нет, окно отмены — вопрос 5.
- Строка `account` физически не удаляется: остаётся обезличенный «надгробный» ряд (id, status, даты) — на него ссылаются
  `commission_entry` (`ON DELETE RESTRICT`) и платежи; почта освобождается.

## Вопросы владельцу

1. **Оплаченный остаток плана при удалении.** Рекомендую: **остаток не возвращается автоматически** — экран удаления
   прямо пишет «оплаченные N дней сгорят»; возврат по заявке в поддержку делает оператор вручную (как все возвраты — решение
   фичи 14). Альтернатива: автоматический пропорциональный возврат через ЮKassa при удалении (больше денежного кода,
   тесты возвратов, сторно комиссии партнёра).
2. **Начисления партнёра или студии, удаляющих аккаунт.** Рекомендую: **начисления в холде и доступные меньше 1 000 ₽
   сгорают; доступные от 1 000 ₽ оператор выплачивает по сохранённым реквизитам СБП в течение 72 ч, после чего реквизиты
   стираются**; экран удаления показывает сумму, которая сгорит. Альтернатива: все начисления сгорают при удалении, реквизиты
   стираются сразу.
3. **Что хранить по закону о бухучёте.** Рекомендую: **записи оплат (сумма, дата, план, id платежа ЮKassa) и начислений /
   выплат хранятся 5 лет обезличенными** — без почты, со ссылкой на обезличенный id аккаунта (402-ФЗ ст. 29); всё остальное
   стирается ≤ 72 ч. Альтернатива: хранить вместе с почтой 5 лет (удобнее для споров и возвратов, но это ПДн сверх
   необходимого).
4. **Студия и клиент.** Рекомендую: **удаление студии не трогает ботов, уже переданных клиентам** — они принадлежат
   клиентам, у студии просто пропадает доступ на чтение; незавершённые приглашения аннулируются; удаление клиента удаляет
   всех его ботов, включая полученные от студии; клиенты удалённого партнёра перестают приносить комиссию
   (`partner_deleted`). Альтернатива: вместе со студией удаляются и боты, переданные её клиентам.
5. **Срок и отмена.** Рекомендую: **сессии и виджеты гаснут сразу, физическое стирание — в ближайший прогон сторожа
   после часового «тихого периода», предел 72 ч; отменить нельзя.** Альтернатива: окно отмены 72 ч (вход по ссылке из
   квитанции возвращает аккаунт), стирание — по истечении окна; виджеты всё равно гаснут сразу.
