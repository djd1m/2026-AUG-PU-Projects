## Проверено и подтверждено

1. **Переиспользование (reuse-map.md, ADR-012).** Каждый файл N6 несёт первую строку происхождения
   («из N5: путь, коммит 90fe80a — без изменений | адаптировано: что»). Cookie — `n6_theme`
   (`apps/web/src/lib/theme.ts:6`), не `n5_theme`; тест-страж явно проверяет `n5_theme=light` → dark
   (`tests/theme.test.ts:22`). Следов бизнес-логики N5 (клипы, лента стадий, `/c/`, `/g/`) в коде N6
   не найдено — классы N5 из `globals.css` не перенесены (заявлено в reuse-map, подтверждено чтением
   файла). `scripts/responsive/rules.mjs` и `check-responsive.sh` — перенесены/адаптированы корректно,
   маршруты N6 (`FIRST_SCREEN_ACTIONS`).
2. **Cookie темы — fail-closed, без XSS.** `themeFromCookie` (`lib/theme.ts:11-22`) — закрытое
   множество: только ровно одна пара `n6_theme=light` даёт `'light'`, всё остальное (18 мусорных форм
   в тесте, включая нестроковый вход) — `'dark'`. Значение попадает в `data-theme` уже как элемент
   типа `Theme` (`'dark'|'light'`), а не сырая строка cookie — инъекция через cookie невозможна;
   `ThemeToggle.tsx` тоже пишет только через тот же закрытый тип. `themeCookie()` формирует строку
   cookie сам, входные данные пользователя туда не попадают.
3. **Токены.** Оба блока (`:root`, `:root[data-theme=light]`) — единственное место для цветовых
   литералов; страж `tests/theme.test.ts:60-63` grep'ает файл вне блоков и требует пустой список
   совпадений `COLOR`-регэкспа — реальная защита, не декларация. AA-контраст проверяется `axe` в обеих
   темах на всех 5 страничных сценариях (`design-shell.test.ts`), включая состояния (`.danger`,
   `.notice`, `.accent-text`, `select`) — так и заявлено в квитанции. Тест «не совпадает с N5»
   (`tests/theme.test.ts:68-73`) сверяет по РЕАЛЬНОМУ снимку палитры N5 (`n5-palette.txt`, > 20 цветов),
   не по придуманному списку — разумно.
4. **Шрифт.** `next/font/local` из `@fontsource-variable/onest@5.3.1`; `package-lock.json` подтверждает
   `"license": "OFL-1.1"`. Пути — локальные файлы `node_modules/...woff2`, никакого `next/font/google`
   и внешних доменов в CSP не появляется.
5. **Страницы.** Лендинг: ровно одно поле `#site-url`, один призыв, `action="/preview" method="get"` —
   помечено как 404 до `preview-flow`, соответствует decisions A-N6-031(6). Тарифы: три плана канона
   §7 с точными числами (0 ₽ / 990 ₽ / 4 900 ₽), строка снятия бейджа — ровно одна, у `nobadge`. Вход —
   форма на существующий `foundation`-API. Кабинет: `dashboard/layout.tsx:14` — без токена или
   `authenticate()==false` → `redirect('/login')`; пустое состояние оформлено как пустота, а не `0%`.
6. **Прибор в `scripts/responsive/`.** Не входит в workspaces (`package.json` root: `["apps/*",
   "packages/*"]`), поэтому `npm ci` в корне его не трогает; `**/node_modules` и `node_modules/` в
   `.dockerignore`/`.gitignore` исключают его из образов. У пакета собственный `package-lock.json` —
   воспроизводимость не потеряна. `check-responsive.sh` явно называет отказ («пакет playwright
   отсутствует» → код 2), а не тихо пропускает — соответствует guard-must-be-able-to-fail. ADR-007
   (`tests/ssrf.test.ts`, «корень не зависит от playwright») не нарушен: подтверждено — первый прогон
   был красным именно на этом страже (1 failed/705 passed), исправление устранило причину, а не страж.
7. **Регрессии 1–7.** `git diff --stat` по всему проекту показывает изменения только в
   `apps/web/{package.json, src/app/**, src/lib/theme.ts}`, `scripts/{check-responsive*,
   test-design-shell-mutations.mjs, responsive/*}`, `tests/{theme.test.ts, browser/**, fixtures/**,
   tsconfig.json}`, `vitest*.config.ts`, `package-lock.json`, `.claude/feature-roadmap.json`,
   `CLAUDE.md`, `docs/decisions-autonomous.md`. Файлы квоты, краулера, PDF, RAG-ответа, cookie сессии,
   compose, security не тронуты — тир M (заявленный) подтверждён составом диффа, а не только словом
   в квитанции.
