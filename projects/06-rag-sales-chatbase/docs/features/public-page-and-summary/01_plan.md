## Порядок операций (security-operation-order)

- `POST /api/bots/{id}/publish`: лимит двери → Origin → сессия → владение (404) → тело `{ enabled, indexable }` строго boolean → запись под блокировкой строки бота.
- `/b/{slug}`: слаг по форме ДО запроса к БД → бот опубликован и активен → рендер → событие просмотра (сбой записи не ломает страницу).
- `POST /api/preview/{id}/share`: те же ворота, что у вопроса предпросмотра (лимит → Origin → cookie браузера), событие с дедупликацией.
- Регистрация: запись прихода — ПОСЛЕ создания аккаунта и сессии, сбой не валит регистрацию (как claimPreview).

## Решения без владельца (записать A-N6-038…)

1. Демо-страница использует тот же бандл виджета, открытый сразу (`data-open`), а не отдельный чат: «тот же чат» буквально, одна реализация CORS/квот/ворот A-N6-035.
2. `noindex` — мета-тегом страницы; заголовок `X-Robots-Tag` ставит общий прокси стенда всем путям, в Next по флагу из БД заголовок страницы не выставить без middleware с запросом к БД.
3. Бейдж на демо-странице ведёт на `/?from=b/{slug}`, а не на наш собственный домен.
4. conv% = пришедшие по бейджу аккаунты с first_answer / клики по бейджу за период — приближение: клик и регистрация связаны только cookie прихода в том же браузере.
5. Вторая кнопка CTA предпросмотра пишет `share_cta_click` и ведёт на регистрацию: опубликовать страницу может только владелец с аккаунтом.

## Вне фичи (перенос с причиной)

- CTA под первым answered в ЧАТЕ КАБИНЕТА (FR-GROWTH-001 «или в кабинете») — у кабинета есть блок «Демо-страница»; CTA в чате — следующей фиче, трогающей чат владельца.
- Калибровка порога 20 + 20 и решение по ADR-003 — владелец (без изменений).
- Экран метрик для оператора — только отчёт командой, UI нет.
