## Что доказано и чем

- **SC-US-013-1:** публикация выдаёт слаг (транслит + 4 символа), страница грузится; в трёх движках — окно чата открыто
  сразу без кражи фокуса, вопрос → ответ с источником по настоящему маршруту и ядру (фейковая модель), бейдж и «Сделать
  такого же» ведут на `/?from=b/{slug}`; первый экран на 320–1440 — чат, без горизонтального скролла (R1/R2), axe AA в обеих темах.
- **SC-US-013-2:** `publicPageMetadata` — `noindex, nofollow` без флага и для несуществующей страницы (unit); связь с
  настоящим `page.tsx` — страж по исходнику.
- **SC-US-013-3:** `loadPublicPage` → null (404) при снятой публикации, неактивном владельце, удалённом боте, негодном
  контакте, мусорном слаге (Postgres); свой origin без публикации — 403 без ACAO (Postgres и браузер).
- **AC-13 (FR-GROWTH-005 @security):** 80 вопросов с демо-страницы от 20 посетителей одного /24 → ровно 60 ответов, 20 × 429 с
  контактом, 60 вызовов модели, установки 0 (Postgres).
- **SC-US-010-1/2:** сводка 40 / 25 / 3 и 20 последних «не знаю»; предпросмотр, `refused_origin`, старше 7 суток и чужой бот
  не входят; пусто — нули, экран пишет «Вопросов ещё не было» без процентов (Postgres и браузер).
- **FR-GROWTH-001 @security:** 100 одновременных «Поделиться» → 1 строка; без показа CTA — 0; кнопка в предпросмотре (браузер).
- **FR-GROWTH-006:** i = 3,5 на 1000 при 7 кликах и 2000 показах; conv% — 16,7 % по каналу сайтов, регистрации с
  демо-страницы в него не попадают; при нуле — null («нет данных»).
- **Приход по бейджу:** закрытая форма (19 видов мусора отвергнуты), cookie HttpOnly/Secure/Lax на 7 суток, запись в аккаунт
  один раз и только при регистрации; CHECK миграции держит форму без кода.
- **Уборка сессий:** пустые без обращений больше суток — удалены; с журналом, событием, историей, свежие и тронутые вопросом —
  остаются; вопрос с сессией остаётся в сводке.
- **carry_over фичи 12 в браузере:** блок «Ответы на сайте» (оба положения и ошибка 409) и баннер месячного лимита, называющий
  тестовый чат, — прибор R1/R2/R5/R8 и axe, обе темы, 320–1440.

## Что НЕ доказано

- **Стенд.** Маршрут Next `/b/{slug}`, middleware лендинга и `generateMetadata` в работающем Next не прогонялись: стенда N6
  нет (прибор — код 2). Браузерная оснастка рендерит ту же разметку и тот же бандл, но не маршрут Next.
- **Safari < 16.4** без `Sec-Fetch-Site` не получит чата на демо-странице (fail-closed, A-N6-038 (6)) — не проверено.
- **Зависший запрос «Поделиться»** в браузере не воспроизводился; таймаут стережётся по исходнику.
- **Показ 409 публикации** проверен разметкой, не запросом из экрана.
- **conv%** — приближение: клик и регистрацию связывает только cookie прихода в одном браузере.
- **Повторного ревью исправлений** не было; независимый валидатор плана не запускался.

## Ответ по строке reuse (ADR-013)

- «Публичная страница по слагу» (N1 `wall.ts`) — **написано заново**: у N1 стена рендерила свои данные, здесь страница —
  оболочка вокруг того же виджета, что на сайте клиента (A-N6-038 (1)); общего кода нет.

## carry_over — ответы

- bot-cabinet (A-N6-033 (1)): баннер исчерпания месяца называет тестовый чат — **проверено в браузере**.
- visitor-ask-and-limits (A-N6-035): баннер и блок «Я проверил ответы бота» — **прогнаны прибором и браузером**; отметка при
  новом источнике — **закрыто фичей 12** (A-N6-036); пустые `visitor_session` — **удаляются сторожем**; сводка читает
  `question_log` с сессией, `refused_origin` отдельно — **сделано**.
- **Не закрыто, у владельца:** калибровка порога 20 + 20, решение по ADR-003.
- **Перенос:** CTA под первым ответом в ЧАТЕ КАБИНЕТА (FR-GROWTH-001 «или в кабинете») — следующей фиче, трогающей чат владельца.
- ADR-015 (рассылка сводки) — не в этой фиче, как и в roadmap.
