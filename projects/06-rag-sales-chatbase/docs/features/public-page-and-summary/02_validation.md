## Сверка со спецификацией — найдено

1. **Pseudocode PublishPublicPage п.3 требует и мета-тег, и заголовок `X-Robots-Tag`.** План даёт только мета-тег
   (решение 2). Следствие: поисковик, читающий только заголовки, страницу увидит; мета-тег Google и Яндекс соблюдают.
   Общий прокси стенда уже ставит `X-Robots-Tag: noindex, nofollow` всем путям — на стенде свойство выполняется.
   Записать решением, не молчать.
2. **FR-GROWTH-005 @security: 200 вопросов с одного /24 на демо-странице → после 60-го отказ по `ip_answers`.** В плане
   не было отдельного критерия. Добавлено: AC-13 — вопросы с `N6_PUBLIC_ORIGIN` расходуют ту же квоту из 5 scope, 61-й
   ответ с одного /24 — 429 с контактом, модель не вызвана (integration).
3. **Pseudocode RecordGrowthEvent не называет ключ дедупликации для `public_page_view`.** План выбирает (бот, /24,
   сутки МСК) — записать решением.
4. **FR-GROWTH-006: «Показ бейджа засчитывается один раз на visitor_session в сутки».** Уже выполнено фичей 11
   (`recordBadgeEvent`), здесь не меняется; метрика i читает эти строки.
5. **ADR-013 строка reuse «публичная страница по слагу» (N1 `wall.ts`)** — ответить в квитанции: адаптировано или
   написано заново.
