# 01 — План: `text-source` (фича 18, третий вид источника «текстовый файл по адресу»)

Дата: 2026-09-28 · Основа: `09677f78` · Ветка: `feature/n6-text-source` · Тир: **L** (`scripts/complexity-router.sh` по
названному списку файлов: «миграция схемы», «кэш, повторы или таймауты»; по таблице `complexity-router.md` — ещё и «новый
внешний вызов»: чтение чужого адреса). Деньги (оплата) не затронуты; платный вызов — эмбеддинги — идёт прежним путём
`EmbedAndStore` с квотой и бюджетом серии. Решение — **A-N6-080** (076–079 заняты соседями). FR — новый **FR-SOURCE-005**.

## Повод

Решение владельца 28.09: владелец сайта aicoding.space предложил `https://aicoding.space/llms-full.txt` — полный текст
курсов и записей блога одним файлом. Обход сайта на free упирается в 50 страниц (crawl-coverage, A-N6-070) — файл
читается одним запросом. BACKLOG п. 9 (оценка «тир L, ≈ 1 день»).

Снято `curl` 28.09 (для чисел плана, не для кода): `200`, `text/plain; charset=utf-8`, **1 917 396 байт** (91 % от 2 МиБ),
`robots.txt` — `Allow: /`. Структура: `# Блог`/`# Курсы` → `## <запись или курс>` + строка `Адрес: https://…` →
`### <раздел>` + `Адрес раздела: …#якорь`. Заголовков: `#` — 5, `##` — 54, `###` — 576.

## Решение

| Часть | Что | Где |
|---|---|---|
| Схема | `015_text_source.sql`: `source.kind` += `text`, `index_job.failure_reason` += `not_text`, `index_start.kind` += `text` — ДОПИСЫВАНИЕМ к текущему `ARRAY[…]` (DO-блок, как 011/013); связка «вид → адрес/имя» переписана импликациями (`kind <> 'text' OR root_url IS NOT NULL`), без перечисления видов; `source.content_bytes`, `source.content_sha256` | `packages/db/migrations/` |
| Загрузка | `fetchTextFile`: форма адреса (http/https, 80/443, без учётных данных) → robots.txt origin'а (через `CheckAddress`) → `safeGet` файла: `CheckAddress` после DNS и на каждом перенаправлении, соединение по проверенному IP, только хост файла и его `www.`, таймаут 15 с, пауза 1 с между запросами, **≤ 2 МиБ** по заявленному и по принятому; тип — `text/plain` или `text/markdown` (HTML-ответ → `not_text` без чтения тела), сверка содержимого: HTML-разметка в начале, NUL, непригодная кодировка → `not_text` | `apps/worker/src/text/fetch-text.ts` |
| Разбор | `splitTextFile`: раздел = заголовок `#` или `##` (вне блоков кода); `###…######` — заголовки внутри раздела (`context_path`); текст до первого заголовка — раздел с адресом файла без якоря; разделы без текста — пропуск; ссылки `[имя](адрес)` → «имя (адрес)», по ссылкам НЕ ходим; якорь — slug заголовка (как у GitHub: буквы/цифры любого алфавита, пробел → `-`), повтор — `-1`, `-2` | `apps/worker/src/text/split-text.ts` |
| Индексация | обработчик `text`: раздел — строка `page` с `url_or_page` = адрес файла + `#якорь`, заголовок — «`#` › `##`»; `ChunkDocument` → `EmbedAndStore` (квота, бюджет серии) → `writeIndexedPage`; раздел считается в предел страниц тарифа (50/300) — лишние разделы не читаются, `done` с `truncated_by = page_budget`, известные = число разделов, до 5 непрочитанных `путь#якорь`; неизменный раздел (адрес+хэш) — без эмбеддинга; исчезнувшие разделы удаляются только после полного прохода; размер и sha256 файла — в `source` | `apps/worker/src/text/text-processor.ts`, `run-index-job.ts`, `index.ts` |
| API | `POST /api/bots/{id}/sources` JSON `{ url, kind: 'text' }` (без `kind` — сайт, как раньше): форма адреса + `CheckAddress` в `web` ДО записи; тот же `Idempotency-Key`, предел запусков в сутки | `cabinet-handler.ts`, `packages/db/src/bots.ts`, `index-jobs.ts`, `cabinet-deps.ts` |
| Кабинет | в `AddSource` — третий вариант «Текстовый файл по адресу» с подсказкой про `llms-full.txt`; лента, «Обновить»/«Удалить» — как у сайта; тексты отказов для файла; пометка усечения говорит «разделов файла» | `CabinetViews.tsx`, `TextSourceForm.tsx` (новый), `SourceTruncationNotice.tsx`, `source-ribbon.ts`; в `BotScreen.tsx` — только строка `AddSource` |

Не делается: обход ссылок из файла (это краулер); ссылка плашки на страницу сайта с тем же slug (не выдумываем адрес —
плашка ведёт на файл); строки `Адрес:` внутри файла остаются текстом фрагмента; предпросмотр и экран установки не трогаются.

## Критерии приёмки

- **AC-1** Разбор: `#`/`##` делят на разделы, `###` — путь внутри раздела; заголовок в блоке кода — не раздел; якоря уникальны;
  текст до первого заголовка — раздел без якоря; пустой раздел пропускается; ссылки превращены в текст.
- **AC-2** Граница адреса: 12 адресов Refinement (петля, частные, link-local/метаданные, CGNAT, IPv6 петля/ULA/link-local,
  DNS на частный, перенаправление на частный) → `blocked_address` ДО загрузки файла (0 соединений к цели); схема не http(s),
  порт ≠ 80/443, учётные данные в URL — отказ; robots.txt запрещает путь → `robots_disallowed`, файл не запрошен.
- **AC-3** Тип и размер: HTML (`text/html`) → `not_text`, тело не читается; `text/plain`, но HTML внутри → `not_text`; 2 МиБ —
  принят, 2 МиБ + 1 байт (заявленный и без `Content-Length`) → `too_large`; 404 → `unreachable`.
- **AC-4** На настоящем Postgres: файл → `done`, строки `page` с `url_or_page` = `адрес#якорь`, фрагменты с `context_path`;
  размер и sha256 в `source`; разделов больше предела тарифа → `done`, `page_budget`, `pages_total` = разделов, 5 примеров.
- **AC-5** «Обновить» неизменного файла → **0 вызовов эмбеддингов**, фрагменты те же; изменённый один раздел → эмбеддинг
  только его; исчезнувший раздел удалён после полного прохода.
- **AC-6** API: `{ url, kind: 'text' }` → 202 с `index_job_id`, источник `text`; адрес внутренней сети → 422 без записи;
  неизвестный `kind` → 400; прежний `{ url }` — сайт.
- **AC-7** Кабинет: третий вариант с подсказкой про `llms-full.txt`, цели ≥ 44×44, axe/R-правила прибора на 320/390, две
  темы, Chromium + WebKit; лента «Текстовый файл», «Обновить»/«Удалить»; тексты отказов `not_text`/`too_large` для файла.
- **AC-8** Мутации: снять `CheckAddress` в загрузке файла → красный; снять предел размера → красный; убрать проверку типа →
  красный; сравнение по хэшу раздела снято («Обновить» эмбеддит заново) → красный; предел страниц снят → красный.
