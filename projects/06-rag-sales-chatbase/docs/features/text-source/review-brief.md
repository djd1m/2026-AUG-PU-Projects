## Что сделано (план — `docs/features/text-source/01_plan.md`)

Третий вид источника бота — текстовый файл по адресу (`llms.txt`, `llms-full.txt`, `.txt`, `.md`), решение владельца.
1. Миграция `packages/db/migrations/015_text_source.sql`: `source.kind` += `text`, `failure_reason` += `not_text`,
   `index_start.kind` += `text` — ДОПИСЫВАНИЕМ к текущему `ARRAY[…]` (DO-блок, параллельные фичи тоже дописывают); связка
   «вид → адрес/имя» заменена импликациями; `source.content_bytes`, `content_sha256`.
2. Воркер `apps/worker/src/text/`: `fetch-text.ts` (форма адреса → robots.txt → `safeGet` с `CheckAddress` после DNS и на
   каждом перенаправлении, соединение по проверенному IP, robots на каждом шаге ДО запроса, ≤ 2 МиБ, только
   `text/plain|markdown`, HTML в теле → `not_text`), `split-text.ts` (разделы `#`/`##`, `###` — контекст, якоря-slug),
   `text-processor.ts` (раздел = строка `page` `адрес#якорь`, предел страниц тарифа 50/300 → `page_budget`, неизменный
   раздел не эмбеддится, исчезнувшие удаляются после полного прохода).
3. API: `POST /api/bots/{id}/sources` JSON `{ url, kind: 'text' }` (`cabinet-handler.ts`, `packages/db/src/bots.ts`).
4. Кабинет: `CabinetViews.tsx` (`AddSource` + `TextSourceForm`, тексты отказов), `TextSourceAdder.tsx`, лента, пометка.
5. Тесты: `tests/text-source.test.ts`, `tests/text-source.integration.test.ts`, `tests/browser/text-source.test.ts`,
   мутации `scripts/test-text-source-mutations.mjs`.

## Ограничения, которые НЕЛЬЗЯ было ослаблять

ADR-010: схема http(s), порт 80/443, `CheckAddress` после DNS и на каждом редиректе, соединение по проверенному IP, robots.txt,
таймаут 15 с, пауза 1 с, предел размера; эмбеддинги — только через `EmbedAndStore` (квота + бюджет серии на каждую попытку).

## Вопросы (ответь на каждый)

1. SSRF и robots: есть ли путь, где файл (или его перенаправление) запрашивается без проверки адреса, к другому хосту, или к
   пути, запрещённому robots.txt? Верно ли, что отказ адреса даёт `blocked_address` ДО загрузки?
2. Размер и тип: можно ли обойти 2 МиБ (Content-Length, поток, сжатие) или протащить HTML/двоичное как текст? Кодировки.
3. Миграция 015: корректна ли на базе, где 011/013/014 применены в любом порядке? Безопасна ли замена `source_check`
   импликациями (прежнее приложение на новой схеме, откат)? Не ломает ли `enums.test.ts`?
4. Индексация: верна ли логика «неизменный раздел не эмбеддится», удаления исчезнувших, `page_budget` и `pages_total`?
   Может ли `completeIndexJob` упасть на CHECK (`unread_sample`, длина, NUL) и задача застрять? Фенс при записи
   `content_bytes`.
5. Честность экрана: тексты отказов, пометка «Прочитано N разделов файла из M», плашка ответа ведёт на `файл#якорь`.
6. Тесты: доказывают ли они сказанное, или какой-то зелёный при сломанной реализации?

## Формат ответа

Первая строка — `Оценка: A|B|C|D` (A — можно вливать; D — блокер). Затем находки списком: `[high|medium|low] файл:строка —
что не так — как проверить — что предлагается`. Не выдумывай: если не уверен — пометь «гипотеза». Пустой ответ недопустим.
