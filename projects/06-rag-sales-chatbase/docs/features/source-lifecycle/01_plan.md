## Порядок операций

- **Удаление:** владение и блокировка строки бота → фенс +1 у задач источника → `DELETE source` (каскад) — одна
  транзакция: следующий поиск фрагментов источника не видит (SC-US-014-2). Опоздавший воркер получает 0 строк по
  фенсу/задаче → откат страницы. Файл PDF в томе у незавершённой задачи удаляет подметание тома (уже есть).
- **Переиндексация:** владение и блокировка бота → предел запусков → задача в `queued` с фенсом +1 → коммит →
  постановка в очередь; сбой постановки не теряет задачу (сторож переставит `queued` > 2 мин).
- **Уборка исчезнувших страниц:** только ПОСЛЕ полного обхода и внутри транзакции с проверкой фенса; обход,
  остановленный бюджетом или временем, и обход с временными пропусками (`unreachable`, `timeout`,
  `too_many_redirects`, `robots_unreachable`) ничего не удаляют — «не увидели» ≠ «страницы нет».

## Ответ по строкам reuse

| Строка roadmap | Ответ |
|---|---|
| ADR-016 «переиндексация — донора нет» | **подтверждено поиском** (правило владельца «используй готовое»): в N1 импорт — CSV отзывов, повторного чтения источника нет; в N5 есть повтор задачи под `FOR UPDATE` (`apps/web/src/server/video-retry.ts`) и суточные слоты загрузки в `quota_counter` (`packages/db/src/quota.ts`, `refundUploadSlot`) — **адаптировано**: повтор под блокировкой строки бота; слоты — в своей таблице и БЕЗ возврата при отказе (перенос MEDIUM-1 требует считать отказы, у N5 отказ файла слот возвращал). Удаление записи в N5 (`video.ts`, `deleted_at` + уборка хранилища после коммита) — **не взято**: мягкое удаление оставило бы фрагменты в поиске, FR-INDEX-004 требует удаления в той же транзакции |
