# 02 — Валидация плана: `crawl-coverage`

Самопроверка исполнителя (как у `budget-truncation`): отдельного агента-валидатора не было. Вердикт: 🟢 READY с
оговорками ниже.

| Проверка | Итог |
|---|---|
| AC проверяемы тестом, у каждого — набор | AC-1/2/3 — `tests/crawl-coverage.test.ts`; AC-3/4/5/7 — `tests/crawl-coverage.integration.test.ts`; AC-6 — `tests/browser/crawl-coverage.test.ts`; AC-8 — `scripts/test-crawl-coverage-mutations.mjs` + браузерная мутация |
| Порядок операций не меняется | robots.txt → sitemap → страницы; `CheckAddress`, пауза, потолок запросов/времени, бюджет страниц — те же константы `limits.ts` и те же проверки в цикле; меняется только выбор СЛЕДУЮЩЕГО адреса |
| Разделяемые ресурсы | очередь — память воркера, потолок `CRAWL_QUEUE_MAX` = 5000 сохранён (вставка по `lastmod` — линейный поиск в разделе, ≤ 5000 × 5000 сравнений в худшем случае, на порядки меньше сетевого времени обхода); запросов к сайту не больше, чем раньше |
| Три состояния задачи различимы | усечённый `done` — «сделано» + пометка `role=status`; не «идёт» и не отказ (лента в тоне успеха) |
| Закрытый набор расширен, не заменён | CHECK миграции 012 содержит все значения 009; тест сверяет последний CHECK с кодом и 009 ⊂ 012 |
| ПДн | в `unread_sample` — только путь (без query/fragment/хоста), ≤ 200 символов, ≤ 5 шт.; в журнал — только счётчики |
| Честность числа | «≥ M известных» — нижняя граница (ссылки непрочитанных страниц не собраны); адреса-дубли по содержимому в M входят — оговорено в квитанции |

Оговорки (не блокеры): `pages_done` при остановке пределом равно пределу — по этому равенству экран называет тариф
(«Бесплатный — 50» / «300»); иное значение (предпросмотр 20) показывается как «предел страниц этого чтения». Specification
FR-LIMIT-002 перечисляет два значения `truncated_by` — правка спецификации меняет её ревизию и ссылки test-scenarios,
оставлена координатору.
