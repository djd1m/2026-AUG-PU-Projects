# 02 — Валидация плана `budget-truncation` (самопроверка)

Независимого валидатора не было — самопроверка исполнителя по INVEST/SMART и правилам репозитория.

| Проверка | Итог |
|---|---|
| Каждый AC проверяем детерминированно (integration / unit / браузер / мутация) | да: AC-1…10 названы с инструментом |
| Три состояния long-running-job различимы | да: усечённый `done` отдельной пометкой, не «выполняется» и не отказ; 0 страниц — отказ (AC-5) |
| model-call-cost: предел — отказ, не деградация | да: внешние потолки — отказ (AC-4); собственный бюджет — объявленный размер работы, сверх него вызовов нет (AC-2) |
| Порядок операций: проверка бюджета ДО оплаты страницы | да: остаток читается до эмбеддинга страницы, пачка-страховка — до вызова (meteredCall.charge) |
| shared-resource-verification | остаток бюджета задачи читает единственный писатель задачи (лиз под фенсом) — гонки чтения-записи нет; квоты аккаунта и глобальные по-прежнему атомарны |
| fail-closed | колонка `truncated` — закрытый набор CHECK; неизвестное значение при разборе — `internal`-подобный отказ чтения, а не «не усечено» |
| Числа владельца не меняются | да: 40 000 / 20 / 500 000 — вопрос в плане, не правка |
| Страж умеет падать | AC-10 — мутация |

Вердикт: 🟢 READY (самооценка). Риск: оценка токенов (`estimateTokens`) и фактические токены различаются — остаток
сравнивается с оценкой, как и списание; расхождение не даёт перерасхода сверх бюджета, потому что списание — по той же оценке.
