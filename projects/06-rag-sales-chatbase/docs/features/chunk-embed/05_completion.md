## Найдено по ходу (и что с этим сделано)

1. **HNSW с фильтром терял свои фрагменты.** Первый прогон: путь HNSW + `WHERE bot_id` + `iterative_scan =
   relaxed_order` вернул 0 из 3 своих при 300 чужих ближайших (чужих — тоже 0: изоляция держалась, полнота нет).
   Поиск переведён на точный перебор внутри бота (A-N6-028); поправка внесена в Architecture и coding-style.
   Причина потери не диагностирована (гипотеза: достижимость ортогональных векторов в графе / пределы обхода).
2. **Мутационная обвязка засчитывала несобравшийся файл как «пойман»** (код 1 от ошибки трансформации). В новом
   скрипте красный требует «N failed».
3. **Два чужих стража не работали на дереве до фичи** (найдено регресс-прогоном, починено):
   `test-quota-mutations.mjs` не связывал `@n6/queue` в копии проекта → `probes.test` не собирался, 6 тестов
   пропущены, зелёная фаза — код 1 (с фичи index-job-core; `probes.test` теперь собирает db и queue, скрипт связывает
   queue) → 6/6; `plan-limit-unlocked` (pdf-source) дважды НЕ пойман: гонка «прочитать, потом записать» не возникала,
   пока соединения пула открывались по одному → в тесте прогрев 6 соединений → пойман (1 failed).

## Чего фича НЕ доказывает

1. **Живой OpenRouter не вызывался.** Формат ответа, `usage`, поведение 429 у настоящего шлюза — только подмена;
   ключ N6 не проверен (EmbedProbe при первом старте — по-прежнему обязателен).
2. **Токены — оценка кода, не токенизатор.** Цель 500 / потолок 600 и списание квоты — в единицах `estimateTokens`
   (кириллица ≈ 2 символа на токен — намеренно сверху). Сверка с `tokens_actual` журнала не делалась: живых вызовов
   нет. Реальный размер фрагмента в токенах cl100k, вероятно, меньше 500.
3. **«Читаются только оставшиеся» — не так для сайта.** «Повторить» эмбеддит только новые/изменённые страницы, но
   краулер ЗАГРУЖАЕТ все страницы заново: хэш известен только после чтения. SC-US-016-2 закрыт в части эмбеддингов, не
   загрузок. PDF после `failed` повторить нельзя (файл удалён, ADR-018) — продолжение PDF работает только внутри
   серии автоповтора.
4. **Индекс HNSW поиском не используется, но стоит записи:** 2,8 мс на фрагмент при вставке пачками по 50 (случайные
   векторы); пачка из 500 не уложилась в 5 с. Страница в 2 млн символов (≈ 2000–4000 фрагментов) держит транзакцию,
   соединение пула и строку `index_job` десятки секунд. Не мерилось на реальных эмбеддингах и на VPS. Решение —
   снять индекс миграцией или ограничить фрагменты страницы — в carry_over `source-lifecycle`.
5. **Бюджета на источник нет:** предел — аккаунт в сутки (2 млн), global, `embed_budget` предпросмотра. Один
   большой источник может выбрать суточную квоту аккаунта целиком.
6. **Точный перебор мерился до 5001 фрагмента одного бота** (34 мс); NFR-SCALE-001 (1 млн фрагментов на машину) и
   бот крупнее пределов плана не мерились; `ef_search`/HNSW-путь для больших ботов не реализован.
7. **Процесс воркера целиком против Redis и шлюза не запускался:** связка проверена на уровне `runIndexJob` на
   настоящем Postgres; `dist` собирается. Стек не поднимался; `check-job-contract` → 2.
8. **Независимого ревью не было** (ни Sonnet 5, ни cross-family).
