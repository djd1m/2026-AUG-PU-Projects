код 1, признак «миграция схемы». Денег и необратимой миграции данных нет (расширение CHECK и две новые колонки), поэтому

## Инцидент (факты из БД стенда 28.09, из постановки координатора)

Бот `829606b3…` (план free) для https://aicoding.space: обход `done` (50 страниц, 1482 фрагмента), домен в `allowed_origin`,
виджет стоит на сайте, посетители спрашивали — все получили «Бот ещё настраивается и пока не отвечает на вопросы.
Напишите: <контакт>». Причина — `bot.answers_verified_at IS NULL`: владелец не нажал «Я проверил ответы бота».

Три дефекта продукта, а не владельца:
1. экран установки выдаёт код без предупреждения, что посетители увидят заглушку, пока отметки нет;
2. отбитые воротами вопросы не пишутся в `question_log` (`widget-ask-handler.ts` отвечает `not_verified` до ядра) —
   сводка говорит «вопросов ещё не было», владелец не видит, что посетители упираются в заглушку (тихий отказ);
3. триггер миграции 004 (A-N6-036) снимает отметку молча — после «Обновить» бот снова замолкает, и владелец не знает.

ADR/решения: ADR-003 (ворота — замена недоказанной цитаты), A-N6-035 (ворота), A-N6-036 (снятие отметки триггером),
A-N6-038 (сводка), A-N6-033 (тестовый чат владельца не пишется в журнал). FR-BOT-004 (сводка), FR-BOT-002 (установка).

## Критерии приёмки

| AC | Что | Как проверяется |
|---|---|---|
| AC-1 | Экран установки: пока отметки нет — баннер ДО кода виджета «Посетители вашего сайта сейчас видят заглушку «Бот ещё настраивается». Проверьте ответы в тестовом чате и нажмите «Я проверил ответы бота»» | браузер (Chromium + WebKit, обе темы): порядок баннер → код |
| AC-2 | Есть готовый источник → в баннере кнопка «Я проверил ответы бота» (цель ≥ 44×44) и ссылка на тестовый чат; готового нет → кнопки нет, текст «дождитесь загрузки материалов» | браузер + прибор R1/R2/R5/R8, axe |
| AC-3 | Экран бота: тот же баннер над остальным, кнопка ставит отметку тем же `POST /verify` | браузер |
| AC-4 | Тестовый чат владельца отвечает и без отметки | integration: `POST /api/bots/{id}/ask` у бота без отметки → `answered` |
| AC-5 | Ответ ворот пишется в `question_log` исходом `not_verified`: без текста, с `visitor_session_id`, БЕЗ списания квоты и без эмбеддинга/модели | unit (порядок вызовов) + integration (строка журнала, счётчики квоты 0, вызовов шлюза 0) |
| AC-6 | Сводка: «N посетителей получили заглушку «Бот ещё настраивается»» отдельной строкой; не смешано с «не знал»; пустая сводка с одними заглушками — не «вопросов ещё не было» | integration (`readBotSummary`) + браузер |
| AC-7 | В баннере AC-1/3 — число посетителей с заглушкой за 7 дней (различные сессии) | integration (`readBotCabinet`) + браузер |
| AC-8 | Снятие отметки триггером записывает `answers_verified_reset_at` + причину `new_material`; баннер «Отметка снята <дата>: материалы обновились — проверьте ответы заново» | integration (вставка фрагмента) + браузер |
| AC-9 | Любое действие владельца с отметкой (поставить/снять) стирает пометку о снятии базой — иначе снятая вручную отметка показывала бы старую дату «материалы обновились» | integration |
| AC-10 | Канон §4, CHECK миграции 011 и `QUESTION_OUTCOME` совпадают; 152-ФЗ: у `not_verified` текст невозможен (CHECK `question_text_only_unknown`) | unit-страж перечислений + integration (вставка с текстом отвергнута) |
| AC-11 | Страж «заглушка не логируется» ловит удаление записи (мутация → красный) | мутационный прогон |

## Порядок операций маршрута (не меняется, добавляется одна запись)

дверь → бот → CheckOrigin → тело → токен → бейдж → **ворота: запись `not_verified` (без текста) → ответ заглушкой** →
ядро. Запись — после проверки токена и бейджа: иначе в журнал писал бы кто угодно без сессии; квота не трогается
(платного вызова нет — model-call-cost не задет, вызовов модели не прибавилось, контракт стоимости не меняется).

## Что сознательно НЕ делается

- Отдельной таблицы событий бота нет: пометка снятия — две колонки строки бота (минимально; история снятий экрану не
  нужна — владельцу важна причина ТЕКУЩЕГО состояния). Счёт сущностей канона §4 не меняется.
- Число в баннере — различные сессии посетителей, а не вопросы: на экране «посетителей». Вопросы без сессии
  (предпросмотр) сюда не попадают — ворота их не касаются.
- Спецификация (`Specification.md`, привязана к sha256) не правится: решение — A-N6-066, канон §4 — перечисление.
