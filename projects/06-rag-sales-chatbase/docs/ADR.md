## ADR-001 · pgvector в нашем Postgres, `vector(1536)`, HNSW cosine

**Контекст.** Постановка: вектора живут в том же контейнере Postgres, никакой отдельной векторной
БД. pgvector индексирует HNSW только до 2000 измерений у `vector` («Supported types are: `vector` -
up to 2,000 dimensions», README pgvector, 2026-09-25); ловушка — на десятке документов всё работает,
отказ приходит при построении индекса.
**Решение.** Образ `pgvector/pgvector:0.8.6-pg16`; колонка `vector(1536)`; индекс
`hnsw (embedding vector_cosine_ops)`, `m = 16`, `ef_construction = 64`, `ef_search = 40`; поиск всегда
с `bot_id` в том же запросе. Размерность — константа кода, не окружения.
**Последствия.** Модель эмбеддингов с другой размерностью = миграция и полная переиндексация.
Запас на рост — `halfvec(1536)` (HNSW до 4000, вдвое меньше памяти).
**Альтернативы.** Отдельная векторная БД (Qdrant, Pinecone) — запрещена постановкой и рамкой;
IVFFlat — требует обучения на данных и хуже на малых ботах; `3-large` на 3072 — не индексируется.
**Confirmation.** Тест миграции создаёт индекс на `vector(1536)` и ПАДАЕТ при попытке `vector(3072)`
с HNSW (ожидаемая ошибка pgvector); тест `EmbedProbe` валит старт при длине вектора ≠ 1536.

## ADR-002 · Эмбеддинги через шлюз OpenRouter; запасной маршрут назван, не выбран

**Контекст.** API OpenAI не обслуживает Россию (бриф, риск №1); постановка требует
`text-embedding-3-small`. OpenRouter отдаёт эмбеддинги (`POST /api/v1/embeddings`) и держит эту
модель в каталоге; N5 на этой машине уже ходит в OpenRouter за ответами модели (A-N6-009).
**Решение.** `EMBED_MODEL=openai/text-embedding-3-small` через `https://openrouter.ai/api/v1/embeddings`
тем же ключом, что ответы. При старте `worker-index` — проба одним эмбеддингом; недоступность шлюза
в работе — задача `failed(embedding_unavailable)`, не «готово». **Запасной маршрут** (решает
владелец, не агент): отечественная модель эмбеддингов с размерностью ≤ 2000 (GigaChat / Yandex) —
смена `EMBED_MODEL`, миграция размерности колонки и полная переиндексация всех ботов; вопросы
посетителей тогда не пересекают границу для эмбеддинга (но пересекают для ответа — ADR-011).
**Последствия.** Один поставщик на оба вызова — один отказ кладёт и индексацию, и ответы: ответы в
этом случае деградируют в «не знаю» с контактом (посетитель не видит ошибку). Проба сети без ключа
выполнена (HTTP 401), проба с ключом — при первом старте (строка `UNCONFIRMED` в Architecture).
**Альтернативы.** Прямой API OpenAI — не обслуживает РФ; VPS вне РФ — ломает «данные в РФ» (152-ФЗ);
локальная модель на CPU (e5/bge) — качество на русском без замера и нагрузка на единственную VPS.
**Confirmation.** Интеграционный тест с подменой шлюза, отвечающего 503: задача обязана стать
`failed(embedding_unavailable)`, а число фрагментов — не вырасти; мутация «глотать ошибку» даёт
`done` и тест краснеет.

## ADR-003 · «Не знаю» вместо выдумки — двойной барьер (@security)

**Контекст.** Бот говорит от имени чужого бизнеса; выдумка — вред клиенту (постановка, PD-CORE-001).
Одной инструкции модели «не выдумывай» недостаточно: модель не гарантирует следования.
**Решение.** Барьер ДО модели: нет фрагмента со сходством ≥ 0.40 — модель ответа не вызывается, ответ
«не знаю» + контакт. Барьер ПОСЛЕ модели: структурированный ответ `{status, text, citations}` и
серверная проверка — `answered` без цитат или с меткой вне контекста = «не знаю». Каждый показанный
ответ несёт плашку источника. Порог — число в коде, калибруется на наборе 20 вопросов «в базе» +
20 «вне базы» (Refinement), цель — 0 выдумок на «вне базы» при ≥ 80 % ответов на «в базе».
**Последствия.** Часть верных ответов уйдёт в «не знаю» (ложные отказы) — это сознательная цена;
сводка «не знал» показывает владельцу, чего добавить. Проверка цитат не доказывает, что текст
соответствует фрагменту, — только что он на него сослался; семантическое соответствие проверяет
ручной прогон набора (метрика §8 Specification).
**Альтернативы.** Только промпт — вероятностно; второй вызов модели-судьи — удваивает расход на
каждом ответе посетителя; NLI-модель на CPU — вне недели.
**Confirmation.** Юнит `ValidateModelAnswer` на 8 формах мусора (не JSON, пустые цитаты, `F9` вне
контекста, неизвестный status, `null`…) → все `unknown`; интеграционный тест «пустой поиск» ставит
счётчик вызовов модели = 0. Мутация «пропустить проверку цитат» краснеет тест.

## ADR-004 · Бейдж решает сервер по тарифу, fail-closed

**Контекст.** FR-GROWTH-003 — ядро петли; бейдж у источника — платный аддон (PD-INSIGHT-002).
Флаг на клиенте снимается правкой одной строки.
**Решение.** `badge_required` вычисляет только `/w/v1/config` через `BadgeRequired(plan)`: всё, кроме
строго `nobadge` и `studio`, — бейдж. Виджет охраняет бейдж `MutationObserver` внутри теневого корня
(донор N1 `badge.ts`); без бейджа поле вопроса блокируется. Скрытие узла-хозяина стилями хозяина
не ловится — условие оферты, не код.
**Последствия.** Смена плана действует со следующего запроса конфигурации (`no-store`).
**Альтернативы.** Бейдж в бандле по флагу — снимается клиентом; отдельный бандл без бейджа —
раскрывает платную сборку.
**Confirmation.** Тест с 11 формами плана (`null`, `''`, `'NOBADGE'`, `' nobadge'`, `['nobadge']`, …) →
`badge_required = true`; мутация «`plan.toLowerCase()`» краснеет тест; тест виджета удаляет бейдж и
ждёт восстановления.

## ADR-005 · Изоляция виджета — Shadow DOM, CORS по списку доменов бота

**Контекст.** Виджет живёт на чужой странице: три класса отказа (embeddable-widget). Чат требует
кросс-доменного POST — N1 делал только GET. В N1 двойной `Access-Control-Allow-Origin` (приложение
+ Caddy) молча ломал CORS.
**Решение.** Shadow DOM (открытый), `all: initial` на корне, `adoptedStyleSheets`, `textContent`.
Iframe не выбран: пузырь и окно поверх страницы в iframe требуют второго документа и
`frame-src` у хозяина, а бейдж в iframe не защищается от перекрытия лучше. CORS — точный origin из
`allowed_origin` бота, без cookie, без `*`, `Vary: Origin`; заголовок ставит ТОЛЬКО `web`.
Запрос вне списка — 403 до квоты. Контракт — [`embed-contract.md`](embed-contract.md).
**Последствия.** Владелец обязан вписать домены — без этого виджет не работает нигде (явная строка
на экране установки). Хозяин с CSP разрешает `script-src`/`connect-src`/`img-src` нашего origin.
**Альтернативы.** `Access-Control-Allow-Origin: *` без списка — любой сайт жжёт чужой лимит;
iframe — см. выше; проверка Referer — подделывается вне браузера (как и Origin — поэтому деньги
защищают квоты ADR-008, а не CORS).
**Confirmation.** Стенд проверки на ЧУЖОМ origin (другой порт) с ограничительным CSP и враждебным
CSS (`check-embed-contract.cjs`); тест, что в ответе ровно ОДИН заголовок ACAO; тест 403 без списания.

## ADR-006 · Ответ без стриминга

**Контекст.** Проверка цитат (ADR-003) требует ответа целиком; стрим показал бы непроверенный текст.
**Решение.** Один POST → один проверенный JSON; индикатор «печатает…» на клиенте; `max_tokens 400`
держит p95 ≤ 6 с.
**Последствия.** Ощущаемая задержка выше, чем у стрима; CORS проще (нет `text/event-stream`).
**Альтернативы.** Стрим с последующим «отзывом» текста — посетитель уже прочитал выдумку.
**Confirmation.** Тест маршрута: ответ приходит только после `ValidateModelAnswer`; мутация
«отдать сырой текст модели» ломает тест SC-US-006-4.

## ADR-007 · Предпросмотр — макет страницы, а не скриншот сайта

**Контекст.** Прототип CJM рисует виджет «на скриншоте своего сайта». Скриншот требует браузера в
воркере (Chromium ≈ 400 МБ, CPU) и открывает ещё одну поверхность SSRF. Iframe сайта обычно запрещён
`X-Frame-Options`.
**Решение.** Макет: заголовок страницы, H1 и фавикон, извлечённые краулером, + живое окно виджета.
Скриншот — v1.
**Последствия.** Aha чуть слабее визуально; ответ с источником — тот же.
**Альтернативы.** Скриншот через внешний сервис — новая внешняя зависимость и передача адресов.
**Confirmation.** Тест: `worker-index` не содержит зависимости браузера (`package.json` без
`playwright`/`puppeteer`) — страж по манифесту.

## ADR-008 · Потолки платных вызовов для анонимных посетителей

**Контекст.** Вызов запускает ПОСТОРОННИЙ без входа (model-call-cost): предел «на аккаунт» не
связывает никого. Донор N4 `quota/keys.ts`: сессия устройства + префикс IP + глобально.
**Решение.** Пять scope на каждый ответ посетителю (канон §7): `visitor_answers` 20, `ip_answers` 60,
`bot_day_answers`/`bot_month_answers` по плану, `global_answers` 3000 в сутки; предпросмотр — свои три
scope. Списание атомарно в одной транзакции ДО эмбеддинга вопроса, по попыткам; достижение —
отказ с контактом; ненастроенный потолок валит старт. Контракт —
[`model-cost-contract.md`](model-cost-contract.md).
**Последствия.** Худший суточный расход ≈ $20,9. Сессия посетителя сбрасывается очисткой хранилища —
поэтому второй ключ по префиксу IP; NAT офиса делит 60 ответов на всех (сознательно: наказывает
редко и дёшево).
**Альтернативы.** Только суточный глобальный — один посетитель съедает день до обеда; капча — вне
недели и бьёт по конверсии.
**Confirmation.** Конкурентный тест: 20 одновременных вопросов при остатке 1 → ровно 1 ответ и 1
вызов модели; тест старта без `QUOTA_GLOBAL_ANSWERS` → код выхода 1.

## ADR-009 · Индексация — долгая задача: Postgres — источник истины, BullMQ — транспорт, fence

**Контекст.** Краулинг 50 страниц с паузой 1 с ≥ 50 с плюс эмбеддинги — дольше окна посредника
(60 с). Правило long-running-job: идентификатор до работы, три состояния, повтор продолжает.
**Решение.** `index_job` в Postgres; `POST` отвечает `202 {index_job_id}`; BullMQ (донор N5
`packages/queue`) только доставляет; аренда `current_fence += 1`, запись результата `WHERE
current_fence = :mine`; продолжение по `content_hash` страниц; сторож: `stalled` после 5 мин.
Контракт — [`long-job-contract.md`](long-job-contract.md).
**Последствия.** Redis с AOF и `noeviction`; повтор не переэмбеддит сделанное.
**Альтернативы.** Очередь в Postgres `SKIP LOCKED` (N4) — меньше сервисов, но кода нет, а у N5 есть.
**Confirmation.** Тест: две попытки одной задачи, старая пишет после новой → 0 строк, результат
отброшен; тест повтора после сбоя на 30-й странице → эмбеддинги только для 20 оставшихся.

## ADR-010 · Краулер без браузера, вежливый, с SSRF-фильтром

**Решение.** undici GET, свой разбор robots.txt, один поток, 1 с пауза, 15 с таймаут, 2 МБ, только
HTML того же хоста; проверка адреса после DNS и на каждом перенаправлении; соединение по
проверенному IP. JS-сайты честно дают `no_text` с предложением PDF.
**Последствия.** Tilda/React-сайты без SSR дают мало текста — это видно владельцу, а не скрыто.
**Альтернативы.** Headless-браузер — вне бюджета VPS (ADR-007).
**Confirmation.** Тесты `CheckAddress` на 12 адресах (`127.0.0.1`, `169.254.169.254`, `[::1]`,
`10.0.0.5`, DNS на частный адрес, редирект на частный адрес…) → все `blocked_address`.

## ADR-011 · Модель ответа — `anthropic/claude-haiku-4.5` через OpenRouter, structured outputs

**Контекст.** A-N6-010: Anthropic через тот же шлюз, что у N5. Цена по каталогу — $1/$5 за 1 млн
токенов; `structured_outputs` поддержан.
**Решение.** `ANSWER_MODEL` из окружения без дефолта; `temperature 0`; `max_tokens 400`; JSON-схема
ответа. Трансграничная передача вопроса + фрагментов — открытый вопрос №1 (152-ФЗ).
**Альтернативы.** Sonnet — ×3 цены за ответ посетителю без замеренного выигрыша на коротких FAQ;
отечественная модель — решение владельца.
**Confirmation.** Тест старта без `ANSWER_MODEL` → выход 1; тест, что запрос несёт `response_format`.

## ADR-016 · RAG, краулер, PDF — написано заново

Донора нет (reuse-inventory §9: поиск по N1–N5 не нашёл pgvector/краулера/PDF). Пишется заново
`packages/rag` и `apps/worker/src/{crawl,pdf,chunk,embed}`; причина `нет в донорах`.
**Confirmation.** Каждый модуль приходит с тестами Refinement «Unit» и мутацией стража.

## ADR-017 · Оплата — спящий код, экран интереса; план назначает оператор

**Контекст.** A-N6-011: у магазина ЮKassa один адрес уведомлений; своего магазина у N6 нет.
**Решение.** Кнопка оплаты → экран интереса; `nobadge`/`studio` назначает оператор командой
(`SetPlanByOperator`) пилотным студиям; атрибуция конвертируется в этот момент. Входящих вебхуков
в неделю нет ([`webhook-contract.md`](webhook-contract.md)).
**Confirmation.** Тест: в неделю нет маршрута `/api/webhooks/*` (страж по дереву маршрутов).

## ADR-018 · Сырой PDF — том воркера, не объектное хранилище

**Решение.** Файл пишется в том `uploads` (общий у `web` и `worker-index`), удаляется в `finally`
индексации; ссылкой-источником служит имя файла и страница, а не файл. Нет S3 — нет внешней
зависимости и ключей.
**Последствия.** Скачать исходный PDF из плашки нельзя (посетителю показывается цитата).
**Confirmation.** Тест: после `done` и после `failed` файла `uploads/<index_job_id>` не существует.
