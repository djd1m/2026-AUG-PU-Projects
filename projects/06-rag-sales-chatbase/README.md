# 06. ИИ-продавец на данных клиента

> **Неделя 06** · `RAG` · референс: **[Chatbase](https://www.chatbase.co/) — $8M ARR, 10 000+ клиентов**

## Простыми словами

**Проблема.** На сайт приходят люди с вопросами: сколько стоит, как подключить, есть ли доставка.
Ответы уже есть — на страницах сайта, в прайсе, в PDF. Но человек их не находит и уходит.
А отвечать вручную круглосуточно невозможно.

**Что делает продукт.** Вы указываете адрес своего сайта и загружаете документы. Система их читает
и создаёт помощника, который отвечает посетителям **только по вашим материалам**. Помощник
ставится на сайт одной строчкой.

**Зачем это людям.** Посетитель получает ответ сразу, а не через день. Бизнес не теряет клиента,
который не дождался ответа.

**Одна честная деталь.** На каждый ответ помощник показывает, из какого вашего документа он взят.
А если ответа в материалах нет — честно говорит, что отвечает только по сайту и не нашёл, и даёт
контакт, вместо того чтобы сочинить. Помощник, выдумывающий условия доставки от лица вашей
компании, — это не помощь, а вред.

**Как этим пользуются.** Дали ссылку на сайт → через минуту пробный бот отвечает прямо на нашем
сайте → сохранили бота → поставили одну строку на свой сайт → нажали «Я проверил ответы бота» →
он отвечает на типовые вопросы, а вы занимаетесь сложными.

## Что делаем

Аналог Chatbase: загрузи сайт и PDF — получи бота за 10 минут. pgvector-RAG и встраиваемый виджет на сайт.

**Целевой стек:** pgvector как расширение нашего Postgres + встраиваемый виджет

## Механики роста (обязательный блок)

Главный продукт — не прототип, а **рост**: аудитория и выручка. В требования закладываем на этапе дизайна, а не после.

| Драйвер | Гипотеза для этого проекта | Как реализовано |
|---|---|---|
| **Виральность** | Виджет живёт на сайте клиента и виден всем его посетителям — «Powered by» loop как у Intercom/Crisp. Каждый клиент бесплатно раздаёт нам показы. | Бейдж «Работает на Суфлёре» на бесплатном плане, решение о бейдже принимает сервер (ADR-004); вход по бейджу `/?from=` считает атрибуцию домена; демо-страница бота `/b/{slug}` без входа |
| **Партнёрка** | Веб-студии ставят ботов клиентам и получают процент с оплат | Коды партнёров и студий, ссылка `/r/{code}`, cookie на 30 дней, анти-накрутка, комиссия 20 % от полученного после удержания ЮKassa 12 месяцев, холд 30 дней, выплата СБП от 1 000 ₽ 5-го числа, передача бота клиенту (фича 15) |
| **Блогеры / люди с аудиторией** | Партнёрский код у человека с аудиторией — тот же механизм, что у студии | Группы кодов `seed-*`, `partner`, `studio`; кабинет партнёра с когортой и суммами к выплате |

> Обязательный блок требований по росту: [`/research/GROWTH-MECHANICS-REQUIREMENTS.md`](../../research/GROWTH-MECHANICS-REQUIREMENTS.md)

## Что решено строить — «Суфлёр»

Продукт получил рабочее имя **«Суфлёр»** (предложена замена «Сноска» — решение владельца открыто).
Путь пользователя — вариант **H**: ядро «бейдж» + демо-страница + партнёрский минимум. Все 17 фич
roadmap закрыты, стенд — **https://sufler.aicoding.space**, первый живой бот стоит на
[aicoding.space](https://aicoding.space) с 28.09.2026.

Что делает бот: читает сайт (обход по разделам по кругу, sitemap с `lastmod`, robots.txt, до 50
страниц на бесплатном плане и до 300 на платных, с честной строкой «прочитано N из ≥ M известных»)
и PDF (до 10 МБ, 100 страниц) → режет текст на фрагменты 500/600/80 токенов → считает эмбеддинги
в pgvector → отвечает посетителю **только если найден фрагмент со сходством ≥ 0,40**, иначе «не
нашёл в материалах сайта» и контакт компании (ADR-003) → к каждому ответу — плашка источника со
ссылкой на страницу. На «привет» и «спасибо» отвечает вежливым шаблоном без вызова модели.

Что построено сверх исходного плана по решениям владельца:
- **живая оплата ЮKassa** — разовая на 30 дней, 990 ₽ «Без бейджа» и 4 900 ₽ «Студия»; без своего
  магазина стек работает в режиме `off` с экраном интереса; вебхук проверяется по IP-сетям ЮKassa
  и перезапросом платежа, повтор события применяется один раз (фича 14);
- **партнёрская программа и студии** (фича 15) — см. таблицу выше;
- **удаление аккаунта по 152-ФЗ** — сессии и виджеты гаснут сразу, стирание сторожем ≤ 72 ч без
  отмены, записи оплат хранятся 5 лет обезличенными, долг партнёру не сгорает (фича 17);
- **ворота «Я проверил ответы бота»** (A-N6-035): пока владелец не подтвердил ответы, посетители
  видят «Бот ещё настраивается»; с 28.09 это видно владельцу баннером на экранах установки и бота,
  число таких посетителей — в сводке, снятие отметки новыми материалами — с датой и причиной;
- **усечение по бюджету вместо отказа** — предпросмотр читает 120 000 токенов и говорит «прочитано
  N страниц», а не падает; **обновление и удаление источника**; **пробел на стыке элементов** при
  извлечении текста.

Чего в продукте сознательно нет: автоматического снятия отметки «проверено» по времени, проверки
смысла ответа второй моделью (риск A-N6-030 огорожен воротами), рассылки сводок в Telegram (v1),
white-label для студий (v1).

Стек: Next.js 15 App Router + `pg` без ORM + zod, PostgreSQL 16 + pgvector 0.8.6, BullMQ на Redis 7.4,
виджет — один `<script>` на 5,8 КБ gzip в открытом Shadow DOM без инлайновых стилей. Модели через
один шлюз OpenRouter: `anthropic/claude-haiku-4.5` для ответов, `openai/text-embedding-3-small`
(1536 измерений) для эмбеддингов; локальных моделей нет. Шесть сервисов Docker Compose за своей
дверью Caddy с лимитом частоты, на стенде — за общим TLS-прокси машины. Расход моделей на стенде за
первые двое суток — меньше $0,12.

## Как запустить

**Полное пошаговое описание — [`docs/REPRODUCE.md`](docs/REPRODUCE.md)**: зависимости, тестовый
стек, контейнер Playwright, конвейер фичи с ревью, подъём стенда с доменом и общим прокси, ключи
ЮKassa, проверки по выданному адресу. Ниже — только суть. Перед любым запуском:

```bash
node ../../.claude/hooks/check-ports.cjs .           # хранилища наружу не смотрят
bash ../../scripts/check-port-conflicts.sh .         # порты этой машины свободны
```

```bash
cp .env.example /path/outside/repo/stand.env         # секреты: openssl rand -hex 24 / 32; 14 потолков QUOTA_* и N6_PUBLIC_ORIGIN дефолтов НЕ имеют
docker compose -f compose.test.yml --project-directory . --env-file <env> run --rm --build test    # 1094 теста на настоящих PostgreSQL+pgvector и Redis
bash scripts/check-responsive.sh --test tests/browser                                               # 673 браузерных теста в контейнере Playwright, 3 движка
docker compose -f docker-compose.yml -f compose.stand.yml --env-file <env> up -d --build            # стенд за общим прокси
bash scripts/stand-set-yookassa.sh                                                                  # включить живую оплату, когда есть магазин
```

Отсутствие любой из 14 переменных `QUOTA_*`, ключа OpenRouter, моделей или `N6_PUBLIC_ORIGIN`
валит запуск намеренно: ненастроенный потолок означает неограниченный платный вызов, а адрес по
умолчанию уезжает в ссылку бейджа на чужих сайтах. `web` при старте делает пробный вызов настоящей
модели и без него не поднимается.
