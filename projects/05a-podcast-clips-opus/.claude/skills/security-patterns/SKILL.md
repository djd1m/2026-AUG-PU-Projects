# Образцы безопасности ClipMkr (05a)

Загрузить `.claude/rules/security.md`, `.claude/rules/secrets-management.md`,
`.claude/agents/cost-guard.md`, `docs/model-cost-contract.md`, `docs/long-job-contract.md` и
нужный алгоритм `docs/Pseudocode.md`.

## Образец: транспорт сессии и CSRF (VT-04/VA-06, ADR-011)

```
1. access-JWT (15 мин) и refresh — ТОЛЬКО в cookie HttpOnly; Secure; SameSite=Lax; Path=/
2. Authorization: Bearer НЕ используется — иначе /admin/* (серверный HTML) не прочитает сессию
3. POST/DELETE проверяют Origin = BASE_URL → иначе 403
4. /admin/* — роль оператора проверяется И в middleware, И в каждом обработчике
```

Одна дыра здесь ломает и вход, и всю операторскую поверхность одновременно — оба класса читают
сессию одним и тем же способом намеренно.

## Образец: файл проверяется по содержимому

```
1. лимит частоты ДО разбора тела
2. лимит загрузок — на POST /api/videos (создание записи video), НЕ на complete (VT-17)
3. объявленный размер ≤ 2 ГБ, длительность ≤ 120 мин — до выдачи ссылок на части
4. после сборки: HeadObject + magic bytes (ftyp/EBML) в web, ДО создания задачи
5. повторно в {job_id}.stt.prepare: ffprobe, разрешение ≤ 3840×2160, длительность совпадает
6. любой отказ → file_invalid, объект удаляется из S3
```

Content-Type и расширение клиента — не доказательство. Двойная проверка (шаг 4 и шаг 5)
намеренная: `web` не может доверять тому, что дошло до `worker-ai` без повторной сверки.

## Образец: выполнимость LLM ДО резерва STT (OWN-05A-012, ADR-006 п.3 — самый дорогой класс находки проекта)

```
1. est_kop ← верхняя оценка ОДНОЙ попытки LLM по длительности видео (вход×цена + max_tokens×цена)
2. est_kop > LIMIT_LLM_KOP_JOB → failed/quota_user НЕМЕДЛЕННО, до первого вызова STT
3. остаток автора (LLM_USER_KOP_DAY) < est_kop → failed/quota_user
4. остаток сервиса (LLM_GLOBAL_KOP_DAY) < est_kop → failed/quota_global
5. все три пройдены → резерв STT (шаг допуска продолжается ниже)
```

Это ПРОВЕРКА ЧТЕНИЕМ, не резерв — настоящий резерв LLM происходит на шаге вызова и может отказать
отдельно. Пропуск этой проверки — единственный найденный класс, где деньги тратятся БЕЗ клипа
(VA-03): двухчасовой выпуск оплачивает STT целиком и падает `selection_failed` только на резерве
LLM.

## Образец: атомарный резерв потолка и ворота допуска (VA-01, ADR-006)

```
INSERT INTO quota_counter (scope, scope_id, day, kind, used) VALUES (…, :n)
ON CONFLICT (scope, scope_id, day, kind)
DO UPDATE SET used = quota_counter.used + :n WHERE quota_counter.used + :n <= :limit
RETURNING used
-- пустой RETURNING = отказ; откат ВСЕЙ транзакции при отказе ЛЮБОГО из ключей
```

Ворота допуска живут в шаге 1 «Транскрипции куска» (`c.attempt_count = 0 AND нет отметки допуска
задачи`), не в «Повторе задачи». Повтор после `quota_user` идёт через ЭТИ ЖЕ ворота — иначе
повтор обходит потолок целиком (единственный blocker Phase 2 итерации 1 этого проекта).

Две РАЗНЫЕ формулы для одного счётчика: персональный — по длительности ЗАПИСИ без перекрытий,
глобальный — по секундам ПРОВАЙДЕРА с перекрытием 5 с. Новичок (< 24 ч, `beta_at IS NULL`) —
дополнительно сверяется с `LIMIT_STT_NEWBIE_SEC_DAY` и общим пулом `stt_sec_newbie`, ОДНОЙ
атомарной операцией с обычными счётчиками.

## Образец: область владения

```
резолвить актёра из сессии → загрузить объект по account_id владельца → только потом авторизовать
```

Чужой и несуществующий `video_id`/`job_id`/`clip_id` дают ОДИН `404`. Исключение — `/admin/*`:
`403` там означает «вы не оператор», не «объект существует». Публичные `/c/{clip_code}`,
`/p/{partner_code}` сервер НЕ открывает сам — публикация засчитывается только по проверке
оператора вручную (нет SSRF-поверхности, ADR-014).

## Образец: знак переживает ЛЮБОЕ кадрирование (OWN-05A-015, три обрезки)

```
1. геометрия знака считается ОДИН РАЗ при старте worker-render: наибольший кегль 40–52,
   при котором площадь плашки 1–4% кадра И pw ≤ 294 px
2. если такого кегля для WATERMARK_TEXT нет — worker-render НЕ СТАРТУЕТ
3. знак — по центру у нижней кромки полосы видео, над субтитрами (НЕ угол, НЕ чёрное поле)
4. проверка OCR на ТРЁХ обрезках: чёрные поля, квадрат по спикеру, fill/zoom 9:16
```

Два прошлых места знака (угол OWN-05A-013, чёрное поле — исходное) были найдены как дефекты
именно потому, что проверялись только на ОДНОЙ обрезке из трёх реальных способов кадрирования
(VA-05, затем VA2-02 на том же самом тесте, изменённом только под первую находку).

## Образец: текст из чужого ответа не исполняется

Названия фрагментов и цитаты приходят от модели; подпись к посту и промокод — от пользователя.
Экранировать на ВСЕХ поверхностях: субтитры ASS (`escapeAssText`), знак (`escapeDrawtext`), экран
клипа. ffmpeg вызывается `execFile`/`spawn` без shell.

## Как доказывается каждый образец

Отрицательным или мутационным тестом (`Refinement.md` §2.4/§2.5): страж, ни разу не показавший
красное, стражем не является. Конкурентность и уникальность проверяются на настоящем
PostgreSQL/Redis. Не объявлять установленным ограничитель частоты, хранилище секретов или
инструмент безопасности, которого не видел.
