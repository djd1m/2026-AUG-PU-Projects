# ClipMkr (05a) — соглашения кода

Источники: `docs/canon.md` (§2 workspace, §4 таблицы, §5 закрытые списки, §11 единицы),
`docs/Architecture.md`/`docs/Architecture-compose.md`, `docs/Pseudocode.md`, `docs/ADR.md`
(ADR-012 стек, ADR-002/010 ffmpeg). Стек — целевой: `package.json` монорепо ещё не заведён, точные
версии сверх зафиксированных lock-файлом донора фиксируются на фиче `foundation-auth` и
подтверждаются исходником, а не этим документом.

## Структура монорепо (canon §2)

npm workspaces, контекст сборки — корень проекта:

```
apps/web            Next.js 15.5.12 (App Router), REST route handlers канона §7, /admin/*
apps/worker         точки входа worker-ai / worker-render, CLI `ops`
packages/db         схема Prisma, миграции, клиент
packages/queue      очереди BullMQ, имена, jobId
packages/s3         клиент S3, ключи объектов, подписанные ссылки
packages/config     чтение и проверка окружения (canon §6, без дефолтов)
packages/models     интерфейсы Transcriber, SelectionModel и адаптеры OpenRouter/OpenAI
packages/payments   интерфейс PaymentProvider и FakePaymentProvider (v1, не подключён к маршрутам)
packages/types      общие типы и закрытые списки canon §5
```

Доменная логика не знает ни Next.js request-объекта, ни клиента Prisma, ни формы ответа
поставщика модели. Адаптеры переводят чужое в свои типы на границе. Поставщик модели и поставщик
оплаты — за интерфейсом с несколькими реализациями каждый.

## Имена и типы

- Имена сущностей, статусов, маршрутов, очередей и чисел берутся из `docs/canon.md` и не
  переизобретаются. Где `Specification.md` расходится с каноном — canon §12 называет расхождение
  и канон правит все документы. Осознанное переименование записывается в план фичи.
- `PascalCase` — типы; `camelCase` — функции и значения; `kebab-case` — файлы и сегменты
  маршрутов; `snake_case` — колонки и таблицы БД (единственное число: `account`, не `accounts`).
- Закрытые перечисления — union-типы, не строки и не булевы флаги: `job.status` (ровно 3),
  `job.step` (3), `job.fail_reason` (9), `transcript_chunk.status` (2), `clip.render_status` (4),
  `account.plan` (2 + fail-closed на прочее), `account.role` (2 + fail-closed),
  `publication.status` (4), `attribution.stage`/`.source` (2/2), `spend_ledger.outcome` (4),
  `quota_counter.kind` (5). Булево там, где значений больше двух, теряет состояние.
- `jobId` BullMQ — разделитель точка, НЕ двоеточие: `{job_id}.stt.prepare`,
  `{job_id}.stt.{chunk_idx}`, `{job_id}.llm`, `{clip_id}.render` (BullMQ 5 отвергает `:` в
  `Custom Id`, VT-01, измерено на `bullmq@5.81.5`).

## Единицы и время (canon §11)

- Позиция в медиа и длительность клипа — миллисекунды, целое, суффикс `_ms`. Модель НЕ возвращает
  мс: фрагмент задаётся индексами `start_unit`/`end_unit`, мс считает код (ADR-005 п.2).
- Аудио в потолках STT — секунды, целое, суффикс `_sec`. **Две разные формулы, не путать:**
  персональный счётчик (`stt_sec` аккаунта/новичка) — по длительности ЗАПИСИ без перекрытий
  (`ceil(Σ unique_ms / 1000)`); глобальный счётчик сервиса — по секундам ПРОВАЙДЕРА с
  перекрытием 5 с (`Σ ceil(chunk.duration_ms / 1000)`).
- Деньги у нас — копейки, целое, суффикс `_kop`; плавающая точка для денег запрещена. Стоимость от
  OpenRouter — микродоллары, целое (`usage.cost` × 10⁶), суффикс `_usd_micro`.
- Граница суток для ВСЕХ счётчиков, включая job-счётчики LLM, — `msk_day(now())` В МОМЕНТ ПОПЫТКИ
  (`Europe/Moscow`, 00:00), не `job.created_at` (VT2-11) — долгая задача, начатая вчера, платит по
  сегодняшнему дню на попытке, случившейся сегодня.
- Кегль знака — px, целое, наибольший из 40–52, при котором плашка занимает 1–4 % кадра 1080×1920
  И `pw ≤ 294 px`; если такого кегля нет — `worker-render` НЕ СТАРТУЕТ (не рендерит со знаком шире
  окна).

## PostgreSQL без ORM-магии

- Миграции — обычные SQL/Prisma-файлы в `packages/db/migrations`, применяются по порядку, откат
  описан. Схема — контракт, не производная от кода.
- Запросы параметризованные. Идентификаторы — значения, не интерполируемые куски SQL.
- Уникальность и потолки обеспечивает БАЗА: `UNIQUE (account_id, idempotency_key)` на `job`,
  `UNIQUE (job_id, chunk_idx)` на `transcript_chunk`, `UNIQUE clip_code`, `UNIQUE
  url_normalized`, `UNIQUE partner_code`, `UNIQUE (account_id, stage)` на `attribution`;
  `quota_counter` PK (`scope`, `scope_id`, `day`, `kind`).
- «Прочитать, потом записать» ЗАПРЕЩЕНО на разделяемом ресурсе. Резерв потолка — один оператор:
  `INSERT … ON CONFLICT (scope, scope_id, day, kind) DO UPDATE SET used = quota_counter.used + :n
  WHERE quota_counter.used + :n <= :limit RETURNING used`. Пустой `RETURNING` = отказ.
- Соединение не удерживается во время внешнего вызова (STT/LLM/S3): резерв закрывается ДО вызова,
  результат пишется короткой транзакцией после.
- `event` — дедупликация ЧЕТЫРЬМЯ частичными уникальными индексами (день считается по
  `(created_at AT TIME ZONE 'Europe/Moscow')::date`): `download_clicked`/`share_clicked` раз в
  сутки на (автор, клип); `clip_viewed`/`self_reported_published` раз на (автор, клип);
  `fakedoor_clicked` раз в сутки на автора; `clip_link_visited` раз в сутки на (клип, сессия
  `sid`).

## Числа и источник

- Цена секунды STT берётся из `GET /api/v1/models` OpenRouter ПРИ СТАРТЕ `worker-ai`; модели нет в
  ответе — старт падает. До ответа провайдера `spend_ledger` пишет ОЦЕНКУ («секунды × цена») с
  `cost_estimated = true`; пришёл `usage.cost` — факт с `cost_estimated = false`. Ноль вместо «нет
  данных» не пишется.
- Транскрипт передаётся модели ВНУТРИ границы `<transcript>` как ДАННЫЕ; цитаты (`hook_quote`,
  `completeness_quote`) сверяются кодом как подстрока после нормализации пробелов/регистра —
  отсутствие совпадения даёт «компонент без балла», не падение всего рендера карточки.

## Ответы и ошибки

- Единый формат ответа API: `202 {job_id}` при создании долгой задачи; `404` для чужого/
  несуществующего; `403` для CSRF и для `/admin/*` без роли; `422` для невалидного входа.
- Отказ называет причину из закрытого списка (`job.fail_reason`, 9 значений) — «приходите завтра»
  для `quota_user`/`quota_global`, а не общий текст ошибки.
- Отсутствие числа показывается как отсутствие: `unmatched`/пустой результат исключается из счёта,
  а не заменяется нулём; метрика на n < 30 — «k из n», не процент.

## Известные грабли стека (перенесены из аудита донора, R3-jan-audit)

- `env.ts` донора подставлял дефолты для `S3_BUCKET`/`S3_REGION` и делал ключи необязательными —
  переписывается: у `@clipmkr/config` дефолтов на переменные canon §6 нет, кроме явно помеченных
  `${VAR:-default}` (хостовые порты, `RENDER_CONCURRENCY`, `LOG_LEVEL`).
- `rate-limit.ts` донора открывался при сбое Redis («без лимита при недоступности») —
  переписывается: недоступный Redis — отказ `503`, не пропуск проверки.
- Донорский воркер делал `process.exit(0)` по SIGTERM — переписывается на `worker.close()` с
  `stop_grace_period: 60s`, иначе активная задача теряется и повтор начинается заново.
- Экранирование ffmpeg (`escapeAssText`, `escapeDrawtext`) — брать из донора как есть, но со
  `execFile`/`spawn` без shell.
- Клиент S3 (AWS SDK JS v3) создаётся с `requestChecksumCalculation: 'WHEN_REQUIRED'` и
  `responseChecksumValidation: 'WHEN_REQUIRED'` — иначе SDK добавляет в подписанные ссылки на
  части контрольные суммы, которые браузер не пришлёт (VA2-11).
- Шрифт для ASS/`drawtext` — ОДИН файл в образе (`/app/fonts/`), не через `apk`/fontconfig: иначе
  libass молча подставит другой шрифт, и текст разойдётся с рассчитанной шириной плашки знака.

## Перед тем как назвать команду

Точные версии, пути внутри workspace и имена npm-скриптов фиксирует фича `foundation-auth` и
подтверждает исходник. До этого команда из документа — предложение, а не факт. Если чего-то нет —
сообщить о пробеле, а не изобрести синтаксис.
