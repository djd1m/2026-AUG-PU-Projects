## Какой секрет какому сервису

Минимальная привилегия проверяема: сервис, которому нечем позвать модель или провайдера оплаты,
их не позовёт.

| Секрет | `web` | `migrate` | `worker-ai` | `worker-render` | Почему |
|---|---|---|---|---|---|
| `OPENROUTER_API_KEY` | нет | нет | **да** | нет | STT и LLM зовёт только `worker-ai` (ADR-004) |
| `OPENAI_API_KEY` | нет | нет | да, только при `STT_PROVIDER=openai` | нет | запасной путь ADR-001, не всегда нужен |
| `JWT_SECRET` | **да** | нет | нет | нет | сессия проверяется только в `web` |
| `SMTP_URL`, `MAIL_FROM` | **да** | нет | нет | нет | письма подтверждения шлёт только `web` |
| `S3_*` (5 переменных) | да | да | да | да | все четыре пишут/читают объекты своего этапа |
| `PAYMENTS_*` (v1) | **да** | нет | нет | нет | оплата не подключена к маршрутам недели, но ключ, если появится, — только у `web` |
| `POSTGRES_PASSWORD` | да | да | да | нет (нет прямого доступа к БД у рендера, читает через `web`/задачу) | — |
| `REDIS_PASSWORD` | да | нет | да | да | все три ходят в BullMQ/лимиты |
| `WATERMARK_TEXT` | нет | нет | нет | **да** | решение о знаке и раскладку принимает только рендер |

`worker-render` не имеет ни одного ключа модели или оплаты. Это не стиль, а инвариант, проверяемый
списком `environment:` сервиса в `docker compose config` (ADR-004: «недоступность — отказ без
тихой смены модели», список секретов — часть того же решения).

## Только окружение, никаких значений в git

- В репозиторий попадают ТОЛЬКО имена переменных и безопасные примеры — `.env.example` (полный
  список canon §6 без значений). Значения живут в `.env` вне git на каждом окружении отдельно.
- Секреты не попадают в образ: `.dockerignore` исключает `.env*`, `.reference`, `docs`,
  `node_modules`, `tests` — `COPY . .` без него утащил бы их в слой.
- Не логировать никогда: `OPENROUTER_API_KEY`/`OPENAI_API_KEY`, `JWT_SECRET`, полное значение
  cookie сессии, содержимое письма подтверждения, полный (не усечённый) email в журналах
  безопасности, сырые байты видео/аудио.
- Наличие переменной проверяется по ИМЕНИ в `docker compose config`, без печати значения; перед
  приложением доказательства к квитанции вывод редактируется.

## Отсутствующий секрет или потолок — отказ, а не дефолт

Пустая переменная не означает «ограничений нет» и не означает «возьмём разумное значение»
(`fail-closed-defaults.md`).

- **Девять потолков** (canon §6: `LIMIT_STT_USER_SEC_DAY`, `LIMIT_STT_NEWBIE_SEC_DAY`,
  `LIMIT_STT_NEWBIE_GLOBAL_SEC_DAY`, `LIMIT_UPLOADS_USER_DAY`, `LIMIT_LLM_USER_KOP_DAY`,
  `LIMIT_STT_GLOBAL_SEC_DAY`, `LIMIT_LLM_GLOBAL_KOP_DAY`, `LIMIT_LLM_ATTEMPTS_JOB`,
  `LIMIT_LLM_KOP_JOB`) — отсутствие ЛЮБОГО валит старт `web`/`worker-ai` ненулевым кодом с
  сообщением, называющим незакрытый вызов (ADR-006). Проверяется ОТДЕЛЬНЫМИ прогонами на каждую
  переменную — проверка одной зеленеет при отсутствующей второй.
- **Дополнительная самопроверка `worker-ai`:** `llm_reserve_kop(7200 × LLM_EST_CHARS_PER_SEC) ×
  LIMIT_LLM_ATTEMPTS_JOB ≤ LIMIT_LLM_KOP_JOB` — если завышенный `LLM_EST_CHARS_PER_SEC` нарушает
  это неравенство, процесс НЕ СТАРТУЕТ (V3-08: гарантия AC-clips-8 иначе ничем не проверялась).
- `BASE_URL` дефолта не имеет по построению: определяет КАЖДУЮ выдаваемую наружу ссылку (письмо
  подтверждения, ссылка на клип в подписи, `/reset?token=`). Тихий `http://localhost:3000` сделал
  бы все выданные адреса нерабочими при зелёных тестах (`silent-fallbacks.md`, заслужено проектом
  01). В compose объявлен как `${BASE_URL:?}`.
- Исключение ровно одно и оно названо: ХОСТОВЫЕ ПОРТЫ (`WEB_PORT`, `CADDY_HTTP_PORT`,
  `CADDY_HTTPS_PORT`) и `RENDER_CONCURRENCY`/`LOG_LEVEL`/`RENDER_CPUS` объявлены как
  `${VAR:-default}` — требование `port-conflicts-local.md`; ошибка в них ломает запуск громко, не
  отдаёт наружу неверные данные.
- `PAYMENTS_PROVIDER`/`PAYMENTS_SHOP_ID`/`PAYMENTS_SECRET_KEY` без дефолта ТОЛЬКО при
  `PAYMENTS_MODE=live`; на неделе `PAYMENTS_MODE=fake` и все три пусты законно (ADR-013).

## OpenRouter — единая точка отказа, не единая точка компромисса

Список запасных моделей (`models: [...]`) НЕ передаётся в запросе OpenRouter — подмена модели
меняет качество и цену без ведома пользователя (ADR-003 п.2). Фактическая модель из ответа
записывается в `spend_ledger.model` — это и проверка, что запрос действительно ушёл выбранной
моделью, а не той, что OpenRouter выбрал сам.

## Ротация и компрометация

- Ротация `OPENROUTER_API_KEY`: новый ключ в окружение, перезапуск `worker-ai`. Незавершённые
  задачи не теряются — `job` строка БД, а не эфемерный брокер (ADR-008).
- Ротация `JWT_SECRET` инвалидирует все выданные access/refresh — пользователи проходят вход
  заново; аккаунты и данные не трогаются.
- Ротация `SMTP_URL`/ключа Resend не влияет на уже отправленные письма; домен отправителя
  (`clipmkr.ru`) должен пройти SPF/DKIM в Resend ДО первой рассылки, иначе письма не уйдут
  (OWN-05A-011, чек-лист дня 0).
- При подозрении на утечку ключа модели: отозвать ключ у OpenRouter ПЕРВЫМ действием (счёт
  выставляют чужие действия и откатить его нечем), затем сверить расход по `ops spend-today` и по
  консоли OpenRouter.
- MinIO (тестовый профиль) — пароль случайный, не `minioadmin` (canon §1, `docker-ports.md`
  Правило №0).
