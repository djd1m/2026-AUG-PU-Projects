## Порядок операций — это и есть защита

| Граница | Обязательный порядок | Что ломает обратный |
|---|---|---|
| Интернет → `caddy` → `web` | TLS → лимит тела 1 МБ → сессия → лимит частоты → валидация → резерв → действие | мусорный запрос доходит до дорогого шага раньше отказа |
| Регистрация/вход | лимит частоты (≤5 регистраций/IP/ч, ≤10 неуспехов входа/аккаунт/15 мин) ДО сравнения пароля, атомарным `INCR` | «прочитать `GET`, потом инкрементировать при неудаче» пропускает конкурентные попытки мимо счётчика (`curl --parallel` обходит лимит целиком, VT-07/VA-12) |
| Загрузка | подтверждение почты → лимит частоты → размер объявлен ≤ 2 ГБ → лимит загрузок (`POST /api/videos`, НЕ `complete`, VT-17) → выдача ссылок → magic bytes после сборки → допуск STT (см. ниже) | без подтверждения почты платный вызов запускает непроверенный адрес; лимит на `complete` не резервирует ничего (потолок обходится) |
| Допуск STT | **выполнимость LLM (est_kop против трёх пределов) ДО резерва STT** (OWN-05A-012) | двухчасовой выпуск оплачивает STT целиком и падает `selection_failed` на резерве LLM — деньги без клипа (VA-03) |
| Повтор задачи | ворота допуска — в шаге 1 «Транскрипции куска», не в «Повторе» | повтор после `quota_user` тратит STT без факта допуска (VA-01, единственный blocker Phase 2 итерации 1) |
| `worker-ai` → OpenRouter | резерв → вызов ВНЕ транзакции → факт в `spend_ledger` | соединение пула держится время сетевого вызова |
| Транскрипт → LLM | транскрипт внутри `<transcript>` как ДАННЫЕ; ответ проходит JSON-схему; цитаты сверяются кодом | текст фрагмента исполняется как инструкция |
| Текст → ffmpeg | `execFile`/`spawn` без shell; `escapeAssText`/`escapeDrawtext` | инъекция в субтитры ломает фильтр или исполняет команду |
| Посетитель → `/p/…`, `/c/…` | лимит 30 обращений с IP в час; несуществующий код = обычный лендинг без события | перебор кодов партнёра |

Недоступность внешнего источника истины (OpenRouter, S3, Resend) — **исключение**, откатывающее
транзакцию, а не возвращаемое значение: штатный возврат из колбэка транзакции её коммитит вместе
со всем, что успело записаться (урок ADR-007 донора — переписывается).

## Транспорт сессии (VT-04/VA-06, ADR-011)

Access-JWT (15 мин) и refresh — только в cookie `HttpOnly; Secure; SameSite=Lax; Path=/`.
`Authorization: Bearer` не используется — иначе серверный рендер `/admin/*` не сможет прочитать
сессию так же, как API. Мутирующие запросы (`POST`/`DELETE`) проверяют `Origin = BASE_URL`
(CSRF), иначе `403`. Refresh хранится хэшем, отзывается при сбросе пароля.

## Владение и раскрытие — `404`, а не `403`

Чужой и несуществующий `video_id`/`job_id`/`clip_id` дают ОДИН `404`. Владение резолвится из
сессии на сервере по `account_id`; идентификатор из тела запроса игнорируется. Исключение —
`/admin/*`: `403` там означает «вы не оператор» и это ожидаемое поведение, а не утечка
существования ресурса.

- `/admin/*` — только `account.role = operator`, проверка в middleware **и** в каждом серверном
  обработчике (урок CVE-2025-29927: middleware одна недостаточна). Значение роли, отличное от
  ровно `operator`, читается как `user` (fail-closed). Роль ставит только `docker compose exec
  worker-ai ops grant-operator <email>` — не через интерфейс.
- `/c/{clip_code}`, `/p/{partner_code}` не открываются сервером (нет SSRF-поверхности): публикация
  засчитывается только после того, как ОПЕРАТОР открыл ссылку сам и проверил пост, клип и знак
  (ADR-014). Сервер ссылку на чужую страницу не запрашивает никогда.

## Граница входа: файл проверяется по содержимому

- Тип определяется по БАЙТАМ (`ftyp` со смещения 4 для MP4/MOV, EBML `1A 45 DF A3` для WebM/MKV).
  Заявленный `Content-Type` и расширение — не доказательство.
- Проверка выполняется ДВАЖДЫ: сразу после сборки multipart-загрузки в `web`, до создания задачи
  (В-14), и повторно в `{job_id}.stt.prepare` вместе с `ffprobe`. Отказ на любом шаге удаляет
  объект из S3.
- Разрешение больше 3840×2160 отвергается ДО декодирования (бомба распаковки, VA-23). Фактическая
  длительность, расходящаяся с заявленной, — `file_invalid`.
- Полиглот (годен и как видео, и как HTML/архив) отвергается.

## Особый денежный контур

Продукт запускает платные вызовы (STT/LLM) действием **постороннего** — любого зарегистрированного
автора своей загрузкой. Правило `model-call-cost.md` применяется целиком; полная механика — в
`.claude/agents/cost-guard.md` и `docs/model-cost-contract.md`. Здесь — только то, что относится к
границе входа: резерв потолка выполняется ПОСЛЕ валидации (мусорный запрос не жжёт квоту) и ДО
любого платного вызова (вызов не оплачивается, пока не разрешён).

## Fail-closed: неопознанное значение — самое строгое

`account.plan` вне `free`/`paid` → `free` (знак вшивается). `account.role` вне `user`/`operator`
→ `user`. `job.status`/`job.fail_reason`/`clip.render_status`/`publication.status`/
`attribution.stage`/`.source`/`spend_ledger.outcome` вне закрытого набора canon §5 —
недопустимое состояние, обработчик отказывает, не подставляет дефолт. Ноль в знаменателе метрики
(0 активированных авторов) → «нет данных», не `0%` (`honest-configuration.md` CFG-I7).

## Шифрование и секреты

TLS на `caddy` для `clipmkr.ru`; TLS до OpenRouter и S3 с проверкой сертификата ВСЕГДА, включая
тестовый профиль — отключение запрещено в любом профиле (дефект донора `rejectUnauthorized: false`
не переносится, ADR-004). Секреты только из окружения, минимальный набор на сервис — см.
`secrets-management.md`. Бакет приватный, ссылки на объекты — подписанные, TTL 15 мин.

## Персональные данные (NFR-clips-6)

Сырой IP не пишется в таблицу `event`. IP в журнале безопасности хранится не дольше 30 дней.

(OWN-05A-004, PRD §7.1) — не сняты кодом, минимальная митигация до юриста — тексты согласий и
галочки при регистрации/загрузке (FR-clips-1 п.2, FR-clips-2 п.4).
