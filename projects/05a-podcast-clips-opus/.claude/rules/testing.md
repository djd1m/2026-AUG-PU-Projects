Раннер и точные версии фиксирует фича `foundation-auth`. Тестовый профиль compose поднимает
Postgres/Redis/MinIO настоящими (OWN-004) — реализация не начиналась, поэтому число прошедших
тестов на 2026-09-23 равно нулю.

## Слой выбирается по природе признака, а не по удобству

| Природа признака | Слой | Примеры этого проекта |
|---|---|---|
| арифметика, закрытые перечисления, границы | unit | балл длины (25 с→10, 47 с→20), диапазоны индексов `start_unit`/`end_unit`, fail-closed `account.plan` |
| согласованность двух компонентов, транзакции, ответы маршрутов | integration | резерв потолка, ответ `Transcriber`/`SelectionModel`, multipart-загрузка MinIO |
| путь человека на РАЗВЁРНУТОМ стенде | E2E | CJM целиком по `https://clipmkr.ru`, не `localhost`; ETag браузером, не `curl` |
| разделяемый ресурс | **конкурентный прогон** | лимит загрузок, допуск STT, аренда рендера, счётчик неуспехов входа |
| свойство исходника | страж по коду | ворота допуска VA-01, атомарность резерва, геометрия знака при старте |

## 13 обязательных конкурентных и адверсариальных тестов (Refinement §2.4) — не факультатив

Последовательный тест на разделяемом ресурсе зеленеет ПРИ ОБЕИХ реализациях: атомарной и
«прочитать-потом-записать». Различает их только параллельный прогон.

1. **Лимит загрузок** — 20 параллельных `POST /api/videos` при остатке 1 из 3 → ровно 1 создаёт
   `video`, 19 отказывают до выдачи ссылок.
2. **Допуск STT — резерв секунд** — N задач при остатке на одну → проходит ровно та, чей резерв
   укладывается, сумма зарезервированного не превышает остаток.
3. **10 аккаунтов за одним NAT** — персональный потолок на `account_id`, не на IP; никто не
   блокирует соседа.
4. **Аренда воркера рендера** — 3 задачи при `RENDER_CONCURRENCY=1` → не больше 1 активного,
   остальные ждут в очереди, не отказывают.
5. **VA-01 — повтор не обходит потолок.** Отказ `quota_user`/`quota_global` на любом куске →
   «Повторить» даёт 0 новых вызовов STT, `spend_ledger` не растёт. Ворота — шаг 1 «Транскрипции
   куска», не «Повтор» (второй прогон того же риска другим путём: подготовка падает ДО допуска —
   уборщик подхватывает задачу, ворота отказывают вызову STT без отметки допуска).
6. **Перебор паролей** — 50 параллельных неверных попыток на один email → не больше 10 дошло до
   `argon2.verify`; счётчик — атомарный `INCR` ДО сравнения пароля.
7. **Выполнимость LLM до оплаты STT** — 4 прогона по ветвям допуска (укладывается / превышает
   `LIMIT_LLM_KOP_JOB` / недостаточно остатка автора / недостаточно остатка сервиса); в отказных
   ветках — ноль строк `stt` в `spend_ledger` для этой задачи.
8. **Знак переживает ТРИ обрезки** — `crop=1080:608:0:420` (чёрные поля), `crop=608:608:236:420`
   (квадрат по спикеру), `crop=342:608:369:420` (fill/zoom 9:16, случай (а), самый частый по
   VA2-02). OCR ≥ 9/10 на всех трёх БЕЗ исключений — плашка гарантированно `≤ 294 px < 342 px`
   окна.
9. **Новичок упирается в 30 мин** — аккаунт < 24 ч без `beta_at`, видео 45 мин →
   `failed/quota_user` на 1800 с, хотя обычный потолок (7200 с) формально позволил бы. Второй
   прогон: тот же аккаунт после 24 ч → допуск проходит по обычному потолку.
10. **Пул новичков ≤ половины сервиса (конкурентно)** — N новых аккаунтов грузят по 25 мин →
    совокупный резерв не превышает 45000 с; превышение даёт `quota_global`, не `quota_user`.
11. **Бета-автор получает полные 120 мин** — отмеченный `ops beta-add` аккаунт < 24 ч грузит
    100 мин → резерв по обычному потолку, НЕ засчитывается в пул новичков.
12. **Самопроверка `worker-ai` при старте** — завышенный `LLM_EST_CHARS_PER_SEC` (2 × резерв >
    2400) → процесс НЕ СТАРТУЕТ. Штатное значение (22) → стартует.
13. **`finish_reason = 'length'` не запускает бесконечный повтор** — обрубленный JSON →
    `finish_reason` проверяется ДО `JSON.parse` → немедленный `failed/selection_failed`, одна
    попытка в `spend_ledger`, без повтора BullMQ на том же `max_tokens`.

## 15 мутационных стражей (Refinement §2.5) — испытаны на падение ДО зачёта

Страж, ни разу не показавший красное, стражем не является. Каждый принимается ВМЕСТЕ с прогоном
на внедрённом дефекте: дефект возвращён → красный; код восстановлен → зелёный; обе строки в
квитанции фичи. Полная таблица «страж → внедряемый дефект» — `docs/Refinement.md` §2.5, не
пересказывать здесь второй раз. Пятнадцать стражей покрывают: контракт долгой задачи, контракт
стоимости, валидатор magic bytes, атомарный резерв, ворота VA-01, выполнимость LLM (шаг 2a),
знак по центру над субтитрами, геометрия знака (`pw ≤ 294`), квота новичка, пул новичков,
бета-обход квоты, самопроверка `worker-ai`, метрика по каналу (не по аккаунту), проверка цитат,
проба ADR-001.

## E2E — на РАЗВЁРНУТОМ стенде, по ЧУЖОМУ адресу

Правило `deployment-seams.md`: модуль, корректный в изоляции, ничего не гарантирует о системе.
Прогон обращается к адресу, который выдало РАЗВЁРТЫВАНИЕ (`https://clipmkr.ru` или адрес тестового
стенда), а не к `localhost` — `BASE_URL` в canon §6 без дефолта именно по этому уроку.

| Сценарий | Что ловит |
|---|---|
| CJM целиком: регистрация → письмо → загрузка → `running` → `succeeded` → просмотр → скачать → скопировать подпись → paste-back | обходной путь пропуска подтверждения; ссылка `/c/{clip_code}` реально ведёт на `BASE_URL` |
| Граница reverse-proxy: прямой запрос к порту `web`/`worker-ai` мимо `caddy` | приложение не опубликовано рядом с прокси; хранилища недоступны кроме петли |
| Загрузка части файла БРАУЗЕРОМ, не `curl` | `ExposeHeaders: ETag` в CORS бакета реально достаёт заголовок скрипту — `curl` не применяет политику CORS |
| Знак после сжатия площадки | клип перекодирован 720×1280 H.264 1.5 Мбит/с, OCR (rus+eng) ≥ 9/10 |
| Умерший воркер | `docker compose kill worker-ai` посреди задачи → переустановка через 5 мин, `worker_lost` после 3 попыток |

## Тесты не ходят в интернет боевыми ключами

Поставщики STT/LLM/оплаты вызываются ЧЕРЕЗ адаптер; в юнит/интеграционных тестах — детерминированный
фейк, отдающий ответы по схеме, включая таймаут, 5xx, `finish_reason='length'`, ответ без
`speaker`. Живой режим включается ключом и помечается в отчёте отдельно — прогон без ключа не
объявляется живым смоуком. Проба STT дня 1 (ADR-001 п.4) — ЕДИНСТВЕННЫЙ живой вызов до
развёртывания стека, и она не заменяет юнит-тест адаптера.

## Трассировка: сценарий на каждый критерий

30 AC (`Specification.md` §8) и 69 сценариев (`test-scenarios.md`, дословно совпадающих с
Specification — сверено `diff` на val3-verify) — у каждого AC есть слой и алгоритм. Строки со
слоем «конкурентный» последовательным прогоном не закрываются ни при каких условиях. AC,
помеченные `@queue-2`, в первой неделе проверяются в СВОЁМ доступном варианте (CLI `ops
spend-today`, не веб-страница) — это удовлетворяет DoD ядра.

## Что считается зелёным

- Отсутствующая, пропущенная, недоступная проверка и код возврата `2` — НЕ зелёный результат.
- Мок вместо PostgreSQL/Redis/MinIO не устанавливает поведение ограничения и блокировки:
  конкурентность и уникальность проверяются на настоящих сервисах тестового профиля.
- Числа NFR-clips-1 (`≤ 20 мин p50`, `≤ 500 мс p95`) — `[НЕ ПРОВЕРЕНО]` до первого живого прогона
  на РАЗВЁРНУТОМ стенде, не на локальной машине (`silent-fallbacks.md`).
- В квитанции фичи: точная ревизия, фактически выполненные команды, коды возврата, что осталось
  непроверенным с причиной. План тестов за результат не выдаётся.
