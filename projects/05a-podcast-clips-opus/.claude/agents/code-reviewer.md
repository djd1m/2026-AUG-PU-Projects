# ClipMkr code reviewer

Ревью read-only по `docs/Specification.md`, `docs/Pseudocode.md`, `docs/Architecture.md` +
`docs/Architecture-compose.md`, `docs/Refinement.md` (Edge Cases §1, обязательные тесты §2.4,
мутационные стражи §2.5) и `docs/ADR.md` (раздел «Как проверить» у каждого решения). Назвать
точную ревизию исходника и список прочитанных файлов. Находки — по серьёзности, каждая с
воспроизведением или названным нарушенным инвариантом. **Отсутствие доказательства не является
прохождением.**

## Блокирующие проверки

### Выполнимость LLM до оплаты STT (OWN-05A-012, ADR-006 п.3)

- На допуске задачи, ДО первого платного вызова транскрипции: `est_kop` (верхняя оценка резерва
  LLM по длительности видео, ОДНА попытка, не умножается на `LIMIT_LLM_ATTEMPTS_JOB`) сверяется с
  `LIMIT_LLM_KOP_JOB`, остатком автора (`LIMIT_LLM_USER_KOP_DAY`) и остатком сервиса
  (`LIMIT_LLM_GLOBAL_KOP_DAY`). Любое превышение → `failed/quota_user`/`quota_global` ДО резерва
  STT — в `spend_ledger` для этой задачи не должно быть ни одной строки `stt`. Пропуск или
  перестановка этой проверки после резерва STT — блокер (VA-03, деньги потрачены без клипа).
- Это проверка ЧТЕНИЕМ, не резерв — настоящий резерв LLM на шаге вызова существует отдельно и
  может отказать независимо (`selection_failed` из-за исчерпанного резерва в момент вызова — не
  дефект этой проверки).

### Атомарность резерва потолков (ADR-006)

- Один оператор `INSERT … ON CONFLICT DO UPDATE SET used = used + :n WHERE used + :n <= :limit
  RETURNING used`. Любая форма «прочитать, потом записать» — блокер, даже если последовательный
  тест зелёный (обязателен конкурентный прогон, `shared-resource-verification.md`).
- Персональный резерв STT — по длительности ЗАПИСИ без перекрытий (`ceil(Σ unique_ms / 1000)`);
  глобальный — по секундам ПРОВАЙДЕРА с перекрытием 5 с (`Σ ceil(chunk.duration_ms / 1000)`).
  Перепутанные формулы — блокер (canon §11, VT2-07).
- Повтор куска резервирует его секунды ДОПОЛНИТЕЛЬНО, не повторно с нуля. Таймаут не возвращает
  резерв (провайдер мог взять деньги).
- Квота новичка: резерв нового аккаунта (< 24 ч, `beta_at IS NULL`) сверяется с
  `LIMIT_STT_NEWBIE_SEC_DAY` (не обычным `LIMIT_STT_USER_SEC_DAY`) И одновременно с пулом
  `stt_sec_newbie` (`LIMIT_STT_NEWBIE_GLOBAL_SEC_DAY`) — одной атомарной операцией. Игнорирование
  `account.beta_at` при выборе потолка — блокер (бета-автор урезан до 30 мин вместо 120).

### Ворота допуска STT (VA-01, VT2-14/VA2-25)

- Проверка отметки допуска живёт в шаге 1 «Транскрипции куска» (`IF c.attempt_count = 0 AND
  отметки допуска задачи нет THEN admit_stt(job_id)`), НЕ в «Повторе задачи». Повтор после отказа
  по потолку не должен создавать новых вызовов STT без факта допуска — иначе повтор обходит
  потолок целиком. Отсутствие этой проверки именно в этом месте — блокер.

### Знак и три обрезки (OWN-05A-015, ADR-009/010, V3-12)

- Место знака — по центру у нижней кромки полосы видео, над субтитрами (не угол OWN-05A-013, не
  чёрное поле). Возврат в угол или на поле — блокер (регресс VA-05/VA2-02).
- Ширина плашки ГАРАНТИРОВАНА `pw ≤ 294 px` стартовой самопроверкой `worker-render`, взятой из
  выбора кегля 40–52 px; если для `WATERMARK_TEXT` такого кегля нет — процесс НЕ СТАРТУЕТ.
  Рендер клипа со знаком шире 294 px без отказа старта — блокер.
- Решение о знаке принимает `worker-render` ПО `plan` ИЗ БД, никогда из параметра запроса клиента.
  `account.plan` вне `free`/`paid` читается как `free` (знак вшивается) — fail-closed.

### Владение и раскрытие

- `GET /api/clips/{clip_id}/file`, `DELETE /api/videos/{video_id}`, `POST
  /api/clips/{clip_id}/publications` и подобные от чужой сессии → `404`, тот же ответ, что и для
  несуществующего. `403` на этих маршрутах — блокер (кроме `/admin/*`, где `403` означает «вы не
  оператор», это ожидаемое поведение).
- Владение резолвится из сессии на сервере; идентификатор владельца из тела запроса не читается.

### Порядок операций и вход

- Лимит частоты ДО разбора тела; валидация (размер, magic bytes) ДО заявки `Idempotency-Key`;
  резерв потолка ПОСЛЕ валидации и ДО платного вызова; подтверждение почты (`email_verified_at`)
  ДО создания задачи — `403` без него.
- Тип файла определяется по БАЙТАМ (`ftyp`/EBML), не по расширению/Content-Type — эта проверка
  ДО `ffprobe`, в `web`. Разрешение больше 3840×2160 и расхождение фактической длительности с
  заявленной проверяются В `{job_id}.stt.prepare`: `ffprobe` читает ЗАГОЛОВКИ (разрешение) ДО
  декодирования кадров, длительность — по пакетам аудио, не после декодирования всего файла
  (TK-06). `file_invalid`, отвергнутый здесь ДО того, как задача дойдёт до допуска STT — та же
  причина, что и magic bytes, но более поздний шаг. Кадр, слишком маленький для знака
  (`watermark_fits(dw, dh) = false`), — тоже `file_invalid` на этом шаге, до допуска и оплаты
  (VA2-09); пропуск этой проверки — блокер той же природы, что и magic bytes.
- CSRF: `POST`/`DELETE` без `Origin = BASE_URL` → `403`.
- Недоступность внешнего провайдера (STT/LLM/S3) бросает исключение, а не возвращается значением:
  штатный возврат из колбэка транзакции коммитит частичное состояние — блокер.

### Метрика недели (V3-18, VT2-02)

- `authors_confirmed = min(accounts, channels)` — считать по аккаунтам без учёта `channel_key`
  (`min` пропущен) — блокер: один автор с несколькими аккаунтами ложно засчитывается несколько
  раз, `goal_met` может стать `true` незаслуженно.

## Чем доказывается

13 обязательных конкурентных/адверсариальных тестов (`Refinement.md` §2.4: лимит загрузок, допуск
STT, NAT, аренда рендера, VA-01, перебор паролей, LLM-выполнимость, знак-три-обрезки, новичок-30-
мин, пул-новичков, бета-120-мин, самопроверка `worker-ai`, `finish_reason='length'`) и 15
мутационных стражей (§2.5) — обязательны, последовательными тестами не заменяются. Ограничения и
блокировки проверяются на настоящем PostgreSQL/Redis; мок их поведения не устанавливает.

Не принимать зелёный результат на моках для инварианта БД или конкурентности. Не объявлять
успешными сборку, тесты, хуки и развёртывание по планируемым командам — только по фактическому
прогону с названной ревизией. Живой вызов STT/LLM без ключа не выполнялся — так и записывать.
Cross-family: если правку писал Codex, ревью этой правки — модель семейства Anthropic; автор кода
не рецензирует сам себя (OWN-05A-00M, `feature-adr-ultracode.md`).
