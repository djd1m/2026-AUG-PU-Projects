# ClipMkr architect

Роли документов: `docs/Architecture.md` + `docs/Architecture-compose.md` — физическое размещение и
границы (разрез объявлен в `docs/dispatch-plan.md`); `docs/Pseudocode.md` — логическая модель,
поля и наборы состояний; `docs/Specification.md` — наблюдаемое поведение; `docs/ADR.md` — решения;
`docs/canon.md` — имена и числа, заморожен после СТОП 2 (хеш в `docs/dispatch-plan.md`).
`docs/C4_Diagrams.md` обязан оставаться согласованным с ними: место знака (OWN-05A-015, по центру
у нижней кромки полосы видео над субтитрами) на 2026-09-23 приведено к единой формуле во всех
четырёх документах (ADR-010 п.2, Pseudocode «Раскладка» шаг 3, C4:130, Specification FR-GROWTH-003
п.4) — прежняя находка V3-03 («в углу» в C4) закрыта; упоминания отменённого OWN-05A-013 в
документах — легитимный след «заменяет», не расхождение. Прочитать все документы ДО изменения
любого контракта, и при следующей правке места знака проверять, что все четыре файла остаются
согласованы, а не подразумевать это.

Дефект живёт в стыке, а не в модуле ([`deployment-seams.md`](../../../../.claude/rules/deployment-seams.md)):
сверка `Architecture` ↔ `Pseudocode` этого проекта уже нашла 4 расхождения (см. Architecture.md
§«Reconciliation with Pseudocode»), два из которых — про источник цены STT и формулу резерва.
Сверять пары документов, а не каждый по отдельности.

## Зафиксированные границы

- Стиль — Distributed Monolith (Monorepo): один репозиторий, один образ, пять процессов с разными
  ролями (`caddy` не входит в образ приложения) в Docker Compose на одном VPS в Нидерландах.
- Сервисов compose РОВНО ВОСЕМЬ (канон §1): `caddy`, `web`, `migrate`, `worker-ai`,
  `worker-render`, `postgres`, `redis`, `minio` (тестовый профиль). Девятый сервис — изменение
  канона, а не деталь реализации.
- `web` не зовёт модели и не запускает ffmpeg. `worker-ai` не рендерит видео и не имеет ключей
  оплаты. `worker-render` не имеет ключей моделей. Ключи моделей — только у `worker-ai`
  (`OPENROUTER_API_KEY`, опционально `OPENAI_API_KEY`); проверяется списком `environment:` в
  `docker compose config`.
- Очередь — BullMQ на Redis, три очереди `stt`/`llm`/`render` (канон §3); строка `job` в Postgres —
  источник истины, BullMQ только доставляет (ADR-008). Постгрес-очередь (`SKIP LOCKED`, как в
  проекте 04) отвергнута явно.
- `postgres`, `redis`, `minio` не публикуют портов на хост. В prod у `web` нет `ports:` вовсе —
  единственная дверь `caddy`; `docker-compose.dev.yml` с `127.0.0.1:${WEB_PORT}` — только машина
  разработки.
- Сессия — только в cookie `HttpOnly; Secure; SameSite=Lax; Path=/`; `Authorization: Bearer` не
  используется, поэтому серверный рендер `/admin/*` и API читают сессию одинаково (VT-04/VA-06).
- API — REST route handlers Next.js по маршрутам канона §7; tRPC не используется (ADR-012, VA-21).

## Охрана решений (ADR-001…017)

| ADR | Что сохранять |
|---|---|
| ADR-001 | STT с диаризацией через OpenRouter за интерфейсом `Transcriber`; модель выбирает **проба дня 1** по 7 критериям; караоке нет |
| ADR-002 | резка ~90 с по паузе, перекрытие 5 с; сшивка меток спикеров эвристикой 60 %; неуверенная сшивка → без подписи спикера |
| ADR-003 | все вызовы моделей — через OpenRouter из Нидерландов; список запасных моделей (`models: [...]`) не передаётся |
| ADR-004 | ключи только у `worker-ai`; недоступность модели — исключение, повтор BullMQ, не смена модели и не «пропустим шаг» |
| ADR-005 | выбор фрагментов и объяснение — один вызов `anthropic/claude-sonnet-5`; индексы единиц, не мс; диапазоны проверяет код (Anthropic structured outputs не поддерживает `minimum`/`maximum`) |
| ADR-006 | 9 потолков; выполнимость LLM проверяется на допуске, до оплаты STT; квота новичка + пул новичков |
| ADR-007 | прямая multipart-загрузка в S3 по подписанным ссылкам; исходник 72 ч, клипы 30 дней; `ExposeHeaders: ETag` в CORS бакета |
| ADR-008 | BullMQ, `job` — источник истины, heartbeat 30 с, повтор продолжает, `worker.close()` по SIGTERM |
| ADR-009 | вертикализация чёрными полями, без кропа/автофрейминга |
| ADR-010 | субтитры ASS фразами с подписью спикера; знак по центру у нижней кромки полосы над субтитрами, `pw ≤ 294 px` гарантирован стартовой самопроверкой |
| ADR-011 | email+пароль, подтверждение до первой загрузки, квота новичка, `ops beta-add`/`ops reset-link` |
| ADR-012 | npm workspaces, стек донора по lock-файлу (CVE-2025-29927/55182 исправлены), compose переписан |
| ADR-013 | fake-door — 2-я очередь; v1 — интерфейс `PaymentProvider`, фейк по умолчанию, не подключён к маршрутам |
| ADR-014 | публикация — только по возвращённой ссылке, проверенной оператором; сервер чужие страницы не открывает (нет SSRF) |
| ADR-015 | код партнёра сильнее cookie; знак несёт только домен; ссылка клипа — в подписи к посту |
| ADR-016 | MCP — только для разработки (Postgres/S3 на чтение); продукт зовёт модели HTTP |
| ADR-017 | `ClipMkr`, `clipmkr.ru`; DNS/TLS — чек-лист до беты |

Не переоткрывать по удобству. Изменение требует нового ADR с миграцией, откатом, влиянием на
совместимость и приёмку, и с разделом «Как проверить» — проверкой, обязанной упасть при нарушении.

## Что проверять в каждом дизайн-ревью

- Владение данными: `owner_key`/сессия, область партнёра, область аккаунта. Чужой ресурс
  неотличим от несуществующего (`404`, единственное исключение — маршрут `/admin/*` в кабинете
  партнёра нет, роль оператора возвращает `403`).
- Транзакционные границы: что удерживается, как долго и кто ещё стоит в очереди за тем же ресурсом
  (`shared-resource-verification.md`). Сетевой вызов (STT/LLM/S3) — ВНЕ транзакции; результат
  пишется короткой транзакцией после вызова.
- Закрытые перечисления и их полнота (canon §5): значение вне набора читается как самое строгое
  (`account.plan` вне `free`/`paid` → `free`; `account.role` вне `user`/`operator` → `user`).
- Денежный контур: какой ключ счётчика связывает вызов, растёт ли счётчик ДО вызова, что видно
  оператору раньше счёта (`docs/model-cost-contract.md`).
- Стык compose: каждая читаемая кодом переменная проброшена в `environment:` СВОЕГО сервиса
  (`x-db`/`x-redis`/`x-s3`/`x-limits` в Architecture-compose.md — эскиз, не финальный файл);
  хостовые порты только `${VAR:-default}`; хранилища без публикации.
- Геометрия знака: любая правка рендера/раскладки сверяется с ТРЕМЯ обрезками
  (`crop=1080:608:0:420`, `crop=608:608:236:420`, `crop=342:608:369:420`), не с одной — VA-05 и
  VA2-02 нашли два разных класса потери знака на одной и той же проверке, покрывавшей только одну
  обрезку.

## Внешние зависимости

Инвентарь в `docs/Architecture.md` §External Dependencies объявлен ИСЧЕРПЫВАЮЩИМ: OpenRouter
(транскрипция, диаризация, structured outputs), прямой OpenAI (запасной STT), Cloud.ru Evolution
Object Storage (multipart, подписанные ссылки, CORS, lifecycle), Resend (SMTP подтверждения
почты), Caddy+ACME (TLS). Ссылаться на то, чего в инвентаре нет — прямой Anthropic API, российские
шлюзы, свой egress-прокси (ADR-003 «Отвергнуто») — запрещено.

Ровно ОДНА строка UNCONFIRMED: конкретная модель OpenRouter с метками спикеров на русском языке —
блокирует только подписи спикеров, не сам продукт (решение координатора VA-08). Новая внешняя
зависимость добавляется строкой «одна способность — одна строка» с дословной цитатой, датой
проверки и вердиктом — вердикт без цитаты не вердикт.

## Чего не утверждать

Точные версии пакетов сверх зафиксированных lock-файлом донора, пути внутри workspace, команды
сборки, теги образов (кроме перечисленных в canon §1), адреса развёртывания сверх названных в
`docs/Completion.md` §2 неизвестны до фичи `foundation-auth` и подтверждаются исходником.
Планируемый компонент не превращать в утверждение, что он установлен или работает: реализация не
начиналась (`Final_Summary.md`). Замеры дня 0 (сеть РФ↔Нидерланды↔Cloud.ru), рендера и токенов LLM
— `[НЕ ПРОВЕРЕНО]`/`[ПРЕДЛОЖЕНИЕ]` до первого живого прогона, не результат.
