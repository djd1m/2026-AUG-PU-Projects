# ClipMkr planner

Планировать по проверенным документам, а не по CJM-прототипу и не по соседнему проекту 05.
До декомпозиции прочитать: `docs/Specification.md` (FR-clips/FR-GROWTH/FR-LOOK/NFR/AC),
`docs/Pseudocode.md` (45 алгоритмов, порядок шагов, `REQUIREMENT:`), `docs/Architecture.md` +
`docs/Architecture-compose.md` (границы сервисов и compose), `docs/ADR.md` (решения и «Как
проверить»), `docs/canon.md` (имена, числа, единицы — §12 расхождений со Specification, канон
правит). `docs/validation-report.md` хранит закрытые находки и оставшиеся оговорки;
`docs/decisions-owner.md` — решения владельца (OWN-05A-000…016) и способ их отката.

Прототип `docs/CJM_Variants.md`/`docs/CJM_Variants.html` — демонстрация выбранного варианта A, не
архитектура. Наличие документа не означает ни реализованного маршрута, ни зелёного теста.

## Порядок планирования

1. Найти фичу и её выполненные зависимости в `.claude/feature-roadmap.json`. Первая фича ядра —
   `stt-probe` (блокирующая проба дня 1, ADR-001 п.4) — она не требует развёрнутого стека и должна
   планироваться первой независимо от остального порядка.
2. Назвать точные `FR-clips-*`, `FR-GROWTH-*`, `FR-LOOK-*`, `NFR-clips-*`, `AC-clips-*`, `ADR-nnn`
   и алгоритм `Pseudocode.md`, которые связывают единицу. Без названного идентификатора единица не
   планируется.
3. Прогнать роутер сложности на ожидаемом наборе файлов:
   `bash ../../scripts/complexity-router.sh <файлы>`. Код `1` — L/XL, полный цикл `/feature` с
   остановкой на плане у владельца — ожидаемо для всего, что трогает STT/LLM-потолки или деньги
   (`stt-pipeline`, `llm-selection`, будущий `PaymentProvider`); код `2` — проверка НЕ выполнена.
4. Разбить составную историю на ограниченные задачи: один писатель на файл, у каждой задачи назван
   способ проверки. Общие манифесты (`package.json`, lockfile, `docker-compose.yml`,
   `packages/db/migrations/*`, `docker-compose.dev.yml`) правит только integration owner.
5. Поставить проверки ПЕРЕД необратимыми и платными действиями: частота → валидация тела →
   `Idempotency-Key` → резерв потолка (**сначала оценка выполнимости LLM, потом резерв STT** —
   OWN-05A-012, ADR-006 п.3) → платный вызов → запись. Подтверждение email — перед первой
   загрузкой, не при регистрации.
6. Разделить документальные ворота, unit/integration, обязательные конкурентные и адверсариальные
   прогоны (`Refinement.md` §2.4, 13 штук), мутационные стражи (§2.5, 15 штук) и E2E на
   развёрнутом стенде по адресу, который выдало развёртывание (не `localhost`). У каждого своё
   доказательство; зелёный одного не закрывает другой.

## Инварианты, которые план обязан сохранять

- **Выполнимость LLM — ДО оплаты STT.** На допуске задачи оценивается верхняя граница резерва LLM
  по длительности видео; не хватает — `failed/quota_user`/`quota_global` до первого вызова
  транскрипции, ноль строк `stt` в `spend_ledger` для этой задачи (OWN-05A-012, ADR-006 п.3).
  Это проверка чтением, не резерв — настоящий резерв на шаге LLM существует отдельно.
- **Резерв — атомарной операцией, ДО вызова.** Персональные секунды STT — по длительности записи
  без перекрытий (`ceil(Σ unique_ms / 1000)`); глобальные — по секундам провайдера с перекрытием
  (`Σ ceil(chunk.duration_ms / 1000)`). Откат — транзакцией, не встречным декрементом.
- **Счёт по попыткам.** Таймаут, отказ провайдера и повтор куска списывают деньги; повтор после
  отказа по потолку НЕ создаёт новых платных вызовов без факта допуска (ворота VA-01 — шаг 1
  «Транскрипции куска», не в «Повторе»).
- **Квота новичка временная, не постоянная.** 30 мин первые 24 ч без `beta_at`; пул новичков ≤
  половины сервиса; бета-автор (`ops beta-add`) получает 120 мин с первой минуты и не входит в пул
  новичков.
- **Модель не выдумывает миллисекунды.** Фрагмент задаётся индексами `start_unit`/`end_unit`; мс и
  баллы длины считает код.
- **Знак переживает три обрезки** (чёрные поля, квадрат по спикеру, fill/zoom 9:16) — ширина
  плашки гарантирована `≤ 294 px` стартовой самопроверкой `worker-render`, а не проверяется
  постфактум рендером.
- **Метрика — по авторам, не по аккаунтам.** `authors_confirmed = min(accounts, channels)`.
- **Чужой ресурс — `404`.** Владение резолвится на сервере из сессии.
- **Ненастроенный потолок валит старт.** Девять переменных canon §6, пустая — не «без границ».
- **Недоступность внешнего источника истины — исключение**, откатывающее транзакцию, а не
  возвращаемое значение.

## Что содержит план единицы

Цель · идентификаторы источника и пути документов · принадлежащие файлы · зависимости ·
отрицательные случаи и конкурентные сценарии (из 13 обязательных `Refinement.md` §2.4, какие
применимы к этой единице) · способ проверки каждого утверждения · страж, который надо испытать на
внедрённом дефекте (из 15 `Refinement.md` §2.5) · что осталось непроверенным и почему. Не
объявлять существующими тесты, сервисы, хуки, ключи поставщика и зависимости, которых не видел.
Cross-family (OWN-05A-00M): план предполагает, что код пишет Codex, ревью — модель другого
семейства (Anthropic); план не назначает исполнителя стадии сам, это решает вызывающий конвейер.
