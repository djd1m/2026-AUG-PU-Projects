## Декларация недели

**Входящие вебхуки:** нет

На неделе продукт не принимает вызовов от чужих систем. Оплаты нет (fake-door, FR-GROWTH-003
п.7), провайдера платежей нет, и никакой другой внешний сервис не звонит в ClipMkr — все внешние
вызовы этой недели идут **из** продукта наружу (STT/LLM через OpenRouter), а не наоборот; тому
классу посвящён [`model-cost-contract.md`](model-cost-contract.md), не этому файлу.

Ожидаемый код ворот на этой декларации — `2` («проверка НЕ выполнена: контракт говорит «Входящие
вебхуки: нет» — чужие системы в продукт не звонят»); это законный ответ, а не нарушение
(`check-webhook-contract.cjs`, exit-код 2 включает этот случай явно), а не `0` и не `1`: проверять
нечего.

## v1 (будущее, за пределами недели) — ЧТО НАЗВАНО СЕЙЧАС, ЧТОБЫ НЕ РЕШАТЬ ВСЛЕПУЮ ПОЗЖЕ

`FR-clips-9` п.5 и `ADR-013` уже фиксируют интерфейс `PaymentProvider { createCheckout,
fetchPayment, parseNotification }` с реализациями `FakePaymentProvider` (детерминированная,
включена по умолчанию), `YooKassaProvider`, `CloudPaymentsProvider` — включён ровно один,
переключателем `PAYMENTS_PROVIDER`; режим `PAYMENTS_MODE=fake|live` без дефолта, `live` без ключей
валит старт. Когда оплата войдёт в скоуп, этот раздел закрывается по образцу переноса из проекта
04 (ADR-013 п.3), и три класса ниже — не эскиз, а обязательство, которое этот же контракт будет
проверять:

| Класс | Что решено уже сейчас (v1, ADR-013 п.3) | Что предстоит доказать прогоном при включении |
|---|---|---|
| `подделка` | у ЮKassa нет подписи уведомлений — подлинность по адресу источника (IP-allowlist) **и** перезапросу статуса `fetchPayment`, а не по одной подписи; у CloudPayments — HMAC по сырому телу, до разбора, постоянным сравнением | тест: поддельное уведомление без валидной подписи/адреса → `403`, платёж не применяется |
| `повтор` | ключ повторности — `(provider, provider_event_id)`, уникальный индекс в `payment_event`; атомарная вставка, не «прочитать-потом-записать» | тест: одно событие ЮKassa/CloudPayments доставлено дважды параллельно → одно начисление |
| `перестановка` | недоступность провайдера — исключение, откатывающее транзакцию, а не возвращаемое значение (порядок операций, `.claude/rules/security-operation-order.md`); статус применяется только если новее уже применённого | тест: событие «оплата» приходит ПОСЛЕ более нового события «отказ» → более новое не перезатирается |

Деньги — целые копейки (canon §11); секреты оплаты — только у `web` (ADR-013 п.3). Этот раздел
не превращает декларацию недели в «да»: он держит решение готовым, чтобы включение оплаты в v1 не
стало решением, принятым в спешке под чужим originом.
