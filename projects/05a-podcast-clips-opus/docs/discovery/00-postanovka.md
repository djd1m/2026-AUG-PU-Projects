```
## GROWTH MECHANICS CONSTRAINTS
Основной growth loop: CONTENT-DRIVEN — продукт производит носитель.
Выход продукта — клип, который пользователь публикует. Watermark на бесплатном тарифе
превращает каждый просмотр чужой аудиторией в показ нашего бренда.
Это единственный из 8 продуктов, где виральный носитель — сам артефакт работы.

⚠️ Watermark у оригинала два независимых источника описали по-разному, проверка не проводилась.
Для нас это ПРОЕКТНОЕ РЕШЕНИЕ, а не копирование: закладываем осознанно.

FR-GROWTH-003 здесь основной, а не третий по важности:
  watermark на free обязателен, снятие — платный тариф, решение фиксируется
  в Specification как часть тарифной архитектуры с первого дня.
  Watermark должен быть читаемым в вертикальном формате на мобильном экране —
  иначе loop не работает, а мы думаем, что работает.

FR-GROWTH-001: момент ценности = пользователь посмотрел первый готовый клип.
               Кнопка «скачать / поделиться» ровно там.

Отдельно зафиксировать: оценка потенциала клипа НЕ создаёт виральность продукта.
Это predictive-инструмент для контента пользователя. Не путать в PRD.

Метрика недели: число опубликованных наружу клипов с watermark.
```

```
## GROWTH MECHANICS CONSTRAINTS (обязательно, наравне с Architecture Constraints)

Главный результат проекта — рост (аудитория + выручка), а не работающий прототип.
Механики роста закладываются в Specification.md как FR, а не описываются прозой в PRD.

Основной growth loop: <ОДИН из: badge | content-driven | incentivized referral | sales | network effect>
Вторичная тактика: <максимум одна, без нового кода>

Обязательный минимум требований — 4 FR в Specification.md, формат FR-GROWTH-NNN:

FR-GROWTH-001  One-click share В МОМЕНТ ПОЛУЧЕНИЯ ЦЕННОСТИ (не на онбординге).
               Момент = <конкретный момент для этого продукта>.
FR-GROWTH-002  Партнёрская атрибуция ДО ПЛАТНОЙ КОНВЕРСИИ, не до регистрации.
               Cookie + промокод как независимый fallback (Safari ITP гасит JS-cookie за 7 дней).
FR-GROWTH-003  Attribution badge на бесплатном тарифе; снятие — платная опция.
               Решается на этапе Specification как часть тарифной архитектуры, не хардкодится потом.
FR-GROWTH-004  Персональные трекируемые коды для партнёров с аудиторией.
               Без кода на партнёра нельзя посчитать CAC по когорте.

Каждый FR-GROWTH обязан иметь три Gherkin-сценария с тегами:
  @FR-GROWTH-NNN @growth @happy-path   — с числовым порогом
  @FR-GROWTH-NNN @growth @edge-case
  @FR-GROWTH-NNN @growth @security     — anti-fraud, ОБЯЗАТЕЛЕН

Метрики, инструментированные с первого релиза: i (invites per user) и conv% — раздельно.
Без них K-factor нельзя посчитать никогда.

НЕ закладывать в план недели: retention D7/D30, CAC payback, любой процент на выборке n < 30.
За неделю это не измеряется — считать их значит обманывать себя.

Anti-fraud минимум в @security-сценариях: self-referral, дубликаты, накрутка.
Любое действие ОТ ИМЕНИ пользователя (инвайт, пост, рассылка) — только по явному отдельному согласию.

Метрика недели: <название> — целевое значение за неделю: <число>
(без числа метрика неизмерима: «больше нуля» — не цель)

ОБЯЗАТЕЛЬНО на первом этапе — не менее 3 вариантов CJM (Customer Journey Map).
Каждый вариант описывается по общему каркасу и ОБЯЗАН быть привязан к growth-цели:

| Поле варианта | Требование |
|---|---|
| Aha Moment | конкретное событие, а не «понял ценность» |
| Entry Hook | какой JTBD-сегмент и какая его боль |
| Onboarding → Core Loop → Paywall | последовательность экранов |
| **Growth loop варианта** | ОДИН из: badge / content-driven / incentivized referral / sales / network effect |
| **Как ложатся FR-GROWTH-001..004** | момент ценности для share-CTA, где живёт badge, где партнёрский код |
| **Микро-тренды** | 2-4 актуальных тренда, на которые опирается вариант, со ссылкой на источник |
| Главный риск | честно, включая «этот вариант не даёт виральности» |

Варианты должны РАЗЛИЧАТЬСЯ по growth loop, а не только по интерфейсу.
Три варианта с одним и тем же loop — это один вариант в трёх обёртках.
Итог первого этапа: сравнительная таблица вариантов + ОСТАНОВКА и ожидание выбора.
```
