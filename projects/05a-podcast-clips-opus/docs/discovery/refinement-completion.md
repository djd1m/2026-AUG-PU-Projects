## Промежуточное падение и исправление (для прозрачности)

Первый прогон `check-job-contract.cjs` дал `exit=1`: в таблице состояний строка «выполняется»
содержала неэкранированный `|` внутри перечисления `transcribing \| selecting \| rendering` —
наивный построчный парсер ворот делит markdown-таблицу по `|` без учёта экранирования, поэтому
`\|` сдвинул все последующие столбцы, и колонка «Доказательство» перестала содержать `job_id`.
Починено заменой на `` `transcribing`/`selecting`/`rendering` `` без символа `|`. Второй прогон —
`exit=0`.

## Вопросы к автору Specification / канону

1. **Расхождение имени таблицы.** `Specification.md` FR-clips-10 п.6 называет таблицу расхода
   `usage_attempt`; `canon.md` §4 называет `spend_ledger` (попытки) и `quota_counter` (резерв по
   суткам/скоупу). По правилу канона (§12 — «при расхождении действует канон») контракт
   `model-cost-contract.md` использует имена канона и явно фиксирует это расхождение отдельным
   разделом («Расхождение со Specification, зафиксированное здесь») — передаю автору Specification
   для правки текста FR-clips-10 п.6 либо для добавления строки в canon §12.
2. **Числовые допущения, не зафиксированные ни в Specification, ни в каноне**, введены в
   `long-job-contract.md` как явно обоснованный расчёт (не решение владельца): «Предельное время
   задачи» = 150 мин (расчёт худшего случая по частям конвейера + запас) и «Таймаут посредника» =
   60 с (консервативная оценка отсутствия явного `reverse_proxy` таймаута у Caddy). Оба числа не
   меняют поведение кода (порог не проверяется кодом, только декларацией ворот), но если у
   владельца/архитектора есть более точное число — заменить в файле напрямую, координатора не
   уведомлять отдельно.
3. **`Продолжение при повторе`** в `long-job-contract.md` заполнено значением
   `запись-в-хранилище` (а не `идемпотентный-ключ`), потому что поле ворот однозначное, а в
   Specification задействованы ОБА механизма на разных стадиях (создание vs повтор после отказа).
   Обоснование выбора — в самом файле, раздел «Как продолжение переживает три отказа». Если
   Pseudocode/Architecture выберут другую формулировку механизма — сверить с этим разделом, а не
   менять только заголовок.
