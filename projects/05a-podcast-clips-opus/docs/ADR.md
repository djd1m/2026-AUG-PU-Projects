## ADR-001 — Транскрипция с диаризацией через OpenRouter за интерфейсом провайдера

**Статус:** Принято (OWN-05A-003, OWN-05A-005).

**Контекст.** Владелец выбрал подписи «кто говорит» вместо караоке. Все вызовы моделей идут через OpenRouter
(ADR-003). `gpt-4o-transcribe-diarize` на OpenRouter нет: API моделей с `output_modalities=transcription` на
2026-09-23 отдаёт 22 модели, её среди них нет ([openrouter.ai/api/v1/models](https://openrouter.ai/api/v1/models?output_modalities=transcription)).
Документация OpenRouter STT ([openrouter.ai/docs/guides/overview/multimodal/stt](https://openrouter.ai/docs/guides/overview/multimodal/stt)):
`POST /api/v1/audio/transcriptions`; multipart до 25 МБ или JSON с base64; `response_format` = `json` | `verbose_json`,
`timestamp_granularities` = `segment` и/или `word`; диаризация включается опцией провайдера в `provider.options`;
апстрим обрывает запрос примерно после 60 с обработки.

**Кандидаты** (описания и цены из API моделей OpenRouter; единица цены `pricing.prompt` — доллары за секунду аудио,
`[ВЫВОД]`: у `openai/whisper-1` она равна 0,0001, это совпадает с официальными $0,006/мин):

| Модель OpenRouter | Что заявлено | $/час `[ВЫВОД]` |
|---|---|---|
| `assemblyai/universal-3-5-pro` | синхронный API, пословные метки | 0,225 |
| `deepgram/nova-3` | много языков; диаризация — опцией провайдера `[НЕ ПРОВЕРЕНО]` | 0,258 |
| `microsoft/mai-transcribe-2` | 60 языков; диаризация через `provider.options` (со слов координатора) | единица цены 0,1 неясна `[НЕ ПРОВЕРЕНО]` |
| `meta/muse-voice-transcribe-1.0` | «speaker-aware transcription» | 0,180 |
| `x-ai/grok-stt-1.0` | пословные метки, «optional speaker diarization» | 0,100 |

**Решение.**
1. Воркер зовёт транскрипцию только через интерфейс `Transcriber.transcribeChunk(audio, opts) → TranscriptUnit[]`.
   Реализации: `OpenRouterTranscriber` (боевая) и `OpenAiTranscriber` (запасная, `gpt-4o-transcribe-diarize`
   напрямую с сервера в Нидерландах). Какая работает, выбирает `STT_PROVIDER`; модель — `STT_MODEL`; дефолтов нет.
2. Единица транскрипта — сегмент (фраза) с `start_ms`, `end_ms`, `speaker_local`, `text`; слова хранятся, если модель
   их дала, но на неделе не нужны. Ответ без меток времени → `failed/no_timestamps`; синтез меток запрещён.
   Ответ без меток спикера — допустим: субтитры без подписи (ADR-010), в журнал `speaker_labels_missing`.
3. Караоке нет (OWN-05A-003): отдельная фича после недели.
4. **Проба дня 1** выбирает `STT_MODEL`. Вход: 10 мин русского подкаста с двумя голосами, режется по ADR-002;
   эталон — ручная расшифровка 2 мин с разметкой спикеров. Критерии, все обязательны:

   | # | Критерий | Порог `[ПРЕДЛОЖЕНИЕ]` |
   |---|---|---|
   | 1 | у каждого сегмента есть `start_ms`/`end_ms` | 100 % |
   | 2 | метки спикеров возвращены через OpenRouter (не только в описании модели) | есть |
   | 3 | WER на эталоне 2 мин | ≤ 15 % |
   | 4 | верная метка спикера у сегментов эталона (после сопоставления меток) | ≥ 90 % |
   | 5 | расхождение начала фразы со звуком, 10 фраз | ≤ 300 мс (NFR-clips-1) |
   | 6 | каждый 90-секундный кусок отвечает | < 60 с, 0 обрывов из 7 |
   | 7 | цена по `usage.cost` | ≤ 62 ₽ за час (R1 M4) |

   Из прошедших берётся самая дешёвая. Не прошла ни одна → `STT_PROVIDER=openai` (прямой OpenAI) и та же проба.
   Не прошёл и он → стоп и вопрос владельцу; тихо снижать пороги нельзя. Результат пробы — файл
   `docs/probes/stt-day1.md` с ответами моделей.

**Последствия.** Модель меняется конфигурацией, код конвейера не трогается. Качество русской диаризации не
измерено ни у одного кандидата — это решает только проба. Цены кандидатов выведены из поля API, а не из прайса.

**Отвергнуто.** `whisper-1` с караоке (владелец выбрал подписи спикеров); два прохода (двойная цена и склейка);
синтез меток по длине текста (дефект донора A).

**Как проверить.** Проба дня 1 по таблице. Юнит-тест адаптера: ответ без `start_ms` → `no_timestamps`; ответ без
`speaker` → сегменты без спикера и событие журнала.

## ADR-002 — Резка на куски и сшивка меток спикеров

**Статус:** Принято (OWN-05A-005: риск путаницы меток принят владельцем).

**Контекст.** Апстрим обрывает запрос после ~60 с обработки, значит кусок должен быть коротким. Метки спикеров
(`A`, `B`) каждого запроса независимы: `A` в куске 3 не обязан быть `A` в куске 4.

**Решение.**
1. Аудио: mono 16 кГц, mp3. Кусок целится в 90 с, рез — в самой длинной паузе (`silencedetect`, −35 дБ, ≥ 300 мс)
   в окне 75…105 с; паузы нет — рез на 105 с. Перекрытие соседних кусков — 5 с.
2. Сдвиг: `start_ms += chunk.offset_ms`. На шве остаётся единица, чья середина по времени лежит до точки шва; дубль
   из перекрытия удаляется. Итог монотонен по `start_ms`, иначе `failed/stt_failed` (FR-clips-4 п. 3).
3. **Сшивка спикеров — эвристика.** Для пары соседних кусков в перекрытии 5 с считается, сколько миллисекунд речи
   метки `x` куска k+1 совпало по времени с меткой `y` куска k. Метка `x` получает глобальный номер `y`, если на `y`
   приходится ≥ 60 % её речи в перекрытии. Метка, не встретившаяся в перекрытии, при двух голосах в куске получает
   оставшийся номер (исключение), иначе — новый глобальный номер. Итог — `speaker_map` куска и флаг
   `speaker_map_confident`.
4. **Честный риск.** Если в перекрытии говорил один человек, второй голос связывается только исключением; при трёх
   и более голосах ошибка вероятна. Подпись с неверным именем вшивается в клип навсегда. Поэтому: если клип
   захватывает шов с `speaker_map_confident = false`, подписи спикеров в этом клипе **не печатаются**, только текст.
   Лучше без подписи, чем с чужим именем.
5. Кусок — единица повтора и учёта: готовый кусок не транскрибируется снова (ADR-008).

**Последствия.** Час записи — около 40 запросов. На длинных выпусках с тремя голосами часть клипов выйдет без
подписей. Доля таких клипов пишется в журнал и видна оператору.

**Отвергнуто.** Один запрос на весь файл (обрыв после 60 с); жёсткие куски без перекрытия (донор, режет слова и не
даёт материала для сшивки); образцы голосов (`known_speaker_references`) — есть только у прямого OpenAI.

**Как проверить.** Тест: синтетический шов посреди фразы → фраза ровно одна. Тест сшивки: пара кусков с
переставленными метками `A/B` → глобальные номера совпали; перекрытие без второго голоса и три голоса →
`speaker_map_confident = false` и клип без подписей. Проба дня 1: доля верных меток после сшивки.

## ADR-003 — Доступ к моделям: OpenRouter, сервер в Нидерландах

**Статус:** Принято (OWN-05A-004, OWN-05A-005).

**Контекст.** OpenAI и Anthropic не обслуживают Россию ([anthropic.com/supported-countries](https://www.anthropic.com/supported-countries),
[help.openai.com](https://help.openai.com/en/articles/5347006-openai-api-supported-countries-and-territories)). Владелец
разместил продукт в Нидерландах и выбрал OpenRouter. Юридические вопросы (152-ФЗ, 38-ФЗ, маркировка) владелец
отложил — они не закрыты, а отложены.

**Решение.**
1. Все вызовы STT и LLM — `https://openrouter.ai/api/v1` с ключом `OPENROUTER_API_KEY`.
2. Модель в запросе одна, явная. Список запасных моделей (`models: [...]`) не передаётся: подмена модели меняет
   качество и цену без ведома пользователя. Фактическая модель из ответа пишется в `spend_ledger.model`.
3. Прямой OpenAI — только как `OpenAiTranscriber` (ADR-001), включается конфигурацией вручную, не автоматически.
4. Сервер в Нидерландах, бакет — Cloud.ru в России (OWN-004 не отменён). Файлы ходят через границу дважды
   (исходник в воркер, клип обратно). Задержка и цена трафика `[НЕ ПРОВЕРЕНО]`; замер вместе с ADR-010.

**Последствия.** Одна точка отказа — OpenRouter; её недоступность отказывает задачу (ADR-004), а не переключает
провайдера. Наценка OpenRouter видна в `usage.cost` каждого ответа.

**Отвергнуто.** Российские шлюзы; свой egress-прокси; российские модели (см. ADR-forks ADR-003).

**Как проверить.** Проба дня 1 идёт через тот же адрес и ключ, что и боевой контур. Тест адаптера: запрос не
содержит поля `models`; `spend_ledger.model` равен полю `model` ответа.

## ADR-004 — Ключи и поведение при недоступности модели

**Статус:** Принято (OWN-05A-009).

**Решение.** `OPENROUTER_API_KEY` (и `OPENAI_API_KEY` при `STT_PROVIDER=openai`) есть только в окружении
`worker-ai`; у `web` и `worker-render` их нет, это проверяется списком `environment:` в compose. Пусто, `''` или
отсутствует → процесс не стартует и называет переменную (honest-configuration CFG-S1/I2). TLS проверяется всегда
(дефект донора `rejectUnauthorized: false` не переносится). HTTP 5xx, 429 и таймаут — исключение, повтор BullMQ;
попытки исчерпаны → `failed/stt_failed` или `failed/selection_failed`. Смены модели, подставного результата и
«пропустим шаг» нет. У `REDIS_URL` дефолта нет (донор подставлял `localhost`).

**Как проверить.** Тест: пустой ключ → старт падает с именем переменной. Тест: `docker compose config` — у `web`
нет `OPENROUTER_API_KEY`. Тест: провайдер отвечает 503 трижды → задача `failed`, в `spend_ledger` три попытки.

## ADR-005 — LLM для выбора фрагментов и объяснимой оценки

**Статус:** Принято (OWN-05A-009).

**Контекст.** API моделей OpenRouter на 2026-09-23 содержит `anthropic/claude-sonnet-5`: контекст 1 000 000,
$2 за 1 млн входных и $10 за 1 млн выходных токенов, среди параметров `structured_outputs` и `response_format`
([openrouter.ai/api/v1/models](https://openrouter.ai/api/v1/models)). Цена совпадает с [claude.com/pricing](https://claude.com/pricing).

**Решение.**
1. `LLM_MODEL=anthropic/claude-sonnet-5`, один вызов на задачу: выбор фрагментов и объяснение вместе (FR-clips-5 п. 6).
2. Транскрипт подаётся нумерованными единицами внутри границы `<transcript>` как данные. Ответ — JSON по схеме
   (`structured_outputs`); фрагмент задаётся **индексами** первой и последней единицы (`start_unit`, `end_unit`), а не
   миллисекундами. Миллисекунды считает код из единиц: модель не может выдумать таймкод.
3. Оценка по FR-clips-6: хук 0–40 и завершённость 0–40 — модель, с цитатами; длина 0–20 — код. Цитаты сверяются
   с текстом фрагмента кодом. Итог — сумма, её считает код.
4. Невалидный ответ — 1 повтор; второй провал → `failed/selection_failed`. Подставных моментов нет.
5. Потолок задачи — ≤ 2 попытки и ≤ 10 ₽ (ADR-006).

**Последствия.** Токены на час записи `[ОЦЕНКА]` 15–20 тыс. на вход, R1 M4: 5–8 ₽. Замер — первые 3 выпуска.

**Отвергнуто.** Opus 5.5 (вдвое дороже без измеренной пользы); Haiku 4.5 на выборе (экономия на главной ценности);
два вызова «выбор, затем оценка» (дороже, спецификация требует один).

**Как проверить.** Тест: ответ с `end_unit` за пределом транскрипта → отказ схемы. Тест: цитата не подстрока →
компонент без балла (AC-clips-9). Замер токенов на 3 выпусках → `docs/model-cost-contract.md`.

## ADR-006 — Потолки расхода на модели

**Статус:** Принято (OWN-05A-007).

**Решение.** Вызовы запускает `посторонний` (зарегистрированный автор). Числа — в конфигурации без дефолта
(имена в каноне), отсутствие или число ≤ 0 валит старт.

| Предел | Значение | Единица счёта |
|---|---|---|
| STT на автора в сутки | 120 мин = 7 200 с | секунда аудио, по попыткам |
| Загрузки на автора в сутки | 3 | создание задачи |
| LLM на автора в сутки | 30 ₽ = 3 000 коп. (3 загрузки × 10 ₽) | копейка, по попыткам |
| STT на сервис в сутки | 1 500 мин = 90 000 с | секунда аудио |
| LLM на сервис в сутки | 300 ₽ = 30 000 коп. | копейка |
| LLM на задачу | 2 попытки и 10 ₽ = 1 000 коп. | попытка, копейка |

1. Сутки — от 00:00 Europe/Moscow.
2. Резерв **до** вызова одной атомарной операцией «увеличить, если результат ≤ предела» в `quota_counter`. STT
   резервирует длительность куска; LLM — верхнюю оценку `вход × цена + max_tokens × цена`. После ответа факт
   (`usage.cost`, доллары → копейки по `FX_USD_RUB_KOP`) пишется в `spend_ledger`, разница с резервом возвращается.
   Попытка с таймаутом резерв не возвращает: провайдер мог взять деньги.
3. Потолок достигнут → отказ `failed/quota_user` или `failed/quota_global` с текстом «приходите завтра»; до вызова.
4. Расход виден: `ops spend today` и `docs/model-cost-contract.md`.

**Как проверить.** Конкурентный тест: 20 одновременных резервов одного автора → прошло ровно столько, сколько
вмещает предел. Тест: переменная потолка пуста → старт падает. Тест: повтор куска увеличивает счётчик.

## ADR-007 — Хранилище, загрузка, жизненный цикл

**Статус:** Принято (OWN-05A-009; OWN-004 из постановки).

**Контекст.** Cloud.ru Evolution Object Storage поддерживает `PutBucketCors`, `PutBucketLifecycleConfiguration`,
`CreateMultipartUpload`, но не `PostObject` ([cloud.ru/docs/s3e/ug/topics/api__methods](https://cloud.ru/docs/s3e/ug/topics/api__methods));
жизненный цикл удаляет по сроку ([concepts__lifecycle](https://cloud.ru/docs/s3e/ug/topics/concepts__lifecycle)).

**Решение.**
1. Браузер грузит файл прямо в бакет: `web` создаёт multipart-загрузку и выдаёт подписанные ссылки на части
   (TTL 15 мин), только если объявленный размер ≤ 2 ГБ. Размер подписью не ограничить, поэтому после завершения —
   `HeadObject`, затем в воркере magic bytes и `ffprobe`; отказ удаляет объект.
2. Ключи объектов — по канону (`videos/{account_id}/{video_id}/…`). Бакет приватный; CORS — только `BASE_URL`.
3. Сроки: исходник удаляется через **72 ч** после завершения задачи (задача-уборщик) + страховочное правило бакета
   на 7 дней; клипы — 30 дней; префикс `tmp/` — 1 день. Срок виден на экране задачи.
4. MinIO — только тестовый профиль, без публикации на хост (или `127.0.0.1:`), пароль случайный.

**Последствия.** Веб не носит гигабайты. Размер проверяется после загрузки, а не до — лишний объект живёт до отказа.

**Как проверить.** Проба дня 1: CORS + PUT части из браузера с origin `BASE_URL` на реальном бакете (не curl).
Тест: объявлено 3 ГБ → ссылки не выданы. Тест: PDF под именем `.mp4` → `failed/file_invalid`, объект удалён.

## ADR-008 — Очереди, воркеры, долгая задача

**Статус:** Принято (OWN-05A-009).

**Решение.**
1. Очереди BullMQ `stt`, `llm`, `render`; роли — `worker-ai` (`stt` + `llm`) и `worker-render` (`render`, ffmpeg).
   Один образ, разные команды.
2. Источник истины — строка `job` в Postgres; BullMQ только доставляет. `job_id` выдаётся в ответе `202` до работы.
   Три состояния `running` · `succeeded` · `failed`, шаг и причины — по канону.
3. Идемпотентность: `Idempotency-Key` при создании; `jobId` BullMQ детерминирован (`{job_id}:stt:{idx}`,
   `{job_id}:llm`, `{clip_id}:render`), дубль не создаётся.
4. Повтор продолжает: каждый кусок транскрипта, результат LLM и каждый клип сохраняются до перехода дальше; воркер
   пропускает готовое и не резервирует потолок повторно.
5. Аренда: воркер обновляет `job.heartbeat_at` каждые 30 с; BullMQ `lockDuration` 120 с с продлением; по SIGTERM —
   `worker.close()` и `stop_grace_period: 60s` (донор делал `process.exit(0)`, и повтор начинался заново). Нет
   heartbeat 5 мин → попытка засчитана, задача переставляется; после 3 попыток → `failed/worker_lost`.
6. Кнопка создания гаснет, пока задача `running`.

**Отвергнуто.** Очередь в Postgres (`SKIP LOCKED`, как в проекте 04): BullMQ/Redis — решение OWN-003; семь
очередей донора — вне недели.

**Как проверить.** `node .claude/hooks/check-job-contract.cjs .` → 0. Тест: убить `worker-ai` посреди куска 3 →
повтор начинает с куска 3, куски 1–2 не транскрибируются снова. Тест: два одинаковых запроса с одним
`Idempotency-Key` → один `job_id`.

## ADR-009 — Вертикализация чёрными полями

**Статус:** Принято (OWN-05A-008). Отменяет размытый фон из FR-clips-7 п. 2.

**Решение.** Исходник 16:9 масштабируется по ширине до 1080×608 и ставится в полосу y = 420…1028; остальное —
чёрный фон: `scale=1080:-2,pad=1080:1920:0:420:black`. Вертикальный исходник — `scale` с сохранением пропорций и
`pad` по центру. Кропа и авто-фрейминга нет.

**Последствия.** Знак (y = 200) и субтитры (y = 1100…1460) лежат на чёрном — читаемость не зависит от кадра. Экран
заполнен видео на ~32 % высоты; размытый фон — отдельная фича.

**Как проверить.** Тест: `ffprobe` клипа → 1080×1920; кадр в точке (540, 300) чёрный, в (540, 700) — видео.

## ADR-010 — Субтитры, знак, бюджет CPU

**Статус:** Принято (OWN-05A-003, 006, 009).

**Решение.**
1. Субтитры — ASS, вшиваются фильтром `ass=`; по одной фразе, не больше 2 строк и 32 символов в строке; подпись
   спикера — префикс «Спикер 1:» (без имён), только при `speaker_map_confident` (ADR-002). Экранирование донора.
2. Знак — `WATERMARK_TEXT=clipmkr.ru` на непрозрачной плашке, левый верх x = 70, y = 200 (FR-GROWTH-003 п. 4–5);
   вшит в пиксели, если `plan !== 'paid'`. Решение принимает `worker-render` по `plan` из БД.
3. `libx264 -preset veryfast -crf 23`, 30 fps, AAC 128 кбит/с, не выше 6 Мбит/с. Параллельных рендеров на
   `worker-render` — `RENDER_CONCURRENCY`, по одному на 2 vCPU; `cpus:` в compose. Таймаут — 5 мин (NFR-clips-1).
4. **Замер до тарифов:** клип 90 с на целевом сервере в Нидерландах — секунды рендера и загрузка CPU.

**Как проверить.** OCR-проверка знака FR-GROWTH-003 п. 6. Тест: `plan` из списка мусорных значений → знак есть.
Замер записывается в `docs/Refinement.md`.

## ADR-011 — Вход и подтверждение почты

**Статус:** Принято (OWN-05A-007, OWN-05A-010). Меняет FR-clips-1 п. 1 («подтверждения нет»).

**Решение.** Email + пароль (≥ 10 символов, argon2id), JWT access 15 мин + refresh-cookie (паттерн донора, VK OAuth
не берётся; форма входа — как в проекте 04 по PWA-идентичности N3a). После регистрации письмо со ссылкой
подтверждения (токен одноразовый, 24 ч, в БД хранится только хэш). Загрузка и любой платный вызов требуют
`email_verified_at IS NOT NULL`; без подтверждения — `403` до создания задачи. Письма — SMTP (`SMTP_URL`, `MAIL_FROM`,
без дефолта). Сброс пароля — оператор (FR-clips-11). Авторизация проверяется и в middleware, и в каждом обработчике.

**Последствия.** Появляется внешняя зависимость — SMTP; доставляемость до mail.ru/Яндекса `[НЕ ПРОВЕРЕНО]`,
проверка — письмо на оба домена в день 1. Одноразовые ящики обходят персональный предел; вторая линия — суточный
потолок сервиса.

**Отвергнуто.** Magic-link, Telegram-вход, закрытая бета (ADR-forks ADR-011).

**Как проверить.** Тест: неподтверждённый аккаунт → загрузка `403`, резерв потолка не создан. Тест: токен
использован дважды → второй раз отказ.

## ADR-013 — Paywall недели и оплата v1

**Статус:** Принято (OWN-05A-010, по решениям проекта 04: OWN-007, OWN-010, ADR-008 и архитектура подписки).

**Решение.**
1. **Неделя — fake-door.** Кнопка «Хочу без знака» пишет `fakedoor_clicked` и атрибуцию; оплаты, маршрутов оплаты и
   вебхуков нет (`incoming-webhooks`: «вебхуков нет»). FR-GROWTH-002 на деньгах на неделе не проверяется.
2. **v1 — интерфейс сразу.** `PaymentProvider { createCheckout, fetchPayment, parseNotification }` с реализациями
   `FakePaymentProvider` (детерминированные события, включая повтор и перестановку), `YooKassaProvider`,
   `CloudPaymentsProvider`. Включён ровно один: `PAYMENTS_PROVIDER`. Режим `PAYMENTS_MODE=fake|live` без дефолта;
   `live` без ключей валит старт; прогон на фейке не объявляется проверкой приёма денег.
3. Уроки проекта 04 переносятся правилом: у ЮKassa нет подписи уведомлений — подлинность по адресу источника,

   provider_event_id)` уникальный; недоступность провайдера — исключение, откатывающее транзакцию; деньги — целые
   копейки. Секреты оплаты — только у `web`.

## ADR-014 — Учёт публикаций по возвращённой ссылке

**Статус:** Принято (OWN-05A-002, OWN-05A-009).

**Решение.** Метрика недели — ≥ 5 уникальных клипов со знаком в статусе `confirmed` на 7-й день от ≥ 3 разных
авторов. Ссылка: `https://`, ≤ 500 символов, хост из закрытого списка канона; статусы `candidate` → `confirmed` |
`rejected` → `removed` на перепроверке. Проверяет оператор (`ops publications …`); сервер ссылку не открывает
(нет SSRF-поверхности). Нормализованная ссылка уникальна. Самоотчёт, кандидаты, переходы — отдельными числами.

**Как проверить.** Сценарии FR-GROWTH-005; тест уникального индекса на повторную ссылку.

## ADR-015 — Атрибуция

**Статус:** Принято (OWN-05A-006, OWN-05A-009; правило «код сильнее cookie» — проект 04 ADR-008).

**Решение.**
1. На знаке — только `clipmkr.ru` (OWN-05A-006). Маршрут `/w` из FR-clips-14 п. 2 не печатается и снимается.
