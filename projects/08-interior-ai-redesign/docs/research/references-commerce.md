# Референсы, товары и бюджет: исследование для расширенного CJM

**Дата наблюдения:** 2026-10-13 UTC  
**Сценарий:** владелец жилья делает ремонт для себя; первый регион — Москва и Московская область.  
**Границы:** только доступные без оплаты первичные источники и прямые проверки. Цены и наличие — снимки, не обещание покупки. Партнёрства и affiliate-интеграции отложены.

## Вывод для CJM

Сохранить каноническую последовательность из gist: **обмер/план → референсы → варианты дизайна → согласование → конкретные товары → бюджет → пересмотр**. Gist прямо описывает два входа (замер и Pinterest-доска), затем визуализацию, поиск мест покупки по Москве и итоговый бюджет. Числовые оценки автора gist являются частным мнением и здесь не используются как рыночные данные: [raw gist](https://gist.githubusercontent.com/djd1m/3dd228d9f6b09b5249dfb35bfdc59aeb/raw).

Практически надёжный первый путь к референсам — загрузка изображений самим пользователем. Pinterest OAuth можно предложить как дополнительное подключение после одобрения приложения, но нельзя делать его обязательным входом. Покупки следует выдавать как редактируемый список с зафиксированными регионом, магазином и временем проверки, а бюджет — как пересчитываемую смету с упаковками, запасом и доставкой.

## Pinterest: рекомендованный контракт продукта

1. Основной вход: `Загрузить референсы` — JPG/PNG/WebP, несколько файлов, подпись пользователя «что именно нравится» и подтверждение прав/разрешения на использование.
2. Дополнительный вход: `Подключить Pinterest` через Authorization Code OAuth. Просить только `boards:read pins:read`; показать, какие доски/Pin будут прочитаны.
3. Импортировать доступные пользователю объекты on-demand; хранить внутренние признаки и пользовательские заметки только в пределах разрешённого политикой. Не обещать импорт любой публичной ссылки.
4. Для публичной ссылки: сначала показать preview самой ссылки/metadata, если это законно и технически доступно; затем предложить пользователю загрузить исходное изображение. Ошибка должна звучать: «Pinterest не разрешил доступ через API», а не «pin не существует».
5. Зафиксировать provenance: `source_url`, `user_uploaded`, `observed_at`, `api_authorized`, `rights_confirmation`; внешний URL не считать вечным asset URL.

## Каталог и список покупок

Минимальная запись позиции:

```text
category, design_element, retailer, product_name, article, product_url,
region, store_id/store_name, observed_at, stock_status, stock_qty?,
sale_unit, pack_quantity, pack_coverage, price_per_pack, price_per_base_unit,
required_base_quantity, waste_rate, packs_to_buy, product_total,
delivery_quote_status, substitute_group, confidence
```

Обязательные правила:

- Показывать город/регион и выбранный магазин рядом с ценой; дата и время снимка видимы пользователю.
- Не смешивать `₽/м²`, `₽/л`, `₽/кг`, `₽/пог. м` и `₽/шт.`. Для покупки считать целые упаковки/штуки.
- `stock_status` отделять от `stock_qty`: «в наличии» без количества не превращать в выдуманный остаток.
- Продавца маркетплейса хранить отдельно от бренда и площадки; условия доставки могут различаться.
- У каждой позиции предусмотреть 1–2 совместимых замены и причину совместимости; замена требует согласования пользователя.
- Перед кнопкой «Купить» обновлять цену, наличие и доставку. Если API нет, открывать официальную карточку/корзину и просить подтвердить актуальные значения.

## Формула количества и бюджета

Для каждой позиции `i`:

```text
need_i = measured_quantity_i × (1 + waste_rate_i)
packs_i = ceil(need_i / pack_coverage_i)       # площадь, объём, масса, длина
pieces_i = ceil(need_i)                        # товары поштучно
product_i = purchasable_quantity_i × price_per_purchase_unit_i

products = Σ product_i
services = Σ installation_i + Σ handling_i
delivery = confirmed_delivery_quotes + unresolved_delivery_allowance
subtotal = products + services + delivery
contingency = contingency_rate × contingency_base
total = subtotal + contingency
```

`waste_rate_i` задаётся по категории и раскладке, показывается и редактируется. Универсальный процент не подтверждён источниками: стартовые значения CJM должны быть явно помечены `[H]` и заменены правилами производителя/мастера. `contingency_rate` также пользовательский параметр `[H]`, а не скрытая наценка. Резерв лучше считать отдельно для материалов, работ и пока не рассчитанной доставки, чтобы не дублировать запас.

Пример интерфейса без притворной актуальности: «Ламинат: площадь комнаты 18 м² → + пользовательский запас 8% `[H]` → 19,44 м² → упаковка 1,99 м² → 10 упаковок. Цена требует обновления». Так пользователь видит округление до продаваемой единицы.

## Последствия для трёх HTML-CJM

Во всех вариантах сохраняется одна ось, меняется способ контроля:

| Шаг | Обязательный экран/состояние |
|---|---|
| Обмер | План/замер, выбранные помещения, явная проверка размеров. |
| Референсы | Upload по умолчанию; Pinterest connect/link как дополнительный путь; карточки «нравится цвет / материал / композиция». |
| Дизайн | 2–3 варианта, список сохранённых конструктивных элементов, согласование версии. |
| Товары | Элемент дизайна → реальные позиции → совместимые замены; регион Москва/МО, магазин и timestamp. |
| Бюджет | Количество в базовой единице → упаковки → цена → доставка/подъём → редактируемый резерв. |
| Пересмотр | Причина изменения (цена, остаток, пожелание), diff сметы и повторное согласование. |

Три полезных акцента:

- **A — «быстро к варианту»:** upload референсов, быстрый дизайн, затем подтверждение размеров и товаров до бюджета.
- **B — «бюджет сначала»:** пользователь задаёт лимит; каждый вариант сразу получает диапазон, долю неподтверждённых цен и доставок.
- **C — «покупка по этапам»:** смета разбита на черновые материалы, чистовые материалы, мебель/декор; закупка только после проверки остатков и зависимостей этапа.

Для homeowner-ценности варианты B/C сильнее обычного photo restyle: они доводят вдохновение до исполнимой сметы и объясняют неопределённость.

## Рекомендуемые fallback и неизвестные

- **Pinterest app не одобрен / pin недоступен:** upload файлов + ссылка как provenance + ручная подпись признака; не скрейпить за логином и не обходить ограничения.
- **Нет retail API:** официальная карточка как deep link, ручное подтверждение цены/остатка пользователем, timestamp и статус `needs_refresh`; экспорт списка CSV/PDF.
- **Цена видна, остаток неизвестен:** считать бюджет, но помечать позицию `availability_unconfirmed`; блокировать обещание срока закупки.
- **Доставка неизвестна:** хранить `quote_required`, адрес/этаж/лифт/пронос; не подставлять «бесплатно» из общего баннера.
- **Регион изменён:** инвалидировать цены, остатки и доставку всей корзины и пересчитать после выбора магазина.
- **API Лемана ПРО:** доступность B2B для данного продукта, коммерческие условия и разрешённый consumer use остаются неподтверждёнными до разговора с менеджером.
- **Дом Лента API:** публичный контракт каталога/цен/остатков не найден; нужно запросить у владельца канала или работать через ссылки/ручную проверку.
- **Публичный Pinterest pin:** страница была доступна 2026-10-13, но стабильный API-импорт и права на копирование изображения не подтверждены.

**Уверенность:** высокая для правил доступа Pinterest, статуса брендов и назначения API Лемана ПРО; средняя для доступности web-каталогов; низкая для будущего программного доступа к каталогу «Дом Лента» и коммерческого допуска N8 к B2B API.
