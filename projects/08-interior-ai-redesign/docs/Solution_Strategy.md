# Solution Strategy

## First Principles and SCQA
Ценность — достоверное сравнение своего помещения с новым стилем. Красивое изображение со сдвинутыми окнами не решает задачу. Depth-карта задаёт пространственное условие, однако математической гарантии нет; поэтому измерение результата отдельно от успешного HTTP-ответа. Ситуация: пользователь выбирает интерьер; осложнение: генераторы могут менять конструкцию; вопрос: как получить полезное сравнение; ответ: SD+ControlNet-depth, контролируемые параметры и строгая проверка корпуса.

## Root cause and TRIZ
Повторный платный запуск возникает, когда UI путает отсутствие ответа с отсутствием задачи. Решение: job id до inference, идемпотентный ключ и durable status. Противоречие «сменить стиль / сохранить конструкцию» разделяется: стиль меняет визуальные материалы, depth управляет пространством, quality gate проверяет окна/двери. Автоматическое принятие по наличию файла запрещено.

## Stakeholders and second-order effects
Пользователь хочет быстрый красивый результат; оператор оплачивает GPU и должен ограничить retries; партнёру нужны достоверные конверсии; получателю shared image нужна пометка виртуального редизайна. Бесплатный кредит может вызывать Sybil abuse, поэтому rate limits и GPU daily cap обязательны. Удаление badge платным пакетом снижает атрибуцию, но это осознанная тарифная граница из задания.

## OODA and decision matrix
Наблюдение: CUDA runtime не подтверждён. Ориентация: CPU fixture не отвечает на geometry question. Решение: реализовать проверяемый pipeline без аренды; реальные GPU quality/performance остаются pending. Действие: bounded coding unit → independent review → конкретные fixes, без повторной необязательной полировки.
Альтернативы: OpenAI image generation отклонено постановкой; generic prompt-only SD отклонено из-за отсутствия depth control; очередь Redis отклонена как лишний сервис при обязательном Postgres; referral rewards отложены как лишний финансовый инвариант.

## Design thinking and implementation strategy
Пользователь сначала видит комнату и выбирает стиль, после результата — share CTA и пакет. Consent на публичную публикацию отдельный, unchecked по умолчанию. Стратегия состоит из вертикальных срезов auth/upload → queue/worker → compare/gallery → payments/growth, каждый с проверкой отказов. Риски, owner и tests зафиксированы в `implementation-plan-v1.md`.
