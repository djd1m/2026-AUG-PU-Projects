## F04a: серверные композиты и публикация

Отдельный Sol6.1 high, до25 минут, затем свежий Astra до12 минут и только конкретные исправления. Владение: `db/006-sharing.sql`, `web/sharing.js`, `web/composite.js`, при необходимости небольшой `web/public-pages.js`, интеграция `web/app.js`, `scripts/migrate.js`, защитные мутации и `tests/sharing*`/`tests/composite*`. Минимальные hooks удаления/quality допустимы в `jobs.js`/`quality.js`/`media.js`, только если нужны для атомарного отзыва. Новые зависимости не предполагаются: sharp уже установлен. Документы API и решения — `docs/features/f04a/`.

Существующий owner-only `/api/jobs` уже ограничивает страницу50 и хранит статусы. Повторно не создавать другую галерею. Личный композит доступен только владельцу завершённого, не удалённого и не rejected результата с совпадающими хешами фактических входных/выходных байтов. Этот owner export следует SHARE01/03; он не является разрешением на публикацию. Unverified остаётся явно unverified, fixture получает видимую надпись демонстрации и noindex. Public token/export использует строгий `qualityEligible`: только accepted real, matching privileged review и immutable evidence. Комментарий F02 о publication/export относится к публичной выдаче; сам строгий guard не ослабляется.

Композит содержит before/after и постоянную AI redesign label. RoomKind badge отсутствует только при серверном `badge_free_entitlement && !billing_hold`; клиентский removeBadge игнорируется. Fixture/demo label не снимается оплатой. Изображения и хеши готовятся вне SQL locks. Финальное разрешение на выдачу сериализуется account→job→share, перепроверяет owner/hold/quality/tombstone/consent и идентичность снимка даже для cache hit. Операция, линейризованная после hold, не выдаёт badge-free. Допустим отказ вместо перестройки. Уже разрешённый ограниченный ответ может завершиться. Бounded memory cache допустим, ключ включает хеши, entitlement, mode/quality и состояние share; persistent cache не нужен для минимального AC.

Публикация требует отдельный `publish:true`, реальный accepted результат, разрешённый style, context1–160 и description40–2000 символов. Согласие одной работы не переносится на другую. Случайный token открывает только композит и escaped metadata; private IDs, email/location/EXIF и исходные/raw result пути не выдаются. Public HTML и галерея показывают полезные context/style/description/AI label. Все публичные чтения снова проверяют разрешение и no-store; private gallery/media также noindex. Public requests ограничены120/IP/min, JSON16KiB. Revoke/delete/reject немедленно закрывают старую страницу, картинку и список; последующая отдельная публикация, если реализована, получает новый token, старый остаётся недействительным.

Share events разделены: deduped share_attempt; share_completed только после сообщения UI о resolved native API; export_delivered только после успешной выдачи скачивания. Native resolution — свидетельство браузерного результата, не доказательство поста в соцсети. Abort/error/unavailable не создают completion; повтор event key не удваивает эффект. Никаких автоматических приглашений или сообщений.

Проверки F04a: реальный PG с двумя аккаунтами, owner/public-token isolation, consent/length/style boundaries, XSS на допустимом принятом примере, fixture/unverified/rejected denial публикации, evidence/byte mismatch, revoke/delete/reject/hold после cached badge-free, конкурентный hold между подготовкой и финальной выдачей, точные event counts/dedupe. Нужна targeted mutation финального entitlement/owner guard из зелёного baseline. Синтетические real-branch fixtures проверяют программную защиту и никогда не считаются настоящим corpus/geometry PASS. Старые suites повторяются по затронутым app/schema/security зависимостям. Docker — CPU2 и общий mutex.

## F04b: интерфейс и настоящий браузерный прогон

Следующий отдельный Sol-пакет по выбранному CJM A: фото → четыре стиля → очередь/статус → результат со slider → личная галерея; resume/idempotency и понятные failure/retry. Пакет ROOM20 и redirect/poll без начисления по return URL; provider disabled/fixture видны честно. Cookie opt-in по умолчанию unchecked, ручной code отдельно. Share CTA рядом с результатом и artifact не более чем за два действия; native resolve/abort/error и download fallback различаются. Публикация имеет отдельный unchecked opt-in и revoke. UI не обещает geometry pass для демонстрации.

Desktop1440/mobile390, клавиатура, отдельные before/after alt, читаемый label/state slider, visible focus, body≥16px, aria-live, reduced motion и отсутствие горизонтального overflow обязательны. Перед E2E — свежий read-only companion preflight с source/build/env/input/effect bindings. Использовать существующий shared Docker Playwright, уникальный context/script, UI mutex и только собственную сеть. Browser health не подменяет app E2E. Демо-генерация в E2E может использовать явно помеченный локальный fixture driver с обычными fenced transitions; ни production fallback, ни поддельное доказательство GPU этим не создаются.
