# Конкретная браузерная граница для F04b

До запуска UI выявлено несоответствие текущего F03b API обычному браузерному GET. `GET /api/attribution` в `web/app.js` требует точный Origin, но браузер обычно не отправляет Origin для same-origin GET/HEAD; JavaScript не может самостоятельно установить этот запрещённый request header. Источник, проверен 2026-10-03: [MDN Origin](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Origin).

F03b injected/Node HTTP проверки задавали Origin явно и поэтому не доказывают браузерную совместимость этого чтения. Программная приёмка F03b остаётся историческим фактом; F04b должен закрыть конкретную интеграционную границу до browser acceptance.

Минимальное решение в UI-пакете: добавить origin-protected POST чтения состояния атрибуции (отдельный маршрут или строгий action state) с аутентификацией, ограниченным JSON и существующим `attribution.state`. Его cleanup истёкшего cookie остаётся защищённым пользовательским действием. Все Origin-проверки пишущих операций сохраняются. UI не должен подделывать заголовки через Playwright routing, доверять произвольному Referer либо молча считать403 пустым согласием.

Проверка: настоящий same-origin fetch из shared browser читает состояние и обрабатывает expiry/clear cookie без ручной установки Origin. Существующие deny/consent/manual/cross-owner тесты остаются обязательными. Также проверить выбранные F04a composite/publication методы на обычную браузерную семантику; public image GET не должен требовать заголовок, который `<img>` не отправляет. Это конкретная совместимость API, не повод заново пересматривать весь backend.
