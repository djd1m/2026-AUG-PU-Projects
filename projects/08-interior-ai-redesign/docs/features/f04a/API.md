## Private share preparation and delivery

1. Explicit user action: `POST /api/jobs/:uuid/share-attempt` with `{ "event_key": "<fresh UUIDv4>", "mode": "native" }` or mode `download`. Response200: `event_key`, `mode`, `quality`, `demo`, `artifact`. The deduped `share_attempt` is recorded only after valid owner/byte authorization. Same key/mode replays; another mode409. `removeBadge` cannot affect server entitlement.
2. GET returned `artifact`, `/api/jobs/:uuid/composite/:mode/:event_key`, using the session. Response is buffered WebP2048×868, ≤8MiB, stripped metadata, pixel BEFORE/AFTER and permanent AI REDESIGN. Optional RoomKind pixel badge follows current server entitlement. Fixture always says DEMO UNVERIFIED; private unverified real output says UNVERIFIED. The second action may invoke native share or download, keeping the artifact flow within two actions.
3. Native: fetch artifact into a File, check native availability/canShare, then explicitly invoke `navigator.share` from the user gesture. Only after its promise resolves, `POST /api/jobs/:uuid/share-outcome` with `{ "event_key": "<same key>", "outcome": "resolved" }`. This requires an existing native attempt with authorized artifact delivery. Resolved completion reports browser API behavior, **never proof of a social post**. Alternative outcomes `abort`, `error`, `unavailable` create zero completions. Replays dedupe; contradictory outcome409. Do not report resolved from a download or from a rejected API promise.
4. Download: GET the download artifact; response has attachment filename `roomkind.webp`. Only HTTP response `finish` records deduped `export_delivered`; close/abort/error do not. It never records `share_completed`. If native unavailable switches to download, create a fresh download event key; do not reuse a native key with another mode. No automatic messages, invitations, email or provider calls.
