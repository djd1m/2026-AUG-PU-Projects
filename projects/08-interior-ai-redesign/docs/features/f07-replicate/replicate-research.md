## API lifecycle and uncertain creation

[HTTP API](https://replicate.com/docs/reference/http) defines create, get and cancel with server Bearer authentication, immutable community-model version selection and data-URL file input. Use asynchronous create; persist ID before polling. No documented create idempotency key or guaranteed caller-supplied ID was established. Cog's internal request schema is not the hosted API contract. Never invent idempotency from app job ID.

[Create/deadlines](https://replicate.com/docs/topics/predictions/create-a-prediction) describes Cancel-After minimum5s through24h and distinguishes it from synchronous wait. [Lifecycle](https://replicate.com/docs/topics/predictions/lifecycle) currently includes starting, processing, succeeded, failed, canceled, **aborted** (deadline before start). This newer lifecycle adds aborted beyond some older model/HTTP enum examples; handle it as terminal failure. Default provider30min is incompatible with app180s; explicit Cancel-After and local absolute deadlines are required. Poll/cancel uses fixed constructed origin/ID, never response URLs.

[Billing](https://replicate.com/docs/topics/billing) says failed runs are not charged; time-priced cancellation can charge elapsed running time. A lost response does not establish failed or canceled status. Keep charge unknown until bound provider evidence; cancellation request is not cancellation confirmation or charge refund. No documented strict monetary maximum per request was established. Admission ceilings are modeled risk bounds and require an approved billing-control method before pilot.

## Transmission, retention, erasure and privacy

[Input files](https://replicate.com/docs/topics/predictions/input-files) supports data URI and library-managed file upload (up to100MB); recommends inline under1MB. HTTP reference recommends inline≤256KB. Use the stricter≤256KiB processed JPEG boundary, JSON≤384KiB; do not send original10MiB source URL or silently switch to upload. API may echo input, hence explicit bounded512KiB response proposal. Keep data URI in process memory only, retain digest/config without bytes. This avoids separately hosting source files; it does not mean zero provider processing/retention.

[Retention](https://replicate.com/docs/topics/predictions/data-retention) states API input parameters/output values/files/logs are removed after one hour by default; website predictions persist until manual deletion. Manual dashboard deletion is documented. Public HTTP reference does not establish predictions DELETE; do not invent it. App tombstones and cleanup do not prove provider erasure. After deletion request cancel known ID, discard local late output, keep cleanup/accounting identity and disclose residual provider retention. No website prediction/share publication in this integration.

[Output files](https://replicate.com/docs/topics/predictions/output-files) identifies replicate.delivery and its subdomains, expiring output URLs and the need to save private copies. Treat URLs as sensitive bearer-like access links, never authorized app media. Use strict HTTPS/DNS/redirect/size/MIME/decode validation in02, no token forwarded to delivery hosts. No browser fetch to provider.

[Privacy policy](https://replicate.com/privacy), updated2026-04-01, is separate from prediction-content retention. Account/business/legal retention cannot be inferred to end after one hour; do not promise zero retention, geography, training exclusion or immediate erasure from these reads. Before any real private-photo transmission, operator records applicable privacy/DPA/subprocessor/transfer acceptance and corpus rights.
