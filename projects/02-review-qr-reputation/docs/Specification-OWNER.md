## FR-PLACE-001: Адрес точки собирается из названия — поля «придумайте адрес» нет

**Заменяет** критерий FR-001 «слаг вводит владелец, занятость проверяется до сабмита» (`1d66ec4e`).
Довод: ссылку **сканируют**, а не набирают; «занято» в лицо новичку стоит отвала, автогенерация —
ничего ([`research/slug-constraints-ux.md`](research/slug-constraints-ux.md)).

**Acceptance Criteria:**
- Форма точки — одно поле «Название» (1–200 символов). Адрес — транслит кириллицы, всё прочее в
  дефис, не длиннее 24 символов, края без дефиса («Кофейня «Артель»» → `kofeynya-artel`)
- Кириллица, пробелы, регистр **нормализуются, а не отвергаются**
- Короче 3 символов, совпадение с резервом (`api admin internal static assets r go v login register
  logout dashboard places private`) или коллизия — **случайный** хвост из 4 hex, а не `-2`
- Итог обязан пройти `^[a-z0-9][a-z0-9-]{1,38}[a-z0-9]$` (код + `ck`-ограничение миграции `010`);
  уникальность — ограничение БД, коллизия разрешается молча новой попыткой (до 4)
- Код: `apps/web/src/slug.ts`, `apps/web/src/places.ts`; тест: `owner.test.ts` «транслитерация адреса»,
  «одинаковые названия у двух владельцев»

## FR-BIND-001: Привязка Telegram одноразовым кодом — только хеш в БД

**Уточняет** FR-003 (реализован только Telegram; MAX — нет). Коммит `d4c20509`, миграции `009`, `012`.

**Acceptance Criteria:**
- `POST /places/:id/bind` (Origin обязателен) выдаёт код 24 случайных байта (base64url); в БД — только
  `sha256`; сам код существует лишь в диплинке `https://t.me/<бот>?start=<код>` и на странице
- Нотифаер завершает привязку по `/start <код>` одним `UPDATE … WHERE bind_token_hash = sha256(код)`,
  который тут же **перезаписывает хеш случайными байтами**: код срабатывает ровно один раз, два
  одновременных `/start` не проходят оба
- Успех подтверждается **сообщением владельцу в Telegram** («Готово…»), неизвестный или сгоревший код —
  ответом «Ссылка устарела…» и строкой `bind_token_unknown` (первые 8 символов хеша) в журнале
- Нет `TELEGRAM_BOT_TOKEN` — привязка спит, а не падает; нет `TELEGRAM_BOT_USERNAME` — страница
  говорит, что бот не настроен
- Тест: `services/notifier/tests/binder.test.ts` (10), `owner.test.ts` «привязка Telegram»

## FR-BIND-002: Выдача нового кода не рвёт действующую доставку

Коммит `27ee2e6b`, миграция `012_bind_token_burn.sql` (грант `UPDATE (bind_token_hash)` для `app_notify`).

- Кнопка «уведомления» **не обнуляет** `chat_id`/`bound_at`: доставка идёт в прежний чат, пока по
  новому коду никто не нажал Start; перепривязка вступает в силу в момент **успеха**
- Выдача нового кода убивает прежний диплинк (хеш перезаписан)
- `GET /places/:id/bind` — безвредная страница с кнопкой (токен выдаётся только `POST`); прямая
  ссылка и закладка не упираются в «не найдено» (`16bdcb75`)

## FR-BIND-003: К боту есть путь, не зависящий от страницы t.me

Коммиты `637c3a75`, `d2420ffb`. Страница t.me принадлежит Telegram и пустеет, если приложение не
подхватило схему — чинить её нечем, поэтому её обходят.

- На странице кода: кнопка t.me, **QR того же диплинка** (для телефона), ссылка `tg://resolve?…`,
  ссылка в Telegram Web и команда `/start <код>` **текстом** — `botDeepLink` строит только ссылку `t.me` (для кнопки и QR); `tg://resolve?…` и ссылка Telegram Web собираются отдельно в `bindPage` (`apps/web/src/pages.ts`)
- Голый `/start` (бот открыт поиском) **не молчит**: бот объясняет, что нужна ссылка из кабинета;
  прочий текст пишется в журнал `tg_message_ignored`

## FR-PRINT-001: QR и печатные макеты — реализация FR-004

Коммит `ea0e93a9`; код `apps/web/src/qr.ts`, `pages.ts` `qrPage`; тест `http.test.ts` «QR и печатные макеты».

- `GET /places/:id/qr` — SVG-QR (`errorCorrection M`, тихая зона 4 модуля) на `BASE_URL/r/<slug>`
- Четыре макета на одной странице, печать браузером: подвал счёта, оборот визитки, наклейка на
  упаковку (уносимые — первыми), тейбл-тент с предупреждением про гостевой Wi-Fi и общий планшет
- Нет подсказок содержания отзыва и вознаграждения (NFR-LEGAL-001); чужая точка — `404`
- **Не реализовано из FR-004:** логотип сервиса на макете бесплатного плана (бренд-строка есть
  только на гостевой странице); PDF-выгрузки нет

## FR-LAND-001: Корень `/` — публичная страница продукта, вход — на `/login`

Коммит `fc392e65` (облик владельческих поверхностей по снимкам Birdeye, FR-LOOK-013…020).

- Без сессии `GET /` отдаёт страницу продукта с ценой из `PRICE_POINT_RUB` (по умолчанию 990 ₽);
  с сессией — редирект на `/dashboard`. `/login` и `/register` — отдельные адреса
- Числа на витрине не выдуманы: у каждого названо, откуда оно; чужих цифр и знаков источника нет
- Все страницы кабинета строятся одной оболочкой; гостевая поверхность облик **не меняла** (T4, ADR-010)
- Тест: `owner.test.ts` «облик: одна система на все владельческие поверхности»

## FR-CACHE-001: Кэш страницы выбора и закрытый внутренний канал сброса

Код `apps/guest/src/server.ts`, `apps/web/src/server.ts`, `services/notifier/src/expire.ts`;
граница на прокси — блок `reviewqr.aicoding.space` в Caddyfile машины.

- `guest` кэширует страницу выбора по ключу `slug` не дольше 60 с (NFR-PERF-001)
- `web` после сохранения ссылок и после вебхука оплаты, `notifier` после истечения подписки зовут
  `POST /internal/invalidate/<slug>` — **после COMMIT**; отказ канала пишется в журнал, кэш добивает TTL
- Снаружи `/internal/*` **не существует**: общий Caddy отвечает `404` до проксирования. Путь открыт
  только внутри compose-сети
- Тест: `payment.test.ts` P-5, P-6 (инвалидация после COMMIT, страж по исходнику)

## FR-EXPIRE-001: Истечение оплаченного периода возвращает бренд-строку

Код `services/notifier/src/expire.ts`; тест `expire.test.ts` P-9; план — [`features/payment/`](features/payment/01_specification.md) PAY-4.

- Раз в час нотифаер переводит `active` подписки с `current_period_end < now()` в `expired` и ставит
  `branding_required = true` всем точкам аккаунта одной транзакцией; повторный прогон — пустой
- Срок возврата бренд-строки — до часа плюс ≤ 60 с кэша (а не «60 с», как в FR-GROWTH-003)
