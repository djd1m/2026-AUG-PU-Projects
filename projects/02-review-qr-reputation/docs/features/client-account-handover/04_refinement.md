# Передача аккаунта · Тесты и мутации

Все — интеграционные, на живой БД, от РОЛЕЙ (`app_owner` и соседних), а не от суперпользователя:
проверяется в том числе то, чего роль не может.

| T | Сценарий | Ловит |
|---|---|---|
| H-1 | Полный круг: агентство создаёт ребёнка и точку → приглашение → заказчик заводит вход → видит точку, ссылки и накопленные сканы | что передача вообще работает |
| H-2 | Повторный переход по использованной ссылке | одноразовость «проверкой перед UPDATE» вместо условия В UPDATE |
| H-3 | **Пять одновременных** приёмов одного приглашения | то же, но на настоящей гонке: последовательный тест зеленеет и на сломанном коде |
| H-4 | Истёкшее приглашение | окно свежести |
| H-5 | Токен подобран/подделан (sha256 не совпал) | утечка через сравнение |
| H-6 | **Агентство пытается привязать чужой существующий аккаунт**: прямой SQL от роли `app_owner` с подставленным id | несущее: должен быть отказ ПРАВ, а не проверки |
| H-7 | После отвязки: запрос от роли агентства к точке, обращениям и статистике заказчика | остаточный доступ через `parent_account_id` |
| H-8 | После отвязки: агентство осталось в `account_members` напрямую | **второй канал доступа** — отвязка родства без снятия членства |
| H-9 | Оплата дочернего аккаунта → комиссия создателю ровно один раз | двойное начисление |
| H-10 | Self-referral: единственный участник ребёнка — сам создатель | выплата себе |
| H-11 | Предел неоплаченных детей достигнут → явный отказ | ферма бесплатных аккаунтов |
| H-12 | Экран приёма содержит предупреждение о доступе агентства к приватным обращениям (страж по разметке) | предупреждение «потерялось» при правке шаблона |
| H-13 | Бренд-строка у точек ребёнка НЕ снимается оплатой родителя | тихая раздача платного признака |

## Мутации (страж обязан покраснеть)

| M | Внедрить | Красным обязан стать |
|---|---|---|
| MH-1 | Вернуть `GRANT UPDATE ON accounts` целиком | H-6 |
| MH-2 | Одноразовость проверкой перед UPDATE вместо условия в нём | H-3 |
| MH-3 | Снять политику `tenant_accounts_ins` | H-6 |
| MH-4 | Отвязка меняет только родство, не трогая членство | H-8 |
| MH-5 | `attach_child` принимает идентификатор родителя аргументом | H-6 |
| MH-6 | Убрать предупреждение из шаблона экрана приёма | H-12 |
| MH-7 | Снять частичный уникальный индекс на действующее приглашение | H-2 |

Мутации внедряются и откатываются **копией файла**, а не `git checkout`, и каждая проверяет,
что легла (PR-035): иначе зелёный прогон читается как «страж слеп».

## Чего тесты не проверяют — честно

Что заказчик **прочитал** предупреждение (H-12 стережёт наличие текста, не понимание). Что
агентство не сохранило пароль заказчика вне продукта. Юридическую сторону доступа третьего лица
к обращениям гостей — это вопрос к оферте, а не к коду; здесь только техническая возможность
отвязаться в любой момент.
