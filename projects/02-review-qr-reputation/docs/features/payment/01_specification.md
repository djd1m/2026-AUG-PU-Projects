# Оплата · Спецификация фичи

Тир: **XL** (деньги) → /feature с остановкой на плане. Источник: Specification FR-010/FR-011,
ADR-009, Pseudocode-OWNER §5. Здесь — консолидация под реализацию, не пересказ.

## Объём

| FR | Что | Приоритет |
|---|---|---|
| PAY-1 | Страница тарифов в кабинете; создание платежа ЮKassa (redirect-flow) | Must |
| PAY-2 | Вебхук `payment.succeeded` / `payment.canceled`: идемпотентно, подлинность перезапросом | Must |
| PAY-3 | Применение тарифа: `subscriptions` + `places.branding_required=false` + инвалидация кэша гостя **после COMMIT** | Must |
| PAY-4 | Истечение периода: бренд-строка возвращается (fail-closed уже в схеме: DEFAULT true) | Must |
| PAY-5 | Комиссия партнёру при первой оплате атрибуцированного аккаунта | Should |

**НЕ входит:** автосписания (только разовый платёж на период), возвраты (вручную через
кабинет ЮKassa), план «Агентство» (после пилота), смена плана посреди периода.

## Критерии приёмки (сокращённо; полные сценарии — 04_refinement)

- AC-1: повторная доставка вебхука с тем же `event` — тариф применён РОВНО один раз
- AC-2: поддельный вебхук с чужим/несуществующим `object.id` — отказ ДО записи идемпотентности
- AC-3: недоступность ЮKassa при перезапросе — **исключение, откатывающее транзакцию**;
  повтор провайдера позже проходит полный путь (НЕ упирается в занятый ключ)
- AC-4: `payment.canceled` после `succeeded` того же платежа — не затирает применённый тариф
- AC-5: после оплаты гостевая страница точки теряет бренд-строку ≤ 60 c (инвалидация+TTL)
- AC-6: истечение `current_period_end` — бренд-строка возвращается без ручных действий
- AC-7: цена НЕ зашита в клиенте и НЕ приходит из формы: сервер берёт из конфига
- AC-8: комиссия начисляется один раз (`uq_commissions_payment_event`), self-attribution отклоняется

значения обязано быть отказом.
