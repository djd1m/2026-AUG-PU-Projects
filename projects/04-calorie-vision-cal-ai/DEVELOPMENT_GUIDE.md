# N4 «Тарелка» — руководство разработчика

## Где что лежит

Общий инструментарий — в корневой `.claude/`. Здесь только добавления, привязанные к источнику;
их полный список с обоснованием — [`docs/toolkit-map.md`](docs/toolkit-map.md). Перед изменениями
читать корневой и проектный `CLAUDE.md`, применимые корневые правила и локальные
`.claude/rules/`.

Источник имён и чисел — [`docs/canon.md`](docs/canon.md), заморожен 2026-09-12. Роли документов:
Specification — что строим, Pseudocode — алгоритмы и наборы состояний, Architecture — физика и
границы, ADR — решения с полем Confirmation, Refinement — проверки, Completion — выпуск.

## Граница состояния

Реализация **не начиналась**. Не существует: `package.json` монорепо, исходников, миграций,
`Caddyfile`, ни одного тестового файла. Существует: документация Phase 1–2, этот toolkit и скелет
контейнеров Phase 4. Скелет проверен `docker compose config` и двумя проверками портов; сборкой он
не проверен, потому что собирать нечего.

## Порядок работы над фичей

1. `/next` — взять верхнюю фичу `.claude/feature-roadmap.json`. Порядок зависимостей линейный:
   `foundation` → `scan-pipeline` → `source-and-correct` → `consent-and-telegram-auth` →
   `diary-and-streak` → `share-card-and-growth-events` → `partner-codes-and-cabinet` →
   `pro-interest-and-limits-ui`.
2. Прогнать роутер сложности на ожидаемом наборе файлов:
   `bash ../../scripts/complexity-router.sh`. Код `1` — тир L/XL, идти полным циклом `/feature` с
   остановкой на плане у владельца; код `0` — тир T/S/M, можно `/plan` или прямую реализацию;
   код `2` — проверка НЕ выполнена, разбираться, а не считать тиром T.
3. `/feature` или `/go`. Фазы PLAN → VALIDATE → IMPLEMENT → REVIEW, Phase 2 не пропускается.
4. Каждому пишущему агенту — изолированный worktree и непересекающийся набор файлов. Общие
   манифесты (`package.json`, lockfile, `docker-compose.yml`, `packages/db/migrations/*`) правит
   только integration owner. Координатор интегрирует по именованным terminal-квитанциям.
5. В квитанции: точная ревизия, фактически выполненные команды, коды возврата, что осталось
   непроверенным и почему.

`complexity` в роадмапе — поле пакетной схемы (`simple | medium | complex`, тиры S/M/L), априорная
подсказка по объёму. Тира XL в схеме нет вовсе: `scan-pipeline` записан `complex`, но по локальной
таблице он XL, потому что трогает деньги. Тир конкретного изменения решает роутер по фактическому
диффу, а не это поле.

## Что проверяется и чем

| Природа признака | Чем проверяется |
|---|---|
| арифметика, границы, закрытые перечисления | unit (vitest) |
| транзакции, ответы маршрутов, согласованность двух компонентов | integration на настоящем PostgreSQL |
| разделяемый ресурс | **конкурентный прогон**; последовательный не засчитывается |
| путь человека | E2E на РАЗВЁРНУТОМ стенде, по адресу развёртывания, не по `localhost` |
| свойство исходника | страж по коду, испытанный на внедрённом дефекте |

Обязательные конкурентные тесты: квота (три ключа), эскалация (четвёртый ключ, 20 одновременных при
остатке 1 → ровно один вызов Sonnet 5), аренда задания с fencing, идемпотентность `POST /scans`.
Обязательные стражи: схема вызова модели без полей калорийности, единственное чтение
`model_estimate_kcal`, `done` без ссылки на `food_item` невозможен, отсутствие `openfoodfacts`,
отказ старта при каждом из трёх ненастроенных потолков (три отдельных прогона).

Каждый страж принимается вместе с двумя строками: дефект внедрён → красный, код восстановлен →
зелёный. Проверка, ни разу не показавшая красное, проверкой не является.

Тесты наружу не ходят: поставщик модели за адаптером, по умолчанию детерминированный фейк.
Ключа `ANTHROPIC_API_KEY` на этой машине нет (DEC-A-009) — прогон без него живым смоуком не
объявляется, а помечается «живое распознавание не выполнено: нет ключа».

## Запуск стенда

Сначала проверки, потом `up`. Порядок не переставлять: docker называет ОДИН порт за прогон, и часть
стека к этому моменту уже поднята.

```bash
cd projects/04-calorie-vision-cal-ai
cp .env.example .env            # заполнить значения; .env в git не попадает
node ../../.claude/hooks/check-ports.cjs .        # что смотрит наружу
bash ../../scripts/check-port-conflicts.sh .      # свободно ли то, что просим
docker compose up -d                              # только db и storage
docker compose --profile app --profile edge up -d # после фичи foundation
```

Наружу стек смотрит ровно одним портом: `127.0.0.1:${N4_EDGE_PORT:-4180}` у Caddy. `db` и `storage`
портов не публикуют вовсе. У `web` хостового порта НЕТ намеренно: опубликованный рядом с прокси, он
позволяет обойти прокси вместе с ограничением частоты, которое тот держит, — это доказал
`check-port-conflicts.sh`, вернув `1` на черновике этого файла. 80 и 443 на машине держит чужой
reverse-proxy, и из проекта они не публикуются.

`scripts/check-env-wiring.sh` в репозитории ОТСУТСТВУЕТ, хотя `Completion.md` и корневое правило
`deployment-seams.md` на него ссылаются. До его написания полнота проброса переменных остаётся
суждением и так помечается. Написать его — работа фичи `foundation`.

## Телеметрия и эксперимент EXP-N4-001

Запись прогона начинается ДО первой стадии и обновляется на границах стадий; учитываются
координатор, все агенты, повторы и fallback. Недоступные счётчики — `null` с причиной. Фактическую
модель подтверждают метаданные исполнения: выбор модели в тексте не означает, что она была
переключена.

Эксперимент
[`2026-09-12-n4-profile-ab.md`](../../docs/development/telemetry/experiments/2026-09-12-n4-profile-ab.md):

| Что | Значение |
|---|---|
| Плечо A | `claude-opus-5` на стадиях PLAN и IMPLEMENT |
| Плечо B | `claude-sonnet-5` на тех же стадиях |
| Судья | Codex `gpt-6-astra`, effort `medium`, слепой: в его промпте нет ни имени модели-автора, ни плеча |
| Координатор | текущая сессия; его расход общий и в стоимость плеча не входит |
| Контролируемые пары | `diary-and-streak` и `share-card-and-growth-events` — обе `medium`, обе без платных вызовов наружу, приёмка из названных `SC-US-*` |
| Остальные фичи | чередование по порядковому номеру: нечётный → A, чётный → B; тир записывается ковариатой |
| Критерий принятия | все обязательные ворота `0` либо законная `2`, находок blocker/high нет после ≤ 2 корректирующих попыток |

Пара реализуется ДВАЖДЫ от одной спецификации: A в worktree `wt-a-<slug>`, B в `wt-b-<slug>`,
разные RUN_ID, без общих квитанций — второй исполнитель не видит ни кода, ни receipts первого. В
основную ветку принимается победившая у судьи реализация; при равенстве — A, объявлено заранее.
§8 эксперимента заполняется из роадмапа ДО первой фичи, иначе распределение перестаёт быть
предрегистрацией.

## Перед тем как отдать результат

- `npm test`, `npm run lint`, `npm run build` — после того как фича `foundation` заведёт скрипты.
  До этого команда из документа остаётся предложением, а не фактом.
- `node ../../.claude/hooks/check-model-cost.cjs .` и
  `node ../../.claude/hooks/check-job-contract.cjs .` — контракты стоимости и долгой задачи.
  Последний сейчас возвращает `2` («НЕ ВЫПОЛНЕНА», причина `not-deployed`), и `2` никогда не
  означает «всё в порядке».
- Ворота трассировки — пакетным чекером из кэша npx с записью пути и версии в квитанцию (DEC-A-010).
- Пропущенная, недоступная проверка и код `2` зелёными не считаются. План проверок за результат не
  выдаётся.
