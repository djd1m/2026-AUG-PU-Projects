# N4 «Тарелка» — соглашения кода

Источники: `docs/Architecture.md` (Technology Stack, Data Architecture), `docs/Pseudocode.md`
(логические поля и наборы состояний), `docs/canon.md` (имена и числа), `docs/ADR.md`.
Стек — целевой: `package.json` монорепо ещё не заведён, точные версии фиксируются на шаге `/start`
и подтверждаются исходником, а не этим документом.

## Структура монорепо

npm workspaces, контекст сборки — корень проекта. Три процесса канона плюс общие пакеты:

```
apps/web          Next.js 15 (App Router, SSR, PWA-манифест, Telegram Mini Apps SDK)
apps/api          Fastify, 13 маршрутов канона
apps/recognizer   Node worker: аренда задания, вызов модели, счёт из базы
packages/db       миграции SQL, типы схемы, клиент pg
packages/shared   общие типы ответов, закрытые перечисления, единицы измерения
scripts/          разовые задачи, в том числе import:fdc (НЕ сервис compose)
```

Доменная логика не знает ни `FastifyRequest`, ни клиента `pg`, ни формы ответа поставщика модели.
Адаптеры переводят чужое в свои типы на границе. Поставщик модели — за интерфейсом с двумя
реализациями: живой клиент и детерминированный фейк для тестов (DEC-A-009).

## Имена и типы

- Имена сущностей, статусов, маршрутов и чисел берутся из `docs/canon.md` и не переизобретаются.
  Осознанное переименование записывается в план фичи, а не вводится молча.
- `PascalCase` — типы; `camelCase` — функции и значения; `kebab-case` — файлы и сегменты маршрутов;
  `snake_case` — колонки и таблицы БД.
- Закрытые перечисления — union-типы, а не строки и не булевы флаги: `recognition.status` (ровно 4),
  `attribution.status` (3), `attribution.source` (3), `scan_quota_counter.scope` (3),
  `growth_event.type` (5), `photo.file_state` (2), `account.status` (3). Булево там, где значений
  больше двух, теряет состояние, которое кто-то потом изобретёт заново.
- `?` в типе означает nullable и НИКОГДА не подразумевает значение по умолчанию.

## Единицы и время

- Масса — `Grams`, целое. Энергия — `Kcal`, целое. Макронутриенты — граммы с одним знаком после
  запятой. Плавающая точка для денег не нужна: денег в неделе нет вовсе (PD-PRICE-001) — если они
  появятся, минорные единицы целым числом.
- Календарные сутки, границы дня, стрик и суточные потолки — `Europe/Moscow`. `diary_entry.eaten_on`
  хранится как `date`, а не как момент времени: ужин в 23:50 по Москве не должен попасть во вчера у
  сервера в UTC.
- Различать `created_at`, `finished_at`, `eaten_on`, `expires_on`, `leased_until` в именах и типах.
  Отсутствующее время поставщика не заменяется временем доставки.

## PostgreSQL без ORM-магии

- Миграции — обычные SQL-файлы в `packages/db/migrations`, применяются по порядку, откат описан.
  Генератор схемы из кода не используется: схема здесь — контракт, а не производная.
- Запросы параметризованные. Идентификаторы — значения, а не интерполируемые куски SQL.
- Уникальность и потолки обеспечивает БАЗА, а не код: `UNIQUE (scope, scope_key, day)`,
  `UNIQUE (device_session_id, idempotency_key)`, `UNIQUE (attribution.device_session_id)`,
  `UNIQUE (partner_code.code)`, `UNIQUE (food_item.source, source_id)`.
- «Прочитать, потом записать» запрещено на разделяемом ресурсе. Квота — один оператор:
  `INSERT … ON CONFLICT (scope, scope_key, day) DO UPDATE SET used = scan_quota_counter.used + 1
  WHERE scan_quota_counter.used < :limit RETURNING used`. Пустой результат И ЕСТЬ «предел достигнут».
- Пул соединений, ограничители частоты и любые счётчики с состоянием создаются ОДИН раз при старте
  процесса. Экземпляр на запрос обнуляет собственную защиту.
- Соединение не удерживается во время внешнего вызова: транзакция аренды закрывается ДО обращения к
  модели, а защиту от второго захвата даёт предикат `leased_until` плюс `lease_fence`, а не
  `SKIP LOCKED` (ADR-003, DEC-A-008).
- Мягкое удаление (`deleted_at`) читается частичными индексами: `WHERE deleted_at IS NULL`. Итог дня
  считается без удалённых В ТОЙ ЖЕ транзакции, что и само удаление.

## Числа и источник

- Число, которое пользователь видит и которое сохраняется, вычисляется как
  `(mass_g / 100) × значение_на_100г` из **снимка** `Snapshot`, а не из живой строки `food_item`:
  переимпорт базы не имеет права задним числом изменить уже показанное число.
- `model_estimate_kcal` читается РОВНО в одном месте — при вычислении `discrepancy_ratio`. Любое
  второе чтение — регресс ADR-001, а не стилистическая вольность.
- Неизвестное не заменяется нулём: позиция без записи базы помечается `unmatched` и исключается из
  итога. Отношение с нулевым знаменателем даёт «не измерено», а не `0%`.

## Ответы и ошибки

- Единый формат: `{ data, meta }` при успехе, `{ error: { code, message } }` при отказе; `meta`
  несёт `request_id` и время ответа.
- Результат операции — явный вариант (`applied` / `conflict` / `invalid` / `rejected`,
  `granted` / `refused(scope)`), а не исключение общего вида и не `null`. Отказ называет причину и
  следующее действие.
- Отказ по потолку называет `scope`: без него «кончились сканы» и «кончились эскалации» неотличимы.

## Известные грабли стека

- `\w` в регулярном выражении НЕ совпадает с кириллицей. Нормализация русских названий блюд —
  `\p{L}` с флагом `/u`, иначе `food_synonym` промахивается на половине входа.
- Приведение `req as CustomType` падает с TS2352. Внешнее значение разбирается из `unknown` через
  схему, а не приводится типом.
- `SET LOCAL` в PostgreSQL действует только на текущую транзакцию текущего соединения. Контекст
  ставится параметризованным `set_config` в ТОЙ ЖЕ транзакции, что и защищаемый запрос.
- `sharp` с поддержкой HEIF — не данность: стандартная сборка libvips её не включает. Наличие
  проверяется при первой сборке образа, а не предполагается (`Dockerfile`, комментарий у stage
  `deps`).
- Порог эскалации 0,6 — число КАНОНА, а не переменная окружения (ADR-004). Потолки 10/3000/600 —
  наоборот, переменные окружения, и их отсутствие валит старт.
