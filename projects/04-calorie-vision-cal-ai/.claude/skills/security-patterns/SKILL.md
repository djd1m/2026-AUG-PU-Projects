# Образцы безопасности N4 «Тарелка»

Загрузить `.claude/rules/security.md`, `.claude/rules/secrets-management.md`,
`docs/model-cost-contract.md`, `docs/long-job-contract.md` и нужный алгоритм `docs/Pseudocode.md`.

## Образец: подпись до разбора

```
1. взять СЫРЫЕ байты строки проверки initData — не результат JSON.parse → stringify
2. посчитать HMAC-SHA-256 по секрету, производному от токена бота
3. сравнить постоянным временем
4. только теперь проверить свежесть auth_date (не старше 24 часов)
5. любая неудача → 401: аккаунт НЕ создан, сессия НЕ выдана, не записано ничего
```

Разбор непроверенных данных означает, что чужие значения уже прошли через логику. Пересборка байтов
ломает подпись навсегда, и обычным «лечением» этого становится отключение проверки. Свежесть ПОСЛЕ
подписи: иначе разное время ответа на «протухло» и «не сошлось» различимо снаружи.

## Образец: файл проверяется по содержимому

```
1. ограничение частоты ДО разбора тела
2. определить тип по БАЙТАМ; расширение и Content-Type клиента — не доказательство
3. отвергнуть полиглот (годен и как изображение, и как HTML/архив)
4. отвергнуть бомбу распаковки по ОБЪЯВЛЕННЫМ размерам (> 100 Мпикс) ДО декодирования
5. снять EXIF, включая GPS, при нормализации
6. непригодный вход → 422 ДО записи в бакет и ДО обращения к квоте
```

Нормализация выполняется на НАШЕМ сервере — она же первый кандидат на исчерпание памяти. Неудача
нормализации — отказ ДО вызова модели: платить за заведомо отвергаемый поставщиком запрос незачем.

## Образец: платный вызов не делается, пока потолок не списан

```
1. собрать ключи ПО ПРИЧИНЕ: primary → 3 (сессия, ip_prefix, global), escalation → 4 (+ escalation)
2. ОДНА транзакция, каждый ключ ОДНИМ оператором:
   INSERT … ON CONFLICT (scope, scope_key, day)
   DO UPDATE SET used = scan_quota_counter.used + 1
   WHERE scan_quota_counter.used < :limit RETURNING used
3. пустой результат ЛЮБОГО ключа → откат ВСЕЙ транзакции, refused(scope), модель НЕ вызывается
4. откат транзакцией, не встречным декрементом: параллельная попытка между инкрементом и
   декрементом получила бы отказ незаслуженно
5. счёт по ПОПЫТКАМ: таймаут и отказ провайдера уже списаны и не возвращаются
```

У анонима ключей ДВА (сессия и префикс адреса), а не один: смена любого одного обнулила бы защиту.
Ненастроенный потолок валит СТАРТ процесса — проверяется тремя отдельными прогонами, потому что
проверка одной переменной зеленеет при отсутствующей второй.

Отказ по счётчику `escalation` не выбрасывает уже оплаченный первичный результат: скан завершается
`done` с `low_confidence` и `failure_reason = quota_exhausted_escalation`.

## Образец: аренда с fencing

```
SELECT … WHERE status='queued' AND (leased_until IS NULL OR leased_until < now())
       ORDER BY created_at FOR UPDATE SKIP LOCKED LIMIT 1
UPDATE … SET leased_until = now() + 60s, lease_owner = :me,
             lease_fence = lease_fence + 1 RETURNING lease_fence   -- запомнить СВОЙ fence
-- закрыть транзакцию, затем внешний вызов
UPDATE recognition SET status = … WHERE id = :scan_id AND lease_fence = :my_fence
-- 0 строк → результат ОТБРОСИТЬ, в аудит stale_lease_result, чужой результат не трогать
```

`SKIP LOCKED` защищает только пока держится транзакция, а держать её во время внешнего вызова
нельзя — десять одновременных сканов выберут пул. Истёкшая аренда не означает, что первый воркер
мёртв: различает их НОМЕР захвата, а не время. Fencing защищает ДАННЫЕ; деньги защищают потолки, и в
окне гонки модель уже вызвана дважды — это названная цена, а не недосмотр.

## Образец: область владения

Резолвить актёра из сессии, загружать объект по его `owner_key`, только потом авторизовать действие.
Чужой и несуществующий `scan_id`, `entry_id`, `card_id` дают ОДИН `404`: `403` сказал бы «оно есть,
но не ваше», а перебор UUID и есть способ это узнать. В `GET /diary` параметра «чей дневник» нет
вовсе — то, чего нельзя попросить, нельзя и получить. Единственное `403` — маршрут 8: код
разрешается на сервере из `partner.account_id`, присланный игнорируется, и ответ означает «вы не
партнёр», а не «такой код существует».

## Образец: согласие на особую категорию ПДн

По умолчанию закрыто всё. Согласие берётся ДО первой записи дневника, версионировано текстом, хэшем,
версией и временем; согласие на неизвестную версию — `422`. Отказ оставляет съёмку и результат
доступными. Отзыв проставляет `revoked_at` всем карточкам НЕМЕДЛЕННО и закрывает публичные адреса не
позже 60 с; `/c/*` отдаётся с `Cache-Control: no-store`, иначе объявленный срок физически
недостижим. Удаление — не позже 72 ч при `account.status = erasing`; повтор не запускает второе
удаление. Недоступность источника истины о согласии — отказ, а не пропуск.

## Образец: текст из чужого ответа не исполняется

Названия ингредиентов приходят от модели, строка кода — от постороннего человека. Экранировать на
ВСЕХ трёх поверхностях: экран результата, экран дня, карточка `/c/{card_id}`. Последняя открывается
незнакомым человеком по ссылке из мессенджера — это самая внешняя поверхность продукта.

## Как доказывается каждый образец

Отрицательным или мутационным тестом: страж, ни разу не показавший красное, стражем не является.
Конкурентность, уникальность и блокировки проверяются на настоящем PostgreSQL. Не объявлять
установленным ограничитель частоты, хранилище секретов или инструмент безопасности, которого не
видел.
