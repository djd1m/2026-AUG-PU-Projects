# Микро-тренды и механики роста для клона Cal AI

Продукт: клон Cal AI — фото еды → калории и БЖУ через RAG по открытой базе продуктов, шеринговая
карточка результата, growth loop на инфлюенсер-сидинге (сеть фитнес-блогеров с промокодами).
Режим QUICK (WebSearch/WebFetch), 27 запросов из бюджета 30, ~40 минут. Дата проверки: 12.09.2026.

### Методология и границы прогона

- Инструменты — только WebSearch и WebFetch; без доступа к TikTok Creative Center, Sensor Tower,
  App Annie/data.ai или закрытым базам прайсов инфлюенсеров. Часть количественных вопросов
  (реальная выручка по каналу, точный CTR роликов) в принципе не отвечается публичным веб-поиском —
  это отражено как «НЕ НАЙДЕНО», а не пропущено молча.
- Два независимых WebFetch-запроса ушли на верификацию конкретной цифры (K-factor для
  health/fitness, раздел D) — это единственная попытка перепроверки первоисточника, доступная в
  рамках бюджета; она провалилась, и результат зафиксирован как отрицательный, а не как отсутствие
  проверки.
- Глобальный контур опирается на англоязычные агрегаторы и блоги индустрии инфлюенсер-маркетинга —
  ни один из них не является первичным академическим исследованием; там, где цифра дана без ссылки
  на первичный источник, она помечена [H].
- RU-контур опирается на русскоязычные маркетинговые агентства (elama.ru, fedotovseo.ru) и на
  официальные/окологосударственные источники по регуляторике (ГАРАНТ, vc.ru со ссылкой на практику
  Роскомнадзора). Отраслевой (фитнес/похудение) срез RU-цен отдельно не найден — только общерыночный
  Telegram.

### Приоритизация трендов для CJM клона [H — синтез, не отдельно измеренный факт]

Три тренда стоит закладывать в первую версию CJM, а не как бэклог:

1. **Тренд 1 (camera-first онбординг)** — это буквально определение продукта Cal AI; откладывать
   его на вторую итерацию означает не строить клон, а строить другое приложение.
2. **Тренд 3 (shareable result cards)** — прямой механизм для growth loop через инфлюенсер-сидинг:
   блогер показывает карточку в своём видео, зритель повторяет действие и получает свою карточку,
   которую можно переслать — цепочка замыкается только если карточка вообще существует с первого
   релиза.
3. **Тренд 8 (Telegram Mini App)** — единственный тренд из таблицы A, для которого RU-контур не
   «тоже работает», а является родным каналом; для growth loop, завязанного на Telegram-инфлюенсеров
   (раздел B.4), отсутствие трения на установку через Mini App снимает главный разрыв воронки —
   переход «увидел ролик в Telegram → поставил стороннее приложение».

Тренды 2, 5, 6, 9 — кандидаты на вторую волну: они улучшают удержание и монетизацию, но не являются
условием, чтобы первая версия продукта вообще работала как задумано. Тренд 4 (стрики) стоит
внедрять с оговоркой [H] из таблицы выше — эффект подтверждён только вторичными источниками.

### B.5 Как считают CAC по инфлюенсеру (общая методология, без конкретных чисел Cal AI)

CAC инфлюенсер-программы = (гонорар креатору + права на использование + внутреннее время активации +
любой paid-буст поверх) / число новых клиентов, которых программа принесла — конверсии считаются по
UTM/промокодам/пиксель-трекингу и CRM, а не по самоотчёту блогера
([Cometly — Influencer Marketing ROI Tracking 2026](https://www.cometly.com/post/influencer-marketing-roi-tracking)).
Для мобильных приложений трекинг по кликабельным ссылкам занижает результат: TikTok/Instagram
редко дают клик по ссылке, аудитория смотрит контент и потом ищет приложение сама — attribution-разрыв
по индустриальным оценкам начала 2026 года составляет 20–40% потерянных данных
([Airbridge — Influencer Attribution Tracking](https://www.airbridge.io/blog/influencer-attribution-tracking-promo-code-vs-tracking-link-mobile-app), 2026).
Практический вывод для клона: промокод как основной канал атрибуции лучше связывать не только с
кликом, но и с MMP-трекингом инсталла + инкрементальным анализом органического подъёма в окне
публикации — [H], общая индустриальная рекомендация, не измеренный факт по конкретно Cal AI.

**Confidence раздела B: 4/5** для блока Cal AI (несколько независимых источников, включая
количественный трекер сделок); **2/5** для блока «другие вирал-аппы» (RizzGPT не подтверждён вообще,
Quittr — иной канал роста, не сидинг); **3/5** для RU-ставок (данные по рынку Telegram в целом
надёжны, по нише фитнес — не найдены отдельно).

### Прокси-метрики вместо неподтверждённого K-factor [H]

Раз отраслевого K-factor для health/fitness нет, для ранней стадии клона практичнее не закладывать
целевой K-factor в финмодель, а измерять его собственный, наблюдая три компонента отдельно: (1) долю
сессий, в которых пользователь дошёл до экрана карточки результата, (2) долю таких сессий, в которых
нажата кнопка «поделиться», (3) конверсию перехода по расшаренной карточке в установку — с этим
последним звеном напрямую связана проблема из B.5: клик по ссылке в Telegram/TikTok недооценивает
реальный эффект на 20–40% по индустриальной оценке. Общий K-factor 0,15–0,4 из раздела D можно
использовать как ориентир диапазона правдоподобия для итогового числа, но не как целевой показатель,
под который проектируется механика на старте.

## E. Открытые вопросы

1. **Формат видео, реально дающий установки.** Ни один из проверенных источников (включая
   SponsorRadar по Cal AI) не раскрывает содержание сценария ролика — демо «сфоткал → увидел
   калории» как формат подтверждён только как индустриальный паттерн трендом A.1, а не как измеренный
   фактор конверсии именно для Cal AI. Нужен либо доступ к самим роликам (YouTube/TikTok выдачи по
   каналам из таблицы B.1), либо интервью с площадкой типа Founders Arm.
2. **RU-специфичные ставки фитнес/похудение-Telegram-каналов.** Найдены только общерыночные цены
   на посевы в Telegram; отраслевого прайса для ниши похудения/питания — нет. Нужен точечный сбор
   (запрос прайс-листов у 5–10 каналов напрямую) — не решается веб-поиском.
3. **Реальная доля Cal AI-подобных приложений в RU через Telegram Mini Apps.** Рост экосистемы
   Mini Apps подтверждён на уровне всей платформы, но данных по проникновению именно health/fitness
   ниши внутри неё — нет.
4. **Позиция Apple App Store по health-claims для non-medical calorie-приложений** — не найдена
   в рамках этого прогона; требуется отдельная проверка Apple Developer Guidelines.
5. **Применимость GLP-1-companion функций к RU-рынку** — не оценивалась количественно (доступность
   препаратов, доля целевой аудитории); решение зависит от бизнес-приоритетов, а не только от тренда.
6. **Юридическая консультация по пунктам раздела C** — обязательна перед запуском платного
   инфлюенсер-сидинга и до включения health-claims в маркетинг; раздел C сознательно оставлен как
   свод норм, а не как правовое заключение.
7. **Формат оплаты RU-блогеров.** Найдены цены за пост (посевы), но не найдено, насколько в RU
   практикуется модель «промокод + процент от подписки» (аналог западного affiliate-creator
   программы Cal AI) против фиксированной оплаты за размещение — это разные структуры риска для
   бюджета сидинга и требуют отдельного точечного опроса агентств.
8. **Собственный K-factor клона.** Раздел D показал, что публичного отраслевого бенчмарка для
   health/fitness нет вообще (циркулирующая цифра не подтвердилась). Единственный источник этого
   числа для клона — собственная телеметрия после первого релиза шеринговой карточки; закладывать
   его в финмодель до запуска нельзя, только диапазон 0,15–0,4 как ориентир правдоподобия.
9. **Верификация состава РФ-справочника продуктов для RAG.** Раздел A (тренд 2) предполагает замену
   USDA на РФ-эквивалент, но конкретный источник (реестр Роспотребнадзора, таблицы Института питания
   или коммерческая база) в рамках этого прогона не выбирался и не проверялся — это отдельная задача
   для технической части discovery, не для этого документа.
