# Суть бизнеса Cal AI и разбор четырёх CJM

Дата: 2026-09-12. Автор: координатор прогона (Claude Fable 5.1) по материалам
[фактов о Cal AI](research/product-research.md), [рынка и данных](research/market-and-data.md),
[трендов и роста](research/trends-and-growth.md). Записано по просьбе владельца перед выбором CJM.
Формат — объяснение для владельца и курса; цифры сохраняют источники из исследований.

## 1. Что за продукт

Cal AI — мобильное приложение: пользователь фотографирует тарелку и через секунды видит блюдо,
калории и белки/жиры/углеводы. Продукт решает не задачу «точно посчитать», а задачу **«не бросить
считать»**: ручной ввод еды — главная причина, по которой ~70% людей бросают дневник питания в
первые две недели ([mHealth](https://mhealth.amegroups.org/article/view/144969/html)). Фото
сокращает три минуты на запись до трёх секунд, и привычка выживает.

Точность при этом посредственная у всех: независимый тест NIH (102 блюда, июль 2026) показал
занижение Cal AI на 345 ккал/блюдо; сама компания заявляет «about 80%». Поэтому в клоне честность
числа — продуктовое отличие: число берётся из открытой базы через RAG, источник виден, расхождение
оценки модели и базы — экран выбора, а не тихое усреднение.

## 3. Где механика роста

**Внутри продукта виральности нет**: пользователю не выгоднее, если его друг тоже считает калории.
Cal AI рос снаружи — сеть ≈250–300 фитнес-блогеров на месячном ретейнере снимала ролики
«сфоткал — увидел калории», затем лестница «UGC → крупные креаторы → платная реклама → партнёрская
программа для креаторов с промокодами» (вторичные кейс-стади, [H]; FAQ источника подтверждает
реферальный код при регистрации, custom promo code и creator-программу). Момент «фото → число» —
идеальный демо-кадр для короткого видео; в этом весь фокус.

Отсюда постановка: основной loop — **content-driven через influencer-seeding**, а не «сделать
вирусным». Без seeding-плана петле не с чего стартовать.

## 4. Общее ядро всех вариантов

Камера первым экраном; один экран результата (фото, название, порция, ккал + 3 макро); источник у
каждого числа; экран расхождения; дневник дня. Подписки в неделе нет; штрихкоды, интеграции с Apple
Health/Google Fit, рецепты и план питания не входят. Контур запуска — RU/СНГ, Telegram-first
(допущение, подтверждает владелец).

## 5. Четыре CJM: сильные и слабые стороны

### A — Карточка (content-driven)
После первого распознавания готова карточка 9:16 «блюдо → калории» с бейджем; блогер с промокодом
приводит зрителей, зрители шерят карточки.
- **Сильное:** ближе всего к реальному росту оригинала; минимум лишнего продукта; метрика недели
  (доля расшеривших ≥1 карточку, цель 20%) измеряется напрямую.
- **Слабое:** без бюджета на 5–10 блогеров петля не стартует; доля шеринга неизвестна — отраслевого
  бенчмарка нет; карточка с заниженным числом может стать мемом «AI не умеет считать».

### B — Открытый дневник (badge loop, из N1 «стена отзывов»)
Вечером сама собирается страница «мой день в тарелках» по ссылке с бейджем «распознано в Тарелке».
- **Сильное:** артефакт виден снаружи без нашего трафика; марафоны похудения в Telegram — готовая
  аудитория, которая и так отчитывается едой.
- **Слабое:** данные о питании — данные о здоровье (152-ФЗ ст. 10): публикация только по явному
  согласию, по умолчанию закрыто, публичных страниц может быть почти ноль; показы ≠ установки.

### C — Тренер видит (sales, B2B2C)
Продаём тренерам и нутрициологам: клиент фотографирует, тренер видит всех клиентов без напоминаний.
- **Сильное:** один тренер приводит 10–50 клиентов; деньги понятнее всего — платит тренер за места;
  спрос подтверждён аналогами (Nutrium, WeStrive).
- **Слабое:** не виральный; цикл продажи дольше недели; метрика недели неестественна; передача
  данных о здоровье третьему лицу требует согласий и договора.

### D — Код блогера (двусторонний incentivized referral, из N1/N2/N3a)
Блогер получает вознаграждение за результат (партнёрская модель N3a), пользователь — бонус
«+30 сканов» за код и свой код после 7 дней стрика; «явный код сильнее cookie» из N1; дайджест в
Telegram и QR в залах из N2.
- **Сильное:** CAC по когорте каждого блогера с первого дня (ровно FR-GROWTH-004); переиспользован
  проверенный код трёх проектов; стимул повышает долю доходящих до первого распознавания.
- **Слабое:** стимул притягивает накрутку (self-referral, фермы кодов) — обязательны anti-fraud
  сценарии; оплаченный блогер маркирует рекламу (ЕРИР); выплаты требуют денег вне недели.

## 6. Вывод и рекомендация координатора

Деньги делает подписка, рост покупается через блогеров, поэтому реальный выбор — между A и D:
A проще и честнее для недели измерения, D сильнее по атрибуции и переиспользованию. Рекомендованный
гибрид: **путь A с блоком «код блогера и кабинет партнёра» из D**. B и C — следующие эксперименты,
не первый.
