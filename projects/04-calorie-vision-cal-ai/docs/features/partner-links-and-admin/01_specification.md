# Фича `partner-links-and-admin` — постановка

Дата: 2026-09-16…17. Тир по таблице `complexity-router.sh`: **L** (новый публичный путь `/r/{code}`,
новый маршрут администратора). Записана ПОСЛЕ реализации — см. «Как шёл конвейер» ниже.

## Откуда взялась

Владелец попросил расписать путь блогера целиком со ссылками на конкретные страницы приложения.
При написании [`docs/operations/partner-journey.md`](../../operations/partner-journey.md)
обнаружилось, что путь **разорван в середине**: партнёрская схема была спроектирована, схема БД,
кабинет партнёра и начисление комиссии существовали и были покрыты тестами — но **применить код
было НЕЧЕМ**. Ни ссылки, по которой приходит читатель блогера, ни поля «у меня есть промокод» на
экране подписки; сам партнёр заводился `psql`-запросом в базу руками.

То есть фича закрывает не «улучшение», а условие запуска: без неё вся партнёрская механика —
мёртвый код.

## Требования

| Ид | Требование | Почему именно так |
|---|---|---|
| FR-PL-1 | Страница `/r/{КОД}` применяет код СРАЗУ при открытии, без формы и без кнопки | посетитель уже принял решение, перейдя по ссылке; лишнее нажатие теряет людей на ровном месте |
| FR-PL-2 | Источник применения со страницы `/r/` — `deeplink` (СЛАБЫЙ по ADR-008) | иначе вторая ссылка молча перебивала бы первую, и блогеры воровали бы друг у друга уже приведённых людей |
| FR-PL-3 | Поле «есть промокод» на `/pro` применяет код с источником `explicit` (СИЛЬНЫЙ) | код, введённый руками, — это осознанное действие человека, оно обязано выигрывать у обеих ссылок |
| FR-PL-4 | Экран `/r/` НИКОГДА не показывает пустоту: у четырёх исходов применения четыре разных текста | «ничего не произошло» — это потерянный посетитель, и владелец уже видел ровно этот отказ на загрузке из галереи |
| FR-PL-5 | Повтор по ТОЙ ЖЕ ссылке отличим от чужого кода: ответ `409` несёт признак `same_code` | без признака второй переход по своей же ссылке пугал сообщением «за вами закреплён ДРУГОЙ код» |
| FR-PL-6 | Чужой код наружу НЕ отдаётся — только признак совпадения | посетителю незачем знать, чей код за ним закреплён |
| FR-PL-7 | `POST /api/v1/admin/partners` заводит партнёра и его код ОДНОЙ транзакцией; форма — в кабинете владельца | партнёр без кода и код без партнёра — половина сущности; ставка по умолчанию 5000 б.п. (50%) |
| FR-PL-8 | Код нормализуется к верхнему регистру на сервере; формат `^[A-Z0-9]{4,12}$` | ссылка набирается руками с экрана телефона, и регистр там — случайность |
| FR-PL-9 | Маршрут администратора отвечает `404`, а не `403`, посторонним | существование кабинета владельца не подтверждается (`security.md`) |

## Границы — чего фича НЕ делает

- Не меняет правил начисления комиссии: деньги считает `subscription-and-commission`.
- Не заводит приглашения по почте с одноразовой ссылкой (`partner_invite` создана миграцией 011
  под вход по почте, но сценарий «пригласить блогера письмом» не реализован — почты в продукте нет).
- Не даёт владельцу редактировать ставку партнёра после создания.

## Как шёл конвейер (честная пометка)

Владелец: «делай последовательно каждый пункт используя пайплайн команды `/go` … главное чтоб был
баланс скорости и качества», затем «я спать на 8 часов, работай в автономном режиме». Конвейер шёл
в **сокращённом** виде: PLAN и VALIDATE слиты в таблицу пробелов `partner-journey.md`, отдельных
`02_pseudocode.md`/`03_architecture.md`/`04_reuse-map.md` НЕ писалось. Проектные решения
записаны там, где их прочитают: `docs/decisions-autonomous.md` (DEC-A-057, DEC-A-058) и
комментарии в коде. Эта постановка восстановлена по результату 17.09.2026 и помечена как
восстановленная, а не выдаётся за написанную заранее.
