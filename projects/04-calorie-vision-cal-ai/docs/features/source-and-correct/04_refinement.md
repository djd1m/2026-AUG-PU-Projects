# Фича `source-and-correct` — уточнение: краевые случаи, проверки, стражи

**Ревизия 2** (DEC-A-023): статус при нуле сопоставлений — `failed`; значения `model` у
`resolve_conflict` нет, множество `choice` состоит из одного `take_db`.

Слой каждой проверки выбран по природе признака, а не по удобству
([`cost-of-detection-ladder`](../../../../.claude/rules/cost-of-detection-ladder.md)). Разделяемых
ресурсов эта фича НЕ добавляет: ни правка, ни поиск, ни импорт не трогают счётчик квоты, аренду
задания и внешний платный вызов. Поэтому обязательных конкурентных прогонов здесь ДВА, а не больше,
и оба названы ниже с причиной — заявлять конкурентность там, где общего состояния нет, значит
разбавлять требование, которое в соседних фичах несущее.

| Пустой seed / пустая `food_item` | таблицы пусты (состояние до импорта) | Каждый скан даёт `failed(no_food_matched)` — тот же СТАТУС, что у заглушки, но по другой причине: искали и не нашли | Отличие от `NullMatchIngredientPort` наблюдаемо: счётчик запросов к базе не ноль. Одинаковый статус — решение DEC-A-023, а не совпадение |

## Testing Strategy

**Unit.** Нормализация (кириллица, `ё`, стоп-слова, пустой результат); арифметика из снимка
(`(mass_g/100) × значение`, округление, один знак у макронутриентов); границы порции 4/5/2000/2001 и
мусорные типы; граница расхождения 15,0/15,1; нулевой знаменатель → `NULL`; разбор `op` и `choice` по закрытым
множествам (`choice` — из одного значения `take_db`).

**Integration (настоящий PostgreSQL, не мок).** Импорт фикстуры из 50 записей и повторный импорт;
загрузка seed и отказ на нарушенных строках; поиск по трём стратегиям в правильном ПОРЯДКЕ; порт на
реальной базе, включая составное блюдо; маршрут `correct` целиком — по одному отдельному прогону
отказа на каждую ветку; владение (свой / чужой / несуществующий); покрытие 50 русских запросов
(ADR-006 Confirmation). Мок вместо базы не устанавливает поведение `CHECK`, уникальности и
`similarity` — то есть ровно того, что здесь проверяется.

**Performance (отдельная команда, не в каждом `npm test`).** 300 000 синтетических строк
`food_item`, 200 поисков, p95 ≤ 200 мс. Число — литерал теста.

**Contract.** Контрактный тест `MatchIngredientPort` из `scan-pipeline` прогоняется против
`UsdaMatchIngredientPort` БЕЗ изменений в его тексте. Изменение теста ради прохождения было бы
подгонкой проверки под реализацию: тест писался именно для того, чтобы принять эту реализацию.

**Concurrency (два прогона, и оба обоснованы).**
1. **Две одновременные правки одного скана** (`set_portion` на позицию 0 и `delete_item` позиции 1):
   обе применяются либо одна проигрывает с явным исходом; состав и итог согласованы — не бывает
   состава от одного состояния и итога от другого. Разделяемый ресурс здесь — строка `recognition`,
   и последовательный тест зеленеет при ОБЕИХ реализациях, атомарной и «прочитать, потом записать».
2. **Правка во время завершения распознавания**: воркер пишет результат условным `UPDATE` по своему
   `lease_fence`, пока приходит `correct`. Правка скана не в `done` отвергается `409`, и гонка не
   может оставить правку, применённую к составу, который в следующий миг перезаписал воркер.

Конкурентного теста квоты здесь НЕТ намеренно: эта фича квоту не трогает вовсе, и прогон, который
ничего не может нарушить, создавал бы видимость проверки. Сам факт неприкосновенности квоты
проверяется иначе — значением `scan_quota_counter.used` до и после каждой операции.

**Стражи по исходнику и их испытание.** Страж, ни разу не показавший красное, стражем не является.

| Страж | Что проверяет | Внедряемый дефект | Ожидаемая пара прогонов |
|---|---|---|---|
| ADR-001, единственное чтение | `model_estimate_kcal` читается ровно один раз — в `compute/discrepancy.ts` | добавить второе чтение в расчёт итога | красный → восстановить → зелёный |
| ADR-001, источник числа | `kcal`/`protein`/`fat`/`carb` берутся из `source_snapshot`, ни одна ветка не читает поля разобранного ответа модели | присвоить `kcal` из ответа модели | красный → восстановить → зелёный |
| ADR-001, статус | `done` невозможен при нуле сопоставлений | разрешить `done` при пустом покрытии | красный → восстановить → зелёный |
| ADR-005 | строка `openfoodfacts` не встречается ни в коде, ни в окружении | добавить вызов OFF | красный → восстановить → зелёный |
| ADR-006, покрытие | 50 частых русских запросов находят совпадение | удалить 10 строк seed | красный → восстановить → зелёный |
| Атрибуция | цитата USDA присутствует на экране результата | убрать строку цитаты | красный → восстановить → зелёный |

Испытание стража `ADR-001, статус` требует ВХОДА С НУЛЁМ СОПОСТАВЛЕНИЙ: на входе, где совпало всё,
удаление проверки ничего не меняет, и тест остался бы зелёным при внедрённом дефекте. Это та самая
ошибка, которую соседняя фича записала как PC2-08, — здесь она учтена заранее.
