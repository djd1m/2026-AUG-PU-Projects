# Фича `foundation` — уточнение: краевые случаи, проверки, ужесточение

Слой каждой проверки выбран по природе признака, а не по удобству
([`cost-of-detection-ladder`](../../../../.claude/rules/cost-of-detection-ladder.md)). Разделяемый
ресурс закрывается ТОЛЬКО конкурентным прогоном: последовательный тест на нём зеленеет при обеих
реализациях.

## Edge Cases Matrix — дополнение от 2026-09-12 (DEC-A-015, DEC-A-018)

| Случай | Вход | Ожидаемое | Как обеспечивается |
|---|---|---|---|
| незавершённая публикация | `recognition` в `queued`, `photo_id IS NULL` | воркер НЕ получает задание | предикат `photo_id IS NOT NULL`: кадр кладётся в бакет ПОСЛЕ заявки ключа повторности, и в этом окне звать модель не на что |
| задание роняет воркеров | аренда истекла трижды | четвёртый захват НЕ выдаётся, задание закрывает уборщик | `lease_fence < 3` плюс правило Б уборщика: каждый захват оплачен, у числа попыток обязана быть граница |
| никто не взял задание | `queued` старше 5 минут, `leased_until IS NULL` | `failed(timeout)` | правило А уборщика; пул воркеров исчерпан либо остановлен — молчание не означает «выполняется» |
| уборщик против живого воркера | аренда ДЕЙСТВУЕТ, задание старое | уборщик НЕ трогает строку | «завершить задание, не прекратив платную работу» хуже задержки |
| запись после уборщика | воркер дописывает результат в уже закрытую строку | ноль строк, `swept_as_timeout` | условие `status = 'queued'` в условной записи; различение по НОМЕРУ ЗАХВАТА, а не по статусу |
| дедлайн вызова истёк | `deadlineMs = 0`, `-1`, `NaN` | ОТКАЗ до работы | поздний ответ оплачен и всё равно выбрасывается — честнее отказать сразу |
| работа дольше бюджета | задержка адаптера больше `deadlineMs` | ОТКАЗ по дедлайну | тот же довод; задержка фейка задаётся ЯВНО, иначе тест мигает |
| эскалация на том же кадре | `model = 'sonnet-5'` вместо `haiku-4.5` | ответ ДРУГОЙ и несёт `model` | модель входит в детерминированный хеш фейка, иначе тест эскалации слеп |

## Edge Cases Matrix

| Случай | Вход | Ожидаемое | Как обеспечивается |
|---|---|---|---|
| потолок объявлен пустым | `N4_SCAN_LIMIT_USER=` | отказ старта, имя переменной в `stderr` | `''` после `trim` — ОТДЕЛЬНЫЙ случай от `undefined`, иначе опечатка теряет диагностику (`fail-closed-defaults` п. 2) |
| потолок нечисловой или ноль | `N4_SCAN_LIMIT_DAY=abc`, `=0`, `=-1` | отказ старта | разбор в целое с проверкой `> 0`; ноль здесь не «запретить всё», а несконфигурированное значение |
| отсутствует ровно одна из трёх переменных потолка | задано две из трёх | отказ старта, назван недостающий потолок | ТРИ независимых прогона: проверка одной переменной зеленеет при отсутствующей второй (ADR-007 Confirmation) |
| `APP_ORIGIN` равен `/` или `не-url` | `APP_ORIGIN=/` | отказ старта | значение проверяется конструктором URL и списком схем, а не подчищается: срезание хвостового слеша однажды дало пустую строку и уронило каждый `new URL(path, base)` |
| `N4_MODEL_PROVIDER` с опечаткой | `=Fake`, `=дичь`, `=` | отказ старта | закрытое множество `{fake, live}` живёт в КОДЕ; окружение только выбирает вариант (`honest-configuration` CFG-I8) |
| `live` без ключа | `N4_MODEL_PROVIDER=live`, `ANTHROPIC_API_KEY=` | отказ старта `recognizer` | условие зависит от режима, поэтому проверяет код, а не compose (DEC-A-009) |
| повторный прогон миграций | `npm run migrate` дважды | второй раз применено 0 файлов, код 0 | журнал `schema_migration` с контрольной суммой |
| применённый файл миграции изменён | правка `001_init.sql` после применения | ошибка с названной версией | сверка контрольной суммы; молчаливое переприменение запрещено |
| два файла с одним номером | `002_a.sql` и `002_b.sql` | ошибка до применения | порядок обязан быть однозначным |
| `n4_app` пытается менять схему | `DROP TABLE`, `ALTER TABLE`, `CREATE TABLE` | ошибка прав | гранты выдаёт `ProvisionDatabaseRoles`; приложение не владеет схемой |
| таблица, созданная будущей миграцией | новая таблица после 001 | `n4_app` видит её сразу | `ALTER DEFAULT PRIVILEGES`; без него дефект вскроется на первом чтении, а не при миграции |
| cookie подделана или устарела | неизвестный `cookie_token_hash` | выдаётся НОВАЯ сессия | неизвестный токен есть отсутствие сессии; прежняя строка не изменяется и не воскрешается |
| две одновременные первые сессии с одной cookie | гонка на вставке | ровно одна строка | `UNIQUE (cookie_token_hash)`: единственность обеспечивает БАЗА, а не код |
| адрес IPv6 | `2001:db8::1` | `ip_prefix` = /48 | усечение на входе; полный адрес не хранится нигде |
| адрес за прокси | `X-Forwarded-For` из нескольких элементов | берётся элемент, поставленный НАШИМ Caddy | доверять произвольному заголовку нельзя: смена заголовка обнулила бы и квоту, и ограничение частоты (`deployment-seams`) |
| 20 одновременных попыток при пределе 10 | конкурентный прогон | ровно 10 `granted` | атомарный `INSERT … ON CONFLICT … WHERE used < limit RETURNING`; проверяется только параллельно |
| соседняя сессия во время насыщения | 5 параллельных попыток другой сессии | все 5 `granted` | ключ квоты гранулярен по сессии и `ip_prefix`; механизм не наказывает добросовестного |
| отказ по потолку | одиннадцатая попытка | `refused(user)` с названным `scope` | без `scope` «кончились сканы» и «кончились эскалации» неотличимы (FR-LIMIT-002) |
| база недоступна при старте | `db` остановлена | процесс не объявляет себя здоровым | `GET /health` → `503`; недоступность источника истины — отказ, а не «наверное, всё хорошо» |
| база падает во время работы | обрыв соединения | `503` с названной причиной, процесс жив | исключение не проглатывается и не превращается в возвращаемое значение внутри транзакции |
| ожидание соединения пула | все соединения заняты | отказ по таймауту | `connectionTimeoutMillis` обязателен: `pg.Pool` без него ждёт БЕСКОНЕЧНО |
| два воркера на одно задание | одновременная выборка | ровно один захват | предикат `leased_until` + `FOR UPDATE SKIP LOCKED` + инкремент `lease_fence` |
| аренда истекла, первый воркер жив | `leased_until` в прошлом | второй захватывает, первый пишет 0 строк | условный `UPDATE … AND lease_fence = :fence`; событие `stale_lease_result` |
| мусорное тело при превышении частоты | невалидный JSON, запрос сверх порога | `429`, тела никто не разбирал | хук `onRequest` раньше разбора тела |
| ограничитель частоты пересоздан | экземпляр на запрос | запрещено | ограничитель и пул создаются ОДИН раз при старте процесса |
| `docker compose config` пуст или недоступен | нет docker / ошибка | код возврата `2` и «проверка НЕ ВЫПОЛНЕНА» | пустой вход НИКОГДА не читается как «нарушений не найдено» |
| `S3_ENDPOINT` в страже | имя с цифрой | не обрезается до `S` | регулярное выражение `[A-Z][A-Z0-9_]*` |
| секрет попал в поле журнала | токен в объекте события | `[redacted]`, поле сохранено | редактор запрещённых значений; исчезнувшее поле выглядело бы как «его и не было» |

## Testing Strategy

Раннер — `vitest` 3. Интеграционные и конкурентные прогоны идут на НАСТОЯЩЕМ PostgreSQL из профиля
`test` (`docker compose --profile test run --rm test npm test`): мок не воспроизводит ни уникального
индекса, ни блокировок, ради которых эти тесты написаны. Наружу тесты не ходят: единственная внешняя
способность — поставщик модели — заменена детерминированным фейком, и живого режима в этой фиче нет.

| Слой | Что проверяет | Почему этот слой |
|---|---|---|
| unit | валидатор конфигурации, усечение адреса, редактор журнала, ключи квоты, разбор порядка файлов миграций | арифметика, закрытые перечисления и границы наблюдаются без базы |
| integration | миграции и роли, создание и повторное использование сессии, последовательная квота, `GET /health`, ограничение частоты | согласованность двух компонентов и ответы маршрутов |
| конкурентный | квота на одной сессии, добросовестный сосед, занятость пула, аренда двумя воркерами, устаревший захват | разделяемый ресурс; последовательный тест зеленеет при обеих реализациях |
| страж по исходнику | отсутствие секретов в вызовах журналирования; единственный экземпляр ограничителя частоты и пула | свойство ИСХОДНИКА, а не одного прогона |
| смоук на стенде | `docker compose build` и `up --profile app`, здоровье сервисов, ответ `GET /health` через дверь Caddy | стык модулей виден только на собранном стеке |

Измерения NFR-PERF-001 и NFR-PERF-002 в этой фиче НЕ снимаются: показывать нечего, продукта на
экране нет. Это записано как честное «не измерено», а не как пропущенный пункт.

## Что Phase 3 добавила сверх плана (2026-09-12)

Плановый список выше не переписан: расхождение плана и факта обязано быть видно. Ниже — тесты,
которых в плане не было, и причина каждого. Все заголовки — дословные.

`tests/unit/config.test.ts` (закрытие находок отчёта валидации)
- `отсутствие любой из четырёх переменных S3 валит старт с названной переменной` — VF-01: раньше
  S3-переменные не были названы НИ ОДНИМ критерием и ни одним тестом
- `отсутствие любого из двух порогов частоты валит старт с названной переменной` — VF-02
- `в поставляемом окружении заданы 30 мутаций и 120 чтений в минуту` — сверка `.env.example` с
  числами канона §7; порог, взятый из того же файла, который проверяется, не проверяет ничего
- `отказ называет ВСЕ незакрытые переменные сразу, а не первую`
- `полное окружение принимается и числа берутся из него, а не из литералов`
- `режим fake без ключа законен: фейк денег не тратит и наружу не ходит`, `режим live с ключом
  принимается`, `отсутствие любой из четырёх переменных S3 валит старт воркера`

`tests/unit/ip-prefix.test.ts`
- `неразбираемый адрес НЕ сохраняется целиком, а помечается unknown` — «не смогли усечь» не даёт
  права записать полный адрес
- `берётся ПОСЛЕДНИЙ элемент X-Forwarded-For — его поставил наш Caddy`, `без заголовка берётся
  адрес сокета`

`tests/unit/source-guards.test.ts`
- `каждый пул имеет обработчик события error и процесс переживает обрыв` — ЗАСЛУЖЕНО живым стендом:
  остановка `db` на 10 секунд убивала процесс `api` целиком
- `единственное поле о калорийности в ответе модели — model_estimate_kcal` — ADR-001, множество имён,
  а не «нет слова kcal»
- `переменные окружения читает только по одному файлу на сервис` — без этого свойства страж
  `check-env-wiring.sh` приписал бы переменные общих пакетов КАЖДОМУ сервису

`tests/integration/quota-sequential.test.ts`
- `эскалация списывает ЧЕТВЁРТЫЙ ключ, и его исчерпание не трогает остальные`
- `ключей у анонима ДВА: исчерпание по адресу отказывает новой сессии` — смена одного ключа не
  обнуляет защиту

`tests/concurrency/quota-parallel.test.ts`
- `двадцать одновременных эскалаций при остатке один дают ровно один успех` — правило проекта
  требует проверять четвёртый ключ ОТДЕЛЬНО, а не «заодно»

`tests/concurrency/lease.test.ts`
- `два воркера на одно задание дают ровно один захват`, `десять воркеров на три задания не берут ни
  одно дважды и не теряют ни одного`
- `воркер с устаревшим захватом пишет событие stale_lease_result в журнал` — гонка воспроизводится
  ТОЧНО (поставщик-«ворота»), а не подгадывается таймингом

`tests/integration/migrations.test.ts`, `rate-limit.test.ts`, `provider-adapter.test.ts`,
`web-shell.test.tsx`, `check-env-wiring.test.ts` — по одному-двум дополнительным утверждениям
каждый: порядок файлов миграций, раздельные пороги чтения и мутаций, восстановление окна,
отсутствие секретов в исходниках `web`, код `2` при отсутствии сервиса в конфигурации.

**Одно изменение расширения:** тест AC-foundation-12 лежит в `tests/integration/web-shell.test.tsx`
— файл содержит JSX.

| дедлайн порта | фейк игнорирует `deadlineMs` | 1 failed \| 5 passed | 6 passed |
| выбор модели | фейк зашивает свою модель вместо переданной | 1 failed \| 5 passed | 6 passed |

## Испытание стражей на внедрённом дефекте

Проверка, ни разу не показавшая красное, проверкой не является
([`guard-must-be-able-to-fail`](../../../../.claude/rules/guard-must-be-able-to-fail.md)). Каждый
страж ниже принимается ВМЕСТЕ с двумя строками в квитанции: «дефект возвращён → красный», «код
восстановлен → зелёный».

| Страж | Внедряемый дефект | Ожидаемая реакция |
|---|---|---|
| валидатор конфигурации | подставить `?? 10` вместо отказа при отсутствии потолка | тест конфигурации краснеет на всех трёх переменных |
| атомарность квоты | заменить один оператор на `SELECT used` + `UPDATE` | конкурентный тест краснеет; последовательный остаётся зелёным — это и есть доказательство, что различает именно конкурентный |
| аренда задания | убрать `leased_until` из предиката выборки | тест устаревшего захвата краснеет: задание захватывается дважды |
| fencing | выполнять запись результата без `AND lease_fence = :fence` | `UPDATE` первого владельца затрагивает строку, тест краснеет |
| порядок «частота ↔ разбор тела» | перенести хук на `preHandler` | тест частоты краснеет: в ответе появляется `400 invalid json` |
| гигиена журнала | передать сырой токен cookie в вызов журналирования | страж по исходнику краснеет |
| `check-env-wiring.sh` | убрать `S3_BUCKET` из `environment:` сервиса `api` | код возврата `1` с названными сервисом и переменной |
| `check-env-wiring.sh`, пустой вход | подменить `docker compose config` пустым выводом | код возврата `2`, а НЕ `0` |

## Security Hardening

- **Порядок операций.** Ограничение частоты — ДО разбора тела; валидация — ДО занятия ключа
  повторности; квота — ПОСЛЕ валидации и ДО любого платного вызова. В этой фиче платных вызовов нет,
  но порядок закладывается сейчас: перестановка позже читается как рефакторинг, а не как регресс
  защиты ([`security-operation-order`](../../../../.claude/rules/security-operation-order.md)).
- **Сессия.** Токен ≥ 128 бит энтропии из криптографического генератора; в базе только хэш; cookie
  `HttpOnly; Secure; SameSite=Lax; Path=/`. Утечка дампа базы не должна выдавать действующие сессии.
- **Адрес.** Усечение на входе, а не при печати: значения, которого нет, не утечёт и по ошибке.
  Источник адреса — заголовок, поставленный НАШИМ Caddy; произвольному `X-Forwarded-For` от клиента
  доверия нет.
- **Секреты.** `ANTHROPIC_API_KEY` — только у `recognizer`, `TELEGRAM_BOT_TOKEN` — только у `api`,
  у `web` нет ни одного. Инвариант проверяется поиском по собранному клиентскому бандлу и списком
  `environment:` в `docker-compose.yml`, а не обещанием.
- **Служебная ручка.** `GET /health` не отдаёт версий, имён переменных, строк подключения и данных
  пользователя: служебный путь не обязан быть источником разведданных.
- **Роли БД.** Приложение не владеет схемой: `DROP`/`ALTER`/`CREATE` под `n4_app` отвергаются
  правами, а не кодом. Компрометация приложения не даёт права переписать схему.
- **Порты.** Перед любым `up` — `node ../../.claude/hooks/check-ports.cjs .` и
  `bash ../../scripts/check-port-conflicts.sh .`. Хранилища портов не публикуют; единственная дверь
  — Caddy на петле.
- **CSP и CORS.** CSP без `unsafe-inline`; CORS не ставится ни приложением, ни прокси — один origin,
  а два одинаковых заголовка ломают CORS молча.
