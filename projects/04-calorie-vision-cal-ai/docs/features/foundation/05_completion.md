## Дополнение контракта от 2026-09-12 (DEC-A-015, DEC-A-018)

Две малые правки контракта пришли из challenge плана соседней фичи `scan-pipeline` и внесены ЗДЕСЬ,
потому что оба механизма принадлежат каркасу, а не ей.

**1. Порт поставщика модели: `recognize(image, schema, opts: { model, deadlineMs })`.** Модель и
дедлайн задаёт ВЫЗЫВАЮЩИЙ, ответ возвращает `model`. Порт, выбирающий модель сам, прячет эскалацию
внутри адаптера: снаружи не видно, какой вызов оплачен дороже, и потолок эскалаций не с чем
сопоставить. Фейк уважает дедлайн — истёкший бюджет и работа дольше бюджета дают ОТКАЗ, а не поздний
ответ: поздний ответ всё равно оплачен и всё равно выбрасывается.

**2. Предикат выборки задания и уборщик.** К предикату добавлены `photo_id IS NOT NULL` (незавершённая
публикация невидима — иначе воркер зовёт модель на кадр, которого ещё нет) и `lease_fence < 3`
(четвёртого захвата не бывает — каждый захват оплачен). У предела есть названная цена: задание с
исчерпанными захватами больше не предложится никому, поэтому ВМЕСТЕ с ним введён уборщик
(`SweepStuckJobs`) в том же цикле опроса: `queued` старше пяти минут без захвата и `lease_fence = 3`
с истёкшей арендой переводятся в `failed(timeout)`. Уборщик НИКОГДА не трогает задание с действующей
арендой.

**Следствие, которого в задании не было, но без которого правка вносит дефект:** условная запись
результата получила `AND status = 'queued'`. Без него воркер затёр бы терминальный статус уборщика и
вернул задание к жизни задним числом. Два случая «ноль строк» различаются по НОМЕРУ ЗАХВАТА, а не по
статусу: номер больше своего — перезахват (`stale_lease_result`), номер равен своему при терминальном
статусе — уборщик (`swept_as_timeout`), потому что уборщик единственный, кто закрывает строку, не
увеличивая номер.

**Схема.** `failure_reason` расширен до десяти значений миграцией `002_failure_reason_timeout.sql`
(DEC-A-018): `001` уже применён, а изменённый после применения файл раннер обязан отвергать. Вместе с
`timeout` добавлено `normalize` — его пишет `scan-pipeline`, но набор из десяти значений уже объявлен
`Architecture.md` и `Pseudocode.md`, и схема, отстающая от документа, который ею управляет, — это два
места с одним правилом.

**Прогон после правки:** `npm test` 29 зелёных (без базы), `npm run test:integration` **41** зелёный
(было 33), `typecheck`, `lint`, `build` — 0; образы `api` и `recognizer` пересобраны, стек поднят,
воркер стартовал с уборщиком в цикле и отработал без `tick_failed`, стенд снят.

**Шесть новых испытаний стражей мутацией** (дефект возвращён → красный, восстановлено → зелёный):
убран `photo_id IS NOT NULL` → 1 failed; убран `lease_fence < 3` → 2 failed; убран `status = 'queued'`
из условной записи → 1 failed (`swept_as_timeout` не появился); убрано правило Б уборщика → 2 failed;
фейк игнорирует `deadlineMs` → 1 failed; фейк зашивает свою модель вместо переданной → 1 failed.

**Что осталось за Phase 2:** пять новых критериев (`AC-foundation-17…21`) не имеют именованных
сценариев в `validation-report.md` — его пишет валидатор, и ворота `--criterion-scenarios` на них
пока не отвечают. Это названный пробел, а не забытый пункт.

**Дополнение контракта в той же попытке:** `ModelProvider.recognize(image, schema, { model, deadlineMs,
signal })` — `signal` стал ОБЯЗАТЕЛЬНЫМ полем. Фейк прерывается по нему немедленно и отклоняет промис
ошибкой с `name: 'AbortError'`, отдельной от `ModelDeadlineExceeded`: отмена и исчерпание бюджета —
разные события, и слить их значило бы потерять причину. Воркер создаёт один `AbortController` на
вызов и гасит его таймером дедлайна.

**Почему allowlist, а не расширение чёрного списка.** Чёрный список ловит ИМЕНА, а утекло ЗНАЧЕНИЕ
произвольной формы в поле с разрешённым именем `route`. Список запрещённых значений всегда неполон;
список разрешённых полей конечен и виден целиком. Поле вне списка СОХРАНЯЕТСЯ и получает
`[redacted]` — исчезнувшее поле выглядело бы как «его и не было».
