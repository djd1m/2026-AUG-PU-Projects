## Findings

### RV-foundation-01 — medium — `tests/integration/provider-adapter.test.ts:117`

**Что сломано.** Новый цикл требует, чтобы каждый вызов без искусственной задержки с бюджетом `0.01` мс завершался `ModelDeadlineExceeded`. Спецификация разрешает обычный ответ, если работа уложилась в бюджет. Минимальная длительность вычисления фейка нигде не гарантирована.

**Доказательство.** Независимый запуск текущего исходника через `typescript.transpileModule` в памяти, без изменения файлов, на Node `22.22.0`, с теми же входом и бюджетом дал в пяти последовательных сериях по 20 вызовов соответственно **5, 17, 19, 19 и 17 успешных ответов**. Каждый такой ответ провалил бы добавленное `.rejects`. При этом штатный файл тестов в Vitest прошёл **8/8**: результат зависит от условий исполнения.

**Почему исправить.** Тест измеряет скорость машины и прогрев исполнения вместо гарантированного истечения бюджета. Корректная реализация может сделать обязательный набор красным; повышение порога лишь передвинет нестабильность.

**Как исправить.** Детерминированно управлять монотонными часами: до формирования ответа бюджет остаётся, на последней проверке — истёк. Отдельно сохранить сценарий успешного ответа в пределах бюджета. Мутация с удалением последней проверки должна гарантированно ронять первый сценарий.
