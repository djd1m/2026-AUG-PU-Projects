## Findings

### RV-foundation-01 — medium — `scripts/check-env-wiring.sh:101`

Страж собирает имена из всего блока сервиса, а не только из `environment`. Поэтому `labels.S3_BUCKET` засчитывается как переданная переменная окружения.

Воспроизведено без изменения файлов: полный синтетический compose-конфиг передан через штатный `ENV_WIRING_CONFIG`; у `api` единственная переменная `S3_BUCKET` перенесена из `environment` в `labels`. Получены код `0` и зелёное сообщение для `api`. Приложение такой переменной не получит.

Тест «страж проброса переменных возвращает 0 1 и 2 на трёх входах» этого не обнаруживает: удаляет имя целиком, не проверяя правильность секции.

Исправление: извлекать ключи строго из `services.<service>.environment`; добавить отрицательный тест с одноимённой меткой. Ожидаемый результат — `1`, `api`, `S3_BUCKET`.

### RV-foundation-02 — medium — `apps/recognizer/src/provider/fake.ts:63`

После ожидания проверяется `latencyMs > deadlineMs`. Это сравнение двух входных чисел, а не проверка истёкшего бюджета. При задержке обработки таймера фейк возвращает успешный результат после дедлайна.

Воспроизведение: текущие TypeScript-модули транспилированы в памяти; вызов с задержкой 10 мс и бюджетом 20 мс запущен перед синхронной занятостью цикла событий на 80 мс. Результат: `{"outcome":"resolved","deadlineMs":20,"elapsedMs":81}`. Сигнал отмены не срабатывал; порт обязан самостоятельно соблюдать переданный бюджет.

Тест «фейковый адаптер уважает дедлайн и отказывает, а не отвечает поздно» проверяет только заранее заданное превышение задержки над бюджетом.

Исправление: фиксировать абсолютный дедлайн монотонными часами и проверять его после ожидания и перед возвратом. Добавить сценарий задержанного исполнения таймера: после освобождения цикла событий должен возвращаться отказ, а не поздний успех.

## Что проверено без замечаний

- Исправление паролей сравнивает `POSTGRES_PASSWORD` с `N4_DB_APP_PASSWORD`, что соответствует именам в compose. Новые тесты проверяют отказ до `psql`, отсутствие/пустоту административного пароля и разрешение разных значений.
- Квота использует атомарный UPSERT, три либо четыре ключа и полный откат транзакции при отказе. Реальных платных вызовов в этой фиче нет; порядок квоты перед будущим живым вызовом здесь ещё не доказан.
- Транзакция аренды закрывается до адаптера; конкурентные тесты действительно запускают несколько операций одновременно. Пороги заданы литералами.
- Страж схемы ADR-001 существует; исторический документ предъявляет его падение при добавлении `calories`. В текущем ревью мутация этого стража не запускалась. Каркас завершает результат без сопоставления статусом `refused`.
- `db` и `storage` не публикуют порты; у приложений публикаций нет, дверь привязана к loopback.
- Среди отслеживаемых `.env`/ключевых файлов найден только `.env.example`; реальные секреты в просмотренном коде не обнаружены.
- Фейк не обращается в сеть. HTTP-тесты используют локальный адрес; конкурентные тесты рассчитаны на PostgreSQL стенда.
- Согласие, Telegram-подпись и доступ к чужим пользовательским ресурсам явно вне объёма foundation; общий ответ неизвестного маршрута `404` не доказывает проверку владения.
