## Findings

**VS-01 (low, без изменений).** MinIO External Dependencies — вердикт `CONFIRMED` при
вторично-источниковом доказательстве. Не блокер.

**VS-02 (low, без изменений).** `AC-scan-pipeline-3` не разделяет явно 413 vs 422 по типу нарушения.

**VS-06 (medium, новая — обнаружена этим прогоном).** `AC-scan-pipeline-19` (`01_specification.md:
464–470`) описывает механизм Попытки 3: «повтор запроса с ТЕМ ЖЕ `Idempotency-Key` перезаписывает
ТОТ ЖЕ детерминированный ключ объекта». Этот механизм (`object_key` по хешу содержимого) прямо
ОТМЕНЁН в этой же ревизии текстом `FR-scan-pipeline-19`: «Ключ по хешу СОДЕРЖИМОГО (Попытка 3)
ОТМЕНЁН». Новый механизм (`object_key` по `recognition_id`, генерируемому ЗАНОВО при КАЖДОЙ попытке)
структурно НЕ ДЕТЕРМИНИРОВАН между повторами: ретрай с тем же `Idempotency-Key` создаёт ВТОРОЙ,
отдельный объект под НОВЫМ ключом; первый (осиротевший при крахе между `PUT` и транзакцией) убирается
не «перезаписью», а отдельным механизмом уборки орфанов по возрасту (`AC-scan-pipeline-31`, тот же
сценарий, что и `AC-19`, но правильно описанный). `AC-19` не был обновлён при переписывании `FR-19` —
текст критерия противоречит собственному же соседнему требованию. Не блокер (Given/When и итоговое
наблюдаемое поведение «строки нет, воркер её не видит» остаются верными; неверна ТОЛЬКО фраза про
«тот же ключ»), но тест, написанный буквально по `AC-19`, будет проверять несуществующий механизм.
**Исправление:** заменить последнее предложение `AC-19` на описание через уборку орфанов (как в
`AC-31`), либо явно сослаться на `AC-31` вместо повторения устаревшего утверждения.

**VS-07 (low, новая).** `03_architecture.md` §«Размещение по пакетам и сервисам» не обновлена с
Попытки 1: перечисляет только `FR-scan-pipeline-1…13`, восемь новых/переномерованных требований
(`FR-14…21`) не имеют строки размещения. В частности, `FR-scan-pipeline-21` вводит НОВЫЙ файл
(`scripts/telemetry/model-calls.sh`), которого нет ни в этой таблице, ни в дереве «Структура
каталогов» — путь назван только в самой `FR-scan-pipeline-21` (`01_specification.md`), не
продублирован в архитектурном документе, как это сделано для всех остальных файлов фичи. Не блокер:
путь к файлу известен и однозначен, только не сведён в общую таблицу.
