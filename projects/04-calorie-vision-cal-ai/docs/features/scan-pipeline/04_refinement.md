# Фича `scan-pipeline` — уточнение: краевые случаи, проверки, ужесточение

Слой каждой проверки выбран по природе признака, а не по удобству
([`cost-of-detection-ladder`](../../../../.claude/rules/cost-of-detection-ladder.md)). Разделяемые
ресурсы этой фичи — счётчик эскалации (четвёртый ключ) и аренда задания ПОД РЕАЛЬНЫМ (хоть и
фейковым) вызовом провайдера — закрываются ТОЛЬКО конкурентным прогоном.

## Edge Cases Matrix

| Случай | Вход | Ожидаемое | Как обеспечивается |
|---|---|---|---|
| HEIC 12 МБ | Фото формата HEIC ровно на границе 12 МБ, разрешение 4032×3024 | Принято на приёме; нормализовано в JPEG ≤1568px ≤5МБ ДО вызова модели | `NormalizePhotoForModel`; фикстура реального HEIC (не сгенерированная заглушка) в `tests/fixtures/` |
| Фото 13 МБ | На 1 МБ больше предела | `413`/`422` с названной причиной, квота НЕ списана | Проверка размера на `api` до записи в MinIO, до идемпотентности |
| Повтор `Idempotency-Key`, та же сессия | Тот же ключ второй раз | `202` с ТЕМ ЖЕ `scan_id`, квота не списана дважды | `INSERT … ON CONFLICT DO NOTHING RETURNING id`; пустой результат — существующая строка |
| Повтор `Idempotency-Key`, ДРУГАЯ сессия | Тот же UUID ключа, другой `device_session_id` | Создаётся ВТОРОЙ, независимый скан — ключ уникален В ПАРЕ с сессией | `UNIQUE (device_session_id, idempotency_key)`, не `UNIQUE (idempotency_key)` — иначе два разных устройства не смогли бы использовать одинаковый (случайно совпавший) UUID |
| Квота ровно на границе | `used = limit - 1`, затем `used = limit` | Предпоследняя — `granted`, последняя — `granted` (равенство ДО инкремента разрешено), СЛЕДУЮЩАЯ — `refused` | Оператор `WHERE used < limit`; тест на трёх последовательных вызовах вокруг границы |
| 601-я эскалация | Счётчик `escalation` уже на 600 | Второй вызов НЕ выполняется; в реальном окружении этой фичи ведёт к `failed(no_food_matched)` (не `done`, см. `01_specification.md` «Стык»); ОТДЕЛЬНЫМ unit-тестом с `FixedMatchIngredientPort` — статус `done`, `low_confidence=true`, `failure_reason=quota_exhausted_escalation` | `escalate.ts` вызывает `CheckAndConsumeQuota(reason=escalation)` ДО Sonnet 5; счётчик обращений к `ModelProvider`, не текст журнала |
| Провайдер 5xx / таймаут | Фейк настроен на исход `provider_unavailable`/`provider_timeout` | `failed(...)` с названной причиной; попытка учтена (списана на приёме, не откатывается) | Исключение из вызова модели НЕ проглатывается: обработчик бросает, колбэк транзакции не превращает его в возвращаемое значение (`security-operation-order.md`) |
| Устаревший fence под реальной задержкой | Воркер A ждёт ответ провайдера, аренда истекает, B захватывает и завершает раньше | `UPDATE` результата A затрагивает 0 строк; результат B цел; `stale_lease_result` в аудите | Фейковый провайдер с УПРАВЛЯЕМОЙ задержкой (тестовый параметр), а не `setTimeout` угадыванием — иначе тест гоняется |
| Фото без еды | Кадр — пустая тарелка или случайный объект | `refused(no_food_detected)`, запись дневника не создаётся, попытка списана в потолки | Фейк отдаёт пустой `items[]`; `recognizer` трактует как терминальный статус, не как повод для ретрая |
| Decompression bomb | JPEG с валидной сигнатурой, заявленные размеры → распаковка > 100 Мпикс | `422` ДО декодирования, сервис не падает | Чтение метаданных размера БЕЗ полного декодирования (`sharp.metadata()` до `sharp.toBuffer()`) |
| Полиглот | Файл — валидный JPEG в начале и валидный ZIP/HTML в хвосте | Отвергается на приёме | Проверка сигнатуры плюс отказ файлов с посторонними структурами после EOI-маркера (детали — реализация Phase 3) |
| Диапазон нарушен | `confidence = 1,5`; `mass_g = 6000`; 13 позиций (три отдельных прогона) | `failed(schema_violation)` с названным полем в КАЖДОМ прогоне, без подрезания | Structured outputs не выражают `minimum`/`maximum`/`maxItems`; проверка — наш код после разбора (fail-closed) |
| Конкурентная эскалация | 20 распознаваний одновременно требуют эскалацию при остатке 1 | Ровно ОДИН вызов Sonnet 5 | Атомарный `INSERT … ON CONFLICT … WHERE used < limit RETURNING` на ЧЕТВЁРТОМ ключе; последовательный тест здесь ничего не доказывает |
| Конкурентная идемпотентность | Два одновременных `POST` с одним ключом | Один `scan_id`, один оплаченный вызов модели | `ON CONFLICT DO NOTHING` — обе попытки не находят строки одновременно НЕ МОГУТ обе вставить (уникальный индекс арбитрирует) |
| MinIO недоступен при загрузке оригинала | `storage` не отвечает во время `PUT` | `503 dependency_unavailable`; заявленная строка `recognition` НЕ остаётся висящей в неопределённом состоянии — переводится в `refused(storage_unavailable)` либо откатывается целиком (решение реализации Phase 3, тест обязателен) | Недоступность источника истины — исключение, а не тихо проглоченное значение |

## Testing Strategy

**Unit.** Диапазоны `confidence`/`mass_g`/число позиций/число кандидатов (fail-closed, без
подрезания); граница эскалации `confidence = 0,59` вызывает второй вызов, `0,60` — не вызывает
(ADR-004 Confirmation); решение об эскалации с `FixedMatchIngredientPort` (доказывает код `done` +
`low_confidence` + `failure_reason`, готовый к реальному порту); определение MIME по сигнатуре байтов
(таблица известных сигнатур JPEG/PNG/WebP/HEIC); проверка decompression-bomb по метаданным без
декодирования.

**Integration.** `POST /scans` целиком: валидация → идемпотентность → квота → сохранение → `202`,
каждый шаг с ОТДЕЛЬНЫМ прогоном отказа; `GET /scans/{id}` — свой/чужой/несуществующий; нормализация
на фикстуре реального HEIC-файла (не заглушке); `provider/anthropic.ts` — контракт формы ответа
(структура схемы совпадает с интерфейсом `ModelProvider`, БЕЗ реального сетевого вызова — используется
записанная фикстура ответа Anthropic, соответствие интерфейсу проверяется статически); журнал
`model_call` пишется на успех, отказ и таймаут.

**Concurrency (обязательны, не опция — `shared-resource-verification.md`).**
1. Идемпотентность: N параллельных `POST /scans` с одним `Idempotency-Key` и одной сессией → один
`scan_id`, один оплаченный вызов модели.
2. Квота `primary` под нагрузкой ЭТОЙ фичи (сквозь реальный маршрут, не изолированный модуль
`foundation`): 20 параллельных `POST /scans` одного устройства при пределе 10 → ровно 10×`202`,
10×`429(scope=user)`.
3. Эскалация, ЧЕТВЁРТЫЙ ключ: 20 одновременных распознаваний с `confidence < 0,6` при остатке
эскалационной квоты 1 → ровно ОДИН вызов Sonnet 5, проверяется счётчиком обращений к адаптеру, а
НЕ текстом журнала. Проверяется ОТДЕЛЬНО от теста 2: ключей у эскалации четыре против трёх у
первичной попытки, и зелёный тест на трёх ключах ничего не говорит о четвёртом
(`.claude/rules/testing.md`).
4. Устаревшая аренда под РЕАЛЬНОЙ (фейковой, но с задержкой) работой: воркер A начинает вызов
провайдера с управляемой задержкой, аренда искусственно истекает, воркер B захватывает и завершает
раньше A; A пишет результат — `UPDATE` затрагивает 0 строк, `stale_lease_result` в аудите, результат
B цел.

**Стражи по исходнику и их испытание** (`guard-must-be-able-to-fail.md`: страж принимается только
вместе с прогоном на внедрённом дефекте).

| Страж | Что проверяет | Внедряемый дефект |
|---|---|---|
| ADR-001, схема вызова модели | JSON-схема `ModelProvider.recognize` не содержит `calories`, `kcal`, `protein`, `fat`, `carbs`; единственное поле о калорийности — `model_estimate_kcal` | вернуть `calories` в схему |
| ADR-001, путь показа | `model_estimate_kcal` читается РОВНО в одном месте (в этой фиче — нигде, поле только сохраняется; страж проверяет ОТСУТСТВИЕ второго чтения) | добавить чтение `model_estimate_kcal` в ответ `GET /scans/{id}` за пределами уже объявленного поля |
| ADR-001, статус | `recognition` со статусом `done`, у которого ВСЕ позиции `unmatched = true`, не встречается ни в одном интеграционном прогоне этой фичи (реальный `NullMatchIngredientPort`) | подменить `NullMatchIngredientPort` на порт, возвращающий фиктивное совпадение, ВНЕ выделенного unit-теста эскалации |
| порядок операций: квота ↔ вызов модели | эскалация не вызывает Sonnet 5 без предварительного `granted` от `CheckAndConsumeQuota(reason=escalation)` | поменять местами шаги 6 (эскалация) в `RecognizeScanWithinScanPipeline` |
| порядок операций: нормализация ↔ вызов модели | вызов `ModelProvider.recognize` не происходит без успешной `NormalizePhotoForModel` | вызвать модель напрямую над оригиналом |
| частота ↔ разбор тела | тело `POST /scans` не разбирается для запросов сверх 30/мин | убрать хук `onRequest`, оставить только валидацию внутри обработчика |
