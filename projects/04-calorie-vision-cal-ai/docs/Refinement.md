## Edge Cases Matrix

| Scenario | Input | Expected | Handling |
|---|---|---|---|
| Empty input | `POST /scans` без файла или файл 0 байт | 400 с названной причиной; попытка НЕ списана с квоты, `recognition` не создаётся (FR-CAPTURE-002) | Валидация тела на `api` до создания задания очереди и до вызова модели |
| Max size | Фото > 12 МБ или < 320×320 px (FR-CAPTURE-002) | Отказ с названной причиной и кнопкой повторной съёмки; квота не списана, потому что вызова модели не было | Проверка размера и разрешения на `api` до записи в MinIO; клиент уже уменьшил длинную сторону до 1536 px, но серверная проверка не доверяет клиенту |
| Concurrent access | 10 одновременных `POST /scans` с одного `device_session_id`, за сутки уже 0 попыток (FR-LIMIT-001) | Ровно 10 создают `recognition`; 11-й (и любой параллельный сверх 10) получает отказ по потолку; ни одна попытка не потеряна и не посчитана дважды | Атомарный инкремент `INSERT … ON CONFLICT DO UPDATE SET used = used + 1 WHERE used < :limit RETURNING` (Architecture.md, `scan_quota_counter`); последовательный тест здесь ничего не доказывает — обязателен конкурентный прогон ([`shared-resource-verification.md`](../../../.claude/rules/shared-resource-verification.md)) |
| Network failure | Провайдер модели (Anthropic) не отвечает или обрывает вызов во время распознавания | `recognition.status = failed`, экран «модель не ответила» с кнопкой «повторить»; попытка засчитана в оба потолка, потому что счёт идёт по попыткам (FR-LIMIT-001, FR-LIMIT-002) | Исключение из вызова модели не проглатывается: обработчик обязан бросить, а не вернуть значение (`.claude/rules/security-operation-order.md`, вывод о недоступности внешнего источника истины); статус пишется в той же строке очереди, что и попытка (ADR-003) |
| Блюдо не найдено в базе | Ингредиент модели не находит совпадения ни в `food_synonym`, ни в `food_item` | Позиция помечена «нет в базе» и исключена из итога; ноль вместо неизвестного числа не подставляется (FR-SOURCE-001, SC-US-002-2) | Поиск возвращает `null`, а не приблизительную запись; UI показывает явный бейдж, а не молчаливый пропуск |
| Уверенность < 0,6 при исчерпанной квоте эскалации | Первый вызов вернул `confidence < 0,6`, но суточный потолок эскалации 600 уже исчерпан (ADR-004, `model-cost-contract.md`) | Второй вызов НЕ выполняется; показывается экран «уточните блюдо» с ручным поиском по базе — тот же экран, что и при низкой уверенности после честной эскалации (FR-RECOGNIZE-002) | `recognizer` проверяет счётчик эскалации ДО второго вызова тем же атомарным механизмом, что и потолок распознаваний; отказ эскалации не выдаёт результат первой попытки как окончательный молча |
| Расхождение > 15% | Оценка модели 780 ккал, сумма по базе 640 ккал → 22% (FR-CORRECT-003) | Экран расхождения: два числа с источниками, по умолчанию выбрана база; тихое усреднение запрещено | Сравнение выполняется на сервере при сборке результата; оба числа сохраняются вместе с выбором пользователя |
| Недействительный код при наличии cookie | В cookie сохранён источник `OLD`; пользователь явно вводит несуществующий код `ZZZZ` (FR-GROWTH-002, ADR-008) | Ошибка ввода; атрибуция по `OLD` НЕ создаётся; ни один код не засчитан | Явный код проверяется веткой, отдельной от cookie-фоллбэка; неудача завершает обработку с ошибкой раньше, чем код доходит до ветки, читающей cookie |
| Повторный apply кода | Устройство с уже существующей атрибуцией пытается применить второй код (любой, включая действительный) | Отклонено; атрибуция устройства не меняется задним числом | `UNIQUE (attribution.device_session_id)` — конфликт вставки и есть ответ, а не проверка в коде приложения (ADR-008, Architecture.md) |
| initData с истёкшим сроком | Подпись Telegram `initData` верна, но `auth_date` старше 24 часов (FR-AUTH-002) | 401; аккаунт не создан, сессия не выдана | Порядок проверки: подпись HMAC-SHA-256 по сырым байтам сравнением постоянного времени первой, свежесть `auth_date` — второй; ни один шаг не пропускается при успехе другого |
| Фото без еды | Кадр не содержит распознаваемой еды (тарелка пуста, случайный объект) | `recognition.status = refused`, подсказка «еда не распознана, снимите тарелку целиком», запись дневника не создаётся; попытка засчитана в потолки (SC-US-001-2) | Модель возвращает пустой список ингредиентов или явный флаг; `recognizer` трактует это как терминальный статус, а не как отказ, подлежащий ретраю |
| Удаление данных по запросу | Пользователь подтверждает удаление аккаунта (FR-AUTH-003) | Аккаунт, дневник, карточки и фото удалены не позже 72 часов; публичные карточки перестают отдавать содержимое не позже 60 с (FR-GROWTH-006, SC-US-012-2) | Публичный доступ (`share_card`) деактивируется синхронно и немедленно; каскадное удаление остальных данных выполняется фоновой задачей с дедлайном 72 ч, а не в одной блокирующей транзакции |

## Testing Strategy

**Unit.** Расчёт числа `(масса_г / 100) × значение_на_100г` (FR-SOURCE-001); диапазон степпера
5–2000 г и шаги 10/50 (FR-CORRECT-001); порог эскалации ровно на границе — `confidence = 0,59`
вызывает второй запрос, `confidence = 0,60` не вызывает (ADR-004 Confirmation); переходы статусов
`recognition.status` (4 значения) и `attribution.status` (3 значения) как закрытые перечисления, а
не булевы флаги; мягкий стрик — один пропуск не обнуляет, два подряд обнуляют (FR-DIARY-002); правило
fail-closed тарифа — всё, что не равно ровно `paid`, требует бейджа (FR-GROWTH-003), включая `null`,
`''`, `'PAID'`, `['paid']`.

**Integration.** PostgreSQL `FOR UPDATE SKIP LOCKED` — N воркеров на M заданий, ни одно не захвачено
дважды, ни одно не потеряно (ADR-003 Confirmation); атомарность счётчика квоты — см. критический путь
ниже; покрытие `food_synonym` — 50 заранее составленных частых русских запросов находят совпадение,
падение покрытия ниже порога есть красный тест, а не предупреждение (ADR-006 Confirmation);
уникальность `partner_code.code` и `attribution.device_session_id` на конфликте вставки, а не на
проверке в коде; проверка `initData` по сырым байтам тела запроса, а не после `JSON.parse` →
`stringify` (`security-operation-order.md`).

**E2E.** Сквозной путь CJM E на РАЗВЁРНУТОМ стенде по адресу, который выдало развёртывание, — дважды:
один раз из PWA-браузера, один раз из Telegram Mini App (ADR-002 Confirmation): вход → первый кадр →
результат с источником → экран расхождения (при наличии) → правка порции → согласие → запись
дневника → код партнёра → карточка 9:16 → шеринг. Отдельно — путь отказа: потолок сканов, лимит
эскалации, недействительный код, отзыв согласия.

**Performance.** NFR-PERF-001 (кадр → результат ≤ 6 с, p95, включая возможную эскалацию) и
NFR-PERF-002 (видоискатель ≤ 1 с) измеряются на живом стенде, не на локальной машине (Specification
§6, NFR-PERF-001). Нагрузочный профиль фиксируется до запуска: 3000 распознаваний/сутки фоном и
всплеск 10 одновременных без деградации сверх NFR-PERF-001 (NFR-SCALE-001); сохраняются commit, seed
данных базы и percentiles, а не время одного показательного запроса.

### Критические пути (обязательны, не опциональны)

1. **Конкурентный тест атомарности квоты.** Правило [`shared-resource-verification.md`](../../../.claude/rules/shared-resource-verification.md)
   требует проверку на разделяемом ресурсе, а не только на сценарии, ради которого писалась защита:
   N параллельных запросов на один `device_session_id` при пределе 10 — ровно 10 успешных, число
   одновременно занятых единиц ресурса не растёт с числом ожидающих, добросовестный параллельный
   пользователь на соседнем `device_session_id` не блокируется чужой квотой.
2. **Страж «число только из базы» — тест по исходнику, испытанный на внедрённом дефекте.** JSON-схема
   вызова модели не содержит полей `calories`, `kcal`, `protein`, `fat`, `carbs` (ADR-001
   Confirmation); тест обязан быть прогнан на редакции, где поле временно возвращено, чтобы доказать
   красный результат, а не только зелёный (`guard-must-be-able-to-fail.md`). Отдельно: `recognition`
   без ссылки на `food_item` не может получить статус `done`.

## Performance Optimizations

`GIN (name gin_trgm_ops)` на `food_item.name` и `GIN (name_ru gin_trgm_ops)` на `food_synonym.name_ru`
для нечёткого совпадения «гречка отварная» ↔ `Buckwheat, cooked` (Architecture.md, Data Architecture).
Частичный индекс `(status, created_at) WHERE status = 'queued'` держит очередь короткой независимо от
роста истории. Кэша нет осознанно: 3000 сканов/сутки ≈ 0,03 rps не оправдывают второй сервис и класс
дефектов «устаревшее значение» (Architecture.md, Technology Stack); решение пересматривается при росте
нагрузки на два порядка. Фото отдаются исключительно presigned-URL с TTL 15 минут (NFR-SEC-001,
ADR-010) — короткий срок ограничивает цену утечки ссылки без дополнительной инфраструктуры.

## Security Hardening

Ограничение частоты работает **до** валидации тела запроса, иначе перебор мусорными телами бесплатен
(`security-operation-order.md`); проверка квоты — атомарно и **до** вызова модели, а не после
(ADR-007); согласие — **до** первой записи в дневник, а не при установке (ADR-009, FR-AUTH-003).
Валидация формата и размера фото на границе `api`, а не на клиенте (FR-CAPTURE-002). Anti-fraud по
кодам партнёра: окно 10 минут, порог 50 применений с одного IP-адреса, блокировка кода и запись в
аудит с усечённым префиксом адреса (FR-PARTNER-003). Данные о питании — специальная категория
персональных данных: доступ только владельцу, публикация только по явному согласию, по умолчанию всё
закрыто (NFR-SEC-002). `web` не имеет секретов вызова модели и токена бота — только `api` и
`recognizer` (Architecture.md, Security Architecture).

## Accessibility

Уровень WCAG 2.1 AA: контраст текста не ниже 4,5:1, зона нажатия не меньше 44×44 px, все действия
доступны одним большим пальцем (PRD §6.3). Числа дублируются текстом, а не только цветом или иконкой
(критично для экрана расхождения, где выбор по умолчанию не должен читаться исключительно по цвету
кнопки). Стрик показывается нейтральной формулировкой без давления и без обратного отсчёта
(FR-DIARY-002) — это одновременно требование доступности по смыслу и требование продукта.
