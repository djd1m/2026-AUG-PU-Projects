# N4 — варианты CJM (Customer Journey Map) для клона Cal AI

Статус: **выбор НЕ сделан — ожидание решения владельца.** Дата: 2026-09-12.
Рабочее имя клона в прототипе — **«Тарелка»** (доступность имени не проверялась).
[Кликабельный прототип](prototypes/cjm/index.html) · [Бриф discovery](product-discovery-brief.md) ·
[Профиль облика источника](source-product-profile.md).

## Общее ядро (одинаково во всех вариантах)

Пользователь фотографирует еду → через секунды видит **название блюда, калории и БЖУ** →
**у каждого числа виден источник** (запись открытой базы, например USDA FoodData Central, и
порция в граммах) → поправляет порцию или ингредиент одним касанием → запись ложится в дневник дня.
Расхождение «оценка модели ≠ число базы» — отдельный экран выбора, а не тихое усреднение
(постановка владельца; у источника такого экрана нет — [FR-LOOK-012](source-product-profile.md)).

Первый экран продукта — камера, без анкеты (FR-LOOK-006). Экран результата один: фото с подписями,
название, степпер порции, четыре плитки, кнопка исправления рядом с подтверждением (FR-LOOK-007).

Ограничения недели, общие для всех вариантов: подписки НЕТ (paywall в прототипе показан как экран
интереса «Pro скоро» при достижении дневного лимита сканов); штрихкоды, Apple Health/Google Fit,
рецепты и план питания не входят. Дневной лимит сканов на пользователя — обязательное число по
правилу о стоимости внешних вызовов, а не тарифная опция ([бриф §M4](product-discovery-brief.md)).

Контур запуска принят как **Россия/СНГ, Telegram-first** (Instagram запрещён, TikTok ограничен —
[исследование §C](discovery/research/trends-and-growth.md)); карточка и промокоды платформенно
нейтральны, глобальный контур — вторая волна. Это допущение, его подтверждает владелец.

Варианты РАЗЛИЧАЮТСЯ growth-петлёй, а не только интерфейсом. Их четыре, а не три: вариант D собран
из решений проектов N1–N3a по просьбе владельца.

| | A — Карточка | B — Открытый дневник | C — Тренер видит | D — Код блогера |
|---|---|---|---|---|
| **Growth loop** | content-driven (сидинг блогеров, органический шеринг) | badge (публичная страница дня с бейджем) | sales (B2B2C: тренер/нутрициолог приводит клиентов) | incentivized referral, двусторонний (N3a-партнёрка + бонус за код) |
| **Aha Moment** | первое распознавание с источником числа → карточка | вечерний «итог дня» собрался сам из фото | тренер увидел дневник без напоминаний; клиент — реакцию тренера | бонус от блогера активирован + первое распознавание |
| **Entry Hook** | ролик «сфоткал — увидел калории» | «покажи, чем ты питаешься» в марафоне/чате | боль тренера: клиенты не ведут дневник | «введи код @blogger — получи +30 сканов» |
| **Paywall (вне недели)** | лимит сканов → «Pro скоро» | снять бейдж / закрыть страницу → «Pro скоро» | места для клиентов тренера → заявка | после окончания бонуса → «Pro скоро» |
| **Метрика недели** | доля активированных, расшеривших ≥1 карточку: цель **20%** | доля, открывших ≥1 страницу дня: **15%** (карточка тоже есть) | клиентов с ≥3 днями дневника на тренера: **≥5** | доля установок с кодом, дошедших до 1-го распознавания: **60%**; расшеривших карточку: **20%** |
| **Главный риск** | виральности нет по построению; без бюджета сидинга петля не стартует | данные о питании = данные о здоровье (152-ФЗ ст.10): публикация только по явному согласию; трафик на личную страницу мал | не виральный; цикл продажи тренеру дольше недели | стимул притягивает накрутку; блогер обязан маркировать рекламу (ЕРИР) |
| **Переиспользование N1–N3a** | badge.ts/tariff.ts (бейдж на free) | wall.ts (публичная страница по слагу, только одобренное) + badge | партнёрские коды N1 partner.ts как коды тренера | N3a партнёрка целиком + N1 referral.ts/partner.ts + N2 notifier (Telegram) и guest (QR) |

## A — Карточка

[Открыть HTML A](prototypes/cjm/variant-a.html).

| Поле | Содержание |
|---|---|
| **Aha Moment** | Первое фото → через ~3 с название блюда, ккал и БЖУ, под числом — «USDA FDC · порция 250 г»; сразу под результатом карточка 9:16 «блюдо → калории» с мелким бейджем клона |
| Entry Hook / сегмент | Сегмент 1 «худеющий на дефиците»: увидел у блогера ролик «сфоткал — увидел», хочет так же, устал вбивать еду руками |
| Onboarding | Нет анкеты: камера сразу; после первого результата — «сохранить дневник?» → вход по Telegram/почте; поле «код блогера» необязательно |
| Core Loop | фото → результат с источником → поправка → дневник дня → вечером «итог дня» → утром напоминание (мягкий стрик) |
| Paywall | Вне недели. В прототипе: при 10-м скане за день экран «лимит на сегодня; Pro скоро — оставить почту» |
| Growth loop | **Content-driven через сидинг**: блогер публикует свою карточку в ролике → зритель ставит → получает свою карточку → делится в сторис/чат → бренд виден на каждой карточке |
| FR-GROWTH-001 | Share-CTA ровно на экране первого результата, не на онбординге; карточка готова без действий пользователя |
| FR-GROWTH-002 | Код блогера при первом входе + cookie/deeplink-параметр; атрибуция хранится до платной конверсии (которой в неделе нет — считаем «активирован через код») |
| FR-GROWTH-003 | Бейдж «распознано в Тарелке» на карточке free; снятие — будущая платная опция, решается в Specification |
| FR-GROWTH-004 | Персональный код у каждого блогера; дашборд когорты: установки → активации → шеринги по коду |
| Микро-тренды | A.1 camera-first онбординг; A.3 shareable cards в эстетике Wrapped (Spotify Wrapped 2025 — 200 млн за сутки); A.7 calm/one-thumb интерфейс; A.2 индикатор уверенности и источника |
| Главный риск | **Inherent-виральности нет** (по постановке и по исследованию): ценность не растёт от шеринга; без 5–10 оплаченных микро-блогеров петля не запускается. Доля шеринга неизвестна — отраслевого K-factor для health/fitness не найдено (проверка провалилась, §D) |
| Проверяемая гипотеза | Карточка, готовая в момент aha, даёт ≥20% шерящих среди активированных за неделю |
| Сегмент лучше всего | 1 «худеющий на дефиците» |

Сигналы для гипотезы: реальный рост Cal AI шёл через ~250 блогеров на ретейнере и лестницу
«UGC → крупные креаторы → paid → affiliate» ([Micro Empires](https://www.microempires.cc/p/cal-ai), [SponsorRadar](https://sponsorradar.com/brands/cal-ai/get-sponsored)); 50 из 60 сделок — каналы 250K+, значит старт с микро-каналов 10–100K — компромисс, а не копия.

## B — Открытый дневник

[Открыть HTML B](prototypes/cjm/variant-b.html).

| Поле | Содержание |
|---|---|
| **Aha Moment** | Вечером страница «мой день в тарелках» собралась сама: 3–5 фото, названия, итог ккал/БЖУ и источники — можно показать одной ссылкой |
| Entry Hook / сегмент | Сегмент 1 в контексте марафона похудения в Telegram: «покажи, чем ты питаешься» — отчёт для чата вместо ручного списка |
| Onboarding | Камера сразу; после первого результата — «страница дня: закрытая / по ссылке / публичная» (по умолчанию ЗАКРЫТАЯ, явное согласие на публикацию — специальная категория ПДн) |
| Core Loop | фото → результат → дневник → страница дня по ссылке `/d/<slug>/<дата>` → зритель видит бейдж → ставит |
| Paywall | Вне недели. В прототипе: «снять бейдж со страницы» и «закрыть страницу паролем» ведут на «Pro скоро» |
| Growth loop | **Badge**: артефакт продукта живёт в чужом чате/ленте и виден снаружи; каждая открытая страница дня несёт бренд |
| FR-GROWTH-001 | Share-CTA на экране первого результата (карточка) И на странице дня («поделиться ссылкой») — момент ценности здесь двойной |
| FR-GROWTH-002 | Переход по ссылке дня ставит cookie-атрибуцию на владельца страницы; код блогера — независимый fallback |
| FR-GROWTH-003 | Бейдж на странице дня и на карточке на free; снятие — платно; правило «только одобренное публично» из N1 `wall.ts` |
| FR-GROWTH-004 | Персональные коды блогеров + личный код пользователя на его странице дня (пользователь как микро-партнёр) |
| Микро-тренды | A.8 Telegram Mini Apps (+162% за год, шеринг в чат без установки); A.4 стрики «дней с логом» [H]; A.3 Wrapped-карточки; A.9 модель «делюсь дневником по ссылке» |
| Главный риск | **Публичные данные о питании — данные о здоровье** (152-ФЗ ст.10, [§C](discovery/research/trends-and-growth.md)): публикация только по письменному согласию, по умолчанию закрыто → доля публичных страниц может быть близка к нулю; трафик на личную страницу мал, показы ≠ установки |
| Проверяемая гипотеза | ≥15% активированных открывают хотя бы одну страницу дня по ссылке за неделю; марафоны дают первые 20 страниц |
| Сегмент лучше всего | 1 в марафонах; частично 3 (клиент показывает тренеру) |

Переиспользование: [`wall.ts`](../../01-testimonials-senja/apps/web/src/lib/wall.ts) (публичная страница по
слагу, фильтр «только одобренное» в коде), [`badge.ts`](../../01-testimonials-senja/apps/web/src/lib/badge.ts)
(адрес бейджа строится на сервере с UTM).

## C — Тренер видит

[Открыть HTML C](prototypes/cjm/variant-c.html).

| Поле | Содержание |
|---|---|
| **Aha Moment** | Клиент: первое фото залогировано за 3 с — и тренер поставил реакцию. Тренер: экран «все клиенты за сегодня» заполнился без единого напоминания |
| Entry Hook / сегмент | Сегмент 3 «клиент нутрициолога/тренера» и сам тренер как покупатель: 70% бросают дневник в первые две недели ([§D](discovery/research/market-and-data.md)) |
| Onboarding | Тренер: создать группу → ссылка/QR клиентам. Клиент: по ссылке → камера сразу → после результата «делиться с тренером Иваном?» (явное согласие на передачу данных о здоровье) |
| Core Loop | клиент: фото → результат → дневник → тренер видит; тренер: утренний обзор → реакция/комментарий → клиент продолжает |
| Paywall | Вне недели. В прототипе: тренер после 5 клиентов видит «места для клиентов — тариф тренера, оставить заявку» |
| Growth loop | **Sales**: продаём инструмент тренерам и нутрициологам; один тренер приводит 10–50 клиентов («привлекаешь одного — он привлекает многих», но через продажу, не через виральность) |
| FR-GROWTH-001 | Карточка результата у клиента остаётся (момент ценности тот же); шеринг — вторичен, тренер может добавить свой бренд рядом с нашим |
| FR-GROWTH-002 | Тренер = партнёр: его клиенты атрибутируются к нему до будущей платной конверсии |
| FR-GROWTH-003 | Бейдж на карточках клиентов и на «отчёте тренера» на free |
| FR-GROWTH-004 | Код тренера = персональный партнёрский код (N1 `partner.ts`: читаемый код + fraud-окно) |
| Микро-тренды | A.9 коуч видит дневник клиента (WeStrive, Nutrium); A.5 protein-first плашка для клиентов «на массе»; A.6 голосовой ввод для перекусов; A.2 источник числа как аргумент тренера |
| Главный риск | **Не виральный** и не про метрику недели «доля расшеривших»; цикл продажи тренеру длиннее недели; передача данных о здоровье третьему лицу требует явного согласия и договора с тренером |
| Проверяемая гипотеза | 3–5 тренеров за неделю приводят ≥5 клиентов каждый, ≥60% клиентов держат дневник 3+ дня |
| Сегмент лучше всего | 3; тренер как покупатель |

Сигналы для гипотезы: платформы для нутрициологов синхронизируют лог клиента с дашбордом коуча
([WeStrive](https://www.westrive.com/features/nutrition), [Nutrium](https://nutriadmin.com/use-cases/software-for-coaches)) — наличие паттерна подтверждено, спрос в RU — гипотеза.

| FR-GROWTH-001 | Share-CTA на экране первого результата; карточка содержит код пользователя, если он уже реферер |
| FR-GROWTH-002 | Атрибуция N3a: код > cookie, хранится до платной конверсии; в неделе без оплаты считаем «активация» и помечаем как pending |
| FR-GROWTH-003 | Бейдж на карточке free (N1 `tariff.ts`: всё, что не ровно `paid`, требует бейдж) |
| FR-GROWTH-004 | Персональные коды блогеров и залов через партнёрскую программу N3a: клики → установки → активации → (позже) оплаты; ручной реестр выплат 5-го числа |
| Микро-тренды | B.1 лестница Cal AI до affiliate-creator программы; B.5 промокод надёжнее ссылки в мобильной атрибуции (разрыв 20–40%); B.4 посевы в Telegram от 500 ₽/пост, тест 15–30 тыс ₽; A.8 Mini App + Telegram-дайджест (N2 notifier) |
| Главный риск | **Стимул притягивает накрутку**: self-referral, фермы кодов (N1 fraud-окно 50 регистраций/IP/10 мин — отправная точка, @security-сценарий обязателен); блогер с вознаграждением обязан маркировать рекламу (ЕРИР/ERID) — ответственность рекламодателя; выплаты требуют денег вне недели |

## Growth-требования, общие для любого выбранного варианта

| ID | Как проявляется в вариантах |
|---|---|
| FR-GROWTH-001 | Share-CTA на экране первого результата во всех четырёх; в B добавляется страница дня, в D — код пользователя на карточке |
| FR-GROWTH-002 | Атрибуция до платной конверсии: код + cookie/deeplink; пока оплаты нет — pending с явной пометкой |
| FR-GROWTH-003 | Бейдж клона на карточке и публичных страницах в free; снятие — платная опция, решается в Specification |
| FR-GROWTH-004 | Персональные коды для людей с аудиторией: блогеры (A, D), пользователи-рефереры (B, D), тренеры (C) |
