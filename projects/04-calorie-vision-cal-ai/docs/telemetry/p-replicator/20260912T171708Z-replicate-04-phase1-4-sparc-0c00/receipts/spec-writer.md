## Отклонения от задания и причины

1. **Объём превышен: 626 строк вместо 350–470 и 343 вместо 180–260.** Заданное содержание —
   22 FR + 7 growth-требований по три Gherkin-сценария + 12 строк облика + 13 историй по два
   сценария + 6 NFR + матрица + метрики + таблица ответов на 22 `PD-*` — в названные рамки не
   укладывается. Сокращать пришлось бы обязательное содержание, а не форму, поэтому выбран
   объём. Плотность формулировок соблюдена: заглушек, `{{…}}`, TODO/TBD в файлах нет (проверено
   grep).
2. **Метрика расхода на модель разведена на две строки, и внешний API назван иначе, чем просило
   задание.** Суточный расход считается по НАШЕМУ журналу попыток — это и есть требование
   NFR-OPS-001, и число существует у нас, как только мы посмотрим. Сверка с биллингом провайдера
   вынесена отдельной строкой и опирается на `внешний API: Anthropic Usage & Cost Admin API`.
   Имя взято дословно из `docs/Architecture.md` → `## External Dependencies`, а не из задания:
   `check-metric-source.cjs` ищет названный токен ПОДСТРОКОЙ в инвентаре, и формулировка задания
   «Anthropic Usage API GET /v1/organizations/usage_report/messages» в инвентаре отсутствует —
   такая строка дала бы код 1 вместо 0. Инвентарная строка проверена автором архитектуры
   2026-09-12 и помечена CONFIRMED со ссылкой на документацию.

   Порядок работы: обе метрики сперва были записаны как `наш журнал` и `ручное измерение`, потому
   что `Architecture.md` на момент написания не существовал. Он появился до сдачи, и метрика
   поднята до внешнего API — иначе она никогда не попала бы под единственную линзу, смотрящую
   наружу документов.

3. **`FR-LOOK-003` и `FR-LOOK-004` отклонены с причиной, а не приняты.** Задание допускало оба
   исхода. Эти строки описывают блог и пресс-раздел маркетингового сайта источника; в неделе
   измерения ни того, ни другого не создаётся, и принятие было бы обязательством без носителя.
   Принятый путь публичного входа — три экрана: лендинг → вопросы и ответы → установка PWA либо
   Telegram Mini App (`FR-LOOK-001`, `FR-LOOK-002`, `FR-LOOK-005`).
4. **Заголовок раздела метрик — ровно `## Success Metrics`, без номера, в обоих файлах.**
   `check-metric-source.cjs` ищет заголовок по точному шаблону `^#{2,6}\s+Success Metrics\s*$`;
   «## 9. Success Metrics» он не видит вовсе и отвечает кодом 2. Из-за этого в `PRD.md` нумерация
   разделов перескакивает с 8 на 10, а ссылки на раздел даны по имени, а не по номеру.
5. **Канон §8 говорит «все 20 `PD-*`», а таблица манифеста в брифе перечисляет 22 идентификатора.**
   Расхождение самого канона с брифом; отвечено на все 22 — меньшее число оставило бы два выхода
   Фазы 0 без ответа. Координатору стоит поправить счёт в `canon.md`.
6. **Формат сценариев приёмки:** идентификатор `[SC-US-nnn-k]` стоит на одной строке с `Given`,
   далее `When` и `Then` отдельными строками. Это компромисс по объёму; идентификаторы уникальны
   и находятся по точному токену, трассировка из Pseudocode не страдает.
