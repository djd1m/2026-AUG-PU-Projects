## Findings

**RV-foundation-01 — high — `apps/api/src/server.ts:72`**

Отсечение query не делает путь безопасным: сегменты пути полностью контролирует клиент. Запрос с битым JSON к `/unknown/review-cookie-token-0123456789/203.0.113.77` воспроизведён через настоящий `buildServer` без обращения к БД. В событии `request_failed` оба значения сохранились в `path`. Разрешённое имя поля не ограничивает его содержимое; страж пропускает передачу через промежуточную переменную. Это нарушает требование гигиены журнала.

Исправление: журналировать шаблон зарегистрированного маршрута, для неизвестного — постоянную метку; исключить сырой путь. Добавить регрессионный запрос с чувствительными значениями в сегментах пути.

**RV-foundation-02 — medium — `tests/concurrency/lease.test.ts:129`**

Тест «четвёртого захвата не бывает» использует импортированный `MAX_LEASE_ATTEMPTS` и для числа захватов, и для ожидаемого fence. Изменение рабочей константы с `3` на `4` передвинет одновременно реализацию и проверку: тест будет проверять запрет пятого захвата. Сценарии уборщика используют ту же зависимость. Это вывод из кода; мутационный прогон на БД сейчас не выполнялся.

Исправление: выполнить ровно три захвата по литералу спецификации, четвёртый проверить отдельно, ожидать fence `3`. Испытать тест мутацией рабочего предела `3 → 4`.

**RV-foundation-03 — medium — `docs/features/foundation/validation-report.md:4`**

Отчёт `READY` привязан к SHA-256 `3be77fbcc5d393f5b8eabaf396ec7c09b00b132223c3b8ff277ab6eb05cb3234`, тогда как текущая спецификация имеет хеш из шапки этого ревью. Отчёт также утверждает, что нового FR не вводили, хотя текущая спецификация содержит `FR-foundation-11`. Следовательно, этот документ не подтверждает валидацию текущего контракта целиком.

Исправление: проверить изменения спецификации и дополнить валидацию актуальным составом требований и хешем. Простая замена контрольной суммы проверки не заменяет.

## Что проверено без замечаний

- `npm test`: exit `0`, **30/30 тестов**, четыре файла; длительность Vitest — **1,05 с**.
- Квота реализована атомарным UPSERT; отказ откатывает всю транзакцию. Первичная попытка содержит три ключа, эскалация — четыре.
- Конкурентные тесты квоты и захвата используют одновременно созданные Promise, а не последовательные вызовы с `await`.
- Аренда проверяет публикацию фото, срок и fence; транзакция освобождает соединение до работы адаптера. Запись результата защищена fence и статусом.
- Страж схемы ADR-001 существует и прошёл текущий unit-прогон. Мутация с `calories` описана в прежней квитанции; сейчас не повторялась.
- Рабочий каркас завершает несопоставленный результат как `refused(no_food_matched)`. Живой адаптер явно не реализован; платных сетевых вызовов в проверенном коде нет.
- В compose хранилища и приложения не публикуют порты; единственная публикация — loopback-порт proxy. Из `.env*` отслеживается только `.env.example`.
- Telegram-подпись, доступ к чужим ресурсам и запись дневника с согласием находятся вне объёма foundation; их безопасность этим ревью не подтверждается.

Ограничения: дополнительный запуск выбранных integration-тестов остановился на временных файлах (`EROFS`, затем ошибка создания каталога); результатов тестов он не дал. Чистая сборка и Docker не запускались.
