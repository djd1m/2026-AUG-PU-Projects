## Findings

### RV-foundation-01 — medium — `apps/recognizer/src/provider/fake.ts:59`

**Сломано:** фейк возвращает успех, когда его заданная задержка превышает бюджет. Это прямо противоречит критерию дедлайна.

**Причина:** ожидание сокращается до `Math.min(latencyMs, deadlineMs)`. После него проверяется только `performance.now() >= expiresAt`. Дробная задержка таймера округляется вниз: при бюджете `5.9` мс таймер может завершиться раньше срока. Проверка времени проходит, хотя запрошенная работа длительностью `1000` мс не выполнена. Проверка `latencyMs > deadlineMs`, существовавшая в базовой ревизии, удалена диффом.

**Воспроизведение:** текущие TypeScript-модули транспилированы в памяти и исполнены без файловых изменений, сети и Docker. Двадцать последовательных вызовов с параметрами:
```ts
createFakeModelProvider({ latencyMs: 1000 }).recognize(
  { scanId: 'probe', objectKey: 'photo' },
  MODEL_RESPONSE_SCHEMA,
  { model: 'haiku-4.5', deadlineMs: 5.9, signal: new AbortController().signal },
);
```
Результат: `succeeded: 20, refused: 0`. Ожидание: каждый вызов отклонён с `ModelDeadlineExceeded`.

**Исправление:** сохранить проверку фактически истёкшего времени и вернуть независимую проверку превышения бюджета заданной задержкой. Добавить регрессионный сценарий дробного бюджета с управляемыми часами. Нынешний тест занятого event loop полезен, но этот отказ не покрывает.

## Что проверено без замечаний

- Все **21** заголовок из Criterion coverage существуют в названных файлах.
- Квота использует атомарный `INSERT … ON CONFLICT … WHERE used < limit RETURNING`; три или четыре ключа находятся в одной транзакции. Отказ вызывает исключение и полный откат.
- Конкурентные тесты квоты и аренды используют `Promise.all`, а не последовательный цикл с ожиданием каждого вызова.
- Аренда проверяет срок, наличие фото и предел захватов; транзакция освобождает соединение до обращения к адаптеру. Запись ограничена fence и статусом `queued`.
- Ограничитель частоты зарегистрирован на `onRequest`, до разбора тела.
- Проверки отсутствующих и пустых S3-переменных представлены для обоих сервисов и прошли в unit-наборе.
- Страж схемы ADR-001 прошёл; `05_completion.md` содержит исторический красный результат мутации `calories`. Рабочий каркас завершает распознавание как `refused`, не выдавая модельную оценку за число из базы.
- Живой поставщик не реализован и явно отказывает. Связка «квота до платного вызова», проверка чужих ресурсов и согласие до дневника относятся к следующим фичам; здесь их реализация не заявляется подтверждённой.
- В compose хранилища и приложения не публикуют порты; опубликована только петлевая дверь proxy. Проверенные отслеживаемые пути не содержат `.env`, PEM или файлов ключей; это не полный аудит истории секретов.
