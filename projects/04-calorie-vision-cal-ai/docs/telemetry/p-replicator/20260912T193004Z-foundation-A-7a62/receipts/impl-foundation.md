## Дополнение: правка контракта DEC-A-015 / DEC-A-018 (2026-09-12, после основной поставки)

Задание координатора: (1) порт `recognize(image, schema, opts: { model, deadlineMs })`, фейк
возвращает `model` и уважает `deadlineMs`; (2) предикат выборки `status='queued' AND photo_id IS NOT
NULL AND (leased_until IS NULL OR leased_until < now()) AND lease_fence < 3` плюс уборщик
(`queued` старше 5 минут без захвата, `lease_fence = 3` с истёкшей арендой → `failed('timeout')`).

**Сделано целиком.** Плюс ОДНО следствие, которого в задании не было, но без которого правка вносит
дефект: условная запись результата получила `AND status = 'queued'`. Появился ВТОРОЙ писатель
(уборщик), и без этого условия воркер затирал бы его терминальный статус, воскрешая задание задним
числом. Различение двух случаев «ноль строк» — по НОМЕРУ ЗАХВАТА, а не по статусу: номер больше
своего значит перезахват (`stale_lease_result`), номер равен своему при терминальном статусе значит
уборщик (`swept_as_timeout`), потому что уборщик единственный, кто закрывает строку, не увеличивая
номер.

**Схема:** миграция `002_failure_reason_timeout.sql` расширяет `failure_reason` до десяти значений
(DEC-A-018). Отдельным файлом, а не правкой `001`: применённый файл раннер обязан отвергать, и это
его собственное проверяемое свойство. Вместе с `timeout` добавлено `normalize` — набор из десяти
значений уже объявлен `Architecture.md` и `Pseudocode.md`, а схема, отстающая от документа, который
ею управляет, и есть «два места с одним правилом».
