# Квитанция: оформление UI «Тарелка»

Исполнитель: impl-ui. Задача: живой стенд выглядел «голым HTML» — часть экранов не имела ни
одного класса, экран результата ссылался на 39 несуществующих классов CSS. Навык
`frontend-design` загружен и применён перед реализацией.

## Решение по теме (обосновано одной фразой, как просил владелец)

**Светлая основа + ОДИН тёмный блок**, а не сквозная тёмная тема: `docs/source-product-profile.md`
FR-LOOK-009 прямо описывает источник как «монохромная база (чёрный на белом), ОДИН тёмный блок»,
и ровно это уже реализовано и принято владельцем в `docs/prototypes/cjm/assets/phone.css`
(`--paper`/`--ink`/`--app-dark`) — расхождение с камерой не в теме, а в природе: видоискатель
тёмный, потому что это живой видеопоток, а не потому что так решено дизайном; он получил СВОИ
токены (`--cam-bg`/`--cam-fg`) в `globals.css`, не общие. Единственный тёмный блок продукта —
плитка ккал на экране результата (`.tile--kcal`), она же крупнее трёх остальных плиток.

## Что взято из источников

- Палитра и радиусы — `docs/prototypes/cjm/assets/{styles,phone}.css` дословно (`--paper`,
  `--paper-2`, `--ink`, `--ink-2`, `--line`, `--app-dark`→`--dark`, `--yolk`→`--accent`, радиусы
  10/16/24).
- Шрифты — `Unbounded` (заголовки/числа) + `Onest` (текст), те же `.ttf`, скопированы в
  `apps/web/public/fonts/` вместе с `OFL-*.txt`; `@font-face` с `font-display: swap`, БЕЗ
  внешнего CDN (запрещён `connect-src 'self'` в `middleware.ts`, шрифты и так лежали бы мимо
  разрешённых источников `script-src`/`style-src`).
- Сетка — шаг 4px, доминанты 16/24, один брейкпоинт 768 (FR-LOOK-011); мобильная раскладка
  основная, широкий экран — центрированная колонка max-width 480px.
- FR-LOOK-012 (источник числа виден) — уже была решена структурой `.source-chip` в
  `result-screen.tsx` (карточка с названием записи USDA FDC и её `source_id`, раскрывается по
  тапу); стилизована как пунктирная акцентная плашка, ВСЕГДА присутствует в разметке.

## Осознанное отклонение от FR-LOOK-008

Источник измерен как ОДНА гротескная семья (FR-LOOK-008) — но это измерение самого CalAI, а
двухшрифтовая система (Unbounded+Onest) уже была авторским выбором владельца в принятом
прототипе пути. Задача явно указала взять типографику из прототипа — оставлено две семьи, это не
проглядели, а предпочли согласованность с уже принятым решением. Численный диапазон и
соотношение H1≈3.25×body из FR-LOOK-008 измерены на ДЕСКТОПНОМ лендинге источника; экраны
продукта — только телефонная ширина (PWA/Mini App), поэтому масштаб адаптирован под мобильную
карточку (кегль ккал 40px против body 15px, ≈2.7×) вместо буквального переноса десктопной шкалы.

## Доступность

Проверены расчётом (WCAG формула контраста), не на глаз: `--ink` на `--paper` 17.4:1,
`--ink-2` на `--paper`/`--paper-2` 5.35:1/4.82:1, `--dark-fg` на `--dark` 16.8:1, `--accent-ink`
на `--accent` 11.65:1, `--ok` (#1F7A48, НЕ прототипный `--mint`, у того было 3.8:1) на `--paper`
5.03:1, `--danger` (#B4432C, НЕ прототипный `--tomato`, у того 2.64:1) на `--danger-bg` 5.04:1 —
все ≥4.5:1. `--accent-deep`/`--accent` НЕ используются как текст на `--paper` (2.3:1/1.5:1),
только как бордер/крупный акцент. Выбор в плашке расхождения различим формой (заливка+галочка
против пунктирной обводки), не только цветом. `:focus-visible` — видимая обводка на всех
интерактивных элементах, отдельный светлый вариант для тёмных поверхностей.

## Непроверенное и почему

- **`npx vitest run --config vitest.integration.config.ts` целиком** (включая
  `public-card-page.test.ts`, конкурентные прогоны) — требует поднятого PostgreSQL профиля
  `test` (`docker compose --profile test run --rm test npm run test:integration`); в бюджет
  задачи (90 минут, только оформление) отдельный тестовый профиль не поднимал. Прогнаны ТОЧЕЧНО
  четыре файла из `tests/integration/`, которые правки этой задачи затрагивают напрямую и не
  требуют БД (см. таблицу прогонов). `public-card-page.test.ts` не гонялся — изменения в
  `route.ts` ограничены `<style>`/разметкой вокруg уже работающей логики (статусы, заголовки,
  `escapeHtml`), которую не трогал; риск считаю низким, но не подтверждённым прогоном.
- **Фото на экране результата (буквальное прочтение FR-LOOK-007 «фото с подписями
  ингредиентов»)** — `ScanResultResponse` (wire-контракт `apps/web/app/result/result-screen.tsx`)
  не несёт URL фото вовсе; добавление поля — это правка контракта API и серверного кода
  (`scan-pipeline`), а не оформления. Задача прямо запретила трогать поведение/серверный код —
  оставлено как названный пробел, не как забытое требование.
- Замер `≤1с`/`≤6с` (NFR-PERF) визуально на живом стенде не снимал — не в объёме задачи.

## Не тронуто

Серверный код, миграции, тесты логики, зависимости (обычный CSS, без Tailwind/UI-библиотек),
поведение компонентов — только `className` и разметка, необходимая для оформления (обёрточные
`<div>` для сетки кнопок в `consent`/`delete-data`). Профиль `edge` (Caddy) не останавливался.
