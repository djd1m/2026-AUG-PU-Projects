# Первый сквозной прогон на развёрнутом стенде — 2026-09-13

Стенд поднят профилем `edge`, все шесть сервисов канона здоровы. Проверка выполнена по адресу,
который ВЫДАЛО развёртывание (`http://127.0.0.1:4180`), а не по внутреннему адресу контейнера —
требование `deployment-seams.md` (страж №3): проверка обязана пользоваться тем, что система выдала.

Образы собраны впервые за проект: `api`, `recognizer`, `web`, `proxy` (последний — из исходников
с модулем ограничения частоты, DEC-A-021). Ревизия: см. коммит этого файла.

## Что НЕ проверено и почему — именно это, а не «всё зелёно»

1. **Статус `done` и числа из базы.** База продуктов ПУСТА: импорт USDA FoodData Central не
   выполнялся, потому что дампа на машине нет, а качать из сети в прогоне запрещено. Seed русских
   синонимов отверг все 100+ строк с причиной `unresolved_fdc_id` — он ссылается на записи, которых
   без импорта не существует. Поэтому наблюдаемый `failed(no_food_matched)` — ПРАВИЛЬНОЕ поведение
   (ADR-001: `done` обещает число из базы), но полный путь «фото → калории» показать нельзя.
   Действие владельца: положить дамп USDA и выполнить `npm run import:fdc`, затем
   `npm run seed:food-synonyms`.
2. **Живой вызов модели.** `ANTHROPIC_API_KEY` в окружении нет (DEC-A-009), работает
   детерминированный фейк. Прогон фейком живым смоуком НЕ объявляется.
3. **Вход через Telegram.** Токен бота на стенде синтаксически верный, но ФИКТИВНЫЙ: сервис
   приложения отказывался стартовать с прежним значением-заглушкой и назвал причину — fail-closed
   сработал как задумано. Проверить подпись `initData` против настоящего Telegram нельзя.
4. **Карточка и дневник с содержимым.** Обе поверхности требуют завершённого скана со статусом
   `done`, то есть упираются в пункт 1.
