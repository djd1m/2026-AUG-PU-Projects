# Поставщик модели: варианты и цена — решение владельца

Статус на 2026-09-13: стенд работает на детерминированном фейке (`N4_MODEL_PROVIDER=fake`),
живого распознавания не выполнялось ни разу (DEC-A-009). Ниже — три пути и то, чего каждый стоит.
Рекомендация: **вариант 1**.

## Что сейчас в коде

Адаптер живого поставщика написан под протокол Anthropic (`apps/recognizer/src/provider/live.ts`,
клиент `new Anthropic({ apiKey, maxRetries: 0 })`). Канон §6 закрепляет ДВЕ модели, и это числа
канона, а не переменные окружения (ADR-004):

| Роль | Модель | Когда зовётся |
|---|---|---|
| основной вызов | Claude Haiku 4.5 | всегда |
| эскалация | Claude Sonnet 5 | уверенность ниже 0,6 |

Потолки вызовов уже стоят и валят старт, если не заданы (ADR-007): 10 сканов на пользователя
в сутки, 3000 вызовов в сутки, 600 эскалаций в сутки.

## Цена сегодняшнего варианта

Тарифы из снимка `docs/development/telemetry/rates/2026-09-12-anthropic-codex.json`
(доллары за миллион токенов):

| Модель | Вход | Выход |
|---|---|---|
| Haiku 4.5 | 1 | 5 |
| Sonnet 5 | 2 | 10 |

Кадр нормализуется до 1568 пикселей по длинной стороне — это порядка 1500 входных токенов,
ответ по схеме короткий. Один скан на Haiku обходится примерно в 0,0015–0,002 доллара, тысяча
сканов — около двух долларов. При суточном потолке 3000 вызовов верхняя граница расхода — около
шести долларов в день, и это ПОТОЛОК, а не ожидание.

## Вариант 1 — оставить Haiku, отключить эскалацию (РЕКОМЕНДУЕТСЯ)

Эскалация вдвое дороже основного вызова и срабатывает на неуверенных кадрах. Отключение —
изменение потолка `N4_ESCALATION_LIMIT_DAY` на 0: счётчик эскалаций исчерпан с первого запроса,
скан завершается `done` с признаком `low_confidence`, а не падает (это уже реализовано, канон §7).

- **Стоимость работы:** ноль, одно число в `.env`.
- **Цена решения:** на сложных кадрах уверенность останется низкой, пользователь увидит пометку.
- **Откат:** вернуть прежнее число.

## Вариант 2 — второй адаптер под совместимый протокол OpenAI

Поставщиков с дешёвыми моделями зрения и протоколом, совместимым с OpenAI, много; конкретные
цены здесь НЕ приводятся намеренно — они меняются чаще, чем этот документ, и проверяются на сайте
поставщика в день подключения.

- **Стоимость работы:** около половины рабочего дня. Порт `ModelProvider` уже существует, писать
  надо ВТОРУЮ реализацию за ним плюс тесты; трогать вызывающий код не нужно.
- **Что обязано сохраниться:** JSON-схема ответа БЕЗ полей калорийности (страж ADR-001),
  проверка диапазонов в коде, счёт по ПОПЫТКАМ, а не по успехам, дедлайн и сигнал отмены.
- **Риск:** структурированный вывод у разных поставщиков ведёт себя по-разному; нарушение схемы
  обязано давать `failed(schema_violation)`, а не подстановку нулей.

## Вариант 2 подробно: OpenRouter — измеренные цены на 2026-09-13

Цены сняты в этот день запросом к `https://openrouter.ai/api/v1/models`, доллары за миллион
токенов. Они МЕНЯЮТСЯ — перед подключением снять заново той же командой, а не верить этой таблице.

| Модель | Вход | Выход | Схема ответа | Замечание |
|---|---|---|---|---|
| `openai/gpt-5-nano` | 0,05 | 0,40 | structured outputs | дешевле Haiku примерно в 20 раз по входу |
| `google/gemma-3-12b-it` | 0,05 | 0,15 | structured outputs | самый дешёвый по выходу |
| `google/gemini-2.5-flash-lite` | 0,10 | 0,40 | structured outputs | |
| `qwen/qwen3.7-flash` | 0,03 | 0,13 | только JSON-режим | схему придётся держать проверками в коде |
| `inclusionai/ling-3.0-flash-vl:free` | 0 | 0 | нет | бесплатно, но без гарантий доступности |
| `google/gemma-4-31b-it:free` | 0 | 0 | только JSON-режим | то же |
| **Claude Haiku 4.5 (сейчас)** | **1,00** | **5,00** | structured outputs | опорная точка |

Один скан — около 1500 входных токенов и короткий ответ. На Haiku это ≈ 0,0015 доллара,
на `gpt-5-nano` ≈ 0,0001. Тысяча сканов: два доллара против примерно десяти центов.

### Почему здесь дешёвая модель уместнее, чем обычно

Модель в этом продукте НЕ считает калории. Она называет ингредиенты и оценивает массу, а числа
берутся из базы (ADR-001). Ошибка дешёвой модели даёт неверный СОСТАВ, который пользователь правит
на экране результата, — а не неверные калории, выданные за измеренные. Это и делает экономию
осмысленной: цена ошибки здесь ниже, чем в задачах, где модель отвечает за само число.

### Что придётся сделать и чем заплатить

- **Работа:** вторая реализация за существующим портом `ModelProvider` (протокол OpenRouter
  совместим с OpenAI), плюс тесты. Порядка половины рабочего дня. Вызывающий код не трогается.
- **Обязано сохраниться:** JSON-схема БЕЗ полей калорийности (страж ADR-001), проверка диапазонов
  в коде, счёт по ПОПЫТКАМ, дедлайн и сигнал отмены. Модель без structured outputs допустима
  только с полной проверкой ответа в коде: нарушение схемы даёт `failed(schema_violation)`,
  а не подстановку нулей.
- **Граница персональных данных, и это НЕ мелочь:** фотографии еды в модели проекта — специальная
  категория ПДн (ADR-009). Сейчас они уходят одному названному обработчику. OpenRouter
  МАРШРУТИЗИРУЕТ запрос к стороннему поставщику, и список обработчиков становится переменным.
  Текст согласия (`2026-09-v1`) этого не описывает. Прежде чем включать, решение владельца:
  либо фиксировать конкретного поставщика и назвать его в тексте согласия, либо остаться
  у одного обработчика.
- **Бесплатные модели** подходят для пробы качества, но не для стенда, который кому-то показывают:
  у них лимиты и непредсказуемая доступность, а `fail-closed` превратит их отказ в `failed`.

## Статус на 2026-09-13 (после реализации): адаптер написан, ВЫКЛЮЧЕН по умолчанию

`apps/recognizer/src/provider/openrouter.ts` реализован — ТРЕТЬЯ реализация `ModelProvider`
(DEC-A-045, DEC-A-046). Роли канона не меняются: основной вызов и эскалация остаются теми же двумя
ролями §6, меняется только носитель, на котором роль исполняется, — отображение ролей на модели
задано КОДОМ, закрытым набором:

| Роль канона | Носитель (`live`, Anthropic) | Носитель (`openrouter`) |
|---|---|---|
| основной вызов | Claude Haiku 4.5 | `openai/gpt-5-nano` |
| эскалация (`confidence < 0,6`) | Claude Sonnet 5 | `openai/gpt-5-mini` |

По умолчанию `N4_MODEL_PROVIDER` остаётся `fake` — адаптер написан заранее и НЕ включён
(DEC-A-046): ничего не отправляется наружу, пока переключатель не тронут явно.

### Как включить

1. Получить ключ OpenRouter и записать его в `.env` этой машины (значения НЕ попадают в git):
   ```
   N4_MODEL_PROVIDER=openrouter
   OPENROUTER_API_KEY=<ключ>
   ```
2. Перезапустить `recognizer` (единственный сервис, читающий эти переменные):
   ```
   docker compose --profile app up -d --force-recreate recognizer
   ```
   `api` и `web` не трогаются — ключ им не нужен (`secrets-management.md`).
3. Проверить перед первым живым сканом:
   - `bash scripts/check-env-wiring.sh .` — 0 (переменная доезжает до сервиса);
   - `node ../../.claude/hooks/check-model-cost.cjs .` — 0 (потолки объявлены и способны отказать);
   - журнал `worker_started` в логе `recognizer` называет `provider: "openrouter"`, а не `fake`.
4. **Граница согласия — обязательный шаг ДО живых пользователей (DEC-A-046), не техническая
   формальность.** Текст согласия `2026-09-v1` называет обработку сервисом «Тарелка» и не называет
   стороннего обработчика; OpenRouter маршрутизирует запрос к переменному поставщику. Включать на
   реальном трафике можно только после ОДНОГО из двух: (а) новая версия текста согласия называет
   обработчика явно, либо (б) решение владельца зафиксировать одного конкретного поставщика
   OpenRouter и назвать его. До этого шага адаптер годится для тестового прогона на стенде без
   реальных пользовательских фото, но не для продакшна.

Откат — обратная операция: вернуть `N4_MODEL_PROVIDER=fake` (или `live`) в `.env` и повторить шаг 2.
