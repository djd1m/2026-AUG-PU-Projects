# Контракт встраиваемого виджета — N4 «Тарелка»

Дата: 2026-09-12. Правило: [`embeddable-widget.md`](../../../.claude/rules/embeddable-widget.md).
Проверка: `node ../../.claude/hooks/check-embed-contract.cjs .`

**Встраиваемый виджет:** нет

Продукт ничего не вставляет на чужие страницы. Поставляемое — два клиента на СВОЁМ origin: PWA за
Caddy и Telegram Mini App, которая исполняется в WebView Telegram по прямой ссылке, а не кодом на
сайте клиента. Публичная карточка `/c/{card_id}` — обычная страница нашего домена, открываемая по
ссылке, а не скрипт в чужой вёрстке.

## Ближайший сосед, который виджетом всё-таки НЕ является

Mini App живёт внутри чужого приложения, и это создаёт одно родственное обязательство — `Content-
Security-Policy` с `frame-ancestors` для доменов Telegram. Но остальные два класса отказа там
отсутствуют по построению: чужого CSS в WebView нет, а перекрёстного запроса нет потому, что фронт
и API живут на одном origin. Соответственно и оснастки «страница на чужом порту с враждебным CSS»
здесь проверять нечего.

Поэтому CSP Mini App записан как требование безопасности в
[`Architecture.md`](Architecture.md) §Security Architecture, а не как строка этого контракта:
объявить его здесь значило бы заявить проверку трёх классов, из которых два неприменимы.

## Когда ответ изменится

Если появится «бейдж калорийности для блога партнёра» или сборщик отзывов на сайте — этот файл
становится обязательным, и проверка обязана выполняться на странице ЧУЖОГО origin (достаточно
другого порта), отдающей ограничительный CSP и несущей враждебный CSS. Своя демо-страница проверкой
не является: на ней ни один из трёх классов отказа проявиться не может.

Код возврата проверки на этом файле — `2` («проверять нечего»), и это законный ответ. `2` никогда не
означает «всё в порядке».
