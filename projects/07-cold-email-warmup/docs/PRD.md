## 1. Executive Summary

### 1.1 Purpose

Грелка — веб-инструмент холодной email-рассылки: владелец подключает свои ящики по SMTP/IMAP,
ящики греются в общем пуле участников (сетевой эффект), продукт показывает доказуемое здоровье
домена и даёт безопасные кампании с ротацией ящиков и жёстким антиспам-контуром. Клон механики
Instantly с двумя отличиями: комплаенс by design (отписка/лимиты/стоп-лист/жалобы — ядро) и общий
пул прогрева с публичной агрегированной статистикой.

### 1.2 Scope

**In Scope (неделя 1 / MVP):**
- аккаунты, привязка домена с проверкой SPF/DKIM/DMARC по DNS
- подключение ящиков SMTP/IMAP (App Password), серверное шифрование секретов
- общий пул прогрева: вход по явному согласию, ramp 2 → +2, маркер прогрева в письме
- кампании: список адресов, цепочка шагов, шаблоны с переменными, ротация ящиков, дневные лимиты
- запуск кампании с явным отдельным согласием; автопауза по жалобе; стоп-лист глобальный
- отписка адресата (RFC 8058 + ссылка), обработка ≤ 48 ч
- health-дашборд: кривая score, доставляемость, спам-жалобы, история
- тарифы Free / Base / Pro, платёж: ЮKassa (₽) и Stripe ($)
- партнёрский код с атрибуцией до оплаты («кто привёл»)
- публичная страница статистики сети

**Out of Scope (не в этой неделе):**
- OAuth-подключения Google/Microsoft; AI-генерация и AI-ответы на входящие
- проверка валидности адресов; покупка доменов/ящиков внутри продукта
- CRM-интеграции, agent-воркспейсы, полный цикл партнёрских выплат
- мобильные клиенты; мультиязычный UI (RU + вход в USD — только два тарифных контура)

### 1.3 Definitions & Acronyms

| Term | Definition |
|------|------------|
| Прогрев (warmup) | контролируемая переписка ящиков участников сети для наращивания репутации домена |
| Общий пул | единое пространство ящиков всех участников; каждый участник согласился на прогрев-переписку |
| Ramp | дневной план наращивания отправок (2 письма в день, далее +2, с рандомизацией) |
| Health score | агрегат доставляемости/жалоб/авторизации по логике Postmaster Tools |
| RFC 8058 | стандарт одноклик-отписки: заголовки List-Unsubscribe(-Post) |
| Стоп-лист | глобальный список адресов и ролей (abuse@, postmaster@ и т.п.), куда кампании не пишут |

## 2. Product Vision

### 2.1 Vision Statement

> Холодный аутрич, который не сжигает домены: сеть ящиков греет друг друга, здоровье — доказуемо,
> антиспам-правила встроены, а не спрятаны.

### 2.2 Problem Statement

**Problem:** рассылка с нового домена летит в спам; продажи стоят, домен горит в фильтрах.
Существующие инструменты несносны по сборке: $37+ старт, скрытые аддоны, «unlimited» с
Fair Use-потолками и warmup-магия, которая с 2024–2025 не спасает (Gmail/Yahoo/Microsoft требуют
авторизацию, спам-рейт < 0,3 %, одноклик-отписку).

**Impact:** 58 % всех ответов приходит уже на первое письмо (брифе M1): письмо в спаме теряет
основную массу будущих ответов, а репутация домена после неудач восстанавливается неделями.

**Current Solutions:** Instantly ($37–358 flat), Smartlead ($39–379 + white-label $29/клиент),
Lemlist/Woodpecker/Reply.io (per-seat), RU-ESP (SendPulse/Unisender) — не cold email-инфраструктура.

### 2.3 Strategic Alignment

Проект N7 курса недели 0/7. Реализует постановку: MJ сегмент B2B-A-Sales; ядро — «веб-сервис с
живым экраном health + SMTP/IMAP», сетевой эффект — единственный подлинный из 8 проектов; вторичная
тактика — партнёрская (минимум). Стек наследует контейнеры и очередь курса (N5/N6-уроки).

### 2.4 Success Metrics

| Metric | Current | Target | Timeline | Источник значения |
|--------|---------|--------|----------|-------------------|
| Ящиков в общем пуле прогрева | 0 | 25 | неделя запуска | наша БД (pool_memberships) |
| Прирост пула (ящиков/день) | н/д | ≥ 3/день к концу недели | постоянно | наша БД (pool_memberships по дням) |
| conv% (визит лендинга → подключённый ящик) | н/д | ≥ 10 % | неделя 1–2 | наша БД (визиты + mailboxes) |
| Кампаний запущено с явным согласием | 0 | 10 | неделя 1–2 | наша БД (campaigns) |
| Спам-жалобы по кампаниям | н/д | < 0,3 % | постоянно | наша БД (complaint events) |
| Активных ящиков с верификацией | 0 | 20 | неделя 1 | наша БД (mailboxes) |

Метрики «прирост пула» и «conv%» инструментированы раздельно с первого релиза (FR-GROWTH-007 из
брифа; i/invites в сетевой петле отсутствует — вместо него прирост пула и коды партнёров).

## 3. Target Users

### 3.1 Primary Persona: соло-продавец (S1)

| Attribute | Description |
|-----------|-------------|
| **Role** | инди-основатель, консультант, фрилансер B2B |
| **Goals** | письма доходят в инбокс, домен не сжигается, цена старта < $20 |
| **Pain Points** | спам-фильтры, цена Instantly, непрозрачность «магии» прогрева |
| **Technical Proficiency** | Medium (умеет дать SMTP/IMAP App Password) |
| **Usage Frequency** | Daily (кампании) / Weekly (health) |

### 3.2 Secondary Persona: агентство/SDR-команда (S2)

канал, а не цель недели: десятки ящиков клиентов, flat-fee, партнёрский код, «кто привёл».

### 3.3 Anti-Personas

Спамеры массовых рассылок по «купленным» базам: платформа может быть нужна им технически, но
продуктовые потолки (fail-closed лимиты, стоп-лист, автопауза) сделаны против их паттернов; RU
рекламные письма без согласия адресата (ст. 18 38-ФЗ) продукт не легализует.

## 5. User Journeys

### 5.1 Journey: соло-продавец запускает рассылку

**Persona:** S1 · **Goal:** письма в инбокс · **Trigger:** «рассылка летит в спам»

```
Step 1: Подключение
  User Action: заходит, привязывает домен, добавляет ящик (SMTP/IMAP)
  System Response: DNS-проверки SPF/DKIM/DMARC, живое тестовое подключение ящика
  Next: Step 2
Step 2: Прогрев
  User Action: входит в общий пул (галочка-согласие)
  System Response: ящик включён в переписку сети, показывает ramp-план дня
  Next: Step 3
Step 3: Aha и рассылка
  User Action: видит рост health score, грузит список, собирает цепочку, запускает
  System Response: pre-flight (стоп-лист/квоты), письма с отпиской и ротацией, стоп при ответе
  Outcome: письма во входящих; health растёт
```

**Error Paths:** SMTP-ошибка → ящик в paused с диагнозом; DNS не сошёлся → блок запуска с текстом.

### 5.2 Journey: агентство подключает клиента

**Persona:** S2 · Trigger: клик партнёра · вход → код партнёра сохраняется ДО оплаты → кампании
клиентов с отдельными health-плашками; комиссия считается от фактической оплаты.

(не только цвет).

## 7. Release Strategy

### 7.1 MVP (неделя 1)

Всё из Scope In. Success Criteria: 25 ящиков в пуле; не менее 10 запущенных кампаний с явным
согласием; жалобы < 0,3 %; отписка обрабатывается ≤ 48 ч.

### 7.2 v1.0

Выплаты партнёрам (прогрессивный НДФЛ/НПД — урок N3), агентский воркспейс, white-label.

### 7.3 Future Phases

v2.0: OAuth-подключения (Google/Microsoft), проверка валидности адресов (не Promise: модель
показывает, что это рискованный рынок), marketplace pre-warmed доменов, Unibox.

## 9. Risks & Mitigations

| Risk ID | Description | Probability | Impact | Mitigation | Owner |
|---------|-------------|-------------|--------|------------|-------|
| R-001 | Пул на малой базе не греет (постановка) | High при пустом сиде | Critical | seed 25: когорта + dogfooding + выпускники; честная метка «сеть разогревается» | платформа |
| R-002 | Gmail/Workspace закрывает SMTP AUTH для части ящиков | Medium | High | диагноз подключения, текст-объяснение, план OAuth-фазы v2 | платформа |
| R-003 | Секреты SMTP/IMAP утечёт | Low | Critical | AES-256-GCM envelope, мастер-ключ в env, аудит-лог, TLS к SMTP | платформа |
| R-004 | RU рекламные письма без согласия | Medium | High (ФАС/КоАП 14.3) | предупреждение, стоп-лист, отписка; равноправно в RU и юр. дисклеймер | владелец кампании |
| R-005 | «Абьюзер» на платформе (новый аккаунт, большой объём) | Medium | High | fail-closed потолки, аккаунт/день, автопауза жалоб, E2E-порог < 0,3 % | платформа |
| R-006 | Ответы содержат ПДн адресатов | Medium | Medium | хранение только метаданных ответа, доступ владельца к своему контенту | платформа |
