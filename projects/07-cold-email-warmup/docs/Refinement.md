| Scenario | Input | Expected | Handling |
|---|---|---|---|

| CSV 100 000 строк | максимум объёма тарифа | стриминговая обработка, не OOM | поток через очередь, прогресс; лимит по тарифу |
| Две попытки запуска одновременно | двойной клик launch | один consent, один запуск | 409 на второй; lock по campaign_id |
| SMTP-таймаут ящика | свисающий сокет | fail-closed: ящик paused, слоты перераспределены | MB-210, diag записан, остальное уходит через другой ящик |

| Пул опустел (все вышли) | 0 участников | плана нет, honest-метка «сеть разогревается» | SC-US-004-3 правило, пустой day |
| Валидация ответа webhook не удалась | malformed JSON | 400, record лог, retry провайдера | BL-410 |
| Если план зоны домена меняется после запуска | DNS стал fail | новые слоты блокируются с сообщением, старые — сработали | pre-flight зазора нет: health показывает warn |

## Testing Strategy

- **Unit (Vitest):** все 20 алгоритмов Pseudocode как чистые функции с инъекцией клиентов; критические пути — планировщик, стоп-лист, идемпотентность, конверт секретов, атрибуция. Coverage ≥ 80 % пакетов worker/api.
- **Integration (Testcontainers):** Postgres 16 + Redis 7.4 поднимать в точных версиях. Сценарии: launch → слоты → dispatch (fake SMTP через greenmail-like контейнер); отписка → стоп-лист; вебхуки (подписи + дедуп); квоты тарифов.
- **E2E (Playwright, web):** путь S1 из PRD §5.1: регистрация → confirm → домен (заглушка DNS через локальный резолвер? — DNS-проверки замещаются фейк-резолвером в тест-профиле) → ящик (фейковый SMTP/IMAP контейнер) → пул → кампания → запуск; путь отказов: DKIM-warn → блок.
- **Performance (k6):** API-эндпоинты 50 VU 5 мин — p99 ≤ 500 мс (NFR-PERF-001); очередь 1000 слотов — 95 % в окне (NFR-PERF-002).
- **Безопасность:** попытки доступа других аккаунтов к чужим ресурсам (403-матрица), тест секретов (запрет plaintext в логах — grep по логам в CI).

## Performance Optimizations

- Расписания слотов — батчами (INSERT ... ON CONFLICT), индекс send_log (campaign_id, slot_at).
- Индексы: stoplist_entry.address (unique), send_log.idempotency_key (unique), send_log(campaign_id, recipient_id).
- Кэш DNS-статусов домена (TTL 1 ч) — резолвер вызывается по требованию и при cron-перепроверке 6 ч.
- IMAP-poll адаптивный: idle у поддерживающих, интервал у остальных.

## Security Hardening

- Без plaintext секретов в логах (CI-gate: логи старта на матч /\$\{...password|secret/).
- Rate limit + burst; запросы чужих user_id → 403 c записью в аудит.
- Вебхуки: ЮKassa — IP-сети + перезапрос статуса (паттерн донора N1); Stripe — верификация подписи.
- Заголовки безопасности API: HSTS, CSP для SPA, Caddy auto-HTTPS.
- Аргон2id с курсовыми параметрами; lockout после 5 неудач на 15 мин.

## Accessibility

- Клавиатурные пути: вход/регистрация, запуск (confirm-модалки с фокус-трапом).
- Цвет не единственный носитель статуса (иконка+текст: verified/paused).
- Контраст AA по фолбэк-палитре Slate/Orange.

## Technical Debt (осознанные упрощения MVP)

- IMAP-поллер болл-опотом, не IDLE-only (успех приоритетен) → v1.0 IDLE.
- Инбокс-тест не в MVP: health из SMTP-событий (документировано) → v1.0.
- Партнёрские выплаты — read-only в MVP; полный цикл — v1.0 с налоговыми удержаниями N3-уроков.
- DNS-селектор DKIM захардкожен default._domainkey → конфигурируемой переменной (v1.0).
