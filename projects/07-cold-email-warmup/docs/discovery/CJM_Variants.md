## Общее ядро (одинаково во всех вариантах)

Владелец подключает свои ящики по SMTP/IMAP (без OAuth в MVP — постановка) → ящики включаются в
**общий пул прогрева** (переписка между ящиками участников; вход в пул — явное отдельное согласие
получать прогрев-переписку, иначе пул сам становится источником спама) → видит health-дашборд своей
репутации → через 2–3 недели запускает цепочку: персонализация по полям списка, ротация ящиков,
лимиты писем в день, отслеживание ответов, остановка цепочки при ответе. Незыблемое (@security,
NON-NEGOTIABLE постановки): отписка в каждом письме (List-Unsubscribe, RFC 8058, один клик),
лимиты отправки на ящик/день, глобальный стоп-лист (включая роли abuse@/postmaster@), обработка
жалоб с автопаузой кампании, любое действие от имени владельца — только после явного отдельного
согласия при запуске. НЕ входит в неделю: OAuth-подключения, AI-ответы на входящие, проверка
валидности адресов, покупка доменов/ящиков внутри продукта, CRM-интеграции.

У всех вариантов один ориентир момента ценности из постановки: **пользователь увидел, что репутация
его домена выросла**.

Варианты РАЗЛИЧАЮТСЯ growth-петлёй, а не интерфейсом.

| | A — «Общая сеть» | B — «Агентская станция» | C — «Здоровый домен на витрине» |
|---|---|---|---|
| **Growth loop** | **network effect** (постановка): каждый подключённый ящик усиливает общий пул; ценность растёт с числом участников само по себе | **incentivized referral**: агентства подключают кампании клиентов; партнёрский код ведёт к выплате процента от платежа клиента | **content-driven**: владелец делится карточкой-снапшотом здоровья домена; аудитория видит наш бренд в карточке |
| **Aha Moment** | кривая health score пошла вверх и в дашборде видно «ящик переписывается с N участников сети» — сеть работает и без моих усилий | агентство увидило health-дашборды всех кампаний клиентов в одном кабинете и счёт партнёрского кода, который копится до первой оплаты | владелец выложил снапшот «SPF/DKIM/DMARC в порядке, жалоб 0,0x %» — аудитория спросила «чем делаешь?» |
| **Entry Hook** | S1: «рассылка с нового домена летит в спам, продажи стоят»; S4: участник когорты — прогрев нужен позарез | S2: агентство платит per-seat за каждый клиентский ящик в оригинальных сервисах и держит десятки ящиков | S1: нужно доказать заказчику или боссу, что рассылка в порядке |
| **Onboarding → Core Loop → Paywall** | подключение домена и ящиков → галочка «войти в общий пул» → прогрев включён → дашборд health → кривая растёт → «готов к рассылке» → список + цепочка → первый запуск с явным согласием → paywall: лимит Free исчерпан → на платных — больше ящиков и объём отправки | вход агентства → ящик клиента подключён → кампании по коду партнёра → все health-дашборды клиентов в одном экране → счёт кода партнёра растёт до оплаты клиента → выплата — вторая неделя | подключение → первый health-отчёт → «экспортируй снапшот» (карточка) → шеринг → CTA на карточке ведёт на лендинг → paywall: частые снапшоты и история health — платно |
| **Как ложатся FR-GROWTH-001..004** | 001: дашборд health = момент ценности, показывается ровно там; 003: бейдж только на публичных поверхностях (в письмах его быть не может — ломает deliverability, [F] правила T2); 002/004: партнёрский код + атрибуция до оплаты | 004 — ядро: код агентства + кабинет по кампаниям; 002: атрибуция клиента агентству до оплаты; 003: бренд агентства на клиентском экране — только платно; 001: health-момент внутри кампании клиента | 001: кнопка «экспортировать снапшот» ровно в момент, когда health вырос; 003: «Powered by» на снапшоте, снятие — платно; 002/004: партнёрский код в ссылке-CTA снапшота |
| **Микро-тренды** | T1, T2, T4 | T1, T2, T3 | T2, T4 |
| **Метрика недели** | **число ящиков в общем пуле прогрева** (метрика постановки); **утверждено владельцем: 25** | агентств-партнёров с ≥ 2 активными кампаниями — цель 3 | чистых снапшотов, экспортированных наружу — цель 10 |
| **Главный риск** | критический по постановке: network effect не работает на малой базе — до критической массы пула прогрев держится на seed-ящиках (когорта курса + dogfooding), aha без массы не наступает; seed-стратегия с первого дня — архитектурное решение | цикл продажи агентству длиннее недели; «unlimited» у аналогов ограничен Fair Use — у себя закладывать настоящие потолки честнее, чем слово «unlimited»; выплаты физлицам — прогрессивный НДФЛ (урок N3) | виральность предполагает, что у владельца есть аудитория; privacy: снапшот показывает домен клиента — публиковать может только сам владелец; наш бренд в чужих постах контролировать нельзя |

## Сравнение и рекомендация

- **Сильнейший вариант — A.** Постановка документально фиксирует network effect основным loop:
  «единственный подлинный из всех 8 проектов», но и самое жёсткое следствие —
  «network effect НЕ РАБОТАЕТ при малой базе», и это архитектурное решение, а не маркетинг.
- **B** реализует постановку FR-GROWTH-002/004 (партнёрская — «стандартный канал в этой нише у всех
  аналогов») как второй мотор, но продажа агентству длиннее недели.
- **C** почти не требует кода, но виральность предполагает, что у владельца есть аудитория,
  а общий пул (ядро продукта) всё равно нужен всем трём вариантам.

**Рекомендованный гибрид H: ядро A + партнёрский минимум из B.** Партнёрский минимум = персональный
код партнёра + атрибуция до оплаты + поле «кто привёл» в кабинете; выплата — только от фактической
оплаты приведённого клиента. Без агентского воркспейса и без полного цикла выплат — они выходят за
рамки недели. Резон: вторичная тактика постановки — партнёрка («максимум одна, без нового кода» —
код партнёра и так обязателен FR-GROWTH-002/004), а шеринг снапшотов C — третья механика, которая
не влезает в недельный объём. Отвергнутые варианты остаются выше с полными описаниями и своими рисками.
