# ADR — Грелка (N7)

Дата: 2026-10-07. Нумерация сквозная; отказ от решения фиксируется словами «отклонено» + причина.

## AD-001: Разделённый монолит (Fastify + workers на общей БД), не микросервисы

**Контекст:** неделя 1, один VPS, очереди SMTP-отправок и IMAP-поллинга.
**Решение:** единая кодовая база: apps/api + apps/worker-* контейнеры, состояние в PostgreSQL/Redis
(BullMQ — донор N6 packages/queue). Роли разделены для изоляции ретраев.
**Отклонено:** микросервисы (цена деплоя/наблюдаемости не окупится на неделе); serverless
(SMTP-долгие коннекции не дружат с холодными стартами).

## AD-002: Секреты SMTP/IMAP — серверный AES-256-GCM envelope

**Контекст:** пароли ящиков нужны СЕРВЕРУ (отправка/чтение) — client-side паттерн N5 неприменим.
**Решение:** data_key случайный → шифр секрета; wrapped_key ← мастер-ключ env (KEK); доступ к
расшифровке только у worker-контура; аудит секретов; plaintext никогда не логируется.
**Отклонено:** просто KMS-облачный (внешняя зависимость и оплата ради первого релиза).

## AD-003: Единый общий пул (глобальная сущность) + публичная агрегированная статистика

**Контекст:** сетевой эффект — постановка; изоляция пула по аккаунту разрушила бы сеть.
**Решение:** pool_membership — единая таблица по платформе; вход по явному согласию (запись текста
+ версии); публичная /pool — агрегаты (size, суммарный прогресс) без доменов/личных данных.
**Отклонено:** приватные пулы на тарифах — фрагментирует сеть и убивает эффект недели; пересмотр
в v1.0 как «комнаты агентств» — отдельным ADR, если попросит владелец.

## AD-004: Fastify + React/Vite + Vitest/Playwright

**Контекст:** AI-исполнители недели; минимизировать магию и число слоёв.
**Решение:** Fastify (Node 20, TS, Zod), React+Vite SPA, Vitest + Testcontainers, Playwright E2E.
**Отклонено:** NestJS/Nuxt/Next (слой декораторов/SSR не нужен курсовой неделе; сложнее держать
Pseudocode↔код соответствие).

## AD-005: Идемпотентная отправка (at-most-once письмо) с TLS-only SMTP

**Контекст:** ретраи очереди и дубли писем — прямой путь жалоб.
**Решение:** idempotency_key (unique в send_log/warmup_pair) + Redis lock; TLS-only (465/587),
plain запрещён fail-closed; ретраи только по сетевым кодам.
**Отклонено:** at-least-once «с dedup на стороне провайдера» — провайдеры дедуп не дают.

## AD-006: Платежи — универсальный интерфейс BillingProvider (ЮKassa ₽ / Stripe $)

**Контекст:** контур RU+мир (решение владельца), курс-доноры по ЮKassa есть, по Stripe нет.
**Решение:** интерфейс checkout/status/webhook; ЮKassa — порт донора N1 payment.ts (IP-сети +
перезапрос статуса, т.к. ЮKassa не подписывает вебхуки — комментарий донора); Stripe — Subscription
+ верификация подписи (цитаты доков 2026-10-07 в Architecture).
**Отклонено:** один провайдер на оба контура (юр- и карта-ограничения RU/мир).

## Следствия и ограничения

- AD-003 требует мониторинг «abuse в пуле»: маркеры, отписка, лимиты — уже обязательны (FR-SEC-*).
- AD-004 фиксирует стек; правки — новый ADR, старые не переписываем (append-only).
- Все решения проверяемы в Phase 2 (рой валидации), несогласные строки — с цитатой или [H].
