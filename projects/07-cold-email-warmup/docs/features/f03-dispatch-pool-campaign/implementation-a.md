# F03a implementation handoff

Scope: AC-A1..A6 only; whole F03 pending F03b and independent review. Campaign list/read/edit/preview/start/pause use session-derived tenants and the existing Origin gate. Existing F02 content, version and sorted recipient fingerprint remain authoritative; migration003 backfills one legacy plain-text step. New step input uses subject/body/delayHours and recipient address/fields. Allowed fields are firstName, lastName, company. Entire snapshot validates before jobs. Five steps,100 recipients,24-hour minimum; no source markup, missing fields or header CRLF. Preview escapes dynamic values; jobs store plain subject/body without address.

Campaign start requires affirmative current F02 consents for every selected owned mailbox. Unique enrollment version+digest and campaign+enrollment+step keys provide durable replay protection. Pause cancels queued/claimed; explicit restart of paused campaigns requeues eligible canceled steps of the same version only. Edits atomically invalidate consent, enrollment and jobs on the shared eligibility transaction.

Enrollment recipient_envelope reuses F02 versioned AES-GCM with purpose-prefixed tenant AAD `n7-enrollment-v1:<tenant>` and enrollment ID. This cannot authenticate a credential-domain envelope. Recipient HMAC uses external RECIPIENT_HASH_KEY_FILE, canonical base64 >=32bytes, distinct from session and every credential key; startup fails closed. F02 owned campaign contact snapshot remains unchanged, while enrollment addresses are encrypted; no plaintext address in the queue.

PoolStore.aggregate returns only count/status, with fresh complete polls (0<=age<60s), verified_test local eligibility, non-quarantined current opt-in and distinct tenants. tick chooses deterministic distinct tenants, stable unorderedpair/UTCday and neutral test content. It creates one initial and one unique reply only after a submitted initial fixture/state. Submitted replies cannot become parents. No directory route exists.

DispatchStore.claim uses the exact F02 eligibilityTransaction, whose first operation after BEGIN is lock(7,1), then SKIP LOCKED. Common queue reservation counts claimed/submitting/submitted/unknown jobs with reserved_day; quota=min(user,provider,30), default user10. Sender order rotates by last claim. Expired claimed leases requeue and clear their token before a new claim, under that same transaction. Submitting/unknown never recover. Lease is45s. Claim has no adapter reference and provides no transport authority.

R1 correction: forward-only migration004 adds nullable send_job.claim_order and its owned bigint sequence. Every successful claim assigns nextval under the existing lock; selection uses each sender's maximum claim_order, independent of equal caller timestamps. Sequence gaps are harmless. Pre004 jobs have null order and receive ordering history on their next claim; historical timestamps are not rewritten. Reclaims advance order as well. claimed_at, lease and polling freshness still use the caller's real clock seam. F03b must use migration005 next and retain claim_order history during final state transitions.

Reservation accounting choice: transactionally derive reservations from send_job instead of a separate counter. Migration003 central release_cancelled_reservation trigger clears reservation and lease on every queued/claimed cancellation, including unchanged F02 mailbox/consent writers. Irreversible states retain conservative charges; future F03b final transition must move UTC-day tokens and preserve this rule.

Durable F04 seams: enrollment(id,tenant,campaign_version,recipient_hash,state), suppression(tenant,recipient_hash), mailbox_poll(completed_at,scan_complete,uidvalidity,cursor_uid), send_job.message_id. DispatchSeams.recordPoll/stopEnrollment/suppress serialize on lock(7,1); they are internal, never user routes. Only tests inject complete local polling evidence. Production has no IMAP poll producer yet and therefore remains blocked without genuine evidence.

F03b owns final claimed→submitting, final current guards/day rollover, local sink, transport outcomes/retries and actual message IDs. F04 owns actual poll/reply ingestion and unsubscribe. F06 owns cabinet UI/browser. None is implemented or tested by this slice. Test fixtures setting submitted are planning tests, not actual submission claims.
