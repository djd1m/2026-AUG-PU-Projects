**R1 — P2: reserved IPv6 addresses pass the public-address gate.**

Location: `src/mailboxes/network.ts:23` (consumed by `resolveEndpoint` at line39). Violated requirement: AC-F02-3 explicitly requires rejection of reserved addresses and mixed unsafe DNS answers; the inherited identity algorithm requires public-address validation before connection.

The predicate treats almost all of `2000::/3` as public. It accepts `2d00::1`, `3000::1`, `3800::1`, and `3ffe::1`, although their prefixes are explicitly RESERVED in the [IANA IPv6 Global Unicast Address Space registry](https://www.iana.org/assignments/ipv6-unicast-address-assignments), last updated 2025-10-10. This is a source defect, not merely missing test evidence.

Realistic trigger: an operator-allowlisted hostname has a stale, erroneous, or hostile AAAA answer in one of these reserved ranges, either alone or alongside a valid public answer. Save-time validation admits it; connection-time revalidation also admits it. A read-only check in the existing Node22 n7f02 container reproduced both `[3ffe::1]` and `[8.8.8.8, 3ffe::1]`: `verifyTest` returned `verified_test`, with two adapter calls in each case. The required result is `unsafe_address` with zero adapter calls. The injected resolver and adapter performed no network connection and used only synthetic fixture credentials.

Impact: the promised public-only and mixed-answer rejection boundary is bypassed, and verification claims a test pass for an unsafe resolution. No live SMTP exploit or credential exfiltration is claimed: this implementation activates only the explicitly labelled test adapter. The safety failure already exists in the F02 connector contract and must be corrected before acceptance.

Minimal required correction: make the IPv6 predicate reject IANA-reserved/unallocated space inside `2000::/3`, including the reproduced ranges; retain the existing special-use exclusions and public positive controls. Add focused regression assertions for reserved-only and mixed public/reserved answers, proving rejection before any adapter call. Rerun the affected unit/mutation checks and required F02/F01 regression and build gates against the corrected source; a new live connector, dispatch implementation, or UI is not required. Evidence: `docs/telemetry/features/20261002T201500Z-f02/evidence/astra-reserved-ip-check.json` and `astra-reserved-ranges.json`, containing exact scripts and observed results.
