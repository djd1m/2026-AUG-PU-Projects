# F04a — trusted durable reply store

Scope: AC-A1..A6 only. Public unsubscribe, complaints, protocol adapter and poll worker belong to F04b. Entire F04 requires both implementations and fresh independent reviews. Authority OWN-N7-002; no real SMTP/IMAP, deployment or charge.

`src/replies/input.ts` bounds pages to 100 headers, 8192 aggregate UTF-8 bytes per header, 50 total References/In-Reply-To IDs, 254 bytes per normalized Message-ID and unsigned IMAP 32-bit identifiers. Header objects reject extra fields, including bodies. Sender must be a single normalized address; Message-ID local part remains opaque and case-sensitive, domain is lowercased. Incoming Message-ID is optional: malformed or absent IDs never suppress matching by own references and exact decrypted enrollment recipient. Subject is not accepted or matched.

Migration 006 adds physical observations `(mailbox, UIDVALIDITY, UID)`, an additional valid incoming-ID ledger `(mailbox, Message-ID)`, immutable application-written semantic events `(mailbox, enrollment, reply)`, and current durable rescan state. Every mutation takes `eligibilityTransaction` lock(7,1) first. The exported client-level `stopEnrollmentClient` shares this transaction; existing DispatchSeams wrappers remain available. Only a newly inserted effect calls the helper. It marks active enrollment replied and cancels queued/claimed jobs; submitting work retains the accepted F03 in-flight contract.

Observations, ID ledger, effects, enrollment/cancellation, cursor, page count and completion evidence commit together. Test-only beforeCommit and afterCommit hooks distinguish rollback from committed crash. Concurrent or stale pages fail run/attempt/validity/cursor validation before writes. No protocol operation occurs under a database lock.

## F04b handoff API

Construct `new ReplyStore(pool, credentialKeyring)` inside the trusted operator worker. No HTTP route accepts this API's evidence. The reader must obtain actual header-only coverage before calling the store; provenance `local_fixture` is explicit fixture evidence and makes no real IMAP claim.

1. `capture(tenant, mailbox, {uidvalidity, uidNext, observedAt, provenance})` creates initial/reset run with fixed H=UIDNEXT−1 and cursor0. Unfinished same-validity work retains run/H/cursor/attempt after restart. After a completed same-validity poll, a new bounded incremental run begins at its committed cursor. A changed validity always starts at zero, superseding all prior callbacks. Capture pauses via `mailbox_poll.scan_complete=false`; mailbox quarantine, consent and operational state are untouched.
2. `status(tenant, mailbox)` returns runId, attempt, validity, H, tailHighWater (null until captured), cursor, state, pages and attemptStartedAt. Keep these fields with each independently fetched page. This tenant-scoped result contains no headers, recipients or credentials.
3. `page(tenant, mailbox, {runId, attempt, uidvalidity, expectedCursor, coveredThrough, kind, tailHighWater, headers, startedAt, completedAt})` accepts explicit trusted range coverage. Scan coverage must increase and stay at/below fixed H. All header UIDs must be unique and within `(expectedCursor, coveredThrough]`. Sparse, empty and expunged ranges are valid coverage. Tail is allowed only once cursor covers H and requires an explicit trusted same-validity `tailHighWater=UIDNEXT−1` snapshot, at least the current cursor. Migration 007 adds its durable nullable column; 006 remains unchanged. The first accepted tail page captures this horizon; every subsequent page in that run (including retry) must supply the same value. Coverage cannot exceed it. Partial, empty or sparse prefixes advance durable progress while scan_complete remains false; header count never proves completion. Equal coverage completes only when tailHighWater equals the cursor. The trusted reader must attest full coverage through coveredThrough, including gaps, under the same selected UIDVALIDITY.
4. Operation evidence must be successful, <=30s duration, nonfuture, and <=30s old at the actual post-lock clock. Each attempt allows <=20 total pages (including tail), <=100 headers/page, and elapsed strictly below120s. The twentieth unfinished page or expired/future clock persists `rescan_incomplete`. A failed tail must call `failTail` with current run identity; it cannot clear the pause. Throwing before a successful page is supplied never supplies completion evidence.
5. Only successful tail coverage reaching the captured tailHighWater completes. Tail horizon, effects, progress and completion commit together and set completed_at to the post-lock clock. Page progress preserves prior timestamp and leaves scan_complete=false. Existing F03 guards continue requiring complete evidence with age<60s and reject future timestamps.
6. Operator-only explicit `retry(tenant, mailbox, currentIdentity)` continues an incomplete run with the same H/run/cursor/tailHighWater, increments attempt, resets pages/start only. Crash restart uses capture/status and does not call retry automatically. Old attempt callbacks fail after retry. F04b must enforce operator authority outside this internal API.

If the worker cannot trust coverage, validity or a successful tail, it must remain paused. There is no fixture HTTP freshness endpoint. Initial empty inbox completion requires explicit trusted local fixture evidence; live protocol authorization and implementation are separate work.
