# N7: VM-провайдеры для существующих Gmail/Yandex через SMTP + IMAP

Проверено 2026-10-08 по официальным источникам. Сценарий: постоянно работающий Linux worker подключается к существующим ящикам с аутентификацией; собственный MTA и исходящий порт 25 не требуются. Цены отдельных инстансов не исследовались.

**Короткий список: Vultr Compute и Google Compute Engine.** Оба прямо документируют доступность исходящего SMTP на **465 и 587**. Для IMAP 993 уверенность основана на документированной общей политике исходящего трафика, а не на специальном обещании работоспособности Gmail/Yandex из любой зоны. Новые VM не создавались; соединения из этих провайдеров не измерялись. GCP имеет подтверждённое ограничение новых регистраций из России; shortlist технический и условен относительно доступности аккаунта/оплаты.

**Заявки и исключения.** GCP снимает 25 автоматически по оценке риска; в проверенном источнике нет гарантированного support-процесса снятия. AWS требует request с регионом, use case и планом предотвращения нежелательной отправки; Elastic IP/rDNS могут быть включены, approval не гарантирован. [AWS request](https://repost.aws/knowledge-center/ec2-port-25-throttle). Azure qualified Enterprise Dev/Test снимает блок через Diagnose and Solve; exemption относится к subscription и трафику VM directly to internet, затем stop/deallocate/start. Для обычных подписок проверенная статья не предлагает такое освобождение. Vultr support ticket: use case, SPF/DKIM/rate limits, объём; case-by-case. Hetzner: минимум месяц пользования, оплачен первый invoice, limit request с valid use case, case-by-case; до этого 465 не считать доступным. OVH regular VPS: support request для 25; требования approval не раскрыты в FAQ. OVH Local Zones исключений не имеют. Для N7 на разрешённых 465/587 заявки на 25 не нужны.

**Регион и аккаунт.** GCP/AWS/Vultr/Hetzner проверенные SMTP-политики описаны на уровне платформы/аккаунта, без перечисления исключений по обычным регионам; это не измерение доступности отдельной зоны. Azure различает subscription types. OVH explicitly различает Local Zones и обычные VPS. OVH VPS policy нельзя автоматически переносить на Public Cloud, dedicated servers или другой юридический storefront.

**Регистрация/оплата.** GCP официальная текущая billing-country таблица сообщает о приостановке новых account signups для пользователей в России с 2022-03-10: [Cloud Billing currencies](https://docs.cloud.google.com/billing/docs/resources/currency). AWS официально объявил прекращение новых Russia/Belarus-based AWS signups 2022-03-08; актуальная допустимость конкретного existing account этим объявлением не устанавливается: [Amazon announcement](https://www.aboutamazon.com/news/aws/updates-to-amazons-retail-entertainment-and-aws-businesses-in-russia-and-belarus). Microsoft объявил остановку новых продаж в России в марте 2022; статья не заменяет account-specific проверку Azure: [Microsoft announcement](https://blogs.microsoft.com/on-the-issues/2022/03/04/microsoft-suspends-russia-sales-ukraine-conflict/). Vultr перечисляет credit card, PayPal, crypto, Alipay, wire transfer, gift code; это **не подтверждает** доступность регистрации из России или пригодность российского платёжного средства: [Vultr payment methods](https://docs.vultr.com/platform/billing/make-account-payments). Для Hetzner/Vultr/OVH официального общего разрешения либо запрета новых российских регистраций в этом ограниченном исследовании не установлено. Hetzner может требовать identity verification: [Fraud prevention FAQ](https://docs.hetzner.com/general/security-and-identify/fraud-prevention-faq/).

**Практический выбор.** Начинать с Vultr при подтверждённой допустимой регистрации/оплате; GCP — второй кандидат при уже доступном допустимом billing account или допустимой новой регистрации. AWS — технический запасной вариант. Hetzner требует изменения N7 на 587, если текущие Yandex-настройки используют 465. Официальные consumer-настройки Yandex подтверждают 465/SSL либо 587 при начале соединения без шифрования (далее требуется STARTTLS в клиенте), и IMAP 993; для подключения не из России они также предлагают imap.ya.ru. Это делает Hetzner реальным вариантом для режима 587, после проверки TLS-настроек N7 и endpoints выбранной VM. [Yandex clients](https://yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/others), [Gmail protocol endpoints](https://developers.google.com/workspace/gmail/imap/imap-smtp).

Минимальная VM должна обеспечивать постоянно работающий worker, стабильное хранение очереди/состояния, перезапуск процесса и исходящий DNS/HTTPS плюс выбранный SMTP и IMAP. Это архитектурная оценка, не результат испытаний N7 на каждом сервисе. Новые инфраструктурные сервисы, mail relay/MTA и перенос почтовых ящиков не нужны.

**Проверка как данные для будущего согласованного теста (не выполнялась).** После разрешённого создания VM зафиксировать provider/product/region, account policy, UTC, DNS A/AAAA, source IPv4/IPv6, timeout и TLS verification отдельно для smtp.gmail.com:465/587, imap.gmail.com:993 и фактических Yandex endpoints N7 (например smtp.yandex.ru:465 и imap.yandex.ru:993). Полезны TLS handshake + SMTP EHLO/STARTTLS и IMAP greeting/CAPABILITY с обязательной проверкой сертификата. Это подтверждает сетевую доступность, но не AUTH, отправку или доставку. Ошибки handshake/timeout отдельно от authentication failures. Аутентификацию и E2E при необходимости проводить только с уже разрешёнными credentials и действиями; этот исследовательский проход не отправлял сообщений и не читал почту.
