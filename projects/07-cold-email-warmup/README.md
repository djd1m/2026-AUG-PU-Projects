# 07. Cold email с прогревом доменов

> **Неделя 07** · `аутрич` · референс: **[Instantly.ai](https://instantly.ai/) ($40M+ ARR) и [Smartlead](https://www.smartlead.ai/)**

## Простыми словами

**Проблема.** Вы пишете потенциальным клиентам первым. Но если рассылать с нового адреса, почта
считает вас спамером, и письма не доходят — они падают в спам ещё до того, как их кто-то увидит.

**Что делает продукт.** Сначала «прогревает» ваши почтовые ящики: они некоторое время
переписываются с другими ящиками системы, и почтовые сервисы начинают считать адрес нормальным,
живым. Потом рассылка идёт не с одного ящика, а распределяется между несколькими, небольшими
порциями — как пишет человек, а не робот. Письма подставляют имя и детали получателя, а когда
человек отвечает, цепочка для него автоматически останавливается.

**Зачем это людям.** Малому бизнесу и продажам, у которых нет бюджета на рекламу, но есть понимание,
кому именно они полезны.

**Одна честная деталь.** В каждом письме — способ отписаться, и есть стоп-лист. Разница между
рассылкой и спамом в том, уважают ли ваш отказ.

**Как этим пользуются.** Подключили ящики → две недели прогрева → загрузили список →
запустили цепочку → отвечаете тем, кто откликнулся.

## Что делаем

Неограниченные ящики, авто-прогрев доменов, ротация ящиков, персонализация, AI-ответ быстрее пяти минут, цепочки в n8n.

**Целевой стек:** ротация ящиков, персонализация, цепочки как сервис compose

## Локальный запуск F01

Реализована основа авторизации: регистрация, вход, выход и изоляция арендаторов.
Регистрация не даёт согласия на отправку. Подключение почты, кабинет, рассылка и
оплата относятся к следующим фичам.

Из каталога проекта:

```bash
bash scripts/local-runtime.sh
bash ../../scripts/check-port-conflicts.sh .
docker compose up -d --build --wait
```

Откройте `http://127.0.0.1:18701`. Внешние зависимости: Docker Compose, Node22 для
локальных npm-команд. PostgreSQL16 доступен только в сети `n7f01_network`; том
`n7f01_pg` сохраняет данные. Не удаляйте том для обычного перезапуска. Ключи и пароль
создаются один раз в `/tmp/n7-f01-runtime`; значения не печатаются. Сохраните файлы
для перезапуска: смена HMAC-ключа аннулирует старые сессии, а смена пароля требует
отдельного обновления PostgreSQL. Для другого порта задайте вместе `N7_WEB_PORT`
и `N7_APP_ORIGIN`; перед запуском снова проверьте конфликты.

`GET /healthz` и `/readyz` возвращают200 только при доступной БД с миграцией1.
API: `POST /api/auth/register|login|logout`, `GET /api/auth/me`. Все POST требуют
точный `Origin`, JSON и ограниченное тело. `GET /api/mailboxes/:uuid` читает только
собственные минимальные метаданные; создание/подключение ящика относится к F02.
Сессия в HttpOnly/SameSite=Lax cookie действует7дней, отзыв хранится в БД.

Проверки в контейнере Node22 (конкурентность файлов тестов1, CPU2):

```bash
docker compose exec -T web npm run typecheck
docker compose exec -T web npm run lint
docker compose exec -T web npm test
docker compose exec -T web npm run test:integration
```

Интеграционный набор использует настоящий PostgreSQL16 и **очищает только
выделенную тестовую БД N7**. Запускайте его на локальном F01 стенде до ввода рабочих
данных. Общий браузерный E2E и независимое ревью выполняет координатор.

PostgreSQL не записывает тексты SQL-ошибок и выражения: они могут содержать
переданные секреты. Приложение возвращает только фиксированные коды ошибок.
