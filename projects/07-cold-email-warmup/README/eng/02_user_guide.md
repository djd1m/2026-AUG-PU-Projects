# 02. Using the cabinet

1. Register with an 8–200 Unicode character password, at most 800 UTF-8 bytes.
   Logout revokes the server session; explicit login invalidates stale UI sessions in other tabs.
2. Save a mailbox with allowlisted SMTP/IMAP hosts and a daily cap. Secrets use AEAD
   encryption. TEST verification is not a real provider login.
3. Opt into the pool separately after reading the sender/header/test-body disclosure.
   Private campaigns and credentials remain tenant scoped. Without another tenant,
   the pool waits; saving a mailbox is not consent.
4. Configure up to five steps and 100 recipients, at least 24 hours between steps.
   Preview the allowed fields, consent to the current version and start explicitly.
   Content changes require consent again.
5. Pause, consent withdrawal, reply, unsubscribe and complaint stop future attempts.
   One attempt committed to submitting may still finish.
6. Enter manual observations with source, interval and counts. Sharing requires a
   fresh comparable improvement; small samples display counts instead of percentages.
7. Create/revoke a public report or partner code. Public reports expose a whitelisted
   snapshot and source origin only. An operator completes TEST Team; no money is charged.

Free allows 3 mailboxes/3 active campaigns; TEST Team allows 10/10. Warmup and
campaigns share a daily budget: default 10, maximum 30, reduced by the allowlist cap.
Use synthetic credentials and contacts when exploring the local TEST environment.
