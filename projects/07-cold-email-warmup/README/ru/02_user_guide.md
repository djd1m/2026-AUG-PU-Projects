# 02. Работа в кабинете

1. Создайте аккаунт. Пароль 8–200 Unicode-символов, максимум 800 UTF-8 байт.
   Выход отзывает серверную сессию; новая явная авторизация очищает чужую сессию в других вкладках.
2. Добавьте ящик, разрешённые SMTP/IMAP hosts и лимит. Секреты сохраняются AEAD-
   шифротекстом. TEST-проверка не означает успешный вход к настоящему провайдеру.
3. Прочитайте отдельное согласие пула: прямой получатель увидит адрес отправителя,
   заголовки и тестовый текст. Частные кампании/credentials ему не доступны.
   Без участника другого tenant показывается waiting. Сохранение ящика не даёт согласия.
4. Создайте до пяти шагов и ста получателей; между шагами минимум 24 часа.
   Preview проверяет доступные поля. Подтвердите отдельное согласие текущей версии
   кампании и запустите её. Изменённое содержание требует нового согласия.
5. Pause, отзыв согласия, ответ, отписка и жалоба останавливают будущие попытки.
   После уже зафиксированного submitting одна попытка может завершиться.
6. Введите ручные наблюдения с источником, окном и числами. Без сравнимого свежего
   улучшения share заблокирован. При малой выборке показываются числа, не проценты.
7. Создавайте/отзывайте публичный отчёт и партнёрский код. Отчёт раскрывает только
   разрешённый snapshot и origin источника. TEST Team активирует оператор; настоящего списания нет.

Free допускает 3 ящика/3 активные кампании, TEST Team — 10/10. Общая квота
warmup+campaign: по умолчанию 10/день, максимум 30, с учётом меньшего allowlist ceiling.
Не вводите реальные секреты и контактные списки для ознакомления с локальным TEST-стендом.
