# Пилот промо-ролика N6 «Суфлёр» — сопоставимое испытание HyperFrames и Remotion

Дата: 2026-09-29. Решение владельца: «да, запускай пилот на N6» (после `docs/research/promo-videos/04_decision.md`).
Цель пилота — выбрать инструмент, а не сделать финальный ролик. Оба исполнителя получают ОДНИ И ТЕ ЖЕ входы и
измеряются ОДНИМ протоколом.

## Фиксированные входы (одинаковы для обоих)

- **Записи экранов** — каталог `/home/dz-projects-2026/.promo-assets/n6/` (вне git; большие файлы в репозиторий не
  кладём). Делает этап «capture» (`promo/capture/`), исполнители их НЕ переснимают.
- **Сценарий 45 с, без голоса** (решение владельца: субтитры + музыка):

| Сцена | Время | Кадр | Текст на экране (субтитр/заголовок) |
|---|---|---|---|
| 1 | 0–5 с | заголовок на фоне токенов N6 (тёмная тема, `--paper #0d0f12`, акцент `#5fd0d8`) | «Посетители спрашивают — сайт молчит.» |
| 2 | 5–15 с | лендинг → форма адреса → ход индексации (запись `preview-*.webm`) | «Вставьте адрес сайта. Через минуту бот отвечает по вашим материалам.» |
| 3 | 15–30 с | пробный чат: вопрос → ответ с плашкой источника; второй вопрос → «Не нашёл в материалах» + контакт (запись `chat-*.webm`) | «Каждый ответ — с источником. Чего нет на сайте — не выдумывает.» |
| 4 | 30–38 с | экран установки: одна строка `<script>`, виджет на странице (запись `install-*.webm` / `widget-*.webm`) | «Одна строка кода — и бот на вашем сайте.» |
| 5 | 38–45 с | финал: название, адрес | «Суфлёр. Отвечает только по вашим материалам. sufler.aicoding.space» |

- **Шрифт:** Onest (как в продукте; файлы — из `@fontsource-variable/onest` в `projects/06-rag-sales-chatbase`), кириллица
  обязательна; переполнения текста — дефект.
- **Музыка:** только CC0/Public Domain с указанием источника и лицензии в отчёте; без музыки допустимо (тогда так и
  записать). Никаких треков «из интернета без лицензии».
- **Форматы:** из ОДНОГО исходника — 16:9 (1920×1080), 9:16 (1080×1920), 1:1 (1080×1080), 30 fps, H.264 MP4, ≤ 45 с.
- **Среда рендера:** образ `promo-render` (`promo/render-image/`) — производный от `mcr.microsoft.com/playwright:v1.60.0-noble`
  + FFmpeg + шрифты; телеметрия HyperFrames выключена (`HYPERFRAMES_NO_TELEMETRY=1`). Рендер — ТОЛЬКО внутри этого
  образа, на CPU этой машины, с лимитом памяти `--memory=4g` и `--cpus=6` (стенды работают рядом).

## Протокол замеров (одинаков для обоих; результат — `promo/<tool>/n6/MEASUREMENTS.md`)

1. **Время рендера** каждого формата: `/usr/bin/time -v` внутри контейнера → wall-clock, user+sys, Maximum resident set size.
2. **Размер файла** и `ffprobe` (длительность, кодек, fps, разрешение) каждого результата.
3. **Воспроизводимость:** рендер 16:9 дважды подряд → `sha256sum` обоих; если различаются — назвать причину
   (таймстемпы в контейнере mp4, недетерминированный энкодер и т.п.) и показать, что кадры совпадают (`ffmpeg -i a -i b
   -filter_complex psnr`).
4. **Число правок до приемлемого результата:** честный журнал итераций исполнителя (что не сработало и почему) —
   `ITERATIONS.md`; это мера агентопригодности (ось D).
5. **Установка:** закреплённые версии (`package.json` с точными версиями, lockfile), время `npm ci`, размер `node_modules`.
6. **Что не удалось** — отдельным разделом, без сглаживания.

## Ограничения

- Стенд `sufler.aicoding.space` и контейнеры `n6-sufler-*` не трогать (запись делает этап capture, один раз).
- Ключи, `.env`, общий прокси — не трогать. Никаких платных сервисов (ElevenLabs, HeyGen cloud, облачный рендер).
- Ролик — не окончательный: типографика и тексты могут быть простыми, важна сопоставимость.
- Всё, что исполнитель не смог доказать, — «не проверено», а не «работает».
