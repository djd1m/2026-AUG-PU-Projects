## Что НЕ снято и почему

- ~~`install-desktop.webm` — экран установки не снят~~ (пилот: учётки не было). **Снят в круге правок 2** —
  `install-*` и `embed-*` учёткой-фикстурой, см. раздел выше; `ui-fixture.json` по-прежнему не использовался.
- **Демо-страница бота `/b/{slug}` для предпросмотра не существует без входа:** её публикует владелец в кабинете
  после сохранения бота («Поделиться» ведёт на регистрацию). Поэтому «виджет» = окно чата самого предпросмотра —
  это тот же вид окна, но НЕ настоящий пузырь `<n6-sufler>` на чужом сайте (открытия пузыря в кадре нет).
  Настоящий виджет стоит на `https://aicoding.space`, но его не снимали: открытие пишет показ/установку в
  статистику живого бота владельца, а постановка разрешала только перечисленные запросы. Если нужен кадр
  пузыря — решение владельца, одна запись по `https://aicoding.space`.
- **«Не нашёл» без контакта.** В сценарии сцены 3 — «не нашёл + контакт»; у бота предпросмотра контакта нет
  (контакт задаётся в кабинете), поэтому ответ честный, но без строки контакта. В титре не обещать контакт
  этим кадром.
- **Кнопки «Сохранить/Поделиться» на mobile нет:** сервер показывает призыв только под ПЕРВЫМ ответом бота,
  он достался desktop-записи.

## Как повторить

```bash
cd promo/capture
docker run --rm --shm-size=1g --name promo-capture-n6 \
  -v "$PWD:/work" -v /home/dz-projects-2026/.promo-assets/n6:/assets -w /work \
  mcr.microsoft.com/playwright:v1.60.0-noble \
  bash -c "npm ci --no-audit --no-fund && node record-n6.mjs"
```

Без публикации портов. `STEPS=landing` — только лендинги (бесплатно). `STEPS=chat,widget` — перезапись чата и
виджета по `.state-n6.json` без нового предпросмотра (чат тратит 4 ответа из 10). Полный прогон создаёт ОДИН
предпросмотр; повторять его не больше двух раз в сутки (квота адреса 3). Отказ создания записывается в журнал
и НЕ повторяется скриптом. `STEPS=fixture,install,embed` — сцена 4 круга правок 2 (платных вызовов 0; нужен
`.fixture.env`, при `.state-n6-fixture.json` повторной регистрации нет; ограничения контейнера серии —
`--memory=1500m --cpus=2`, имя `promo-n6-capture`).

## Грабли, на которые наступили

- `recordVideo` Playwright 1.60 при `deviceScaleFactor 2` и `size 780×1688` кладёт кадр 390 × 844 в левый верхний
  угол серого поля (screencast Chromium отдаёт CSS-пиксели; то же в `channel: chromium` и с
  `Emulation.setDeviceMetricsOverride({scale: 2})`). Решение — `hidpi-recorder.mjs`: CDP `Page.captureScreenshot`
  (физические пиксели, ~30–34 снимка/с) → ffmpeg из поставки Playwright с постоянными 25 fps, недостающий
  кадр дублируется. Desktop пишется штатным `recordVideo`.
- `video.saveAs()` после `page.close()` однажды упал «Target page, context or browser has been closed» — вызов
  запускается до `close()` и дожидается после.
