## Что НЕ снято и почему

- **Настоящая загрузка на телефоне.** Нажатие «Создать клипы» на mobile запустило бы вторую платную обработку;
  `upload-mobile` обрывается у кнопки, ход обработки на телефоне — отдельный `progress-mobile` той же записи.
- **Монтаж N из M в кадре дальше «0 из 5».** Держать запись 5 минут ради счётчика не стали: переход «0 из 5 →
  5 из 5» есть только в журнале (`progress.offscreen`).
- **«Клипы для гостя» и код партнёра** — вне сценария; гостевые запросы заблокированы.
- **Звук клипов** не записан (Playwright пишет только видео); клип в карточке запущен без звука.

## Как повторить

```bash
cd promo/capture
docker run --rm --memory=1500m --cpus=2 --shm-size=1g --name promo-n5-capture \
  -v "$PWD:/work" -v /home/dz-projects-2026/.promo-assets/n5:/assets -w /work/n5 \
  mcr.microsoft.com/playwright:v1.60.0-noble \
  bash -c "npm ci --no-audit --no-fund && node record-n5.mjs"
```

Без публикации портов. `STEPS=landing,showcase` — бесплатно. `STEPS=clips,link` — перезапись экранов готовой
записи по `.state-n5.json` (бесплатно). Шаг `upload` (платный) при существующем `.state-n5.json` отказывается и
пишет отказ в журнал; для новой обработки файл нужно удалить осознанно — это новый платный вызов.

## Грабли

- На странице своего клипа без призыва автора главная кнопка — `a.cta` «Сделать свои клипы», а не
  `.secondary-link`, как на витрине; первый прогон `link-desktop` ждал `.secondary-link` 30 с и упал (файл
  перезаписан вторым, бесплатным прогоном). Наведение курсора теперь ждёт элемент не дольше 5 с.
- Контейнеру нужен `--memory=1500m`: при свободных 0–1 ГБ (available 3–4 ГБ) прогон прошёл без OOM.
