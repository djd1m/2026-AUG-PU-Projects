Прочитай `promo/PILOT-N6.md` (сценарий, форматы, протокол замеров), `promo/render-image/README.md` (как запускать
рендер в образе `promo-render:2026-09-29`; Chromium под root — вопрос `--no-sandbox`), `promo/capture/README.md`
(таблица записей, тайминги событий в `record-log-*.json`: где в `chat-*` начинается вопрос, где приходит ответ — паузы
ожидания ~30 с ВЫРЕЗАТЬ), `docs/research/promo-videos/01_tools/<твой инструмент>.md` (факты и пример кода).

## Входы (не менять, не переснимать)

- Записи: `/home/dz-projects-2026/.promo-assets/n6/*.webm` (монтировать в контейнер как `/assets`, только чтение).
- Сцена 4 — экран установки НЕ снят (нужен вход): использовать `widget-*.webm` (окно чата предпросмотра с бейджем
  «Работает на Суфлёре»); титр «Одна строка кода — и бот на вашем сайте» — оставить, но в отчёте отметить, что кадр
  показывает окно чата, а не `<script>`.

  без слова «контакт».
- Шрифт: `/usr/local/share/fonts/Onest-*.ttf` внутри образа (или тот же TTF, скопированный в проект). Кириллица.
- Токены N6: фон `#0d0f12`, текст `#eef1f4`, акцент `#5fd0d8`.
- Музыка: только CC0/Public Domain с источником и лицензией в отчёте, либо без музыки — тогда так и записать.

## Где работать

- Проект ролика: `promo/<tool>/n6/` (`package.json` с ТОЧНЫМИ версиями, lockfile, исходники сцен, `render.sh`).
- Результаты рендера: `/home/dz-projects-2026/.promo-assets/n6/out/<tool>/{16x9,9x16,1x1}.mp4` (вне git).
- Установка зависимостей и рендер — ТОЛЬКО внутри образа: `docker run --rm --memory=4g --cpus=6 --network <bridge для
  npm ci, затем --network none для рендера, если инструмент не требует сети> -v $PWD/promo/<tool>/n6:/work
  -v /home/dz-projects-2026/.promo-assets/n6:/assets:ro -w /work promo-render:2026-09-29 …`. На хосте Node 20 — ничего
  не ставить глобально, `npx` на хосте не использовать. Порты не публиковать.
- Внешние скрипты с CDN (например GSAP у HyperFrames) — vendor'ить в проект с закреплённой версией; рендер обязан
  работать с `--network none` (если не работает — записать в «не удалось» с причиной).

## Замеры — строго по протоколу `PILOT-N6.md` → `promo/<tool>/n6/MEASUREMENTS.md`

- Измеряемые рендеры выполнять ПОД БЛОКИРОВКОЙ, чтобы второй исполнитель не мерил параллельно:
  `flock /home/dz-projects-2026/.promo-assets/render.lock docker run …` — и записать, что блокировка применялась.
- `/usr/bin/time -v` внутри контейнера (если `time` отсутствует в образе — `apt`-установка внутри одноразового
  контейнера недопустима; используй `bash -c 'TIMEFORMAT=…; time …'` + `docker stats --no-stream` или
  `/sys/fs/cgroup/memory.peak` и запиши, чем мерил).
- Воспроизводимость: два рендера 16:9 → `sha256sum`; при различии — `ffmpeg … -filter_complex psnr` и причина.
- `ffprobe` каждого результата: длительность (≤ 45 с), 30 fps, H.264, yuv420p, разрешение.
- `ITERATIONS.md`: каждая попытка — что не сработало, что поправил, сколько минут; это мера агентопригодности.
- Разрешён ОДИН узкий вызов Codex `gpt-6-astra` medium (по `codex-invocation-local.md`) на вопрос «правильно ли
  использован API инструмента» — если нужен; ответ в `promo/<tool>/n6/CODEX.md`. Не более одного.

## Критерий готовности

Три mp4 по протоколу, `MEASUREMENTS.md` + `ITERATIONS.md` + `README.md` (как воспроизвести одной командой), коммиты
`feat(promo): …` / `docs(promo): …` по-русски без Co-Authored-By. Бюджет — 90 минут активной работы; если ролик не
собирается за 6 итераций — остановиться и честно записать, на чём. Стенд `sufler.aicoding.space`, контейнеры `n6-*`,
`.env`, ключи — не трогать; платных сервисов и облачного рендера — нет.
