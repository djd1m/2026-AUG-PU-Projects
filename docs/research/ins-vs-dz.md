## A) Что на самом деле делает p-replicator

**Модель данных.** Плоский markdown-лог `.claude/insights/index.md`. Запись — заголовок
`## <ISO-дата> — <заголовок>`, поля `**Tags:**` (2-5 через запятую), `**Problem:**`,
`**Solution:**`, `**References:**`. Никакого ID, реварда, типа, домена, счётчика
использований. Жизненный цикл: append-only, «никогда не удалять, помечать как
superseded». Разбиение на архивы `<YYYY-MM>.md` при >50 записей — описано в правиле,
кодом нигде не реализовано.

**Кто и когда пишет.** Только человек, только вручную, только явной командой
`/myinsights "<текст>"`. Автозахвата нет ни в каком виде. `Stop`-хук
`autocommit-insights.cjs` лишь коммитит уже написанный файл.

**Как возвращается в работу.** `SessionStart` → `session-insights.cjs` печатает в stdout
**последние 3** записи; Claude Code вбирает stdout в стартовый контекст.

> **Расхождение документации с кодом (найдено, стоит починить независимо от решения).**
> `myinsights.md` обещает инъекцию «when their tags match the current task», а
> `insights-capture.md` — «relevant insights». Код (`session-insights.cjs:34`) делает
> `sections.slice(-3)` — берёт три ПОСЛЕДНИЕ по порядку в файле, без какого-либо
> сопоставления с задачей. Теги в рантайме не читает никто. Механизм релевантности,
> обещанный в двух документах, не существует.

> **Вторая необеспеченная связь.** `myinsights.md` → «Related: `/harvest` — extracts
> reusable patterns from insights at project end». `grep` по `.claude/commands/harvest.md`
> и всем четырём модулям `knowledge-extractor` даёт **ноль** упоминаний `insights` /
> `index.md`. Заявленный потребитель знания не подключён.

**Фактическое использование на этой машине.** 27 записей в трёх проектах курса
(APR-LESSON-07/08/09, май 2026). В текущем AUG-репозитории и во всех восьми `projects/*`
— файла нет вовсе. То есть за последние месяцы механизм не сработал ни разу, при том что
за это время в репозиторий легло множество разобранных «граблей» (компрометация Postgres,
обход прокси по `X-Forwarded-For`, MODULE_NOT_FOUND в хуках) — все они осели в
`CLAUDE.md`, `harness-forge/` и правилах, а не в инсайтах.

## B) Что делает `dz`

**Кто и когда пишет.** Четыре независимых пути, три из них автоматические:
| путь | режим |
|---|---|
| `dz teach "<pattern>" [--reward] [--domain] [--type rule\|success-pattern\|lesson-learned]` | вручную/агентом |
| `dz consolidate` | автоматически из `sessions.jsonl` |
| `dz retro [--install-hook]` | автоматически на `SessionEnd`: майнит транскрипт на повторяющиеся ПРОЦЕССНЫЕ грабли, учит агента и «дрилит» человека |
| `dz mr-rakes --teach` | майнит QE-отчёты фич на повторяющиеся ошибки (порог ≥2/≥3 независимых источника) |
| feature-adr Step 8 | часть пайплайна: сравнивает уроки прогона с отозванными на Step 0, `--reinforce` вместо дубликата |

**Что хранит.** `PatternRecord` в `.dz/` (SQLite/AgentDB + legacy `patterns.jsonl`):
текст, `dzId`, reward, domain, type, метки quarantine, счётчики инъекций и обращений,
вектор эмбеддинга. Retention по умолчанию 90 дней (`.dz/config.json`).

**Как возвращается.** Три канала:
1. `UserPromptSubmit`-хук `.claude/helpers/recall-hook.cjs` — на КАЖДОМ промпте считает
   косинусную близость к хранилищу и инъектит только то, что перебивает порог
   релевантности (пороги ИЗМЕРЕНЫ на 32-пробном размеченном наборе: 0.38 для кириллицы,
   0.31 для латиницы; z-score пробовали — 69% точности, отвергнут). Молчание при
   нерелевантности — заявленная фича. Стоимость 50–83 мс с резидентным эмбеддер-демоном
   (`SessionStart`, ~427 МБ RSS, выход по 30 мин простоя), 37 мс без него.
2. `dz recall "<query>"` — гибридный лексический+векторный поиск по требованию.
3. Ранжирующий буст в `dz recommend` (`BOOST_CAP=50`, `PER_MATCH_WEIGHT=10`).

**Кросс-проектность.** `dz brain` — durable cross-project store. Здесь и сейчас в нём 4
источника, 714 KU (`vysokonagruzhennye-prilozheniya` 116, `adr-monograph` 60, `ai-apps` 223,
`fundamental-software-architecture` 315). `dz brain ground` — отдельный
`UserPromptSubmit`-хук с бюджетом токенов. Плюс `--project <dir>` в `teach`/`recall`
пинит хранилище к каноническому «мозгу», чтобы урок из чужого чекаута не осел в `.dz`
того репозитория (это прямо прописано в `feature-adr-ultracode.md`).

**Дедупликация и гигиена.** Точный дедуп текста в `teach`; `--reinforce` вместо
near-duplicate; `dz vector harmonize` — семантический дедуп по порогу; `dz consolidate
--prune-noise` (мусор) и `--prune-quarantine` (протухшие неподтверждённые) — оба dry-run
по умолчанию со снапшотом; `dz recall --forget/--promote`. **Карантин**: свежий урок —
гипотеза, исключён из авто-инъекции и придавлен в recall, промоушен зарабатывается.

**Измеримость окупаемости.** `dz compounding` — write-only ratio пула, траектория
повторных нарушений guard'а (по РЕЙТИНГУ, не по абсолюту), cold-vs-warm replay,
здоровье инструментовки. Гейт без данных говорит `INSUFFICIENT_DATA`, а не фальшивый
вердикт. Плюс цепочка хешей над `.dz/recall-usage.jsonl` и `.dz/guard-audit.jsonl`
(классы дефектов `BrokenLink`, `DuplicateSeq`, `DoubleCounted` …) — «честность
доказательств» здесь отдельный проверяемый инвариант.

Прогон в этом репозитории: `pool 0/0`, `replay insufficient-data`, `applyLegLive: false` —
локальный `.dz` пуст, живёт только `brain` в `/root/.dz`. То есть **у dz на этой машине
apply-нога тоже не запущена** — сравнение идёт по проектной способности, не по факту
использования.

## Сравнение по осям

| Ось | p-replicator `/myinsights` | `dz` |
|---|---|---|
| **Кто пишет** | только человек, явной командой | человек + агент + пайплайн + майнеры транскриптов/QE-отчётов |
| **Когда пишет** | когда вспомнил | `SessionEnd`, Step 8 feature-adr, `consolidate`, `mr-rakes` — автоматически |
| **Что хранит** | markdown: дата, заголовок, теги, проблема, решение, ссылки | запись с `dzId`, reward, domain, type, карантином, счётчиками, вектором |
| **Как возвращает** | последние 3 записи на `SessionStart`, **без** учёта релевантности (вопреки документации) | инъекция по измеренному порогу близости на каждом промпте + `recall` по запросу + буст в `recommend` |
| **Кросс-проектность** | **нет вовсе**: один файл на проект, по замыслу («one file per project to keep recall trivial») | `dz brain` + `--project` пиннинг к каноническому мозгу; 4 источника / 714 KU уже накоплено |
| **Дедупликация** | **нет**: append-only, «superseded» вручную | точный дедуп, `--reinforce`, `vector harmonize`, два prune, `forget`/`promote`, карантин |
| **Измеримость** | счётчик записей в статуслайне (`💡 Insights ●N`) — сколько написано, не сколько сработало | `dz compounding` + `recall --usage` + цепочка хешей над журналами доказательств |
| **Переносимость** | максимальная: markdown в git, читается человеком, переживает удаление любого инструмента, ревьюится в PR, едет с репозиторием к студенту | `.dz/` git-ignored, машинный, привязан к бинарю; экспорт `recall --all --json` / `vector export` есть, но это отдельное действие |
| **Работа без второго инструмента** | **да** — чистый Node, ноль зависимостей | нет: нужен установленный `dz`, для семантики — эмбеддер (~427 МБ RSS) |
| **Стоимость** | ~0 (одно чтение файла на старте) | 50–83 мс на промпт + резидентный демон |
| **Цена ошибки** | ноль (текст в git, откатывается) | отравление хранилища — поэтому и появился карантин |

**Где перекрытие полное.** «Записать грабли — вернуть их в контекст, когда пригодятся».
Здесь dz строго сильнее по всем осям, кроме переносимости.

**Где перекрытия НЕТ.** Три вещи, которых dz не делает и не собирается:
1. **Артефакт в git.** Инсайты — версионируемый текст в репозитории. Их видно в diff'е,
   их можно отревьюить в PR, они уезжают вместе с клоном. `.dz/` — git-ignored и машинный.
   Для репозитория **учебного курса**, где содержимое читают студенты, это не побочный
   эффект, а сам продукт.
2. **Работа на голой машине.** p-replicator ставится одной `npx`-командой и обязан
   работать там, где `dz` нет. Это ограничение задачи, а не пожелание.
3. **Человекочитаемая формулировка.** Инсайт написан человеком для человека
   (проблема → решение → ссылка). Урок `dz` оптимизирован под ранжирование, а не под чтение.

## Рекомендация

### **Вариант 2 — делегировать `dz`, когда он есть; деградировать к собственному, когда его нет.**

Обоснование по трём пунктам.

**Почему не вариант 3 (убрать).** Задача не исчезла — исчез бы носитель. Убрав инсайты,
p-replicator теряет единственный **git-коммитируемый, человекочитаемый** след разбора
граблей и перестаёт закрывать петлю обучения вообще на любой машине без `dz`. Доказать
ненужность задачи нечем: 27 реальных записей в трёх проектах курса — это ровно тот тип
знания, который иначе теряется («Telegram заблокирован → архитектурный пивот»,
«sparc-prd-mini молча пропустил 2 из 11 документов»). Последнее вообще является баг-репортом
на сам пайплайн; в `.dz` он был бы невидим для того, кто клонирует репозиторий.

**Почему не вариант 1 (оставить как есть).** Механизм в текущем виде проигрывает не
только dz, но и собственной документации. Он (а) обещает релевантность, которой в коде
нет; (б) обещает потребителя `/harvest`, который его не читает; (в) не имеет ни
дедупликации, ни ротации, ни измерения — то есть при 50+ записях `slice(-3)` начнёт
инъектить три случайных недавних записи вместо трёх нужных; (г) в новых проектах не
используется вообще. Оставить «как есть» — значит законсервировать write-only-лог с
неверной документацией.

**Почему именно 2.** Роли разделяются без потерь и без дублирования:
- **markdown остаётся источником истины** — он переносим, ревьюируем, работает без всего;
- **`dz`, когда он есть, берёт на себя apply-ногу** — релевантную инъекцию вместо
  «последних трёх», плюс кросс-проектность и измеримость, которых у p-replicator нет
  и не должно появиться (реализовать эмбеддинги внутри p-replicator — это построить
  второй `dz` худшего качества);
- **двойной инъекции не возникает**: собственный хук замолкает ровно тогда, когда
  вооружён `recall-hook` от `dz`.

Ключевой инвариант, который делает это безопасным: **делегирование одностороннее**.
p-replicator пишет в оба хранилища и читает из своего; `dz` — необязательное усиление,
никогда не предусловие. Удаление `dz` с машины не ломает ничего и не теряет ни одной
записи.

## Что менять

### 1. `templates/.claude/hooks/session-insights.cjs` — умолкать, когда apply-нога dz вооружена

Детект — **чистое чтение файлов, без запуска процессов** (хук в `SessionStart` с
таймаутом 5 с, `spawnSync('dz')` там неуместен):

```js
// Вооружён ли UserPromptSubmit-хук dz? Именно он, а не наличие бинаря: сам по себе
// установленный dz ничего не инъектит, а вооружённый recall-hook делает это лучше нас.
function dzApplyLegArmed(root) {
  try {
    const s = JSON.parse(fs.readFileSync(path.join(root, '.claude', 'settings.json'), 'utf8'));
    return JSON.stringify(s.hooks?.UserPromptSubmit ?? []).includes('recall-hook');
  } catch { return false; }
}
```

Поведение:
- **вооружён** → печатать одну строку `## Project insights\n\n<N> записей в
  .claude/insights/index.md — релевантные подтягивает dz recall` и выйти. Тихая
  деактивация без диагностики запрещена: молчащий хук неотличим от сломанного.
- **не вооружён** → текущее поведение (`slice(-3)`), но с исправленной документацией
  (см. п. 4) либо с наивным скорингом по тегам (см. п. 5).

### 2. `templates/.claude/commands/myinsights.md` — зеркалить запись в `dz`, если он есть

Команду исполняет модель, поэтому детект здесь дешёвый и надёжный: `command -v dz`.
Добавить шаг 4 в раздел Capture:

```
4. Если `command -v dz` успешен — продублировать инсайт в обучающее хранилище:
   dz teach "<заголовок>: <решение>" --type lesson-learned --domain <первый тег>
   Ошибка/отсутствие dz — не ошибка команды: markdown уже записан, это единственный
   обязательный носитель. Залогировать одной строкой и продолжить.
```

Симметрично в режим Recall: при наличии `dz` сначала `dz recall "<query>"`, затем
грепнуть `index.md` и слить результаты, пометив источник каждой строки.

Замечание по домену: `--domain` из первого тега даёт бесплатное соответствие тегам
p-replicator и доменной модели dz — но НЕ `--reward`: реварда у инсайта нет, а
выдуманное число исказит ранжирование.

### 3. `templates/.claude/rules/insights-capture.md` — раздел «Интеграция с dz»

Табличка «кто за что отвечает» (markdown = источник истины и fallback; dz = релевантная
инъекция, кросс-проектность, измеримость), явное указание, что зависимость
**необязательная и односторонняя**, и что удаление `dz` ничего не ломает. По
`.claude/rules/skill-interface-protocol.md` §5-6 это OPTIONAL-зависимость, а значит
обязан быть документированный fallback — им и является текущее поведение хука.

### 4. Починить документацию (нужно при ЛЮБОМ из трёх вариантов)

- В `myinsights.md` и `insights-capture.md` убрать обещание инъекции «по совпадению
  тегов» — либо реализовать (п. 5). Сейчас документ описывает несуществующее поведение.
- Из `myinsights.md` убрать строку «Related: `/harvest` — extracts reusable patterns from
  insights» ЛИБО подключить: добавить `.claude/insights/index.md` во входы
  `knowledge-extractor/modules/01-agent-review.md`. Второе полезнее — инсайты это ровно
  тот вход, для которого `/harvest` и задуман, и это единственное место, где
  p-replicator может дать кросс-проектность в своём стиле (через извлечённые артефакты
  тулкита, а не через векторное хранилище).

### 5. Опционально — наивный скоринг в fallback-ветке

Когда `dz` нет, `slice(-3)` при 50+ записях бесполезен. Дешёвая замена без единой
зависимости: разобрать `**Tags:**` каждой записи, посчитать пересечение с токенами
`prompt`/`source` из JSON-payload хука на stdin, взять топ-3 по пересечению, при нуле
пересечений — откатиться на последние 3. ~25 строк, ноль зависимостей, и документация
наконец становится правдой. Это дополнение к варианту 2, а не альтернатива ему:
лексическое пересечение тегов слабее измеренных косинусных порогов dz, поэтому и
включается только в его отсутствие.

### 6. Поведение `init` — не меняется

`dz` НЕ добавляется в зависимости, `init` его не ставит, не проверяет и не требует;
`.p-replicator.json` не получает новых полей. Все изменения — внутри трёх шаблонных
файлов, детект целиком рантаймовый. Контракт pre-shipped артефактов
(`.claude/rules/replicate-pipeline.md`, раздел «What Gets Generated vs Pre-shipped») и
коды выхода `verify`/`doctor` сохраняются без изменений.

### 7. Тесты (слой 1 по лестнице стоимости обнаружения из корневого `CLAUDE.md`)

Проверки детерминированные, значит им место в `tests/unit/`, а не в суждении ревьюера:
- `session-insights.cjs` без `.claude/settings.json` печатает записи (fallback жив);
- с `recall-hook` в `UserPromptSubmit` печатает ОДНУ строку-уведомление и не дублирует
  содержимое инсайтов;
- отсутствие `dz` в `PATH` не влияет на код возврата `myinsights` (проверяется на тексте
  шаблона: рядом с вызовом `dz teach` обязана стоять формулировка про необязательность);
- grep-гвардия: если `myinsights.md` упоминает `/harvest`, то `01-agent-review.md` обязан
  упоминать `insights/index.md` — иначе связь снова разъедется молча.

## Ответ одной строкой

**Вариант 2.** Механизм не утратил смысл — утратила смысл его apply-нога: markdown в git
переносим и работает без `dz`, а релевантную инъекцию, кросс-проектность и измерение
окупаемости `dz` делает несравнимо лучше, поэтому их и надо ему отдать при наличии.
