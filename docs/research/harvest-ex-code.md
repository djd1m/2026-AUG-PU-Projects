## A. Сниппеты

### `client-ip-behind-proxy`
**Путь:** `apps/web/src/lib/client-ip.ts:30`
**Что делает:** достаёт клиентский IP из `X-Forwarded-For`, доверяя **последнему** элементу цепочки (его дописал наш прокси), с фолбэком на `X-Real-IP` и литералом `unknown` вместо пустой строки.
**Почему переиспользуемо:** каждый проект за reverse-proxy решает эту задачу, и обычно неправильно — берут первый элемент, то есть значение, присланное атакующим. В шапке файла записано несущее условие: приложение не должно быть опубликовано в обход прокси, иначе «последний элемент» снова становится клиентским и лимит обнуляется сменой заголовка.
**Вычистить:** «Caddy» → параметр (какой прокси, сколько его хопов в конце цепочки); порог 5/час — доменный.

### `unbiased-random-token`
**Путь:** `apps/web/src/lib/slug.ts:19`
**Что делает:** случайная строка из `randomBytes` с отбрасыванием байтов вне кратного диапазона; алфавит без гласных и похожих глифов.
**Почему переиспользуемо:** ошибка `randomBytes()[i] % alphabet.length` (смещение к началу алфавита) встречается почти в каждом проекте — здесь уже исправлена. Алфавит без гласных: суффикс не должен случайно сложиться в слово.
**Вычистить:** алфавит и длина → параметры.

### `slug-normalize-and-uniquify`
**Путь:** `apps/web/src/lib/slug.ts:40` и `:80`
**Что делает:** детерминированная нормализация (регистр, спецсимволы → дефис, схлопывание повторов, обрезка + повторная обрезка дефиса после `slice`) и отдельно — доподбор свободного значения с лимитом попыток.
**Почему переиспользуемо:** ценно РАЗДЕЛЕНИЕ на две функции, объяснённое в `:50-63`. Добор случайным суффиксом применяется только к выведенному из названия слагу; применить его к явно введённому — значит молча превратить невалидное «ab» в валидное «ab-x7q» и увезти в БД вместо 400.
**Вычистить:** ссылки на Pseudocode §9; границы 3/40 → параметры.

### `validated-base-url`
**Путь:** `apps/web/src/lib/urls.ts:17`
**Что делает:** резолвит внешний BASE_URL из цепочки переменных, валидируя результат через `new URL` + allowlist схем (только http/https), а не просто срезая хвостовой слеш.
**Почему переиспользуемо:** ловит реальный класс дефекта — `BASE_URL="/"` после trim даёт пустую строку, и каждый последующий `new URL(path, base)` падает с «Invalid URL». Поймано тестом, а не чтением. За прокси приложение своего внешнего адреса не знает — задача универсальная.
**Вычистить:** имена переменных (`BASE_URL`/`NEXT_PUBLIC_BASE_URL`) → параметр; `widgetSnippet`/`buildProjectUrls` из того же файла не брать.

### `opaque-session-token`
**Путь:** `apps/web/src/lib/session.ts:31-63`
**Что делает:** непрозрачный токен 32 байта base64url → в БД только HMAC-SHA256 на секрете; сверка `timingSafeEqual`; fail-closed, если секрет не задан или короче 16 символов; опции httpOnly-cookie.
**Почему переиспользуемо:** полная схема сессий без библиотеки, ~40 строк. Записаны два решения: HMAC вместо голого sha256 (иначе украденный дамп перебирается заранее посчитанной радужной таблицей) и `sameSite:'lax'` вместо `'strict'` (иначе ломается возврат с внешнего платёжного провайдера).
**Вычистить:** имя cookie `pw_session`, TTL 30 дней и его мотивировка → параметры.

### `safe-external-url`
**Путь:** `apps/web/src/lib/branding.ts:21` (+ hex-guard `:18`)
**Что делает:** пропускает только абсолютный http(s)-URL через `new URL` + allowlist протокола; рядом — строгий `^#[0-9a-fA-F]{6}$` для значения, уходящего в inline-`style`.
**Почему переиспользуемо:** два места, где `javascript:`/`data:` доезжают до разметки: `src` картинки и атрибут стиля. Строка вида `red;background:url(javascript:…)` — ровно тот случай, который отсекает hex-проверка.
**Вычистить:** дефолтный цвет, `heading`, лимит 120 символов.

### `stream-download-size-cap`
**Путь:** `services/transcribe/src/transcribe.ts:88`
**Что делает:** качает URL во временный файл с `AbortController`-таймаутом и лимитом размера, проверяемым **дважды**: по `Content-Length` и по фактически прочитанным байтам.
**Почему переиспользуемо:** проверять только `Content-Length` недостаточно — заголовок врёт или отсутствует. Нужно везде, где сервис тянет файл по чужой ссылке.
**Вычистить:** `SttApiError` → обобщённый тип ошибки; упоминания видео и FR-003.

### `normalize-domain`
**Путь:** `apps/web/src/lib/widget-install.ts:26`
**Что делает:** нормализует домен из `Referer`/`Origin` в ключ дедупликации: регистр, порт, `www.`, голый хост; отдельно — литеральное `"null"`.
**Почему переиспользуемо:** значение приходит снаружи и попадает в unique-ключ; без нормализации один сайт насчитает три записи. Литеральное `"null"` браузер шлёт для `file://` и sandboxed iframe — это отсутствие домена, а не домен; находится только на практике.
**Вычистить:** `isOwnDomain` (`:48`) тянет `APP_DOMAIN`/`BASE_URL` → параметризовать.

### `require-env-config`
**Путь:** `services/worker/src/config.ts:11-63`
**Что делает:** `requireEnv` бросает с внятным сообщением при старте; типизированный `WorkerConfig` с дефолтами, принимающий `env` **аргументом**, а не читающий `process.env` внутри.

**Вычистить:** имена переменных и все интервалы.

### `video-container-sniff` (сиблинг уже взятого `sniffImage`)

## B. Паттерны

### `insert-based-idempotency`
**Путь:** `apps/web/src/lib/payment.ts:126`; `apps/web/src/lib/widget-install.ts:12-14`
**Что делает:** дедупликация повторной доставки через `INSERT ... ON CONFLICT DO NOTHING [RETURNING id]` — непустой результат означает «первая доставка, обрабатываем».
**Почему переиспользуемо:** гарантия «ровно один раз» переносится на СХЕМУ (`unique(provider,event_id)`), а не на логику приложения. Суть записана в обоих файлах: «проверить, потом вставить» оставляет окно, где два параллельных повтора оба видят «нет» — в `widget-install.ts` это разобрано на сценарии двух одновременных первых рендеров.
**Вычистить:** имена таблиц, `PROVIDER='yookassa'`; `applyTariffUpgrade` и комиссии — доменное, не брать.

### `single-rate-limit-store`
**Путь:** `packages/db/src/rate-limit.ts` целиком (89 строк)
**Что делает:** одна таблица `(scope, key, created_at)` и пять функций: `count`, `record`→id, `revoke`, `exceeded`, `cleanupOlderThan`.
**Почему переиспользуемо:** три разных требования проекта обслужены одним механизмом — новый случай расширяет `scope`, а не заводит таблицу. Отдельно ценен `revoke` с записанным правилом (`:58-62`): квота откатывается только при инфраструктурном сбое ПОСЛЕ списания, но НЕ при отказе валидации — за невалидные попытки квота должна списываться.
**Вычистить:** конкретные scope-строки и пороги. `interface Executor` (`:17`) — самостоятельная находка: один код работает и с `Pool`, и с `PoolClient`, то есть и внутри чужой транзакции, и вне её.

### `skip-locked-queue`
**Путь:** `services/worker/src/transcribe-job.ts:59` и `:139`
**Что делает:** очередь на Postgres без брокера — `SELECT ... FOR UPDATE SKIP LOCKED LIMIT 1` внутри транзакции + поллер, выгребающий очередь без пауз и спящий только на пустой.
**Почему переиспользуемо:** очередь на одной БД для масштаба, где Redis избыточен. Зафиксирован реальный дефект (`:70-77`): без фильтра «строка вообще обрабатываема» воркер брал непригодные записи, падал, и `ORDER BY created_at` возвращал ту же строку вечно — очередь встала на 21 записи.
**Вычистить:** имена таблицы/колонок и весь STT-путь. Сохранить осознанный компромисс из шапки: транзакция держится открытой на всё время обработки, потому что enum статусов зафиксирован ровно тремя значениями.

### `untrusted-content-rendering`

## C. Тестовые приёмы

### `exact-shape-assertions`
**Путь:** `apps/web/tests/widget-config.test.ts:84`; `services/transcribe/tests/contract.test.ts:59` и `:68`; `apps/web/tests/tariff.test.ts:21`

**Почему переиспользуемо:** ловит поле, утёкшее в публичный ответ завтра, и случайный второй эндпоинт. В обоих файлах записано правило «не смягчать до `toContain`/`минимум один`» — иначе тест перестаёт ловить добавление. Дополняется проверкой `JSON.stringify(cfg)).not.toContain(...)`: поле не спрятано во вложенной структуре.
**Вычистить:** имена полей и путей → параметры шаблона. (Арность взята из `tariff.test.ts`, но это отдельный переносимый приём, а не сам тест тарифа.)

### `pure-decision-from-snapshot`
**Путь:** `apps/widget/src/badge.ts:33-44`; тест `apps/widget/tests/badge-integrity.test.ts:1-21`
**Что делает:** решающая логика вынесена из DOM в чистую функцию над снапшотом (`display`, `visibility`, `opacity`, `offsetWidth/Height`), потому что jsdom не считает layout и `offsetWidth` там ВСЕГДА 0 — тест на настоящих узлах не отличил бы «предок скрыт» от «просто jsdom».
**Почему переиспользуемо:** приём против самообмана в тестах. Даёт трёхуровневую структуру: чистый классификатор на синтетике → реальный DOM там, где среда честна (`getComputedStyle` из инлайн-стиля, без layout) → явно названный `[GAP]` на то, что требует браузера. Переносится на любую логику, зависящую от среды, которую тест не воспроизводит.
**Вычистить:** badge и ADR-002; забрать структуру и формулировку честной границы в шапке.

### `live-db-test-isolation`
**Путь:** `apps/web/tests/content-threshold.test.ts:17` (`inRollback`); `services/worker/tests/helpers/test-db.ts:29` и `:101`; `packages/db/tests/env-setup.ts`; `services/worker/tests/skip-locked.test.ts:21`
**Что делает:** четыре слоя изоляции тестов против живой Postgres — (1) `inRollback`: тест целиком в транзакции, которая всегда откатывается через бросок маркерной ошибки с результатом в её поле; (2) свои таблицы теста в ОТДЕЛЬНОЙ схеме `worker_test`, недосягаемой для миграций, и `DROP SCHEMA CASCADE` сносит только созданное самим тестом; (3) `setupFiles` присваивает `DATABASE_URL := TEST_DATABASE_URL` ДО импорта модулей; (4) `describe.skipIf(!TEST_DATABASE_URL)` — зелено там, где БД нет.
**Почему переиспользуемо:** гонки, RLS и идемпотентность на моках не проверяются в принципе, а живая БД сразу даёт проблему изоляции. Каждый слой заслужен конкретным падением, зафиксированным в комментарии: `DROP TABLE` из тестов воркера сносил таблицы `packages/db` и делал `npm test` неидемпотентным (18 тестов падали, при том что `schema_migrations` считала миграцию применённой); присваивание внутри `setup.ts` не сработало бы, потому что импорты поднимаются наверх и пул уже создан с пустым connectionString.
**Вычистить:** имена таблиц в `truncateAll`, `seedAccountWithProject`. `inRollback` продублирован в 10 файлах — при обобщении вынести в один хелпер.

### `schema-fidelity-rule`
**Путь:** `services/worker/tests/helpers/test-db.ts:60-67`
**Что делает:** правило в комментарии над фикстурой — колонки, участвующие в ОТБОРЕ строк, обязаны совпадать с боевой схемой по типу и nullability.
**Почему переиспользуемо:** не код, а правило, но с доказательством. Конкретно: `video_object_key` в фикстуре стоял `NOT NULL`, в бою `NULLABLE`; из-за этого запись без видео в тестовой БД существовать не могла, и баг «воркер забирает необрабатываемые строки и встаёт навсегда» был невоспроизводим в тестах, хотя на стенде заблокировал очередь.
**Вычистить:** имена колонок; формулировка правила переносится дословно.

### `deterministic-guard-scripts`
**Путь:** `scripts/check-env-wiring.sh`; `scripts/check-port-conflicts.sh`
**Что делает:** два bash-стража слоя 1. Первый: `grep -rhoE 'process\.env\.[A-Z][A-Z0-9_]*'` по исходникам сервиса против `docker compose config` — что код читает, но до сервиса не доезжает. Второй: занятые порты из `docker ps` и `ss` против желаемых из `docker compose config`.
**Почему переиспользуемо:** оба ловят класс дефектов, при котором приложение стартует, тесты зелёные, а наружу выдаётся неверное. Заслужены: `BASE_URL` читался кодом, но отсутствовал в `environment` у web — каждая выданная ссылка вела на `localhost:3000`; ни старт (есть дефолт), ни юнит-тесты (сломана не функция, а доставка значения), ни открытие страниц этого не показали. Два записанных решения: `.env.example` НЕ является опорой (сам оказался неполон), и список исключений ЯВНЫЙ — молчаливых быть не должно. В port-скрипте: полагаться на «увижу при `up`» нельзя, docker называет ОДИН порт за прогон, а часть стека уже поднята. Ловушка регулярки зафиксирована прямо в коде (`:38-39`): без цифр в классе `S3_ENDPOINT` обрезается до `S`.
**Вычистить:** списки сервисов (`apps/web services/worker services/transcribe`) и `ALLOWED` → параметры/конфиг проекта.
