## 3. Пропуски и риски

- **`02_comparison.md`: отсутствует MoviePy → пропущен прямой кандидат между DIY и полноценным движком сцен.** Python API и MIT делают его уместным для программной сборки записей, титров и аудио. Он потенциально выигрывает у строк фильтров FFmpeg по удобству сопровождения; победа по скорости или дизайну не установлена. Достаточно короткой карточки, без нового большого исследования. [Документация MoviePy](https://zulko.github.io/moviepy/).

- **`00_coordinates.md` + карточки лидеров: разрешён только Playwright-контейнер, предлагаются другие браузерные образы → главный конфликт окружения не разрешён.** Нужно доказать работу выбранного рендера в разрешённом образе либо отдельно изменить исходное ограничение. «Есть Docker» этого не решает.

- **`02_comparison.md`: риски не включают ресурсную конкуренцию → 11 ГБ RAM и 16 ГБ диска нельзя считать свободным бюджетом рендера.** Здесь же работают стенды; нужны ограничения памяти, воркеров, временного диска и очистка кэша. Оценка «4–8 воркеров» не учитывает их нагрузку.

- **`02_comparison.md`: закрепления версии и образа достаточно → не зафиксированы исходные медиа, шрифты, внешние скрипты и данные.** Повторный захват потокового ответа N6 способен изменить ролик при неизменном коммите. Для проверки детерминизма захват следует сохранить как неизменяемый вход.

- **`02_comparison.md`: пилот N6 означает, что остальные проще → вывод не следует из `05_project_inputs.md`.** У N1 есть модерирование, у N4 — фото и платное распознавание, у N5 — длинная обработка и отсутствующий гостевой код. N6 проверяет сложный динамический экран, но не покрывает эти особенности.

- **`02_comparison.md`: риск телеметрии не включён → у HyperFrames документированы сбор сведений об окружении и привязка прежней анонимной истории после входа.** Для воспроизводимого окружения следует явно задать режим телеметрии; документация также связывает её отключение с исключением из canary-rollout. [CLI HyperFrames](https://hyperframes.heygen.com/packages/cli).

- **`02_comparison.md`: стоимость шести роликов фактически не рассчитана → бесплатный рендер не равен бесплатному производству.** Не учтены агентные итерации, повторные записи, TTS и три формата. При этом для шести роликов с тремя форматами исходный объём уже составляет 18 результатов до правок.

## 5. Вердикт и три обязательные поправки

**Да с поправками. Оценка B:** исследование полезно для короткого списка, содержит источники и честно обозначает многие неизвестные. Но итоговый рейтинг точнее, чем позволяют доказательства.

Обязательны ровно три поправки:

1. **Исправить факты и согласовать окружение.** Убрать обязательность Node 22 у Remotion, уточнить возможности video-use и доказать допустимый контейнерный путь для обоих лидеров.
2. **Пересчитать оценки по единой шкале.** Определить 1/2; одинаково учитывать внешний захват и TTS; условно оценивать C; представить F Remotion по фактическому сценарию использования.
3. **Выбирать победителя после сопоставимого пилота.** Одна сохранённая запись, одинаковые FPS и качество, три формата; измерить время, пиковую память, временный диск, повторяемость и число исправлений агента. Без этого преимущество 54 против 53 не доказано.

Проверка выполнена без запуска рендера и изменения стендов. Профиль — документальное ревью, ROUTE: T; пересчёт сумм прошёл, E2E неприменим. Точный идентификатор модели/effort, полный замер длительности и расход недоступны; заявлять подтверждённый запуск `gpt-6-astra medium` нельзя. Файл отчёта и телеметрия не созданы из-за режима только чтения.
