# Бриф для проверочного ревью (OpenAI Codex, gpt-6-astra, medium)

Ты — независимый проверяющий из другого семейства моделей. Прочитай `docs/research/promo-videos/00_coordinates.md`
(система координат), все карточки `docs/research/promo-videos/01_tools/*.md` и сводную таблицу
`docs/research/promo-videos/02_comparison.md`. Инвентарь входов — `05_project_inputs.md` (контекст).

Задача — найти ОШИБКИ, а не пересказать:
1. **Факты.** Для каждой карточки: какие утверждения о лицензии, цене, версии, требованиях к рендеру (GPU/CPU/Docker),
   TTS, форматах и интеграции с браузером противоречат твоим знаниям или внутренне противоречивы; где источник
   не подтверждает утверждение; что помечено «не проверено», но использовано в баллах как факт.
2. **Оценки.** По каждой оси A–I: где балл не следует из карточки (завышен/занижен), где два инструмента с одинаковыми
   фактами получили разные баллы. Особо: ось C (рендер на CPU без GPU) у HyperFrames и Remotion — обоснованы ли «2»;
   ось F у Remotion (Company License) — верно ли описаны условия; ось D (агентопригодность) — не переоценена ли у HyperFrames
   из-за новизны.
3. **Пропуски.** Инструменты того же класса, которых нет в списке и которые могли бы выиграть по нашим осям; риски,
   не названные в разделе рисков.
4. **«video in use».** Согласен ли с опознанием как `browser-use/video-use`? Другие правдоподобные кандидаты?
5. **Вердикт:** можно ли на этой таблице принимать решение владельцу (да / да с поправками / нет), и какие 3 поправки
   обязательны. Оценка качества исследования: A/B/C/D.

Формат ответа: markdown, по-русски, разделы 1–5, каждая находка — «файл: утверждение → что не так → источник/довод».
Не переписывай карточки, только находки. Если ошибок нет — так и скажи по каждому разделу.
