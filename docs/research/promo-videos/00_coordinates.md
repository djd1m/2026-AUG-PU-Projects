# Промо-ролики для шести проектов — система координат для выбора инструмента

Дата: 2026-09-29. Автор: координатор. Статус: черновик до утверждения владельцем.

## Задача

Сделать по одному промо-ролику на каждый из шести продуктов: N1 Proofwall (сбор отзывов + виджет), N2 ReviewQR
(QR на отзывы с «двойной дверью»), N3 «Круг» (реферальная платформа), N4 «Тарелка» (фото еды → калории), N5
«КлипМейкер» (длинная запись → вертикальные клипы), N6 «Суфлёр» (RAG-бот для сайта). Все продукты — веб, на русском,
живут на стендах этой машины. Готового видеоматериала нет; есть живые интерфейсы, README «простыми словами»,
дизайн-токены (N5/N6 — свои темы), логотипов/брендбука нет.

## Что фиксировано (не обсуждается при сравнении)

- **Где рендерим:** этот VPS — 8 vCPU, 11 ГБ RAM, **без GPU**, 16 ГБ свободного диска, Node 20, Docker; браузер —
  только контейнер `mcr.microsoft.com/playwright:v1.60.0-noble`. Всё, что требует GPU или macOS, — только как облачный
  сервис с явной ценой.
- **Кто делает:** агенты (Anthropic — основная работа, OpenAI/Codex — проверка). Инструмент обязан быть удобен
  агенту: сцены описываются кодом/текстом, воспроизводимо из git, без ручного монтажа в GUI.
- **Шесть роликов из одного шаблона:** выбор делается один раз; цена ошибки — ×6.
- **Язык:** русский текст и (если есть) русская озвучка.

## Оси сравнения (система координат)

Каждая ось — 0…3, где 3 — лучше всего для НАШЕЙ задачи. Веса — предложение координатора, утверждает владелец.

| # | Ось | Что измеряем | 0 | 3 | Вес |
|---|---|---|---|---|---|
| A | **Воспроизводимость из кода** | ролик = файлы в репозитории, `render` даёт тот же результат; правка текста = коммит | только GUI/облачный редактор | полностью код, детерминированный рендер | 3 |
| B | **Живой интерфейс в кадре** | как попадают экраны наших продуктов: запись через Playwright/скринкаст, встраивание веб-компонентов, только статичные скриншоты | нет способа | нативная интеграция с браузером/React-компонентами | 3 |
| C | **Работает на этом VPS** | рендер без GPU, в Docker, за разумное время (ролик 60 с ≤ 15 мин) | только облако/GPU | локально, CPU, контейнер есть | 3 |
| D | **Агентопригодность** | может ли LLM написать ролик целиком: документированный API, примеры, типизация, предсказуемые ошибки | нет API/документации | текстовый/кодовый DSL с примерами и типами | 3 |
| E | **Русская озвучка и субтитры** | TTS на русском (качество, цена), автоматические субтитры, шрифты с кириллицей | нет | встроено или тривиально подключается | 2 |
| F | **Лицензия и цена** | лицензия для коммерческого использования (у Remotion — company license!), цена за 6 роликов и за правки | платно/неясно | свободно для компании, без платы за рендер | 2 |
| G | **Качество и брендирование** | типографика, анимация, темы, 9:16/16:9/1:1 из одного исходника | шаблон без контроля | полный контроль стилей, форматы из одного кода | 2 |
| H | **Зрелость и поддержка** | версия, активность, документация, известные ограничения (2026) | заброшено/альфа | стабильно, активно | 1 |
| I | **ИИ-генерация материала** | нужна ли/есть ли генерация футажа, аватаров, музыки; риск «пластикового» вида | — | опционально, отключаемо | 1 |

### Промежуточные уровни 1 и 2 (круг 2, после ревью Codex)

Общие правила для всех кандидатов:
- **Внешний слой захвата** (Playwright-запись/скриншоты) и **внешний голос/распознавание** (Piper, Whisper) доступны
  всем, кто импортирует видео и аудио. Балл даётся за то, что инструмент добавляет сверх этого общего слоя.
- **A** оценивает повторный рендер ЗАФИКСИРОВАННЫХ входов. Получение входов (повторная запись стенда) — отдельный шаг.
- **C** выше 2 не ставится без замера на этом VPS: 2 означает «официальный путь есть, до замера».

| # | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| A | только GUI/облачный редактор | исходник в git, но результат заново решает LLM или случай при каждом прогоне | код/спека в git; повторяемость требует ручной фиксации параметров (случайные умолчания, решения агента, нет версий релиза) | код в git, рендер зафиксированных входов детерминирован, версии релизов закрепляемы |
| B | нельзя поместить экран продукта | только импорт готовой записи/скриншотов | импорт записи + собственный путь сверх него: переиспользование стилей/компонентов продукта (DOM/CSS/React) или встроенный захват | всё из 2 + интерактивный сценарий (клики, потоковые состояния) в кадре ПОДТВЕРЖДЁН |
| C | только облако/GPU | CPU возможен, но официального headless/контейнерного пути нет или окружение конфликтует | официальный CPU/headless-путь, совместимый с разрешённым окружением; скорость не измерена («до замера») | измерено на этом VPS: 60 с ≤ 15 мин |
| D | нет API/документации | API есть, документации и примеров мало, ошибки непредсказуемы | документированный API/DSL с примерами, но без агентского инструментария (или инструментарий без типизированного API) | типизированный/декларативный API + официальные навыки для агентов + машинная проверка до рендера |
| E | нет импорта аудио | импорт аудио; путь к субтитрам по времени не найден (собирать вручную) | импорт аудио + документированный путь к субтитрам (Whisper-интеграция или рендер SRT/ASS); русский голос внешний | встроенный локальный русский TTS + автоматические субтитры |
| F | платно, цена неясна | платная лицензия с известной ценой | бесплатно при условии, которое надо подтвердить (численность, копилефт, обязательный платный внешний сервис) | разрешительная лицензия, без платы за рендер и без условий |
| G | шаблон без контроля | ограниченная типографика и моушн (текстовые оверлеи, базовые переходы) | полный контроль стилей и анимации; мультиформат из одного исходника не показан документацией | полный контроль + мультиформат из одного исходника документирован |
| H | нет коммитов 12 мес. | нет релиза 6 мес. (или релизов нет вовсе), коммиты есть | релиз за 6 мес., но pre-1.0 или без регулярности | стабильный (≥1.0) релиз за 6 мес. и регулярные релизы |
| I | держится на генерации | обязательный генеративный компонент | генерация включена по умолчанию, отключаема | генерация опциональна или отсутствует |

Итог = Σ(балл × вес), максимум 60. Инструмент с 0 по осям A, C или D **выбывает** независимо от суммы (это
не пожелания, а условия задачи).

## Как сравниваем (протокол)

1. Каждый кандидат — карточка `01_tools/<name>.md`: что это, кто делает, версия и дата, лицензия и цена,
   как рендерит (движок, GPU?), как встраивается браузер/React, TTS/субтитры, минимальный пример кода,
   **источники с датами** (официальные документы, репозиторий, лицензия). Утверждения без источника — «не проверено».
2. Сводная таблица баллов по осям — `02_comparison.md`, с обоснованием каждой оценки одной строкой.
3. Проверочное семейство (OpenAI, Codex `gpt-6-astra` medium) читает карточки и таблицу и ищет ошибки фактов и
   оценок — ответ дословно в `03_verification_codex.md`.
4. Решение — с владельцем: `04_decision.md` (что выбрано, почему, что отклонено, план пилота на одном проекте).
