## 1. Production compose — топология «одна дверь»

**Путь:** `docker-compose.yml`

**Что шаблонизируется:**
- Слоистая топология: хранилища (`expose:` только) → приложения (`expose:` только) →
  reverse-proxy (единственный сервис с `ports:`, и то через `${HTTP_PORT:-80}:80`).
- Секреты передаются голыми именами переменных без `=` (`- POSTGRES_PASSWORD`); значение
  пишется только там, где оно не секрет и внутреннее (`- SVC_URL=http://svc:7331`).
- `depends_on: condition: service_healthy` на каждую stateful-зависимость + healthcheck
  с экранированием `$$VAR` (`test: ["CMD-SHELL", "pg_isready -U $$POSTGRES_USER"]`).
- У каждого сборочного сервиса `context: .` + `dockerfile: <путь>` с комментарием
  «корень монорепо: package-lock.json только здесь».
- Пин тега образа + комментарий, почему без тега нельзя (`:latest` = невоспроизводимая сборка).

**Обязательно переносить вместе с шаблоном** — комментарий на приложении о том, почему
оно НЕ публикуется: публикация ломает rate limit, потому что `extractClientIP` доверяет
ПОСЛЕДНЕМУ элементу `X-Forwarded-For` (его дописывает прокси); при прямом доступе этот
элемент задаёт клиент. Общее правило: гарантия прокси действует ровно до тех пор, пока
прокси нельзя обойти. Плюс комментарий у переменной внешнего адреса: её отсутствие ничего
не ломает при старте и видно только в выданных наружу ссылках.

**Что доменного:** имена сервисов (`web`/`worker`/`transcribe`), переменные S3/ЮKassa/
`BASE_URL`/`APP_DOMAIN`, имена томов, конкретные пины образов.

## 3. Caddyfile — TLS, immutable-кэш ассета и комментарий об ОТСУТСТВИИ CORS

**Путь:** `Caddyfile`

**Что шаблонизируется:**
```
{ email {$ACME_EMAIL} }
{$APP_DOMAIN} {
    encode gzip zstd
    @asset path /<name>.*.js
    header @asset Cache-Control "public, max-age=31536000, immutable"
    reverse_proxy <service>:<port>
}
```
Домен и почта ACME — только через `{$VAR}`, ни одного зашитого адреса; named matcher под
ассет с content-hash в имени; один `reverse_proxy` на внутреннее имя сервиса.

**Обязательно переносить** — комментарий, документирующий ОТСУТСТВИЕ: CORS для API виджета
здесь намеренно не ставится, его выставляет приложение; два `Access-Control-Allow-Origin`
ломают запрос ЦЕЛИКОМ, при этом `curl` показывает оба заголовка и всё выглядит нормально —
дефект виден только в браузере на кросс-доменном запросе. Без этого комментария следующий
редактор «услужливо» добавит `header`. Там же — почему HTTPS не обсуждается: скрипт по HTTP
на чужом HTTPS-сайте блокируется как mixed content молча.

**Что доменного:** маска `/widget.*.js`, апстрим `web:3000`.

## 4. Многостадийный Dockerfile для монорепо на npm workspaces

**Путь:** `apps/web/Dockerfile`, `services/worker/Dockerfile`, `services/transcribe/Dockerfile`
(три файла, один скелет; два сервисных различаются только именем workspace и одним `apk add`)

**Что шаблонизируется:**
- Стадии `deps` (только prod-зависимости) / `build` (полные + компиляция) / `runtime`.
- Блок «сначала ВСЕ манифесты workspace, потом исходники», повторённый в `deps` и `build`:
  копируются `package.json` каждого рабочего пространства, а не только целевого.
  Две причины, обе в комментарии: `npm ci` сверяет ВЕСЬ lock-tree и без остальных манифестов
  падает с «Exit handler never called!»; и слой кэшируется, не инвалидируясь правкой кода.
- Точечная установка: `npm ci --workspace @scope/name --include-workspace-root`
  (без `--include-workspace-root` теряются корневые зависимости).
- Не-root в runtime: `addgroup -S app && adduser -S app -G app` … `USER app`,
  объединённый в один `RUN` с `apk add`, где пакет нужен.
- HEALTHCHECK одной строкой на node, без curl в образе:
  `CMD node -e "fetch('http://127.0.0.1:PORT/health').then(r=>process.exit(r.ok?0:1)).catch(()=>process.exit(1))"`
- Шапка с «КОНТЕКСТ СБОРКИ — КОРЕНЬ РЕПОЗИТОРИЯ, не ./services/X» — то же утверждение
  намеренно продублировано в compose, потому что каждое по отдельности обходится.
- Слот «почему эта зависимость живёт здесь, а не в соседнем сервисе» (ffmpeg — в transcribe,
  и в worker явно написано, почему его там НЕТ, со ссылкой на раздел архитектуры).

**Ещё два комментария, теряющиеся при бездумной генерации:** путь сборки Next лежит в
`apps/web/.next`, а не в корне контекста — путь копирования обязан совпадать с рабочим
пространством, иначе рантайм стартует на пустоте; и `npm start` в корне не существует,
скрипт объявлен в workspace → `CMD ["npm","start","--workspace","apps/web"]`.

**Что доменного:** имена workspace (`@proofwall/*`), список манифестов, порт 7331, ffmpeg,
пути артефактов Next, отдача `packages/db` исходниками на TypeScript.

## 6. `.env.example` как комментированный контракт, а не список переменных

**Путь:** `.env.example`

**Что шаблонизируется:**
- Разбиение на секции баннерами `# --- Название ---` (БД / объектное хранилище / сессии /
  платежи / внешние API / TLS / хостовые порты).
- Пустые значения у всего секретного + подсказка, что считается годным («длинная случайная
  строка»), и предупреждение о цене дефолта.
- ОТДЕЛЬНАЯ секция хостовых портов с правилом «правится ПОД МАШИНУ, а не в docker-compose.yml»,
  командой предполётной проверки и фразой «конфликтует только левая (хостовая) часть».
- Конвенция `[GAP: …]` прямо в файле — для непринятых решений.
- Флаг-заглушка (`*_STUB=true`) с задокументированным дефолтом и явным «для локальной
  разработки оставить true».
- У переменной внешнего адреса — не только описание, но и КОМАНДА пост-деплой-проверки.
- Явная документация ОТСУТСТВИЯ секрета («секрета для проверки подписи здесь нет и не должно
  быть») — чтобы никто не дописал его по аналогии с другими провайдерами.

**Что доменного:** сам набор переменных (бакеты S3, ЮKassa, OpenAI), примеры доменов, цены.

## 7. Структура файла миграции

**Путь:** `packages/db/migrations/001…010_*.sql`

**Что шаблонизируется:**
- Шапка: `-- путь файла` → `-- Источник:` с точными §-ссылками на документы → обоснование.
  Ключевое: ЯВНОЕ отделение «переписано из документа» от «выведено инженерно»
  («…ВЫВЕДЕННОЕ из того, какая функция какую таблицу трогает — не отдельный факт документов»).
- Нумерация с фиксированным смыслом, применяется раннером по сортировке имён:
  extensions → roles → таблицы → rls → audit → поправочные миграции.
- Тотальная идемпотентность: `create … if not exists`, `drop policy if exists` перед
  `create policy`, `do $$ … if not exists (select 1 from pg_roles …) $$` для ролей.
- `comment on column …` — обоснование сохраняется в самой БД, а не только в файле.
- Жизненный цикл `[GAP: …]`: маркер прямо в SQL → закрывается отдельной поздней миграцией,
  которая называет, какой GAP закрывает, приводит источник числа и статус проверки, и
  отдельно помечает оставшийся открытый вопрос владельца.
- Шаблон поправочной миграции: чего требуют документы → чего схема не выражает → значит
  описанная проверка нереализуема и непротестируема → колонка, с обоснованием nullability
  по смыслу, а не по удобству.

**Что доменного:** сами таблицы, колонки, номера разделов документов.

## 8. Каркас двухролевой RLS-изоляции арендаторов

**Путь:** `packages/db/migrations/002_roles.sql` + `007_rls.sql` + `008_audit.sql`

**Что шаблонизируется:**
- Две роли `NOLOGIN`: обычная (работает ПОД RLS) и сервисная (`BYPASSRLS`, для анонимных и
  системных путей без контекста арендатора). Приложение подключается ОДНИМ пользователем,
  роль переключается ВНУТРИ транзакции через `SET LOCAL ROLE`; обе роли гранятся `current_user`.
- Контекст арендатора: `set_config('app.current_<key>', $1, true)`, чтение в политиках как
  `nullif(current_setting('app.current_<key>', true), '')::uuid`.
- Повторяемый шаблон политики на каждую таблицу с ключом арендатора:
  `drop policy if exists …` → `create policy … for all using (…) with check (<то же>)`.
- Grants, аргументированные построчно: какая функция и под каким актёром трогает таблицу.
  Никаких грантов «на всякий случай».
- Append-only таблица: только `select, insert`, `update`/`delete` не выдаётся НИКОМУ,
  плюс ОТДЕЛЬНАЯ `for insert with check`-политика — без неё владелец A может записать
  строку в чужой `project_id`, пусть и не прочитав её потом.

**Обязательно переносить — три комментария:**
1. Честное предупреждение про `BYPASSRLS` капсом: Postgres не применяет НИ ОДНУ политику
   ни на одной таблице для этой роли, изоляция на анонимных путях держится ИСКЛЮЧИТЕЛЬНО
   на явном `WHERE` в коде; если фильтр забыт — RLS не подстрахует.
2. Почему `set_config()`, а не `SET LOCAL`: Postgres не поддерживает bind-параметры для
   имени/значения GUC в команде `SET`.
3. Почему RLS вешается и на корневую таблицу арендатора, у которой нет FK на саму себя —
   иначе дашборд-путь не изолирован на первом же уровне (defense in depth).
   Плюс заметка о порядке миграций: RLS для audit живёт в 008, потому что на шаге 007
   таблицы ещё не существует.

**Что доменного:** имена ролей `app_*`, `projects`/`account_id`, конкретный список таблиц
и матрица привилегий.

## 9. Раннер миграций

**Путь:** `packages/db/src/migrate.ts` (~80 строк)

**Что шаблонизируется:** переносится целиком. Сам создаёт служебную
`schema_migrations (filename primary key, applied_at)`; читает `migrations/*.sql`,
сортирует по имени; каждый файл — в СВОЕЙ транзакции с `ROLLBACK` и ошибкой, называющей

`process.exitCode = 1` вместо `process.exit`. Транзакция на файл — именно то, что делает
учёт в `schema_migrations` осмысленным.

**Что доменного:** ничего, кроме имени переменной подключения и драйвера.

## 10. Формат журнала развилок (ADR-lite)

**Путь:** `decisions/README.md` + `decisions/D-NNN-<slug>.md`

**Что шаблонизируется:**

*Индекс:* заявление об области действия («журнал ЛОКАЛЕН для проекта, у каждого свой»);
триггер записи (решение принято БЕЗ владельца, после ~5 мин молчания, когда работа
блокировалась; каждое можно переиграть, указано что править и во что обойдётся);
словарь статусов (`принято мной` / `принято агентом` / `подтверждено владельцем` /
`переиграно` / `выбрано владельцем`), изменившиеся статусы выделены жирным; таблица
`| ID | Тема | Решение | Статус |`; правило включения из трёх пунктов (меняет продукт или
архитектуру, а не оформление; была разумная альтернатива; владелец не подтверждал явно)
и правило исключения — «мелкие технические выборы без альтернатив сюда не пишутся, иначе
журнал станет шумом».

*Запись:* `# D-NNN: <вопрос>` → строка `**Дата** · **Проект** · **Статус**` →
`## Контекст` (что вынудило решение, часто со ссылкой на находку валидации) →
`## Варианты` (таблица `| Вариант | За | Против |`, выбранная строка помечена `← выбрано`) →
`## Решение` (одна жирная фраза) → `## Обоснование` → `## Когда пересмотреть`.

*Расширенный вариант для решения владельца:* `## Развилка` → `## Проблема, которую это
создаёт` → `## Варианты A/B/C` → `## Решение: вариант X` → `## Что сделано` (список
конкретных правок кода и конфигурации).

**Две вещи, ради которых формат и существует:** секция «Когда пересмотреть» не даёт журналу
окаменеть (условие, при котором решение переворачивается, названо заранее); «Обоснование»
предпочитает ВНУТРЕННИЙ прецедент внешней best practice — решающий аргумент D-004 в том, что
Postgres уже был выбран вместо Redis в соседней задаче, и агент нашёл этот прецедент сам,
вместо того чтобы притащить привычный стек.

**Что доменного:** содержимое D-001…D-009.

**Обязательно переносить — шапку файла:** палитра получена ИЗМЕРЕНИЕМ (`getComputedStyle` по
всем видимым узлам, отсортировано по частоте), а не на глаз — это воспроизводимая процедура
снятия языка дизайна с образца. И граница по интеллектуальной собственности в том же
абзаце: логотип, название и тексты оригинала НЕ переносились — это марка, а не язык дизайна.
Плюс комментарии-правила, а не факты: «один аккуратный вход, без россыпи микроанимаций».

**Что доменного:** конкретные hex, шрифтовая пара, посекционные стили страниц продукта.

## 12. Раскладка tsconfig в монорепо

**Путь:** `tsconfig.base.json` + `apps/*/tsconfig.json`, `packages/*/tsconfig.json`,
`services/*/tsconfig.json`

**Что шаблонизируется:** база держит общее — строгость (`strict`, `noUncheckedIndexedAccess`,
`noImplicitOverride`, `noFallthroughCasesInSwitch`), `target/lib/module`, `paths`-алиасы
рабочих пространств, общий `exclude`. Каждый workspace расширяет её и переопределяет ровно
три оси: модульная система (`NodeNext` у node-сервисов), режим эмита (`outDir`+`rootDir` у
собираемых, `noEmit` у Next и браузерного бандла), `types` (`node` / `vitest/globals`).
Корневой `typecheck` гоняется по базовому файлу одной командой.

**Обязательно переносить — единственный комментарий во всём наборе:** `baseUrl` ОБЯЗАН быть
переопределён в workspace, потому что унаследованная `.` считается относительно БАЗОВОГО
файла (корень монорепо), и тогда `./src/*` указывает мимо пакета. Следствие: web-workspace
переобъявляет ВЕСЬ `paths` целиком с префиксами `../../`. Генератор, выдающий `extends` +
`paths` без переопределения `baseUrl`, молча даёт конфиг, резолвящийся не туда.

**Что доменного:** скоуп алиасов `@proofwall/*`.

**Что шаблонизируется:** `"private": true`, `workspaces` глобами (`apps/*`, `services/*`,
`packages/*`), `engines.node`; два семейства скриптов — веерные по рабочим пространствам
(`build`/`test`/`lint` как `npm run X --workspaces --if-present`; именно `--if-present`
позволяет гонять один набор команд по разнородным пакетам, где у части нет такого скрипта)
и корневые операции (`typecheck` одним `tsc -p tsconfig.base.json`, `db:migrate` делегатом в
db-пакет, `up`/`down`/`logs` поверх `docker compose`).

**Что доменного:** имя проекта, `build:widget` со связкой сборка+копирование.

## 14. `.gitignore` с указанием производителя файла

**Путь:** `.gitignore`

**Что шаблонизируется:** стандартные игноры сборки и окружения плюс тройка
`.env` / `.env.*` / `!.env.example`; и главное — у КАЖДОЙ неочевидной записи назван скрипт,

**Что доменного:** путь бандла виджета.

## Сквозное — стоит зафиксировать отдельно от любого шаблона

1. **Комментарий с инцидентом — часть шаблона, а не украшение.** Каждая опасная на вид
   строка несёт породивший её случай. Без комментария следующий редактор снимает
   `127.0.0.1`, `${VAR:?}`, `expose:` и `name:` как шум.
2. **Один инвариант намеренно повторён в двух файлах там, где каждый по отдельности
   обходится** — контекст сборки монорепо назван и в compose, и во всех трёх Dockerfile;
   «БД не публикуется» — в боевом compose, в тестовом и в demo-оверрайде.
3. **Отсутствия документируются так же явно, как присутствия** — нет CORS на прокси, нет
   ffmpeg в worker, нет секрета вебхука в `.env.example`, нет `update`/`delete` на журнале
   аудита, нет потолка комиссии. Каждое объясняет, ПОЧЕМУ его нет, — это и мешает вернуть.
4. **`[GAP: …]` — полноценная конвенция**, проходящая через SQL и `.env.example` и
   закрываемая отдельной поздней миграцией со ссылкой на источник.
5. **Скаффолд и его детерминированный сторож едут парой** — `.env.example` называет
   `check-port-conflicts.sh` и `check-cjm.sh`, шапка compose — правило про порты.
