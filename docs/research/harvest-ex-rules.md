## C. Безопасность

| Правило | Чем заслужено | Детерминированная проверка |
|---|---|---|
| **Проверка, которую провайдер не может пройти, хуже отсутствия проверки: отсутствие видно, видимость — нет.** Мёртвую ветку защиты УДАЛИТЬ и закрепить тестом «модуль это не экспортирует» | `D-009`, `b1ccb57`: HMAC-проверка вебхука, реализованная строго по провалидированному ADR-006, не могла сработать никогда — заголовка с подписью у ЮKassa просто нет. В коде оказалась видимость защиты | **ДА** — тест на отсутствие экспорта |
| Allowlist живёт В КОДЕ, не в переменной окружения | `D-009`: «в переменной он однажды приедет пустым, а пустой allowlist — это пускать всех». Осознанное следствие: правка allowlist проходит ревью, а не деплой конфига | **ДА** — grep |
| Пустая маска `1.2.3.4/` — это ОПЕЧАТКА, а не `/0`; сравнение CIDR строкой по префиксу недопустимо | `ip-range.ts`, `b1ccb57`: `Number('')===0` → маска `/0` → приём ЛЮБОГО адреса; одна опечатка в списке сетей молча открыла бы дверь всем (поймано тестом). `185.71.76.0/27` покрывает .0–.31, но НЕ .100, хотя текстовый префикс совпадает | **ДА** `[уже в snippets/typescript/cidr-match.ts]` |
| **Порядок операций — это и есть защита**: лимит ДО валидации; квота ПОСЛЕ валидации; подпись/аутентификация ДО записи идемпотентности; свежесть ПОСЛЕ подписи; метка времени ВНУТРИ подписи | `473fdb8`, `669692d`, `PR-003`: при обратном порядке подделка с угаданным `event.id` записывается первой, и НАСТОЯЩИЙ вебхук отбрасывается как дубль — «оплата не применится никогда, а в логах будет всё обработано». Свежесть до подписи различима по времени ответа. Лимит после валидации обходится перебором невалидными телами бесплатно. Ни сценарий, ни алгоритм порядка не выражали — вскрылось при ручной починке | **НЕТ** для вывода порядка, **ДА** для его закрепления тестом |
| HMAC считается от СЫРОГО тела — `request.text()`, не `.json()` | `473fdb8`: тест демонстрирует, что та же нагрузка после `JSON.parse`→`stringify` подпись уже не проходит | **ДА** |
| Тип файла определяется по СИГНАТУРЕ содержимого, не по `Content-Type` (его задаёт клиент) | `photo.ts`, `0293869`: «image/png на HTML — обычный запрос, а не аномалия». Тест требует, чтобы `upload` вообще не вызвался | **ДА** `[уже в snippets/typescript/sniff-image-magic-bytes.ts]` |
| SVG запрещён к загрузке; «очистка» SVG ненадёжна | `7539dc5`: формально изображение, по сути XML-документ со `<script>`/`onload`; открытый на нашем домене увёл бы сессию владельца | **ДА** |
| Файл отдаётся ЧЕРЕЗ свой роут с типом, определённым НАМИ, + `nosniff` + CSP sandbox; ключ объекта `projectId/uuid.ext` проверяется на ТОЧНОЕ соответствие; имя файла автора не используется нигде; разные режимы доступа — разные бакеты | `7539dc5`, `0293869`: без `nosniff` браузер угадывает тип сам и может решить, что это HTML. Прямая ссылка = либо публичный бакет, либо истекающая presigned (витрина через час показывает битые картинки). Общая политика однажды сделала бы публичным и видео | **ДА** — тест на заголовки отдачи и на `../` |
| `JSON.stringify` НЕ обезвреживает JSON-LD | `0d3a4c6`: schema.org требует `dangerouslySetInnerHTML` — единственное место, где авторский текст попадает внутрь `<script>` и React не защищает. `stringify` экранирует кавычки, но `<` и `/` оставляет → `</script>` закрывает тег. Побочно: сами U+2028/U+2029 нельзя писать в регэксп-литерале — они разделители строк JS и рвут литерал (поймала сборка, а не чтение) | **ДА** `[уже в snippets/typescript/safe-json-ld.ts]` |
| Значение, вставляемое в DOM ЧУЖОГО сайта, проверяется на схему И на точный вид пути | `render.ts`, `7539dc5`: `javascript:` выполнился бы в контексте страницы владельца (тест перебирает 7 схем). Проверка «начинается со слеша» была дырявой — `//evil.example/x.jpg` тоже начинается со слеша, и при пустом apiBase это протокол-относительный URL. **Тест поймал дыру в самой проверке** | **ДА** |
| `Origin` может прийти ЛИТЕРАЛЬНОЙ строкой `"null"` (file://, sandboxed iframe) | `cf7e3ed`: уезжало в `utm_content` ссылки badge как «null». Поймано настоящим браузером, не тестом | **ДА** — после того как знаешь |
| Факты, управляемые клиентом, берутся из ЗАПРОСА, не из тела — даже если клиент их присылает | `f9b7df6`, `6d265f6`: иначе клиент назовёт чужой IP в обход anti-fraud или подставит чужую реферальную метку. Домен берётся из `Origin`/`Referer`, а НЕ из query-параметра, хотя виджет его шлёт: параметр задаёт скрипт (сторона под контролем атакующего), заголовок ставит браузер | **ДА** — страж по исходнику `[паттерн: source-parsing-invariant-guard]` |
| Неопознанное значение = самый строгий вариант (fail-closed) | `be3e893`, `f26676b`: проверено на 11 видах мусора, включая `'PAID'`, `' paid'`, `['paid']`; отдельный тест на ОПЛАЧЕННОМ, но деактивированном проекте | **ДА** |
| Различимость ответов — утечка: одинаковый 404 для несуществующего и деактивированного; 429 без счётчика и времени сброса; beacon-роут всегда 204 | `669692d`, `5b75587`: тест «в теле 429 нет цифр»; различимый ответ beacon дал бы анонимный перечислитель существующих слагов. Дамп БД не должен давать захват активных сессий и не должен перебираться заранее посчитанной таблицей | **ДА** |
| В долгоживущий журнал пишется ХЕШ адреса; ключ лимита — хеш с РАЗДЕЛИТЕЛЕМ | `f9b7df6`, `669692d`: сырой IP в аудите — персональные данные без нужды (тест требует отсутствия адреса и присутствия хеша). Без разделителя `ip="1.2"+id="3.4"` и `ip="1.2.3"+id=".4"` дают одно ведро | **ДА** |

## D. Целостность данных и конкурентность

| Правило | Чем заслужено | Детерминированная проверка |
|---|---|---|
| Дедупликация и идемпотентность — на уровне СУБД (`ON CONFLICT`), не «проверить, потом вставить» | `6d265f6`, `473fdb8`: «проверить, есть ли, затем вставить» оставляет окно, где два конкурентных первых рендера ОБА видят «ещё нет». Проверено не рассуждением: **8 РЕАЛЬНО параллельных соединений** на один ключ, ровно одно получает непустой RETURNING | **ДА** — тест с настоящей параллельностью |
| Оптимистичная блокировка на переходе состояния (`where status = $from`) | `7fd74cf`: вторая вкладка, считающая объект всё ещё pending, обновит 0 строк и не затрёт чужой переход молча | **ДА** |
| Переход статуса и пересчёт производного состояния — в ОДНОЙ транзакции | `721e987`: иначе есть окно, где отзыв одобрен, а производный флаг ещё не снят, и краш в нём оставляет рассогласование навсегда | **ДА** |
| Всё, что входит в unique-ключ, нормализуется | `6d265f6`: `Example.com`, `https://www.example.com/path`, `example.com:8080` обязаны стать одной строкой, иначе один сайт насчитает несколько установок | **ДА** |
| `null` ≠ `0`: «нет данных» и «0%» — разные ответы | `f9b7df6`: `conversion_rate = null` при нуле регистраций + обратный тест (регистрации есть, конверсий нет → именно 0) | **ДА** |

| Мера соответствует угрозе: за одним NAT сидят живые люди → блокируется АТРИБУЦИЯ, а не регистрация | `f9b7df6`: тест проверяет обе половины — аккаунт на месте, начисления нет | **ДА** |

## G. Три сквозных наблюдения, которых нет ни в одном файле

1. **Тихие отказы кучкуются там, где есть graceful fallback.** У каждого P0 этого прогона
   был запасной путь, оставлявший систему «здоровой»: дефолт `BASE_URL`, `non-blocking`
   хуки, имя compose-проекта по умолчанию, лимит, продолжавший отвечать 200.
   **Аудит начинать с фолбэков.** — детерминированно: инвентаризация фолбэков как артефакт.

2. **Самый дорогой способ обнаружения применён четырежды** — владелец продукта или второе
   мнение (Codex) открыли вещь руками: `BASE_URL`, обход rate limit, двойной CORS,
   Supabase в постановке. Каждый раз после этого появлялся скрипт слоя 1. Бюджет на
   сквозной прогон по развёрнутому стенду планировать ДО, а не после. — детерминированно: нет.

3. **Разумный дефолт у конфигурационной переменной превращает «неправильно настроено» в
   «молча неверно».** Для значений, определяющих то, что продукт отдаёт наружу (базовый URL,
   публичный домен, origin коллбэка), дефолт — вред: он снимает единственный дешёвый сигнал
   (падение при старте) и переносит обнаружение на человека, открывающего ссылку в проде.
   Оба файла фиксируют сам дефект `BASE_URL`, но не выводят из него это правило. —
   детерминированно: **ДА**, список «переменных без права на дефолт» + fail-fast при старте.
